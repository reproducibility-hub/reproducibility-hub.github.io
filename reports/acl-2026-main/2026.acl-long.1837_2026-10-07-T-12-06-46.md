**Summary.** The released LoGo implementation reproduces the paper's BBH numbers almost exactly on LLaMA-3.1-8B, Qwen-2.5-7B and DeepSeek-LLM-7B-Base:
- All 6 BBH averages are within 0.2 points.

- LLaMA: 9/16 task-level numbers match. The 7 others are off by 1.3–5.4 points, i.e. 1–8 test samples.

## Why not fully reproduced
- **Missing data (main reason).** Only `data/bbh/boolean_expressions` is in the repo. `dataset_list.py` names all 26 Table-1 datasets, but the repo contains no files, no prompt templates and no preprocessing code for the 18 non-BBH ones, and the paper does not specify the prompts. CodeXGLUE (Table 2) is missing too. Running them as released gives empty datasets.
- **No baseline code** for AdapterSoup, LoRAHub or LoRARetriever.
- Coverage is therefore SUBSET (BBH only). BBH ran at full scale, with all samples, all 3 backbones and both signals.

## Discrepancies
1. **code_vs_paper (major, affects results).** `utils/model.py::select_and_predict` calls `peft_model.set_adapter(selected_loras)` and never restores the full adapter set. So from the second instance on, the "probe pass" runs with the previous instance's top-20 adapters (at unit scaling), not with all N adapters as Sec. 3.2 / Alg. 1 describe.
   - Results then depend on the previous instance and on the order in which datasets are run.
   - Fixing it moves LLaMA-Norm BBH from 38.28 to 41.76; running tasks in separate processes gives 39.97.
2. **code_vs_paper (minor).** The signal uses `hidden_states[layer]`, the residual stream before the block's input RMSNorm, not the normalised tensor that q_proj (and its LoRA) actually receives. This literally matches "hidden representation entering block B_T", but it is not exactly the adapter's real projection output. Effect not measured.
3. **paper_internal (no effect on results).** The abstract and intro say "27 datasets", but Table 1 / Sec. 4.1 list 26: 8 BBH + 6 WMT + 4 GEM + 4 CBQA + 4 NLI.
