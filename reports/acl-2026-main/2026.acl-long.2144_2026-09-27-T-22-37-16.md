## Target
The target is Table 3 (Recall@1, 15 subcategories plus Total = mean over categories) and Table 5 (Recall@3) on EDIR. The paper's headline claim is that even SOTA embedders (RzenEmbed, GME) struggle, with the lowest scores on remove, viewpoint, texture and shape.

The released code has model wrappers for only **RzenEmbed-7B (V2), Ops-MM-embedding-v1-7B, GME-Qwen2-VL-2B and GME-Qwen2-VL-7B**. Those 4 are the models I evaluated. The other 9 baselines (PIC2WORD, SEARLE, MagicLens, MMRet, E5-V, VLM2Vec, UniME-2B/7B, mmE5) have no code in the repo, and EDIR-MLLM (the paper's trained model) was not released.

## Important data difference
The HF dataset card says the release is a *"streamlined evaluation variant … we have completely removed these extra distractor images"*. Concretely:
- 5,000 queries, which matches the paper.
- A corpus of **28,645** images, versus **178,645** in the paper (the 150k distractors are gone).

The paper's exact Table 3/5 setting is therefore not reproducible from the release. With fewer distractors, Recall is expected to rise. The dataset card itself publishes "Updated Results" for the streamlined set, which include GME-2B and GME-7B, and I also compare against those.

### Two protocol issues in the released `main.py` that change the results
1. **GME never receives the query instruction.** `Qwen2VLModel.query_emb` calls the processor with `is_query=False`, and `format_model_input` only adds the instruction when `is_query` is true.
   - Applying it (system prompt, with the paper's instruction *"Given an image, find a similar image satisfying the query."*) raises GME-2B from 41.4 to **46.5** and GME-7B from 43.5 to **45.6**.
   - The instruction-applied numbers agree closely with the authors' own HF-card results for the streamlined set: 23 of 30 subcategory entries are within tolerance. So the authors evidently ran GME with the instruction applied.
2. **Ops-MM-embedding is routed to the GME wrapper.** `load_model` sends `'ops'` to `Qwen2VLModel`, which gives R@1 41.0, far below the paper's 47.2 and below GME.
   - Ops' official inference code (`ops_mm_embedding_v1.py`) uses the same system/user template and last-token pooling as the repo's RzenEmbed wrapper.
   - Running Ops through `RzenModel` (a CLI `--model_id` change only) gives **51.6**, tied with RzenEmbed (51.8). That reproduces the paper's Rzen = Ops tie (47.2 / 47.2).

I call these runs "native-protocol". RzenEmbed is identical in both settings.

## Codebase completeness: MAJOR_FIXES
The evaluation loop and metrics (pytrec_eval Recall@k) are released and work. However, the released code has two bugs that affect results: the query instruction is dropped for GME, and Ops is routed to the wrong wrapper. It also has two crash bugs:

Changes to `codebase/` (uncommitted; see `codebase_changes.diff`):
- `models/qwen2vl_model.py`: added `attn_implementation="flash_attention_2"`. With default SDPA, the Qwen2-VL vision tower allocates a 56 GB block mask for a 32-image batch and OOMs.
- `models/qwen2vl_model.py`: added `.clone()` on the pooled embeddings. `_pooling_last` returns a view, so every stored embedding kept its batch's full last_hidden_state alive, and GME-7B OOM'd at 121 GB. This fix has no numerical effect.
- Added `dataset/edir/*.jsonl` (symlinks to the HF files).

Environment: `requirements.txt` pins `transformers==4.5.1` (meaning 4.51–4.57; I used 4.51.3). The RzenEmbed wrapper also needs `flash-attn`, which is not listed; I installed the 2.8.3 wheel.

Scripts I wrote outside the repo:
- `aggregate.py`: per-subcategory Recall@1/3 and the category mean.
- `compare.py`: comparison against the paper and the HF card.
- `sens_gme_instr.py`: GME with the query instruction applied.
- `run_*.sh`: run queues.

Missing from the release: wrappers for 9 of the 13 evaluated models, the 150k distractor images, and the EDIR-MLLM checkpoint and training code.

## Why not fully reproduced
- The paper's 178,645-image corpus is not released; only the 28,645-image streamlined corpus is.
- Only 4 of the 13 models have code.
- The released evaluation script's protocol for GME and Ops differs from what the paper's numbers imply.

Within those limits, the paper's conclusions held for the four models I could run.
