## Why it is not fully reproduced
- **Retraining is slightly but consistently weaker than the paper and the released checkpoints**, most visibly on Rest16 (MF1 81.66 vs 84.38) and on the French multilingual set (77.35 vs 80.94).
  - The runs are deterministic on our setup: an identical rerun gave identical numbers.
  - I found no code/config difference that explains the gap. The likely cause is hardware/kernel differences (RTX 5090 + torch nightly vs H200 + stable torch) combined with the very high seed sensitivity of the small, imbalanced restaurant test sets under test-set checkpoint selection. Flag: `RERUN_WEAKER_THAN_RELEASED`.
- **Stronger baseline:** our encoder-only baseline is stronger than reported on Lap14 (+1.35 MF1) and Rest16 (+2.18 MF1). Together with the weaker DABS, the Rest16 gain falls to 3.72 pp and is no longer significant (p = 0.11, 3 seeds). Flag: `BASELINE_STRONGER_THAN_REPORTED`.
- **DORA's marginal value over ACBS is not reproduced.** Full − ACBS-only is −0.06 / +0.67 / +0.01 / +0.54 MF1, vs the paper's +1.59 / +1.72 / +1.46 / +2.13.
- **Not run:**
  - LLM 5-shot baselines: the paper's own evaluation, but no released code for it.
  - Table 5: no KGAN-BERT code.
  - BERT-base backbone and Tables 7–9 / 13 (time priority).
  - The structure-aware and fine-tuning baselines of Table 2 are numbers copied from prior work, so they can't be rerun. The "competitive with" comparisons therefore rest only on our DABS numbers.

## Discrepancies
1. **(code_vs_paper, major) Loss function.** The paper (Sec. 3.5) says cross-entropy. The code trains every DORA/ACBS/Full model with focal loss (γ=2, `_compute_focal_loss`), while the encoder-only baseline uses plain CE. So the baseline and the method also differ in their loss.
2. **(code_vs_paper, major) The encoder-only baseline is aspect-blind.** `scripts/train.py` feeds only the sentence (no aspect term, marker or span) to the encoder-only and pure DORA-only models, so every aspect of a multi-aspect sentence gets the same prediction. The paper presents this as the matched encoder baseline for its paired significance tests (Tables 3, 4, 11, 12) and never says it ignores the aspect. The reported "+6–9 pp" gains therefore largely measure giving the model the aspect at all.
3. **(code_vs_paper, major) "FLOPs reduction" is not measured.** `multi_aspect_reuse_benchmark.py` uses `seq_len*2000 + M*seq_len*500` vs `M*seq_len*2500`, which yields exactly 40/53.3/60% (the abstract's "up to 60%"). Real FLOPs give 49.9/66.5/74.8%: the head costs only 0.25% of the shared pass. The claim holds, but its number is an artefact of the constants.
4. **(code_vs_paper, minor) Max sequence length.** 128 in the code vs 256 in the paper (B.3). Sentences are short, so this likely has no effect.
5. **(code_vs_paper, minor) Head details.**
   - Token selector: ReLU in the code vs GELU in the paper.
   - Depth selector: the code uses 2d→d/2→12 logits, sliced to the last K and renormalised; the paper says 2d→d→K.
   - Classifier: the code uses a 2-layer MLP with LayerNorm instead of the paper's "Linear(h)".
6. **(observation, not a discrepancy) Rest16 Accuracy of the released checkpoints.** They score 93.74 Acc vs 94.87 in Table 2, though their MF1 (84.30) matches. The other datasets' released accuracies match within 0.9.
