### Settings that differ from the paper
* MMLU sample: the paper text says 1,204 MMLU *validation* questions for both models. The numbers in
  Tables 1/2/4 (and the authors' shipped `mmlu_analysis/detailed_results.csv`) come from **400 validation
  questions for Llama** (`-n 400`) and **2,000 test questions for Mistral** (`-n 2000 --split test`). I used the
  latter (matching the reported numbers) for the main comparison and also ran the paper-text setting
  (`-n 2000 --split validation` → 1,204 questions) with vLLM (results in `results/h1_summary.json`,
  key `paper_text`; conclusions unchanged, e.g. Llama-StrucQ / Mistral-SecAlign suffix RR 91.5 / 75.6 on 1,204 Qs, the Mistral value with the released, unfixed template).
* GPQA: the paper says "all 100 questions from gpqa_diamond"; gpqa_diamond has 198 questions and the code
  randomly samples 100 (seed 42). Used the code's sampling.
* Software versions: transformers 5.17 / torch 2.13 (the authors' versions are unknown; no requirements file).
* Generation for the supplementary vLLM run used vLLM instead of HF `generate` (same token ids incl. the
  duplicated BOS, greedy, same EOS id, max 2048). The primary numbers are from the unmodified HF pipeline.
* Mistral dual-question prompts (GPQA, MMLU) use the paper's App. B.2.3 template (fix above) in the "Ours" column;
  AIME Mistral dual prompts are left as released (the paper shows no AIME template).

## Why not fully reproduced
* As released, Mistral H1 magnitudes deviate because the released Mistral dual-question prompt differs from the one
  in the paper (fixed; see above). After the fix MMLU matches; GPQA/AIME remain noisy (50 / 15 pairs).

## Discrepancies
1. **code_vs_paper** (major) — *meval/prompts/formatter.py MistralFormatter.format_dual / format_dual_mmlu vs App. B.2.3 (Dual-Question Prompt Template, Mistral)*. Paper: Mistral dual prompt: '<s>[INST] Please answer the following two multiple-choice questions step by step: Question 1 ... Question 2 ... Please analyze both questions step by step and provide your final answers in the format: Answer 1/Answer 2 ... [/INST]'. Code/other: The released formatter starts the prompt with the FULL dual system message ('... step by step. Analyze both questions step by step and provide your final answers in the format: Answer 1: [letter] Answer 2: [letter] where ...') and then repeats the format instructions at the end. With the released prompt Mistral suffix RR on MMLU is 74.9 (SecAlign) / 33.4 (StrucQ) instead of the reported 89.6 / 62.2; with the paper's template the reported numbers are reproduced (89.0 / 64.3). Affects results: True.
2. **code_vs_paper** (minor) — *Sec. 4.2.1 / App. B.2.1 (MMLU) vs scripts/run_eval.py usage and shipped mmlu_analysis/detailed_results.csv*. Paper: 1,204 randomly selected MMLU validation questions are used (for both models). Code/other: Default run_eval (-n 2000, validation, balanced sampling) indeed gives 1,204 questions, but the reported Table 1/2/4 MMLU numbers come from 400 validation questions for Llama (-n 400) and 2,000 *test* questions for Mistral (-n 2000 --split test), as shown by the authors' own detailed_results.csv and reproduced here. Affects results: True.
3. **code_vs_paper** (minor) — *Sec. 4.2.1 / App. B.2.1 (GPQA) vs meval/benchmarks/gpqa.py random_sample_problems*. Paper: 'We include all 100 questions from the gpqa_diamond split'. Code/other: gpqa_diamond has 198 questions; the code randomly samples 100 of them (seed 42) and shuffles options with np.random. Affects results: True.
4. **code_vs_paper** (major) — *Sec. 3.3 (Keyword Trigger Set), Sec. 4.4, App. C.1 vs prompt-guard-models-analysis/*. Paper: Trigger prompts x+t are compared with matched controls x+r in which a random technical term of similar length/POS is inserted; 'matched non-trigger controls do not' increase refusals. Code/other: No x+r control set or code exists; the only ablation is trigger deletion/masking on NotInject (Table 5). The control-based comparison described in the paper is not implemented. Affects results: False.
5. **code_vs_paper** (minor) — *Table 3 'Baseline Safety' column (PG rows) vs EVAL_SCRIPTS_README.md*. Paper: All prompt guard models are evaluated on the same Baseline Safety (PINT + WildGuard benign) set. Code/other: Only PromptGuard2 is evaluated by the released code; ProtectAIv2/LakeraGuard/FMOPS/Deepset baseline values are copied from the NotInject paper (README says so). Recomputing them with the release's PINT/WildGuard code gives the same values (13.8/65.9/65.4). Affects results: False.
6. **code_vs_paper** (minor) — *prompt-guard-models-analysis/eval_deepset_masked.py evaluate_all_strategies()*. Paper: Deepset is evaluated on NotInject with/without triggers (Tables 3, 5). Code/other: The evaluation loop is commented out; the script only re-prints cached results (outputs {} without the shipped JSON). Affects results: False.
7. **paper_internal** — *Table 4, Llama-3 + StrucQ*. Paper: Avg. Acc 12.8 (drop -18.8). Code/other: Table 4 is defined as the average of the GPQA/MMLU/AIME accuracies, and all other Table 4 entries equal the mean of the Table 1 accuracies; Table 1 gives (16.0 + 32.5 + 0.0)/3 = 16.2 for Llama+StrucQ, not 12.8. Affects results: True.
8. **paper_internal** — *Table 4, Llama-3 + SecAlign*. Paper: 22.4 (-3.1). Code/other: 31.6 - 22.4 = 9.2, so the reported drop -3.1 is inconsistent with the table's own values. Affects results: True.
9. **paper_internal** — *App. B.2.2 vs Tables 1/2 'Base' rows*. Paper: App. B.2.2: the single-question baseline results 'are shown in Table 1 and Table 2 "Base"'; '+StrucQ/+SecAlign' rows are the dual-question test. Code/other: Table 2 'Base' has distinct 1st/2nd-position values and equals the ORIGINAL model on the dual-question prompt (verified against the authors' shipped analysis_report.txt and our runs); Table 1 is the mean of the two positions of Table 2. 'Base' therefore means 'undefended model', not 'single-question condition'. Affects results: False.
10. **paper_internal** — *Sec. 4.4 / Abstract vs Table 3*. Paper: 'inserting a single trigger token increases refusal rates by 40-50% across both fine-tuned models and prompt guard systems'. Code/other: Table 3 shows increases of only +5.3/+8.9 (Llama StrucQ/SecAlign) and +12.4/-2.7 (Mistral) for the fine-tuned models; the trigger-stress set is the THREE-word-trigger NotInject subset, not a single token. Affects results: False.
11. **paper_internal** — *Sec. 4.2.2 vs App. B.3 (Baseline Safety set size)*. Paper: Sec. 4.2.2: benign splits of PINT (3,007 samples) + WildGuard (971). Code/other: App. B.3: benign PINT is ~2.8k samples; the shipped PINT.json has 3,007 rows of which 2,845 are benign (162 are attacks). Affects results: False.
