# Reproduction report — *Fiction Flows: A Replication and Reinterpretation of Narrative Sequentiality* (ACL 2026, 2026.acl-long.1576)

## Verdict

**PARTIALLY_REPRODUCED** — result match **MIXED** (as released: **TREND_MATCH** for the HippoCorpus settings the unmodified pipeline was run on), coverage **SUBSET**, codebase completeness **MISSING_SCRIPTS**.

* The headline HippoCorpus result (Fig. 2 / Table A1, "With Topic" formulation: imagined > recalled with medium-to-large
  Hedges' g in every model, retold > recalled smaller) reproduces **numerically**: mean of per-model median g = 0.577
  (paper 0.582), every model in 0.48–0.64 (paper 0.43–0.70); retold vs recalled 0.175 (paper 0.199).
* The "No Topic" collapse reproduces in direction (mean g drops from 0.58 to 0.12; retold vs recalled 0.02 vs paper 0.04),
  but the **per-model pattern does not**: with a clean likelihood computation Llama 3.1 and Mistral 3 show the *largest*
  positive no-topic effects (0.22, 0.25), not a reversed effect (paper −0.106) / Qwen-only positivity (paper 0.28, 0.22).
* We traced this to a **bug in the released scoring code** (`model.py` + the llama.cpp fork the README requires): the echoed
  BOS piece (e.g. `<|begin_of_text|>`, 17 characters) is counted by `_get_logprob`'s character reconstruction, so for
  BOS-adding models 1–3 trailing *context* tokens are scored as part of the target sentence. Emulating the bug in our
  backend (verified against the real fork: per-story r = 0.99+ with the unmodified pipeline) reproduces the paper's Llama
  numbers (no-topic −0.099 vs paper −0.106; "reversed effect at small windows that attenuates"). A second artifact
  (4-bit Q4_K_M quantisation of Qwen3-0.6B-Base gives the 2nd token of un-prompted text log-prob ≈ −22 instead of ≈ −7)
  inflates the unconditional baseline for non-BOS Qwen models in the released pipeline.
* The CONLIT fiction/non-fiction experiment (Fig. 3, Table 2, Tables A4–A6) — the paper's main *positive* claim — and the
  mixed-effects covariate analysis (Sec. 5.4, App. B/C) **cannot be run**: neither the CONLIT passages nor any code for
  passage sampling, covariates (spaCy/RST/coreference/BERT features) or the lme4 regressions is in the repository, despite
  "We release our code and data". GPT-3 (davinci-002) could not be run (no OpenAI API key configured).

Data: `codebase/data/hippoCorpusV2.csv` (6854 stories); 50 % subsample exactly as the README:

1. **Main runs (HF backend, `codebase/scripts/hf_compute.py`, written by me)** — `run_all.sh`, `run_instruct.sh`:
   `python hf_compute.py --hf-model <id> --name <name> --shuffle --seed 1 --maxcount 3425 [--no-topic] [--chat llama|smolm]`.
   The released `core.compute_sequentiality`, `utils.sent/prepare_contexts/load_dataset` and
   `OpenAIModel._apply_chat_template` are used unchanged; only the probability backend is replaced: every
   (context, target) request the released code makes is recorded, scored in large batches on the GPU in bf16
   (full_text = prompt + " " + target, the first target token is the one whose cumulative character end reaches
   len(prompt) — the same rule as `_get_logprob` — and the first token of an un-prompted text has no log-prob, as with
   echo), then fed back into the released code. Validated against unbatched HF scoring (differences ≈ bf16 noise).
   Reason: the released backend makes one HTTP request per sentence/window with a 50 ms sleep
   (~137 requests/story, ~100–200 stories/h per run); 14 model×condition runs at full scale would take > 10 days.
2. **BOS-bug emulation** (`run_emulate.sh`, flag `--emulate-llamacpp-bos`): same, but the BOS piece text is counted in
   the character reconstruction exactly as the released `model.py` does with the fork's echoed tokens.
3. **Unmodified released pipeline** (`run_released_resume.sh`): built the README's llama.cpp fork
   (`fo40225/llama.cpp@v1_completions_echo`, CUDA, sm_90), converted+quantised Llama-3.1-8B and Qwen3-0.6B-Base to
   Q4_K_M, ran `llama-server -m <gguf> -ngl 999 -c 1024 --port P -fa` and the released
   `compute.py --model <name> --port P --shuffle --maxcount N [--no-topic]` with no code changes, sharded into
   125-story blocks (16 server/client pairs) by pre-filling each shard's checkpoint CSV with placeholder rows so that
   compute.py's own resume logic starts at the right offset. Scale: first 1000 stories of the subsample for Llama
   no-topic, first 500 for Llama with-topic and Qwen3-0.6B no-topic.
4. **Ablation** (`run_ablation.sh`): post-trained `Qwen/Qwen3-0.6B` and `Qwen/Qwen3-8B` scored without chat template
   (the only official Qwen3 GGUFs are of the post-trained models; the paper's "Qwen 3 base" GGUF provenance is unknown).
5. Analysis: `hedges_tables.py` (Hedges' g with small-sample correction, Welch t-test, median over the 10 windows,
   as in Table A1 captions; decompositions from extra length-normalised NLL columns my wrapper writes),
   `compare_released.py`; the released `analyze.py` (Student t + Cohen's d) was also run (`results/analyze_released_*.txt`).

Differences from the paper's setup: bf16 instead of 4-bit for the main numbers (4-bit only in step 3); HF checkpoints
chosen by me; no GPT-3; instruct models only Llama-3.1-8B-Instruct and SmolLM3-3B (the release has chat templates only
for these two — Qwen3/Mistral instruct templates are not implemented); no CONLIT / covariate analyses.

## Discrepancies

1. **code_vs_paper (major, affects results)** — `scripts/model.py::OpenAIModel._get_logprob` + the README's llama.cpp fork.
   The fork echoes the BOS piece (`<|begin_of_text|>`, 17 chars; `<s>` for Mistral) as a token. The character
   reconstruction that decides how many prompt tokens to skip counts that text, so for BOS models the last 1–3 tokens of
   the *context/topic* are summed into the target sentence's log-prob. The paper's Eq. 1–2/5 score only s_i's tokens.
   Verified on the real fork: for `ctx="… yesterday afternoon."`, `tgt="We bought some apples."` the
   released code scores ` yesterday afternoon .` + target. Effect: Llama no-topic imag-vs-rec g = +0.22 (correct)
   becomes −0.08 (released) / −0.10 (paper); with-topic 0.64 becomes 0.35 (released) / 0.43 (paper).
   Mean seq_h1 for Llama no-topic: +1.05 (correct) vs −0.06 (released).
2. **code_vs_paper (major, small effect)** — same function. The fork returns one generated token despite `max_tokens=0`.
   Its entry in `token_logprobs` is a *probability* (e.g. 0.147), and it is summed into every target score.
3. **code_vs_paper (major, affects results)** — No-topic baseline (Eq. 5). With an empty prompt the first token of
   s_i has no log-prob (OpenAI-style echo returns None) for models without BOS (GPT-2, Qwen, SmolLM). NLL∅ therefore omits
   the first word, NLLC∅ includes it, and both are divided by the same word count. This biases SEQ′ upward and
   differently across models (mean no-topic seq ≈ 0.25–1.5 depending on the model; Fig. 2 top row).
4. **code_vs_paper (minor)** — `scripts/analyze.py` runs Student t-tests with Cohen's d per window. The paper reports Welch
   t-tests with Hedges' g, medians over windows (Tables A1–A9). No script producing the paper's tables/figures is released.
5. **code_vs_paper (minor)** — `core._compute_window_sequentiality`: for h>0, sentences 1..h−1 are skipped, but sentence 0
   is always included with SEQ = 0. Eq. 4 averages SEQ over all n_d sentences.
6. **code_vs_paper (minor)** — the paper says the open models were run 4-bit with llama.cpp. 4-bit Q4_K_M quantisation of
   Qwen3-0.6B-Base gives the 2nd token of un-prompted text log-prob ≈ −22 (f16 GGUF / HF bf16: ≈ −7). This inflates
   NLL∅ and no-topic SEQ′ (released mean seq_h1 1.70 vs 0.44 in bf16; g 0.33 vs 0.07 on the same 500 stories).
   This is not a code bug but a model-setting artifact that drives the paper's "Qwen consistently positive" finding.
7. **code_vs_paper (minor)** — `compute.py --seed` help says "default: 2025" but the default is 1 (`utils.load_dataset`'s
   default is 2025). The paper does not state the seed or which 50 % subsample was used.
8. **paper_internal** — Appendix A text says the instruct models were evaluated "at h ∈ {0, 1, 3, 9}", but the Table A7/A8
   captions say h ∈ {1, 3, 9}. Table A7 is "median" g, Table A8 is "mean" g.
9. **paper_internal** — Table A7, "No Topic Ret. vs Rec." row: the only two reported values are −0.021 and 0.014, yet
   "Inst Mean" = −0.025 (their mean is −0.004).
10. **paper_internal** — Footnote 1 / Sec. 1 says "We release our code and data", but the repository contains only HippoCorpus
    (no CONLIT passages, no covariate/regression code).

## Codebase completeness: MISSING_SCRIPTS

The release (`scripts/compute.py, core.py, model.py, utils.py, analyze.py, convert.py`, `data/hippoCorpusV2.csv`)
