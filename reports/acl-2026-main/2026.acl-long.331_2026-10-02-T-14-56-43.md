## 1. What the paper claims and what was released

TNR is a benchmark with ~94k QA–FV pairs built from ICEWS. Each pair has a forward question (QA) and a backward claim to verify (FV). The paper defines a **Consistency Rate (CR)**: the fraction of pairs where both QA and FV are correct. The main result is **Table 3**: QA, FV and CR for 6 open-source LLMs (Llama-3-8B, Qwen3-8B, Qwen3-14B, QwQ-32B, Qwen3-32B, Qwen2.5-72B) and 3 API models. Scores are given Overall and for {Simple, Medium, Hard} × {Temp-Rel, Temp-Num}, all with CoT prompting (Appendix H, Fig. 8/10), temperature 0 and 20 context facts per item. Section 4.3 then makes these claims:
- (a) There are notable QA/FV discrepancies, and CR is well below both QA and FV.
- (b) Qwen3-32B has the highest CR among open-source models, above Qwen2.5-72B.
- (c) Small models (Llama-8B) drop sharply in CR despite moderate FV.
- (d) Consistency is harder to keep on temporal-numerical tasks than on temporal-relational ones.
- (e) CR falls as difficulty rises.

**Release:** `train.json`, `dev.json` and `test.json` (git-LFS) plus a README. There is **no evaluation code**: no prompts, no answer-format instructions, no answer parser, no metric implementation and no model-running scripts. The dataset was **replaced on 2026-08-25** ("Update dataset release"), after the paper's experiments. The current version has separate `qa_context`/`fv_context` fields. The older version, which I recovered from git history, has one shared `context` field.

## 2. What I did

The pipeline (all in `tnr_eval/`) was written by me from the paper's description:
- `run_tnr.py`: builds the CoT QA/FV prompts verbatim from Appendix H (Fig. 8 and Fig. 10). The paper does not give the "{answer format instruction}" text, so I wrote it per answer type: entity/date lists separated by ` | `, numbers with up to 2 decimals, the option letter for 6-way multiple choice, an Allen relation name, ranking lists, and True/False. Every prompt also asks for a final `Final Answer: ...` line. The script runs vLLM 0.30.0 in bf16 with greedy decoding (temperature 0) via each model's chat template.
- `score_tnr.py`: implements Sec. 4.1:
  - **QA:** normalized exact match (lowercase, whitespace removed); numbers rounded to 1 decimal; option-level F1 with the subset indicator for multiple choice.
  - **FV:** exact match on True/False.
  - **CR:** Eq. 5.
  - **Multi-gold lists:** about 1,000 test questions have more than one gold answer, and the paper does not say how they are scored. My primary scorer (**`any`**) counts a non-empty predicted set that is a subset of the gold set as correct. I also report `f1` (Eq. 4 applied to answer sets; CR needs F1 = 1) and `exact` (set equality). `f1` is 0.5–4 points lower for QA/CR; FV is unaffected.
- `compare.py`, `claims.py`, `make_status.py`, `simulate_cap.py`: build the comparison tables, check the claims, and run the generation-length sensitivity analysis.
- Drivers: `run_all.sh` (current test set) and `run_old.sh` (old pre-2026-08-25 test set). Raw generations are in `preds/*.jsonl`, scores in `results/*.json|txt`, logs in `logs/`.

Commands, run from the attempt dir after `source envsetup.sh`:
```
python tnr_eval/run_tnr.py --model <hf_id> --out preds/<run>.jsonl [--enable_thinking 0|1] [--quantization fp8 --max_model_len 8192 --max_tokens 4096]
python tnr_eval/score_tnr.py preds/<run>.jsonl --json_out results/<run>.json [--data data/old_test_conv.json]
PYTHONPATH=tnr_eval python tnr_eval/compare.py any
```

**Settings that differ from the paper, or that the paper leaves unspecified:**
- **Qwen3 thinking mode.** Not stated in the paper, so I ran both. *Thinking disabled* is the main setting: it is the one that matches the paper (see §4).
- **Generation length.** Not stated. I used max 8,192 new tokens (16k context); 4,096 for Llama-3-8B, which has an 8k context window, and for Qwen2.5-72B; 14,000 for QwQ-32B.
- **Qwen2.5-72B-Instruct** ran with **FP8 weight quantization** (vLLM `--quantization fp8`). In bf16 it is about 145 GB and does not fit on one 141 GB H200; the paper used 4×A6000 without quantization.
- **"Llama-3-8B".** Table 3 says Llama-3-8B, but the text says LLaMA-3.1-8B. I ran both Meta-Llama-3-8B-Instruct (main) and Llama-3.1-8B-Instruct.
- **Answer-format instructions** are my own (see above).
- **Data.** Main runs use the current released test split. Its per-type counts match Table 2 exactly. Supplementary runs use the old test split.
- **Closed-source models** (GPT-5, GPT-4o-mini, DeepSeek-V3.1) were not run: no API keys.

## 4. Why the numbers differ (diagnosis)

1. **Unreported inference settings:** thinking mode, generation-length cap, the answer-format instructions, and the answer parser. My sensitivity analysis shows these alone can move scores by 20–40 points. The paper's Qwen3-8B per-column QA pattern (e.g. Hard Temp-Rel 67.86, the highest column) matches our thinking-off run (71.79, also the highest). This suggests the paper ran Qwen3 with thinking off. QwQ cannot turn thinking off, so its low paper scores point to a generation cap or parsing failures.
2. **Data version:** the release was rebuilt after the paper. QA and FV now have separate contexts, and the evidence bug for Relative Reasoning is fixed. Measured effect: about 1–4 points overall.
3. **Hardware/precision:** FP8 for Qwen2.5-72B. The expected effect is small (under 1 point typically).
4. **Scorer choice for multi-answer questions:** 0.5–4 points (see the `f1`/`exact` variants).
