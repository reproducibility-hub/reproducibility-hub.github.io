# Reproduction report: 2026.acl-short.53 — One-step Nonautoregressive NLG with Shortcut Flow Matching Models

**Verdict: PARTIALLY_REPRODUCED.** Result match `MIXED` after my fixes. As released it is `TREND_MATCH`, but only
because of an evaluation artifact: the released shortcut model never learns. Coverage `SCALED_DOWN`, codebase
completeness `MAJOR_FIXES`.

## TL;DR
- **The released shortcut-model code does not learn one-step generation** on any of the three datasets. Within a few
  thousand steps its one-step outputs degenerate (e.g. "quentin quentin ...", or an immediate `[SEP]`). With a
  corrected extraction its test BLEU stays ≤ 1.5 at every checkpoint. Multi-step sampling (NDS up to 256) doesn't help.
- **The released evaluation scores these degenerate outputs as copies of the source.**
  `shortcutfm/decoding/text_processing.py::_process_prediction_text` splits the decoded sequence on `[CLS]`. When the
  predicted target segment doesn't start with `[CLS]`, it falls back to `cls_parts[-1].split(sep)[0]`, i.e. the source
  sentence. With the released checkpoint selection (max **test** BLEU over all checkpoints,
  `analysis/metrics_analysis.py::build_best_df`), the released pipeline reports exactly the "copy the source" scores
  for the shortcut model:
  - QQP: 27.72 BLEU / 0.8364 BERTScore (paper 19.40 / 0.8143)
  - PAWS: 64.65 / 0.9436 (paper 42.71 / 0.8634)
  - ParaSCI: 40.55 / 0.8178 (paper 13.55 / 0.7843)

  As released, the shortcut model therefore "beats" the baseline, but only because the source is scored as its output.
- **Training bug.** `criteria.py::CompositeCriterion._prepare_batches` builds the self-consistency batch with
  `x_start=embeddings[num_flow_matching_elems:]` (other examples), while its `seqs`/`x_t` come from
  `embeddings[:num_consistency_elems]`. So the second half-step of every self-consistency target (Eq. 8) is computed
  with the source part of the input replaced by another example's source. With a one-line, opt-in fix
  (`SHORTCUTFM_FIX_CONSISTENCY_XSTART=1`) the shortcut model trains normally.
- **With both fixes, results are mixed** and well short of the claimed large improvement (BLEU "more than doubling" on
  PAWS and ParaSCI). The shortcut model wins on PAWS, is split on QQP, and loses on ParaSCI:
  - QQP: BLEU 13.13 vs 15.03 (worse); BERTScore 0.648 vs 0.607
  - PAWS: BLEU 27.64 vs 18.39; BERTScore 0.712 vs 0.618
  - ParaSCI: BLEU 1.90 vs 10.31; BERTScore 0.418 vs 0.529. At matched steps (10k) the baseline has 5.90 BLEU /
    0.503 BERTScore, so the shortcut model is still clearly worse.

  All numbers are far below the paper's shortcut numbers.
- The flow-matching baselines reproduce the paper's baseline numbers reasonably well:
  - QQP: within 1 BLEU
  - PAWS: 2.6 BLEU lower at 15k steps
  - ParaSCI: 4.3 BLEU **higher** (`BASELINE_STRONGER_THAN_REPORTED`)

## Why it is not reproduced
1. The released shortcut training is broken by the consistency-batch `x_start` misalignment. The model collapses at
   one step, and even at many steps.
2. The released evaluation hides the collapse: degenerate predictions are scored as source copies, which on these
   paraphrase datasets score very high, and test-set checkpoint selection then picks the copy-dominated checkpoints.
3. After fixing both, the claimed improvement holds only partly:
   - PAWS: clear gain, but 1.5x rather than the claimed 2x (27.6 vs 18.4 BLEU).
   - QQP: lower BLEU (13.1 vs 15.0), slightly higher BERTScore/ROUGE.
   - ParaSCI: clearly worse (1.9 vs 10.3 BLEU; 1.9 vs 5.9 at matched 10k steps).

   Absolute shortcut numbers stay far below the reported 19.4 / 42.7 / 13.6 BLEU and 0.81–0.86 BERTScore. Overall
   result match: `MIXED` (wins on one dataset, loses on another), and none of the paper's shortcut numbers is reached.

Caveat: my runs are shorter than the paper's (10–25k vs 40–60k steps), although the paper's own Table 2 lists 21k
training steps for its QQP shortcut model. The fixed shortcut models were still improving slowly at the end (PAWS
25–28 BLEU from 9k to 15k; QQP 12–13 BLEU from 11k to 15k; ParaSCI 0.3 → 1.9 BLEU from 5k to 9k, when the baseline
was at 4–6). I can't exclude that longer training would close part of the gap. Only one seed per setting was run; the
QQP test set has just 100 sentences.

## Codebase completeness: `MAJOR_FIXES`
The method, training, generation and evaluation pipelines are all released, and the public data is obtainable. But the
shortcut model's results depend on two bugs I had to fix: a training-logic bug and an evaluation bug that silently
changes the numbers. My edits to `./codebase` are left uncommitted:
- `scripts/run_tokenize.py`: removed a stray `z` before `)` in the ParaSCI branch (SyntaxError; the script didn't run).
  The README's CLI flags (`--data_dir`, `--tokenizer`) don't exist; I used `--dataset/--max_seq_length` and the
  hard-coded `datasets/raw/<dataset>` layout (symlinks to `./downloads`).
- `shortcutfm/train/pl/train_unit.py::_process_timestep_losses`: move timesteps/losses to CPU once instead of a
  per-element `.item()` (logging only, about 5% faster; no effect on training).
- `shortcutfm/criteria.py::CompositeCriterion._prepare_batches`: opt-in fix

## Discrepancies
1. **code_vs_paper, major, affects results**: `decoding/text_processing.py::_process_prediction_text`. The paper scores
   the generated paraphrase. The code returns the **source sentence** as the hypothesis whenever the predicted target
   segment lacks a leading `[CLS]`.
2. **code_vs_paper, major, affects results**: `criteria.py::CompositeCriterion._prepare_batches`. The paper's Eq. 8 /
   Alg. 1 computes the two half-steps on the same example. The code sets the consistency batch's `x_start` to
   `embeddings[num_fm:]` (different examples than its `x_t`), so step 2 is conditioned on a wrong source. In addition,
   the flow-matching and consistency sub-batches overlap (both start at index 0), and the last 25% of each batch is
   used only by the rounding loss.
3. **code_vs_paper, major, affects results**: `analysis/metrics_analysis.py::build_best_df` and the generation configs
   (`split: test`, one generation per saved checkpoint) select the reported checkpoint by maximum **test** BLEU. The
   paper doesn't mention checkpoint selection on the test set.
4. **code_vs_paper, major, affects results**: the baseline is not the shortcut model without shortcuts. The baseline
   uses 128-d embeddings normalised onto the unit sphere after every step (`baseline.yaml`: `input_dims 128`,
   `normalize_embeddings: true`, `__main__.py` `baseline_config`). The shortcut model uses 768-d unnormalised
   embeddings. The paper (App. A) describes a single 768-d input/output configuration.
5. **code_vs_paper, minor**: the released training configs use `max_steps: 50000` (LR schedule over 60000); the paper
   says a maximum of 60,000 update steps.
6. **code_vs_paper, minor**: the QQP generation configs set `use_ema_weights: false`, while the paper says EMA is
   applied (the default in `GenerationConfig` is `true`).
7. **code_vs_paper, minor, no effect**: the README tokenization commands use flags that `scripts/run_tokenize.py` does
   not accept, and the script has a syntax error.
