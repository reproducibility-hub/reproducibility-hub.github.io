## 1. What the paper claims (target)
Table 1, the main result: Pass@16 on the *difficult subset* (problems where the teacher's greedy decode fails). Teacher is Qwen3-4B-Instruct-2507, student is Gemma-3-4B-IT, T=0.7, 8192-token context. Paper numbers:

- Self-consistency baseline: 38.5 / 35.3 / 33.7 / 11.7 / 14.5 (avg 26.7).
- SOE: 76.9 / 70.6 / 45.9 / 15.5 / 20.8 (avg 45.9).
- Benchmark order: AIME24, AIME25, MATH-500, OlympiadBench, Omni-Math(hard).
- The abstract summarises this as "+62.4% average accuracy". It also claims "+113.7% average sampling efficiency" (Fig. 5).

## 2. What the release contains
- `step1_baseline_gen.py`: teacher greedy decode, vLLM.
- `step2_filter_error.py`: keeps the failures.
- `step3_soe_intervention.py`: the core method, in HF transformers. It truncates at the first three `### Step` headers, takes 8 teacher Monte-Carlo samples of 8 tokens (T=1.0), and 8 student probes of 8 tokens (T=1.0). It embeds both by mean last-layer teacher hidden state, runs SVD on the centred teacher samples, and picks the probe with the largest orthogonal residual ratio, then stitches it in.
- `step4_evaluate.py`: the teacher continues from each stitched context. It uses n=1, **max_tokens hard-coded to 2048**, and scores only `outputs[0]`, reporting per-record accuracy.
- `utils.py`: the evaluator (boxed extraction plus string normalisation).
- **Missing**: the self-consistency baseline, any Pass@16 computation or aggregation of the up-to-3 contexts per problem, the distinct-solution / efficiency metric, the PRM baseline, and the random-probe ablation. No data is shipped; the README says to bring public jsonl files.

## 3. What I ran (all in `env/`, Python 3.11)
The environment was vllm 0.31.0, torch 2.13 (cu13), transformers 5.17. Data was public HF datasets, written to `data/*.jsonl` by `scripts/prep_data.py`:
- AIME24: Maxwell-Jia/AIME_2024 (30)
- AIME25: math-ai/aime25 (30)
- MATH-500: HuggingFaceH4/MATH-500 (500)
- OlympiadBench: Hothan/OlympiadBench `OE_TO_maths_en_COMP` (674; the paper does not say which subset)
- Omni-Math: KbsdJames/Omni-MATH with difficulty ≥ 8 (452)

Pipeline (`scripts/run_step1.sh`, `scripts/pipeline.sh`, `scripts/post.sh`, `scripts/chat.sh`):
1. Released step 1 + step 2 on each dataset with `--max_tokens 7680` (the paper uses an 8192 context; the README's 1024 would truncate almost everything). Env var `VLLM_USE_FLASHINFER_SAMPLER=0` was set because FlashInfer JIT needs nvcc.
2. Released step 3 with README arguments (`--num_samples 8 --max_new_tokens 8 --batch_size 32`). `flash_attention_2` was replaced by `sdpa` because flash-attn is not installable for torch 2.13/cu13.
3. **Self-consistency baseline** (`scripts/sample_eval.py --mode baseline`, written by me): 16 teacher samples from the original step-1 prompt. Settings: T=0.7, top_p=0.95, max_tokens = 8192 − prompt length, vLLM seed 42.
4. **SOE** (`--mode soe`): exactly the step-4 prompt format (`SYSTEM\n\nProblem: …\n\nContext:\n<prefix+probe>`), with 16 samples per stitched context and the same sampling settings as the baseline, apart from the 8192 cap.
5. **Pass@16** (`scripts/aggregate.py`): the denominator is the full difficult subset. For SOE, 16 samples per problem are taken round-robin over that problem's ≤3 contexts, so the budget matches the baseline. A failure with no `### Step` header gets no SOE context and counts as unsolved (8 + 13 + 5 + 1 + 1 such problems; numbers excluding them are also given below).
6. Correctness uses the **released evaluator** (step-4 rule). As a secondary check I also used a strict `math_verify` comparison of the last `\boxed{}`.
7. Extras:
   - Random-probe ablation (`--mode random`, Table 8) on AIME24/25 and MATH-500.
   - Released step 4 as-is.
   - Student greedy (Table 2).
   - AIME25 seeds 1024/2024 (Table 10; step 3 re-run because it is unseeded).
   - Distinct correct solutions using jina-embeddings-v2-base-en with τ ∈ {0.8, 0.9, 0.95, 1.0} (`scripts/distinct.py`, Table 9 / Fig. 5). This runs with transformers 4.44 from `jina_libs/`, because the jina remote code is incompatible with transformers 5.
   - Paired sign test (`scripts/paired.py`).
   - Chat-template sensitivity check (`--chat`).

Settings that differ from or are unspecified in the paper:
- The OlympiadBench subset choice.
- top_p=0.95 for both arms (taken from step 4; the paper only says T=0.7).
- How the 16 SOE samples are allocated over the ≤3 contexts (not specified in the paper).
- vLLM 0.31 / sdpa instead of the authors' (unknown) versions with flash-attn.

## 5. Why it is not reproduced
- The released pipeline runs, and the SOE arm alone lands near the paper on several benchmarks: MATH-500 46.4 vs 45.9, Omni 19.5 vs 20.8.
- But the same teacher under plain 16-sample self-consistency, with identical sampling settings, is **much stronger than the paper reports**: +28 / +24 / +20 / +22 / +3 points.
- It matches or beats SOE on 4 of 5 benchmarks, so the claimed +62% average improvement disappears (ours: −12%).
- This holds under the released evaluator and under strict math_verify, across three seeds, and when excluding problems without truncation points.
- SOE's orthogonality-based selection is no better than a random student probe.
- The release has no baseline or Pass@16 code, so I cannot check how the authors obtained their baseline numbers. The large gap suggests their baseline used a different (weaker) configuration than what the paper describes as "identical conditions".

Issues noted in the released code:
- Step 4 hard-codes `max_tokens=2048` and scores only `outputs[0]`, even when `--n_samples` > 1.
- There is no Pass@16 aggregation, no baseline, no efficiency metric, and no PRM baseline.
- `MathEvaluator.is_equivalent` accepts any prediction that *contains* the normalised gold string (`norm_gt in norm_pred`; e.g. gold "1" matches "10").
- Step 1 additionally falls back to searching the gold answer anywhere in the full generated text when there is no `\boxed{}`. This marks some unanswered problems as correct; on AIME24, 2 of 18 "correct" greedy outputs had no boxed answer. It shrinks the difficult subset.
- No chat template is applied anywhere. Generations are raw completions that often loop until the length cap (e.g. repeated `\boxed{23}`).
