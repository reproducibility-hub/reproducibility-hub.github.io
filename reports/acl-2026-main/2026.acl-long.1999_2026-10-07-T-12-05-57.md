**Bottom line.** HeteroCache's own accuracy numbers reproduce: every Avg/Overall number is within 1 point of the paper. The claim that it stays close to FullAttention at 30–50% KV memory also holds. The paper's claim that HeteroCache "significantly outperforms existing state-of-the-art baselines" does **not** hold against the one baseline the release implements, CAKE. Run through the released pipeline at the same measured memory budget, CAKE is much stronger than the paper reports. In short, HeteroCache and CAKE are statistically indistinguishable here.

### Settings that differ from the paper
- InfiniteBench (Table 3) is scaled down. It uses the first 120 examples of each task (first 50 of 103 for En.Sum, and all 229 for En.MC); only HeteroCache and FullKV were run, on Llama only. Reason: at 128K tokens one example takes 20–35 s with two jobs sharing the GPU, so the full 2,996 examples × methods did not fit in the 48 h budget.
- Not run:
  - DeepSeek-R1-Distill-Llama-8B (Table 2, third block): needs 4-bit quantization and up to 2K–10K sampled reasoning tokens per item, and the model was not cached.
  - Quest, ShadowKV and OmniKV: the release does not implement them; the README points to external repos with no configs. Paper claims against them are NOT_COMPARABLE.
  - Latency (Fig. 4, the "3× speed-up at 224K" claim), NIAH (Fig. 3) and ablations (Tables 4–5, Fig. 5).
- Hardware: H200 instead of A100. This does not affect accuracy numbers.

### Additional check: offline calibration
I re-ran `tools/get_weights.py` and `tools/get_cluster.py` with the README command (Llama, 5,000 tokens, 100 decode steps, τ = 0.5). ### Observation (not scored): decode overhead
On LongBench's short contexts (≤ ~30K tokens), HeteroCache decoding was markedly slower than FullKV in the released implementation. On the code tasks it took ~12–15 s/example vs ~4 s; on gov_report ~77 s vs ~48 s, with GPU sharing similar in both cases. The likely cause is per-layer Python work and host syncs every 5 steps in `decode_select`. The paper's latency claim is for 128K–224K contexts, which I did not measure.

## Why not fully reproduced
1. The claimed advantage over CAKE disappears. The released CAKE baseline comes out 0.9–3.1 points stronger than the paper reports on LongBench, and 1.9 points stronger on Qwen LongBench v2. Paper vs ours: Llama LongBench 49.16 vs 50.07; Qwen LongBench 46.92 vs 50.04 (Multi-Doc QA 42.95 vs 52.45); Qwen LongBench v2 31.6 vs 33.5. It does so at the same verified KV budget. I found no bug or config difference that explains the gap; the paper may have produced its CAKE numbers with different code or settings. → flag BASELINE_STRONGER_THAN_REPORTED.
2. Coverage is scaled down: InfiniteBench is a subset; DeepSeek rows, latency and external baselines were not run (compute/time limits, and the external baselines are not in the release).
3. Llama LongBench Multi-Doc QA is about 3.8 points higher than the paper for all three methods (e.g. FullKV 44.65 vs 40.82); the other categories match. This is a uniform offset with an unknown cause (possibly a different data version or truncation in the authors' run), and it does not change rankings.
