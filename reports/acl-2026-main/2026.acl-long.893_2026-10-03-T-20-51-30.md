# Reproduction report: PALU — "Maximizing Local Entropy Where It Matters: Prefix-Aware Localized LLM Unlearning" (2026.acl-long.893)

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): MIXED**. As released: **MIXED** too. No source code was edited; only config, a data-path symlink and environment variables were changed.
- **Coverage: SUBSET.** Covered: Table 1 PALU rows (TOFU forget05) for both models, Figure 3 PALU points (forget01/forget10, both models), and part of the Table 6 / Figure 4 ablations. All at the paper's scale. Not covered: MUSE (Table 4, appendix; no MUSE pipeline in the release) and all baselines (no code or configs released).
- **Codebase completeness: MINOR_FIXES**

Summary:
- **Llama-2-7B (main setting).** The released code reproduces PALU's headline FQ and MU on TOFU forget05: FQ 0.7126 / MU 0.6241 vs. the paper's 0.7126 / 0.6238 (best epoch). Truth-ratio metrics also match. But:
  - Exact Memorization (0.85 vs 0.59) does not match.
  - The MIA AUCs of Table 2 (≈0.78 vs 0.18) do not match.
  - Fluency is ≈10% lower.
- **Llama-3.1-8B.**
  - FQ is lower: 0.71 at the final epoch / 0.79 at the best epoch, vs 0.9238.
  - MU is higher than reported: 0.70 vs 0.62.
  - Fluency collapses: 0.33–0.40 vs 0.87. Forget-set generations contain garbage tokens at the sensitive positions (e.g. `"Hina Ameen primarily writes in the?)\n…/stdcoding"`). The paper attributes this kind of output to TPO, not PALU (Table 9).
- **Ablations.** The trends behind the dual-sparsity claims hold: K=1 collapses utility; K=All and N=1 are worse than K=5000 / N=3; first-3 tokens beats all tokens.
- **Hyperparameters.** The paper does not report the final lr, λ or selected epoch. The released script is a 600-config grid per split. Our best-matching value, λ=0.5, comes from the script's grid, not from the paper's stated grid λ∈{1,2,5,10}. Results are very sensitive to lr, λ and epoch.

## What was done

1. Read the paper (PDF). Main claim: Table 1 (TOFU forget05; PALU vs baselines on Llama-2-7B-chat and Llama-3.1-8B-Instruct). Also Fig. 3 (forget01/10), Fig. 4 / Tables 3, 6 (ablations), Table 2 (MIA AUCs), Table 4 (MUSE, appendix).
2. Cloned https://github.com/nxZhai/PALU (commit 8c3fea6) into `./codebase`. It is a trimmed fork of Open-Unlearning, containing:
   - the PALU trainer (`src/trainer/unlearn/palu.py`)
   - GPT-annotated forget sets (`data/palu/forget{01,05,10}_with_common_words_gpt`)
   - Open-Unlearning's official Original/Retain eval JSONs (`saves/eval`)
   - two grid-search scripts (`scripts/unlearn/tofu/train_tofu_palu_llama{2,3}.sh`).
3. Environment: `conda create -p ./env python=3.11.13`, `pip install -r requirements.txt`, plus the flash-attn 2.7.4.post1 wheel from `env_setup.sh` (torch 2.4.1, transformers 4.45.1).
4. Models/data from HF:
   - `open-unlearning/tofu_Llama-2-7b-chat-hf_full`
   - `open-unlearning/tofu_Llama-3.1-8B-Instruct_full`
   - `locuslab/TOFU`
   - the gibberish classifier `madhurjindal/autonlp-Gibberish-Detector-492513457`
5. Runs, all on 1×H200:
   - `runs/run_palu.sh` is a single-config copy of the released grid script, with identical arguments: `experiment=unlearn/tofu/tpo trainer=PALU`, per-device batch 8 × grad-acc 4 = 32, 10 epochs, paged AdamW, 1-epoch warmup, wd 0.01, `retain_loss_type=NLL`, `gamma=1`, `target_mode=mean`, eval every epoch.
   - Its arguments are `MODEL SPLIT LR ALPHA TOPK FIRST_N [EPOCHS] [SEED]`.
   - `runs/queue_runner.sh` runs the lines of `runs/queue.txt` sequentially.
   - Example: `bash runs/run_palu.sh Llama-2-7b-chat-hf 05 2e-5 0.5 5000 3`
6. Hyperparameters:
   - Fixed to the paper's stated values: K=5000, N=3, c = global mean of the current logits.
   - lr ∈ {1e-5 (Llama-2 only, λ=1), 2e-5, 5e-5} × λ ∈ {1, 2, 5, 10} (the paper's grid) plus λ ∈ {0.5, 0.2} (the released script's grid).
   - Totals: 12 configs for Llama-2, 10 configs for Llama-3.1.
7. Configuration selection: the config with the highest **final-epoch** FQ on forget05 was lr=2e-5, λ=0.5 for both models. That config was then used for:
   - seeds 1 and 2,
   - forget01/forget10,
   - the ablations.
8. Per-epoch metrics for every run are in `all_results.json`, `runs/summary_all_runs.txt` and `runs/summary_quick.txt`. Raw per-sample evals are in `runs/out/<model>/<split>/<cfg>/checkpoint-*/evals/TOFU_EVAL.json`.

The paper does not say which epoch it reports. The README says evaluation runs every epoch. Below, "final" means epoch 10 and "best" means the epoch with the highest FQ. Choosing the best epoch by FQ uses the test metric to pick the checkpoint.

### Settings that differ from the paper
- **Hardware:** 1 GPU with batch 8 × grad-acc 4 (exactly what the released script does) instead of 8×A800 with batch 32. The effective batch is the same.
- **Final lr/λ:** not reported. Selected by grid as described above. The selected λ=0.5 lies outside the paper's stated grid {1,2,5,10}.
- **Ablations:**
  - The paper says it sets the non-ablated dimension to "dense".
  - We ran: K=1 with N=All; K=All with N=3; N=1 with K=All; N=All with K=5000.
  - So our K=All point uses N=3, not N=All.
- **Baselines:** not run (GA/GD/DPO/NPO/SimNPO/PDU/TPO). The release has no code or configs for them, apart from bare GradAscent/GradDiff trainer classes without hyperparameters.
- **MUSE:** not run. There is no MUSE data loader, config or evaluator in the release, although the README mentions `configs/eval/muse.yaml`.

### Claims vs. our evidence
- **"PALU achieves the best FQ/MU trade-off on TOFU" (Table 1).**
  - Llama-2: PALU's own numbers reproduce. FQ 0.71 at the best epoch and 0.63 at the final epoch (3-seed mean 0.63), with MU ≈0.62–0.63.
  - Llama-3.1: FQ is lower than reported (0.71–0.79 vs 0.92), and Fluency collapses.
  - Superiority over baselines is **NOT_COMPARABLE**: no baseline code is released and we did not reimplement any.
  - Note that our Llama-3.1 FQ (0.71–0.79) is about the paper's own reported TPO number (0.7216). So the claimed 28% FQ gain over TPO would not show up with our PALU numbers.
- **"PALU preserves fluency / avoids garbled outputs" (Table 1 Fluency, Table 9).**
  - Not reproduced for Llama-3.1 (Fluency ≈0.35).
  - Partly reproduced for Llama-2 (0.73 vs 0.81).
- **EM and MIA (Table 2).** Not reproduced. PALU leaves teacher-forced memorization high (EM ≈0.85 for Llama-2 and ≈0.79 for Llama-3.1, vs 0.59/0.65 in the paper), and MIA AUCs stay well above 0.5.
- **Dual-sparsity ablations.** The directions reproduce.

## Discrepancies
1. **code_vs_paper (major, affects results).**
   - Where: `src/trainer/unlearn/palu.py` `compute_loss`, the KL on common tokens.
   - Paper (Eq. 4, Alg. 1): KL(P_θref ‖ P_θ).
   - Code: `sum(exp(logp_θ) * (logp_θ − logp_ref))` = KL(P_θ ‖ P_ref), i.e. the reverse KL.
2. **code_vs_paper (minor).**
   - Where: Appendix E vs `scripts/unlearn/tofu/train_tofu_palu_*.sh`.
   - Paper grid: lr ∈ {1e-5, 2e-5, 5e-5}, λ ∈ {1, 2, 5, 10}.
   - Script grid: lr ∈ {1e-5, 2e-5, 3e-5, 4e-5, 5e-5}, α(λ) ∈ {1, 2, 5, 0.5, 0.2}, plus top-K ∈ {1, 1000, 5000, 10000} and first-N ∈ {1, 2, 3, 4, 5, 10}.
   - The config that reproduces the Llama-2 Table 1 FQ/MU uses λ=0.5, outside the paper's grid.
3. **code_vs_paper (minor).**
   - Where: paper overall vs release.
   - Neither the paper nor the code states the selected lr/λ/epoch for the reported numbers.
   - The released script evaluates every epoch. The numbers depend strongly on which epoch is picked (e.g. Llama-2 FQ 0.7126 at epoch 8 vs 0.6284 at epoch 10).
4. **code_vs_paper (minor).** The README references `configs/eval/muse.yaml` and MUSE evaluation; neither exists in the repo.
5. **paper_internal.**
   - §5.3 text: with K=1 "the MU suffers from catastrophic collapse, dropping to nearly 1×10⁻⁴".
   - Figure 4(a): at K=1, FQ ≈1e-4 and MU ≈0.36. Also MU ≈0.18 at K=1K, which contradicts "performance recovers rapidly as K increases".
6. **paper_internal (minor).** Table 2, Llama-2: the GA and GD rows are identical in all four columns (0.9243 / 0.8202 / 0.9603 / 0.7103). This is likely a copy error.
