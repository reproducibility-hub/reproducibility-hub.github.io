The representation-geometry results reproduce very closely with the released code. These are the step-specific probes (Fig 1b / Table 1 / Table 6), the step-count statistics (Table 10), the train-split trajectory distances (Fig 2a), and the seed-averaged correctness predictors (Tables 3 and 8).

The inference-time intervention results reproduce only partly:

- **Fig 3a (trajectory steering):** our largest change is +2.3 points for 6-step problems (paper +7.6), and 0.0 for 7-step problems (paper +7.7). The headline "most effective on long chains" gains do not reproduce.

## 3. Deviations from the paper's setup (scale-downs and settings)
- **Table 4 scaled down.** As released, each intervened question needs a baseline `generate` plus ~1,024 uncached full forward passes. The Instruct model never emits EOS with this raw (no chat template) prompt and loops until the 1,024-token cap. That is ~50 s per question alone and ~3–5 min with GPU sharing, so 6 configs × 1,319 questions (≈110+ GPU-h) was impossible.
  - **Gated numbers:** I ran each intervention on all 114 test questions flagged by the predictor (8.8% of the 1,296 test questions with Step/#### positions; the paper flags 12.3%). Gated accuracy on the full test set is then exact, because unflagged questions keep their baseline answer.
  - **Always-on numbers:** estimated as the exact flagged-set contribution plus the mean change on a random 80-question test subset (seed 0) restricted to unflagged questions (n≈73), scaled to the unflagged population. These carry substantial sampling error (±~4 points).
- **Predictor for gating:** `hash_pca` at layer 29 (the paper's peak layer; the paper does not say which predictor/layer gates Table 4).
- **Fig 3a:** trajectory-steering α is not stated in the paper, so I used the script default α = 0.5. For K=3 and K=4 only the first 100 test questions in the script's order were run (time).
- **Fig 2b:** odd layers only (`--quick`, 16 of 32 layers). Each `train_predictors.py` config takes ~10 min, and the released `mp.Pool` passes the 21 GB activation dict to every task, so it had to run with 1 worker. Paper averages are over all layers.
- **R1-Distill:** generated and probed on the **test** split only (1,319 questions; 1,191 usable). Base and Instruct were run on both splits. The paper's README suggests probes were trained on the 8,000-question train split for all models.
- **Generation batch size:** 256/128/64 instead of the default 16. Prompts are left-padded to a fixed 250 tokens, so the only effect is GPU numerics.
- **Not run:** freeform robustness (§3.5 / Tables 2, 7), MATH-500 / MMLU transfer (§4.4 / Table 5), shuffled-label control, length-balanced resampling (no script), step-count-only baseline (no script; the 0.6491 value is a hard-coded print).

As a clearly-labelled reconstruction, I used the released `intervene_all_steering.py` in `ALL_PROLONG_MID_N` mode: it adds α·s at every decoding step, with s = mean(answer-marker − step activation), layers 13–17. | α | reasoning length (tokens) | steps | accuracy |
|---|---|---|---|
| −0.4 (prolong) | 1024 (loops to cap) | 29.5 | 3.3% |
| −0.1 | 343 | 7.7 | 80.0% |
| +0.1 (shorten) | 211 | 4.1 | 80.0% |
| +0.4 | 0 (emits `####` immediately, repeatedly) | 0 | 0.0% |

Reasoning length moves monotonically with α in the claimed direction: toward the termination direction shortens, away prolongs. However, accuracy already drops 10 points at |α|=0.1 and collapses at |α|=0.4. The paper reports ~1% change for |α|≤0.4 and smooth control up to 0.8. Because the exact configuration had to be guessed (mode, layers, α normalisation), this is NOT_COMPARABLE.

## 5. Why not fully reproduced
1. **Compute:** the intervention scripts (Table 4, Fig 3a/3b) decode token by token without KV cache. Combined with the 1,024-token loops of the Instruct model, a full Table 4 would cost >100 GPU-h, so it was scaled down (§3). R1-Distill was run on the test split only; Fig 2b on odd layers only.
2. **Evaluation bugs in the released Table 4 pipeline** (§6): as released, gating never triggers, and text-injection runs are scored with a different answer extractor than the rest of the pipeline.
3. **Missing scripts:** Fig 3b (length control), step-count-only baseline, length-balanced resampling.
4. **Unspecified settings:** trajectory-steering α (Fig 3a); which predictor/layer gates Table 4.
5. Fig 3a's large K=6/7 gains did not appear with the defaults.

The released Pass-2 computes per-token logit-lens features for all 33 layers in Python loops: >12 min and 121 GB GPU for 8 questions, i.e. weeks for the dataset. None of these per-token artifacts are read by any downstream script; the per-question JSON fields that are used (`produced_text`, `full_seq_ids`, `dp1_idx`, `dp2_idx`, `produced_answer`, `gold_answer`) are identical. Performance-only.

Result-changing bug fix.

Scripts I wrote outside the release (in the attempt directory):
- `rescore_interventions.py`: re-scores text-injection result JSONs with the first-#### extractor (`extract_answer_after_hash`, used by the generation pipeline and `intervene_all_steering.py`). `intervene_text_injection.py` scores with `src.utils.extract_answer`. - `summarize_probes.py`, `summarize_pred.py`: read the released result JSONs.

Other issues noticed (not fixed):
- `train_predictors.py`: `--seed` is ignored (fixed 42). `mp.Pool` pickles the full ~21 GB activation dict for each task, so multi-worker runs are infeasible. The best-epoch weights are saved with a shallow `state_dict().copy()`, so the final rather than the best weights are restored.
- `logprob_entropy_baseline.py` prints the step-count baseline AUC (0.6491) as a hard-coded constant.
