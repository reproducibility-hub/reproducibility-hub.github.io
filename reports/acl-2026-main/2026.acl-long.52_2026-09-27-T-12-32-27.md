# Reproduction Report: Identifying the Periodicity of Information in Natural Language (2026.acl-long.52)

**Verdict: PARTIALLY_REPRODUCED**

## 1. Paper's main claims / target results

The paper introduces **AutoPeriod of Surprisal (APS)**: given a document's
token-surprisal (negative log-likelihood, NLL) sequence, APS (1) computes a
Lomb-Scargle periodogram and flags "period hints" whose power exceeds a
Monte-Carlo permutation threshold at a given confidence level (CL), then (2)
validates each hint via autocorrelation (ACF) hill-detection to produce
"valid periods." Central results:

- **Table 1** (main result): applying APS (CL = 0.90, stated in §3.2 "CL =
  .90 is used throughout this study") to four corpora — WSJ_en (|Σ|=2499),
  Brown_en (|Σ|=500), GCDT_zh (|Σ|=50), CTB_zh (|Σ|=2773) — and reporting
  |P1| (docs with ≥1 period hint), |P2| (docs with ≥1 valid period), their
  ratios, and mean/median hint & period lengths.
- **Tables 2-7**: harmonic-regression (HR) validation of APS periods/hints on WSJ.
- **Tables 4-5**: HR-modeling MSE across data portions (WSJ, GCDT).
- **Table 8**: human vs. LLM-generated text periodicity (FACE, EvoBench).
- **Appendix D / Figs. 6-9**: a fully worked single-document example on
  PTB-WSJ document #2380 — candidate period hints 60/99/101/374/403 tokens
  (CL=.99) → final valid periods **61, 101, 374 tokens**.

## 2. Codebase

Repo: https://github.com/CLCS-SUSTech/APS (verified, single commit).
Contents: `autoperiod.py` (APS algorithm exactly as in Algorithms 1-3),
`nll.py` (NLL/surprisal via a HF causal LM), `example.py` (demo),
`wsj_2380_nll.npy` (precomputed surprisal for the Appendix D example),
`requirements.txt`. **The repository ships only the core algorithm and one
worked example — no corpus-level experiment scripts, no corpora
(WSJ/Brown/CTB/GCDT/RST-DT/FACE/EvoBench), and no HR-modeling code.**

scipy, scikit-learn, nltk, joblib, accelerate. GPU: 1x H200.

## 4. What was run

### 4.1 Sanity check — exact reproduction of the paper's own worked example
```
cd codebase && python example.py
```
Loads the shipped `wsj_2380_nll.npy`, runs `AutoPeriod(mc_iterations=1000, confidence_level=.99)`.

**Result:** `{'periods': [101, 61, 374], ...}` — **exactly matches** the
paper's Appendix D reported valid periods (61, 101, 374 tokens). ✅ This
confirms the released code faithfully reproduces the paper's own reported
single-document result.

### 4.2 Table 1, Brown-corpus row — best-effort reproduction on a real, full corpus

PTB and CTB are LDC-licensed and unobtainable in this environment; GCDT/RST-DT
and FACE/EvoBench are not bundled with the repo and require access this
environment doesn't have either. However, Table 1's Brown_en row has
**|Σ|=500**, which matches exactly NLTK's freely-available Brown Corpus (the
canonical 500-sample Brown Corpus that PTB's "Brown portion" is itself
derived from). This is the one row of Table 1 that could plausibly be
reproduced from public data with the codebase as-is.

Procedure (scripts: `compute_nll.py`, `run_aps_brown.py`):
1. Downloaded all 500 NLTK Brown documents (`nltk.corpus.brown`, full text
   via `.words()` joined with spaces).
2. Computed NLL for each full document (2242-3537 tokens; well under context
   window, so **no truncation** was applied — unlike the code's own
   `max_length=1024` default in `nll.py`, we used `max_length=4096` to avoid
   truncating any document) using **LLaMA3-8B**, the paper's stated English
   surprisal model (§4). Meta's official `meta-llama/Meta-Llama-3-8B` repo is
   gated and no HF token/license acceptance was available in this
   environment, so we substituted the weight-identical ungated mirror
   `NousResearch/Meta-Llama-3-8B`.
3. Ran `AutoPeriod` on each of the 500 NLL sequences with the paper's stated
   `confidence_level=.90`, `mc_iterations=1000` (other params left at the
   repo's defaults: `fft='lomb_scargle'`, `threshold_method='default'`,
   `acf_method='unbiased'`), parallelized across 14 CPU cores via joblib.
4. Aggregated |P1|, |P2|, ratios, and mean/median hint & period lengths.

**Result vs. paper's Table 1 (Brown_en column):**

| Metric | Paper (Brown_en) | This run (NLTK Brown) |
|---|---|---|
| \|Σ\| | 500 | 500 |
| \|P1\| | 52 | 103 |
| \|P2\| | 25 | 18 |
| \|P1\|/\|Σ\| | 10.40% | 20.60% |
| \|P2\|/\|P1\| | 48.08% | 17.48% |
| \|P2\|/\|Σ\| | 5.00% | 3.60% |
| P1 hints mean (median) | 111.37 (28) | 506.37 (456) |
| P2 periods mean (median) | 144.57 (84) | 194.9 (141) |

**Comparison:** The qualitative core claim of the paper — "a considerable
proportion of human language demonstrates periodicity of information,
detectable at CL=0.90 by APS" — is **qualitatively confirmed**: on a real,
complete, public corpus with the paper's own model and confidence level,
20.6% of documents produce ≥1 period hint and 3.6% produce a strict valid
period, both clearly non-negligible, matching the paper's overall narrative.
However, the **exact Table 1 numbers are not reproduced**: our |P1| rate is
~2x higher, our |P2|/|P1| pass-through rate is ~3x lower, and detected
period lengths are 3-5x larger.

**Diagnosed cause:** NLTK's Brown Corpus files (500 total) each contain a
**full ~2500-token text sample**, whereas the paper's WSJ_en documents
average far shorter (its |P1| mean hint of 127.68 tokens implies WSJ
documents are individual, short newswire articles). We checked whether the
detected hint lengths scale with document length rather than being an
absolute artifact: for our 103 P1 documents, the ratio of (longest detected
hint)/(document length) has mean 0.17, median 0.15 — i.e., detected hints
sit at a fairly consistent ~15-17% of document length. Applying that same
ratio to the paper's likely (shorter) per-article WSJ/Brown document lengths
would reproduce roughly their absolute hint-length scale, i.e. **the
mismatch is best explained by a document-unit/granularity difference
between NLTK's whole-file Brown samples and the PTB Treebank's (likely
per-article, shorter) "Brown portion" documents**, not by an error in the
algorithm implementation (§4.1's exact match rules out an algorithmic bug).
We could not verify document boundaries directly since PTB is LDC-licensed
and unavailable here. We also checked for a simpler confound (a monotonic
surprisal trend inflating low-frequency power) — mean |correlation between
token position and surprisal| across P1 documents was only 0.06, so this is
not a linear-detrending artifact.

### 4.3 Not attempted (blocked)
- **Table 1 (WSJ_en, CTB_zh rows)**: requires PTB/CTB, LDC-licensed corpora
  not available in this environment (no LDC subscription/credentials).
- **Table 1 (GCDT_zh row)** and **§5.2 (Fig. 4, EDU/sentence/paragraph
  comparison)**: requires RST Discourse Treebank (LDC-licensed) and GCDT,
  neither bundled with the repo nor obtainable here in the time budget.
- **Tables 2-7 (harmonic regression validation)** and **Tables 4-5 (HR MSE
  comparison)**: require the RST/GCDT discourse annotations plus HR-modeling
  code that is not part of the released repository (paper acknowledges
  receiving "data for harmonic regression analysis" from other authors,
  i.e. this is not self-contained/released code).
- **Table 8 (human vs. LLM-generated text)**: requires the FACE and
  EvoBench datasets, which are not bundled with this repo (separate papers'
  releases) and were not tracked down within the time budget.

## 6. Summary / Verdict rationale

- The released code exactly reproduces the paper's own single-document
  worked example (Appendix D) — the algorithm implementation is correct and
  matches the paper.
- A full-corpus (not scaled-down document-count-wise) run on Brown_en (500/500
  documents, matching Table 1's exact document count) with the paper's
  stated model and confidence level qualitatively confirms the central claim
  (periodicity is detected in a non-trivial fraction of real text) but does
  **not** quantitatively match Table 1's Brown_en numbers, likely due to a
  document-granularity mismatch between the freely-available NLTK Brown
  Corpus and the LDC-licensed PTB Brown-portion the paper actually used.
- The remaining three corpora and Tables 2-8 could not be attempted at all
  because their underlying data (LDC-licensed PTB/CTB/RST-DT, or third-party
  FACE/EvoBench releases) is not available in this environment, and the
  released repository does not include experiment/HR-modeling scripts for
  them.

Given one full experiment exactly matched, one full-scale (not
document-count-reduced) experiment qualitatively but not quantitatively
matched, and the majority of the paper's tables blocked by data licensing
that is outside this environment's control, the overall verdict is
**PARTIALLY_REPRODUCED**.
