## Bottom line

**Main claim reproduces.** For all four open-weight models I could re-run, scores fall sharply and significantly (p<0.001) from Baseline (isolated task) to Dialogue.
- **Baseline means match the paper:** within 0.003 for Command A and Qwen3 30B, +0.018 for Qwen3 4B, +0.031 for Mistral.
- **Dialogue and Dialogue-concise means deviate** by -0.04 to +0.14. They are often higher than the paper's, so the gap is smaller (0.37–0.51 vs the paper's 0.42–0.51), but it is still large.

**Ablations mostly reproduce.** I re-ran four of the six ablations (Figs. 25–28): multi-turn baseline, single-turn dialogue, no tools, and baseline with role. In 15 of 16 model×ablation cases the effect has the paper's direction.
- Multi-turn baseline is lower than baseline, and single-turn dialogue is higher than dialogue, for all four models. This supports the claim that the gap is "largely driven by the multi-turn nature of dialogue".
- The one miss: removing tools no longer helps Qwen3 4B (Δ -0.001 vs the paper's +0.142).

**Two problems explain most of the deviations:**
1. **The released code has a prompt bug.** The Dialogue-concise template uses `{{ max_sentences_upper }}`, which the code never sets. As released, the prompt reads "at most  short sentences" instead of the paper's "at most two" (Fig. 10). I fixed it; the authors' own released outputs contain "2".
2. **The released model outputs behind Figure 6 don't match the paper's described prompts.**
   - **Spatial tasks:** for many model×task cells, the Dialogue / Dialogue-concise prompts lack the coordinate-system sentence ("Spatial coordinates are given in meters from the origin, a (0, 0) point in the southwest corner…"). The paper (App. A.2, E.6) and the released code both include it, and every Baseline prompt has it.
   - **Effect:** without that sentence the paper's Dialogue scores on spatial tasks are much lower, which inflates the Baseline→Dialogue gap there. Examples: Qwen3 4B directional relations 0.35 (paper) vs 0.78 (ours); Command A distance 0.00 vs 0.49.
   - **On non-spatial tasks** our Dialogue means are close to the paper's: Qwen3 30B 0.605 vs 0.604; Qwen3 4B 0.50 vs 0.47; Command A 0.43 vs 0.47; Mistral 0.34 vs 0.42.

## Why it is not fully reproduced

- **Coverage.** Only 4 of 8 models were re-run:
  - Qwen3 235B doesn't fit the hardware.
  - Two closed models plus DeepSeek V3.2 need an OpenRouter key, which isn't configured.
  - Two ablations (reduced domains, reasoning instructions) were not run.
- **Dialogue-setting numbers deviate**, for three reasons:
  - Inconsistent prompts in the authors' released outputs (spatial coordinate sentence; sunset time in some Baseline prompts). Our re-run follows the paper's description and the released code.
  - The Dialogue-concise template bug in the released code.
  - Non-deterministic greedy decoding across Ollama/llama.cpp versions and batching.
- **The qualitative conclusions hold:** a large significant gap, a strong effect from multi-turn structure, and a smaller role effect. The size of the Dialogue penalty on spatial tasks is overstated in the paper.

## Codebase completeness: MAJOR_FIXES

The pipeline for the main experiment is complete and runs. One bug that changes results had to be fixed (the concise template), plus an error-handling fix for current Ollama.

**Changes to `./codebase`** (left uncommitted; see `git diff`):
1. **`boulder/inference.py` (`build_chat_messages`):** added `"max_sentences_upper": 2` to the template parameters. Without it the Dialogue-concise prompt says "at most  short sentences" (paper Fig. 10: "at most two short sentences"). This changes results.
2. **`boulder/llm/clients.py` (`OllamaClient.chat`, both `client.chat` calls):** catch `ollama.ResponseError` when it is either HTTP 500 "invalid tool call arguments" or HTTP 400 "exceeds the available context size", and return an empty response. This mirrors the OpenRouter client's existing handling of HTTP 500.
   - Current Ollama raises these errors and kills the whole shard. It fired 12 times in the main runs, each scored as a wrong answer.
   - A first, broader version (any HTTP 500) also masked llama-server crashes during the first ablation attempt. That attempt was discarded and re-run (`runs/ablations_failed_threadlimit`).

**Other issues:**
- The README's commands fail with `ModuleNotFoundError: boulder` unless `PYTHONPATH=.` is set.
- There are no configs or scripts for the ablations. The released ablation datasets use an older schema (`metadata.task_type`, different file names) that the released loader rejects. I converted them with `eval/convert_ablation_data.py`.

**Scripts I wrote** (outside the codebase):
- Runners: `run_all.sh`, `run_all8.sh`, `run_concise_fixed.sh`, `run_ablations.sh`, `rerun_shard.sh`, `chain_*.sh`, `switch_to_8.sh`
- Analysis: `eval/merge_shards.py`, `eval/build_comparisons.py`, `eval/compare*.py`, `eval/prompt_audit.py`, `eval/make_status.py`
- Paper numbers transcribed: `eval/fig6_paper.py`, `eval/ablation_paper.py`

**As released vs fixed.** The "as released" numbers use the unmodified prompt code. They still include fix 2, which is environment-level and needed to complete runs on current Ollama. With the Ollama version the authors used, which I don't know, the unmodified code might run without it. The fixed concise prompt changes only the Dialogue-concise rows.

## Discrepancies

1. **code_vs_paper, major, affects results:** Dialogue-concise template variable `max_sentences_upper` is never passed, so the prompt is missing "two" (paper Sec. 4.1, Fig. 10).
2. **code_vs_paper, major, affects results:** The released outputs behind Fig. 6 omit the coordinate-system sentence from Dialogue/concise prompts for spatial tasks. Affected:
   - Qwen3 4B, Mistral, Command A and Qwen3 235B: all three spatial tasks.
   - Qwen3 30B: directions and path.
   - Claude and DeepSeek: distance.

   The paper (App. A.2, E.6) and the code include the sentence, and every Baseline prompt has it. The paper's Baseline→Dialogue gap is inflated on these cells.
3. **code_vs_paper, major, small effect:** Released Baseline outputs for Departure time lack "Sunset time is HH:MM" for Qwen3 4B, Qwen3 30B and DeepSeek V3.2. The paper (Fig. 1, App. A.2) and the shipped benchmark provide it.
4. **code_vs_paper, minor:** Significance stars are described as coming from t-tests; the code uses a z-test on PPI confidence intervals.
5. **paper_internal:** The Anthology abstract says "nine LLMs"; the PDF abstract, the contributions list and Table 3 say eight.
6. **paper_internal:** Sec. 5 says Gemini 2.5 Flash's Baseline "scores only slightly above 0.70". Figure 6's Gemini Baseline values average 0.80 (released outputs: 0.796).
