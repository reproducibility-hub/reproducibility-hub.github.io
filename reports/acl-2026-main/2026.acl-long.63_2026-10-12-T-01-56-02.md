- **Flags:** `CHECKPOINT_ONLY`, `CLOSED_JUDGE_UNAVAILABLE`.

### Bottom line
- **Table 1 (prefix-level NLI F1):** all 6 numbers reproduced within 0.1 F1, plus the 6 faithful-class F1s of Table 10. This uses the released MiniTrue/MiniTruePrefixes checkpoints and the released SummEditsPrefixes/RAGTruthPrefixes test sets.

  - XSum: all 6 settings within 1.1 pt of the paper.
  - CNN/DM: our absolute scores are 1–4 pt higher for every setting (vanilla included).
  - On both datasets the method's gains reproduce: Prefix vs vanilla is +9.9 / +6.7 / +5.1 (1B/3B/8B) on XSum (paper +8.1 / +6.2 / +5.5) and +8.3 / +6.4 / +2.6 on CNN/DM (paper +7.5 / +5.7 / +2.9).

  - MAUVE (c=0.5) is within 5% everywhere.
  - Fluency and relevance stay stable under the method, as the paper claims.

We wrote `scripts/eval_prefixnli.py`; the release has no evaluation script.

```
python -I scripts/eval_prefixnli.py --model {sapirharary/MiniTruePrefixes|sapirharary/MiniTrue|minicheck-ft5} --dataset {summedits|ragtruth} --out results/table1/...
```

- **MiniTrue / MiniTruePrefixes** are scored exactly as in the release's logits processor:
  - prompt: chat template with `premise: {doc} hypothesis: {prefix}`;
  - P(entailed) = exp(logprob of token "1"), taken from the vLLM top-20 logprobs;
  - a prefix counts as entailed when P > 0.5.
- **MiniCheck-Flan-T5-Large** uses the official `minicheck` chunking (500-word chunks, max over chunks, threshold 0.5), batched across examples.
- **Data:** the full released test splits (SummEditsPrefixes 8,910 prefixes; RAGTruthPrefixes 210,678).
- **Metric:** F1 of the unfaithful class, with a 95% CI from 1,000 bootstrap resamples.

### Table 2 (controlled decoding)
- **Prefix (MTP):** the released script, with only the argument additions listed below:
  ```
  python codebase/controlled_decoding_pipeline.py --gpu 0 --lm_model <gen> --dataset_name xsum --dataset_document_column_name document \
     --start_idx S --end_idx E --output_csv gen/prefix_<sz>_xsum_S_E.csv --entailment_model_gpu_memory_utilization 0.06 --entailment_max_model_len 4096
  ```
  CNN/DM: `--dataset_name cnn_dailymail --dataset_config_name 3.0.0 --dataset_document_column_name article`. All other hyperparameters are the release defaults, which equal the paper's: K=3, top-p 0.9, max 20 candidates, λ=5, τ=0.5, entailment model sapirharary/MiniTruePrefixes.
- **Vanilla:** `scripts/vanilla_generate.py` (ours). It uses the identical prompt, `generate()` kwargs and long-document skip rule, without the entailment logits processor.
- **Generators:**
  - `unsloth/Llama-3.2-1B-Instruct` and `unsloth/Llama-3.2-3B-Instruct`: weight-identical mirrors, because meta-llama 3.2 is gated for us;
  - `meta-llama/Llama-3.1-8B-Instruct`: the paper writes "LLaMA-3.2-8B-Instruct", which does not exist.
- **Documents:** the first 1,000 test documents of XSum and of CNN/DM 3.0.0. After the code's own filter (chat prompt > 2,047 tokens), this leaves 996 XSum and 986 CNN/DM docs, identical across all 6 configs (paired).
  - Runs were sharded by doc range and run concurrently (`scripts/launch_gen.sh`, `scripts/scheduler.py`).
- **Evaluation** (ours):
  - `scripts/score_summaries.py` computes per-doc scores:
    - Bespoke-MiniCheck-7B via the official `minicheck` package (vLLM V0, bf16, max_model_len 8192, so every doc is a single chunk);
    - each summary sentence (nltk) is checked against the full source doc and gets a binary label;
    - a summary's score = fraction of supported sentences; we report the mean and the standard error of the mean (SEM).
    - ROUGE-L F1 (rouge_score, stemming) against the reference.
  - `scripts/aggregate_table2.py` computes means and MAUVE (gpt2-large features, `mauve_scaling_factor=0.5` as stated in the paper).

**CNN/DM absolute offset.** Every CNN/DM configuration, vanilla included, scores 1–4 pt above the paper. The largest gaps are vanilla 1B (+3.4) and Prefix 1B (+4.2, 5.3% relative, hence TREND_MATCH). Because the offset also affects vanilla, it does not come from the method. Plausible causes:

## Codebase completeness: MISSING_CORE
The repository contains `README.md`, an unpinned `requirements.txt`, and `controlled_decoding_pipeline.py`, which implements the PrefixNLI logits processor and the generation loop. Models and datasets are public on HF.

**Missing or written by us:**

**Edits to the released code** (`codebase/controlled_decoding_pipeline.py`, uncommitted; diff in `codebase_changes.diff`):
1. Added `--dataset_config_name`. `load_dataset("cnn_dailymail")` fails without a config, so CNN/DM could not run as released (bug fix; no effect on results).
2. Added `--start_idx/--end_idx`. The script iterates over the whole test split (11k docs) while the paper uses 2,500; needed for doc limits and sharding (no effect on per-doc outputs).
3. Added an optional `--entailment_max_model_len`, passed to vLLM `LLM(max_model_len=...)`. The default None keeps the original behaviour. We used 4096 so that 6 runs fit on one GPU; entailment prompts are always shorter than this, so scores are unaffected.

**Other issues:**
- The README command `python controlled_decoding.py` names a file that doesn't exist.
- The script hard-codes `os.environ["CUDA_VISIBLE_DEVICES"]=args.gpu` and the XFORMERS backend; the latter forces the vLLM V0 engine.
- The generator is loaded in fp32 (no dtype), so the 8B generator needs ~32 GB of GPU memory.
- The per-step Python loops in `__call__` (element-wise tensor comparisons with GPU syncs) take about half the decoding time on our hardware.

## Discrepancies
- **code_vs_paper (minor, affects results):** `generate()` uses beam *sampling* (`do_sample=True`, temperature 0.7, repetition_penalty 1.2, no_repeat_ngram_size 3, fp32 generator). The paper describes deterministic beam search with K=3 over the top-p candidate set and mentions none of these settings.
- **code_vs_paper (minor):** documents whose prompt exceeds 2,047 tokens are silently skipped (4 XSum / 14 CNN/DM in the first 1,000 docs). The paper says "2,500 test set documents".
- **code_vs_paper (minor):** the README usage refers to `controlled_decoding.py` (the real file is `controlled_decoding_pipeline.py`), and the CNN/DM dataset cannot be loaded without a config argument.
- **paper_internal:** Table 1 gives MiniTruePrefixes 78.1 ± 1.0 / 47.6 ± 0.6. Table 7 gives the same model and numbers as 78.1 ± 0.8 / 47.6 ± 0.1. Our bootstrap CIs (±1.0 / ±0.6) agree with Table 1.
- **paper_internal:** §6.3/Table 2 put Prefix-1B runtime at up to 2.9× vanilla (4.84/1.74 and 5.67/1.93). Appendix G says "only about 2.4× slower".
- **paper_internal:** §6.2 lists "LLaMA-3.2-8B-Instruct", a model that does not exist (the 8B model is Llama-3.1-8B-Instruct).
