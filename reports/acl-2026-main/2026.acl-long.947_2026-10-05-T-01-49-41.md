## What the paper claims / what I targeted
- **Table 1 ("Ours")**: the full framework (unified open-set classifier trained with PLM-generated and LLM-generated pseudo unknown-type instances, plus UHCL with α=0.1, Q=25, τ=0.07, lr 3e-5, BERT-base) on the new OSET benchmarks built from BBN and Few-NERD. Metrics: Acc-all, F1-all (weighted F1), F1-known (weighted F1 over known types), F1-binary.
- **Table 2**: variants BASE (known-type instances only) and PGM (PLM-generated pseudo-instances only). LGM was not run, see below.
- **Table 3**: ablation "w/o UHCL".
- The README's "Quickly Reproduce" path trains the final classifier from the **released** pseudo unknown-type instances (`checkpoints/{BBN,fnerd}/*.zip` + `llm_ood_llama_dpp_valid_w.txt`). That is what I ran. The generation stage (keyword extractor training, iterative substitution, Llama3-8B DPP-ICL generation) was **not** re-run, so the claims about generation quality are only tested through the released artifacts.

Settings that differ from the paper: none intentionally. The GPU was an H200 instead of an A6000, and torch 2.4.1 replaced 1.13.1 because the cu116 build cannot run on sm_90. Up to 9 runs shared the one GPU in parallel.

## Discrepancies
1. **F1-binary positive class** (`open_eval.py::evaluate`, `f_ood = f1_score(all_ood_truth, all_ood_pred)` where known=1, unknown=0). The paper (§4.1.1) says F1-binary "assesses the ability to detect unknown-type instances", but the code computes the F1 of the **known** class. Re-evaluating the BBN seed-6 checkpoint (`scripts/eval_binary.py`): known-positive 0.8075 (the reported quantity, matching the paper's 0.823 scale); unknown-positive 0.714; macro over both classes 0.761. The paper's numbers are consistent with the known-positive definition. The paper never states the positive class, so I record this as a minor code-vs-paper discrepancy. It does change how good unknown detection looks.
2. **Optimizer**: the paper (App. C) says Adam, lr 3e-5. The code uses AdamW (weight decay 0.01) with linear warmup over 10% of steps, gradient clipping 1.0, 50 epochs, and model selection on dev known-type weighted F1. Minor.
3. **α default**: `train_weight_llm.py` defaults to `--lamb 0.0` (α), while the paper says α=0.1. The README command passes `--lamb 0.1`. Minor; no effect when following the README.
4. **Dataset sizes**: the paper (Table 4 / README) gives BBN 2,431 validation and 961+961 test instances. The released BBN files contain 2,432 dev and 1,921 test mentions. Few-NERD and BBN-train match exactly. Minor; negligible effect.

The Table 2 PGM configuration is never stated in the paper. On Few-NERD the with-UHCL configuration matches the paper's row; on BBN only a without-UHCL run matches. This is not counted as a discrepancy.
