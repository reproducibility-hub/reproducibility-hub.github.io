## 1. Paper claim and what was released

**Claim.** VC-Inspector is Qwen2.5-VL-3B/7B fine-tuned with LoRA on ActivityNet-FG-It. That dataset contains synthetic captions with controlled object/action errors, a 1-5 score and an explanation. The paper says the resulting reference-free metric beats prior reference-free metrics:
- on VATEX-Eval (Table 2, "our primary results");
- on the image benchmarks Flickr8K-Expert and Flickr8K-CF (Table 4).

**Release:**
- GitHub: `src/training/train_lora.sh` (ms-swift LoRA SFT), `src/gen_data/*` (LLM data generation), `src/inference.py` (one video / one caption).
- HuggingFace dataset `dipta007/ActivityNet-FG-It`: balanced split of 22K train / 1.1K val, an imbalanced split, and `frames.zip` with 25 GB of 320×240 frames.
- HuggingFace merged checkpoints `dipta007/VCInspector-3B` and `-7B`.
- **No evaluation code for any benchmark.**

## 2. What we ran

1. **Released checkpoints.** VC-Inspector-3B and -7B on:
   - VATEX-Eval (no-reference setting, Kendall τb and Spearman ρ);
   - Flickr8K-Expert and Flickr8K-CF (Kendall τb).
2. **Base-model baselines.** Qwen2.5-VL-3B/7B-Instruct on VATEX-Eval, with the same prompt and pipeline (the Table 2 "Qwen2.5-VL" rows).
3. **Re-training both models from scratch** with the released `src/training/train_lora.sh`, unchanged:
   - on the released balanced ActivityNet-FG-It data and frames;
   - 1×H200, so per-device batch 16 × grad-accum 8 = global batch 128; ZeRO-3; 1 epoch = 172 steps; LoRA r=32, α=32, dropout 0.05; lr 1e-4 with cosine decay to a 1e-5 floor; warmup 0.05; ViT and projector frozen;
   - then merged the LoRA with `swift export --merge_lora true` and evaluated with the same pipeline.
   - 3B: 8h45m, final train loss 0.358. 7B: 9h00m, train loss 0.297.
4. **Sensitivity check on input resolution.** Inputs kept their aspect ratio at ≤320×240 pixels, the resolution of the released training frames, instead of the paper's 224×224 (section 5).

**Evaluation pipeline (written by us; nothing in the release does this):**
- `scripts/eval_vc.py` scores every candidate with vLLM 0.11.
  - Prompt: the exact training prompt (Prompt D.6 / training jsonl), in the ms-swift `qwen2_5_vl` chat format with system prompt "You are a helpful assistant." and one vision block per frame.
  - Video: 32 uniformly sampled frames (the `np.linspace` rule from `src/inference.py`), resized to 224×224 as in paper §4.1.
  - Images: one-frame "videos" at 224×224.
  - Greedy decoding. The first digit 1-5 in the output is the score (0 unparsable outputs for VC-Inspector; 12 and 2 for the base 3B and 7B models, which were scored 0).
- `scripts/compute_corr.py` applies the official correlation protocols:
  - VATEX-Eval: EMScore's `compute_correlation_uniquehuman`, i.e. the mean over the 3 annotators of scipy `kendalltau` (τb) and `spearmanr`.
  - Flickr8K: PAC-S `compute_correlations.py`, i.e. `kendalltau(variant='b')` over all judgment rows of `flickr8k.json` (16,992) and `crowdflower_flickr8k.json` (47,830).
- Runners: `scripts/run_vatex.sh`, `run_flickr.sh`, `run_train.sh`, `run_sensitivity.sh`; `scripts/make_status.py` builds status.json.

**Data:**
- VATEX-Eval annotations come from the EMScore Google Drive.
- The VATEX-Eval videos are no longer fully on YouTube, and yt-dlp from the cluster fails. We used the third-party HF mirror `zrchen03/vatex_videos_2581`: 2,581 of 3,000 videos, 15,486 candidates. The paper used 2,590 videos and 15,540 candidates, so we have 9 fewer videos.
- Flickr8K-Expert/CF: the PAC-S Google Drive (images plus json files).

Example commands (from the attempt dir):
```
scripts/run_vatex.sh dipta007/VCInspector-3B dipta007/VCInspector-7B Qwen/Qwen2.5-VL-3B-Instruct Qwen/Qwen2.5-VL-7B-Instruct
scripts/run_flickr.sh dipta007/VCInspector-3B dipta007/VCInspector-7B
scripts/run_train.sh Qwen/Qwen2.5-VL-3B-Instruct     # = cd train_run; bash codebase/src/training/train_lora.sh <model>
swift export --adapters train_run/outputs/Qwen2.5-VL-3B-Instruct-lora/checkpoint-172 --merge_lora true --use_hf true
```

**Settings that differ from the paper:**
- VATEX-Eval: 2,581 vs 2,590 videos.
- Our re-training used 1 GPU (global batch still 128) instead of 4×A100.
- Training data is 22K samples, the released split. The paper says 44K, but the released checkpoints were themselves trained on 22K (see discrepancies).
- torch 2.8.0 instead of 2.11.0 from uv.lock, so that vLLM 0.11 could be installed. All other training libraries are pinned as in uv.lock.
- The released checkpoints were evaluated with our own pipeline; the authors' evaluation code and exact input preprocessing are unknown.

**Do the claims hold?**
- **VATEX-Eval (Table 2).** Released and re-trained models give τb of 40.1 / 40.1 for 3B and 42.2 / 41.1 for 7B. These beat every reference-free baseline number the paper reports (EMScore 22.88, CLIPScore 22.33, FactVC 22.79, PAC-S 25.1, ViCLIPScore 30.92, G-VEval 39.4), and beat our own base Qwen2.5-VL runs (32.95 / 28.31). 7B > 3B also holds.
- **Fine-tuning gain over the base model.**
  - 3B: +7.1 τb (paper +6.7).
  - 7B: +13.9 τb (paper +7.9), because our base 7B run is weaker than the paper's.
- **Flickr8K (Table 4).**
  - Expert: VC-Inspector is the best metric overall (63.5-65.0 for 7B), as claimed.
  - CF: our 7B scores 42.5 (released) / 41.5 (re-trained) vs 46.0 in the paper, i.e. 3.5-4.5 points lower. It still beats every reference-free and reference-based number in Table 4 (best other: 38.8). The 3B CF result matches.
- **Training reproduces.** Re-training both models with the released script and data gives numbers within ~1 point of the released checkpoints (3B essentially identical; 7B −1.2 τb on VATEX, −1.5 on Expert, −1.0 on CF).

**Baselines.** We only ran the base Qwen2.5-VL models, which use the same pipeline and prompt. The other baseline rows of Tables 2 and 4 (EMScore, CLIPScore, ViCLIPScore, FactVC, PAC-S, G-VEval, FLEUR, ...) were not re-run: the release contains no code or configs for them, so "beats X" uses the paper's reported baseline numbers.
- Our base Qwen2.5-VL-7B is clearly weaker than reported (28.31 vs 34.70 τb). It predicts score 1 for 53% of candidates under this prompt. The paper does not give the baseline's prompt or decoding details.
- Our base 3B is slightly stronger than reported (32.95 vs 31.29). That shrinks the 3B gain by ~1.7 points, but it is not a clear "baseline stronger" case.

## 6. Codebase completeness: MISSING_SCRIPTS

**Edits to the released code:** none. `codebase/` has no diff.

**Missing pieces that we wrote ourselves:**
- All benchmark evaluation: data loading for VATEX-Eval and Flickr8K, frame sampling and resizing, batch scoring, score parsing, and correlation computation (`scripts/eval_vc.py`, `scripts/compute_corr.py`).

**Other gaps (not needed for our runs):**

**Environment-level workarounds:**

- `train_lora.sh` runs `source .venv/bin/activate` (a uv venv). This fails harmlessly; we put our conda env on PATH instead.
- torch 2.8.0 instead of 2.11.0, to co-install vLLM 0.11.0 for evaluation. All other training libraries match uv.lock: ms-swift 3.12.6, transformers 4.57.6, peft 0.18.1, deepspeed 0.18.9, liger-kernel 0.7.0, trl 0.24.0, qwen-vl-utils 0.0.14.

## 7. Discrepancies

1. **code_vs_paper, major, does not affect the reported numbers.** In `src/gen_data/augmentation.py`, the quality-score code differs from the paper.
   - Paper §3.2: score = 1 − |R|/(|O|+|A|), a deterministic count.
   - Code: computes that value and then overwrites it with `get_score()` = 0.3 × harmonic mean of Qwen3-Embedding-8B word similarities + 0.7 × caption-embedding similarity. The README also says "Compute quality scores based on semantic similarity".
   - The released labels look consistent with the count-based formula: every score-5 item has 0-1 listed errors, and the score falls monotonically with the error count. Running the released generator would therefore not reproduce the released data.
2. **code_vs_paper, minor.** Generator LLM: `gen.py` and the README default to Qwen/Qwen3-32B; the paper and dataset card say Llama-3.3-70B-Instruct.
3. **code_vs_paper, minor, affects results.** Training-set size.
   - Paper (§3.2, §4.1): ActivityNet-FG-It has 44K instances, 8.8K per label.
   - Release: the balanced train split has 22,000 instances (4,400 per label). The released checkpoints' `args.json` shows they were trained on `train_change_obj_act_balanced_1-5_22k.jsonl`. The HF dataset card still claims 44K.
4. **code_vs_paper, minor, affects results.** Frame resolution.
   - Paper (§4.1, Table 11): 224×224 for training and testing.
   - Release: frames are 320×240 JPEGs fed as *images*. `train_lora.sh` sets only `VIDEO_MAX_PIXELS=50176`, which applies to video inputs, and `max_pixels` is None. Training therefore runs at ~336×252 per frame.
5. **code_vs_paper, minor, does not affect the reported numbers.** Inference input format.
   - `src/inference.py` passes 32 full-resolution frames and also prepends 32 literal `<image>` strings to the text. The chat template already inserts one vision block per image, so the input differs from the training format.
   - The HF model card example instead feeds a whole video at fps=1 with max_pixels=360·420. Neither matches the paper's 32 frames at 224×224.
