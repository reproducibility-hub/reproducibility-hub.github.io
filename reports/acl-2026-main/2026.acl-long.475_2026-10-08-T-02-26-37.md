## What the paper claims / what was targeted
MHL adds an auxiliary task to the RPG generative recommender: reconstructing masked history items. It uses entropy-guided masking and a curriculum (random masking → entropy masking → ratio decay → prediction only). Table 1 reports R@5/N@5/R@10/N@10 on three Amazon-2014 5-core datasets, as the mean of 3 seeds. MHL beats every baseline, including RPG* (RPG with Sentence-T5 embeddings).

Repo: https://github.com/CQU-MM-Intelligent-Lab/MHL (linked in the paper). It contains the full pipeline: download and preprocessing of the Amazon 2014 data, Sentence-T5 → PCA → FAISS OPQ semantic IDs, the model, the curriculum trainer, and graph-constrained beam-search evaluation. The README gives one exact command per dataset.

## What I ran
- Env: `conda create -p ./env python=3.10`, torch 2.6.0+cu124, and `requirements_fixed.txt` (see codebase notes). Hardware: 1×H200.
- Data: `reviews_<cat>_5.json.gz` and `meta_<cat>.json.gz` from snap.stanford.edu, the URLs the code itself uses. Stats match the paper: Beauty has 22,363 users and 12,101 items.
- Embeddings: `sentence-transformers/sentence-t5-base` from HF (the code pointed at a local `/data/user/sentence-t5`).
- MHL: the exact README command per dataset, plus `--rand_seed={2024,2025,2026} --run_id=... --entropy_log=False --case_study_log=False` (`scripts/run.sh <dataset> <seed> mhl`). The two `*_log` flags only switch off per-batch statistics logging.
- RPG* baseline: the same README command plus the code's own switch `--pure_predict_only=True` (no masking, no reconstruction, plain RPG training), 3 seeds (`scripts/run.sh <dataset> <seed> rpg`).
- Extra checks:
  - RPG with 16 codebooks for Toys and Sports (`rpg16`, 1 seed). This is the Table 2 "No Mask" setting.
  - A random-masking curriculum ablation `mhlrand` (`--mask_strategy=token`, i.e. R→Inf), 3 seeds per dataset.
- Runs were executed sequentially, one MHL-type chain plus one light chain. MHL's per-sample masking loops slowed down about 10× when several processes shared the GPU.
- Logs: `runs/*.out` holds the per-run stdout. `runs/logs/` holds the code's own logs. Aggregates are in `runs/summary.txt` and `runs/tables.md`.

Settings that differ from the **paper text** but follow the **released README/configs**:
- lr 0.003/0.01, batch size 256, beams 100/200, edges 100/200, propagation steps 2/3/5, codebooks 16 for Beauty, and recon weights 1.0–1.8. The paper says lr 5e-4, batch 64, beam 50, 50 edges, 3 steps, 32 codebooks and equal weights.
- I used the README values because they are the authors' released run commands. They reproduce the reported numbers.

### Supplementary: does entropy guidance matter? (not part of the verdict)
`mhlrand` is the same pipeline with random token masking plus the decay curriculum (R→Inf), using the README per-dataset ratios.

- **Beauty:** this config equals Table 2's (codebook 16, ratio 0.15).
  - Ours: R→Inf N@10 .0484 vs MHL (R→E→Inf) .0489. The difference is within noise.
  - Paper Table 2: .0480 vs .0495.
  - So the gain from entropy guidance specifically is small or absent in our runs.
- **Toys and Sports:** random variants averaged lower (N@10 .0481 vs .0551, and .0279 vs .0291), but this comparison is confounded.
  - In the code, the random-only path has no minimum-epoch guard. In 4 of 6 runs it left the masking phase after 6–9 epochs (`Enter DECAY at epoch 6/7/9`), effectively becoming RPG with a brief masking phase.
  - In the runs where it kept a full random phase (Toys s2024: .0544; Sports s2025: .0292), it is close to MHL.
- These are not Table 2's exact settings for Toys and Sports (Table 2 uses 16 codebooks and ratio 0.15), so they are not compared number by number.

## Discrepancies
1. **code_vs_paper (minor)**: the hyperparameters in the paper text don't match the README:
   - Paper: lr 5e-4, batch 64, beam 50, 50 edges, 3 propagation steps, 32 codebooks, equal loss weights.
   - README: per-dataset lr 0.003/0.01, batch 256, beams 100/200, edges 100/200, steps 2/3/5, 16 codebooks for Beauty, recon weight 1.2/1.0/1.8, mask ratio 0.10/0.15/0.05.
   - The README values reproduce the table.
2. **code_vs_paper (major)**: masking selection differs from the paper.
   - Paper (Sec. 3.3): aggregate token entropies into item scores, sample a budget N ~ U(1, ⌊γT⌋), and mask the top-N *items*.
   - Released configs (`entropy_token`): rank individual *token* positions and mask a fixed top-k = round(γ·#tokens). There is no stochastic budget and no item-level aggregation.
3. **code_vs_paper (major)**: where the entropy comes from.
   - The entropy for position t is computed by running the (shared next-item/reconstruction) prediction heads on h_t of the *unmasked* sequence. There, those heads are trained to predict item t+1.
   - So the score measures next-item uncertainty, yet it is used to choose whether to mask item t. The paper's Eq. 4 frames it as uncertainty about the item at t.
4. **code_vs_paper (minor)**: curriculum ratios and timing.
   - Paper: Phase I uses a "low" random ratio and Phase II a "high" entropy ratio.
   - Code: both phases use the same r0. Entropy masking only starts after epoch ≥15 (hard-coded default) and 5 non-improving evaluations.
5. **code_vs_paper (minor, no effect)**: the task token does nothing.
   - The PREDICT/RECON task token is appended after the last position, but only the first L hidden states are used.
   - Under causal attention those positions never attend to the token, so it has no effect.
6. **paper_internal**: decay schedule. Sec. 3.4 / Eq. 5 describes exponential decay γ←max(γmin, γη). Appendix I (and the code) uses linear decay of 0.1·r0 per evaluation.
7. **paper_internal**: codebooks and mask ratio.
   - Sec. 4.1 / App. I say 32 tokens per item and r0 = 0.15.
   - But Table 1's Beauty MHL row is identical to Table 2's codebook-16 / ratio-0.15 row, and the README Beauty config uses 16 codebooks.
   - Table 1's RPG* row equals Table 2's "No Mask" row (codebook 16).
   - For Toys and Sports, MHL is run with 32 codebooks and ratios 0.05/0.10.
   - Our RPG with 16 codebooks (Toys .0437, Sports .0240 N@10) is about the same as with 32, so this does not change the conclusion.

Other observations:
- In the predict-only stage, the trainer re-saves the checkpoint whenever the stage-local best improves, even if it is below the global best.
- The random-only ablation path can exit its masking phase after only a few epochs (see the supplementary section).
