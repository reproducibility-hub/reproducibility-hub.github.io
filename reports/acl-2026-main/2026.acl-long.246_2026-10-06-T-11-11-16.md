## Code
- The catalog link (https://github.com/zjunlp/EasyEdit) points to the third-party toolkit the paper used only for its **baselines**. EasyEdit contains no RILKE code; the clone is kept, unused, in `./easyedit_ref`.
- The first author's official implementation was found by web search: **https://github.com/Xuyuan0204/RepKnowledgeEdit**. Its README says "Official implementation of ... (ACL 2026, Oral)". We used commit `9b61ad8` as `./codebase`.

## What was run (exact commands)
**Environment**
- Conda env `./env`: Python 3.10, torch 2.4.1+cu124, transformers 4.45.1 (pinned by pyreft 0.1.0), pyvene 0.1.8, sentence-transformers 5.7.0, rouge-score 0.1.2.
- `flash-attn` is not installed, so we used `--attn_impl sdpa`. The repo's own `configs/cluster.yaml` does the same.
- Hardware: one H200, shared by all our processes.

**1. Routing keys** (repo script, unchanged)
```
python store_activation.py --model_name meta-llama/Llama-3.1-8B-Instruct --dataset_name unke_v3 --data_src {original,rephrased} --target_layer 15
python store_activation.py --model_name Qwen/Qwen2.5-7B-Instruct --dataset_name unke_v3 --data_src {original,rephrased} --target_layer 18
```

**2. Individual RILKE training: 1,000 modules per model, 1,000 epochs each, using the paper's Table 9 settings.** This is the README command. We split the 1,000 edit indices into ranges with flags we added and ran several processes in parallel.
```
python train_test.py --num_samples 1000 --dataset unke_v3 --adv_train_method Explicit --model_name <M> --rank 4 --epochs 1000 \
  --learning_rate 1e-2 --noise_std 0.02 --drop_out 0.05 --lambda_consistency 0.001 --target_layer <15|18> --attn_impl sdpa \
  --save_weights_dir <single_unke_llama|single_unke_qwen_layer18> --train_start a --train_end b --skip_test
```

**3. Evaluation at T ∈ {10, 100, 1000}**
- Uses the repo's `Reft_test`: routing among the first T stored keys, greedy decoding, at most 512 new tokens.
- Run as `scripts/eval_single.sh {llama,qwen} T`, which calls `python -u train_test.py --num_samples T ... --skip_train`.
- Aggregated with `scripts/score.py` and `scripts/make_status.py`.

**4. MMLU utility (`scripts/mmlu_eval.py`, written by us; the repo has no MMLU evaluation)**
- Questions: the 5,000 MMLU questions shipped in `datasets/UnKE/final_data_v3.json`. These are 5 per edit item, matching App. A.7.1's "5,000 unrelated samples from MMLU".
- Prompt and scoring: 0-shot chat prompt; the answer is the argmax of the next-token logits for A/B/C/D.
- Routing: the key is the layer-L hidden state at the last prompt token, compared by cosine similarity to the 1,000 stored edit keys. The routed module is applied only if the maximum similarity is ≥ τ=0.9 (paper Sec. 5.2). Otherwise the unedited model answers.
- `--mode none` gives the unedited baseline; `--mode single` and `--mode cluster` give RILKE.

**5. Cluster-shared RILKE (Table 3)**
- Training: `REPRO_SKIP_INLOOP_EVAL=1 python train_cluster.py --config configs/cluster.yaml`, run in cluster-index shards. It uses the shipped `cluster_index/unke/unke_v3_3_hac_maxsize8.json` (306 clusters).
- Evaluation: `REPRO_EVAL_START/END=... python -u test_cluster_rep.py --config configs/cluster.yaml`. We ran 3 item ranges in parallel; each range routes over the full set of 1,000 keys.

**Settings that differ from the paper**
- None on purpose.
- The Qwen intervention layer is 18, taken from the README; the paper does not give a layer for Qwen.
- The MMLU protocol is ours, because the paper gives none.
- λ_robu=0.001 and dropout 0.05 are the repo defaults; the paper gives no value for λ.

**What these results show**
- **Edit efficacy is perfect for both models at every T.** Ori BertS and ROUGE-L are 1.000 everywhere.
- **LLaMA paraphrase generalization matches the paper essentially exactly.**
- **Qwen at T=1000 matches the paper exactly.** At T=10 and T=100, Qwen's paraphrase scores are 2–12 points below the paper.
  - At T=10 (only 10 items), one degenerate generation dominates: a Chinese-language answer with BertS 0.37.
  - In general, Qwen's paraphrase loss comes from routing. Key-only paraphrase routing accuracy at layer 18 is 1.00 / 0.86 / 0.712 for T = 10 / 100 / 1000 (LLaMA: 1.00 / 0.98 / 0.93).
  - At T=1000, correctly routed Qwen paraphrases score BertS 0.964 / RougeL 0.874. Misrouted ones score 0.730 / 0.298.
- **Utility (MMLU) is preserved.**
  - Under our MMLU prompt, none of the 5,000 MMLU queries reaches τ=0.9 (maximum similarity 0.78), so the routed model's MMLU equals the base model's.
  - The paper reports a 0.011 drop for LLaMA. Our numbers support its claim of "near parity with the unedited base model".
  - Our base-model MMLU (0.647 / 0.712) is close to the paper's (0.633 / 0.713), which suggests a similar protocol.
- **Shared-subspace RILKE (Table 3) reproduces the claim:**
  - same efficacy;
  - storage cut about 3× (29.4 vs 95.9 MiB);
  - a small generalization cost. That cost is smaller in our run than in the paper: Para BertS 0.967 → 0.941, vs the paper's 0.963 → 0.901. Cluster-level routing accuracy is 0.94.
- **The release ships one result file we did not reproduce.** `result/unke/single_unke_results.jsonl` contains Qwen individual results on the older `final_data_v2.json`, with T=1000 Para BertS 0.972 and RougeL 0.894. Those numbers are higher than both the paper (0.893 / 0.718) and our rerun on v3. It uses a different data version, so it is not comparable to Table 1, and it does not reproduce the paper's numbers. We therefore do not raise the RERUN_WEAKER_THAN_RELEASED flag.

## Not run
- **Baselines** (FT-L, MEMIT, GRACE, UnKE, AnyEdit, WISE).
  - They are not in the RILKE release; the paper says they were run with EasyEdit's default configurations.
  - Re-running six methods × 2 models × 1,000 sequential edits did not fit the 48 h single-GPU budget alongside RILKE itself, which needed about 30 h of GPU time.
  - The claim that RILKE beats these baselines is therefore checked only against the paper's own reported baseline numbers; we did not re-run it. Our RILKE numbers exceed all of the paper's baseline rows.
- **ZsRE columns of Table 1 (T=3,000).** The release has no ZsRE data or scripts (the repo was cleaned to "UnKE-only"). Training 3,000 more 1,000-epoch modules would also have exceeded the budget.
- **Table 4** (without L_robu), **Table 5** (sequential ingestion), **Table 6** (EditEverything), and the App. A.6/A.7 sweeps were not run for budget reasons.

## Codebase completeness: MISSING_SCRIPTS
**What the release covers.** The method itself is complete and ran at full scale without logic changes:
- the LoReFT-style intervention with noise-robust training;
- routing by cosine similarity;
- HAC clustering, with the cluster index shipped;
- cluster-shared training;
- routed evaluation.

**What is missing for the main table.**
- The MMLU utility evaluation: the data is shipped in `final_data_v3.json`, but no script uses it. We wrote `scripts/mmlu_eval.py`.

**Changes to the released code** (left uncommitted in `./codebase`; the full diff is in `logs/codebase_diff.patch`). None of them changes training or evaluation logic.
- `train_test.py`:
  - added `--train_start/--train_end`, which train only a range of edit indices so several processes can run in parallel;
  - added resume (skip adapters that are already saved);
  - added `--skip_train/--skip_test`.
- `train_cluster.py`:
  - env vars `REPRO_CLUSTER_START/END` for cluster-index sharding plus resume;
  - env var `REPRO_SKIP_INLOOP_EVAL`, which skips the per-cluster oracle-routed generation inside the training loop. That generation is not used for any table; routed evaluation is done by `test_cluster_rep.py`.
  - a guard on the final summary for when that in-loop generation is skipped.
- `test_cluster_rep.py`: env vars `REPRO_EVAL_START/END` to evaluate an item range. Routing still uses all keys, and the output file gets a `_partA-B` suffix.

**Scripts we wrote outside the repo**
- `scripts/mmlu_eval.py`: MMLU with τ-gated routing.
- `scripts/score.py` and `scripts/make_status.py`: aggregation.
- `scripts/eval_single.sh`, `scripts/progress.sh`, `scripts/wait.sh`: helpers.

**Environment changes**
- Dropped `flash-attn` from the requirements (it is not installable here); sdpa is used instead.
- Pinned torch 2.4.1 and transformers 4.45.1.
- The README's `--record True` is parsed by argparse as `bool(str)`. Every value, including "False", becomes True. We ran with `WANDB_MODE=disabled`.

## Discrepancies
**Code vs paper**
1. **Robustness objective** (major; affects results, direction unknown).
   - **Where:** `REFT_trainer.py::ReftTrainerAdv` together with `REFT_module.py::LoreftIntervention_Explicit`. This is the path the README's `--adv_train_method Explicit` uses.
   - **Paper (Eq. 2):** cross-entropy on the *clean* intervened representation, plus λ·KL(p_clean ‖ p_perturbed) with ε ~ N(0, σ²I).
   - **Code:**
     - Gaussian noise (std 0.02) is added to h in *every* training forward pass. The trainer only zeroes `adv_epsilon`, an attribute the Explicit module does not have.
     - As a result, the cross-entropy is computed on a perturbed branch, and the "clean" KL target is a second, independently perturbed branch computed under `no_grad`.
     - Dropout (0.05) is also applied to the whole intervened hidden state.
     - λ = 0.001.
   - **Net effect:** noise-augmented cross-entropy plus a weak consistency term, which is a different loss from Eq. 2.
2. **The routing threshold is not applied in the generation eval** (minor).
   - **Where:** `train_test.py::Reft_test` and `test_cluster_rep.py`.
   - **Code:** always applies the nearest module.
   - **Paper:** applies it only if the maximum cosine similarity is ≥ τ=0.9.
   - **Effect:** negligible here; 0.1% of LLaMA paraphrases and 0% of Qwen paraphrases fall below 0.9.
3. **Maximum cluster size** (minor).
   - **Paper:** Table 9 lists "Max Cluster Scale 16".
   - **Code:** the code, README and shipped cluster index all use `max_cluster_size=8`. The 306 clusters reported in Tables 2 and 11 correspond to the code's setting.
4. **Routing key vs intervention location** (minor).
   - **Code, routing key:** the *input* to decoder layer L (`store_activation.py` hooks `input[0]` of `layers[L]`), taken at the last token of the prompt *with* the assistant generation header.
   - **Code, intervention:** applied to the *output* of layer L, at the last token of the prompt *without* the generation header.
   - **Paper:** describes both as "the layer-l representation of the last token".
5. **ROUGE-L variant** (minor).
   - **Code:** ROUGE-L *recall* (`score["rougeL"].recall`).
   - **Paper:** just says "Rouge-L".
   - **Effect:** changes absolute RougeL values.

**Paper-internal:** no inconsistencies found.
