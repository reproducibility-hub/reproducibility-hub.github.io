# Reproduction report — MTA: Multi-Granular Trajectory Alignment for LLM Distillation (ACL 2026, 2026.acl-long.1507)

## Verdict

| field | value |

| Codebase completeness | **MINOR_FIXES** |

The released code can be made to train and evaluate all six GPT-2 settings of Table 1. Every baseline lands close to the paper's numbers, and so does every MTA variant except DistiLLM+MTA. The paper's central claim is that MTA "consistently improves all baseline frameworks", and it only partly holds:

- **FDD + MTA:** a small but consistent gain. Ours is +0.41 avg ROUGE-L (mean of 3 training seeds, positive in every seed pair); the paper reports +1.02.
- **DistiLLM + MTA:** no gain. Our 3-seed mean is 20.69 vs 20.88 for the baseline; the paper reports 21.45 vs 20.21. Our DistiLLM baseline is stronger than reported, mainly on S-NI (27.3 vs 25.28).
- **DistiLLM-2 + MTA:** the released configs train the baseline with LR 5e-5, while the MTA variant and the paper's Table 9 both use LR 1e-4.
  - With the released configs the gain is +1.82 (paper: +1.35).
  - At the paper's stated LR the baseline reaches 19.56 instead of 18.27, and the gain shrinks to +0.45 (2-seed means: 20.01 vs 19.56).

## What was run

Paper target: **Table 1, GPT-2 1.5B → GPT-2 120M**. The same numbers also appear as the "Full" rows of Tables 2/3, the DistiLLM row of Table 4 and the 5-epoch rows of Table 7. Metric: ROUGE-L on Dolly (500), SelfInst (242), Vicuna (80) and S-NI (1694, the `11_` split). Each score is averaged over 5 generation seeds (10–50), sampling with T=1.0 and top-p=1.0, as in the release's evaluator.

- **Teacher:** `MiniLLM/teacher-gpt2-1.5B`, as in the release scripts.
- **Student init:** `openai-community/gpt2`.
- **Training data:** Dolly train (11,435 examples) / dev (1,000), tokenized with the release's `distillm-fdd/tools/process_data_dolly.py` (max prompt 128, max length 256).
- **Training schedule:** 5 epochs. DistiLLM and FDD use 3570 steps at effective batch 16; DistiLLM-2 uses 7145 steps at effective batch 8.

### Commands (all run from `codebase/`; wrappers live in `../myscripts/`)

1. **Data.**
   - The DistiLLM README's MiniLLM `data.tar` Azure link is dead (signature error), so I used the official MiniLLM HF mirrors instead: `MiniLLM/dolly` (`raw.jsonl`, `valid.jsonl`), `MiniLLM/self-inst`, `MiniLLM/Vicuna`, `MiniLLM/sinst` (`11_/valid.jsonl`), and `MiniLLM/dolly-processed` (`full/gpt2/{train,valid}.jsonl`).
   - The release's `process_data_dolly.py` expects `data/dolly/train.jsonl` and `dev.jsonl`, which no released script creates. I copied the MiniLLM-processed train/valid jsonl to those names, then ran `bash distillm-fdd/scripts/gpt2/tools/process_data_dolly.sh ./distillm-fdd`.
2. **DistiLLM / FDD (± MTA)** — the release scripts, unchanged apart from the env/path notes below:
   - `bash ./distillm-fdd/scripts/gpt2/{distillm/train_0.1B_1.5B_on.sh, spandistillm/train_0.1B_1.5B.sh, fdd/train_0.1B_1.5B.sh, spanfdd/train_0.1B_1.5B.sh}`
   - Extra CLI args: `--save <dir>`, plus `--seed 43` / `--seed 44` for the extra training seeds (`myscripts/train_fdd_family_tf452.sh`, `myscripts/train_seed_tf452.sh`, `myscripts/pipeline_seed.sh`).
3. **DistiLLM-2 data.**
   - Student: `bash distillm-2-master/scripts/gpt2/prepare_data_gpt2_0.1B.sh`.
   - Teacher: the same `generate.py` command with `--model_path MiniLLM/teacher-gpt2-1.5B`.
   - Then `generate/reformat.py`. It is given the `generated_train.jsonl` *files*, because the release script passes directories, which `datasets` cannot load. The release's eval checkpoint name (`checkpoint-7145` = 1429 steps/epoch × 5 at batch 8) confirms that only the train split was used.
4. **DistiLLM-2 (± MTA)** — the release's `distillm_2_gpt2_0.1b.sh` and `span_distillm_2_gpt2_0.1b.sh`.
   - I also ran the baseline at the paper's Table 9 LR of 1e-4 (`myscripts/gpt2-1.5b-0.1b-distillm2-lr1e-4.yaml`, the release yaml with only `learning_rate` and `output_dir` changed).
   - Seed 43 was run for both the LR-1e-4 baseline and MTA (`myscripts/d2_seed43.sh`).
5. **Evaluation:** `python src/run_eval.py --val_batch_size 128 --student_device cuda:0 --output_dir … --seed 42 --model_path <ckpt> --tokenizer openai-community/gpt2`. This is the same command as `scripts/eval_*.sh`, wrapped in `myscripts/eval_ckpt.sh`. The final checkpoint is evaluated for every run. Results are collected with `myscripts/collect.py`.

### Settings that differ from the paper or the release

- **Environment.**
  - The release has two setups: `distillm-fdd/install.sh` (torch 2.6.0 + transformers 4.52.4) and `distillm-2-master/setup.py` (torch 2.4.0, transformers 4.43.2, trl 0.9.6).
  - Only one conda env is allowed here, so the env holds the DistiLLM-2 versions. The DistiLLM/FDD runs and **all evaluations** use torch 2.6.0 + transformers 4.52.4 from a pip `--target` overlay (exposed through `PYTHONUSERBASE`; `myscripts/setenv_fdd.sh`).
  - This matters. Under transformers 4.43 the FDD baseline's teacher attention wrapper (`fdd_finetune.py::customize_model_attention`) makes the wrapped GPT-2 layers run SDPA with a *non-causal* mask: the teacher sees future tokens, hidden states diverge by more than 100, and the student collapses (dev ROUGE-L about 7.6).
  - Under 4.52.4 the wrapper is exact (max hidden-state diff ≤ 0.125). The broken first FDD run was discarded.
  - I also kept three early DistiLLM / DistiLLM+MTA / FDD+MTA runs made under transformers 4.43; they don't use the wrapper. They are reported below as extra replicates only.
- **Extra training seeds.** The paper reports a single run. I trained seeds 42 (the release default), 43 and 44 for the four DistiLLM/FDD settings, and seeds 42 and 43 for DistiLLM-2 at LR 1e-4 and DistiLLM-2+MTA.
- **Checkpoint.** I evaluate the final checkpoint (epoch 5) for every method. The release eval script for DistiLLM+MTA instead points to checkpoint **2856 (epoch 4)**; that checkpoint is also reported below.
- **GPU sharing.** Hardware is one H200 (paper: A100 40GB). Up to 7 jobs shared the GPU; this changes speed, not the configs.

## Why this is not fully reproduced

1. **DistiLLM + MTA does not beat DistiLLM.** This holds over 3 training seeds in the release's own environment, and also over 4 runs once the tf4.43 replicates are added. I found no bug or code–paper difference that would explain it. The configs match Table 8 and Table 10 (λ_DSA = 2 via `--w-span-loss 2.0`; λ_Hid = 0.2 via `token_loss/10` × 2), and the layers match Table 11 (student 6 | 9, 12).
2. **The baselines are stronger than reported.**
   - DistiLLM S-NI: 27.3–29.0 in our runs vs 25.28 in the paper.
   - DistiLLM-2 at the paper's stated LR: 19.56 vs 18.59.
   - The paper's DistiLLM-2 baseline number is consistent with the released 5e-5 config (ours 18.27), not with the 1e-4 its Table 9 states. This inflates the reported DistiLLM-2 gain.
3. **The FDD+MTA and DistiLLM-2+MTA gains are real in our runs, but smaller.** FDD+MTA: +0.41 (paper +1.02). DistiLLM-2 LR-matched: about +0.5 (paper +1.35).
4. **Only GPT-2 is covered.** The repo has no scripts or configs for Qwen1.5-1.8B→0.5B or OPT-6.7B→1.3B (the other two blocks of Table 1, including the LoRA setup). They were not attempted.
5. **The GPT-4o-mini judge results (Figs. 4–5) were not run.** That metric needs an API we don't have, and it is not part of the main ROUGE-L table.

## Codebase completeness: MINOR_FIXES

The method (DSA and hidden alignment losses, spaCy span extraction, token weighting) is fully implemented for all three frameworks, and the GPT-2 training scripts are present. Changes I made to the release (all left uncommitted in `./codebase`; see `git diff`):

1. `src/run_eval.py`: the whole `main()` body after `set_seed` is commented out, so the released eval script does nothing. I uncommented it, verbatim (it matches the intact copy in `distillm-2-master/generate/generate.py`).
2. `distillm-2-master/generate/reformat.py`: it writes `chosen`/`rejected` as chat-message lists, but `DistiLLMTrainer.tokenize_row` requires strings (the chat-template step is commented out in `run_distillm.py`), so training crashed. Changed it to write the response strings.
3. `distillm-2-master/training_configs/*.yaml`: added `report_to: none`. `alignment/configs.py` declares `split_layer_mapping` with `field(default=list)`; that is a dataclass default bug which makes the value the `list` type itself, and the TensorBoard callback crashes serializing it in the baseline run.
4. `distillm-2-master/accelerate_configs/deepspeed_zero0.yaml`: added `main_process_port` so two runs can share the node.
5. All training shell scripts: commented out the hard-coded `export CUDA_VISIBLE_DEVICES=…`. It was `1` in the DistiLLM-2 scripts; the Slurm allocation must be used instead.
6. The scripts use `BASE_PATH=./distillm-master`, but the folder is named `distillm-fdd`. I added a symlink `codebase/distillm-master -> distillm-fdd` (path fix, no edit).
7. The release's `reformat_data.sh` passes directories to `reformat.py`, which `datasets` cannot load. I passed the jsonl files on the command line instead.

Missing pieces I worked around:

- The data link in the README is dead; I used the HF mirrors.
- `process_data_dolly.py` (modified by the authors) needs `data/dolly/train.jsonl` and `dev.jsonl`, which no script produces; I used MiniLLM's processed train/valid splits.
- There are no scripts or configs for Qwen1.5 or OPT.
- There is no GPT-judge evaluation script for Figs. 4–5 (`src/gpt_eval.py` exists but needs an OpenAI key).

The environment issue (the FDD baseline is silently broken under the DistiLLM-2 transformers pin) is an env/version incompatibility, not a code edit. It is solved by using the release's own `install.sh` versions.
