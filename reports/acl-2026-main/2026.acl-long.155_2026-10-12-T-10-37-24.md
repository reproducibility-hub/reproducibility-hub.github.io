## Component extraction check (beyond the paper's tables)

The Table 2 results above use the authors' **released** components. To check the method itself (activation collection → top-k feature selection → Pearson-correlation graph → Neuronpedia density pruning → weakly connected components → KL ranking), we re-ran `pipeline_extract_components.py`:

1. **As released, it can't regenerate the released components.** Two bugs:
   - **Density cache keyed by feature index only.** `feature_densities[feature]` ignores the layer, so the density of feature *i* at one layer (or from an earlier prompt) is reused for feature *i* at every other layer. On capital/China this gives a 664-node sparse graph instead of the released 689-node one.
   - **Top-k overwritten.** `for k in sorted_component_indices:` overwrites the top-k hyperparameter (k = 5), so every prompt after the first selects ~700–900 features per layer (~20k nodes; observed for currency/China). Every released graph has ~1.0–1.8k nodes, so the authors' data wasn't produced by this exact code path.
2. **After fixing both (`git diff codebase/pipeline_extract_components.py`), re-extraction of all 30 country-fact prompts reproduces the release exactly.** Full graphs, sparse graphs and component sets are identical, and the top-5 KL ranking is identical for every prompt; ranks differ only in the near-zero-KL tail. Recomputing the 10 country concept key components (intersection over relations, using the indices in data.zip `country_components.json`) from our re-extracted components gives exactly the released key components.
3. **The released translation components were built with the density-cache bug.** Densities stored in the released translation graphs disagree with the true per-(layer, feature) Neuronpedia density for 2,521 of 30,298 nodes checked; for countries it is 0 of 15,290. For example, node 0.7011 is stored with density 0.0015 but its true density is 0.035 > τ, so it should have been pruned. Neither correct nor per-prompt-buggy re-pruning reproduces the released translation sparse graphs exactly; the bug probably carried across prompts within a run.
4. **The released verb-transformation components were built without density pruning.** Their "sparse" graphs keep 100% of the full graph's edges and contain nodes with density up to 0.99 (other tasks: max 0.01, 50–65% of edges). Re-extracting 5 verb prompts with τ = 0.01 gives different components (e.g. capitalize/break: 78 vs 125 components, top-5 all different). The hand-picked indices in `sae_modules/tasks/verbs.py` refer to the unpruned extraction. So the verb results in Tables 2 and 5 come from a method variant that Section 2 doesn't describe.
5. The relation-component indices used to build the countries/translation **relation** key components aren't released, and `combine_components.ipynb` asserts they exist, so those key components can only be taken from data.zip.

## Codebase completeness: MAJOR_FIXES

The main experiment (Table 2 steering with the released components) runs with the released `pipeline_eval.py`. The only change needed was environment-level: the hard-coded `HF_ENDPOINT=https://hf-mirror.com`. For that path alone the level would be TRIVIAL_FIXES. The level is MAJOR_FIXES because the method's own component-extraction script has two results-changing bugs that had to be fixed before it could regenerate the released components.
