**Summary.** The paper says its data is released with the code on GitHub (App. B.1). It isn't. The repo has no
question/split files (`things.jsonl`, `things-hyp.jsonl`, `data/preprocessed_THINGS/*.json`), no script that generates
them, and no stimuli for the LM-only experiment (`yn_questions.jsonl`, `all_questions.jsonl`, `category-lexicon.csv`).
The released training script also crashes as shipped. I rebuilt the data from public sources: THINGS images (OSF),
THINGSplus 53-category annotations, and the Rodriguez et al. (2025) lemma list. Then I ran the released training and
eval code (with fixes) for the main experiments: Figs 3, 4, 6 and 7, plus the §4.1 and §4.3 numbers.

On the rebuilt data, all the paper's main claims hold, and most numbers fall inside the paper's 95% CI or within 5%:
- **Central claim (Fig 4, 100% ablation).** With no hypernym evidence at all, pretrained Qwen3 backbones generalize
  well above chance to held-out hypernyms (ours 70.8 / 76.0 vs paper 74.1 / 74.6; majority 39.6 / 39.2). Random-init
  LMs stay near chance (46.2 / 47.9 vs 45.2 / 45.3).
- **Counterfactual shuffles (Fig 6).** Across-category shuffles drop to near chance (45.4 / 46.8 vs 46.4 / 48.2). The
  within-category shuffle stays at the level of the original data (70.2 / 79.3 vs 73.7 / 76.7). This holds at every
  random-ablation level.
- **SigLIP vs DINOv2 (Fig 3).** Comparable performance (SigLIP 74.1 / 70.7 vs paper 67.8 / 73.2).
- **Visual coherence (§4.3).** original 0.281 vs paper 0.27; across-shuffle 0.117 vs 0.12.
- **Coherence–F1 correlation (Fig 7).** r = 0.50 vs 0.43.
- **LM-only hypernymy (§4.1).** 75.7 / 85.5 vs 78.5 / 88.5.

Two things did not reproduce:
1. Randomly initialised LMs learn the *leaf* task much worse than the paper reports, especially for Qwen3-1.7B
   (61.5 vs 84.4). The random-init procedure is not in the release, so it had to be reconstructed.
2. The systematic-ablation held-out numbers aren't comparable. The released `ablate_cat.py` doesn't produce the
   authors' own test sets (see the Discrepancies section).

Under the task rules, numbers on rebuilt data are `NOT_COMPARABLE` and the verdict is FAILED. The table below still
gives an informal agreement label for each number.

## What was done
1. **Read the paper.** Main claims: Fig 4 (Held-Out Hypernyms, pretrained vs random LM, random/systematic ablation),
   Fig 6 (counterfactual shuffles), Fig 3 (DINOv2 vs SigLIP), and the preconditions in §4.1.
2. **Codebase.** Cloned github.com/sally-xu-42/cross-modal-taxonomic-gen (commit aefd30e) into `./codebase`. Its
   `prismatic-vlms` submodule (a public fork, sally-xu-42/prismatic-vlms @ 168e919) went into `codebase/prismatic-vlms`.
3. **Environment.** conda env `./env`: Python 3.11, torch 2.9.0+cu128, transformers 4.57.1, timm 0.9.10, draccus @
   13dd58f, as pinned in `requirements.txt`. `minicons` is left out (it requires torch<2). Since then deleted.
4. **Data rebuild** (`repro/build_base_data.py`, `repro/make_ablations.py`):
   - **Leaves.** THINGS concepts whose word is one of the 1,216 `generic=='p'` lemmas of Rodriguez et al. and that
     have a THINGSplus category: 1,197 image folders / 1,180 lemmas / 16,953 images (paper: 1,222 folders / 1,216
     lemmas / 17,336 images). Hypernyms come from THINGSplus `category53_longFormat.tsv` (53 categories, 1.69 per
     leaf; paper 1.67). Question phrasings ("item of clothing", "source of light", "musical instrument", …) are taken
     from the column names of the authors' released result CSVs.
   - **Questions.** "Is there {a/an X} in this image?". Each image gets one positive leaf question, one negative leaf
     question (uniformly sampled other leaf), and a positive plus a uniformly sampled negative hypernym question for
     each of its hypernyms. Split per concept is 70/5/25 (sorted file names), as in the fork's
     `scripts/additional-datasets/things.py`.
   - **Sizes vs paper Table 2.** Train (100%) 22,722 vs 23,250. Test leaf 9,182 vs 9,394. Test hypernym 15,552 vs
     15,702. At 30% ablation: train 42,958 vs 43,340, test unseen 7,376 vs 7,568.
   - **Ablations and shuffles.** Produced by calling the released functions: `ablate_hyp.py` (random ablation),
     `mislabel.py` (shuffle maps), `ablate_hyp_shuffle.py` / `ablate_hyp_local_shuffle.py`. Systematic ablation uses
     `ablate_cat.py`'s category lists and its question-level removal logic, extended to the train split.
5. **Training** (`repro/train_one.sh`, a 1-GPU version of `scripts/train.beehive`). Uses
   `prismatic-vlms/scripts/resumable_pretrain.py` in the align stage: frozen DINOv2-L/14 (or SigLIP-SO400M) and frozen
   Qwen3, training only the 2-layer GELU MLP projector, 5 epochs, global batch 16. Our per-device batch is 16 with no
   gradient accumulation; the authors used 4 GPUs × 4. LR 1e-3, weight decay 0, linear-warmup (3%) + cosine. These
   are the align-stage code defaults the released scripts use; see the Discrepancies section on Table 1. Gradient
   checkpointing is off (a speed-only change). 3 workers ran in parallel on one H200.
6. **Evaluation.**
   - `repro/eval_batched.py` is a batched copy of `src/evaluation/eval_things.py`'s align-stage path: same model
     construction, same prompt, same decision rule (argmax of first-token log-prob over {Yes, No}). It agrees with the
     unmodified `eval_things.py` on 299/300 predictions; the one disagreement looks like a bf16 near-tie.
   - Per-category macro-F1 (sklearn) is computed per hypernym, with the category taken from the question via
     `eval_things.extract_hypernym`, then averaged over categories × seeds. This is the exact aggregation behind the
     paper's plots: applied to the authors' released per-run CSVs it reproduces Table 5 exactly (78.42±1.33,
     50.04±0.68, 79.82±1.17; majority 39.20).
   - "Paper" numbers below are that aggregation applied to the authors' released
     `results/main-results/macro-f1s/*.csv`, i.e. the exact values plotted in Figs 3/4/6.
7. **Run grid.** 86 trained models in `runs/` (plus 6 sensitivity runs), all with DINOv2 unless marked SigLIP:
   - **100% ablation:** {0.6B, 1.7B} × {pretrained, random-init, across-shuffle, within-shuffle} × 3 seeds (42/218/7).
   - **SigLIP:** {0.6B, 1.7B} × 3 seeds at 100% ablation.
   - **Random ablation 10/30/50/70/90%:** pretrained (seed 42; plus seed 218 for 0.6B at all levels and for 1.7B at
     50/70/90%), random-init LM (seed 42), across- and within-shuffle (seed 42), for both LMs.
   - **Systematic ablation 10/20/30/40 categories:** pretrained, seed 42, both LMs.
   - **Sensitivity runs:** paper-LR (2e-5/0.1) runs and HF-style random-init runs, kept in `runs_paperlr/` and
     `runs_hfinit/`.

### Settings that differ from the paper
- Data rebuilt, so splits and negative samples differ (see above).
- Fewer seeds at the intermediate ablation levels and for the random-LM / shuffle / systematic curves (1 seed, or 2
  for some levels, instead of 3).
- Not run (appendix, or no released code):
  - systematic ablation with random-init LMs, and systematic ablation under the shuffles;
  - Llama-3.2 backbones (Figs 10/11);
  - Qwen3-8B (Table 5);
  - the hypernym-level swap toy experiment (§5; no released code);
  - the mixed-effects regressions.
- Random-init LM: implemented by us with PyTorch default module init (`reset_parameters`). With HF `_init_weights`
  (std 0.02), the random-LM VLM stays at chance even on leaves (0.6B leaf F1 47.5 vs paper 85.2).

## Why it is not a full reproduction
- **Missing data.** The question/split files, the script that generates them (negative sampling), and the LM-only
  stimuli are not released, even though App. B.1 says the data is released with the code. I had to rebuild them; the
  rebuilt leaf set covers 98% of the paper's images.
- **Missing code.**
  - The random-init-LM baseline (`--random_init_llm`, passed by `train.beehive`) is not implemented in the fork.
  - The script that materialises the shuffled datasets (`*_shuffled.json`) is missing.
  - The F1 aggregation script is missing.
  - `src/__init__.py` is missing, and its absence crashes training (see "As released" below).
  - Model configs `siglip+500m` / `siglip+1b` and dataset configs for the systematic, shuffled and 8B runs are missing.
- **Compute.** Running all 3 seeds for every intermediate ablation level and every curve would have exceeded the
  48 h / 1-GPU budget, so most intermediate levels have 1 seed.

## Discrepancies
- **[code_vs_paper, minor] Table 1 (App. A) vs prismatic/conf/models.py align-stage defaults used by scripts/train.beehive** — paper: learning rate 2e-5, weight decay 0.1 — code/other: align stage (projector-only, the stage used for all runs) uses align_learning_rate=1e-3, align_weight_decay=0.0; train.beehive does not override them (2e-5/0.1 are the finetune-stage defaults). With 2e-5/0.1 our runs underfit (e.g. Qwen3-1.7B 100% ablation leaf 89.8 / held-out 68.3; 0.6B within-shuffle leaf 72.9 / held-out 63.3) while 1e-3/0.0 matches the authors' released results, so 1e-3/0.0 was used. — affects results: True
- **[code_vs_paper, major] Sec 3.3 'Random Hypernym Ablation' vs src/ablation/ablate_hyp.py (create_train_ablations/create_test_ablations)** — paper: removing a mapping (x,h) removes only image-question pairs with images of leaf x and questions about hypernym h (and the corresponding negatives) — code/other: for each hypernym a fraction of its leaves is sampled and ALL hypernym questions of those leaves (for every hypernym, positive and negative) are removed from train and assigned to the 'unseen' test split; at least one leaf is removed per hypernym — affects results: True
- **[code_vs_paper, major] Sec 3.3 'Systematic Hypernym Ablation' / Table 3 vs src/ablation/ablate_cat.py** — paper: entire hypernyms removed from the positive training examples; a removed hypernym may still appear as a negative category; Table 3 test 'unseen' sizes 5,608 / 8,626 / 11,460 / 13,018 for 10/20/30/40 categories (these equal the authors' released all_unseen_counts.csv, whose unseen sets contain questions under all 53 categories) — code/other: ablate_cat.py removes every question whose text names a removed category (question-level, incl. negatives), only for val/test of the within-shuffled data; applied to our rebuilt data it yields unseen sets of 3,149 / 5,796 / 8,269 / 10,985 restricted to the removed categories — the procedure behind the paper's systematic-ablation splits is not in the release — affects results: True
- **[code_vs_paper, minor] Sec 4.3 / Algorithm 2 vs src/shuffle/mislabel.py::shuffle_concepts_within_category** — paper: within-category shuffle permutes leaves within groups of identical hypernym sets; its visual coherence is identical to the original by definition — code/other: singleton groups are merged into the most specific subset group and leftover orphans are deranged across groups, so some leaves move across categories; the authors' own released coherence CSV gives 0.269 (within) vs 0.274 (original) (ours 0.275 vs 0.281) — affects results: True
- **[code_vs_paper, major] Sec 3.2 (randomly-initialized LM counterparts) vs scripts/train.beehive / resumable_pretrain.py** — paper: VLMs with randomly initialized LM backbones are trained as a control — code/other: train.beehive passes --random_init_llm True but the option does not exist in the released fork (draccus would reject it); the initialisation scheme is unspecified. With HF _init_weights our random-LM VLMs stay at chance even on leaves (0.6B leaf F1 47.5), with PyTorch default init 78.9 (0.6B) / 61.5 (1.7B) vs paper 85.2 / 84.4 — affects results: True
- **[paper_internal] Fig 3 (dashed majority line) vs Table 5 / Fig 4** — paper: Fig 3 draws the majority-label baseline for the 100%-ablation held-out test set at 47.1 (analyze-f1-results.R: geom_hline(yintercept = 0.471)) — code/other: Table 5 reports the majority-label baseline for the same 100%-ablation setting as 39.2 (= released all_hyp_guess_f1_scores.csv test_hyp 39.20) — affects results: False
