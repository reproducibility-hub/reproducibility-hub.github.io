## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): MIXED.** Llama-2-7B, the paper's headline model:
  - The Table 1 zero-shot numbers match within tolerance (0.5–2.4 pts low, all ≤5% relative).
  - Perplexities match.
  - MMLU-5shot is 38.5 vs 44.0, and training-free MMLU is 37.5 vs 42.5. Neither matches.
  - GSM8K-8shot collapses: 0.8% strict / 3.0% flexible vs 13.0.
  - Qwen-2.5-7B zero-shot is mixed: 2 tasks within tolerance, ARC-C above the paper, and WinoGrande and HellaSwag 5.4–5.5 pts below.
- **Result match as released: DOES_NOT_RUN.**
  - The released zero-shot evaluation imports a Wanda-modified lm-eval 0.3 fork (`hf-causal-experimental`, `pretrained_model=`) that is not shipped.
  - That eval also uses few-shot settings that differ from the paper.
  - The unmodified `run_cmoe.py` with the paper's 2048 SFT samples was OOM-killed on our 111 GB host before carving (details below).
- **Coverage: SUBSET.**
  - Run at paper scale: Llama-2-7B and Qwen-2.5-7B, S3A3E8 config, 8 calibration samples, 2048-sample LoRA SFT.
  - Not run:

    - Qwen3-30B-A3B (the hierarchical MoE-of-MoE code is not in the release).
    - All baselines (no code in the release).
    - HumanEval (not available in the lm-eval version used).
    - Speedup/throughput tables (no efficient-kernel or benchmark code released).

## What was run
Environment:
- Conda env at `./env`, Python 3.11, torch 2.4.1+cu124.
- transformers 4.47.1, peft 0.14.0, datasets 2.21.0, accelerate 1.2.1, lap 0.5.12. These are the README pins.
- lm_eval 0.4.5 for evaluation.

Models:
- `NousResearch/Llama-2-7b-hf` (identical weights to meta-llama/Llama-2-7b-hf).
- `Qwen/Qwen2.5-7B`.

Driver: `repro_run.py` (written by me). It:
- calls the released `cmoe_sequential` (carving, training-free PPL, then LoRA SFT via `simple_sft`) and the released `cmoe_ppl_eval`;
- evaluates with lm-eval 0.4.5 `HFLM(pretrained=<in-memory model>)`:
  - zero-shot piqa, winogrande, arc_easy, arc_challenge, hellaswag (the paper's Table 1 tasks);
  - `mmlu` 5-shot;
  - `gsm8k` 8-shot.

Settings:
- Paper config: S3A3E8 (`--nshared 3 --nactivated 3 --nexperts 8`), K_a=10.
- Calibration: 8 WikiText-2 samples × 2048 tokens.
- SFT: 2048 WikiText-2 samples, 1 epoch, LoRA r=8/α=32, batch size 2.
- γ=1e-3, router-scale lr 1e-3, LoRA lr 5.65e-5 (code default; the paper says 5.95e-5).

Commands (all from the attempt dir; `$L` / `$Q` = local HF snapshot paths):
```

CMOE_TRAIN_SCALE=1 python repro_run.py $L wikitext2 ... --nsamples 2048 --mmlu --out results/llama2_S3A3E8_ft2048_trainscale.json    # learnable-scale bug fixed

python repro_run.py $Q wikitext2 ... --nsamples 2048 --auto --out results/qwen25_S3A3E8_ft2048.json ; python repro_run.py $Q wikitext2 --dense --auto ...
```

### Learnable-scaling fix (my ablation)
In the released code, LoRA's `get_peft_model` freezes `Router.extra_scale`. After SFT it is exactly 0 in all 32 layers, so the gates stay binary. With `CMOE_TRAIN_SCALE=1` (my opt-in fix), the scales train (max |u| per layer ≈ 0.10–0.25), but results barely change:

| Task | As released | With fix |
|---|---|---|
| PIQA | 73.83 | 72.85 |
| WinoGrande | 65.04 | 62.90 |
| ARC-E | 65.32 | 64.56 |
| ARC-C | 38.65 | 39.16 |
| HellaSwag | 66.98 | 67.41 |
| MMLU | 38.54 | 39.27 |
| PPL (wiki / C4) | 5.78 / 11.21 | 5.77 / 11.09 |

The fix does not explain the MMLU gap.

### Not reproduced / not comparable
- Baselines in Tables 1/2/3/5 (SliceGPT, SLEB, LLaMA-MoE, LLaMA-MoE-v2, EMoE, MoEfication, Read-ME): the paper says they were "re-implemented by us", but none of that code is released. So the "outperforms all baselines" claims can only be checked against the paper's own baseline numbers.
- Llama-2 70B: about 140 GB of bf16 weights plus LoRA SFT do not fit on one 141 GB GPU with 111 GB host RAM. Insufficient compute.
- Qwen3-30B-A3B (hierarchical restructuring, Sec 4.4; Tables 1, 7, 11): the release only handles dense LLaMA-style MLPs. The MoE-of-MoE code is missing.
- Tables 7, 8, 9 (FLOPs/throughput/speedup, WINA, Qwen-2.5 72B industrial speedup): there is no benchmarking or efficient-kernel code. The released MoE forward is a Python loop over experts.
- Tables 10 and 11 and Figures 4 and 6: not run, to keep within budget and focus on the main table.

## Why it is not fully reproduced
- **Coverage:** two of the four Table 1 models cannot be run (compute / missing hierarchical code), and baselines are absent.
- **Results:** on Llama-2-7B the zero-shot and PPL numbers reproduce, but the knowledge and reasoning results (MMLU, GSM8K) are far below the paper. Our dense MMLU (45.7) and GSM8K (14.4) agree with standard Llama-2-7B values, so the eval pipeline is sound. I found no bug in the method code that explains the gap; the one bug I found (frozen scaling) has a negligible effect.
- **Qwen-2.5-7B:** two tasks are 5+ points below the paper.

## Codebase completeness: MINOR_FIXES
Changes to the released code (uncommitted in `./codebase`, see `git diff`):
1. `run_cmoe.py::cmoe_sequential`: allocate the calibration-capture buffer for 1 batch only, break after the first batch, and remove the unused `outs`/`moe_outs`. The original allocates three CPU tensors of size `nsamples/8 × 8 × 2048 × 4096` bf16 (3 × 34 GB for 2048 samples), but only `inps[0]` (the 8 calibration samples) is ever used. This OOM-killed the process on our 111 GB host (cgroup `oom_kill 1`). The fix is memory-only; results are unchanged.
2. `datautils.py::get_c4`: added the missing `from datasets import load_dataset` (NameError when using C4 calibration).
3. `sft_utils.py::simple_sft`: an opt-in (`CMOE_TRAIN_SCALE=1`, default off) unfreezing of `extra_scale` after `get_peft_model`. It was used only for the ablation above; the main numbers are from default (as-released) behaviour.

Scripts I wrote:
- `repro_run.py`: driver plus a thin lm-eval 0.4.5 HFLM wrapper, replacing the unshipped Wanda lm-eval fork used by `zero_eval.py`. It also loads Qwen via `AutoModelForCausalLM` (`get_llama` hard-codes `LlamaForCausalLM`, which would silently drop Qwen2's qkv biases) and injects `get_loaders` into the `run_cmoe` module namespace, where it is otherwise only imported under `__main__`.
- `queue*.sh`, `poll.sh`.

Other notes:
- README: `--nsamples 0` for training-free mode would crash (empty capture tensor / missing `position_ids` key). I used `--epoch 0 --nsamples 8` instead, which gives identical calibration.
- `run.sh` defaults (S2A2E16, 64 samples) are not the paper's main config.
