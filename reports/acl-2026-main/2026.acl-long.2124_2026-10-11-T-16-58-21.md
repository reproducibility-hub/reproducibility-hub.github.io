# Reproduction report: Mind's Eye (ACL 2026, 2026.acl-long.2124)

**Verdict: PARTIALLY_REPRODUCED.** Result match: **MIXED** (as released: **DOES_NOT_RUN**). Coverage: **SUBSET**. Codebase completeness: **MAJOR_FIXES**.

- Code: https://github.com/microsoft/Mind-s-Eye (linked in the paper). It includes the benchmark data (`data.tar`), the generators and an evaluation pipeline (`evaluation/evaluation_pipeline.py`, Gemma3:4b judge via Ollama).
- Target: **Table 2** (main results, CoT setting). These are the per-task accuracies on the 8 tasks for the open-source MLLMs that the release supports, all ≤ 11B. Per the user's instruction, Qwen2.5-VL-32B was skipped.
- **Headline claim holds.** Every evaluated MLLM stays far below the reported human accuracy (68–88% per task) and below 50% on average. The best average is 41.2% (InternVL3.5-8B).
- **Individual numbers and the model ranking do not reproduce.** Only 7 of 56 per-task numbers are within tolerance (≤ 1 pt absolute or ≤ 5% relative).
  - Our spread across models is much larger than in Table 2. The paper has every model at roughly 24–27% average. We get InternVL3.5 41.2, Qwen2.5-VL-7B 33.0, Idefics3 28.2, Qwen2.5-VL-3B 28.1, Phi-3.5-V 25.8, LLaVA-1.6 22.8 and Llama-3.2-11B-Vision 16.3.
  - Some single tasks exceed 50%: InternVL3.5 VCS 63.7 and MC 57.7; Qwen2.5-VL-7B VCS 51.1.

## What was run
- Environment: conda env (python 3.10) with torch 2.6.0, transformers 4.53.3, accelerate, qwen-vl-utils 0.0.14, deepeval 4.2.8, ollama 0.6.3 and timm/einops.
- Judge: Ollama v0.40.3 (local binary in `./ollama`) serving `gemma3:4b`, which is the code's default and matches "Gemma-3" in the paper.
- Data: the released `data.tar`, extracted to `codebase/data`. It holds 911 items: VRA 221, VCS 90, and 100 for each other task.
- Command for each model (`run_model.sh`):
  ```
  MINDS_EYE_DATASET_ROOT=codebase/data MINDS_EYE_EVAL_OUTPUT_DIR=model_evaluation MINDS_EYE_OLLAMA_BASE_URL=http://127.0.0.1:11555 \
  MINDS_EYE_LLAMA_PATH=unsloth/Llama-3.2-11B-Vision python codebase/evaluation/evaluation_pipeline.py --models <m> --steps 0 1 2
  ```
  Phi uses `python run_with_phi_shim.py --models phi --steps 0`. All models ran concurrently on one H200.
- Runs: the code runs every model 3 times ("steps").
  - Qwen2.5-VL-3B/7B (sampling at T=0.1) and InternVL3.5-8B (`do_sample=True`, T=0.1) got all 3 runs.
  - Idefics3 also got 3 runs; its responses were byte-identical across runs.
  - LLaVA-1.6, Llama-3.2-11B-Vision and Phi-3.5-V use greedy decoding (no `do_sample`), so repeats are identical. To save GPU time they were stopped after run 1.
- Settings are the code's own throughout: `max_new_tokens` 1000 (1024 for InternVL), temperature 0.1, the released prompts, and the judge extraction prompt.
- Aggregation: `aggregate.py` reports per-task accuracy as the mean ± std over runs. `make_comparisons.py` builds the table below.

### Differences from the paper's setting
- Llama weights come from `unsloth/Llama-3.2-11B-Vision`, an ungated mirror with weights identical to the gated meta-llama repo.
- Prompts are the released ones (generic "Reason step by step"). The paper's anchored CoT template is not in the release.
- InternVL: the code evaluates InternVL3.5-8B, but the Table 2 row is labelled "InternVL3 - 8B".
- Item counts are those of the released data (VRA 221 and VCS 90, not 100).

Notes on the results:
- **Run-to-run std.** For the sampled models (Qwen, InternVL) it is 1–6 points. Table 2's "±0.01–0.71" values are far smaller, unless they are fractions, which would mean 1–71 points. With a ±2-point tolerance a few more rows would match, but the overall picture is the same.
- **Llama-3.2-11B-Vision.** The release prompts the *base* model with a raw prompt and no chat template. It mostly degenerates ("I'm not able to provide information about the image's content…" repeated up to 1000 tokens), and 33% of its outputs are unparseable. This gives below-chance scores on MT, DSC and SS. The paper's ~29% numbers for Llama cannot come from this code path as released.
- **Unparseable rate** (judge returns X or an invalid letter): Idefics3 3%, InternVL 0%, Qwen-7B 3%, Qwen-3B 10%, LLaVA 11%, Llama 33%.
- **As-released Idefics3** (`model_evaluation_asreleased/`): VRA 17.6, HPE 16, DSC 16, VCS 4.4, SS 17, MT 25, PF 27, MC 29. Here 7 of 8 tasks got a 1-character prompt.

## Why it is not fully reproduced
1. The release cannot produce Table 2 as is. A debug `break` limits evaluation to 1 item per task, and `question[0]` turns the prompt into a single character for 7 of 8 tasks. After the fixes, the numbers differ substantially from Table 2: different per-task values and a different model ranking. I found no remaining code/config difference that would explain this, except that the anchored-CoT prompt templates of the paper are not released.
2. Models not run:
   - Qwen2.5-VL-32B: skipped per user instruction (> 14B).
   - BLIP-2.7B, InstructBLIP-4B, PaliGemma-3B, SmolVLM-2.2B, Vision-G1-7B, GT-Thinker-7B, V-Thinker-8B: the release has no loader or inference code for them.
   - GPT-o3, GPT-4o, Gemini-2.5: closed APIs, no key available.
   - Human study: not reproducible.
   - Appendix prompting-strategy tables (16–19): their templates are not released.
