# Reproduction report — 2026.acl-long.472 "When Morphology Hides in Plain Sight" (HuTieuBERT)

## Verdict
- **Verdict: FAILED**
- result_match (with our pipeline): **NO_MATCH**; result_match_as_released: **DOES_NOT_RUN** (release has no training/eval scripts)
- coverage: **SUBSET** (8 of 10 Vietnamese tasks of Table 1 and the 4 accessible datasets of Table 2, all at full scale: full splits, 5 seeds, 30/5 epochs; VLSP_13, VLSP_16 and Table 3 Chinese not run; stage-1 MLM not re-run, used released checkpoint)
- codebase completeness: **MISSING_SCRIPTS**
- flags: BASELINE_STRONGER_THAN_REPORTED (+ derived: CODE_PAPER_MISMATCH_MAJOR/MINOR, PAPER_INCONSISTENT)

**Bottom line.** We used the released stage-1 checkpoint (`ducanhdinh/HuTieuBert`) with the released model code (layers 1–2, all 12 heads, α=0.5, β=−0.3, γ=δ=0, adaptive BMES fusion) and fine-tuned it with a stage-2 pipeline we wrote from the paper. Under that setup HuTieuBERT is **not better than plain PhoBERT-base** on any of the 8 tasks we could run; it is the same or slightly worse. The headline POS gains do not appear: the paper reports UD_VTB 95.67 and VnDT 98.73, and we get 92.87 and 94.77. On those two datasets PhoBERT fine-tuned the same way scores 93.13 and 94.77. On PhoNER and VietMed, both models score far *above* the paper's numbers. HuTieuBERT's macro-F1 on the four sentence-level tasks is close to the paper's values, but there too PhoBERT scores higher. In the ablation, only one paper finding holds up: removing BMES fusion consistently hurts.

## What the release contains
- `model/tokenizer.py`: MorphemeAwareTokenizer, which does VnCoreNLP word segmentation, BMES tagging and BMES→subword alignment.
- `model/embeddings.py`: Adaptive Boundary-Token Fusion (gated BMES embedding plus LayerNorm).
- `model/model.py`: MorphemeAwareRobertaModel, which monkey-patches the self-attention of the chosen layers to add the structural bias. It also provides the MLM and sequence-classification wrappers.
- `model/bias_utils.py`: builds the structural bias matrix.
- `utils/visualize_bias_matrix.py`: plotting helper.
- On the HF hub: the pretrained checkpoint `ducanhdinh/HuTieuBert` (all weights load, including the BMES embeddings and gate).
- **Not released:** data preparation, stage-1 MLM training, stage-2 fine-tuning, a token-classification head (needed for POS/NER), evaluation, baseline configs, hyperparameters (learning rate, batch size, max length, warmup and patience are not in the paper either), and anything for the Chinese MAChineseBERT experiment or the Fig. 3 / Table 4 analysis.

## What we ran
Environment: conda env at `./env` with Python 3.11, torch 2.6.0, transformers 4.57.1 (the version recorded in the checkpoint config), py_vncorenlp (VnCoreNLP), seqeval and scikit-learn. `JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64` must be set for pyjnius.

Scripts we wrote (in `./scripts`, none of them part of the release):
1. `preprocess.py` writes `prepared/<task>/<split>.jsonl`.
   - **POS:** UD_Vietnamese-VTB (GitHub HEAD: train 1400 / dev 1123 / test 800; UPOS tags) and VnDT v1.1 gold-POS (8977 / 200 / 1020).
   - **NER:** PhoNER_COVID19 word-level (5027 / 2000 / 3000) and VietMed-NER (HF `leduckhai/VietMed-NER`, syllable-level, 4616 / 1154 / 3497).
   - **Sentence classification:** UIT-VSFC sentiment and topic (the Google Drive files referenced by the HF loader; 11426 / 1583 / 3166) and UIT-ViCTSD constructiveness and toxicity (HF `tarudesu/ViCTSD`; 7000 / 2000 / 1000).
   - **Where BMES tags come from:**
     - Already-segmented corpora (UD_VTB, VnDT, PhoNER-word) use their gold segmentation, following the paper's statement that "datasets that are already segmented require no preprocessing".
     - VietMed is segmented with VnCoreNLP.
     - Sentence-classification text goes through the released `MorphemeAwareTokenizer` exactly as in the README (truncation at 256).
2. `finetune.py` does stage-2 fine-tuning.
   - **Model setup:** released `MorphemeAwareRobertaModel.from_pretrained("ducanhdinh/HuTieuBert", target_heads={1: all, 2: all}, alpha=0.5, beta=-0.3, gamma=0, delta=0)`.
     - POS/NER head: dropout + linear on the first subword of each labelled unit.
     - Sentence tasks: the released `MorphemeAwareRobertaForSequenceClassification`, with `.roberta` replaced as in the README.
   - **Training:** AdamW, lr 2e-5, batch 32, linear schedule with 10% warmup, weight decay 0.01, grad-clip 1.0, bf16 autocast, max 256 subwords.
     - POS/NER: 30 epochs with early stopping (patience 5) on dev accuracy / F1.
     - Sentence tasks: 5 epochs, keeping the best dev macro-F1 epoch.
     - 5 seeds (0–4), each with its own shuffling of the training data.
   - **Metrics:**
     - POS: word-level accuracy.
     - NER: seqeval entity-level micro-F1 (VietMed scored at syllable level).
     - Sentence tasks: accuracy, macro-F1 and weighted-F1. The paper's Table 1 says "F1"; macro-F1 is the variant that lands close to the paper's numbers, so we compare on macro-F1.
   - **Speed fix:** the released `create_bias_matrix` is an O(L³) Python loop. At runtime our script replaces it with a vectorised function, and asserts on random inputs that both give identical matrices.
   - **Variants run:**
     - `l12` (main), `l56`, `l910`.
     - `w_bias` (the released `block_bmes_emb=True` with bias on layers 1–2).
     - `w_bmes` (no target heads).
     - `none` (both components off; extra, not in the paper).
     - PhoBERT-base (`vinai/phobert-base`, input words joined with "_", same head and hyperparameters) as a sanity baseline.
3. `aggregate.py` writes `summary.json` (mean ± sample std over the 5 seeds). `make_status.py` builds the comparison table.

Commands: `scripts/run_all.sh` (160 runs: 8 tasks × {HuTieuBERT l12, PhoBERT} × 5 seeds, then 4 POS/NER tasks × 4 ablations × 5 seeds) and `scripts/run_2.sh` (40 runs of the `none` variant). Each run looks like `env/bin/python scripts/finetune.py --task vndt --seed 0 --model hutieu --variant l12 --out results`. Per-run JSON files (with full dev history) are in `results/`, logs in `logs/`. A quick learning-rate check on UD_VTB dev (2e-5 / 5e-5 / 1e-4, in `results_tune/`) changed HuTieuBERT test accuracy by only about ±0.2, so a single learning rate was used for every model.

### Settings that differ from the paper or are unknown
- **Stage-1 MLM was not re-run.** We used the released HF checkpoint and assumed it is the stage-1 output.
- **Stage-2 hyperparameters were chosen by us,** because neither paper nor code gives them.
- **UD_VTB:** we used the current GitHub version with UPOS tags. The paper doesn't say which version or tag set (UPOS vs XPOS).
- **VLSP_13 and VLSP_16 were not run.** Both are licence-gated VLSP data. The only HF mirror of VLSP 2016 holds just the training set, re-split 80/20, with no official test set.
- **Table 3 (Chinese) was not run:** no code, and the THUCTC MLM stage is not released.
- **Baselines:** XLM-R and mBERT were not run (no configs). PhoBERT was run only as a sanity check through our pipeline.

### Reading the results
- **Main claim (Table 1, "consistently outperforms strong baselines, with the largest gains on syntactic tasks"): not reproduced.** In our pipeline PhoBERT-base scores ≥ HuTieuBERT on all 8 tasks.
  - The paper's PhoBERT numbers look under-tuned compared with ours and with the literature. For example, PhoNER PhoBERT is 83.83 in the paper versus 94.81 for us; the original PhoNER paper reports about 94.2. Hence the flag BASELINE_STRONGER_THAN_REPORTED.
  - The paper's HuTieuBERT POS numbers (UD_VTB 95.67, VnDT 98.73) are 2.8–4.0 points above anything we obtain with any configuration.
- **Stage-1 checkpoint vs the structural components:** inside the released checkpoint, the structural components do help a little relative to switching them off (`none` → `l12`: +0.1 to +1.2 points). Most of that comes from BMES fusion: w_bias, which has no fusion, is consistently below l12 on all 4 POS/NER datasets, which agrees with the paper's Table 2. The attention bias adds almost nothing once fusion is on (w_bmes ≈ l12), and the injection layer (1-2 / 5-6 / 9-10) makes no consistent difference. Both of those contradict the paper's ranking.
- **Overall:** because the central improvement claim does not hold and the syntactic numbers do not match, the overall result_match is NO_MATCH.

## Discrepancies
1. **code_vs_paper, major** — `model/bias_utils.py:create_bias_matrix`.
   - Eq. 5 gives β to every cross-compound pair (single-syllable words included) and α+δ on the diagonal.
   - The code gives γ (=0) to any pair that involves an `S` token: single-syllable words, special tokens and padding. It gives only δ (=0) on the diagonal.
   - With the paper's settings, the cross-word penalty β therefore applies only between two multi-syllable words. We kept the released behaviour.
2. **code_vs_paper, minor** — the model classes default to α=0.1, β=−0.05, while the paper uses 0.5 / −0.3. The README example passes 0.5 / −0.3, and so did we.
3. **code_vs_paper, minor** — the README results table does not match the paper's Table 1 for many baseline numbers:
   - PhoBERT PhoNER: 0.8779 (README) vs 0.8383 (paper).
   - XLM-R UD_VTB: 0.7480 vs 0.9189.
   - XLM-R PhoNER: 0.8317 vs 0.6975.
   - mBERT UD_VTB: 0.8010 vs 0.9049.
   - Several standard deviations also differ.
   - The README labels the semantic tasks "Acc.", while the paper's Table 1 says "F1".
4. **paper_internal** — HuTieuBERT VnDT is 0.9873 in Tables 1 and 2, but the Sec. 4.4 text gives 98.75% (and +4.10 pp over PhoBERT, which is 98.75 − 94.65).
