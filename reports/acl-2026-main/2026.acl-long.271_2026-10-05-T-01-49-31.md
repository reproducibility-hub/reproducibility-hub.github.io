## Why as-released differs (bug)
`Trainer.eval`/`predict` thresholds the full padded batch grid (`max_len × max_len`) and hands it to `utils.decode` without masking. Padded cells are excluded from the loss (`grid_mask2d`), and `GridRefiner` multiplies their features by zero, so their logits are exactly `classifier.bias`.

If any event-type bias ends up > 0, every padded diagonal cell `(i,i)` decodes as a one-token trigger at an offset beyond the document. Whether that happens depends on the seed: here it was seeds 42 and 52. The released checkpoint and seed 62 have all-negative biases.

The result is trigger precision of 0.06–0.19 on dev and test (diagnosed with `diag.py`: 8393 predicted triggers vs 2445 gold, with out-of-range offsets). The bug also corrupts dev-based checkpoint selection, since it uses TC.

Fix: one line, `pred = pred & grid_mask2d.bool().unsqueeze(-1)`. Training is deterministic (dev AC curves are identical with and without the fix), so the fix changes only trigger decoding and model selection.

## Codebase completeness: MAJOR_FIXES
Changes to the released code (uncommitted, see `git diff` in `./codebase`):
1. `config/scievents.json`: added `"ontology"` and `"seed": 52`. `config.py` requires both keys and crashes with `KeyError: 'ontology'` otherwise. This is a config-value change.

## Discrepancies
- **code_vs_paper (major, affects results):** decoding includes padded grid cells. The paper's inference (Eq. 6, Alg. 1) works on the document's own l×l grid.
- **code_vs_paper (minor):** the paper's CLN (Eq. 1) uses MLP_γ/MLP_β, but the code uses single bias-free linear layers.
- **code_vs_paper (minor):** the released config lacks keys the code requires, and the paper doesn't give its run seeds.
- **paper_internal:** Table 4 Sub-event AC for EXCEEDS (48.32) differs from Table 3 EC (48.25). With the released evaluator these two quantities came out identical for every run I scored, and several other paper rows do coincide exactly (OneIE, EEQA, DEEIA, both ablations).
- **paper_internal:** the text says removing the grid refiner gives "consistent degradation across metrics", but in Table 3 TI is higher without it (75.36 vs 75.29).
