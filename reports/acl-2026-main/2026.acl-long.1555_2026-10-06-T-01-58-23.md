### Settings that differ from the paper, or that the paper does not specify
* **Models:** aya-101 (`CohereLabs/aya-101`, bf16, HF transformers), bloomz-7b1-mt, falcon-7b-instruct, gemma-2b-it and Llama-3.1-8B-Instruct (bf16, vLLM). aya-23-8b was not run (licence gate).
* **Prompts:** the per-model prompts of Appendix F, transcribed verbatim (`scripts/prompts.py`). For TCLM model→X, the paper's prompt 2 literally reads "Target Language: {partial}". We substituted the language name.
* **Chat template** (not specified in the paper): applied for WT and BOW MT on every model whose tokenizer ships one (gemma, Llama, falcon). Not applied for bloomz or aya-101. TCLM is scored on the raw prompt text.
* **Decoding** (not specified beyond "deterministic"): greedy decoding.
  * WT: max 24 new tokens; the prediction is the first non-empty output line.
  * BOW MT: max 256 new tokens; the prediction is the full output.
* **TCLM probability:** P(word | prompt + partial translation) = product of the probabilities of the word's tokens, where the word is preceded by a space when the partial translation is non-empty. For aya-101, the partial translation is fed to the decoder (Appendix F.3).
* **Data sampling:** the released `lite` feeders. For TCLM this is 300 random (sentence, word-index) items over all 1012 devtest sentences, and for BOW MT 300 random sentences. The paper (App. H) says "the first 300 sentences". For WT it is 300 random lexicon entries, as in the paper.
* **Language sets:**
  * WT: all 2752 lexicon pairs per direction (paper: 2746).
  * TCLM / BOW MT: 203 FLORES-200 languages. Languages without a lexicon (9–10 X→model pairs) cannot be scored and are excluded. Two more (hrv_Latn, ilo_Latn) are excluded from BOW MT X→model because U+3000 characters in FLORES-200 break the evaluator's fast_align token indexing.
  * Applying the paper's "≥100 words per language" filter changes no mean by more than 0.4 (`summary_minwords100.json`).
* **Tolerance:** the "±" in Table 15 is the spread across languages, not an uncertainty on the mean, so we did not use it as a tolerance. We used the 1-point / 5% rule.

### Where the numbers deviate
* **TCLM** comes out 2–8 points higher than reported for every model, in both directions; rankings are unchanged. The paper itself notes TCLM is "brittle to punctuation and spacing" (Table 11). The exact prompt whitespace, BOS/chat formatting and word-tokenisation boundary are unreported.
* **WT X→model:**
  * gemma-2b-it: ours 9.3 vs 4.1 reported.
  * bloomz-7b1-mt: ours 4.8 vs 9.0 reported.
  * Most of gemma's "correct" answers come from the lenient substring/synonym heuristics applied to its verbose chat answers. Only 0.4% of predictions are exact matches.
  * A sensitivity run without the chat template (`results_nochat/`) gives gemma 6.7 / 1.7, against the paper's 4.1 / 1.5.
  * bloomz often emits an empty string (immediate EOS), which lowers its WT score and nearly zeroes BOW MT, consistent with the paper's 1.1 / 3.7.
  * These depend on unreported inference details (chat template, max tokens, parsing).
* **BOW MT model→X:** gemma 12.8 vs 17.5 and Llama 32.2 vs 26.4. Our predictions keep the full model output.

The release (`github.com/ec5ug/chikhapo`) contains the `chikhapo` pip package: data loaders, task feeders producing lite data and default prompts, the scoring heuristics/evaluators, a result analyzer and a Glottolog reader. Lexicons are on the HF Hub. The paper says "We release our dataset, code for our experiments", but there is **no code that runs any model**. Missing pieces:
* per-model prompt selection (Appendix F);
* chat formatting, decoding settings and output parsing;
* TCLM probability extraction, including aya-101's decoder-side prefix;
* the loop over languages, and the script that produces Table 15 / the figures.

We wrote all of this ourselves (list below). No file in `./codebase` was modified (`git status` is clean). Every fix lives in our wrapper scripts.

Changes and workarounds, all outside `./codebase`:
1. `scripts/common.py`: patches `chikhapo.Loader` to read the same Hub data from local snapshots. Without it, the loader calls `get_dataset_config_names` and `load_dataset` per language: about 11k Hub calls, which hit rate limits. It also points the FLORES loader at FLORES-200, and turns the import-time `huggingface_hub.login()` (which rewrites `$HOME` token files) into a no-op.
2. `scripts/evaluate.py`: resets `Evaluator.word_scores` before each file. **This bug fix changes results.** As released, `clear_intermediary_data()` leaves `word_scores` intact, so each language's score in `ResultAnalyzer` is averaged over the words of every language scored before it. Examples: gemma BOW model→X is 5.9 as released vs 12.8 fixed, and aya-101 BOW model→X is 25.6 vs 33.9. Per-language std collapses to about 2.
3. `scripts/eval_as_released.py`: runs the unmodified `ResultAnalyzer`.
   * For WT it raises `There is a language field that is an invalid ISO code` (`sap_eng`, `eng_leg`, from the released lexicon) even with the pinned pycountry 24.6.1. The as-released pipeline therefore cannot produce the WT table.
   * It also keys results by 3-letter ISO, so FLORES script variants (e.g. ace_Arab / ace_Latn) overwrite each other: 195 instead of 203 languages.
4. `scripts/run_model.py`, `scripts/prompts.py`, `scripts/build_tasks.py`, `scripts/summarize.py`, `scripts/secondary.py`, `scripts/breakdown.py`, `scripts/run_all.sh`, `scripts/run_as_released.sh`: the missing experiment pipeline (inference, prompts, aggregation, figures).
5. Environment workarounds:
   * pinned pycountry 24.6.1. Newer versions rename or remove some languages, which changes prompt language names. Languages run with the newer names were re-run.
   * `VLLM_USE_FLASHINFER_SAMPLER=0` (no nvcc for the FlashInfer JIT);
   * the `TRITON_ATTN` attention backend for BLOOM (ALiBi crashes vLLM's default FA2 path);
   * `HOME` pointed into the attempt directory for scoring, because the evaluator clones and builds fast_align (and NLTK fetches WordNet) under `~`. fast_align was pre-built once, since parallel workers race on the git clone.
6. Bug not exercised (WTWC blocked): `WordTranslationWithContextFeeder.get_prompts_for_lang_pair` passes `xxx_Latn` to `convert_iso_to_name`, so the language name in prompts is empty.

## Discrepancies
**code_vs_paper**
1. **(major)** WTWC model→X: the paper uses English monolingual sentences (Sec. 3.2; Table 1 example). The feeder instead loads the target-language GLOTLID corpus and matches English lexicon headwords inside X-language text. Affects results (not run).
2. **(major)** `ResultAnalyzer` / `Evaluator`: `word_scores` is never reset between languages, so language scores are contaminated by earlier languages (see above). Affects results.
3. **(major)** WTWC prompts: the language name is empty because `convert_iso_to_name` is called on `iso_Script`. Affects results (not run).
4. **(minor)** The package ships one default prompt per task, whereas the paper uses per-model prompts (App. F). The package's TCLM default also differs in punctuation from the paper's prompt. Affects results if the defaults are used. We used the App. F prompts.
5. **(minor)** Lite sampling for TCLM/BOW MT: the paper uses the first 300 sentences (App. H); the code uses a random sample of 300 (sentence, position) items or 300 sentences. Affects which items are scored.
6. **(minor)** Language filtering: the paper discards languages with fewer than 100 lexicon entries and requires ≥100 words per language score; the code has no filter. The released lexicons have 2752 pairs per direction vs 2746 in the paper. Negligible effect (≤0.4).
7. **(minor)** `ResultAnalyzer` aborts on ISO codes missing from pycountry and collapses script variants. Prevents the WT aggregation from running as released.

**paper_internal:** none found. Sec. 5's "30% of the data" for TCLM/BOW is consistent with App. H's 300/1012 sentences. Table 15 and Figure 2 agree. Figure 5 is for aya-23-8b only (stated in the figure).
