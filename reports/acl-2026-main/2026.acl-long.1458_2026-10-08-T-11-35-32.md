## What the paper claims (main experiment = Table 1)
SAFO (LoRA fine-tuning with an EMA-smoothed softmax group-reweighting Adversary + Nash-inspired λ Regulator) vs ERM, KL, CVaR DRO, Group DRO on CGSS/ESS/GSS with Llama-3.1-8B-Instruct and Qwen2.5-7B-Instruct, 3 seeds. Claims: SAFO matches/surpasses ERM accuracy, reduces Wasserstein by 2.9–16.4%, CV by 6.9–17.3%, Gini by 7.9–16.0%, improves worst-group by 1.6–8.2%, best Nash welfare, lowest seed variance. Figure 2: full SAFO best on all six metrics vs w/o DRO / w/o EMA / w/o Nash.

## What the release contains
- `LLaMA-Factory/` fork. SAFO and all baselines are in `src/llamafactory/train/sft/trainer.py::compute_loss`, selected via env `LOSS_MODE` (`erm`, `ufao`=SAFO, `group_dro`, `cvar_dro`, `kl`, `ablation_no_{dro,ema,nash}`). `group_label` is passed through by the data pipeline.
- Training scripts `examples/train_lora/{gss,cgss,ess}.sh` and an inference script `run.sh`, which calls `scripts/vllm_infer.py`.
- Evaluation scripts `other/generates/{analysis,small,result}.py` plus the authors' xlsx outputs.
- **Released prediction files** `other/generates/{gss,cgss}_{llama8b,qwen7b}_{erm,ufao}_seed{42,123,2025}.jsonl`. These hold full test prompts, labels and predictions for GSS (4,506) and CGSS (5,762).
- **Data:** `data/{gss,cgss,ess}/*_{train,test}.json` contain **one row each**. The README says "Due to licensing restrictions, we provide sample data and processing scripts instead of the full datasets". The `scripts/process_data.py` it mentions is **not in the repo**.

## What I did
### 1. Evaluate the authors' released predictions (no training)
`scripts/eval_preds.py` imports the authors' metric functions from `other/generates/small.py`. It rebuilds each sample's `group_label` from the `your <attr>: <value>` lines of the prompt, because the released test json has only one row.

My numbers reproduce the authors' own `evaluation_results_with_stability.xlsx` exactly (e.g. GSS-Qwen ERM CV 0.0619±0.0090). So the group reconstruction is identical to theirs.

### 2. Rebuild the GSS training set from public raw data
The rebuild is high-fidelity, but it is still a rebuild.
- **Raw source:** GSS 1972–2024 cumulative Stata file (R3a, gss.norc.org, public), year 2024 (3,309 respondents).
- **Questions and processing:** the 11 questions, option strings and label rules were reverse-engineered by matching the released test prompts back to raw records. Details are under "Data-processing findings" below.
- **Sample counts:** the rules give 22,466 samples (paper: 17,963 + 4,506 = 22,469) and exactly 401 missing-age samples (paper: 355 + 46).
- **Train split:** train = all rebuilt samples minus the released test samples (multiset match on demographics + question + answer; 17 of 4,506 test items unmatched). This gives **17,977 train samples (paper 17,963)**. Train demographic counts match Table 3 almost exactly (age 18–24: 1,187 vs 1,187; female 9,776 vs 9,774; income "refused" 407 vs 407; under $1,000: 368 vs 368).
- **Test set:** the released GSS test set, **verbatim** (taken from the released prediction files).
- **Region:** the current public 2024 release only has 4 census regions. The prompts use 9 census divisions.
  - I recovered the division for 2,565 of 3,309 respondents. Sources: the authors' own AlignSurvey GSS file (`github.com/PiLab-ZJU/AlignSurvey`, whose `respondent_id` is the GSS id) and unique matches against the released test prompts. The two sources had 0 conflicts.
  - The remaining 543 respondents got a division imputed within their known region.
  - Resulting train region counts differ from Table 3 by up to ~10% for some divisions (e.g. West South Central 2,092 vs 1,907).
- Option order inside each prompt is randomly shuffled (seed 0), as in the authors' data, but the specific permutations differ.
- CGSS (cnsda.ruc.edu.cn application) and ESS (account login) raw data are registration-gated, so they were not rebuilt.

### 3. Re-train with the released code, unmodified
`scripts/run_one.sh` replicates the commands in `examples/train_lora/*.sh` and `run.sh`:

```
LOSS_MODE=<mode> LOSS_PROBE_DATASET=<run> python -m llamafactory.cli train --model_name_or_path {meta-llama/Llama-3.1-8B-Instruct|Qwen/Qwen2.5-7B-Instruct} \
  --stage sft --do_train --finetuning_type lora --lora_rank 8 --lora_target all --dataset gss_train --dataset_dir data_rebuilt \
  --template {llama3|qwen} --cutoff_len 2048 --per_device_train_batch_size 64 --gradient_accumulation_steps 1 --learning_rate 1e-5 \
  --num_train_epochs 1.5 --lr_scheduler_type cosine --warmup_ratio 0.1 --bf16 --seed {42,123,2025}
python scripts/vllm_infer.py --model_name_or_path ... --adapter_name_or_path <run> --dataset gss_test --dataset_dir data_rebuilt --template ...
```

- Settings: 1 × H200, 422 steps, about 16 min per run including inference.
- Runs: 39 in total. That is 2 backbones × {ERM, SAFO, Group DRO, CVaR DRO, KL} × 3 seeds, plus Llama × {w/o DRO, w/o EMA, w/o Nash} × 3 seeds. None failed.
- Seeds 42/123/2025 follow the released file names (`run.sh` lists 2026).
- Epochs follow the paper: 1.5 (scripts use 1 or 2). All other hyperparameters are the code defaults, which equal paper Table 6.
- Decoding uses the release's `vllm_infer.py` defaults, i.e. sampling with temperature 0.95 and top_p 0.7. A greedy re-decode of all 39 adapters was added as a robustness check (section 4c).
- Metrics are computed with the authors' `small.py` definitions (per-attribute group weighted-F1, averaged over attributes). Variants following the paper's Appendix E text (group accuracy, worst-group = global min) are in `results/rerun_sampled_eval.txt`.

## Data-processing findings (GSS)
Inferred from the released test labels, since the processing code is not released.
- **Unasked questions get the middle option as label.** For parsol, kidssol and goodlife, respondents who were never asked the question (GSS `.i` = inapplicable, about 35–40% of respondents) are labelled with the middle option ("About the same" / "Neither agree nor disagree"). kidssol's "no children" answer is also mapped to "About the same". This affects roughly 140–160 of about 600 test items per question.
- **fair uses a label that isn't an option.** Labels come from the web-volunteered variant `fairv`, so "depends (phone mode only: volunteered)" is a target label but is never shown as an option.
- **finrela and getahead labels don't match the option strings.** finrela labels have no letter and are capitalized ("Average"). getahead labels read "hard work most important" while the option says "hard work most".
- **Test split is sample-level, not respondent-level.** 1,675 test profiles have about 2.7 questions each, so the same respondent appears in both train and test.

## Why it is not reproduced
1. **Missing data (release problem).** No training data is released for any dataset, and the processing script is missing. GSS could be rebuilt from public data with high fidelity; CGSS and ESS are gated behind registration. The current GSS release also lacks the 9-division region, which I had to recover or impute.
2. **On the rebuilt GSS, the claimed effect disappears.** The baselines run through the same pipeline reproduce Table 1, so the setup is sound. SAFO still does not reduce disparity relative to ERM, and is slightly worse on worst-group and Nash. The authors' own released GSS prediction files show the same reversal.
3. **Not run:** CGSS/ESS training (data gated), ESS evaluation (no released predictions), Mistral / FairDRO / ROAD (Appendix I; code not in release), Figure 3/5 sensitivity and scaling sweeps.
