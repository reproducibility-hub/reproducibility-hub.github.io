### Interpretation
- **Exact or near-exact reproduction** (within 0.25 points on every number, all 4 datasets): gte-modernbert-base, stella_en_400m_v5, Dragon-ChatQA. bge-large-en-v1.5 also reproduces: MTR plus Table 5 via the infinity backend, ChatRAG via the `_st` backend.
- **Dragon-DocChat**: the paper's numbers reproduce only with mean-pooled queries (infinity, as `query_embedding.sh` lists it). The README explicitly warns this configuration seriously degrades Dragon models. Used correctly (CLS pooling), DocChat reaches MTR R@5 50.78 (paper 31.50), i.e. the paper under-reports this baseline.
- **gte-Qwen2-7B-instruct**: the released pipeline gives much higher numbers than the paper:
  - MTR R@5/R@20 75.69/85.78 vs 39.75/53.23
  - QReCC R@5 92.37 vs 59.78
  - R@1000 97.06 vs 82.2
  
  Only Doc2Dial (Table 11 MRR/NDCG) agrees. A probe with the alternative (`_st`) document backend gives the same QReCC result (92.16), so the backend choice doesn't explain the gap. I found no configuration in the release that reproduces the paper's Qwen numbers.
- **Effect on the claims**:
  - "MTR-Bench is much harder than prior benchmarks" still holds for 5 of 6 retrievers; for gte-Qwen2-7B the prior-vs-MTR R@20 gap shrinks to about 10 points.
  - The Section 7.4 claims (best model reaches only 82.2% at R@1000; even the best retriever misses ~34% at top-100) and the ranking of retrievers on MTR (gte-modernbert best) **do not hold** in our runs (gte-Qwen2: 97.1% at R@1000, misses 7.8% at top-100).
  - The aggregate gap statistic is 39.99 points on the 3 prior datasets we ran, vs 47.18 computed from the paper's own Table 3 on the same 3 datasets (43.54 in the paper with TopiOCQA included).
  
  Hence MIXED.

## Discrepancies
- **code_vs_paper** / major, *eval/query_embedding.sh (infinity backend) for Dragon-DocChat queries vs Table 3/11 'Dragon-DocChat'*. Paper: Dragon-DocChat is evaluated as an off-the-shelf SOTA conversational dense retriever (MTR R@5/R@20 31.50/40.98). Code/other: query_embedding.sh embeds DocChat queries with infinity, which mean-pools; the README says mean pooling 'harms dragon+ like model huge'. The paper's numbers come out only with that configuration (ours 31.66/41.01). With CLS pooling (the model's correct usage, via the released _st scripts) MTR R@5/R@20 = 50.78/59.01, so DocChat beats ChatQA and roughly ties gte-modernbert. Affects results: True.
- **code_vs_paper** / minor, *eval/document_embedding*.py vs eval/query_embedding*.py backends; Table 3/11/5 bge-large-en-v1.5*. Paper: single set of bge-large-en-v1.5 results. Code/other: bge's MTR numbers (Table 3/5/11) match the infinity backend (normalized, text-only docs); its ChatRAG numbers match the _st backend (CLS, unnormalized, fp32). With _st, MTR is 26.57/31.76; with infinity, ChatRAG is higher (QReCC R@5 83.74, Doc2Dial 71.74). The paper doesn't say which backend was used. Affects results: True.
- **code_vs_paper** / minor, *eval/query_embedding*.py formate_mtr + tokenizer truncation (Sec 6.3)*. Paper: the input is the serialized conversation history prepended to the current query. Code/other: the full history is serialized and then right-truncated to the model max length (512 tokens for bge/Dragon), so for 27.2% of MTR-Bench turns (bge tokenizer) the current query is cut off.
