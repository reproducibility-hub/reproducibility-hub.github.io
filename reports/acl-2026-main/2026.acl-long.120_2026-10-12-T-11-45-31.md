# Reproduction report: 2026.acl-long.120: *Breaking the Generator Barrier: Disentangled Representation for Generalizable AI-Text Detection* (DRGD)

## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match, after fixes: TREND_MATCH.** For "Ours" in Table 2, 9 of the 14 main numbers (7 held-out categories × Acc/F1) are within tolerance. The other 5 are all *higher* than the paper reports: LLaMA and OPT Acc/F1 are +5–7 points, and FLAN-T5 F1 is +7.6. The paper's numbers for its own method are therefore met or exceeded on all 7 held-out categories. Claims that it beats the baselines can't be checked, because no baseline code is released.
- **Result match as released: DOES_NOT_RUN.** The released `train.py` crashes on the first optimisation step. Also, no data or data paths are shipped, and the main script is a hard-coded 3-generator demo that raises a `KeyError`.
- **Coverage: FULL.** All 7 leave-one-category-out settings of Table 2 were run at the paper's scale: 5 epochs, batch 16, lr 2e-5, the full rebuilt train/test sets, and seed 0. Seed 1 was also run for 4 categories.
- **Codebase completeness: MISSING_SCRIPTS.** The method is implemented, but the data construction and the leave-one-generator-out pipeline are missing and had to be written. The code also had crash and logic bugs; see below.
- **Important caveat:** following the code, the reported numbers are the **best test-set accuracy over evaluations during training** (test-set checkpoint selection). Training is very unstable. The *final* checkpoint is often much worse (GLM 50.0, BigScience 50.9, FLAN-T5 53.1), i.e. the model often collapses to predicting one class. Without test-set selection, the paper's numbers would mostly not be reached.

## What was done
1. Read the paper. The main claim is Table 2: cross-generator generalization on a 7-category / 20-LLM MAGE subset under leave-one-generator-category-out (train on 6 categories, test on the held-out one), reporting Acc/F1.
2. Cloned https://github.com/PuXiao06/DRGD (commit 8ccf2f6) into `./codebase`. It contains `train.py`, `test.py`, `module/{model,IB,data}.py`, `tools/eval.py` and one unrelated sample jsonl. There is no `environment.yml`, no data and no data-preparation script.
3. Environment: `conda create -p ./env python=3.10`, then `pip install torch==2.4.1 transformers==4.44.2 scikit-learn scipy pandas tqdm "numpy<2"`. BERT: `bert-base-uncased`. The code points to `./bert-base-english`, which is not shipped and is not a public model id.
4. Data: downloaded the public MAGE (`yaful/MAGE`: train/valid/test.csv). `scripts/build_mage_subset.py` rebuilds the Table 1 subset following App. A.1:
   - Pool all MAGE splits.
   - Drop T0-3B/11B and OPT-125M/350M/1.3B/13B/30B.
   - Single-model categories (GLM-130B, Bloom-7B) are taken whole.
   - Multi-model categories get per-model, domain-stratified random sampling to the Table 1 totals: FLAN-T5 5×1800, GPT 3×4600, LLaMA 4×2250, OPT {2.7B, 6.7B, IML-30B, IML-Max-1.3B} 4×2250, EleutherAI 2×4500.
   - Each category gets an equal number of human texts, matched per domain and disjoint across categories (seed 0).
   - Resulting AI/Human counts: FLAN-T5 9000, GPT 13800, LLaMA 9000, OPT 9000, GLM 9182 (paper: 9100), BigScience 8818 (paper: 8900; MAGE only has 8818), EleutherAI 9000.
5. Training/eval command, one per held-out category in {flant5, gpt, llama, opt, glm130b, bigscience, eleutherai}:
   ```
   source scripts/env.sh   # BERT_PATH, DRGD_DATA_DIR, DRGD_CACHE_DIR, TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1
   cd codebase && python train.py --heldout <cat> --epochs 5 --eval_every 1000 [--seed 1] [--released_eval_mode]
   ```
   Hyperparameters are the code defaults and match the paper (§4.1): AdamW (transformers), lr 2e-5, batch 16, K=5 latent samples, head dropout 0.5, effective β = 0.5×1e-5 = 5e-6, 5 epochs (code default; the paper gives no epoch count), max length 512.
   The held-out set is evaluated every 1000 steps and at the end of each epoch. As in the code, the best test accuracy (and its F1) is reported. The released code evaluates every 10 steps, which is impractical (≈3,700 full test-set passes per run). Our checkpoint selection is therefore coarser, which is if anything conservative.
   F1 is `sklearn.f1_score` with the default `pos_label=1`, which in this code is the **human** class. This is the code's metric; the paper doesn't define it. AI-class and macro F1 are also logged.
6. Ran the 7 main runs (seed 0), plus seed-1 runs for FLAN-T5/GPT/LLaMA/OPT, plus two "released-behaviour" runs (see below). Logs are in `logs/run_*.log`; the summary is in `logs/summary.json`.

## Codebase completeness: MISSING_SCRIPTS
Changes to the released code. These are left uncommitted in `./codebase`; the full diff is in `logs/codebase.diff`.
- `module/model.py`: `from IB import IB_Module` → `from module.IB import IB_Module` (ImportError when run from the repo root).

- `module/data.py::build_all_caches`: data paths were `'-'` placeholders and the tokenizer path was `./bert-base-english`. These are now taken from env vars (`DRGD_DATA_DIR`, `BERT_PATH`, `DRGD_CACHE_DIR`), using the 7 category files, and `BertTokenizerFast` is used (same tokens).

  - **Crash fix.** The code ran `loss.backward(retain_graph=True)`, then `optimizer.step()`, then `pure_loss.backward()`, which raises "modified by an inplace operation" (verified with the unmodified code, `scripts/check_asreleased_step.py`). Stage-II gradients for the shared bottleneck parameters (`optimizer_share`) are now computed with `torch.autograd.grad` before the stage-I step and applied with `optimizer_share`.
  - The `__main__` is replaced by a `--heldout` leave-one-category-out driver, with generator ids 0..5 for the 6-way generator head. It also adds `--seed`, `--eval_every` and `--released_eval_mode`.
  - The evaluation interval is configurable; the code reports best-so-far acc together with its F1.
- `tools/eval.py`: returns `(acc, f1)` instead of `acc`, logs AI/macro F1, and restores the model's previous train/eval mode. The released version left the model in eval mode, which silently disabled IB sampling and the perturbation losses during training.
- `test.py`: not used. It hard-codes `/home/czp/...` checkpoints and a 'grover' cache, and `train.py` never saves checkpoints.
- README: references a missing `environment.yml`, and claims BERT is randomly initialised (the code and paper use pre-trained BERT).
- Scripts I wrote: `scripts/build_mage_subset.py` (data), `scripts/queue.sh` (runner), `scripts/summarize.py` and `scripts/write_status.py` (log parsing), `scripts/check_asreleased_step.py` (crash check).

## Discrepancies
**Code vs paper, major (all affect results):**
1. **Model selection.** The code evaluates on the held-out *test* set every 10 steps and reports the maximum. The paper describes no model selection. Final-checkpoint results are much lower.
2. **Train/eval mode.** `evaluate()` leaves the model in eval mode for the rest of each epoch. This disables K-sample IB training, dropout and the cross-view perturbation losses that the paper describes (Eq. 2, 6).
3. **Generator labels.** They are misaligned because each name is appended twice in `process_jsonl_file`.
4. **Cross-view regularisation differs from Eq. 5–6.**
   - The code uses fixed AdaIN strengths (0.15 on a random 30% of samples; 0.4 for AI-sample generator features) instead of γ~U(0.5,1).
   - The augmented AI samples are all AI×batch pairs with N(0,0.1) noise and strength 0.5.
   - There is an extra human-perturbation loss (weight 0.8) that is not in the paper.

**Code vs paper, minor:**
5. The prior is initialised with `randn` / `softplus(randn)`, not N(0, I).
6. Stage-II loss: class-weighted CE [1.0, 0.7], GRL λ=0.5, GRL cross terms only on AI samples, KL terms included, plus an extra Linear(32,32) before the heads.
7. The README says BERT is randomly initialised; the paper and code use pre-trained BERT. This does not affect results.

**Paper internal:**
8. The Table 2 caption and §4.2.1 claim consistent gains over all methods on all held-out generators. In Table 2's own F1 column, Ours is below Fast-DetectGPT, MCP and PECOLA on FLAN-T5, and below MCP on GPT.
9. Table 1 lists Bloom 8,900 and GLM 9,100 with "entire set retained", but public MAGE has 8,818 and 9,182.
