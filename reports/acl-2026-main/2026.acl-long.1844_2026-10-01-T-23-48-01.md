# Reproduction report — SIREN: "LLM Safety From Within: Detecting Harmful Content with Internal Representations" (ACL 2026, 2026.acl-long.1844)

## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after our fixes): MIXED** · **as released: MIXED** · **Coverage: SUBSET** · **Codebase completeness: MAJOR_FIXES**
- Code: https://github.com/CSSLab/SIREN (linked in the paper), cloned to `./codebase`.

**Summary.** We ran the released SIREN pipeline end-to-end for all four backbones in Table 1 (Qwen3-0.6B, Llama-3.2-1B,
Qwen3-4B, Llama-3.1-8B), using the released config and full data. Training is on all 7 datasets: 236,528 train+val
examples, matching Table 5 exactly.
- **Table 1, SIREN rows, as released:** the paper's numbers reproduce. Averages are 84.4 / 84.7 / 86.8 / 86.3 against the
  paper's 85.6 / 85.7 / 86.7 / 86.3. All 28 per-dataset numbers are within 5% relative (most within about 1 point).
- **Data-split bug.** The released code makes its data splits with an unseeded `train_test_split`. It also calls the
  split function separately for train, validation and test, and again at evaluation time. As a result, about 70% of the
  OpenAI-Moderation test prompts (234/336) are also in the training data, and 83% of the validation set overlaps train.
  - On the leaked prompts the models score about 99.8 F1. On held-out prompts they score about 67–82.
  - With a seeded, single, disjoint split (the paper says 80/20 with seed 42), SIREN's OpenAI-Moderation F1 drops from
    89–94 to **78–81**. The Table 1 averages drop by 0.9–2.1 points.
  - The "substantially outperforms guard models" claim then weakens on this benchmark. The margin over Qwen3Guard-0.6B
    falls from +15.4 to +2.4, and the margin over Qwen3Guard-4B from +12.9 to +0.5. SIREN on Llama-3.1-8B (80.9) now
    falls *below* the reported LlamaGuard3-8B (85.3).
  - SIREN still beats the paper's reported guard averages for every backbone. Leak-free averages are
    83.1 / 83.8 / 84.7 / 85.0, against guard averages of 81.7 / 70.7 / 83.4 / 77.0.
- **Table 3 (adaptive vs. uniform layer weighting):** not reproduced. Over 3 runs each, adaptive and uniform are equal
  within noise: 84.7 vs 84.6 on Qwen3-0.6B, 85.3 vs 85.1 on Llama-3.2-1B. The paper reports a +1.0–1.3 gain.
- **Parameter efficiency:** with the released config (η=0.9) the trained MLPs are much larger than reported. Qwen3-4B
  gets 69.5M parameters vs. 14.0M, i.e. about 58× fewer than the 4B guard rather than "250× fewer".
- **Guard baselines were not run.** The release has no code for them, Llama-Guard-3-1B is gated for our account, and the
  prompt/response formatting for each dataset is not specified. Claims of the form "SIREN beats guard X" are therefore
  `NOT_COMPARABLE`; we only quote the paper's guard numbers for context.

## What we ran
Environment: conda env at `./env` (python 3.11.13), with the exact pins from `codebase/environment.yaml` (torch 2.7.0,
transformers 4.53.3, datasets 4.0.0, optuna 4.6.0, scikit-learn 1.7.1). Hardware: 1× H200, 111 GB host RAM.

Pipeline (all scripts in `./scripts`, logs in `./logs`, outputs in `./results/<model>_<variant>/`):
1. `scripts/make_splits.py --mode released|fixed` builds the splits with the repo's `train/preprocess.py`.
   - `released` reproduces the released behaviour exactly: separate unseeded `preprocess_dataset` calls for
     train / validation / test (as in `extract_all_representations`) plus one more call for evaluation (as in
     `evaluate_general_siren.py`).
   - `fixed` makes one seeded call (seed=42) per dataset.
   - Both modes then combine and permute the data with `RandomState(42)`, as the released code does.
2. `scripts/extract.py --model M` extracts mean-pooled residual-stream representations for every layer and every
   unique text. It reuses the repo's model loader (`utils/model_hooks.Qwen3RepresentationExtractor`: bf16, max_length
   512, same text cleaning, decoder-layer output hook, mean over valid tokens).
   - Storage is a lossless bf16 disk memmap. The released code keeps a Python dict of float32 arrays per sample, which
     needs about 95 GB (Qwen3-4B) or 135 GB (Llama-3.1-8B) of host RAM, more than the 111 GB available.
   - Texts are batched sorted by length, and pooling is vectorized. We checked against the repo's `extract_batch`:
     max relative difference 0.8%, median 0.04% (bf16 noise from different padding/batching).
3. `scripts/run_siren.py --model M --splits ... --reps ...` runs the released `train_general_siren.main()` steps 2–3,
   followed by `evaluate_general_siren.py`.
   - It imports and calls the released functions: `train_probes` / `LinearProbe` (L1 probes,
     C ∈ {200, 500, 1000}), `get_layer_weights`, `select_salient_neurons` (η=0.9), and the Optuna TPE search
     (seed 42, 32 trials, 5-fold CV, same search space, `AdaptiveMLPClassifier`). Final training is 512 epochs on
     train+val; evaluation uses fp32 argmax and per-dataset macro-F1.
   - Only the data containers were swapped (see codebase notes).
   - Settings come from `run_general_siren.sh`: `C_VALUES="200 500 1000"`, `THRESHOLDS=0.9`, `N_TRIALS=32`,
     `N_FOLDS=5`, `REP_TYPES=residual_mean`.
4. Extra runs, all reusing the trained probes:
   - `--uniform`: Table 3 ablation with all layer weights = 1. Run 3× each for adaptive and uniform on Qwen3-0.6B and
     Llama-3.2-1B, because the MLP stage is unseeded.
   - `--thresholds 0.8`: Table 2 spot check.
5. `scripts/analyze_leak.py` breaks OpenAI-Moderation F1 down into test prompts seen in training vs. unseen.
6. `scripts/summarize.py` builds the tables below and `comparisons.json`.

Exact command for one model (as-released variant):
```
env/bin/python scripts/make_splits.py --mode released --out work/splits_released.pkl
env/bin/python scripts/extract.py --model qwen3-4b --splits work/splits_released.pkl work/splits_fixed.pkl --out_dir work/reps_qwen3-4b
env/bin/python scripts/run_siren.py --model qwen3-4b --splits work/splits_released.pkl --reps work/reps_qwen3-4b --out results/qwen3-4b_released
```

### Settings that differ from the paper / release
- **WildGuardMix** (`allenai/wildguardmix`) is gated for our HF account. We used public mirrors with the original columns
  and row counts: `ToxicityPrompts/wildguard-train` (86,759 rows) and `iagoalves/wildguardmix_eval` (1,725 rows;
  1,699 after the repo drops unlabeled rows). They are injected by patching `load_dataset` inside `make_splits.py`. Row
  order may differ from the original, which only matters for which items fall in val vs. train.
- **meta-llama/Llama-3.2-1B** is gated (403). We used `unsloth/Llama-3.2-1B`, a mirror with the same weights and
  config. Its tokenizer pads on the left by default, so we forced `padding_side="right"`, which is the default of the
  original Meta tokenizer and is what the released pooling code assumes.
- **Released config vs. paper.**
  - CV folds: the release uses 5, the paper's Table 6 says 3.
  - C grid: the release uses {200, 500, 1000}, the paper says {100, 200, 500, 1000}.
  - η is fixed at 0.9 in the release; the paper gives a range [0.6, 0.9] and does not state the per-backbone value.
  - We used the release's values.
- **Representation types:** the paper says residual-stream and FFN representations are considered. The released
  script uses only `residual_mean`, and we followed the script.
- **Single run per configuration** for Table 1; the MLP training is unseeded in the released code. Table 3 was repeated 3×.
- **The "as released" OpenAI-Moderation test split** is one random draw; every rerun of the released evaluation draws a
  new one. Over 20 re-draws, the F1 (mean ± std) is 92.4±0.9 / 93.1±1.2 / 93.3±1.0 / 94.2±1.2 for the four backbones.

## Codebase completeness: MAJOR_FIXES
The release contains the full method and the main train/eval scripts. However:
1. A data-splitting bug changes the reported numbers (OpenAIMod test leakage). We fixed it optionally: `preprocess_dataset(..., seed=None)`
   keeps the released behaviour, and `seed=42` plus a single call gives disjoint splits.
2. On a 111 GB host, the released in-memory representation store cannot run for Qwen3-4B or Llama-3.1-8B. We had to
   rewrite the extraction/storage loop and the CV/final-training data handling. The rewrite keeps the same logic and
   math, but is a substantial edit.

List of changes:
- `codebase/train/preprocess.py`: added an optional `seed` argument to `preprocess_dataset`, passed to every
  `train_test_split`. The default `None` keeps the released behaviour. This is the only edit inside `codebase/`.
- `scripts/make_splits.py` (new): builds released-style and fixed splits; patches `load_dataset` to use the WildGuardMix mirrors.
- `scripts/extract.py` (new): replaces `extract_all_representations` / `extract_representations` with
  memory-efficient storage (bf16 memmap, deduplicated texts, length-sorted batches, vectorized mean pooling, base model
  without the LM head, right padding forced).
- `scripts/run_siren.py` (new): driver that calls the released functions; monkey-patches `extract_layer_features` /
  `aggregate_features` to array versions that compute identical values; adds `--probes` (reuse probes) and `--uniform`.
  - Replaces `tgs.objective`/`train_model` fold copies with GPU index views of a single GPU-resident X. Same search
    space, KFold(42), epochs, patience, AMP; trial=None, as released. The released version copies about 37 GB per fold
    on the host for the 8B model.
  - Replaces `train_final_model(use_val=False)` with a GPU-resident version that has the same init, CPU `randperm`
    order and AMP ops. The released branch gathers each mini-batch on the CPU and ignores `use_gpu_data`.
- `scripts/analyze_leak.py`, `scripts/summarize.py`, `scripts/lane*.sh` (new): analysis and job queueing.
- Note: the first two runs (`qwen3-0.6b_released`, `llama3.2-1b_released`) used the released `tgs.objective` and
  `tgs.train_final_model` unchanged. All later runs used the GPU-resident equivalents described above, after the 8B
  model hit host-memory limits.
- Intermediate representation memmaps (about 116 GB in total) are kept in `work/reps_*`; they can be regenerated with
  `scripts/extract.py`.
