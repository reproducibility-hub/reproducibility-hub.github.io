## What the paper claims (main experiment)

PGB-CT (soft mask m∈[0,1]^N; loss 1/(1+ℓ) + λ1‖m‖1 + λ2 mᵀ(1−m) with linearly scheduled λ; Adam; truncation at τ=0.5) finds sparse sets of attention heads or MLP neurons that maximise a gender-bias / factual metric ℓ(D,m). It beats top-k and random, comes close to greedy, and is much faster (Table 1, Tables 4/5, Figs 3–5).

### Summary of the comparison
- **Table 1 (main result), GPT-2 family + Qwen3-1.7B:** all 48 PGB-CT cells are within 5% of the paper; most are within 2%. Run with the released code, the method reproduces the paper's numbers once λ is tuned.
- **Table 1, Llama-3.2-1B:** does not reproduce numerically. The Llama metric is very unstable from epoch to epoch (e.g. 0.16 → 0.45 → 1.0 between consecutive epochs).
  - WinoGender: we find a 25-head mask with ℓ=2.51, which beats every paper cell, including the paper's 40% value of 2.449.
  - WinoBias: our best is 0.32/0.46/0.56/0.65 vs the paper's 0.75/1.01/1.77/2.75. I tried 19 (λ1,λ2) settings, including unregularized λ=0 (which reaches only ≈0.2–0.4).
  - I found no code or config difference that explains this (Llama ships its own script and the README pins transformers 4.51.x, which I used). Our values still beat the paper's top-k numbers at every Llama level except WinoGender 10%: there our value exceeds top-k, while the paper's own PGB-CT number is below it.
- **Tables 4/5 (MLP neurons):** the trend holds everywhere: PGB-CT is orders of magnitude above the paper's top-k/random numbers, and the metric grows explosively with the number of neurons.
  - Exact values depend strongly on λ and on the epoch. Some cells match (distilGPT2 Professions 2.5%: 11.86 vs 11.76; Llama 5%: 1.08e4 vs 1.1e4; CounterFact distilGPT2 5%: 62.22 vs 62.22; CounterFact GPT-2 10%: 8284 vs 8376).
  - In other cells we are far above the paper (distilGPT2/GPT-2 Professions ≥10%) or far below it. GPT2-medium/large/xl never reach the paper's saturated 6.8e7–6.6e11 regime with our grid.
- **Not verified:** the claims about baselines (top-k, greedy, random, DCM: "PGB-CT beats top-k, close to greedy") and the runtime/speed-up claims (1.76× vs top-k, 229× vs greedy). The release does not include baseline code ("Plot generation and baseline-only scripts are intentionally excluded"), so I did not reconstruct them. Those claims can only be checked against the paper's own baseline numbers, which is how the TREND labels above are defined. Our per-run times are not comparable either: 15 full epochs on a shared node under heavy CPU/GPU contention, vs early stopping on an A6000 in the paper. As a sense of scale, a GPT-2 small WinoGender run takes 67 s alone.
- **VBD / Fig. 6 (LLaMA-13B, attention heads + MLP blocks):** not run. It is a secondary experiment, notebook-style, needs a separate environment (transformers 4.56.2, torch 2.8) and LLaMA-13B weights, and reports only a curve with no table.

## Why it is not fully reproduced
1. Baseline code is missing from the release, so the comparative claims can only be judged against the paper's own baseline numbers (coverage SUBSET).
2. The λ used for each table cell is not reported. The README λ (0.05/0.05) collapses the mask to empty, so a grid search was needed. For the extremely sensitive MLP metric, the grid and selection protocol largely decide the number.
3. Llama-3.2-1B attention results differ substantially from the paper (unexplained; possibly a different λ / seed / epoch selection; the metric is very unstable).
4. VBD and the timing experiments were not run.

## Discrepancies
1. **code_vs_paper (minor):** README run commands use λ1=λ2=0.05. The paper says λ was grid-searched in [0, 0.1] but gives no values. With 0.05/0.05 every GPT-2/Qwen attention run and every GPT-2 MLP run collapses to an empty mask (ℓ=0) within 1–3 epochs. Useful values are 1e-5–1e-3 (attention) and 1e-6–1e-2 (MLP/CounterFact). Affects results: yes (as-released commands give no result).
2. **code_vs_paper (minor):** Professions data has 17 templates × 159 professions = 2703 pairs (`data/professions/*`, 29 female + 130 male occupation lines). The paper (App. C.2 / Table 3) says 169 professions and 2873 examples. Affects results slightly.
3. **code_vs_paper (minor):** The paper (Sec. 4, Alg. 1) stops when |H_t| ≤ S. The scripts have no S argument and always run the fixed number of epochs, so selecting the mask for each sparsity level is left to the user and is not in the release. Affects how Table 1 is produced, not the method.
4. **paper_internal:** Sec. 5.2 says "Across all models and sparsity levels, PGB-CT yields higher ℓ(D,m) values compared to the top-k algorithm". Table 1 Llama-3.2-1B WinoGender 10% shows top-k 0.450 > PGB-CT 0.366, and Table 4 distilGPT2 ≤2.5% shows top-k 14.86 > PGB-CT 11.76 ("significantly higher … than … top-k across different models and sparsity levels").

## Notes on the run
- Shared node: our cgroup has 7 physical cores. Running more than 2–3 processes at once on the single GPU caused 5–10× slowdowns, so concurrency was reduced mid-run (this changes no results).
- Two CounterFact GPT-2 runs (λ1=3e-5, 3e-4) were OOM-killed when three ran at once (`train_factual.py` needs about 24 GB host RAM each). They were rerun one at a time.
- I never touched other users' processes. `readme_watcher.py` only signalled my own runs (checked via cwd under this attempt directory).
