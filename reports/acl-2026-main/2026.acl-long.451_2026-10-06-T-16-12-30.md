# SPEAK: Spiking Neurons as an Entropy-Aware Tokenizer for LLMs (ACL 2026 long 451) — reproduction report

## Verdict

- **Verdict: FAILED**
- **Result match (after fixes): NO_MATCH**. **As released: NO_MATCH.**
- **Coverage: SCALED_DOWN.** GTok runs used 60k of the 200k configured steps, 1 of 3 seeds, and 5 of 6 Table-1 datasets (no cc-100). RTok covers only XNLI-en; the other 12 XNLI languages and UNER can't be run with the release.
- **Codebase completeness: MISSING_CORE**

Summary:

1. **GTok (Table 1, the headline BPC 1.108 / SF 4.32 claim).**
   - **As released**, SPEAK's spiking tokenizer fires at about 65% of character positions. That gives **SF ≈ 1.5×** on every dataset, against 3.8–4.8× in the paper.
   - At equal training budget, SPEAK's BPC is still **worse** than the DTP-Unigram baseline from the same release. On text8: 1.276 vs 1.240. On wiki40b-en: 1.247 vs 1.197. The baseline also has a far higher SF (5.8×).
   - **Fixed variant.** I implemented the two parts of the method that the paper specifies but the GTok code omits: soft reset θ=0.8 (Eq. 10) and the 2nd L_mem term (Eq. 14). With these, SF reaches **4.75×** on text8 (paper 4.6×) and **4.93×** on wiki40b-en (paper 4.5×). BPC barely moves: 1.276 on text8 and 1.244 on wiki40b-en, both still worse than the same-budget DTP baseline (1.240 and 1.197).
   - The paper's optimization algorithm (momentum-based proxy supervision with Metropolis–Hastings acceptance, Eq. 13/15/16) is absent from the release.
2. **RTok (Table 2, XNLI).** `RTok_Experiments/main.py` as released trains XLM-R+LoRA to **chance accuracy (33.3%)** on XNLI-en; the paper reports 84.9%. A config-only variant that unfreezes the SNN tokenizer also gives 33.3%.
   - The released RTok pipeline has no hypernetwork, though the paper says it uses ZeTT's. Its entropy/membrane auxiliary losses are commented out.
   - Its character vocabulary covers only English, so the other 12 XNLI languages crash on an assertion. There is no UNER code at all.

## What the paper claims (reproduction targets)

- Table 1 (GTok, Hourglass Transformer trained from scratch, DTP pipeline). SPEAK gets test BPC text8 1.120, cc-100 1.208, wiki40b en/fi/he/vi 1.068/0.932/1.273/1.049, average 1.108. SF is 4.6/4.8/4.5/3.8/3.8/4.4×, average 4.32×. The paper says this beats MAGNET (1.117 / 4.20×) and DTP (Unigram 1.115 / 3.80×; Entropy 1.123 / 3.98×). The baseline numbers are copied from the DTP paper.
- Table 2 (RTok, XLM-R base + LoRA + ZeTT hypernetwork). XNLI average 73.1% over 13 languages, en 84.9%. Table 6: UNER average F1 79.2%.

## What I ran

Environment: conda env at `env/` with Python 3.11, torch 2.8.0+cu128 and the repo's `requirements.txt` pins. spikingjelly silently upgraded torch to 2.14, so I re-pinned torch to 2.8.0 and the cu12 cuDNN/cuBLAS wheels. I also installed wandb, because `main.py` hard-codes `report_to="wandb"`; it was run with `WANDB_MODE=disabled`. Hardware: 1×H200. Up to 6 GTok runs shared the GPU.

### Data
- text8: `scripts/get_text8.sh` steps (wget + `scripts/prep_text8.py`), giving 90M/5M/5M.
- wiki40b en/fi/he/vi: `scripts_repro/prep_wiki40b.py` (my script). It mirrors `scripts/download_wiki40b.py` and `get_wiki40b.sh`: truncate to 4e8/1e7/1e7 chars, then `cleaners/clean.py:text8_cleaner`. The release's versions have hard-coded `E:/ACL2026/...` Windows paths, and `clean.py`'s `__main__` ignores the CLI args that `get_wiki40b.sh` passes.
  - Data comes from HF `google/wiki40b` (parquet).
  - Non-English text there is stored as Python bytes reprs (`b'\xd7\x9c...'`), so my script decodes it with `ast.literal_eval(...).decode('utf-8')`. The first, undecoded attempt produced garbage (spelled-out hex digits); it was discarded.
- cc-100 (en): **not run.** The release has no download/prep script for it, and the raw corpus is ~80 GB.

### GTok (Table 1)
Configs: `configs/unigram.yaml` from the release (wiki40b-en), plus copies `configs/{text8,wiki40b_fi,wiki40b_he,wiki40b_vi}.yaml` that differ only in `data:` and `tokenizer_path:`. All use the released `spmunigram-10000.model` for that dataset. Command, from `codebase/GTok_Experiments`:
```
python -u main.py --config configs/<ds>.yaml --work_dir ../../runs/g_<ds> --nw 2 --eval_interval 1000000 --max_step 60000
```
- `--max_step 60000` instead of 200000. A single run takes ~2.2 steps/s alone and ~0.7 steps/s with 5 sharing the GPU, so 5 datasets × 200k × 3 seeds could not fit the 48h budget. The cosine schedule is set by `max_step`, so the LR anneals fully. Warmup is 4000, as in the config.
- `--eval_interval 1000000`: only the final validation/checkpoint and test evaluation run, to save time. This doesn't change the final test numbers, because `Trainer.evaluate()` uses the final model.
- `--nw 2`: dataloader workers, CPU-limited.
- 1 seed (1111, the default) instead of 3.

**SF computation.** `Trainer.cal_SF` only prints the boundary count over the overlapping eval windows (tgt 500 + ext 1500). It also never resets the SNN state between batches. SF is therefore computed by `scripts_repro/sf_from_log.py` as (number of positions those windows pass through) / (boundary count). I cross-checked it with `scripts_repro/check_sf.py` on non-overlapping 2000-char windows with the SNN state reset per batch. The two agree: text8 as released 1.533 vs 1.533; fixed variant 4.75 vs 4.79; DTP 5.85 vs 5.87.

Extra runs:
- **DTP-Unigram baseline at the same budget** (text8 and wiki40b-en). The release still contains DTP's `BoundaryPredictor` (sigmoid boundary predictor + BCE to unigram boundaries); LM.py only has it commented out. I added an opt-in env switch `SPEAK_BASELINE=dtp` in `LM.py`. Everything else is identical: same unigram-10000 supervision, model, optimizer and steps.
- **"Paper-faithful fix" variant** (`SPEAK_FIX=1`, text8 and wiki40b-en). This changes two things in `utils/networks.py`:
  - (a) `ConditionalLIFNode`: every spike soft-resets the membrane by θ·u_th with θ=0.8 (paper Eq. 10; same as the release's own `RTok_Experiments/utils/xnli_snn/neurons.py`). It then hard-resets to u_reset where the entropy reset mask is on. The release instead does *no reset at all* on spikes outside the mask.
  - (b) `MembraneLoss`: adds the 2nd term of Eq. 14, which pushes non-target potentials below threshold, with a learnable β. This is the same form as the release's RTok `MembraneLoss`.
  - Not implemented: MH sampling / momentum proxy. It is not in the release, and the paper doesn't give enough detail to rebuild it faithfully: where does s^{N+1} come from, and how is L_LM(s) evaluated per candidate?

### RTok (Table 2, XNLI-en only)
- As released: `cd RTok_Experiments; WANDB_MODE=disabled python -u main.py`. This is lng=en, 15 epochs, batch 100, lr 3e-4, LoRA r=128, frozen SNN tokenizer `a1.2_b0.6_houglass_128.pt`, entropy=False. Log: `runs/rtok_asreleased_xnli_en.log`.
- Variant: `scripts_repro/rtok_main_unfrozen.py`, a copy of main.py with `snn_frozen=False`, `report_to="none"`, and an added evaluation on the XNLI test split. Log: `runs/rtok_unfrozen_xnli_en.log`.
- Diagnostics (`scripts_repro/rtok_diag.py`, plus inline checks). The shipped SNN tokenizer segments XNLI text roughly into words (~2.5 chars/token). Its output embeddings don't collapse. The training loss still stays at ln 3 the whole time. The projection from SNN features into XLM-R's embedding space is never trained: `snn_pretrain.py` only optimizes the membrane loss, and main.py freezes it. The paper's mechanism for producing token embeddings, the ZeTT hypernetwork, is absent.
- Other 12 XNLI languages: can't be run. `utils/xnli_snn/vocab.pt` and the 159-char embedding table in the checkpoint come from English XNLI only, so `Vocab.convert_to_tensor` asserts on unseen characters. UNER: no code in the release.

## Why it isn't reproduced
1. **Core method parts missing from the release:**
   - MH-sampling, momentum-based proxy supervision (Sec. 3.3, App. B; "w/o MH sampling" is an ablation in Table 5).
   - ZeTT hypernetwork integration for RTok.
   - RTok entropy-reset and membrane auxiliary training (commented out).
   - Multilingual/UNER RTok pipelines.
2. **GTok code differs from the paper in ways that change results.**
   - With no reset on spikes outside the entropy mask, SF collapses to ~1.5. Adding the paper's soft reset (and the L_mem 2nd term) restores SF ≈ 4.7.
   - Even then, SPEAK doesn't beat the same-budget DTP baseline in BPC.
3. **Reduced compute.** 60k/200k steps, 1/3 seeds, no cc-100. Full-scale runs might shift absolute BPC, but I have no evidence they would reverse the equal-budget ranking.

## Discrepancies
Code vs paper:
1. **MH-sampling momentum proxy missing** (major, affects results). Paper: Eqs. 13, 15–16 and App. B. Code: GTok `boundary_predictor.py:SNN.calc_loss` and RTok. Neither implements it; GTok's spike target is unigram boundaries ∪ top-20% entropy positions.
2. **No reset on non-masked spikes** (major, affects results). Location: GTok `utils/networks.py:ConditionalLIFNode.neuronal_reset`. Paper Eq. 10 / Sec. 3.2: soft reset (scaled by θ) at low-entropy tokens. Code: when a spike occurs outside the reset mask, the potential is left unchanged ("No reset at all"), so the neuron keeps firing. Measured SF is 1.5× instead of ~4.6×.
3. **L_mem lacks its 2nd term** (major, affects results). Location: GTok `utils/networks.py:MembraneLoss`. It implements only the first term of Eq. 14 (encourage spikes at targets), i.e. the "w/o L_mem 2nd term" ablation of Table 5. There is no β, though App. C.1 says α and β are learnable.
4. **No hypernetwork in RTok** (major, affects results). Location: `RTok_Experiments/utils/xnli_snn/model.py`/`snn_tokenizer.py`. Paper Sec. 4.4: token embeddings come from the ZeTT hypernetwork, following DyTok. Code: they come from the SNN tokenizer's LN–Linear–GELU–Linear–LN projection. It is frozen (`snn_frozen=True`) and never trained; App. C.2 calls Linear2 "a single Linear layer". Result: chance accuracy.
5. **RTok auxiliary losses commented out** (major, affects results). Location: RTok `model.py:TkLM.forward`. The entropy-aware reset supervision, membrane loss and reset BCE are all commented out; only the LM loss is used. `main.py` sets `entropy=False`, so there is no entropy-aware reset.
6. **RTok English-only** (major, affects results). The char vocab (`vocab.pt`) and the SNN checkpoint cover only English XNLI, so the other 12 languages of Table 2 can't run. There is no UNER pipeline (Table 6).
7. **Character-level entropy** (minor). Location: GTok `LM.py`/`boundary_predictor.py`. The paper ranks "token-level entropy"; the code computes the LM's per-character predictive entropy and marks the top 20% of positions per sequence.
8. **SF not computed by the code** (minor, affects reported SF only). `Trainer.cal_SF` outputs a boundary count over overlapping eval windows without resetting SNN state, so SF must be derived manually. The paper says SF is computed relative to DTP-Unigram's token length (App. D.2).

Paper-internal:
- Table 1, "Δ to MAGNET" row (minor, no effect on results). text8 is listed as −1.2%, but 1.120 vs 1.132 is −1.06%. he is listed as −0.8%, but 1.273 vs 1.281 is −0.62%. Other entries agree within rounding.
