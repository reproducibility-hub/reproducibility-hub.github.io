## What was run
Models (fp16, greedy decoding, raw text prompts with no chat template, as in the code):
- meta-llama/Llama-3.1-8B-Instruct
- mistralai/Mistral-Nemo-Instruct-2407
- Qwen/Qwen3-4B-Instruct-2507 (the paper says only "Qwen3-4B-Instruct"; this is the matching HF instruct checkpoint)
- HuggingFaceTB/SmolLM3-3B

Data and prompts:
- Data comes from the repo's released CSVs: DRUID Borderlines / Politifact / ScienceFeedback-cluster1, LegalBench corporate lobbying (Bill / Company), and ConflictQA Counter / Parametric.
- MF2 was rebuilt from the public HF `sardinelab/MF2` metadata.
- We used the "implicit" prompts, i.e. the variant that the repo's concatenate script uses (`PROMPT_TYPE='implicit'`) and that Fig. 2a matches.

Pipeline (all scripts in `./repro`; logs in `./logs`):
1. `make_jobs.py` builds per-model job lists. `driver.sh` runs `extract_fast.py --model M --jobs jobs/M_{baseline,random,random_mf2}.json` sequentially.
2. `extract_fast.py` uses the repo's `create_prompt_*` functions and `check_instruction_followed`. It stores the hidden states at the last prompt position for all layers (embedding layer plus every block; HF `hidden_states`). For random contexts it stores only the final layer.
   - It replaces the released one-prompt-at-a-time `model.generate`, which also writes a JSON dump of every layer.
   - Speed comes from computing the KV cache of the shared few-shot prefix once and batching with left padding.
   - It generates 16 new tokens. These are only needed for the ")True." instruction-following check; the released `max_length` is not specified.
   - Validation (`validate_equiv.py`) against the released `_inference_with_activations_helper`: identical completions, per-layer cosine 1.0000, about 0.2% fp16 relative difference at the final layer.
3. `analyze.py --acts_root acts/M --name D --out_root results/M` re-implements `create_dataset.py`, `random_shuffle_choices.py` and `theta_activations_ground_truth_metrics.py`, calling the repo's metric functions.
   - `validate_analysis.py` shows identical output (max abs diff 0) to the released scripts on a released-code test run (`asreleased_run/`).
4. `aggregate.py` runs the repo's unmodified `compare_baseline_random_types_ground_truth.py` (Tables 3/4) and computes Tables 2/6/10. `plot_curves.py` draws the Fig. 4/5 analogues (`tables/fig4_theta.png`, `tables/fig5_relmag.png`).
   - Full tables are in `tables/tables.md`; per-entry comparisons are in `tables/comparisons.json`.

Settings that differ from, or are unspecified in, the paper and code:
- 16 generated tokens instead of a full 3–4 sentence justification. This only affects the instruction-following check; the activations come from the first decoding step either way.
- Batched fp16 inference with left padding.
- Seeded random choice-pair selection; the release uses an unseeded `random.random()`.
- MF2 random contexts were regenerated, because the release does not ship them:
  - We ran the repo generator with seed 42.
  - "Random wiki" paragraphs come from a local Wikipedia 20231101 dump rather than the live API, which rate-limits with HTTP 429.
- Table 2/6 significance test: one-sided Wilcoxon signed-rank against 1, written by us since it is not in the release.
