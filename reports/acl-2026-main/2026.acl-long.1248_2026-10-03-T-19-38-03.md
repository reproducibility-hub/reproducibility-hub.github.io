## What the paper claims (target)

The main claim is in Table 1 (ALFWorld, 140 seen / 134 unseen games, 20-step cap). An actor fine-tuned to read a sender's last-layer hidden states ("latent communication", Interlat) beats the same actor given the sender's plan as text (Text), no communication (No-Comm), and fine-tuned CoT / No-CoT baselines. Swapping in another task's latents (CrossTask) or perturbing the latents (noise, CovGauss, RandomRot) hurts performance, which the paper takes as evidence that the actor uses task-specific latent content. The sender is the Instruct model and the actor is the Base model of the same family.

## What I ran

1. **Data**:
   - Training trajectories: ETO `alfworld_sft.json` (Song et al. 2024; 3,119 trajectories, matching the paper's N=3,119) from HF `agent-eto/eto-sft-trajectory`.
   - ALFWorld games: `alfworld-download`. `base_config.yaml` comes from the alfworld repo.
2. **Sender latents**: the released `data_collection/alfworld_collection.py` with Qwen2.5-7B-Instruct, and separately Qwen2.5-0.5B-Instruct, over all 3,119 training tasks and the 274 eval tasks.
   - Settings: temperature 0.7, top-p 0.9, max_new_tokens 1500 (the `scripts/collect_alfworld.sh` defaults), `--torch_dtype bfloat16`.
   - Run via `scripts_mine/run_collect_shards.sh`: 16 shards in parallel processes on the one GPU.
   - Mean latent length was ~460 (cf. the paper's "128L ≈ 28.8%" → L ≈ 444).
3. **Actor training**: `core_training/train.py` via `scripts_mine/train_actor.sh`.
   - Base models: Qwen2.5-7B / Qwen2.5-0.5B.
   - From the paper: lr 1e-5, global batch 16 (train.py forces per-device 2, so grad-accum 8), 3% warmup, bf16 + FlashAttention-2.
   - From `train.sh`: cosine schedule, wd 0, prepended_length 1000, model_max_length 2048.
   - 10 epochs (the `train.sh`/`quick_start --full` default; the paper gives no epoch count) = 1,850 optimizer steps.
   - 5% held-out eval split (`--eval_ratio 0.05`); the final model is used (the code forces `load_best_model_at_end=False`).
   - Optimizer: torchao AdamW with bf16 stochastic rounding (see deviations).
   - Time: 7B 5.0 h; 0.5B ~1.6 h.
4. **Evaluation**: `eval/alfworld/eval_agent/main.py` (`scripts_mine/eval_variant.sh`), HiddenAgent with temperature 0.7 and max_new_tokens 100; `--split dev` = seen (140 games), `--split test` = unseen (134 games).
   - Variants: `none` (Interlat), `text`, `no_comm`, `cross_task`, `randomrot`, `covgauss0`, `covgauss1`, and `noised --noise_std 1.0` (WhiteNoise).
   - Metric: success rate; steps = mean steps on successful / all episodes (`scripts_mine/score.py`, `aggregate.py`).

### Settings that differ from the paper
- **Optimizer numerics.**
  - Paper / `train.sh`: DeepSpeed (ZeRO-2 + CPU offload), i.e. AdamW with fp32 master weights.
  - Why I couldn't do that: fp32 master + Adam states for 7.6B params (~122 GB) fit neither the 141 GB GPU (with activations) nor the 111 GB host-RAM limit.
  - Why not run the README's direct `python train.py` path: it casts the model to bf16 and runs plain AdamW on bf16 weights, which rounds away most lr=1e-5 updates (measured: ~8× smaller effective updates).
  - What I used: torchao `_AdamW(bf16_stochastic_round=True)` with fp32 moments, enabled opt-in through `INTERLAT_BF16_SR_ADAMW=1`.
- **Collection dtype**: bf16 instead of the collector's float32 default. The bf16 option is advertised by the collector; I used it for speed.
- **Validation split**: 5% held out as in the paper, but the final checkpoint is used because the code cannot select the best one. The 7B eval loss was lowest around steps 400–1000 (0.43–0.44) and rose to 0.51 by step 1600.
- **Training runs**: one training run per backbone; the paper averages "three independent runs".
- **Eval runs**:
  - 7B: 3 runs for Interlat / Text / No-Comm, 2 for CrossTask, 1 for the other perturbations.
  - 0.5B: 2 runs for Interlat / Text / No-Comm, 1 for CrossTask.
- **Eval config**: `max_steps` set to 20 (the paper's cap; the config said 50).
- **Text variant**: plan tokens are fed as raw embeddings between `<bop>`/`<eop>`, matching the plan part of the training curriculum.
- **No-Comm variant**: an empty `<bop><eop>` span. The release crashed on both variants, so this is my interpretation.

### Reading the results
- **Absolute Interlat numbers**:
  - Qwen2.5-7B seen: 69.8 vs 70.5, a match.
  - Qwen2.5-7B unseen: 5.7 points low.
  - Qwen2.5-0.5B: ~6 points low on both splits.
- **Latent vs. text communication (the central claim)**:
  - 7B seen: Interlat beats Text by only +1.2, which is within the run-to-run std of ~2–3 points (paper: +6.2).
  - 7B unseen: Text beats Interlat by 7.0 (paper: Interlat +3.0).
  - 0.5B seen: Text beats Interlat by 4.3 (paper: Interlat +6.7).
  - 0.5B unseen: Interlat +0.75, within noise (paper: +10.2).
- **Latent vs. No-Comm**: 7B +3.3 seen and 0.0 unseen (paper +8.3 / +3.2); 0.5B −1.8 / +1.5 (paper +10.7 / +13.4).
- **Baselines**: run through the same pipeline, the Text and No-Comm baselines come out 3–6 points stronger than the paper reports, which removes most of the reported gain (`BASELINE_STRONGER_THAN_REPORTED`).
- **Task-specificity**: CrossTask latents are as good as matched latents (7B 65.0/61.2 vs 69.8/59.7; 0.5B 57.9/51.5 vs 55.4/51.1). RandomRot, CovGauss-µ and WhiteNoise also show no consistent drop. The paper's claim that the actor relies on task-specific latent structure is not supported in our runs; only CovGauss-0µ on 7B seen shows a drop (−9 points, n=1).
- **Steps**: Interlat episodes are not longer than Text or No-Comm, so the paper's "more exploratory behaviour" observation does not appear either.
- **Separation loss**: the hinge `max(0, 0.69−JS)` fell from ~0.56 to ~0.43 over training. There was no sharp "aha" drop (Fig. 3), so the actor learned only weak sensitivity to the latents. This fits CrossTask ≈ Interlat.

**Overall: `NO_MATCH`.** The method's reported number reproduces only for 7B seen. The effects the paper attributes to latent communication (beating text communication, and depending on task-specific latents) are within noise or reversed in 3 of 4 backbone/split settings.

Caveats that could explain part of the gap:
- I used one training seed and the final rather than best-on-validation checkpoint; validation loss rose late in training.
- I used a stochastic-rounding bf16 optimizer instead of DeepSpeed fp32-master AdamW.
- Bugs I had to fix (below) mean the authors' exact eval setup is unknown.

## Discrepancies

### Code vs. paper
1. **Curriculum (major)**, `custom_model.py`:
   - Paper: r ∈ {0, 0.1, …, 1.0}, with the first ⌊rL⌋ positions replaced by plan token embeddings and latents after them.
   - Code: r ∈ {0.1, …, 0.9} at every step, with no annealing. The mixed message is `hidden[:rL] + plan[rP:]`, i.e. latents first and plan tokens after.
   - Effect: the actor never trains on a fully-latent message, yet that is what it gets at test time.
2. **Alignment loss (major)**:
   - Paper: β·KL(p_θ‖p_plan) + α·(1 − cos) over per-position normalized logits.
   - Code: 0.7·KL(p_plan‖p_θ) (reverse direction) + 0.3·(1 − cos) over the flattened probability vectors of all positions.
3. **Separation loss (minor)**: paper −JS; code hinge `max(0, 0.69 − JS)`.
4. **Loss weights (minor)**:
   - Paper: λ_sep ∈ [0.1, 1], λ_align ∈ [0.1, 0.2].
   - Code: λ_sep ∈ [0.01, 0.5], λ_align ∈ [0.01, 0.05], set dynamically every step and overriding the CLI values.
5. **Model selection (minor)**:
   - Paper: best model on a 5% validation split.
   - Code: default split 1%, and `load_best_model_at_end` is forced False, so the final model is used.
6. **Eval config (minor)**:
   - Paper: 20-step cap.
   - Code: `max_steps` 50; `icl_format` "first", which crashes `main.py`.
7. **Latent extraction (minor)**: the collector skips the state that predicts y₁ (off by one relative to the paper's definition of H).
8. **Noise variants (major for those rows)**: CovNoise (covariance-shaped noise) is not implemented; only isotropic noise exists.
9. **Baselines (major)**: no training code or config for the CoT(full) / No-CoT baselines.
10. **Eval agent (minor)**:
    - The adapter's MHA dropout (p=0.1) stays active at test time because the wrapper is never put in `eval()` mode.
    - The test-time first prompt (ETO ICL format, no newline before "Now, you are given a step-by-step plan…") differs from the training format.
11. **Precision (minor)**: the README's direct train.py path runs AdamW on bf16-cast weights, unlike the paper's DeepSpeed setup.

### Paper-internal
- Table 3 vs. Table 8 (same Qwen2.5-7B untrained compression results) disagree slightly:
  - 5% seen: 64.29 vs 64.52.
  - 128L: 64.55 / 60.25 vs 64.52 / 60.20.
  - 64L: 66.23 / 61.53 vs 66.19 / 61.44.

## If not fully reproduced: why
- The released pipeline needed several bug fixes before it produced any non-zero result. With them, the method's absolute number matches only for Qwen2.5-7B seen tasks.
- The paper's comparative claims did not reproduce: Text and No-Comm come out stronger than reported, and the task-specificity ablations show no effect.
- Compute limits: one training seed per backbone; no LLaMA3.1-8B / cross-family / MATH / compression runs (each needs another multi-hour collection + training cycle); a substitute optimizer, because DeepSpeed fp32-master training doesn't fit 1 GPU / 111 GB RAM.
- The CoT(full) / No-CoT baselines can't be compared because the release has no code to train them.
