## What the paper claims
CLEAR is a loss for cross-lingual retrieval: 0.4·InfoNCE on English (q_en→p_en), plus 0.4·a *reversed* cross-lingual InfoNCE (English passage as anchor, target-language queries as candidates), plus 0.2·a KL term. The paper reports these effects:
* CLEAR beats a standard InfoNCE baseline (target-language query → English passage) in most cross-lingual settings. This holds for 4 models (bge-m3, multilingual-e5-base, gte-multilingual-base, jina-v3) × 9 languages, on Belebele and XQuAD, in both directions (Table 1, App. Tables 9/10).
* The largest gains are on low-resource languages (e.g. mE5 te/bn En-Lang 80.97/85.44 vs InfoNCE 77.14/81.81, "up to 15%" over the base model).
* English retrieval degrades less than with InfoNCE (Table 1 English-English).
* CLEAR also wins in multilingual training (Tables 2, 3, 11, 12), and each component helps (Table 4).

## Discrepancies
1. **code_vs_paper (major, affects results): `train.py`.** The paper trains on 12,698 samples for one epoch; the code trains on the first 500 samples only, for about 21 epochs with the README settings.
2. **code_vs_paper (major, description only): the KL term in `loss.py`.**
   * Paper, Eq. 5: KL(S_en‖S_CL), with S_CL[i,j] = sim(p_en_j, q_ℓ_i), i.e. rows indexed by queries.
   * Code: `F.kl_div(log_softmax(origin), softmax(cross))`, which is KL(P_CL‖P_en), the reversed direction. It compares query-to-[passages + hard-negative passages] rows with passage-to-[queries + hard-negative queries] rows, so S_CL is indexed by passage.
   * The paper's numbers are reproduced with the code's version; the paper's formula was not tested.
3. **code_vs_paper (minor, unverifiable): hard-negative rank range.** The paper says top 30–100; the authors' default data path name says `5HN_50-100`.
4. **paper_internal: Table 1 XQuAD gte-multilingual "ar" row.** It is an exact copy of the multilingual-e5 "ar" row and contradicts Table 10's gte ar values.
5. **paper_internal: Table 11 Base and some rows contradict Table 9.** The Base model is untrained, so Base values must match across tables, but they differ in places:
   * bge-m3 te En-Lang Base/InfoNCE/CLEAR 92.58/92.94/93.50 duplicates the vi row (Table 9 Base 87.12).
   * jina-v3 te nDCG@10 duplicates the vi row.
   * mE5 vi/te Lang-En Base values are swapped.
   * gte te Lang-En Base is 90.48 vs 88.46.
   * These account for our largest Table 11 "misses" (ours: bge-m3 te 89.31/89.72; jina te 86.58/87.09).
6. **paper_internal: Sec 5.1 text.** It says "on Bengali and Telugu ... 80.97 and 85.44", but the table order is te = 80.97, bn = 85.44.
7. **Possible copy error, not counted as a discrepancy:** Table 1 jina-v3 English-English Belebele InfoNCE is "94.01 (+0.75)" for hi, vi and bn alike. We get 95.4 for each.
