## What the paper claims and what was released

- Main claim (abstract, Table 2, Table 3): SememeLRM is DeBERTa-v3-large with sememe-tree sense embeddings produced by a 3-layer R-GCN and inserted into a prompt. It improves over DeBERTa-large on all 5 LRC benchmarks and both HyperLex splits, by +1.6% on average.
- A second set of rows uses sememe trees from the automated STC pipeline ("w/ automated STC").
- Repo `https://github.com/COOLPKU/SememeLRM` (linked in the paper) contains:
  - one script, `src/train_deberta_pos_rgcn.py`, which handles LRC only (classification);
  - sememe-annotated jsonl data for CogALexV, EVALution, ROOT09 and HyperLex (lexical and random splits), plus `graph_data.json`.
- Not released:
  - BLESS and K&H+N data (the git history shows a "Delete BLESS directory" commit);
  - the STC pipeline (ASP/MSP/SSP/SRC);
  - any LE (regression) code;
  - code or config for the DeBERTa-large baseline, the gloss variant and the ablations.
- The README does not say whether the released sememe trees are the HowNet (gold plus STC supplement) version or the fully automated STC version. We compare against the main "SememeLRM" rows and list the STC rows as supplementary.

## What we ran

Environment: conda env at `./env` with Python 3.10, torch 2.4.1+cu121, transformers 4.46.3, accelerate 1.1.1, torch-geometric 2.5.3, datasets, scikit-learn and sentencepiece. Backbone: `microsoft/deberta-v3-large` (HF hub).

Every run uses the README hyperparameters, which equal the paper's App. C: batch 32, lr 2e-5, 10 epochs, weight decay 1e-5, warmup 0.1, cosine schedule, R-GCN hidden 1024, evaluation every 30 steps with the best dev checkpoint kept. Each setting was run with seeds 42, 1, 2, 3, 4; the paper reports neither its seed count nor a std.

Launcher: `scripts/run.sh NAME SOURCE DATADIR DEVFILE SEED SCRIPT [flags]`. Each run gets its own directory `runs/<NAME>/`, with `data` symlinked so the script's relative `./data/graph_data.json` resolves. It runs:

```
env/bin/python codebase/src/train_deberta_pos_rgcn.py --train_path <ds>/train_data.jsonl --dev_path <dev> \
  --test_path <ds>/test_data.jsonl --source <DS> --deberta_name <deberta-v3-large snapshot> --rgcn_hidden_dim 1024 \
  --batch_size 32 --lr 2e-5 --epochs 10 --weight_decay 1e-5 --warmup_ratio 0.1 --output_dir runs/<NAME>/out --seed <s> [flags]
```

Settings (job lists are in `scripts/jobs*.txt`):

| Run name | What | Flags |
|---|---|---|
| `evalution` | EVALution, as released (it has no random class, so as released = fixed) | none |
| `cogalexv_fixed` | CogALexV, paper protocol: train with `random`, report weighted F1 excluding `random`, use the final checkpoint because there is no dev set | `--keep_random --exclude_random_in_metric --no_dev` |
| `cogalexv_nodev` | CogALexV, released logic (`random` dropped everywhere) with the final checkpoint | `--no_dev` |
| `cogalexv_devtest` | CogALexV, fully unmodified code; the test file is passed as dev because the script requires one (best-on-test selection) | none |
| `root09_fixed` | ROOT09, paper protocol (3 classes, `random` kept) | `--keep_random` |
| `root09` | ROOT09, as released (`random` dropped, so 2 classes) | none |
| `le_lexical`, `le_random` | HyperLex lexical and random splits with our LE variant `scripts/train_le.py` | none |
| `base_*` | Same settings without sememe tokens in the prompt (our guess at "DeBERTa-large (ours)") | `--no_sememe` |

Settings that differ from the paper:
- 5 seeds instead of an unknown number.
- fp16 is used, as in the code.
- For HyperLex we cap words at 5 senses, as the paper states (App. C). The released HyperLex data has up to 20 senses per word; the LRC data is already capped at 5.
- LE scores are normalized as `score/6`. Spearman ρ is invariant to this.

## Why the run is not fully reproduced

1. **Missing data.** BLESS and K&H+N, two of the five Table-2 datasets, have no sememe-annotated data in the release, and the STC pipeline needed to rebuild it is not released either.
2. **The main claim does not hold under our baseline.** With a no-sememe DeBERTa-large run through the same released pipeline, the improvement disappears on 3 of 5 runnable benchmarks. The paper's DeBERTa-large (ours) numbers are 1–4 points lower than what this pipeline gives without sememes. The baseline config is not released, so this is a strong signal rather than proof.
3. **As released, the code does not follow the paper's protocol.** It drops all `random` pairs from train, dev and test, which inflates CogALexV and ROOT09 by 5 and 4 points. It also has no LE code at all.

## Codebase completeness: MISSING_DATA (+ PARTIAL_DATA)

Our edits to `codebase/src/train_deberta_pos_rgcn.py` are left uncommitted; the full diff is in `codebase_changes.diff`. All of them are opt-in flags, so the defaults reproduce the released behaviour exactly.
- **Fixes that change results:**
  - `--keep_random`: keep `random` pairs in the relation vocabulary and in train/dev/test. Implemented as module globals `KEEP_RANDOM`, guarding the 3 places that drop `random` (`build_rel_vocab`, `preprocess_sample`, `filter_and_map`).
  - `--exclude_random_in_metric`: compute weighted and macro F1 over the non-random labels (`METRIC_LABELS` passed to `f1_score` in `compute_metrics`), following the CogALexV protocol the paper cites (Santus et al. 2016a).
- **Missing piece added:** `--no_dev`: train all 10 epochs and evaluate the final checkpoint, as App. C specifies for datasets without a validation set. CogALexV has no dev file, and the released script always requires one and loads the best dev checkpoint.
- **Baseline added (not part of the release):** `--no_sememe` removes the sememe tokens from the prompt.

Scripts we wrote outside the codebase:
- `scripts/train_le.py`: the missing LE variant (paper Sec. 4.2). It was generated from the released script by `scripts/make_le.py` and `scripts/patch_le_nosememe.py`. Changes:
  - the classifier outputs 1 value through a sigmoid;
  - MSE loss;
  - the target is the HyperLex score / 6;
  - Spearman ρ for model selection and test;
  - no `random` filtering;
  - at most 5 senses per word.
- `scripts/run.sh`: launcher. `scripts/aggregate.py`: log parser that writes `results_summary.json`. `scripts/status.sh`: progress monitor. `data_links/hyperLexRandom`: symlinks that give the HyperLex random split the file names the launcher expects.

Other release issues:
- The README describes a single unified `./data/{train,dev,test}_data.jsonl` filtered by `--source`, but the repo ships per-dataset folders.
- `--epochs` defaults to 8; the README and paper use 10.
- `TrainingArguments(label_smoothing_factor=0.1)` has no effect because `CustomTrainer.compute_loss` is overridden; the paper does not mention it.
- The release saves a full checkpoint, including optimizer state, every 30 steps. Our 50 runs wrote about 338 GB; we deleted the checkpoints afterwards.
- Code for the gloss variant, the ablations (Table 7 and Table 13) and the STC pipeline is not released.
