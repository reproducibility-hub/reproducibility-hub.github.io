  - Qwen3: top-k 20 + top-p 0.8.

  The paper's baseline numbers reproduce only with this stacked chain. With each method applied alone ("pure" variant), the baselines collapse much earlier: e.g. LLaMA Top-p on GSM8K at T=2 gives 0.2% vs 46.6% in the paper. Min-k and Top-nσ barely change. So the stacking matters for how the baselines look, but not for the Min-k claim.

## Discrepancies
**Code vs. paper**
1. **[major, affects results] Default sampling settings stacked on every method.** Paper §4 defines each baseline by a single parameter (Top-k k=20, Top-p p=0.9, …) and Min-k as truncation + temperature. The released reasoning scripts (`llm_*.py`) call `model.generate(do_sample=True, …)` without overriding the model's `generation_config`, so every method also gets:
   - LLaMA-3: top-k 50 + top-p 0.9;
   - Qwen3: top-k 20 + top-p 0.8.

   The paper's baseline numbers reproduce only with this stacking; e.g. "Top-p" on Qwen is really top-k20 + top-p0.9. By contrast, `creative writing.py` explicitly sets `top_p=1.0, top_k=0`, so Table 1 and Table 2 use different protocols.
2. **[major, affects results] GPQA options are never shuffled.** `GPQA.py::build_prompt` always lists the correct answer as (A) with ground truth 'A'. Paper App. C.1 says the four options are randomly shuffled. My shuffled re-run gives similar numbers.
3. **[major, affects results] GPQA answer regex.**
   - Paper App. C.1: `The final answer is\s*\(([A-D])\)\.?\s*$`.
   - Code: `The final answer is \(([A-D])\)`.
   - The prompt example has no parentheses.
   - The reported LLaMA-3-8B and Qwen3-30B GPQA numbers match only an extractor with optional parentheses. Neither the released regex nor the paper's regex reproduces them.
4. **[major, affects Table 2] Min-p in the creative-writing script.** In `creative writing.py`, `MinPLogitsProcessor` is a custom processor applied to the raw logits *before* temperature, which makes it temperature-invariant. The paper (and the reasoning scripts, via HF `min_p`) treat Min-p as a temperature-sensitive probability-space method. This explains why Min-p stays at 51.6/46.6 at T=3 in Table 2 while it collapses in Table 1.
5. **[minor, affects reported number] Table 2 Mirostat value.** Released `llm-result/main_evaluation_results_llama3.json` has LLaMA Mirostat at T=3 = 2.8; paper Table 2 has 1.40.
6. **[minor] Small script bugs and defaults.** `llm_topk.py` `--k` float crash; `llm_topnσ.py` `--n type=int`; README file names; `llm_mink.py` default temperature is 4.0 and the default data path `data/aqua.parquet` doesn't exist. None of these affect results.

**Paper-internal**
1. **Table 5 text vs table.** §D.1 text says full Min-k scores 74.53% on GSM8K at T=4 (and "w/o Fallback" the identical 74.53%). Table 5, Table 6 and Table 1 give 76.15.
2. **Table 7 Qwen3-30B AQuA counts.** The values (e.g. 54.55, 50.26, 42.62, 19.23, 1.24) are not multiples of 100/254, so they cannot be accuracies on the 254-sample AQuA set that §4 states. Our full-set run gives ~77–80% for Min-k/Top-nσ vs the paper's ~59–61%.
3. **Appendix C.1 GPQA.** The text says options are shuffled and gives a regex requiring parentheses. The prompt shown has no parentheses in its example, and the reported numbers fit neither.
