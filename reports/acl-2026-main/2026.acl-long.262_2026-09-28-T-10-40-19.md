# Reproduction report: ReVisiT (ACL 2026, 2026.acl-long.262)

"Revisit What You See: Revealing Visual Semantics in Vision Tokens to Guide LVLM Decoding" by Beomsik Cho and Jaehyung Kim.
Code: https://github.com/bscho333/ReVisiT (linked from the paper).

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match: MIXED.** Greedy baselines mostly match the paper's numbers. The ReVisiT gains reported in Table 3 mostly do **not** show up.
  - **LLaVA-1.5-7B:** ReVisiT is *worse* than greedy on all three CHAIR metrics.
  - **Qwen2.5-VL-7B:** ReVisiT lowers CHAIR_S and CHAIR_I (smaller drops than the paper), but F1 does not go up.
  - **InternVL3-8B:** changes are tiny: CHAIR_S −0.6, CHAIR_I +0.28, F1 +0.19.
  - **Second 500-image subset (seed 1):** same picture. No consistent improvement on any model, and LLaVA gets worse again.
  - **Bottom line:** the paper's claim that ReVisiT "consistently enhances visual grounding… improvements in all three metrics" on CHAIR is not supported by our runs.
- **Coverage: SUBSET.**
  - Covered: Table 3 (CHAIR), the Greedy and ReVisiT rows, for all three main models, at full paper scale (500 images, max 512 new tokens, greedy decoding).
  - Not covered: the other benchmarks (HallusionBench, POPE, VQAv2, MMMU; Tables 2, 4, 5) and the baselines (DoLa, VCD, M3ID, CODE, SID). The release does not include code for any of these.
- **Codebase completeness: MINOR_FIXES.** No released source file was edited, but:
  - the released shell wrappers are broken, so I ran the Python entry points directly with the same arguments;
  - the Table 3 F1 metric is not implemented in the repo, so I wrote a small scorer from the paper's Appendix D.1 definition.

## What I ran

- **Environment:** one conda env (`env/`) with Python 3.10, torch 2.6.0+cu124, and the repo's bundled `transformers-v4.50.0`, installed editable with `--no-deps`. Other packages were pinned to the versions in `prerequisites/ReVisiT.yaml` (accelerate 1.5.2, tokenizers 0.21.1, qwen-vl-utils 0.0.8, timm 1.0.20, etc.).
- **LLaVA overlay:** the README asks for a second env for LLaVA (transformers 4.31), but only one env was allowed. Instead:
  - LLaVA runs put the repo's bundled `src/transformers-v4.31.0/src` first on `PYTHONPATH`;
  - they also use a small `--target` directory (`pydeps_llava/`) containing tokenizers 0.13.3 and accelerate 0.21.0 (the versions pinned in `ReVisiT_LLaVA.yaml`).
  - The LLaVA runs therefore used torch 2.6 instead of torch 2.0.1.
- **Data and weights:** COCO val2014 plus 2014 annotations (`prerequisites/download_coco.sh` URLs). Model weights from `liuhaotian/llava-v1.5-7b`, `Qwen/Qwen2.5-VL-7B-Instruct` and `OpenGVLab/InternVL3-8B` via `prerequisites/download_from_huggingface.py`.
- **Generation:** `run_gen.sh <model> <use_revisit> <port>` runs exactly the command in `eval_chair_<model>.sh`:
  ```
  torchrun --nnodes=1 --nproc_per_node=1 eval/chair_eval_<model>.py --seed 42 --model_path ./data/<model> \
     --model_base <model> --data_path ./data/coco/val2014/ --anno_path ./data/coco/annotations/instances_val2014.json \
     --output_path ./output --do_sample False --use_revisit {False|True} --exp_name chair/<model>/s42_m512_n500/<tag> \
     --max_new_tokens 512 --num_eval_samples 500
  ```
  ReVisiT hyperparameters are the per-script defaults in the release, and they agree with Sec. 5.1 and App. D.2:

  | Model | Layers | α (`relative_top`) |
  |---|---|---|
  | LLaVA-1.5-7B | `last` | 1e-5 |
  | Qwen2.5-VL-7B | `all` (even layers) | 1e-5 |
  | InternVL3-8B | `last` | 1e-6 |

  "Greedy" is the same script with `--use_revisit False`.
- **Scoring:** `score.sh <model> <tag>` runs the repo's `eval/chair.py` (with the bundled `chair.pkl` evaluator cache) to get CHAIR_S and CHAIR_I. `score_chair.py` then computes F1 as defined in App. D.1:
  - per caption, Prec = in-GT mentions / all mentions (duplicates counted), and Rec = GT objects mentioned / GT objects;
  - F1 = mean over captions of 2PR/(P+R), counting 0 for a caption with no mentions.
  - Check: this definition gives 82.41 for our LLaVA greedy run versus the paper's 82.33, which suggests it is the right one.
- **Scheduling:** the six main runs went concurrently on the single H200.
- **Supplementary checks** (not in the paper, to measure subset noise and α sensitivity):
  - all Greedy/ReVisiT pairs repeated on a second 500-image subset (`--seed 1`);
  - LLaVA ReVisiT with α = 1e-3 and 1e-4.

### Settings that differ from the paper

1. **The 500-image subset is almost certainly not the paper's.**
   - `CHAIRDataset` builds the subset by `random.shuffle(os.listdir(val2014))` with seed 42. `os.listdir` order depends on the filesystem, so the same seed picks different images on different machines.
   - We used the same 500 images for every model and method, verified by hashing image IDs.
   - This probably explains most of the greedy-baseline gaps, e.g. LLaVA CHAIR_S 49.8 vs 53.8. It cannot explain away the paired Greedy→ReVisiT differences, and the second subset shows the same pattern.
2. **Library versions:** torch 2.6/cu124 for every model (paper: torch 2.6/cu118 for Qwen/InternVL, torch 2.0.1 for LLaVA). Python 3.10 instead of 3.9 for Qwen/InternVL.
3. **One env instead of two:** a PYTHONPATH overlay was used for LLaVA, as described above.

**Claims about baselines** ("best on InternVL3, top-2 on the others versus DoLa/VCD/M3ID/CODE/SID"): NOT_COMPARABLE. The release contains no baseline implementations or configs, so none were run.

**Interpretation.**
- The baseline side reproduces well: 8 of 9 greedy numbers are within tolerance, and the one miss comes from the different image subset.
- The method side does not. Across 2 subsets × 3 models × 3 metrics (18 paired comparisons), ReVisiT improves on 7 and gets worse on 11.
  - The improvements are almost all small (0.2–0.6 points), except Qwen CHAIR_S −2.4 on the main subset.
  - LLaVA is reversed on both subsets.
- The paper's consistent 1–5 point gains are therefore not reproduced. Some ReVisiT values land within the loose 5%-relative tolerance only because the greedy baselines are close to the paper's, not because ReVisiT helps.

**Likely reasons (none confirmed):**
- The paper's 500-image subset cannot be recovered (listdir-dependent). Still, the paired differences on two separate subsets do not support the claimed gains.
- Library differences: torch 2.6 vs 2.0.1 for LLaVA, and cu124 vs cu118. The fp16/bf16 numerics in the JSD selection could be sensitive to these.
- The paper may have used α or layer settings other than the released script defaults. The paper only says α was "chosen per task type" on a validation split.

## Codebase completeness: MINOR_FIXES

- **No edits to released code** (`git diff` in `./codebase` is empty; only data, output, logs and caches are untracked).
- **Workarounds:**
  - **Broken shell wrappers:** `eval_chair_*.sh` run `cd eval; python eval/chair.py ...`, which points at `eval/eval/chair.py` (does not exist) and breaks the relative `./output` paths. I ran the same Python commands directly through my own wrappers `run_gen.sh` and `score.sh` in the attempt dir.
  - **Default sample counts:** `eval_chair_llava.sh` and `eval_chair_qwenvl.sh` default to `num_eval_samples=10`. I passed 500, as the paper states.
  - **Missing F1 scorer:** Table 3 F1 is not computed anywhere in the repo (chair.py only reports CHAIR_S, CHAIR_I and Recall). I wrote `score_chair.py` from the paper's Appendix D.1 formula.
  - **One env instead of two:** instead of the README's two conda envs, I used a single env plus a PYTHONPATH overlay (repo's bundled transformers 4.31 + tokenizers 0.13.3 + accelerate 0.21 in `pydeps_llava/`) for LLaVA.
  - **NLTK data** was downloaded into `./nltk_data` (NLTK_DATA), not `$HOME`.
- **Missing from the release:** code for HallusionBench, POPE, VQAv2 and MMMU (Tables 2, 4, 5) and for all baseline decoders (DoLa, VCD, M3ID, CODE, SID).
