## What the release contains
- The code only does TruthfulQA hallucination mitigation (408/409 split, `train_test_split(seed=0)`).
- It covers the **MoSE** stage only:
  - prototype experts from K-Means on normalised difference vectors;
  - a PCA residual basis;
  - an attentive gating network and β-MLP trained with MSE;
  - steering added at one layer during greedy generation.
- It also has a GPT-based judge script, which needs an OpenAI key.

**Not released:**
- the SCS gating (subspace energy ratio, τ, soft/logistic gate);
- the jailbreak-defense data and pipeline (Table 1);
- the XSTest/MATH/GSM8K utility evaluation (Table 3);
- the efficiency and ablation scripts (Tables 4–6);
- any baseline implementation;
- any BLEURT scorer.

The released steering is applied to every query. That makes it the paper's "w/o SCS" variant. Table 6 reports this variant as roughly equal to full FineSteer on TruthfulQA (54.77 vs 54.28 True %).

## What I ran
Environment: conda env (python 3.11, torch 2.5.1+cu124, transformers 4.46.3, datasets<4, scikit-learn), with `pip install -e codebase`. Everything ran on 1×H200.

```
# per model: one run per strength; the first run trains MoSE, later runs reuse the checkpoint
finesteer --model <HF id> --method MoSE --layer <L> --strength <S> --run-dir runs [--reuse-checkpoint]
#   meta-llama/Meta-Llama-3-8B-Instruct  L=12
#   Qwen/Qwen2.5-7B-Instruct             L=12
#   google/gemma-2-9b-it                 L=20      (layers from paper App. A.1)
#   S in {0 (= unsteered base model), 1.5, 2.0, 2.5 (code default), 3.0, 3.5}
python -I scripts/bleurt_eval.py runs/<model>/predictions/*.jsonl --out results/bleurt_<model>.json
```

- Wrapper: `scripts/run_model.sh`. Logs are in `logs/`, predictions in `runs/`, scores in `results/`.
- I also re-ran Llama-3-8B with `--max-new-tokens 256` (the TruthFlow protocol) as a sensitivity check (`runs_256tok/`).

**How BLEURT is scored** (`scripts/bleurt_eval.py`, written by me):
- Checkpoint: BLEURT-20 PyTorch port (`lucadiliello/BLEURT-20`).
- An answer counts as truthful if its max BLEURT against the correct references beats its max against the incorrect references (TruthfulQA convention).
- I report two variants:
  - **with** "I have no comment." added to the correct references (as in the original TruthfulQA eval);
  - **without** it.
- Neither the paper nor the code says which one is used. The "without" variant reproduces the paper's *unsteered* baselines for all three models within ≤1.23 points, so I treat it as primary. The other variant is shown too.

**Settings that differ from or go beyond the paper:**
- **No SCS gate.** It is not in the release.
- **λ = 2.5 for all models.** This is the code default. The paper picks λ from {1.5,…,3.5} but does not report the per-model value; the full sweep is below.
- **max_new_tokens = 64.** This is the code default; the TruthFlow protocol uses 256. At 256 tokens the Llama-3-8B FineSteer score is 67.24 vs 67.48, so the effect is negligible.
- **Precision is fp16.** This is hard-coded, including for Gemma-2. No NaNs were observed.
- **Llama-3.2-3B-Instruct (Table 8) was not run.** It is a gated Meta repo and this HF account is not authorised.

- There is no jailbreak, XSTest, GSM8K or MATH pipeline or data, and no ablation or efficiency scripts.

## Discrepancies
**Code vs paper:**
- **Major — SCS gate missing.** Eq. 15 / Alg. 3 is H ← H + λ·g·v with an SCS gate g. The code applies H ← H + λ·v to every query.
- **Major — judge script differs from the paper's evaluation.** `evaluate_openai.py` uses `gpt-5.6-luna` with one batched JSON request and a different prompt. The paper uses `gpt-4-1106-preview` with the per-question prompt in App. A.6.
- **Minor — layer off by one.** The query activation comes from `hidden_states[L]`, which is the output of block L−1. The steering hook is on `model.layers[L]`, which corresponds to `hidden_states[L+1]`.
- **Minor — K is pinned at the lower bound.** The paper picks K by the Calinski-Harabasz index. The code searches only K∈[4,10], on 256-dimensional PCA projections, and picked K=4 (the minimum) for all three models.
- **Minor — generation settings and model choice.** The code defaults to max_new_tokens=64 (the TruthFlow protocol is 256) and its README targets Llama-3.1-8B, while the paper uses Llama-3-8B for TruthfulQA. The 256-token rerun gave a negligible difference.
- **Minor — difference vectors.** Eq. 1 pools over the whole prompt (last token or mean). The code pools over response tokens only, and uses only `correct_answers[0]` and `incorrect_answers[0]`.

**Inside the paper:**
- **Soft gate defined three ways.**
  - Eq. 8: (F̂(s)/ε)^γ.
  - Eq. 9–10: a logistic gate trained on general queries, which App. A.1 calls the default.
  - Sec. 5.3 / Alg. 3: g = SER.
- **Model name inconsistent.** App. A.1/A.2 say "Llama-3.2-4B-Instruct" and "Llama-3-3B-Instruct"; Table 8 says Llama-3.2-3B-Instruct.
