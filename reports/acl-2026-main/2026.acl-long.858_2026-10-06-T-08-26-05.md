The release contains no code to train the proposed method. All I could test is the one released LoRA checkpoint, evaluated with the released scripts. In my runs:

## What I ran
The target is Table 2 (the main claim, which the abstract also states as +1.26 Naive / +3.95 CoT), for the two rows that can be run: **Original** and **θ\*** (the released checkpoint). That covers all 5 datasets at full size, with both prompting modes.

1. **Quantization.** Paper App. C.1 says every model, including the fine-tuned checkpoint, was evaluated under llama.cpp Q4. To match that:
   - Base model: Ollama registry `qwen2.5:7b-instruct` (Q4_K_M), registered as `qwen2.5-7b-instruct`, the scripts' default model name.
   - Checkpoint (θ): I merged the LoRA into fp16 (`scripts/merge_lora.py`), converted it with llama.cpp `convert_hf_to_gguf.py` (b11443) and quantized it to Q4_K_M with `llama-quantize`. It is served as `theta-q4`.
   - Server: Ollama 0.35.1, with temperature 0, `num_predict` 4096 (the script defaults), context 8192, and `num_thread 6`. The default of 112 threads on 14 allocated CPUs gave about 1 token/s.
2. **Running the scripts.** I ran the released scripts unmodified. Example:
   `cd codebase/main/Normal_Evaluation/NSA-LR && python nsalr-cot-ollama.py --model theta-q4 --dataset data/test.json --output_file results/theta/nsalr-cot.jsonl`
   - ProverQA = easy + medium + hard (`data/dev.json` is hard), 1500 items in total.
   - The slow CoT runs were sharded: I split the dataset files and ran the same script on each shard (`scripts/run_shards.sh`, `scripts/shard.py`).
   - Accuracy comes from `scripts/score.py` (prediction == actual).
3. **Repeat runs.** I ran everything **twice** (`results/{original,theta}` and `results/{original,theta}_r2`), because llama.cpp's parallel batching is not fully deterministic. The table reports the mean of the two runs. Run-to-run differences are 0–3 points per dataset and ≤0.4 on the averages.
4. **Supplementary bf16 run.** I served the bf16 base + LoRA with vLLM 0.31 (the README's serving path). A small `ollama` → vLLM shim (`shim/`) lets the unmodified scripts call it. Results are in `results/bf16_*`.

Settings that differ from the paper:
