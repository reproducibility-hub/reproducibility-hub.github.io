  - Qwen3-VL-2B and InternVL3.5 on OmniDocBench were not run (time).
  - Baselines VCD/TVC (Table 4) and the closed-model/Shuffle analysis (Table 2) are not in the release and were not run.

- **Main claim** (abstract, Sec. 4, Table 3): PAR (Positional Perturbation + Foveal Attention Recycling, training-free) reduces Linguistic-Priors hallucination on the GlitchText probing dataset for DeepSeek-OCR, Qwen3-VL-8B and InternVL3.5-8B. In the Chinese subset CER, Iden and Cor all improve, and CER drops "consistently across all models and languages".
- **Secondary claims**: Table 5 ablations (removing FAR or PP hurts), and Table 6 (PAR yields "consistent improvements in Overall" on OmniDocBench).
- **Release**: <https://github.com/Zoeyyao27/PAR-for-Faithful-OCR> (linked in the paper). It contains the PAR attention implementations for DeepSeek-OCR, Qwen3-VL and InternVL3.5, the GlitchText evaluation script (`ocr_eval_main.py`), an OmniDocBench inference script (`eval_omini.py`), YAML configs per model and task, and a Google-Drive link to the GlitchText data (zh `top_n_20`, en `top_n_20`, en `top_n_20_baseline_padding_200`).

- Conda env (one env, `python=3.12`): `torch==2.6.0`, `torchvision==0.21.0`, `vllm==0.8.5` (only imported, never used), `transformers==4.57.1`, `flash-attn==2.7.3` (prebuilt wheel), `qwen-vl-utils==0.0.14`, `timm` (needed by the InternVL code but missing from the requirements), plus `requirements.txt` (rapidfuzz, accelerate, evaluate, …).
  - The README asks for **two** envs because DeepSeek-OCR needs `transformers==4.46.3`/`tokenizers==0.20.3` while Qwen3-VL needs ≥4.57. Only one conda env was allowed, so I installed 4.46.3 with `pip install --no-deps --target pylib_tf446` and put it on `PYTHONPATH` for the DeepSeek runs only.
- Models (HF): `deepseek-ai/DeepSeek-OCR` (rev 9f30c71), `Qwen/Qwen3-VL-8B-Instruct` (rev 0c351dd), `OpenGVLab/InternVL3_5-8B` (rev 9bb6a56).
- GlitchText data: the authors' Google Drive folder. `gdown` was rate-limited, so I fetched the same file IDs via `drive.usercontent.google.com` (`scripts/list_drive.py`, `scripts/dl_drive.py`).
- GlitchText runs: `scripts/run_queue.sh {dpsk,qwen8b,intern}`. These are the README commands verbatim, plus `--dataset_dir ../data --cache_dir $HF_HOME/hub --overwrite`. For example:
  - `python ocr_eval_main.py --run_baseline` / `--smart_config_path configs/dpsk/ocr.yaml` (zh, 500)
  - `... --max_samples 200 --lang en --dataset_type top_n_20_baseline_padding_200` (en)
  - Qwen: `--model_path Qwen/Qwen3-VL-8B-Instruct --prompt "Read all the text in the image." [--smart_config_path configs/qwen8b/ocr.yaml]`
  - InternVL: `--model_path OpenGVLab/InternVL3_5-8B --prompt "Read all the text in the image."`, with `configs/internvl/ocr.yaml` (zh) and `configs/internvl/ocr_pad.yaml` (en), as in the README
  - Seed: 42 (hard-coded in `ocr_eval_main.py`). Extra seeds go through `scripts/run_seed.py`, which only overrides the seed.
- Ablations: `scripts/run_ablation.sh` with `configs_extra/dpsk_ocr_noFAR.yaml` / `dpsk_ocr_noPP.yaml`. These are copies of `configs/dpsk/ocr.yaml` with one `enabled: false`.
- OmniDocBench: images and GT from HF `opendatalab/OmniDocBench` at revision `91fe284bbf` (v1.5, 1355 pages, the version current at paper submission). Official evaluator from GitHub `opendatalab/OmniDocBench` at commit `0f22218` (Jan 2026, pre-v1.6), `configs/end2end.yaml`.
  - Inference uses the README command `python eval_omini.py [--run_baseline] --image_dir ... [--smart_config configs/dpsk/omni.yaml]` (`scripts/run_omni.sh`). For Qwen it adds `--model_path Qwen/Qwen3-VL-8B-Instruct --prompt "Convert the document to markdown. "` and `configs/qwen8b/omni.yaml`.
  - `scripts/omni_runner.py` reuses the released `eval_omini.worker_func` unchanged but allows a custom image list and worker count. I needed it because `eval_omini.py` hard-codes 4 workers per GPU, which doesn't fit next to other jobs on one GPU.
  - Table-6 columns are computed by `scripts/omni_eval.py` exactly as the evaluator's `tools/generate_result_tables.ipynb` does: TextEdit = text_block page-avg edit, TEDS = page TEDS ×100, Overall = ((1−TextEdit)·100 + CDM + TEDS)/3. CDM is not computed, i.e. 0. The paper's Overall values are consistent with CDM = 0 too (e.g. DeepSeek Ori: (61.88 + 83.66 + 0)/3 = 48.51).

## 4. Verdict details

- **Result match after fixes = MIXED.**
  - Holds: the main GlitchText claim (PAR reduces CER for every model/language; on Chinese it raises Iden and lowers Cor), the Table 5 ablation ordering, and DeepSeek-OCR OmniDocBench.
  - Doesn't hold: the PAR gain on OmniDocBench for Qwen3-VL-8B reverses, and DeepSeek-OCR English's Iden gain doesn't hold on average over seeds. Several Qwen3-VL-8B baselines are stronger than reported.
- **Result match as released = MIXED.**
  - The same numbers come out of the unmodified code for every PAR run and for the Qwen/InternVL baselines.
  - The DeepSeek-OCR baselines (`--run_baseline`) crash as released: `models/` package missing, plus an `UnboundLocalError` in `eval_omini.py`. Those rows are `DOES_NOT_RUN` as released; the reported DeepSeek PAR numbers still come out of the unmodified code.
- **Coverage = SUBSET.**
  - Table 3 fully, at paper scale.
  - Table 5: 3 of 7 rows (the others have no code).
  - Table 6: 2 of 4 models at full scale.
  - Not run: Tables 2, 4, 8 and Fig. 5.
- Missing baselines: VCD and TVC (Table 4) have no code or config in the release, so the claim "PAR outperforms VCD/TVC" is **NOT_COMPARABLE** (not run). Closed models (GPT-4o, Claude) appear only in the Table-2 analysis, not in PAR claims.

## 5. Codebase completeness: **MINOR_FIXES**

Changes to the released code (left uncommitted in `./codebase`, see `git -C codebase status/diff`):
1. **`codebase/models/` added** (5 files copied verbatim from the HF `deepseek-ai/DeepSeek-OCR` snapshot 9f30c71). `eval_utils/wrappers.py` imports the DeepSeek baseline from `models.modeling_deepseekocr`, but the repo has no `models/` package, so every DeepSeek-OCR baseline (`--run_baseline`) crashes with ModuleNotFoundError. These are the stock DeepSeek-OCR files; the PAR copies in `models_w_attn/modeling_dpsk` only add the attention hook and two HF-compat edits.
2. **`eval_utils/wrappers.py`, `DeepSeekOCRWrapper.load_model`**: `if self.smart_config:` → `if self.smart_config and not self.if_baseline:`. `eval_omini.py` always passes a smart config, so the baseline OmniDocBench run crashed with `UnboundLocalError: SmartLlamaFlashAttention2` (the class is only imported in the non-baseline branch). This doesn't affect results.
3. `codebase/cache` symlink → `$HF_HOME/hub`. `eval_omini.py` hard-codes `cache_dir="cache"`; this avoids re-downloading models.

Environment-level issues: two incompatible `transformers` versions (solved with a `--target` side install), `timm` missing from requirements, and `vllm`/`qwen_vl_utils`/`dotenv` imported at module top even though vllm is unused.

Scripts I wrote (outside `codebase/`; all are runners, loops, aggregators or data fetchers):
- `scripts/run_queue.sh`, `run_ablation.sh`, `run_seeds_dpsk.sh`, `run_seed.py`
- `run_omni*.sh`, `omni_runner.py`, `fill_one_by_one.sh`
- `aggregate_glitch.py`, `aggregate_extra.py`, `omni_eval.py`, `build_comparisons.py`, `build_status.py`
- `list_drive.py`, `dl_drive.py`, `debug_qwen*.py`

OmniDocBench is only scored by the external official evaluator, which the README says to run separately. In my copy of that third-party evaluator I made one edit (`omnidocbench_eval/utils/match.py`: `item['latex']` → `item.get('latex','')` for GT tables). v1.5 GT tables have no `latex` field, so the evaluator crashed whenever Qwen emitted a LaTeX table. ## 7. Other notes / problems encountered

- A transient `Disk quota exceeded` on /scratch (shared filesystem; no per-user quota was set) killed 2 of the 4 DeepSeek-OCR OmniDocBench baseline workers mid-run. The 2 zero-byte outputs were deleted and the missing pages were regenerated with identical settings.
- To fit everything in the time budget I ran several jobs concurrently on the single GPU. Only throughput changed: all decoding is greedy, and PAR randomness is seeded in `ocr_eval_main.py`.
  - One caveat: `eval_omini.py` uses spawned worker processes, which do **not** inherit the `set_seed(42)` of the parent. So PAR's phase noise in the OmniDocBench runs is unseeded in the released code; as-is behaviour.
- I cancelled the DeepSeek-OCR **zh** extra-seed runs to free GPU time; only the **en** extra seeds were run.
- The conda env was removed at the end (`conda env remove -p .../env`). The small side install `pylib_tf446/` (transformers 4.46.3) and all logs and predictions (`data/*/*_eval_results`, `omni_preds/`, `logs/`) are kept.
- GlitchText `top_n_20_baseline_padding_200` has 986 entries; the README/paper use the first 200 (`--max_samples 200`), which is what I did.
