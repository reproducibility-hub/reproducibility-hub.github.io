## Summary
The paper's main artifact is the set of "FRED" difficulty metrics (F, R, E, D). They are computed for about 60 language pairs (Table 2 and appendix Tables 6–12) and compared with high-resource "reference" pairs.

- **R, D and E reproduce essentially exactly** for every released low-resource pair:
  - 390 of 392 low-resource D/R numbers match. These cover BLEU, chrF and chrF++, both translation directions, and Formosan, Americas, African, Indic and ancient languages.
  - All 70 low-resource E-scores match. This is despite my rebuilding the 31 GB NLLB public-bitext infini-gram index from the public download script.
  - The Table 2 group averages match (e.g. Formosan D/R-BLEU 5.27/13.81; Americas 1.83/4.72 and chrF++ 11.19/15.05; African 1.43/5.21; E averages 0.006 / 1.17).
  - The two D/R mismatches are explained by paper typos or data-size choices (see Discrepancies).
- **Token fertility (F) does not support the paper's fertility claim.** The released `sentence_length.py` reproduces Ntoken, Nchar and F for most pairs. It does not give the values behind "Formosan and ancient languages show fertility approaching 1.0":
  - **Akkadian:** F = 0.06 on the source side (0.30 on the larger side) vs 1.00. Cuneiform becomes `<unk>`, which the util excludes.
  - **Egyptian:** F = 0.64 vs 1.00. Ntoken matches (23.96 vs 24.0), but Nchar is 37.3, not 24.0.
  - **Formosan:** F = 0.74 (larger side; average 0.76) vs 0.91/0.92. The paper's Mandarin-side Ntoken of 10.6 equals our count *including* the two special tokens (10.63); every other row excludes them.
- **Table 3 regression is not reproducible.** No code is released and Appendix A is underspecified. My best-effort single-feature R² gives R² = 0.09 for the R-score pooled over 54 pairs, and 0.29 on the Table 2 rows only. The paper reports 0.58, and the feature ranking differs.
- **Not run:**
  - PBSMT columns / Fig. 3: these need Moseskit in Docker, and no Docker/Apptainer is available.
  - mBART high-resource fine-tuning (Table 5 / Fig. 1): no code is released for it.
- **High-resource reference rows (ja/hi/fi/zh/ar) are NOT_COMPARABLE.** The authors' 10k training-subset id lists (`data_process/...`) are not released, so I used the first 10k training lines.
  - Test sets match for hi/fi/ar: their E-scores agree (85.35/85.50/108.41 vs 85.98/85.46/108.57).
  - D/R differ moderately. The group averages are still close: D-BLEU 1.30 vs 1.37, R-BLEU 3.39 vs 3.24.

Overall, the paper's claims about R (high R explains high ancient-language scores; Zulu's R exceeds its best neural model; Wayuu's R-chrF++ is 23.89 vs model 12.58) and about E (Americas 0.24–0.65 vs high-resource ~86–114) are reproduced. The fertility claim and the Table 3 R² are not → **MIXED**.

## What I ran
Environment: one conda env (`env/`, Python 3.12) with the README pins: sacrebleu 2.4.3, nltk 3.9.1, tqdm 4.66.5, infini-gram 2.6.0, transformers 4.57.3, numpy 2.3.5, protobuf 6.33.2, sentencepiece 0.2.1. I also installed `sacrebleu[ja]` (ja-mecab), datasets, scipy, gsutil, translate-toolkit and openpyxl. The README asks for Python 3.9 for quality_check and 3.12 for infinigram; a single 3.12 env worked for both.

1. **D and R scores** — released `quality_check/src/calculate_{D,R}_score.py`.
   - Run unmodified on tao (BLEU), ctp and nya (BLEU, chrF, chrF++): `results/released/`, `scripts/run_released_checks.sh`.
   - The released scripts make an O(N_train × N_test) pure-Python `sacrebleu.sentence_*` call per pair, about 0.2–0.4 ms each. Covering all pairs, both sides and 3 metrics would cost about 2.4M CPU-seconds, which is more than 48 h on the 14 cores available.
   - I therefore wrote `scripts/fred_fast.py`, an exact vectorized re-implementation. It uses sacrebleu's own n-gram extraction and a sparse-matrix min-count intersection, transcribes `BLEU.compute_bleu` / `CHRF._compute_f_score` exactly, and re-scores near-ties with sacrebleu itself to keep the released "first strict max" tie-breaking.
   - Validated identical to the released scripts per test sentence (max abs diff ≤ 4e-14, identical retrieved neighbours) on tao, ctp and nya × {D, R} × {BLEU, chrF, chrF++}, and also against direct sacrebleu calls (`scripts/validate_pairs.py`, `scripts/validate_vs_released.py`).
   - Full run: `python scripts/run_DR.py 11` (all 55 low-resource pairs + 5 high-resource pairs) → `results/DR/*.json`.
   - Settings follow the paper's Appendix E.2: 13a everywhere, `zh` for Mandarin, `char` for Akkadian cuneiform, `ja-mecab` for Japanese, sentence-level BLEU with exp smoothing.
   - D was computed on both sides. **The paper's numbers correspond to D on the source side** (as in the README's `--lang fi` example), not the target side of Eq. 3.
2. **F (Ntoken, Nchar)** — released `quality_check/utils/sentence_length.py` (`-t token` and `-t string`) on each test file, both sides (`scripts/run_F.py`). F = mean Ntoken / mean Nchar.
3. **E-score**
   - Ran the fairseq NLLB `download_parallel_corpora.py` (as the infinigram README says) → 26 GB.
     - XhosaNavy and Bianet failed because of dead OPUS URLs.
     - I skipped Mburisano_Covid, which requires accepting SADiLaR terms of use.
   - Wrapped each line as `{"text": ...}` → 288M lines, 31 GB, split into 29 files because the indexer loads each file into RAM.
   - Indexed with infini-gram using the repo's `infinigram/indexing.py` (mBART-50 tokenizer, u32). I copied it over the site-packages one, as the README instructs. Took about 7.5 h on ~12 cores; index 57 GB.
   - Ran the released `infinigram/calculate_E_score.py -n 4` on each test set, both sides (`scripts/run_E.py`).
4. **High-resource reference pairs** — data from HF:
   - `wmt/wmt18` fi-en and zh-en (test: newstest2018);

   - `cfilt/iitb-english-hindi`.
   - Training was capped to the first 10k sentences because the authors' selection is unreleased.
5. **Regression (Table 3)** — `scripts/regression.py`: a best-effort single-feature R², because no code is released.
6. `scripts/compare.py` and `scripts/make_tables.py` build the comparison (`results/comparison.json`, `results/comparison_table.md`).

Settings that differ from the paper:
- High-resource training subsets are the first 10k lines (unreleased selection); ja/zh test sets also differ (Ntoken/Nchar don't match).
- For the 5 MAFAND languages with no train split in the release (amh, kin, nya, sna, xho), I used dev as training data. The paper's N-train equals the dev sizes, and all their D/R values then match.
- NLLB bitext is missing XhosaNavy, Bianet-ku and Mburisano (tiny); the E-scores match anyway.

## Discrepancies
Code vs paper:
1. **F / token count** (major, affects results): `quality_check/utils/sentence_length.py` excludes special tokens *and `<unk>`* from Ntoken.
   - The paper's Mandarin-side Ntoken (zh→tao 10.6; Table 2 Formosan F 0.91/0.92) equals the count *including* the 2 special tokens (ours 8.63 + 2 = 10.63). The other rows (e.g. tao 11.0, kha/en 31.3) exclude them.
   - Akkadian Ntoken = Nchar = 24.6 and Egyptian Nchar = 24.0 (F = 1.00) can't be produced by the released util: it gives akk Ntoken 1.45 (cuneiform → `<unk>`, excluded; 2.78 if `<unk>` is counted) and egy Nchar 37.26.
   - The paper's fertility claim for Formosan/ancient languages depends on these values.
2. **High-resource training cap** (minor): `data/README.md` describes the 1k/10k/100k/1M caps as counts of English tokens (e.g. "10k": 2241 sentences), while the paper says 10k sentences. The selected-id lists are not released.
3. **D-score side** (minor): Eq. 3 defines D over target sentences y_i, y_j. The released script takes `--lang` and the README example passes the source language. All paper D values match the source side (e.g. tao D-BLEU 5.34 on the tao side vs 3.41 on the Mandarin side).

Paper-internal:
1. Table 6 tao→zh D-chrF 31.06 vs Table 9 13.06 (ours 13.06).
2. Table 6 forward Americas rows: shp 3.98/5.42, hch 3.18/3.91, quy 2.60/4.66 (D/R-BLEU) vs Tables 2/10: 3.83/4.86, 3.05/3.41, 1.27/3.85. Ours match Tables 2/10.
3. Zulu R-BLEU: 32.85 in Table 2, Table 6 and the main text vs 34.85 in Table 11 (ours 34.85).
4. Table 11 kin R-chrF++ = 19.19, identical to R-chrF 19.19 (ours 16.67; looks like a copy error).
5. Table 6 guc Nchar 35.9 equals Ntoken. F = 0.40 implies Nchar ≈ 90 (ours 89.9).
6. Egyptian "10k" training: R-BLEU matches the first 10k lines of the released train file (23.42), while R-chrF/chrF++ (41.95/41.34) match the full 12,044-line file.
7. Table 11 lists hau N-train 3098, but the released `en-hau/train.json` has 5865 lines. All hau D/R values match the released file.
8. Footnote 2 says Nchar for non-Latin languages is `len(str.split())`, but the reported Nchar values (ja 56.3, Mandarin 11.7) are character counts (`len(str)`).
9. Table 6 forward Americas rows report chrF++ in the D/R columns (e.g. shp D 8.69), while the reverse rows report chrF (es→quy D 13.68 = our D-chrF). The caption mentions chrF++ only for the Model column.
10. Table 3's R² values (R = 0.58, Ntrain = 0.001) are not consistent with simple single-feature fits on the paper's own Table 2 values (R 0.29, Ntrain 0.17).
