### Summary of findings
1. **Training and generation run with the released code.** With one re-implemented dataset builder, the pipeline runs end to end: training, stage-1 preference prediction, vLLM generation, ArmoRM scoring and the win-rate script. It produces 178 optimizer steps, matching the authors' `checkpoint-178`.
2. **Absolute numbers mostly don't reproduce.** 2 of 12 Table-1 HelpSteer2 numbers are within tolerance, and 7 of 60 Table-2 cells.
   - SGA_DPO is *higher* than reported on 4 of 6 models (average 60.0 vs 55.6).
   - SGA_SFT is *lower* on 5 of 6 models (average 46.4 vs 55.9).
3. **Table 5 (adaptive sensing vs. external steering) doesn't reproduce.**
   - The paper's 3.5–5-point advantage of SGA over fixed or ground-truth steering shrinks to at most about 1 point. That is within the sampling-seed noise we measured (0.6–1.6 points).
   - SGA loses to fixed-0.5 on Llama3.2-3B and to fixed-1.0 on Qwen3-4B.
   - The "higher fixed score → higher win rate" trend holds for Qwen3-4B (38.5 → 40.0 → 42.8) but not for Llama3.2-3B (49.6 / 51.1 / 49.7).
   - SGA does beat ground-truth steering and most fixed values, but only by tiny margins. This partial, direction-only agreement is why the overall result is MIXED rather than NO_MATCH.
4. **The regression head does almost no "adaptive sensing".**
   - In all 12 checkpoints the predicted preference vector is nearly constant (per-dimension std ≤ 0.05).
   - After the released code rounds scores to {0, .25, .5, .75, 1}, 73–96% of prompts get the same steering vector (1, 1, 1, 0.5, 0.5).
   - About 72% of |s − ŝ| errors are below 0.2. This matches the paper's Fig. 4 observation, but it comes from predicting the label mean, not from prompt-specific preferences.
5. **The main baseline comparisons can't be checked.** No code or configs for RiC, CPO, Vanilla SFT or MODPO are released, so "SGA outperforms SOTA baselines" is NOT_COMPARABLE.
6. **Context run (not in the paper).** The *untouched* instruct models, run through the identical pipeline with no score suffix and scored on the same prompt as the references, average a 68.0 macro win rate. That is above SGA_DPO (60.0) on 5 of 6 models and above SGA_SFT (46.4) on all 6. In this pipeline, SGA training does not improve over the base instruct model.

## What was run

**Paper target:** Table 1 and Table 2 (HelpSteer2 block) and Table 5 (HelpSteer2 column).
- Win rate = fraction of test prompts where the ArmoRM-Llama3-8B-v0.1 objective score of the generated response is greater than that of the reference response, per HelpSteer2 objective, macro-averaged over the 5 objectives.
- Test set: HelpSteer2 `validation` split, 1038 rows; the response in each row is the reference (paper Table 7: test size 1k).

**Pipeline** (all GPU work on 1× H200, serial; driver scripts in `scripts_repro/`):
1. **Training:** `codebase/sga/run_sga_train.py` (unmodified) on `nvidia/HelpSteer2`.
   - Settings: `--training_mode dpo_mse --dpo_weight 1 --mse_weight 1000 --beta 0.1 --use_lora True --lora_r 32 --lora_alpha 64 --lora_dropout 0.05 --learning_rate 1e-5 --num_train_epochs 2 --max_length 1024 --save_strategy epoch`, with gradient checkpointing as in the released scripts.
   - Effective batch 96 (`--per_device_train_batch_size 4 --gradient_accumulation_steps 24`), matching the released 6-GPU scripts.
   - SGA_SFT adds `--sft_only True --no_logsigmoid_sft True --reference_free True`.
   - Script: `scripts_repro/train_queue.sh`.
2. **Stage 1:** `codebase/sga/infer/infer_preference.py` (unmodified; imports the re-implemented `build_helpsteer2_dataset`) with `--dataset_type helpsteer2 --dataset_split validation --batch_size 1 --max_length 1500 --layer_type mlp --num_neurons 1024 --num_layers 3`.
3. **Stage 2:** `codebase/sga/infer/vllm_sga.py` (unmodified) with `--temperature 0.6 --top_p 0.9 --max_tokens 1024 --seed 3407 --max_lora_rank 128`, env `VLLM_USE_V1=0`.
4. **Scoring:** `codebase/sga/eval/test3.py` (ArmoRM, unmodified), called through the wrapper `scripts_repro/score_armorm.py`, which also scores the reference responses.
5. **Win rates:** `codebase/sga/eval/compare_scores3.py` (unmodified). 1036 matched samples, because the script drops 2 duplicate reference texts.

`scripts_repro/eval_one.sh` chains steps 2–5. `scripts_repro/master.sh` orchestrates the full run. Table 5 variants rewrite the stage-1 JSON (`scripts_repro/make_variant.py`); the released discretization step then maps fixed 0.2 to 0.25.

**Results files:** `results_hs2.csv` (all runs), `comparisons_raw.json`, `results_regression_head.txt`, plus per-run outputs in `eval/<tag>/` and logs in `logs/`.

**Settings that differ from the paper:**
- **Hardware and batch:** 1× H200 instead of 4× L40. Effective batch 96, from the released scripts, instead of the paper's 2×8×4 = 64.
- **Llama-3.2 weights:** meta-llama/Llama-3.2-1B/3B-Instruct are gated for our token, so we used the unsloth mirrors. Their safetensors SHA256 matches Meta's, and we edited the tokenizer config back to Meta's (no pad token).
- **Environment:** a single env (torch 2.6, vLLM 0.8.5.post1, transformers 4.51.3, peft 0.10.0, trl 0.8.0, accelerate 0.34.0, flash-attn 2.7.4) instead of torch 2.2 plus a separate vLLM env.
- **Stage-1 batch size:** 1 instead of the released 2 (see Discrepancies).
- **SGA_SFT loss:** the paper's exact SGA_SFT flags are unknown; we used summed CE plus 1000·MSE.
- **Checkpoint choice:** we report the final checkpoint (epoch 2, `checkpoint-178`). The released inference scripts evaluate both epochs and, for Qwen3-4B and Qwen3-8B, also λ=10 runs, so the paper's numbers may come from a test-set-selected checkpoint. Epoch-1 numbers for DPO are shown too.

## Discrepancies
1. *(code_vs_paper, minor, affects results)* **Batch size.** Paper Table 6 / App. B.2 says batch 2 × grad-accum 8 on 4 GPUs. The released scripts use 6 GPUs, giving an effective batch of 96.
2. *(code_vs_paper, minor, affects results)* **Score discretization.** `vllm_sga.py` rounds the predicted ŝ to {0, .25, .5, .75, 1} before injecting it; the paper describes injecting the continuous ŝ. This also turns the paper's fixed 0.2 into 0.25, and the format `<x_score: 1.00>` differs from the training format `<x_score:1.0>`.
3. *(code_vs_paper, minor, affects results)* **SGA_SFT loss.** The paper uses L_CE + λL_MSE. No SGA_SFT config is released, and the `sft_only` default loss is −logsigmoid(β·Σ log p); plain CE needs `--no_logsigmoid_sft`.
4. *(code_vs_paper, minor, affects results)* **Stage-1 padding bug.** Stage 1 left-pads batches but reads the value head at `attention_mask.sum()-1`, which is wrong for padded rows with the released `BATCH_SIZE=2`. Measured effect: 8 of 1038 steering vectors change for Llama3.2-1B. We used batch size 1.
5. *(code_vs_paper, minor, affects results)* **Prompt cleaning before ArmoRM.** `test3.py`'s cleaning regex misses the angle-bracket score format, so ArmoRM sees "…the following scores: and and and and" in the prompt. This is identical for model and reference responses.

No paper-internal inconsistencies were found: Table 5's SGA_SFT numbers equal the corresponding Table 1 entries, and the Table 1 averages are consistent.
