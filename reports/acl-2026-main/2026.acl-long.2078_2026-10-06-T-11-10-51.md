## 1. What the paper claims and what was targeted
Most of the paper's results are **heatmap figures** of the ODDS score. The only numeric table is Table 2 (HANS). I reproduced:

1. **Fig. 1 / App. D.1–D.2** (central claim): activation patching (AP) on Pythia-1B (step 143k) for the residual stream, attention output, MLP output (all tokens) and attention heads (last token). Covers all 7 FGD constructions, 8 NPI constructions and the control. Claims tested:
   - FGD uses a shared, localized mechanism: heads 7.5, 7.6 and 9.2, with the residual-stream score at the verb jumping around layer 7.
   - NPI has no unified mechanism.
   - The control pattern looks different.
2. **Fig. 2 / App. D.3**: training checkpoints 1k, 2k, 3k, 4k, 10k and 143k, filler-gap only. Residual stream and heads for all 7 constructions. Claim: EWhK converges by step 4k, while PCleft is still below its final level at 10k.
3. **Fig. 3 / App. D.4**: Pythia-2.8B/6.9B and Gemma-3-12B, on EWhK and PCleft only (the constructions in Fig. 3).
4. **Fig. 4**: BLiMP steering (heads 7.5/7.6/9.2 scaled by α ∈ {0.8, 1.0, 1.2, 1.5, 2.0}), all 67 patterns in the released category list.
5. **Fig. 19 / App. E**: SyntaxGym steering.
6. **Table 2 / App. F**: HANS steering with Gemma-3-1B-IT, all 30k evaluation examples, α ∈ {0.8, 1.0, 1.2, 1.5}.
7. **Fig. 5 / App. D.5**: DAS vs AP, leave-one-out, lr 5e-3, 100 steps, batch 4:
   - residual stream: all 7 FGD constructions;
   - heads and attention output: EWhK, the construction shown in Fig. 5;
   - attention output also on PCleft and MatrixQ;
   - MLP: EWhK.

## 2. Commands
All runs go through thin wrappers around the released entry points. The env is Python 3.11 with the pinned deps from `pyproject.toml` (torch 2.9.0, transformers 4.56.0, pyvene 0.1.6, nnsight resolved to 0.7.0) plus `statsmodels`, which `blimp.py` needs but `pyproject.toml` omits. wandb ran in offline mode.
- `run_ap.sh NAME pythia 1b STEP 16 --categories {filler_gap|npi|control} --proj_method {vanilla|das} --interv_component ... [--only_last_token] [--src_base_pattern label2]` calls `codebase/main.py ... --do_leave_one_out --batch_size 10`, exactly as in the README.
- `run_ap_subset.sh`: the same, but `analysis/main_subset.py` restricts `filler_gap` to EWhK and PCleft. Used for the 2.8B, 6.9B and Gemma-12B runs.
- `run_das_subset.sh`: the same, but `analysis/main_eval_subset.py` only evaluates the listed held-out constructions. LOO training data is unchanged. Used for DAS heads, attn and mlp.
- `run_blimp.sh` / `run_blimp2.sh`: `codebase/blimp.py --steer_heads 7.5 7.6 9.2 --steer_strengths 0.8 1.0 1.2 1.5 2.0 --categories all`, split across two processes.
- `run_sg.sh`: `codebase/syntaxgym.py`. `run_hans.sh`: `codebase/nli.py --steer_strength α`.
- Analysis: `analysis/summarize.py`, `steps.py`, `das_attn.py`, `parse_steer.py` and `plot_maps.py`. Figures are in `figures/`, summaries in `analysis/out/`, raw outputs in `runs/out/*/…jsonl` and `runs/results/`, logs in `logs/`.

**Settings that differ from the paper:**
- The model-size and Gemma comparisons used only EWhK and PCleft, the two constructions shown in Fig. 3; the appendix has all 7.
- Gemma-3-1B AP was not run: the released code's `model.model.language_model` path does not exist for the text-only 1B model.
- DAS heads, attn and mlp were evaluated only on EWhK, plus PCleft and MatrixQ for attn.
- DAS `label-ood` runs were not done.
- Training-step sweep: attn and mlp outputs were not run; only residual stream and heads.
- No other hyperparameter changes. The NPI runs use `--src_base_pattern label2`, as the README says.

## 4. Why not fully reproduced
- **Bug that changes a reported conclusion.** In `subspace/das/das.py::batch_subspace_swap`, any component other than `attn-head` falls into the `else` branch. So the DAS rotation for `--interv_component attn` (and `mlp`) is *trained* by overwriting the **residual stream** output of the layer. At test time (`intervene.py`) the learned direction is patched into the **attention (MLP) output**. The direction is therefore trained for a different representation space than it is evaluated in.
  - Running the released code reproduces the paper's Fig. 5b: DAS-attn below AP, especially in early–mid layers.
  - Training on the attention output instead makes DAS-attn **exceed** AP on ID in all three constructions tested. It still drops on OOD, so the overfitting message survives.
  - The specific claim "DAS on attention output yields lower scores than AP even in the ID test set … changes the interpretation of the mechanism" (Sec. 6.2) is therefore an artifact of this bug.
- **Scale-downs (compute/time):** described in §2.
- **Not reproduced:** the head-level training-speed sub-claim in Sec. 4.4 ("improvement … quicker in attention heads").

## 5. Codebase completeness: MAJOR_FIXES
Edits to `codebase/` are left uncommitted; the diff is in `analysis/codebase_changes.diff`. A pristine copy in `codebase_released/` was used for the as-released DAS runs.
1. `subspace/das/das.py`: added `attn` and `mlp` branches to `batch_subspace_swap` so DAS trains on the component it is evaluated on. **Changes results** (Fig. 5b).
2. `activation.py::get_token_indices`: `--only_last_token` with `--categories control` raised `ValueError` (control missing); now maps to `"verb"`. Minor crash fix.

4. `models/pythia.py`: Gemma-3 (pt) is loaded with `nnsight.VisionLanguageModel`. nnsight 0.7.0, which satisfies the pinned `nnsight>=0.5.10`, refuses multimodal Gemma-3 in `LanguageModel`. Library-version fix.
5. Data / environment:
   - SyntaxGym JSONs: `[`/`]` → `(`/`)`, and `-` → `_` in condition names. Otherwise `cleft` precedence is wrong and the garden-path suites crash on `Unknown variable`. The README warns about this.
   - HANS: the README's `heuristics_test_set.txt` is actually `heuristics_evaluation_set.txt`.
   - Added `statsmodels` to the env.
6. Scripts I wrote outside the repo:
   - run wrappers;
   - `main_subset.py` / `main_eval_subset.py` (restrict constructions);
   - analysis and plot scripts. The repo's `plot.py` only logs images to wandb and no numeric table is produced, so the heatmap numbers were extracted from the jsonl outputs.

## 6. Discrepancies
- **code_vs_paper (major):** `das.py::batch_subspace_swap`. The paper (Sec. 6.1) learns a DAS direction in the attention or MLP output, f_interv(b,s) = f(b) + (f(s)a − f(b)a)aᵀ applied to the component f. The code trains it by intervening on the residual-stream output for `attn`/`mlp`, then evaluates it on the attention/MLP output. This affects Fig. 5b, Fig. 15–16 and the Sec. 6.2 conclusion.
- **code_vs_paper (minor):** the README and Fig. 4 disagree on steering strengths. The README uses α ∈ {0.8, 1.0, 1.2, 1.5}; the Fig. 4 legend uses {0.8, 1.0, 1.5, 2.0}; `blimp.py`'s flag is `--steer_strengths`, not the README's `--steer_strength`. No effect on results; I ran the union.
- **code_vs_paper (minor):** `models/pythia.py` loads `EleutherAI/pythia-{size}` (non-deduped) but caches into a `…-deduped` directory, and the non-nnsight `load_model` uses the deduped model. The paper only says "Pythia". Unclear which was intended; the analysis path uses non-deduped.
- **paper_internal:** Sec. 4.4 says head scores improved "quicker" than the residual stream. With the released code, heads at 4k reach only 44–57% of their final value, while EWhK resid reaches 100%. This may be a figure-reading issue rather than a true inconsistency, so it is recorded as a result mismatch, not a paper_internal entry.
