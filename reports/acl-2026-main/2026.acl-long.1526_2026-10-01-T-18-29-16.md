# Reproduction report — Neuron-Aware Active Few-Shot Learning for LLMs (2026.acl-long.1526)

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): MIXED.** Our Random baseline lands close to the paper's numbers on most rows, so the setup is broadly comparable. NeuFS's claimed advantage, though, mostly disappears:
  - **TREC:** NeuFS beats the paper's seed-42 Random on 4/4 models, but by only +0.3 to +1.4 acc points (paper: +1.8 to +5.9). That gain is inside the spread across Random selection seeds.
  - **MMLU-Pro:** NeuFS ≈ Random on Qwen3-4B, Qwen3-8B and Llama-3.2-3B. On Llama-3.1-8B NeuFS is worse (−1.8 pt).
  - **Edu-Feedback:** NeuFS is *worse* than Random on 3/4 models (−5 to −8 acc points). The paper reports +3.6 to +8.6.
  - The ablations also don't show the paper's patterns (details below).
- **Result match as released: DOES_NOT_RUN.** The release has no evaluation pipeline, no data or prompts for MMLU-Pro/TREC, and no baselines. Its collator also crashes under transformers ≥ 5, which vLLM requires.
- **Coverage: SUBSET.** We ran all 4 models × 3 datasets × {5, 10, 20, 30} shots × 3 inference seeds at the paper's scale, plus the Fig. 3/4 ablations. Only NeuFS and Random were run: the other 5 baselines (Entropy, TypiClust, Patron, (Fast-)VoteK, linguistic variants) and the Table 4 representation variants have no released code.
- **Codebase completeness: MISSING_SCRIPTS.**

## What the release contains

The repo is https://github.com/johnnychanv/NeuFS (linked from the paper). It contains:
- `neufs/collect.py`, `collate.py`: FFN-hook / early-unembedding activation collection, ported from MUI-Eval.
- `features.py`, `kmedoids.py`, `select.py`: Jaccard K-Medoids clustering and dual-criteria selection.
- Two CLI scripts and a demo on the Edu-Feedback pool/test files (`examples/essay_comments`, 1799 / 14228 samples, matching the paper).

It is missing:
- The `system_prompt.txt` that the README and `run_example.sh` refer to.
- Any data or prompts for MMLU-Pro and TREC.
- Any few-shot ICL inference/evaluation code (paper: vLLM, temperature 0.6, 3 seeds).
- The Random baseline and all other baselines.
- Any script that produces the tables.

## What I ran

Everything below ran in `env/` (Python 3.11, torch 2.13 cu130, vllm 0.30, transformers 5.18) on 1×H200.

1. **Data** (`repro/prep_data.py`):
   - Edu-Feedback: the repo's `pool.jsonl` / `testing.jsonl`.
   - TREC: coarse 6-way labels from `SetFit/TREC-QC`, 5452 train as pool / 500 test.
   - MMLU-Pro: `TIGER-Lab/MMLU-Pro` test split (12,032 questions), shuffled with `random.Random(42)`; 2000 become the pool and the remaining 10,032 the test set (paper Table 5: 2000 / 10032; the seed of the paper's split is unknown).
2. **Activation collection:** released `scripts/01_collect_activations.py`, unmodified apart from the collator compatibility fix; `--top_k_per_layer 2000` (paper: n = 2000).
   - Prompts and label strings: `repro/prompts/*.txt`, `repro/tasks.py`. The Edu user template and labels come from `run_example.sh`. All system prompts, and every TREC / MMLU-Pro template, were written by me.
3. **Feature cache:** `repro/build_cache.py`, a streaming re-implementation of `features.build_features` that is exact (verified: identical Q(x) and top-k feature sets, and identical selected indices vs. `02_select_fewshot.py` on a test pool). It was needed because the released loader keeps ~29 MB of Python dicts per sample, i.e. >150 GB host RAM for the 5452-sample TREC pool against a 111 GB limit.
4. **Selection:** `repro/run_select.py` calls the released `neufs.select.neufs_select` with the same seeding as `02_select_fewshot.py` (seed 42, n_init 10). K and τ come from paper Table 6 for each model/dataset. Random baseline: `random.Random(42).sample` (paper App. B.2).
5. **Evaluation:** `repro/evaluate.py`, vLLM:
   - Chat prompt = system prompt + demonstrations as user / assistant `<answer>label</answer>` turns + query, with `enable_thinking=False`.
   - Temperature 0.6, max 32 new tokens, seeds 0/1/2, results averaged.
   - Accuracy and macro-F1. Any output that can't be parsed counts as wrong.
6. **Aggregation:** `repro/summarize.py` and `make_tables.py`, as in the paper: per-shot mean over 3 seeds, then mean ± std over 5/10/20/30 shots.
7. **Ablations** (`repro/run_ablation.sh`), MMLU-Pro, Qwen3-4B and Qwen3-8B:
   - Fig. 3: k ∈ {2000, 4000, 6000, 8000, 10000} at τ = 0.5.
   - Fig. 4: τ ∈ {0, 0.2, 0.4, 0.5, 0.6, 0.8, 1.0} at k = 8000.
8. **Extra check, not in the paper** (`repro/run_random_extra.sh`): Random with 3 more selection seeds (1, 2, 3), to see how much a single Random draw varies.

Driver scripts: `repro/run_model.sh <model>` (steps 2–6), `repro/run_all.sh`, `repro/rerun_main_mmlu.sh` (re-runs MMLU-Pro with the final answer parser, which also accepts "Option X" without "is correct"; the reported MMLU-Pro numbers come from this rerun), `repro/run_ablation.sh`, `repro/run_random_extra.sh`. Logs are in `logs/`, raw results in `results/`, selected demonstrations in `sel/`.

### Settings that differ from (or are unspecified in) the paper
- **Prompts and answer strings:** the paper gives none. Label strings had to have ≥2 tokens that the released collator accepts, because `features.py` drops the last answer token (see Discrepancies); a single-token label would give an empty neuron set. So we used:
  - TREC: "Abbreviation/Descriptive/Entity/Human/Location/Number question".
  - MMLU-Pro: "Option X is correct".
  - Edu: "With/Without Explanation", as in the repo.
- **Llama-3.2-3B-Instruct:** the `meta-llama` repo is gated for us, so we used the identical-weights mirror `unsloth/Llama-3.2-3B-Instruct`.
- **MMLU-Pro split:** the random seed is unknown (we used 42).
- **Answer parsing and max tokens:** unspecified in the paper; ours are described above.

## Why it isn't fully reproduced
1. **No evaluation code, prompts, or MMLU-Pro/TREC data formatting were released.** Prompt wording strongly affects absolute ICL accuracy: our Random baseline is 5–10 pt above the paper's on MMLU-Pro (Qwen3) and TREC (Llama). It may also change which demonstrations help. Our results therefore test the released selector under one reasonable prompt protocol, not the authors' exact protocol.
2. **Under that protocol, NeuFS's gains over Random are small or negative.** They are mostly within the variance of a single Random draw. The paper compares against a single Random draw (seed 42).
3. **Edu-Feedback reverses** for 3/4 models. The NeuFS sets have label ratios similar to the Random sets (e.g. 23 vs 24 "Without" out of 30 for Qwen3-4B), and I did not diagnose the cause further. Note that this test set's majority-class rate is 0.712, close to the paper's best Edu accuracies.
4. **Baselines other than Random were not run** (no code), so "NeuFS beats Patron / TypiClust / VoteK / Entropy" claims are NOT_COMPARABLE.

## Discrepancies
1. **code_vs_paper (major)**, `neufs/features.py::build_features`.
   - Paper (§3.1): N_act(x) = N(x, y_0) ∪ … ∪ N(x, y_t), the union over *all* predicted tokens.
   - Code: iterates `for pos in range(max_pos)`, which drops the last answer position (commented as "matches the original notebook").
   - Effect: with a single-token answer (e.g. a bare option letter) the neuron set and Q(x) are empty and selection degenerates. With multi-token labels, the neurons that produce the final label token are always ignored.
2. **code_vs_paper (minor)**, Q(x).
   - Paper: Q(x) = |N_act(x)|, the top-k activated set.
   - Code: Q(x) counts the unique neurons in the pre-filter pool (top-2000 per layer per position, union over positions). Clustering uses the global top-k set instead.
   - Note: taken literally, the paper's definition would be nearly constant (= k for every sample).
3. **paper_internal**, Eq. 3.
   - Eq. 3: Score = τ·Q̃ + (1−τ)·D̃_J(x, µ), with D̃_J the normalized Jaccard *distance* and the highest score selected. That favours samples far from the medoid.
   - Text: the second term should reward "representativeness (proximity to the cluster center)". The code (and README) use (1 − D̃). Eq. 1 also calls the Jaccard *similarity* D_J.
4. **paper_internal**, App. A.1 / Fig. 5. Text: t = −3.5698. Fig. 5 annotation: t = 3.5698.
5. **paper_internal**, Fig. 7 caption / App. A.2.
   - Fig. 7 caption: "selecting challenging, high-consensus demonstrations … yields better performance".
   - Paper elsewhere (§3.2, rest of A.2): *more* unique activations means *lower* consensus.
6. **code_vs_paper (minor)**, `scripts/01_collect_activations.py`.
   - Code: sets `pad_token = eos_token` and builds `attention_mask = ids != pad_token_id`. For Llama-3 (`eos = <|eot_id|>`) this masks out every in-prompt end-of-turn token during activation collection.
   - Paper: describes nothing like this. It affects the Llama activations only.

## Flags
- **BASELINE_STRONGER_THAN_REPORTED:** our Random is 0.460 vs 0.412 (Qwen3-4B, MMLU-Pro), 0.487 vs 0.388 (Qwen3-8B, MMLU-Pro), 0.829 vs 0.764 (Llama-3.1-8B, TREC), and 0.763 vs 0.707 (Llama-3.2-3B, TREC). Our prompts are a likely cause; NeuFS rises with them, but its margin over Random shrinks or vanishes.
