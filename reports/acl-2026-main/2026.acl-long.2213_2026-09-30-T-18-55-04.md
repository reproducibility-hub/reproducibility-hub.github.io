## Summary

- I re-ran every **SharVeT (proposed)** row of the main table (Table 2) at the paper's full scale: 3 models × 2 ratios (70%, 50%). That is 5,000 SlimPajama documents, 2 epochs, the full WikiText2/C4 perplexity evaluation and the full lm-eval tasks. I also ran three sanity or ablation checks: the original models, SharVeT without fine-tuning (Tables 6/9), and SharVeT without the KD/feature losses (Table 3, SharVeT_L).
- **4 of the 6 Table 2 settings match within tolerance on nearly every number** (Mistral 50/70%, LLaMA-3-8B 70%, TinyLlama 70%). For example, Mistral-7B at 50% scores 17.8 / 14.8 perplexity and 0.612 average accuracy, against the paper's 18.0 / 14.5 / 0.610.
- **The untuned compression stage is identical to the paper's.** The no-fine-tuning LLaMA-3-8B 50% model gives C4 742.1, Wiki 1366.0 and accuracies .540/.538/.285/.502/.001. These equal Table 6 (perplexity) and Table 9 (accuracies) to every printed digit.
- **LLaMA-3-8B 50% is the one large gap.** Perplexity matches (31.0 / 36.7 vs 31.9 / 36.9), but average accuracy is **0.562 vs the paper's 0.609**: ARC −6.9, LAMBADA −8.3, WinoGrande −4.1 points. Our full-SharVeT run lands exactly on the paper's ablation rows: SharVeT_L in Table 3 (0.56), SharVeT‑C in Table 7 (0.565), and SharVeT_Λ in Table 9 (0.564).
  - When I removed the KD and feature losses myself, the result matched the paper's SharVeT_L row exactly (.71/.64/.48/.58/.41) and was essentially identical to the full run.
  - So with the released `run/test.yaml`, the "proposed loss helps" ablation claim (Table 3) **does not reproduce**, and the headline 50% LLaMA accuracy is not reached.
  - One LR-sensitivity run (lr = 5e‑4, inside the paper's 1e‑4–1e‑3 search range) was slightly worse (avg 0.555, Wiki 40.4, C4 32.7), so the learning rate does not explain the gap.
- **The paper's main conclusion still holds against the paper's own baseline numbers.** Even our weaker LLaMA-50% numbers beat the best baseline in Table 2 on every metric except COPA (avg 0.562 vs 0.505 for SEQ and 0.502 for Basis Sharing). On COPA, SEQ's 0.72 also beats the paper's own SharVeT (0.71). Every one of our 6 settings beats the reported Basis Sharing on perplexity and average accuracy.
  - The one exception is a single task: TinyLlama 50% COPA scores 0.60, below Basis Sharing's 0.64.
  - I did not re-run the baselines (SEQ, CYCLE, CYCLE‑R, Basis Sharing + LoRA). The release contains no code or configs for them, so "beats X" claims are only checked against the paper's reported baseline numbers.

## Discrepancies

**Code vs paper**
- **Functional similarity input (major, `similarity.py::_init_similarity`/`_get_functional_similarity`).** The paper computes CKA on the activations X_C of each module from calibration data. The code takes the raw token embeddings of a single 1024-token calibration sequence and multiplies them by every layer's weight; the actual per-layer input activations are not used.
- **Inverse-similarity allocation (major, `utils.py::similarity_based_num_basis`).**
  - The paper sets η ∝ 1 / (sum of pairwise similarities in the group). The code uses 1 / (mean pairwise similarity).
  - Singleton groups get no share of the residual budget, yet still count in the normaliser, so a small part of the budget goes unused.
- **Decomposition (minor).** The code whitens the weights with a Cholesky factor of the calibration XᵀX before the SVD (SVD-LLM / Basis Sharing style). The paper only describes plain SVD of the concatenated weights (Eq. 2–3).
- **L2 regularisation (minor, `train.py`).** It is applied only to the vectors of the attention modules (`layer.self_attn`), not the MLP vectors. With λ = 1e-8 the effect is negligible.
- **Optimizer (minor).** The paper says Adam. The code uses AdamW (weight decay 0.01) with a LinearLR schedule from 1.0 to 0.8.

**Paper internal**
- **Table 6 vs Table 9.** For LLaMA-3-8B, Table 6 lists SharVeT (no fine-tuning) COPA = 0.830 with avg 0.332, but Table 9 lists SharVeT_T COPA = 0.540 with avg 0.373. Our run gives .540 / .373, so 0.830 (and the 0.332 average) is a typo; it is also inconsistent with the other Table 6 columns.
- **Table 7 vs Table 8.** The SharVeT‑F and SharVeT‑K rows of Table 7 are identical in all 8 numbers to the SharVeT_Agg and SharVeT_DB rows of Table 8, which are different ablations.
- **Table 2 TinyLlama 50%.** SEQ and CYCLE have identical perplexities (55.6 / 66.8), probably a copy error.
- **Limitations section.** It says "our experiments are confined to the LLaMA", but the paper also reports Mistral, Qwen2, InternLM2 and GPT2-XL.
