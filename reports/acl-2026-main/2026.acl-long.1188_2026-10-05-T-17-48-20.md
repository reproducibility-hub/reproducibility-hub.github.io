# Reproduction report — Stable-RAG (2026.acl-long.1188)

**Paper:** Stable-RAG: Mitigating Retrieval-Permutation-Induced Hallucinations in Retrieval-Augmented Generation (ACL 2026)
**Code:** https://github.com/zqc1023/Stable-RAG (linked in the paper, footnote 1). Released LoRA adapters: https://huggingface.co/qianchi/Stable-RAG (LLaMA3-8B-Instruct × {NQ, TriviaQA, HotpotQA} × Contriever only)

## Verdict

**PARTIALLY_REPRODUCED.** Result match: **TREND_MATCH** (both after fixes and as released). Coverage: **SCALED_DOWN**. Codebase completeness: **MINOR_FIXES**. Flags: `RERUN_WEAKER_THAN_RELEASED`.

- The **authors' released adapters** reproduce the paper's Stable-RAG numbers almost exactly: Table 2, LLaMA3-8B-Instruct + Contriever, on NQ, TriviaQA and HotpotQA, and Table 6 (shuffled order). All within ≤1.03 points SubEM / ≤0.64 F1.
- **Our baselines also match.** Vanilla RAG through our rebuilt Contriever top-5 retrieval matches Table 2 on all three datasets (≤0.9 points), so our data setup is equivalent to theirs.
- **Retraining doesn't reach the paper's SubEM.** Running the released data-construction → DPO pipeline ourselves gives models that beat vanilla RAG on SubEM and F1. Their F1 matches or exceeds the paper's, but their SubEM gain is much smaller:
  - NQ: +2.3 SubEM vs the paper's +7.4 (42.83 vs 48.14), at the paper's training scale.
  - HotpotQA: +3.3 vs +8.2 (34.20 vs 38.91), at reduced scale.
  - We found no config difference that explains this. Training scale (5.5k / 12k / 18k questions) moves NQ SubEM only from 42.1 to 42.8. Replicating the release's `<|eot_id|>` attention masking exactly also changes nothing: 42.47 vs 42.13 unmasked on the same 5.5k questions.
- **"Best overall" doesn't hold for our retrains,** but this can't be tested properly. Compared with the paper's *reported* baseline numbers (we could not run those baselines), the retrained NQ SubEM of 42.8 would sit below ATM (43.75) and Pos2Distill (44.58). The released checkpoints (48.17) do beat them.
- The retrained models answer in a terser style (≈2.7 words vs 5.0 for the released NQ adapter) and almost never abstain. The released adapters are also more accurate on short answers (SubEM on ≤5-word answers: 50.6 vs 42.3 on NQ), so this isn't only an answer-length artifact of SubEM.

## What the paper claims / what we targeted

Main claim (abstract, §5.2, Table 2): Stable-RAG (permutation-sensitivity estimation → hidden-state spectral clustering → preference data → DPO) improves SubEM/F1 over vanilla RAG and robust-RAG baselines on NQ/TriviaQA/HotpotQA. It is also more robust to shuffled document order (Table 6).

Our target was Table 2 (LLaMA3-8B-Instruct, Contriever-MS MARCO top-5) plus Table 6 (shuffled order):
- Direct Generation, Vanilla RAG and Stable-RAG on all three datasets.
- Stable-RAG two ways: (a) the released checkpoints; (b) retrained with the released code.

Not attempted:
- **Qwen3-8B rows and DPR columns.** No released checkpoints; each retrain costs ≈10–20 GPU-hours of data construction. The H200 sustains ≈530 TFLOP/s on the 120-permutation forward passes (≈4 s per training question), so this was compute-bound.
- **RetRobust / ATM / RAAT / Pos2Distill / Ms-PoE / Vanilla SFT / Standard DPO baselines.** The release contains no code or configs for them, so claims like "beats ATM" are NOT_COMPARABLE.
- **Stable-RAG♣** (exhaustive decoding). `exhaustive_decoding.py` exists but costs ~3× more.
- **Tables 1, 3, 5 and Figures 5–7.**

## What we ran (exact pipeline)

All runs used the conda env `env/` (Python 3.11 + the repo's `requirements.txt`) on one H200.

1. **Data.** The paper's top-5 retrieval files are not released; the README says retrieved documents "can be obtained using Self-RAG" (Contriever-MS MARCO over the DPR Dec-2018 Wikipedia). We rebuilt them that way:
   - `scripts/prep_questions.py` builds the question files:
     - NQ-open: train 79,168 / test 3,610 (DPR csv).
     - TriviaQA: train 78,785; evaluated on the 8,837-question split, which is the size Table 7 calls "test"; the standard 11,313 split is also reported. The released TriviaQA adapter matches the paper only on the 8,837 split.
     - HotpotQA: KILT train 88,869 / KILT dev 5,600 as test, matching Table 7's 88.9k/5.6k.
     - Training questions: a random (seed 42) 20k subset per dataset.
   - `scripts/retrieve_contriever.py`:
     - Encodes queries with `facebook/contriever-msmarco` (mean pooling).
     - Runs exact inner-product search over the released Contriever-MS MARCO passage embeddings (`wikipedia_embeddings.tar`).
     - Takes the top-5 `psgs_w100` passages, each formatted as `"{title}\n{text}"`.
   - NQ test answer recall in the top-5 is 66.8%.
2. **Evaluation.**
   - `scripts/eval_batched.py` is a batched copy of `codebase/inference.py`: same prompt and chat template, fp16, max_new_tokens 32, sampling at temperature 0.01, and the same `metrics.py` SubEM/F1 on `strip().rstrip('.')` outputs.
   - Validation: the **unmodified** `codebase/inference.py` on NQ with the released NQ adapter gives SubEM 48.34 / F1 46.08; our batched script gives 48.17 / 45.58.
   - `--mode nodocs` runs Direct Generation (the paper gives no prompt for it; we used the same system prompt with no documents).
   - `--shuffle` runs Table 6 (random document order, seed 42).
3. **Released adapters.** Merged with `merge_lora_dpo.py::merge_lora` (via `scripts/merge.py`), then evaluated.
4. **Retraining (released code).**
   - Representative decoding: `scripts/rep_decoding_batched.py`, a batched driver that imports the released clustering functions unchanged (`cluster_hidden_states`, `select_representative_indices`, PCA 30, σ = 0.1, KMeans). It batches the 120 permutation forward passes and the K greedy decodes.
   - Then the released `get_data.py` → `get_dpo_data.py` → `train_dpo.py`:
     - Hyperparameters are the code's own: LoRA r = 128, α = 128, β = 0.4, lr 5e-6, batch 2 × grad-accum 8, 1 epoch, 85/15 split, cap of 18,000 pairs.
     - Then merge → eval.
   - Orchestration: `scripts/post_train_eval.sh`, `scripts/orchestrate*.sh`.

### The `<|eot_id|>`-masking detail

The released `representative_decoding.py` (and `inference.py`) sets `pad_token = eos_token` and builds `attention_mask = (input_ids != pad_token_id)`. For LLaMA3-Instruct the EOS token is `<|eot_id|>`, so the `<|eot_id|>` tokens **inside the chat prompt** are masked in the hidden-state forward pass and in the representative decoding. Our batched driver initially used a plain all-ones mask.

On 40 NQ training questions:
- Unmasked batched driver vs the unmodified sequential script: same cluster count K for only 2/40 questions; same FC/PC/F* category for 32/40.
- With `--mask_eot` (replicating the release): same K for 39/40, same category for 39/40, identical answer sets for 33/40.

So the NQ-12k/18k and HotpotQA retrains above used data that deviate from what the released script produces. We therefore ran a controlled NQ comparison on the same first 5,500 training questions, masked vs unmasked.

**Result:** masked (release-faithful) gives NQ SubEM 42.47 / F1 44.73; unmasked gives 42.13 / 44.56. The masking detail has no material effect, so the retraining gap is not an artefact of our batched driver.

## Discrepancies

- **code_vs_paper** — `data_construction/representative_decoding.py::cluster_hidden_states / main`, severity **major**, affects results: True.
  - Paper: Spectral clustering (Sec. 4.1, App. B.5) on final-layer last-token hidden states: affinity A=exp(-(1-cos)/sigma), normalized Laplacian, K from the eigengap over all eigenvalues, then clustering of the row-normalized first-K eigenvectors (spectral embedding).
  - Code/other: Hidden states are first reduced with PCA to 30 dims (not mentioned in the paper); the eigengap is searched only over the first 20 eigenvalues; the clusters are then obtained by KMeans directly on the PCA-reduced hidden states, i.e. no spectral embedding is used for the assignment (sigma=0.1 default).
- **code_vs_paper** — `data_construction/representative_decoding.py::get_last_token_hidden_state and inference.py::get_answer`, severity **minor**, affects results: False (control: 42.47 masked vs 42.13 unmasked NQ SubEM).
  - Paper: Hidden states/answers for the chat prompt in Table 8.
  - Code/other: pad_token is set to eos_token (<|eot_id|> for LLaMA3-Instruct) and attention_mask = (input_ids != pad_token_id), so the <|eot_id|> tokens inside the prompt (end of system and user turns) are masked out during hidden-state extraction, representative decoding and inference.
- **code_vs_paper** — `data_construction/get_data.py::is_substring_match`, severity **minor**, affects results: True.
  - Paper: Representative answers are compared with the ground truth (the evaluation metric is SubEM: gold substring of prediction).
  - Code/other: Correctness for FC/PC/FA/FU categorization is bidirectional substring matching (prediction in gold OR gold in prediction), so a prediction that is merely a substring of a gold answer counts as correct.
- **code_vs_paper** — `data_construction/get_dpo_data.py (partially_correct branch)`, severity **minor**, affects results: True.
  - Paper: Sec. 4.2: one preference tuple (x, y_w, y_l) per PC instance, x = q + a document permutation.
  - Code/other: Two DPO pairs per PC question (same chosen/rejected, once with the wrong-answer permutation and once with the right-answer permutation).
- **code_vs_paper** — `data_construction/get_dpo_data.py::build_dpo_sample`, severity **minor**, affects results: True.
  - Paper: Table 8 prompt: 'Answer the question with couple of words using the provided documents.'
  - Code/other: Training prompts say 'with a couple of words' while inference.py / representative_decoding.py use 'with couple of words'.
- **code_vs_paper** — `train_dpo.py (DPOConfig)`, severity **minor**, affects results: False.
  - Paper: App. A.3: beta=0.4, Qwen3-8B trained for 2 epochs (README: beta 0.4/0.3 for LLaMA3/Qwen3).
  - Code/other: beta=0.4 and num_train_epochs=1 hard-coded for all models (Qwen3 settings require editing).
- **code_vs_paper** — `data_construction/get_data.py vs get_dpo_data.py`, severity **minor**, affects results: False.
  - Paper: Three-step data pipeline (README).
  - Code/other: get_data.py writes outputs/random_order_status_train_hidden_state.json but get_dpo_data.py reads outputs/random_order_final_status_train_hidden_state.json; all paths are hard-coded.
- **paper_internal** — `Table 7 vs Table 2 (TriviaQA)`, affects results: False.
  - Paper: Table 7 lists TriviaQA Dev 11.3k / Test 8.8k.
  - Code/other: The standard (DPR/FiD) splits are dev 8,837 / test 11,313; the released adapter reproduces Table 2 only on the 8,837-question set, so the reported 'test' numbers are on the set usually called dev (naming inconsistent with the standard split, not stated in the text).
- **paper_internal** — `Table 4 vs Table 2`, affects results: False.
  - Paper: Table 2: Stable-RAG TriviaQA Contriever SubEM 72.05.
  - Code/other: Table 4 reports 'Ours' TriviaQA Contriever as 72.04.

## Codebase completeness: MINOR_FIXES

The method, data construction, DPO training, merge and inference scripts are all present and ran. Issues and every change/addition:

1. **Env.** `requirements.txt` pins `contourpy==1.3.3` and `scipy==1.16.3`, which need Python ≥ 3.11, while the README says 3.10, so we used 3.11. `deepspeed==0.17.2` breaks `import peft/transformers` without `CUDA_HOME`; it isn't used by the code, so we uninstalled it.
2. **`data_construction/get_data.py`, `get_dpo_data.py`.** Input/output/model paths are hard-coded placeholders, so we made them overridable by environment variables (only edit to released source; uncommitted in `codebase/`). `get_data.py` writes `random_order_status_train_hidden_state.json` but `get_dpo_data.py` reads `random_order_final_status_train_hidden_state.json`.
3. **`merge_lora_dpo.py`.** Has hard-coded placeholder paths, so we call `merge_lora()` via `scripts/merge.py`.
4. **`bash/*.sh`.** Contain placeholder paths. `train_dpo.py` uses `device_map="auto"` and writes `./saves/...` relative to the CWD. Its `device_map="auto"` load fails ("meta tensor") if the GPU is partly occupied by another process; this is environmental.
5. **Data preparation missing.** No retrieval or dataset-formatting scripts; the README defers to Self-RAG's retriever. We wrote `scripts/prep_questions.py` and `scripts/retrieve_contriever.py`. The rebuilt data reproduce the paper's vanilla-RAG numbers.
6. **Efficiency wrappers (not needed for correctness).**
   - `scripts/rep_decoding_batched.py`: the batched representative-decoding loop. The released per-permutation loop would take ~2× longer.
   - `scripts/eval_batched.py`: batched evaluation, validated against `inference.py`.
7. **Unimplemented in the release.** No scripts for Direct Generation, the shuffled-order evaluation (Table 6), the baselines, PSR (Table 5), or the clustering analysis (Table 1).

As-released vs after fixes: our only source edits are the path overrides, which don't change results. The released pipeline is otherwise reproduced faithfully, including the `<|eot_id|>` masking in the control run. So `result_match_as_released` equals `result_match`.
