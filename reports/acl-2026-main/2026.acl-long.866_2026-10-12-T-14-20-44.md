## Summary
* **Claim 1, SEE tracks noise-induced degradation (Fig. 3, abstract "correlation of 0.98"): reproduced.** Across 3 models × 3 MMAU tasks × 7 SNRs, the mean SEE and the generation success rate (GSR) have Pearson R from −0.96 to −0.99 (paper: −0.96 to −1.00). All 9 cells are within 5% of the paper's R. SEE rises monotonically as SNR drops, and the clean-input SEE values reproduce Table 7 for Qwen and MiniCPM almost exactly (e.g. Qwen music 0.354 vs 0.354).
* **Claim 2, SEEN improves GSR under noise (Table 3/8, "consistently improves GSR across all datasets and models"): not reproduced.** The released SEEN pipeline reproduces the absolute GSR numbers of Table 8 within tolerance (26/27 cells). But the effect attributed to SEEN, i.e. GSR(SEEN) − GSR(no denoising) at −10 dB, is positive in only 5/9 model × task settings. It is zero in 1 and negative in 3 (StepAudio speech −2.67). The mean is −0.15 points; the paper reports +0.33 to +1.33 in every cell (mean +0.73). All of our differences are within ~1–2 flipped answers out of 300, except StepAudio speech (8). On LibriSpeech (supplementary; the paper reports no WER) SEEN makes WER worse for MiniCPM and StepAudio.
* **Claim 3, SEEN beats conventional denoisers by 6.7%: NOT_COMPARABLE.** No code or configs for STFT/WT/Segan/DFL are released, so they were not reconstructed.
* **Release completeness:** the SEEN intervention and SEE energy computation are released. The **offline noise-subspace identification** (Sec. 3.1 / Algorithm 1) that produces the bases is **not**; only precomputed `v_list_*.pt` bases are shipped. My own implementation of Algorithm 1 for Qwen, from the paper text, does not recover the released bases: with ρ=0.95 it keeps almost no directions. Applying Eq. 5 as written gives layer 0, while flipping its D inequality gives exactly the hard-coded layer 23. Swapping in this re-derived basis leaves GSR unchanged (Qwen music −10 dB: 75.67 vs 75.33 with the released basis vs 75.00 with none). Hence `MISSING_CORE` + `CHECKPOINT_ONLY`. Two crash bugs had to be fixed; neither changes the GSR numbers.

## What I ran
Environment: `conda create -p ./env python=3.12`; torch 2.8.0+cu128, transformers 4.52.4 (yml: 4.52.0.dev0), qwen-omni-utils 0.0.8, librosa 0.11, jiwer, s3tokenizer/hyperpyyaml/onnxruntime-gpu (Step-Audio2), vocos/vector-quantize-pytorch (MiniCPM-o TTS init). Step-Audio2 inference code cloned from github.com/stepfun-ai/Step-Audio2 (on PYTHONPATH). 1× H200, shared with my own parallel workers (up to 6 processes).

1. `cd codebase/Qwen && bash create_data.sh` (builds all noise types × SNR {−10,−5,0,5,10,20,30} for the 4 datasets; Gaussian noise via seed 42).
2. For each model `M ∈ {Qwen, MiniCPM, StepAudio}`, dataset `d ∈ {music, sound, speech}`, SNR `s ∈ {−10,−5,0,5,10,20,30}`:
   `cd codebase/M && python get_acc.py --datasets d --noise gauss --SNR s` (default `--test_len 300`), which is the released script that `getacc.sh` loops over (getacc.sh's default noise list is crowd/machine/traffic, not the Gaussian noise of the main tables). Each sample runs four generations: clean, clean+SEEN, noisy, noisy+SEEN. Job runners: `scripts/run_model.sh`, `scripts/run_queue*.sh`.
   `python get_wer.py --datasets librispeech --noise gauss --SNR -10` (100 utterances) for each model (supplementary).
3. GSR / SEE / correlations from the released scripts' CSV outputs: `scripts/aggregate.py` (GSR = agreement of the prediction with the clean-input prediction, i.e. the code's "vs Clean agreement rate"; SEE = mean over samples of `row_mean_E` of `SEES_<d>/gauss/noise/E_<s>.csv`). Paper comparison: `scripts/compare.py`, `scripts/make_tables.py`.
4. Extra: `scripts/extract_basis_qwen.py` + `scripts/basis_variants.py` (my Algorithm 1 implementation, 50 clean speech clips + their 0 dB Gaussian noise-only signals, as in App. A.4). Then `v_list_gaussours_0.1_0.pt` + symlink `datasets/music/noise/gaussours → gauss`, and `get_acc.py --noise gaussours --SNR -10 --datasets music` (Qwen).

Settings vs. paper: identical models (bf16, sdpa), data subsets, N=300 per MCQA task / 100 STT, λ=1, δ=0.1 (released bases), 7 SNR levels, Gaussian noise. Main-table noise type: the paper does not name the noise type of Table 3/8. I used Gaussian noise because Table 7's SEE values equal Table 2's Gauss column, Tables 19–21 (Gauss) share Table 8's "None" GSRs, and `--noise gauss` is the script default. All runs use the full 300 samples per (model, task, SNR). Hardware differs (paper: RTX 5090). Gaussian noise realisations depend on file-listing order, so the noisy audio is not byte-identical to the authors'.

## Why not fully reproduced
* The method's claimed gain (SEEN vs no denoising) is within ±1 point and changes sign across settings in our runs. The paper's gains are also small (+0.3 to +1.3 points, i.e. 1–4 of 300 answers), so they lie within run-to-run noise from noise realisation and hardware. We cannot confirm that SEEN "consistently improves GSR".
* The headline comparison against STFT/WT/Segan/DFL (6.7%) cannot be checked: the baselines are not released.
* The basis-construction step of the method is not released (only its output), so the SEE/SEEN pipeline cannot be re-run end-to-end from the paper's description.

## Discrepancies
* **code_vs_paper (major):** the SEE values the code reports, and that match the paper's tables (e.g. Table 7 Qwen BASE 0.354 = ours 0.354), are the *un-normalized* mean projected energy mean_t‖A_tQ‖². They are not the normalized ratio of Eq. 9 (which is ~0.003–0.05 here). They are also measured inside the SEEN forward pass, so layers after the first target layer see already-neutralized activations. Correlations are similar with either definition (table above).
* **code_vs_paper (minor):** Eq. 5 (`D_l > D̄`) vs hard-coded target layers (Qwen 23, MiniCPM 18, StepAudio 27). On our Qwen activations the printed rule gives l* = 0 and the flipped inequality gives 23.
* **code_vs_paper (minor):** App. A.2 says all MCQA prompts use "Answer … by outputting ONLY one letter". Only Qwen does; MiniCPM has no format instruction; StepAudio uses "you only need to give the final answer".
* **code_vs_paper (minor):** `getacc.sh` runs crowd/machine/traffic, not the Gaussian noise of the main tables, and crashes for MiniCPM/StepAudio on `crowd` (no basis file).
* **paper_internal:** Qwen speech Gauss −10 dB SEE is 1.63 in Table 2 and 1.625 in Table 7, but 1.39 in Table 21 (and the Fig. 3 axis range).
* **paper_internal:** StepAudio/MiniCPM clean SEE differs between Table 7 (2.14–2.74 / 0.56–1.18) and Table 11 (5.43–7.88 / 2.46–3.15), with no stated change of basis.
* **paper_internal:** Sec. 3.1 keeps singular directions with σ > α (absolute); App. A.4 uses an energy ratio ρ = 0.95.
