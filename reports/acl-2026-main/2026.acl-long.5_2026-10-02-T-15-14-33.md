**Summary.**
- **Qwen3-32B:** the paper's curves come out almost exactly, in shape and level, across all four main figures. This includes details such as the flat ≈0.57 mean-pooled diffMean on RQ, the drop at the final layer, and the cross-dataset diffMean cosine peaking ≈0.5 at layer 1 and ending at ≈−0.15.
- **Llama-3.3-70B-Instruct:**
  - AUROC results match: within-dataset (Fig 1) and transfer (Fig 3 top row), as does cross-dataset cosine (Fig 4).
  - The alignment and ranking-agreement numbers (Fig 2; Fig 3 Spearman/Jaccard) depend strongly on the probe-training hyperparameters, which the paper does not report.
  - With the released config that fits Llama (`run_training.sh`, lr 1e-3), agreement is *higher* than reported. For example, SRAQ diffMean–probe cosine is ≈0.82 against the paper's ≈0.5, and the top-20% Jaccard under transfer is ≈0.4 against "often below 0.2".
  - With `train.py`'s own defaults (lr 0.1) the values come close to the paper's (≈0.59, ≈0.3).
  - With the other released config (`run_training_loop.sh`, lr 1e-5), Llama probes do not train: features are 10–30× smaller than Qwen's, and probe AUROC falls to ≈0.5–0.6 on SRAQ.
- **The paper's qualitative conclusions hold in every configuration where the probes train properly:**
  - linear separability is ≈0.85–0.9 AUROC on RQ;
  - transfer AUROC is ≈0.7–0.85;
  - directions learned on different datasets are not collinear (cosine ≈0.15–0.4);
  - transfer ranking agreement is clearly below within-dataset agreement;
  - top-ranked overlap is below bottom-ranked overlap.
- **The exact sizes of the alignment numbers depend on the hyperparameters.**

## What I did

1. **Paper:** read the PDF (`paper.pdf`, `paper.txt`). Main results are Figs 1–4 (layer-wise curves), Tables 1–2, and the numeric claims in the text.
2. **Code:** cloned https://github.com/ruyi101/rq-representation-probing into `./codebase` (no edits; only the generated `data/SRAQ.csv` was added).
3. **Data:**
   - RQ ships with the repo (4,997 rows: 3,200 / 797 / 1,000; 2,332 rhetorical).
   - SRAQ is not shipped. I took it from the SRAQ authors' repo (https://github.com/Abby-OGV/sraq), as the README says to do. Its files are concatenated pretty-printed JSON objects, not JSONL.
   - `work/make_sraq_csv.py` converts it into the CSV format the code expects. The result is 971 rows: 384 / 103 / 484, with 609 rhetorical, exactly as in §3.1.
   - Average lengths with the Llama-3.3 tokenizer are 38.4 tokens (RQ question_with_context; paper 38.9) and 58.3 tokens (SRAQ paragraph; paper 58.5).
4. **Environment:** conda env at `./env` (Python 3.11, torch 2.14.1+cu130, transformers 5.18.0, scikit-learn 1.9.1). The README gives no version pins.
5. **Models** (from the shared HF cache):
   - Qwen/Qwen3-32B
   - unsloth/Llama-3.3-70B-Instruct (an ungated copy of the official weights; the file name gives the same `Llama-3.3-70B-Instruct` tag)

   - meta-llama/Llama-3.1-8B-Instruct
   - openai/gpt-oss-20b

   - `work/run_embed.sh`: released `generate_embeddings.py` (last token) and `generate_embeddings_mean.py` (mean-pooled) for every model × {RQ question_with_context, SRAQ paragraph, SRAQ full_turn}, run from `work/data`.

   - `work/run_train.sh` / `run_queue.sh`: released `linear_model_training/train.py`, one probe per layer, logistic and hinge, for each setting and pooling.
     - Hyperparameters for Qwen3-32B, Qwen3-8B and gpt-oss-20b: from released `run_training_loop.sh`, which lists exactly these models (lr 1e-5, wd 1e-4, 1000 epochs, patience 100, batch 256).

   - `work/keynums.py`: layer-segment summaries, giving `work/results/keynums_main.txt` and `keynums_appendix.txt`.

## Discrepancies

1. **code_vs_paper (major, small effect): PCA fitted on all rows.** `scripts/pca_transform.py` fits the per-layer PCA on all rows (train + validation + test). Appendix B says the PCA mean is computed on the training split. This is unsupervised use of test inputs; I expect only a small effect.
2. **code_vs_paper (minor): probes have no bias.** `linear_model_training/model.py` uses `nn.Linear(bias=False)`. Eqs. (6)–(10) include a bias b. On PCA-centred features this mainly affects the threshold, not the direction or AUROC.
3. **code_vs_paper (major): transfer AUROC computed on all rows.** `pca_map_back/proj_auroc.ipynb` and `proj_transfer.ipynb` compute transfer AUROC on all rows; the test filter is commented out. The Fig 3 caption says "test AUROC". The effect is small (≤0.03; both versions are in `analysis_*.json`).
4. **code_vs_paper (major): wrong probe pairs and Jaccard fraction in transfer ranking metrics.**
   - `pca_map_back/spearman_and_jaccard.ipynb` contains `if metric == projected_files_file['metric']: continue`. This skips the same-probe pairs, so the in-domain probe X is compared with a *different* transferred probe Y.
   - The paper compares in-domain and transferred directions of the same probe.
   - The notebook also uses `top_bottom_jaccard`'s default `frac=0.10`, whereas Fig 3's caption says 20%.
   - I computed both versions. The as-released variant gives lower top Jaccard (Qwen ≈0.10–0.16), closer to the paper's "often below 0.2".
5. **code_vs_paper (minor): probe hyperparameters are not specified.**
   - The paper gives none.
   - The release contains three different sets: `train.py` defaults (lr 0.1, wd 0, patience 20); `run_training_loop.sh` (lr 1e-5, wd 1e-4, patience 100; Llama models commented out); `run_training.sh` (lr 1e-3, wd 1e-2, 500 epochs, patience 20; default model Llama-3.1-8B).
   - Which one produced which figure is not documented. This affects the Llama alignment numbers (see the table above).
6. **code_vs_paper (minor): RQ split name.** `data/RQ.csv` names the validation split `dev`, but `dataset.py` (and the README) expect `validation`. Unmodified, `train.py` fails on RQ with "Dev split is empty". I fixed this in a data copy (`work/data/RQ.csv`).
7. **paper_internal: mean-pooled diffMean level.** §4 text says mean-pooled diffMean reaches "≈0.60–0.65" at early layers. In Fig 1 (top row), RQ mean-pooled diffMean is flat at ≈0.57 for both models and SRAQ is ≈0.68. Our results match the figure.

Also noted, but not used for any paper figure: `linear_model_analysis/projection_transfer.ipynb` uses `dm_map[key]` (the in-domain direction) instead of `dm_map[second_key]`, so its "transfer" projections are not transferred.

- **Why not REPRODUCED:**
  - The paper reports curves, not tables, so many "paper" values are approximate figure readings or text ranges.
  - Most Qwen3-32B numbers and all AUROC numbers fall within those ranges.
