# Reproduction report — GenPT (ACL 2026, 2026.acl-long.1901)

**Verdict: PARTIALLY_REPRODUCED** · result match (after fixes): **MIXED** (forced by the PARTIAL_DATA rule; the reproducible CharacterRAG part is a TREND_MATCH) · result match as released: **DOES_NOT_RUN** · coverage: **SUBSET** · codebase completeness: **MISSING_DATA** (flag `PARTIAL_DATA`)

## 1. What the paper claims, and what could be tested

The paper compares GenPT (projective tests TAT/Rorschach/SCT → Interpreter → Diagnostician) with self-report questionnaires (BFI, 16P, BDI, BSS) on two persona sets:

* **CharacterRAG** (15 anime characters, PDB labels) → Big Five + MBTI. **Released** (`characters/CharacterRAG`, `pdb_labels.json`).
* **AnnaAgent / D4** (15 sampled mental-health profiles + counselling dialogues) → depression and suicide risk, plus the long-context condition (Figure 4). **Not released**: the README says it is withheld because it contains real help-seeker conversations. The loaders expect `characters/AnnaAgent/D4_prompts_with_labels.json`, `D4_S.json` and `selected_30.json`, and the persona IDs used are not given. The AnnaAgent GitHub repo does not contain them either, and D4 is application-gated.

So the **depression and suicide columns of Table 2, the depression and suicide rows of Table 1, and all of Figure 4 (longctx) cannot be reproduced.** That part includes the paper's headline claims: suicide-ideation fake-good drift of the questionnaire, GenPT winning on mental-health risk, and the order-of-magnitude longctx response. What I reproduced is everything on CharacterRAG:

* **Table 2:** Big Five exact-match accuracy and MBTI Hamming distance, for the questionnaire and GenPT with all 3 Interpreter/Diagnostician backbones.
* **Table 1:** Big Five and MBTI κ / DCR under `sdb_job` and `sdb_clinical`, for the questionnaire and all 3 backbones.

## 2. Setup actually run

* Env: conda python 3.11, `vllm 0.31.0`, `torch 2.13 (cu130)`, `transformers 5.17`, `openai`, `accelerate`, `pandas`, `openpyxl`; `pip install -e codebase --no-deps`. Env vars in `envvars.sh`:
  * `CUDA_HOME` / `PATH` point at the pip CUDA toolkit;
  * `VLLM_USE_FLASHINFER_SAMPLER=0`, because flashinfer JIT failed on this node;
  * `GENPT_MODELS_DIR=./models`: symlinks to HF snapshots, replacing the hard-coded `/home/aiscuser/models`.
* Models (all from HF):
  * Examinee: `Qwen/Qwen3-VL-8B-Instruct`. The paper never names the Examinee model; this is the code default.
  * Interpreter/Diagnostician backbones: `Qwen/Qwen3-8B`, `microsoft/Phi-4-mini-reasoning`, `internlm/Intern-S1-mini`, all with thinking enabled (the code default).
* **Stage 1 (Examinee)**: `scripts/generate_behaviors.py --sources characterrag --num-groups 1 --condition <c> --api-base http://127.0.0.1:18431/v1` (5 shards in parallel). Release defaults otherwise: T=0.8, max_tokens=1024, stimuli seed 42 → 8 TAT (4:3:1), 10 Rorschach + inquiry, 20 SCT.
  * Examinee served by `vllm serve` with `--max-model-len 32768`. With the README launcher's default of 16384, about 10 of the 75 personas overflowed the context in the multi-turn Rorschach dialogue; they were re-run with `--skip-existing`.
  * Conditions:
    * `baseline`;
    * `sdb_job` / `sdb_clinical` **as released**: framing passed as a 2nd system message, which is silently dropped (see §5);
    * `sdb_job` / `sdb_clinical` **fixed**: framing merged into the persona system prompt.
* **Stage 2+3** (Interpreter + Diagnostician): the release has `BatchInterpreter` / `BatchDiagnostician` (`genpt/pipeline/batch_runner.py`) but **no script that runs them over `data/behaviors/<condition>`**, despite the README's description. I wrote `run_stage23.py`, which only wires the released classes together with their default prompts, versions and sampling configs (interp T=0.3, max 3072 tokens; diag T=0.6, max 2048 tokens; persona summary injected for BF/MBTI exactly as `DiagJob.persona_summary` intends). It runs in-process with vLLM, one run per backbone.
* **Questionnaire**: `scripts/evaluate_questionnaire.py --source characterrag` (local transformers, Qwen3-VL-8B, T=0.3), unmodified for the baseline. For the SDB conditions I added a `--condition` flag (the released script has none) that appends the framing text from `genpt/pipeline/validity.py` to the persona system prompt.
* **Metrics**: `analyze.py`.
  * Accuracy and Hamming distance come from the released `genpt/evaluation/metrics.py`.
  * **κ and DCR are not implemented anywhere in the release**, so I implemented them from Eq. 12–13. Pooled linear-weighted κ is over 15×5 Big Five items (K=5) and 15×4 MBTI axis-items (K=2).
  * DCR uses "up" = toward I/N/F/P for MBTI. For the 3-run aggregate, DCR is pooled over runs (Σup vs Σdown).
* **Replicates**: the paper reports one run. Because a single run with 15 personas is very noisy, I ran the complete pipeline **3 times** (run1, rep2, rep3; same stimuli seed, fresh sampling in all stages). The questionnaire baseline was run 4 times (one baseline-only replicate is used purely for the noise floor) and each SDB condition 3 times. "Ours" below = mean over 3 runs (pooled DCR).
* Differences from the paper's setting: depression/suicide/longctx not run (no data); the Examinee model is unspecified in the paper; 3 replicates instead of 1. Everything else uses the release's defaults.

## 4. Interpretation

* **Table 2 (CharacterRAG): trend reproduced.**
  * The questionnaire's Big Five accuracy matches exactly: 0.373 in every one of 4 runs.
  * Its MBTI Hamming distance is worse than reported (1.00±0.07 vs 0.733) but still the best of all methods.
  * All three GenPT backbones are below the questionnaire on both metrics (BF 0.24–0.31, HamD 1.47–2.05), as the paper says.
  * Qwen3-8B has the lowest MBTI Hamming distance among backbones, as the paper says.
  * The paper's ranking of backbones on Big Five (Qwen > Intern > Phi) is not stable across our runs: means are Phi 0.307 ≈ Qwen 0.302 > Intern 0.244.
* **Table 1, personality rows: the qualitative picture holds.**
  * Questionnaire κ is high (0.74–0.80) and it drifts one-sidedly upward under both framings (pooled DCR 0.64–0.82 ↑), as the paper reports (0.55–0.62 ↑). Its noise floor is κ≈0.89–0.97, so the framing has a real effect on the questionnaire.
  * GenPT κ is much lower (Qwen 0.51–0.60, Phi 0.06–0.46, Intern 0.03–0.21; paper 0.20–0.63), with pooled DCR near 0.5 (0.50–0.61).
  * Individual κ values for Phi and Intern differ substantially from the paper, and DCR arrows for GenPT are essentially random. Only one cell contradicts the paper outright: Phi-4-mini MBTI sdb_job, paper 0.70↓ vs ours 0.52↑.
* **Important caveat on what GenPT's κ/DCR measures.** In the released code the SDB framing never reaches the GenPT examinee (§5). So the paper's GenPT SDB cells, if produced with this code, compare two framing-free samples. Our `_asrel` numbers confirm this: they are indistinguishable from the `_fixed` ones and from the baseline-vs-baseline noise floor (e.g. Qwen BF κ 0.54–0.66 for pure re-sampling). GenPT's lower κ and near-0.5 DCR reflect the pipeline's own sampling noise (T=0.8 examinee, T=0.3/0.6 thinking-mode interpreter and diagnostician), not resistance to framing.
  * With the framing fixed, GenPT still shows no systematic drift on trait tasks, so the paper's conclusion for traits survives.
  * But this experiment cannot separate "resists framing" from "too noisy to show a framing effect".
* **Robustness issues in the released pipeline** (not changed, documented):
  * With thinking enabled and the hard-coded `max_tokens` (3072 interp / 2048 diag), many outputs are truncated before `<answer>`.
  * Rorschach SRAS encodings come back empty for 5–10/15 personas with Qwen3-8B and 10–15/15 with Phi and Intern, so CPS/ARS/IRS/SCS fall back to formula defaults.
  * For the Big Five diagnosis, the parser then picks the first "O=…" inside the truncated reasoning (Qwen, Phi), or falls back to all-3 (Intern-S1-mini, 5–9 of 15 personas per condition).
  * This is a large part of the backbone-to-backbone differences.

## 5. Discrepancies

1. **code_vs_paper, major, affects results.** `genpt/pipeline/examinee.py::Examinee._system_messages` + `validity.py`: the SDB framing is sent as a *second* `system` message. The Qwen3-VL chat template only renders `messages[0]` as a system turn and silently drops later system messages. I verified this on the vLLM server: 20 prompt tokens with or without the framing. GenPT `sdb_job` / `sdb_clinical` behaviours are therefore generated **without any framing**, contrary to §5.3.1.
2. **code_vs_paper, major, affects results.** `batch_runner.py::BatchDiagnostician.diagnose_many` / `DIAG_USER_TMPL_WITH_PERSONA`: for Big Five / MBTI the Diagnostician receives the canonical CharacterRAG character description as **"PRIMARY evidence — anchor to this"**, with projective indicators only "SECONDARY". The paper defines ŷ = D(S, E; task) from the interpreted indicators only (Eq. 5, 10). GenPT's personality predictions are thus largely read off the persona text, not projective behaviour.
3. **code_vs_paper, minor, affects results.** SDB framing wording.
   * Paper §5.3.1: sdb_job = "job interview… show your best self"; sdb_clinical = "confidential counselling room… answer honestly". Those strings exist only in an unused `config.SOCIAL_DESIRABILITY_PROMPTS`.
   * The code actually uses deliberately valence-neutral texts in `validity.py` ("psychological screening as part of a job application… respond as you normally would" / "psychological assessment at a mental-health clinic…").
4. **code_vs_paper, minor.** README's Stage-2 command `scripts/run_experiments.py` runs a different, legacy end-to-end pipeline: `run_single_assessment` with `Interpreter` / `Diagnostician` and its own prompts, re-generating Stage 1 behaviours. It is not the batch pipeline with fixed behaviours and swappable backbones the paper describes. The README's `--api-bases` / `--served-model-name` options do not exist, and the README launcher call signature (`launch_vllm_plain.sh Qwen/Qwen3-8B 8000 0`) does not match the script's (`GPU PORT MODEL SERVED`).
5. **paper_internal.** §5.3.1 text: "Big Five and MBTI DCRs sit at 0.60–0.62 under both framings" for the questionnaire. Table 1 gives questionnaire MBTI sdb_clinical DCR = 0.55.
6. **paper_internal (minor).** The paper never states which model is the Examinee (code: Qwen3-VL-8B-Instruct), nor the questionnaire sampling temperature (code: 0.3).

## 7. As-released run of the README end-to-end command
The README's documented Stage-2 command (`python scripts/run_experiments.py --scope characterrag`, unmodified; models via `GENPT_MODELS_DIR`) is a legacy end-to-end pipeline. It uses local transformers, regenerates Stage-1 behaviours, and runs the legacy `Interpreter` / `Diagnostician` with `max_tokens=None`, i.e. unbounded generation.

I launched it as an as-released data point for GenPT (Qwen3-8B) in Table 2. The first persona finished its 8 TAT calls in 4 min, but then spent **over 60 min in the Rorschach phase without finishing** (no output, GPU active). That is consistent with run-away unbounded generation. Extrapolated over 15 personas it could not finish within the job budget, so I stopped it (log: `logs/run_experiments_asrel.log`).

It is also not the protocol the paper describes (discrepancy 4), so no as-released GenPT numbers exist. `result_match_as_released = DOES_NOT_RUN`:

* the κ/DCR pipeline, the Stage 2/3 backbone-swap driver and the questionnaire SDB conditions are absent from the release;
* the paper's own AnnaAgent data is missing.

The only fully unmodified released script that produced a paper number is the questionnaire baseline: BF 0.373 (NUMBERS_MATCH) and MBTI HamD 1.067 (paper 0.733, TREND_MATCH).
