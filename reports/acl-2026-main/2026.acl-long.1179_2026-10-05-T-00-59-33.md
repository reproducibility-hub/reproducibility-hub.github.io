**Paper:** *Can Spectral-Clipping Enable Better Learning While Forgetting Less for Low-Rank Adaptation?* (Wi & Park)
**Code:** https://github.com/hyowonwi/SCLoRA (commit `c9b5d02`), cloned to `./codebase`

**Summary**
- **RoBERTa-base GLUE (Table 1, top), all 8 tasks:** reproduced closely. Our best-epoch average is 86.87 vs. the paper's 87.08, and every task is within 0.6 points.
- **DeBERTaV3-base GLUE (r=8 and r=2):** we ran only the four small tasks (RTE, MRPC, CoLA, STS-B), one seed each. All are within 0–1.3 points of the paper.
- **LLaMA-7B commonsense (Table 3):** SCLoRA is lower than reported, 76.25 vs. 79.4 (−3.2). Our own LoRA baseline in the same pipeline gets 74.57, essentially the paper's 74.7. So the claimed improvement over LoRA is present but much smaller: +1.7 vs. +4.7 points.
- **Forgetting (Table 4, LLaMA part):** the release has no script for this, so we wrote one with our own perplexity protocol. The direction reproduces:
  - LoRA's adapter spectral norm is much larger than SCLoRA's (max 56.4 vs. 2.30).
  - Perplexity rises much more after LoRA. C4: base 7.47 → SCLoRA 8.12, LoRA 11.13. PG19: base 10.77 → SCLoRA 11.51, LoRA 14.86.
  - Absolute values are not comparable to the paper's, because its protocol isn't described.

**As released**, several things go wrong:
- The RoBERTa trainer has its evaluation hook commented out ("#### runtime #### For training, uncomment"). It only reports the last epoch (average 86.11), and on CoLA, RTE and MRPC this falls below the paper's own LoRA/DoRA baselines.
- The DeBERTa code crashes under any PyTorch that supports the H200.
- The LLaMA launcher uses lr 2e-4 instead of the paper's 3e-4. Run as released, the adapter averages 63.81, below our LoRA baseline (74.57). Its outputs degenerate on WinoGrande (19.7) and on HellaSwag's long WikiHow prompts (43.0).
- No code exists for any of the forgetting experiments.

## Discrepancies

### code_vs_paper
1. **sigma_bar is computed from a random matrix, not from W0** (`scloralib/layers.py`, `Linear.__init__`, in RoBERTa, DeBERTa and QA).
   - **Paper (Eq. 3):** σ̄ = Q_q(σ(W0)).
   - **Code:** `svd(self.weight)` runs in the constructor, before `from_pretrained` loads W0, so σ̄ is a quantile of a kaiming-uniform random matrix's spectrum. For roberta-base layer 0 query: q=0.25 gives 0.73 vs. 3.36 from W0; q=0.5 gives 0.47 vs. 1.87. The `mid` init likewise uses the random matrix's r smallest singular vectors.
   - **Severity:** major; affects results. Our W0 diagnostic changed STS-B by −0.5 and RTE by −2.2 (one seed).
   - The LLaMA tuner is fine: it loads cached spectra that match LLaMA-7B (verified).
2. **σ̄ is not saved with the model** (`scloralib`).
   - Reloading a saved SCLoRA model recomputes σ̄ from a *new* random matrix. So `load_best_model_at_end` and the final "eval" in `run_glue.py` evaluate a corrupted model (RTE: 55.2% instead of 82.7%).
   - **Severity:** major; affects the numbers the pipeline prints. We used the per-epoch logged dev metrics instead.
3. **RoBERTa trainer evaluation hook is commented out.**
   - The paper protocol (best dev result with per-epoch evaluation, via `--evaluation_strategy epoch --load_best_model_at_end`) is disabled. The released code reports the last epoch.
   - **Severity:** major; affects results (avg 86.11 vs. 86.87).
4. **LLaMA learning rate:** `llama_7B_SCLoRA.sh` uses lr 2e-4, while paper Table 14 says 3e-4 for LLaMA-7B. Severity: minor; affects results (see Table 3, as-released column).
5. **RoBERTa `command_sclora_best.sh` disagrees with Table 8** (the per-task README table matches Table 8):
   - SST-2: `1e-2 Q3_init` vs. Table 8's γ=1e-1, q=1.0
   - QNLI: `1e-2 mid` vs. γ=1e-1, q=0.25 with U=0 init
   - STS-B: `Q3_init` vs. q=0.25
   - Severity: minor. We used Table 8.
6. **U/V init:** paper Table 8 says "random r singular vectors of W0". The code's `mid` option uses the r *smallest* singular vectors (`U[:, -r:]`, `Vh[-r:]`), and of the random-init matrix (see 1). Severity: minor.
7. **Regularizer norm:**
   - **Paper (Eq. 5):** ‖UᵀU−I‖ + ‖VVᵀ−I‖.
   - **Code:** the RoBERTa trainer sums `mean(|UᵀU−I|)` (elementwise mean-abs) over layers. DeBERTa and LLaMA use the Frobenius norm averaged over layers.
   - Severity: minor.
8. **DeBERTa r=2 CoLA:** `scripts_sclora_r2/run_debertav3_cola.sh` uses `--lora_r 3`, while the paper says r=2. Severity: minor.
9. **SQuAD v1.1 metric:** `QA/scripts/run_debertav3_squadv1_sclora.sh` passes `--version_2_with_negative`, so v1.1 is post-processed and scored as SQuAD v2 (null answers allowed). Severity: major (evaluation protocol). Not run by us.
10. **Launcher port variable:** the RoBERTa scripts use `--master_port=$master_port`, but the script defines `RANDOM_PORT`, so the launch fails unless the environment sets it. Severity: minor.
