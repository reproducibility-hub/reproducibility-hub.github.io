# Reproduction report — Splits! Flexible Sociocultural Linguistic Investigation at Scale (2026.acl-long.117)

**Verdict: PARTIALLY_REPRODUCED**. Result match: **MIXED**. As released: **MIXED**. Coverage: **SUBSET**. Codebase completeness: **MISSING_SCRIPTS**.

Summary:
- **What reproduced.** We reran the released lift and triviality code over all 29,618 released PSLPs. Every precomputed lift value (all 7 cutoffs) and every triviality value comes back exactly. Table 13 (lift@0.5% by prompt type) matches number for number. The Table 1/10/11 post counts match exactly, and the 'dance' proportions match within 3%.
- **What did not.** Two paper-level statistics computed from the same released PSLP pool don't match:
  - Only ~2,300 PSLPs pass p<0.025 in the paper ("over 10x" reduction). From the released file we get **8,049 of 29,618 (3.7x)**.
  - The paper gives Spearman ρ(triviality, lift@0.5) = 0.32. We get **0.264**: still positive and significant, but outside tolerance.
- **What could not be run.** The human annotations (Table 3, ρ = −0.38), the literature-inspired PSLPs (Fig. 6, mean 0.585) and the AAVE/Yiddish lexica (Table 1 rows 1–2 proportions) are not released.
- **Bug in the release.** The released `core_logic.query_bm25_index` has a padding bug. Run unmodified, it reproduces Table 13 only approximately, and the demo's default `doc_count=2000` gives very different lifts.

## 1. What the paper claims and what was released
- Claims:
  - Splits! is a 9.7M-post Reddit dataset split by 6 demographics × 89 topics.
  - It replicates 5 known SLPs (Table 1; App. B Tables 10, 11).
  - The two-stage filter works: **lift** (BM25 re-ranking of a paired demographic/topic index, hypergeometric test) plus **triviality** (subspace-BERTScore recall vs. a demographic seed lexicon). In support, the paper reports:
    - Table 13: lift by prompt type.
    - Sec. 5.1: ρ = 0.32 between triviality and lift.
    - Sec. 6.1: ~2,300 of 23,000+ PSLPs significant.
    - Sec. 5.2/Table 3: human validation.
    - Sec. 5.3/Fig. 6: literature-inspired PSLPs are less trivial (0.585 vs 0.810).
- Release (https://github.com/eyloncaplan/splits, linked from the paper):
  - `core_logic.py` (BM25 phrase query, lift, hypergeometric test, triviality wrapper) and the `subspace/` SubspaceBERTScore library.
  - A demo notebook.
  - Metadata JSON files.
  - `download_data.sh`, which syncs the HF bucket `ecaplan/splits-storage`. The bucket holds 793 BM25 indexes (40 GB) and `keyword_similarities_with_lifts_4.1.jsonl`, which has 29,618 LLM PSLPs with precomputed lifts and triviality.
  - The HF dataset `ecaplan/splits` (v3 `splits.jsonl.zip`).
- **Not released:**
  - Scripts that run lift/triviality over the PSLP pool, build Table 1 or compute the paper statistics.
  - The AAVE and Yiddish lexica.
  - The human annotations.
  - The 591 literature-inspired PSLPs.
  - The PSLP-generation pipeline (needs GPT-4.1 anyway).

## 2. What I ran
Environment: `conda create -p ./env python=3.10 openjdk=21 uv`, then `uv pip install -r requirements.txt` (pyserini 0.44, transformers 4.53.2, torch 2.14), plus `statsmodels` for my own z-test. pyserini imports an OpenAI client at import time, so I set `OPENAI_API_KEY=dummy` (it is never called). Data came from `hf sync hf://buckets/ecaplan/splits-storage codebase/lexica/` (as in `download_data.sh`) and `splits.jsonl.zip` from the HF dataset.

Scripts I wrote (in `./scripts`, outputs in `./results`):
1. `run_lift.py` (9 parallel workers, ~45 min):
   - For each of the 29,618 PSLPs, it finds the paired index `topic_A-B` (780 indexes are used).
   - It builds the query exactly as `core_logic.query_bm25_index` does: quoted phrases OR'ed together, `StandardQueryParser` with the bert-base-uncased HF analyzer.
   - It pads unretrieved docs with the same md5(query)-seeded shuffle, and scores with the release's own `lift_at_k` / `lift_ci` at 0.5, 1, 2, 3, 4, 5 and 10%.
   - Per-index labels are cached for speed. A spot check showed this is bit-identical to calling the release function.
   - Four protocols are run:
     - (a) whole index, padding that excludes already-retrieved docs ("fixed"; this is what the paper describes);
     - (b) as (a) with `doc_count=2000`;
     - (c) whole index with the release's buggy padding, an exact emulation of the unmodified `query_bm25_index(..., doc_count=num_docs)`;
     - (d) the unmodified function with the demo default `doc_count=2000`.
2. `run_triviality.py`: the release's `SubspaceBERTScore(bert-base-uncased)` with `demo_seed_words.json` (= paper Table 12), `Recall` as triviality, computed for all PSLPs on the GPU.
3. `table1_stats.py`, `table1_dance.py`: per-(demographic, topic) post counts from v3, and the 'dance'/'dancing' lexicon on Personal Cultural Identity with a one-sided two-proportion z-test.
4. `analyze.py`: Table 13, significance counts, Spearman correlations and triviality means → `results/analysis.json`.

Settings that differ from the paper:
- None for lift and triviality: same indexes, same lexica, same cutoffs.
- The paper's "Professional" topic set is not defined. I used the 20 topics of the "Professional & Career-oriented Spaces" category, keeping only splits with ≥2,000 posts.
- The paper's exact matching rule for 'dance' is not given. I used word-boundary regex `\b(dance|dancing)\b`, case-insensitive.

## 4. Codebase completeness: MISSING_SCRIPTS
- The method (lift, hypergeometric test, triviality) is implemented in `core_logic.py` / `subspace/`. There are no scripts for the main experiments (running the PSLP pool through the indexes, computing Table 13 and the correlation/filtering statistics, Table 1). I wrote `scripts/run_lift.py`, `run_triviality.py`, `table1_stats.py`, `table1_dance.py` and `analyze.py`.
- **Bug in `core_logic.query_bm25_index`:**
  - `row.update(metadata)` overwrites the hit's external id (`"doc123"`) with the metadata's integer `id`.
  - So `returned_ext_ids` never matches `jd["id"]`, and the padding pool contains *all* docs, including already-retrieved ones. They get re-added as duplicates and some docs never appear.
  - This changes lift values (MAD 0.057 at full index).
  - The paper's precomputed values correspond to the correct behaviour. I did **not** edit the released file; my script implements the corrected padding and separately emulates the buggy one (verified identical to the unmodified function).
- The padding loop also re-parses every stored document on every query, which makes whole-index runs very slow. My script caches the labels instead.
- The demo notebook uses `doc_count=2000` (top-2000 plus random padding) instead of ranking the whole index as the paper describes.
- Environment: pyserini 0.44 needs `OPENAI_API_KEY` set at import (I used a dummy value), and conda `openjdk` (21).
- No source files in `./codebase` were modified. Python-regenerated `__pycache__` files were restored with git.

## 5. Discrepancies
- **code_vs_paper (major):** `core_logic.query_bm25_index` has the padding bug described in Section 4. The paper re-ranks the whole index; the code adds duplicate docs. Affects lift values (paper numbers were produced without the bug).
- **code_vs_paper (minor):** the demo notebook ranks with `doc_count=2000` rather than the whole index (Sec. 4.1). This gives very different lifts.
- **code_vs_paper (minor):** released data vs. paper counts:
  - v3 `splits.jsonl` has 10,235,741 rows over 193 topics (9.9M / 118 topics after the ≥2,000-post filter). The paper says 9.7M posts / 89 topics.
  - The PSLP file has 29,618 PSLPs; the paper says "over 23,000".
  - 780 paired indexes are used (793 in the bucket); the paper says 781.
  - DETAILS.md says 10 categories / 200 topics; the paper says 11 categories / 89 topics.
  - The Table 2 lexica are not in the released file in the stated setting.
- **paper_internal:**
