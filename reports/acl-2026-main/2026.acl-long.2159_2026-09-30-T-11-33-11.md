## 2. What I ran

**Environment**: `conda create -p ./env python=3.10.11`, then `pip install -r requirements.txt`. I dropped the `chardet @ file:///tmp/...` line (a local path) and the `spacy/thinc/blis/weasel/confection` pins, which conflict with `numpy==1.26.4` and aren't imported by the code. torch 2.5.1+cu124, transformers 4.51.3, captum 0.8.0. One H200, fp32, batch 1, as in the release.

**Pipeline** (released entry points, from `codebase/src`, via thin CLI wrappers in the attempt dir):
1. `token_ablation.py` (LLM) / `token_ablation_vlm.py` (VLM), `--attribution contrastive --grad_method integrated_gradients --num_samples 50 --top pos|neg`. Contrastive IG on the first 50 examples, ablating the top-k positive or negative tokens, saving last-token hidden states of all layers.
2. `steering_mc.py` / `steering_mc_vlm.py`, `--methods pca --mode pos|both --layer_idxs ... --alphas ...`. PCA steering vector, one-layer forward hook, base and steered MC evaluation over the split.

Example commands:
```
# LLM attribution (k=3), then sweep
python token_ablation.py --dataset_name truthfulqa --model_name llama-3.1-8b-instruct --num_samples 50 --top_k 3 --top pos \
   --attribution contrastive --grad_method integrated_gradients --split validation --output_path_meta results/llm/token_attribution --output_path_hidden data/llm/hidden_states
#   (same with --top neg)
python steering_mc.py --dataset_name truthfulqa --model_name llama-3.1-8b-instruct --num_samples all --split validation \
   --hidden_states_path data/llm/hidden_states/..._3_pos_integrated_gradients.npz --hidden_states_neg_path ..._3_neg_integrated_gradients.npz \
   --top_k 3 --grad_method integrated_gradients --attribution contrastive --mode both pos --methods pca \
   --layer_idxs 4 8 12 16 20 24 28 31 --alphas 1 2 4 6 8 10 --output_dir results/llm/sweep
# VLM attribution (k=20, IG 5 steps, captum batch 1, frozen weights)
IG_STEPS=5 IG_BATCH=1 FREEZE_PARAMS=1 python token_ablation_vlm.py --dataset_name spa-vl --model_name llava-1.6-7b --num_samples 50 --top_k 20 --top pos ...
python steering_mc_vlm.py --dataset_name spa-vl --model_name llava-1.6-7b --num_samples all --layer_idxs 31 --alphas 10 --mode pos ...
```

**Settings vs. paper**:
- k = 3 (LLM) / 20 (VLM), as in paper §4.1/4.2. The released `.sh` scripts use K=10 / K=50; I also ran the released script config once.
- IG steps: the code hard-codes 20; the paper says 5.
  - LLM main runs use 20 (as released); a second set uses 5 (paper).
  - VLM runs use 5, because 20 steps in one captum batch OOM even at 141 GB.
- Steering layer / λ / mode: the paper says they are tuned on a dev set but doesn't report the values. I swept them with the code's own grid arguments and selected on dev:
  - TruthfulQA / FaithEval: the 50 steering samples are `split[:50]`, as the released loader does. The remaining samples are split 10/90 into dev/test with seed 0.
  - SPA-VL: dev = validation samples 50–349 (LLaVA) or 50–199 (Qwen-VL).
  - Grids: Llama-TQA 96 configs; Qwen-TQA 84; LLaVA 8; Qwen-VL 36 (three rounds: 8 + 4 + 24).
- Reported "all" numbers use the release's protocol (full split, steering samples included). That protocol reproduces the paper's base numbers exactly. "Test" numbers exclude every sample used for steering or selection.
- SPA-VL: LLaVA evaluated on all 7000 validation samples. Qwen2.5-VL on the first 2000 only. Qwen-VL in fp32 creates up to ~16k visual tokens for large images and was ≥1–4 s/sample, and one image needs a 16 GB attention buffer.

**Interpretation**:
- **Base models match the paper almost exactly**: TruthfulQA 34.15 / 51.41 identical; SPA-VL 40.34 vs 40.24, 53.40 vs 53.21. So the paper's tables were produced by this released evaluator: `EleutherAI/truthful_qa_binary`, full validation split, each answer scored only by its last token's log-prob.
- **SPA-VL / LLaVA-1.6-7B** (the abstract's "+8.11%") reproduces: +8.99 on all 7000, +8.67 on held-out samples, with the released VLM script's own config (layer 31, α=10, mode pos).
- **TruthfulQA / Qwen2.5-7B** reproduces with code-default IG steps (59.12 vs 59.85). With the paper's 5 steps it is 57.16, still a clear gain.
- **TruthfulQA / Llama-3.1-8B**: the gain is much larger than reported (60.7–65.8 vs 47.37). The metric is a binary choice scored by one token, so chance is 50% and the base is below chance. Steering is extremely hyperparameter-sensitive:
  - 92% of 96 swept configs beat the base, and they span 32–67%.
  - With the released script defaults, the gain nearly disappears (35.13).
  - The paper's number is therefore not a stable property of the method; any value between ~35 and ~67 is reachable depending on layer/λ.
- **SPA-VL / Qwen2.5-VL-7B**: no gain. Across 36 dev configs and 5 configs re-evaluated on 2000 samples, the best is +0.65, versus the claimed +5.69. This contradicts the paper for this model.
- **Instability of the steering vector**: in "both" mode, v = PC1(δ+) − PC1(δ−). The two unit vectors have cosine ≈ 0.9, so v is a small, noisy residual. The same Llama config gives cos(v_IG20, v_IG5) = 0.53, and accuracy drops from 60.71 to 33.29.

## 6. Discrepancies

Code vs. paper:
1. **(major)** Steering is applied at a **single layer**. `add_steering_hook` `break`s after the first matching module, and the scripts use layer 31. The paper's method steers **every layer** (§3.3, Fig. 2C; Table 11 lists "All layers" as GrAInS).
2. **(major)** Norm preservation uses `orig.norm(dim=1)` on a (batch, seq, hidden) tensor, i.e. a norm across sequence positions per hidden unit. Eq. 5 uses the per-token ‖h_t,l‖. The vector is also multiplied by a hidden ×10 (`10 * alpha`).
3. **(major)** The attribution objective uses the log-prob of only the **last token** of each response, not log P(y|x) (Eq. 1).
4. **(major)** MC and SPA-VL evaluation compare **last-token** log-probs, not response log-likelihoods (App. A.1: "compute the log-likelihood of both responses"). The paper's base numbers match this evaluator, so the paper apparently used it too.
5. **(major)** VLM attribution, ablation and hidden-state extraction run **without `pixel_values`**. The image never influences the steering vectors; the "visual tokens" are identical `<image>` placeholder embeddings. This contradicts the paper's joint visual/textual attribution (§3.1, Tables 12–13).
6. **(major)** Data protocol. The paper uses a random 50 for steering and a 10/90 dev/test split of the rest (App. A.1). The code uses `split[:50]` and evaluates on the full split, steering samples included; there is no dev split.
7. **(major)** Toxigen / FaithEval / MMHal-Bench pipelines are absent or broken (see §4).
8. **(minor)** IG steps hard-coded 20 vs 5 in the paper. Scripts use k=10/50 vs 3/20. The LLM attribution script uses `GRAD_METHOD=vanilla` while the steering scripts load `*_integrated_gradients.npz`. VLM scripts use mode `pos` (v+ only), not v+ − v− (Eq. 4).
9. **(minor)** Default `LAYER_IDXS=31` doesn't exist for Qwen2.5 (28 layers). No hook gets registered, and "steered" silently equals base.

Paper-internal:
- The Llama Toxigen gain is "over 9.89%" (§1), "7.79%" (§4.1) and "+12.8%" (App. A.3), while Table 1 gives 60.98 − 51.19 = 9.79.
- Table 8's Llama Toxigen base/IG is 48.10 / 60.94 vs 51.19 / 60.98 in Table 1.
