## Summary

- **Table 3 (retrieval, MMLongBench and LongDocURL, Top-K = 1/3/5): reproduced.** We ran the released `src/retrieval_mab.py` over all 1073 MMLongBench and 2325 LongDocURL questions with Qwen2.5-VL-7B-Instruct and ColPali-v1.3, the same setup as the paper. 23 of 24 MAB-DQA numbers are within tolerance. The exception is MMLongBench Recall@1: 48.26 vs 50.97 (relative difference 5.3%). The released ColPali-only baseline matches the paper's "MDocAgent (Colpali)" row on all 24 numbers (usually within 0.3 points), which suggests the setup and metrics are the same as the authors'. MAB-DQA beats this ColPali baseline on every metric in both datasets. The average relative gain is 6.01%; the paper says 6.55%.
- **Table 2 (QA accuracy, the headline "+10.38% over the strongest baseline"): not comparable.** Scoring needs a GPT-4o judge, and no OpenAI key is available here. The release also has no judging script, and the README marks the Question Answering module as "#TODO / refactoring underway". The released `qa_reflection.py` (HRRA) crashes as released. After about 8 small crash fixes (no logic changes) it ran on all MMLongBench questions and produced answers (1073/1073, no errors). It also ran over all 2325 LongDocURL questions. These answers are not scored, and we did not substitute an open judge.
- **Not run:** FetaTab and PaperTab (they appear only in the QA tables, which need the judge; no configs are shipped for them). We also did not run the paper's other baselines (M3DocRAG, MDocAgent, MoLoRAG/MoLoRAG+): their code is not in the release. Claims of the form "beats MoLoRAG" are therefore NOT_COMPARABLE. For reference, our MMLongBench K=1 numbers (R 48.26 / P 63.52) would fall slightly below the paper's own MoLoRAG numbers (48.93 / 64.11). At K=3 and K=5, and on LongDocURL at every K, ours are above them.

## What was run

Environment: conda env at `./env` with Python 3.12.11, torch 2.8.0, transformers 4.56.0, accelerate 1.10.1, qwen-vl-utils, pymupdf, hydra-core and opencv-python-headless (the README pins, plus cv2, which `backbones/colpali` imports). Hardware: 1×H200, where the paper used 4×V100.
Models: `vidore/colpali-v1.3-merged` and `Qwen/Qwen2.5-VL-7B-Instruct`, both symlinked into `codebase/checkpoints/`. Data: `Lillianwei/Mdocagent-dataset` (MMLongBench and LongDocURL folders), as the README instructs.

Settings that differ from the paper:
- **MAB hyperparameters:** we left them at the code defaults (α=0.8, β=0.01, λ=1, 2 rounds × top-5 nodes). The paper states β=0.1, λ=0.75, m=20, and its λ convention is the reverse of the code's. As a side run on MMLongBench we used the paper's values via a monkeypatch (β=0.1, bandit-confidence weight 0.75, 4 rounds ≈ 20 VLM evaluations). It gave nearly identical results, all within ±0.7 points:

## Discrepancies
- **[code_vs_paper / severity: major] src/mab/thompson_sampling.py ThompsonSamplingBandit.__init__/_compute_score** — paper: score = (1-a)*max LI + a*s_vlm + b*[(1-l)*h_i + l*s_cb], with a=0.8, b=0.1, l=0.75 (Eq. 8, Sec. 4.4). code/other: score = (1-a)*col + a*vlm + b*(l*hits + (1-l)*cb) with a=0.8, b=0.01, l=1 -> the Thompson-sampling confidence s_cb gets zero weight, so the bandit posterior never affects the page ranking (only pages' VLM scores, LI scores and hit counts do). affects results: False. Re-running MMLongBench with the paper's values (b=0.1, cb weight 0.75, ~20 VLM evals) via a monkeypatch gave nearly identical numbers (R@3 69.46 vs 69.14, P@3 34.44 vs 34.32), so the reported numbers do not hinge on it.
- **[code_vs_paper / severity: minor] src/mab/thompson_sampling.py mab_retrieval(m=5, k=10, b=2)** — paper: m = 20 retrieval iterations, one page evaluated per iteration (Alg. 2, Sec. 4.4). code/other: b=2 rounds expanding the top-5 nodes each (<=10 VLM evaluations after initialization, plus one per subquery during hypergraph construction). affects results: False.
- **[code_vs_paper / severity: major] src/mab/document_hypergraph.py construct_query_specific_hypergraph** — paper: h_i = degree of page p_i in the hypergraph H. code/other: h_i = 'hits' counter, with a +20 bonus (best_first_hit_score) for each top-1 page of each subquery and for all top-10 pages of the subquery whose top-1 page got the best VLM score; with b=0.01 this bonus (~0.2-0.45) is a dominant score term. Not described in the paper. affects results: True.
- **[code_vs_paper / severity: minor] src/mab/thompson_sampling.py mab_retrieval (neighbor expansion)** — paper: jump to best unvisited neighbor and score it with Eq. 8. code/other: neighbor's stored vlm_score is multiplied by an undocumented 0.5 penalty (n_penlty) for later re-ranking, but its score at evaluation time uses the unpenalized value. affects results: True.
- **[code_vs_paper / severity: minor] src/retrieval_mab.py run_query_embed** — paper: Q = {atomic subqueries} U {E_q} (Eq. 3), M+1 arms. code/other: arms = atomic subqueries + the comma-joined decomposition + the original query (M+2 arms); the original query is used as the global reference. affects results: False.
- **[code_vs_paper / severity: minor] src/mab/thompson_sampling.py query_vlm_relevance** — paper: Appendix C.2: a single 'detailed + conditional prior' relevance prompt. code/other: dataset-specific prompts: MMLongBench uses the normal / conditional prompt, all other datasets use the detailed prompt without the conditional prior. affects results: True.
- **[code_vs_paper / severity: minor] src/eval_rag.py ndcg_cell** — paper: NDCG with graded relevance rel_i = LI score and IDCG over the ideal ranking of the |gt| relevant pages (Eq. 13-15). code/other: binary relevance, and IDCG assumes all k positions are relevant (num_relevant is computed but unused), i.e. a position-weighted precision. The paper's Table 3 numbers match this code definition, not Eq. 13-15. affects results: True.
- **[code_vs_paper / severity: major] src/eval_rag.py __main__** — paper: Retrieval metrics on MMLongBench and LongDocURL. code/other: always shifts ground-truth pages by -1, but LongDocURL evidence_pages in the released (MDocAgent) data are already 0-indexed (2319/2323 lie in start_end_idx-1; 6 contain page 0). Used as is, LongDocURL R@1 drops from 49.94 to 9.79. The paper's numbers match the unshifted evaluation. File list is hard-coded to paths the retrieval script does not write. affects results: True.
- **[code_vs_paper / severity: major] src/qa_reflection.py (HRRA) / README 'Question Answering: #TODO'** — paper: HRRA re-enters the hypergraph and builds a Query-Focused Page Subgraph in a reflective loop (Sec. 3.4); GPT-4o judge with prompt C.3. code/other: the QA script crashes as released; after fixes it does answer -> self-validation -> basis analysis -> summary -> refined answer on the same top-4 retrieved pages, with no hypergraph re-entry or new retrieval. There is no GPT-4o judging code (eval_qa.py only averages a pre-existing 'binary_correctness' field) and no prompt C.3 in the code. affects results: True.
- **[code_vs_paper / severity: minor] Appendix E vs code** — paper: fixed random seed 42; results are the best of ~3 runs. code/other: no seed is set anywhere (scipy beta.rvs unseeded); a single run. affects results: False.
- **[paper_internal] Table 4 vs Table 2** — paper: Table 2: ColPali (Top-4) / M3DocRAG LongDocURL accuracy = 0.503. code/other: Table 4 'Colpali (Baseline)' LongDocURL = 0.554 (other three datasets equal Table 2's M3DocRAG row); with 0.554, 'w/ MABR' (0.543) would be below the baseline despite being described as an improvement. affects results: False.
