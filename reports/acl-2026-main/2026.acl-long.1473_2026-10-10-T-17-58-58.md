## What was run

Environment: conda env at `env/` with Python 3.12 and the versions pinned in `codebase/uv.lock`: torch 2.5.1+cu121, transformers 4.56.2, transformer-lens 2.16.1, numpy 1.26.4. Hardware: 1×H200. Models came from the HF hub: Qwen/Qwen3-4B, Qwen3-8B, Qwen3-14B (thinking disabled, as in the code), Team-ACE/ToolACE-2.5-Llama-3.1-8B and watt-ai/watt-tool-8B. TransformerLens loads the Llama config from meta-llama/Llama-3.1-8B-Instruct.

For each model, `scripts/run_model.sh <model>` runs the README pipeline from `codebase/` in this order:
1. `scripts/gen_behavior.py <model>`. A thin driver around `utils.data_util.create_data`, the same calls as `behavior_analysis/generate_data.py`. It generates next-token logits for: pair D0–D4, ground_truth D0–D4, counterfactual (substitution) D1, random D0, param_removal / param_addition D1, and the prompt-baseline pair D0–D4. That is 19×5,050 forward passes per model. It skips the random-pairing sets for D1–D4 and the prompt-baseline ground-truth sets, which no reported number uses.
2. `python -m mech_analysis.attribute --model_name M --add 1 --split train --circuit_type {semantic,structural} --trunc 500` (= `run_attribution.sh`)
3. `python -m mech_analysis.scale_search --model_name M --top_n_factor 0.02`. This is the grid search ρ_sem∈{1.1..1.5} × ρ_str∈{0.5..0.9} on val D1. Only k=2% was run, the paper's setting; the script's default also sweeps 1% and 3%.
4. `scripts/select_factor.py M <top_n>`. **Written by us**: it applies the Appendix K selection rule and writes the `best_factor.json` that `evaluate.py` needs.
5. `python -m mech_analysis.evaluate --model_name M` (Table 3 Base and CAA on test D0–D4)

Extras: `python -m mech_analysis.scale_search_single --model_name qwen3-8b --top_n_factor 0.02` for Fig 7, and `python -m mech_analysis.evaluate_compare --model_name qwen3-8b --mode pathway` for Fig 6.
Aggregation: `scripts/aggregate.py` (same TIR logic as the notebooks: rank-0 for Qwen, decoded-prefix check for the Llama models) → `results_summary.json`; `scripts/make_comparisons.py` → `comparisons.json`.

Settings that differ from the paper:
* **Train/val/test template split.** It is not the authors' split, because it depends on the filesystem's `os.listdir` order. Ours is saved in `our_split_templates.json`: 40/20/41 templates, which gives 2,000/1,000/2,050 samples, the same sizes as the paper's (623/2050 = 30.39%, the paper's Qwen3-8B D0 Base). This affects Table 3, the ρ selection, and Fig 6/7, but not Table 1, Fig 3, Fig 4 or Table 4, which use all 5,050 samples.
* **ρ selection (Appendix K).** We read the rule's ambiguous wording ("increase in TIR on semantic counterfactuals no more than 3%") as "TIR on ground-truth-tool samples drops by at most 3 points". ## Discrepancies
* **code_vs_paper (minor, affects results):** the paper uses a 40/20/40 template split. The code builds it with `random.seed(42); random.shuffle(names in os.listdir order)`, so the split depends on the filesystem and the paper's split cannot be regenerated. Probing listdir, sorted, case-insensitive and reversed orders did not recover it (`scripts/split_probe.py`).
* **code_vs_paper (minor, no material effect):** the prompt-baseline instruction is "If none of the tools can be used, point it out." in Appendix L but "If none of the tool can be used, point it out." in the code.
* Note (not a discrepancy): the paper says only Qwen3-4B needed the relaxed 6-point gt threshold. On our split Watt-Tool-8B needed it and Qwen3-4B did not. This follows from the different split.
