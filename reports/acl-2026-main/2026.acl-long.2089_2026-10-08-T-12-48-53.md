## Main finding
The released `main.py` builds `emotion_DataSet('train'|'valid'|'test', tkr)` without passing `args.dataset`. The default in `datasets.py` is `dataset='go_emotion'`. So `python main.py --dataset ED`, which is the README's only command, trains, validates and tests on **GoEmotions** data, using a 32-way ED label-description head.

- **The buggy path reproduces the paper's "ED" row almost exactly.** It gives 65.60 / 65.06 / 56.58 against the paper's 65.52 / 64.95 / 57.34, all within the paper's std for Acc and wF1. The pattern of Macro-F1 sitting 8 points below Acc is also typical of the imbalanced GoEmotions data, not the near-balanced ED data.
- **On the real ED data, after the fix, AML scores much lower.** It gets 60.33 Acc / 59.70 wF1. That is 5.2 points below the paper and level with the TACO number the paper reports (60.57). The claimed +8.17% gain over TACO disappears.
- **The adversarial component itself adds almost nothing.**
  - On ED: λ_adv=0 vs λ_adv=1 is 60.05 vs 60.33 Acc (+0.28). The paper's Table 3 reports +4.63.
  - On GE: 65.42 (λ=0) vs 65.06 (AML), so AML is slightly worse.
  - On the as-released GE-data "ED" path: 65.56 vs 65.60.
- **GE results are within tolerance.** AML gets 65.06 / 64.49 / 56.75 vs the paper's 66.05 / 65.67 / 57.19.

The paper's headline claim is a large ED gain coming from adversarial metric learning. With the correct data, that claim does not hold.

## What was run
Environment: conda env, Python 3.9, torch 2.3.1+cu121, transformers 4.24.0, numpy<2, scikit-learn 1.2.2, pandas, tqdm, wandb. The README specifies py3.7 / torch 1.10, which cannot run on H200 (sm_90).

All commands were run from `codebase/src` (fixed) or `asreleased/src` (pristine `git archive HEAD` copy), with seeds s = 0..4:
```
# AML, ED (fixed loader)
python main.py --dataset ED --topk 10 --seed $s
# AML, GE (the fix has no effect for go_emotion, so these are also the as-released GE numbers)
python main.py --dataset go_emotion --topk 20 --seed $s
# AML, ED as released (unmodified code -> GoEmotions data)
python main.py --dataset ED --seed $s            # in asreleased/src
# Ablation "AML w/o Adv": the same commands with --lambda_adv 0 (ED fixed, GE, ED as-released)
```
Settings match the paper: roberta-base, AdamW lr 2e-5, wd 1e-3, batch 64, λ=1, k=10 (ED) / 20 (GE), T_D = T_E = 1. Epochs (8) and early-stopping patience (4, on dev Acc+wF1) are code defaults; the paper does not state them. The scripts are `scripts/queues.sh`, `scripts/queues2.sh` and `scripts/summarize.py`. Logs are in `logs/`, and per-seed numbers in `logs/summary.json`.

## Discrepancies
1. **Data-loading bug (code_vs_paper, major).** `main.py` and `datasets.py` load GoEmotions for `--dataset ED`. The paper's ED numbers match this buggy path, not real ED.
2. **Discriminator is not adversarial (code_vs_paper, major).** The paper's objective is min_θ max_φ L_aml. In the code, the discriminator does gradient *descent* on the same BCE the encoder minimizes, so the game is cooperative.
3. **Hard-pair mining differs (code_vs_paper, major).**
   - Paper: per-anchor BottomK/TopK, giving |B|·k pairs.
   - Code (`construct_hard_pairs`): the global top-k pairs in the whole batch, only k positives and k negatives per batch.
4. **Extra losses in the code (code_vs_paper, major).**
   - Paper: L_cls is plain cross-entropy.
   - Code: also adds TACO's KMeans cluster-guided supervised contrastive loss (α=0.4) and a label-correlation loss (γ=0.4). These are still present in "w/o Adv" (λ=0), whereas the paper describes that variant as using only L_cls.
5. **Discriminator regularization (code_vs_paper, minor).** The paper uses β=1·Ω(φ). The code has no explicit Ω; it relies on AdamW weight decay 1e-3 and uses a 10× lower discriminator learning rate, which the paper does not mention. D is not symmetrized (the paper calls this optional).
6. **ED split sizes (code_vs_paper, minor).** The released ED split sizes are 17,802 / 2,761 / 2,541, vs Table 1's 19,533 / 2,770 / 2,547. The GE sizes match exactly.
7. **Max-step direction is inconsistent within the paper (paper_internal).** Sec 3.3.3 writes min_θ max_φ, but Algorithm 1 and the text describe the "max" step as gradient descent / minimizing the loss, and Sec 4.4 says the discriminator loss decreases during max-steps.
