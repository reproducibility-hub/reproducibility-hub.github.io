**Memory efficiency and resource-rational encoding in sentence processing** (Xu, Dillon, Futrell, ACL 2026)

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match:** TREND_MATCH overall. Most numbers are within tolerance (Exp 3 and SPR/Maze NSC are essentially exact). The Provo bars are off by about 10–15%, but the paper's conclusions all hold.

- **Codebase completeness:** MISSING_SCRIPTS. The method and almost the whole pipeline are released, but I had to write two data-prep steps myself (the Provo text file and the WikiText-103 binarisation); details below.
- **Wall-clock:** about 12.7 h (2026-09-30 13:40 → 2026-10-01 02:25 CDT). Most of it went to NSC surprisal extraction: 100 noise samples × batch-1 prefixes for the first 512 tokens of each story, about 45–60 min per story per model.

## What the paper claims / what was targeted
The paper trains GPT-2-small-like LMs on WikiText-103 with Gaussian noise injected into the attention value vectors. Precision decays as τ0·exp(−θ·d), and a precision penalty λ ∈ {0, 0.001, 0.01, 0.1, 1} is added to the loss. It also trains a noise-free base GPT-2.
- **Exp 1 (Fig 1c):** the learned θ decays first in lower layers, then spreads to higher layers as λ grows.
- **Exp 2 (Fig 2):** surprisal ΔLL on Provo, SPR NSC and Maze NSC (10-fold CV lmer). WM constraints improve the fit, especially SPR NSC at λ = 0.01 and Provo first fixation. Perplexity rises with λ, extreme surprisals become rarer, and attention becomes locally biased in a non-monotonic way.
- **Exp 3 (Fig 3c, Fig 4):** stronger λ compresses the next-word representation space (smaller pairwise distance). Temporal vs. spatial prepositions become more separable (silhouette score); animacy does not.

## What I ran (commands)
Environment: conda env (python 3.11) with torch 2.14 (cu130), transformers 5.18, accelerate, tiktoken, wordfreq 3.1.1, sklearn, pandas **2.2.3**, plus R 4.3 with lme4, rsample, tidyverse, brms, etc. (conda-forge).

Models and data:
- Released checkpoints from the authors' Google Drive (`gdown --folder`). This includes `ckpt_16000_{gpt2_base,lambda*}.pt`, the authors' own `E3_logprobs/*.npy` and `SPR_processed_RTs.tsv`.
- The HF models `weijiexu97/nanogpt-noisy-*` for Exp 3.
- Provo from OSF (`Provo_Corpus-Eyetracking_Data.csv`).
- NSC text and Maze RTs from github.com/vboyce/natural-stories-maze. `MazeRT.csv` is `Data/cleaned.rds` exported to CSV; its 102,640 critical rows match the authors' notebook output exactly.

All runs used a mirror directory `run/` (symlinks plus copies of the released scripts and notebooks), so `codebase/` is untouched.
1. **Exp 1:** `scripts/exp1_theta.py` reads softplus(_theta) from each released checkpoint. Retraining used `PYTHONPATH=. python train_noisy.py --precision_lambda={0.01,0.001} --out_dir=out` (released defaults, 16k iterations) on WikiText-103 prepared by `scripts/prepare_wikitext103.py`.
2. **Exp 2 surprisal/attention:**
   - `scripts/run_surprisal_subset.py get_Provo_surprisal_attention <all models>`.
   - `scripts/run_surprisal_subset.py get_NSC_surprisal_attention_2phase <model> [start_bs]`, one process per model, run in parallel on one GPU.
   - The wrapper only picks the model subset, the output filename, and optionally the starting batch size for accelerate's auto batch finder.
   - `scripts/merge_nsc.py` merges the per-model CSVs into the single file the released notebooks expect.
3. **Exp 2 preprocessing and stats:**
   - Released notebooks `preprocess_{Provo,NSC,SPRNSC}_RT.ipynb` (nbconvert --execute).
   - Released R scripts `analysis_first_fix_crossval.R`, `analysis_total_RT_crossval.R`, `SPRNSC_stats_analysis_{critical,spillover}.R`, `MazeNSC_stats_analysis.R`.
   - Fig 2b/c come from `scripts/fig2bc.py` and Fig 2d from `scripts/fig2d.py`. These are vectorised re-implementations of `viz_perplexity.R`, `surprisal_breakdown_all.R` and the attention notebooks' aggregation; they print numbers instead of plots.
4. **Exp 3:**
   - Released `get_logprobs.ipynb`, which reran next-word log-probs for 1000 NPs with the HF models and 100 noise samples.
   - Released `analysis_representation_space.ipynb`, run on both the authors' released logprobs and my rerun.
   - `scripts/exp3_distances.py` prints the Fig 3c numbers using the same pipeline.

Settings that differ from the paper: none for the evaluations. The retraining used the released defaults, which are 32×4 = 128 sequences per step; the paper says 256 (see Discrepancies).

## Codebase completeness: MISSING_SCRIPTS
No released source file was edited (`git status` in `codebase/` is clean). Issues and workarounds:
1. **Missing script:** `Provo_corpus_text.csv`, the input to `get_Provo_surprisal_attention.py`, is not released, and nothing in the repo describes how to build it. I wrote `scripts/build_provo_text.py`:
   - It takes one row per interest area from the Provo eyetracking data, ordered by IA_ID.
   - It keeps each passage's first word, which has no ID in the RT data, under a synthetic ID so the model sees the full context.
   - This is the likely source of the small Provo deviations.
2. **Missing script:** WikiText-103 preparation (`data/wikitext-103/{train,val}.bin`) is not released, and the released checkpoints look like they were trained on a differently prepared version. I wrote `scripts/prepare_wikitext103.py` (HF `wikitext-103-raw-v1`, tiktoken GPT-2 BPE, uint16). This affects only my retraining check.
3. **Data step:** `MazeRT.csv` is not in the Maze repo; I exported it from `Data/cleaned.rds`.
4. **Import names:** the code imports `modeling_GPT2Noisy` / `modeling_GPT2`, but the files are named `*_nano.py`. I fixed this with symlinks.
5. **Inconsistent filenames and paths:**
   - The Provo script loads `ckpt_16000_gpt2.pt`, but the Drive file is `ckpt_16000_gpt2_base.pt`.
   - Notebooks and R scripts disagree on `corpus_data/` vs `nsc_corpus_data/` vs `provo_corpus_data/`.
   - All fixed with symlinks.
6. **Dependency pin:** the preprocessing notebooks break with pandas 3.0 (`groupby.apply` drops the grouping columns), so I pinned pandas 2.2.3.
7. **Plotting dependency:** `viz_deltaLL_crossval.R` needs `ggtext`, which I did not install. I read the ΔLL numbers directly from the CSVs it would plot.
8. **Wrapper scripts I wrote** (no logic changes):
   - `run_surprisal_subset.py` runs model subsets in parallel and can lower accelerate's starting batch size to avoid GPU OOM restarts.
   - `merge_nsc.py` merges the per-model NSC CSVs.
   - `fig2bc.py`, `fig2d.py`, `exp3_distances.py` and `exp1_theta.py` print numbers instead of plots, following the released aggregation code.
9. **Missing artefact:** the base GPT-2 model is on Google Drive only, not on HF. This did not block anything.

## Discrepancies
1. **Effective batch size** (code_vs_paper, minor): the paper (App. A) says 256 sequences per step. `train_noisy.py` / the checkpoint configs use batch_size 32 × grad_accum 4 = 128 sequences (65,536 tokens). The code comment "~10 epochs" matches 128.
2. **θ initialisation** (code_vs_paper, minor): the paper says θ ~ N(1, σ² = 0.001). The code uses `randn*1e-3 + 1` (σ = 0.001), and θ is also passed through softplus, so the effective θ starts at about 1.31.
3. **Precision-penalty normaliser** (code_vs_paper, minor): the paper's Eq. 9 uses z = L·H·T(T−1)/2. The code averages over T(T+1)/2 pairs per head, which includes the diagonal.
4. **Biases** (code_vs_paper, minor): the paper says the architecture is the same as GPT-2 small except block size. The code and checkpoints use `bias=False` in Linear and LayerNorm layers, whereas GPT-2 has biases.
5. **Unmentioned analysis option** (not a discrepancy): the RT analysis code also produces a surprisal ≤ 25-filtered ΔLL that the paper never mentions. The paper's figure uses the unfiltered version, which is consistent with the text.
