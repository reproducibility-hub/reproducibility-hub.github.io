# Reproduction report: Safeguarding LLM Fine-tuning via Push-Pull Distributional Alignment (SOT), 2026.acl-long.1083

## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): TREND_MATCH**. Every non-judge number we could compare supports the paper's conclusions:
  - SOT's OT weights separate harmful from benign fine-tuning samples almost perfectly (Fig. 4).
  - The ablation ordering SOT > Pull-only > Push-only holds.
  - SOT keeps AGNews accuracy on par with plain SFT, for all three models we tried.
  - However, our Llama AGNews accuracies are about 5–6 points higher than the paper's, for both SOT and SFT.
- **Result match as released: DOES_NOT_RUN**. The only experiment script (`scripts/run_all_orca.sh`) calls a non-existent `../sota_copy.py` and points at `../datasets/...` and `../models/...`, none of which ship with the repo. There is no generation or evaluation code at all.
- **Coverage: SUBSET.** The paper's headline metrics, Harmlessness Score (HlS) and Helpfulness Score (HpS), are LLM-as-judge scores from **Kimi-latest**, a closed API. No key is configured, so those metrics are `NOT_COMPARABLE` (flag `CLOSED_JUDGE_UNAVAILABLE`). For the main SlimOrca setting and the Table-3 ablations we ran the full pipeline at paper scale and saved all generations, but could not score them. The comparable numbers are:
  - AGNews accuracy (Table 1 and Table 6) on Llama-3.1-8B-Instruct, Qwen3-8B and Llama-3-8B-Instruct;
  - harmful-data filtering recall (Fig. 4, Llama-3.1, SlimOrca).

  Not run:
  - MetaMathQA, GSM8K and LegalBench: all of their metrics are judge-based;
  - gemma-3-4b-it: not cached locally;
  - Figure 2 and the λ / layer sweeps.
- **Codebase completeness: MISSING_SCRIPTS.** The SOT method (feature extraction, push-pull Sinkhorn weight learning, Top-K filtering, weighted LoRA SFT) is implemented in `sota.py`. The data, the data-building script and the evaluation pipeline are missing.

## What was run
Environment: `env/` (Python 3.10, torch 2.6.0+cu124, transformers 4.52.4, peft 0.15.2, datasets 3.5.0, POT 0.9.5, vllm 0.8.5 for generation). flash-attn was not installed; this has no effect, because `get_model` always loads with eager attention regardless of `--flash_attn`. Hardware: 1× H200.

### Data (rebuilt; `my_scripts/build_data.py`, `my_scripts/build_eval.py`)
The SOT repo's script expects `datasets/BlueOrca/train.jsonl`, `datasets/RedOrca/90kslimOrca.jsonl`, `datasets/RedOrca/22400redteaming.jsonl` and `datasets/Beaver_unsafe.jsonl`. None are shipped. The README also references `build_beaver_and_other_dataset.py`, `readme2.md` and data-processing scripts, which are absent too.
- **BlueOrca / RedOrca.** These are the public datasets of SEAL (Shen et al. 2025, github.com/hanshen95/SEAL), stored there as git-LFS objects. We downloaded them via the LFS API (sha256 verified).
  - RedOrca has 112,000 rows. Rows 0–22,399 are HH red-team samples and rows 22,400+ are SlimOrca. We checked that the boundary is exact.
  - From this we built `22400redteaming.jsonl` (rows 0–22,399) and `90kslimOrca.jsonl` (89,600 rows). The file names in the authors' script match these counts exactly.
- **Beaver_unsafe.jsonl**: the first 5,000 `is_safe == False` rows of BeaverTails `30k_train`, following the paper's "first 5,000 harmful samples from BeaverTails".
- **Fine-tuning mixture** (sota.py logic, unchanged): 500 harmful red-team rows plus 4,500 downstream rows, i.e. p = 0.1 and n = 5000. The safe reference is 50 rows; the harmful reference is the 5,000 BeaverTails rows.
- **AGNews** (rebuilt by us):
  - the downstream pool is a random shuffle of the AGNews train split (seed 0);
  - the 50 safe-reference rows are a disjoint random sample from the same split;
  - the test set is 1,000 random AGNews test rows;
  - the harmful part is the same red-team rows.
- **Eval prompts** (App. A.4):
  - 1,000 HH red-team-attempts first-turn prompts not present in the fine-tuning red-team pool;
  - 1,000 held-out SlimOrca rows (rows 10,000+ of `90kslimOrca`).

  The paper's exact random subsets are not released, so these are our own draws.

### Training: paper hyper-parameters (`my_scripts/run_sot.sh` wraps `codebase/sota.py`)
Settings used:
- 250 OT epochs, OT mini-batch 200, λ (`--eta`) = 0.5, Sinkhorn ε (`--reg`) = 0.1, cosine cost, uniform initialisation, last-layer last-token features;
- Top-K = 80%, weighted loss (`--reweighter`, code default `weight_norm=softmax`);
- LoRA r = 16, α = 16, dropout 0, q_proj/v_proj; batch size 1; lr 4e-5 with cosine schedule and 3% warm-up; 2 epochs; bf16.

Runs:
- **Standard SFT** = the same script with `--topp 1.0` and no `--reweighter`. This means no filtering and no reweighting, matching the paper's Standard SFT baseline.
- **Ablations** (Table 3):
  - Pull-only: `--mechanism safety`
  - Push-only: `--mechanism harmful`
  - Top-K-only: no `--reweighter`
  - Reweight-only: `--topp 1.0 --reweighter`
- **Two extra variants**:
  - the released script's own hyper-parameters (`--cost euclidean --reg 0.2 --lr_scheduler constant --learning_rate 1e-5`);
  - the paper's re-normalisation formula (`--weight_norm exp`, a branch we added).
- **Seeds**: 42 for everything; Llama-3.1 AGNews SOT and SFT also with seeds 43 and 44.

### Evaluation (`my_scripts/eval_gen.py`, written by us)
- Generation uses vLLM with greedy decoding and the same `Human: {q}\nAssistant: ` template used in training.
- AGNews prompts use the repo's `build_agnews_prompt`. Accuracy is the first category word in the output compared with the gold label.
- A **strict refusal-keyword rate** on red-team prompts is reported only as a crude supplementary signal. It is NOT the paper's HlS and is not used for any match label.

### Other variants
- **Released-script hyper-parameters** (euclidean cost, ε 0.2, lr 1e-5 constant) on AGNews, Llama-3.1: Acc 0.913, refusal kw 0.623. On SlimOrca these weights give AUC 0.9997 and 98.2% recall at 10%, so filtering is equally good.
- **Paper's re-normalisation** w' = exp(w)/Σexp(w), AGNews, Llama-3.1: Acc 0.913, refusal kw 0.580. This is essentially the same as the code default (0.917 / 0.569), so on AGNews, where Top-K already removes every harmful sample, the formula difference has no measurable effect.
- **Runtime.** OT weight learning took about 4.8 minutes (paper: under 12 minutes). Each LoRA fine-tune took about 10–25 minutes on the H200.

## Discrepancies
1. **code_vs_paper, major**: sample re-normalisation (`sota.py`, `train()`, `weight_norm='softmax'` default).
   - Paper (Sec. 4.2): w'_i = exp(w_i)/Σ_j exp(w_j).
   - Code: softmax((w − max w)/std(w)) · K, i.e. temperature equal to the std of the logits.
   - With the learned logits (range 0.984–1.012, std 0.0036), the paper's formula gives nearly uniform weights (0.993–1.022 × mean). The code gives 0.08–223 × mean, so the "soft emphasis" is much stronger in code. This changes the training weights, but on AGNews we measured no effect (Acc 0.913 vs 0.917; refusal kw 0.58 vs 0.57). The effect on HlS/HpS could not be measured.
2. **code_vs_paper, minor**: the released `run_all_orca.sh` uses `sota.py` defaults for the OT cost and ε: squared-euclidean cost and `--reg 0.2`. The paper uses cosine cost and ε = 0.1. On our features the filtering quality is the same.
3. **code_vs_paper, minor**: the released script uses lr 1e-5 with a constant schedule; Table 5 says 4e-5 with cosine and 0.03 warm-up.
4. **code_vs_paper, minor**: the README example (`--sf_num 5000 --harm_ratio 0.05 --priori cos_dist --topp 0.1`) contradicts the paper's setting (50 safe, p = 0.1, uniform initialisation, top-80%).
5. **code_vs_paper, minor**: the optimiser is `torch.optim.Adam` (betas 0.9/0.95, weight decay 0); Table 5 says AdamW. They are equivalent at weight decay 0 apart from β2.
6. **paper_internal**: Sec. 5.2 says "SOT attains the lowest HlS in every scenario", but HlS is defined as higher-is-better and Table 1 shows SOT with the highest HlS. App. A.5 uses the same inverted wording.
7. **paper_internal**: Sec. 5.3 text gives "Top-K Only … (HlS: 0.205)"; Table 3 gives 0.795.
8. **paper_internal**: App. A.6 says "the full SOT achieves the best results (Avg 0.864)"; Table 3 gives SOT Avg 0.791.
