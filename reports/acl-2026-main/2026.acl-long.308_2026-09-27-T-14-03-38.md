## Summary
- **Table 1 (main result) reproduces.** On both C4/Llama-2-7B and LFQA/Llama-3.1-8B-Instruct, QuantileMark has the best bit accuracy, AUC and TPR@1%FPR. The other 3 (LFQA MPAC TPR and PPL, LFQA QuantileMark PPL) are off by more than 5% relative but keep the paper's conclusion.
- **Table 5** (negatives are unwatermarked generations from the same model) reproduces: 10/12 numbers within tolerance, 2 trend-only, same ranking everywhere.
- **Table 2** (robustness on C4): copy-paste, deletion and DIPPER paraphrase match within tolerance for all three methods, including the paper's own case where MPAC beats QuantileMark on AUC under deletion and paraphrase. **The synonym-substitution attack in the released code is much stronger than in the paper for every method.** Under it, QuantileMark's AUC (0.931) falls below MPAC's (0.971), whereas the paper reports QuantileMark best (0.9963 vs 0.9876). Bit-accuracy ranking under synonyms is preserved. This is the only ranking flip among 68 comparisons.

## What was run
Model/data setup follows Sec. 4.1 of the paper and the repo's `quantile.sh`: 24-bit message, m=2 (M=4 bins), `lefthash_3` seeding, `permute` mapping, top-k=128, τ=1.0, T=300 (exact-length filter), 500 watermarked samples, human references as negatives. MPAC uses γ=0.25, δ=2.0; StealthInk uses γ=0.5 (m=1 in the paper's notation, base=2). PPL is computed with the generating model as oracle (`ORACLE_MODEL=$MODEL_PATH`, as in `quantile.sh`).

- `run_table1.sh` (my wrapper; the same CLI flags as `quantile.sh` with RUN_ATT off):
  `WATERMARK_TYPE={quantile,MPAC,stealthink} DATASET={c4,lfqa} MIN_GEN=500 BS=32 bash run_table1.sh`
  → `generation_pipeline.py` then `evaluation_pipeline.py --evaluation_metrics=all_w_ppl`.
  - C4: `--dataset_name=c4 --dataset_config_name=realnewslike` (note: the repo's loader maps this to `allenai/c4` config `en`, streaming train split), `--input_filtering_strategy=prompt_and_completion_length`, no chat template.
  - LFQA: `--dataset_name=lfqa` (default `--lfqa_source=hf`, `adamjweintraut/eli5_lfqa_best` train split, downloaded to `./data`), `--apply_chat_template=T`, `--wrap_output_in_chat_template=T`.
- `run_attack.sh` (my wrapper; flags from `quantile.sh`'s attack section), applied to the existing C4 generations:
  copy-paste `--cp_attack_type=single-single --cp_attack_insertion_len=80%` (ε=0.2); `synonym-basic --syn_sub_rate=20%`; `word-deletion --deletion_rate=10% --keep_structure=T`; `dipper --lex=20 --order=0` (DIPPER-xxl). Then `evaluation_pipeline.py --evaluation_metrics=z-score`.
- `summarize.py` computes the metrics from each `gen_table_w_metrics.jsonl`, using the same definitions as `evaluation_pipeline.py`:
  - Bit Acc = mean `w_wm_output[_attacked]_bit_acc`.
  - AUC and TPR@1%FPR = ROC of `w_wm_output[_attacked]_z_score` (positives) vs `baseline_completion_z_score` (negatives), with TPR taken at the last threshold where FPR < 1%. Table 5 uses `no_wm_output_z_score` as the negatives instead.
  - PPL = mean `*_ppl`.
  - Time = mean `w_wm_output_decoding_time`.

  I needed my own script because the pipeline logs its summary only to wandb, and offline wandb 0.30 wrote no readable summary file.
- `make_report_tables.py` / `finalize.py` build the comparison table.

### Differences from the paper's setting
- **Model weights:** ungated mirrors of the same checkpoints, from the shared HF cache. `NousResearch/Llama-2-7b-hf` stands in for meta-llama/Llama-2-7b-hf and `unsloth/Meta-Llama-3.1-8B-Instruct` for meta-llama/Llama-3.1-8B-Instruct.
- **Llama-2 model directory:** I created a local dir `models/meta-llama/Llama-2-7b-hf` that symlinks the Nous weights and tokenizer files. It has a corrected `generation_config.json`, because the Nous mirror sets `pad_token_id: 32000`, which is out of vocabulary and crashed `generate` with an embedding index assert. The corrected file uses `pad_token_id: 0`, as in the official meta-llama release. The directory name contains "llama" and "hf", so the repo's own Llama-2 branch in `load_model` is used (slow LlamaTokenizer, pad=0), which is what the authors' `meta-llama/Llama-2-7b-hf` path would trigger.
- **C4 / Llama-2 runs in fp32 (`--load_fp16=F`) instead of fp16.** In fp16, Llama-2-7B produced NaN logits on some sequences (verified in isolation: raw model logits, step 236 of a batch), and `torch.multinomial` then crashed. LFQA runs use fp16 as in the script. This is a precision change only.
- **Hardware/concurrency:** a single H200, with up to 5 jobs sharing it and a CPU-contended node. This affects only detection time.
- **Message:** one random message per run (seed 0), exactly as the repo does.
- **Dataset loading as in the repo:** a single run per setting, no seeds averaged; the paper also reports single numbers.

## Codebase completeness: MINOR_FIXES

Edits to released code (left uncommitted in `./codebase`):
