# Reproduction report: 2026.acl-long.824 — Threshold Differential Attention (TDA)

**Verdict: PARTIALLY_REPRODUCED** — result match (after fixes) **MIXED**, as released **DOES_NOT_RUN** (for the main
experiment; the only runnable released artifact, the TRA kernel benchmark, gives **NO_MATCH**), coverage **SCALED_DOWN**,
codebase completeness **MISSING_SCRIPTS**.

The released repo (https://github.com/snap-research/TDA) has one file, `triton_threshold_attention.py`. It holds the Triton forward/backward kernels for
Threshold Rectified Attention (TRA) and a 10-line `differential_threshold_rela_triton` wrapper (TDA). It contains no model, no training
or data pipeline, no lm-eval or passkey scripts, no benchmark script and no checkpoints. I wrote the GPT-2+RoPE model,
the training loop, and the evaluation/diagnostic/passkey/benchmark scripts myself from the paper's description (Sec. 6, App. C–E).
I then trained Softmax, TRA and TDA with the paper's hyperparameters, but on **6.3B tokens per model instead of about 100B**
(1 H200 GPU, 48 h limit).

Result match as released: the release contains no script for any main experiment (Table 2/3/4, Fig. 1/3), so the unmodified
code cannot produce them (**DOES_NOT_RUN**). The released kernel, run unmodified on Table 5, gives **NO_MATCH**
(≈10× slower than FA2 instead of 1.24–1.29× faster). After fixes (one contiguity fix plus the pipeline I wrote): **MIXED**.
Flags: BASELINE_STRONGER_THAN_REPORTED (passkey Softmax baseline 41% vs the paper's 6% at 4000 tokens).

### Sensitivity run: TDA with the Differential-Transformer λ re-parametrisation (`tda_dt`)

The paper only says λ is "a learned scalar" in (0,1), so I trained a second TDA model (identical otherwise, 12k steps)
with λ = exp(λq1·λk1) − exp(λq2·λk2) + λ_init (Ye et al., 2025), still clamped to [0,1] as in the released wrapper. λ again collapsed toward 0
(final per-layer λ 0.01–0.08), but this variant reaches the paper's relative picture on the short-context benchmarks:

## What was run (exact commands)

All commands are run from `scripts/` in the env `env/` (python 3.11, torch 2.5.1+cu124, triton 3.1.0, flash-attn 2.7.2.post1,
lm_eval 0.4.5, transformers 4.46.3, datasets 2.21.0).

1. Kernel correctness: `python test_kernel.py ../codebase`. This compares TRA forward and dQ/dK/dV against a naive PyTorch reference for fp32/bf16, T∈{64,200,1024},
   p∈{1,2,3}. Relative error is ≤1.4e-2 in fp32 (TF32 dots) and ≤2e-3 in bf16, so the kernel is correct for contiguous inputs.
2. Table 5: `python bench_table5.py ../codebase 12 ../logs/table5_H12.json`. Settings: B=1, H=12, D=64, causal, BF16 inputs,
   median of CUDA-event timings, FA2 = `flash_attn_func(causal=True)`; non-causal FA2 and fwd+bwd are also recorded.
3. Data: pre-tokenized FineWeb-Edu 10B sample (GPT-2 tokenizer, build-nanogpt format; first 100M-token shard = val,
   exactly the paper's "first 100M tokens for validation"), from HF `kjj0/finewebedu10B-gpt2`, shards 0–66.
4. Pretraining (`run_stream.sh`): `python train.py --data ../data --attn {tda,softmax,tra} --out ../runs/<attn> --max_steps 12000 --B 32`.
   GPT-2 small (12L/12H/768d, tied embeddings, 124M params; TDA 138M because of the second q/k projections), RoPE θ=10000,
   context 1024, 524,288 tokens/step, AdamW(0.9,0.95) with wd 0.1, lr 1e-3 → 1e-4 cosine with 715 warmup steps, grad-clip 1.0,
   seed 1337, bf16 autocast, val every 250 steps on 20 batches. TRA/TDA: q,k L2-normalised, τ_i = β√(2 log(i+1)/d), β=1, κ=1,
   p=2 (released kernel), per-head RMSNorm on the attention output (paper's "Norm = RMSNorm"). TDA: two q/k projections, one v,
   output = Norm(O1 − clamp(λ,0,1)·O2), with λ a learnable per-layer scalar initialised to 0.8−0.6·exp(−0.3·l).
5. Evaluation (`post_model.sh`): `python evaluate_model.py --ckpt ../runs/<attn>/final.pt --out ../results/eval_<attn>.json`. This computes:
   val loss (6.5M val tokens, plus a 327k-token subset), sparsity (App. E.1: fraction of exact zeros among causal entries of the
   mechanism's weight matrix, i.e. ΔA for TDA, averaged over layers/heads and 16 random 1024-token val sequences), gSinkRatio(1)
   (Sec. 3 definition, ℓ1-normalised |A| rows, T ∈ {64..1024}), and lm-eval-harness zero-shot (hellaswag, arc_easy, arc_challenge,
   openbookqa, piqa, winogrande; acc/acc_norm) via a custom `LM` wrapper around our model (tiktoken GPT-2 tokenizer).
6. Context extension + passkey (Sec. 6.3/App. D), Softmax and TDA only (as in Fig. 3):
   `python train.py --attn <a> --init_from ../runs/<a>/final.pt --rope_scale 4 --T 4096 --B 8 --max_steps 500 --warmup 50 --max_lr 1e-4 --min_lr 1e-5 --start_shard 63`
   (NTK-aware RoPE ×4, 500 extra steps on unseen shards), then `python passkey.py --ckpt ../runs/<a>_ext4k/final.pt`
   (App. D prompt, 100 trials per length with seeded random passkeys and positions, greedy decoding, integer match).
   Also `passkey.py` on the un-extended 1024-context models at 500/1000 tokens.
7. Sensitivity run (not in the paper): TDA with the Differential-Transformer λ re-parametrisation (`--attn tda_dt`, otherwise identical).

## Settings that differ from the paper

- **Training tokens: 12,000 steps × 524,288 = 6.3B tokens per model** (paper: 5 "epochs" × 38,146 steps ≈ 190,730 steps ≈ 100B
  tokens on 8×A100). The cosine schedule is compressed to 12k steps. This is the only way to fit three models into 48 h on 1 GPU.
- Micro-batch 32 instead of 16 (same 524,288-token global batch; only gradient-accumulation count differs).
- Hardware: 1×H200 instead of 8×A100 (this affects the Table 5 absolute latencies).
- Unspecified details that I chose: tied embeddings (paper says "GPT-2-162M"); TDA head layout (12 heads × 64 dims, two
  q/k sets); λ parametrisation/initialisation; per-head RMSNorm placement; no (1−λ_init) output scaling; no learnable β (β=1 fixed,
  as in Sec. 6; the released kernel cannot learn β anyway); context-extension length (4096), NTK factor (4) and extension LR;
  passkey prompt-length targeting; Table 5 B/H/D and fwd-only timing.
- Baselines: only Softmax (which needs no released code) was run. Gated Softmax, SSMax, Entmax, LSSAR, ReLA, Diff-Softmax,
  Dex and Diff-ReLA are not in the release; I did not reconstruct them. SCROLLS (Table 3), multi-needle (Table 4), the
  hyper-parameter study (Table 6) and the appendix diagnostics were not run (the release contains no code or data-format details for them,
  and there was not enough compute).
- Single run/seed per model, as in the paper ("single-run results").

## Why the main claim is only partially reproduced

- Supported: ultra-sparsity (~98–99% exact zeros), no attention sink (gSinkRatio < 1 and non-increasing with length, while
  Softmax's grows), and zero-shot accuracy on par with Softmax. TDA also beats single-view TRA on val loss.
- Depends on implementation: val-loss parity with Softmax. With a plain learnable λ (the simplest reading of the release), TDA
  is 0.015 nats worse than Softmax. With the Differential-Transformer λ re-parametrisation it ties (+0.0006), as in the paper.
- Not supported: (ii) Long-context passkey retrieval is dramatically *worse* for TDA than for Softmax, both after the paper's NTK + 500-step
  extension recipe and inside the training context. Our Softmax baseline is much stronger than the paper's (41% vs 6% at
  4000 tokens). (iii) The efficiency claim does not hold for the released kernel.
- Caveats: 16× fewer training tokens than the paper. Several TDA details are unspecified; λ collapsed toward 0 under both parametrisations we tried.
  The extension/passkey protocol details (extension length, LR) are guesses. Baselines other than Softmax were not run.

Edits to the released code (uncommitted in `codebase/`, diff in `logs/codebase.diff`):
- `triton_threshold_attention.py`, `ThresholdRelaFunction.forward`: `q, k, v = q.contiguous(), k.contiguous(), v.contiguous()`;
  `backward`: `dout = dout.contiguous()`. The kernels index the flattened batch×head dimension as `pid_bh * stride(1)`, which is only
  valid for contiguous tensors. With the standard `view(B,T,H,D).transpose(1,2)` layout used in GPT code, the kernel silently returns
  wrong outputs (max abs error 0.07 in a small test) and gave NaN losses in training. The fix doesn't change the method.

for compatibility with torch 2.5 / lm_eval 0.4.5.

## Discrepancies

1. code_vs_paper (major, affects results): Sec. 6.5/Table 5 attribute TRA's speed-ups to sparsity "which reduces value aggregation
   cost". The released kernel computes a dense `tl.dot(P, V)` for every key block (no sparsity-based skipping). It also doesn't skip fully
   masked causal blocks, and it up-casts BF16 inputs to FP32 (TF32 tensor-core dots) although the benchmark is "under BF16". Measured result: ≈10× slower
   than FA2 at long context instead of 1.24–1.29× faster.
2. code_vs_paper (minor, no effect at the paper's settings): Sec. 4.1 calls β "a learnable scalar". The released autograd function
   converts β to a Python float and returns no gradient, so β cannot be learned.
3. code_vs_paper (minor, no effect with κ=1): τ_i = β√(2 log((i+1)/κ)/d) in the paper and App. C; the code has no κ (uses log(i+1)).
4. code_vs_paper (minor): the paper's TDA output is Norm(Σ Δa v) with RMSNorm and a learned λ ∈ (0,1). The released TDA function has no
   normalisation and takes λ as an external tensor clamped to [0,1], so the λ parametrisation and initialisation are unspecified. This affects results: with a plain
   learnable λ TDA is 0.015 nats worse than Softmax, and with the Differential-Transformer re-parametrisation it ties.
5. paper_internal: Sec. 6.6 says "β=1.0 achieving the best validation loss", but Table 6b lists β=0.8 with a lower loss (3.1140 < 3.1190).
6. paper_internal: App. E.3 says "5 epochs with 38,146 steps per epoch" at 524,288 tokens/step. That is 20B tokens per "epoch", twice
   the 10B-token dataset described in Sec. 6 (≈100B tokens total, i.e. ~10 passes).
7. paper_internal: Sec. 4.1 says β is learnable, but Sec. 6 fixes β = 1 for all experiments (and Table 6b treats it as a hyper-parameter).
