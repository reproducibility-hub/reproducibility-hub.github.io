# Reproduction report: LegalGraphRAG (ACL 2026, 2026.acl-long.1738)

**Verdict: PARTIALLY_REPRODUCED.** Result match: **MIXED** (same as released, since no source code was edited). Coverage: **SUBSET**. Codebase completeness: **MINOR_FIXES**.

## Summary
- **Code:** https://github.com/XMUDeepLIT/LegalGraphRAG, cloned to `./codebase` at commit `a3c9c30`. The release includes the method, the 14,049-case retrieval corpus, both evaluation sets (CAIL 568 cases; CMDL 1,374 defendant records), the criminal-law resource, a main-experiment config (`configs/main.env`) and the evaluator. Baselines are not included; the README says so.
- **Main experiment:** LegalGraphRAG with the Qwen3-8B backbone, run on CAIL and CMDL at full scale (Table 2's LegalGraphRAG row). Two full CAIL runs were done because decoding is stochastic. The three retrieval-operator ablations from Table 3 that the config exposes were also run at full scale.
- **What reproduces:**
  - The headline overall numbers. CAIL charge ACC/F1 is **38.9/50.4**, and **39.0/50.5** on the repeat run, against the paper's 40.9/52.8 (Table 3, Fig. 9). Both are within 5% relative.
  - The Table 2 "Average All" of 49.5. Our mean of the CAIL and CMDL overall ACC is **49.0**.
  - The overall CMDL ACC of **59.2** is close to the repo's archived CMDL output (57.6 ACC). Its F1 of 65.5 is above the archived 61.7.
- **What does not reproduce:**
  - **Per-category numbers in Table 2 are mixed.** 6 of 16 are within tolerance. Public Safety is 9–12 points below the paper on both datasets, and CMDL Social Order is 5–7 points above.
  - **Appendix tasks miss clearly.** Law-article ACC is 41.5 vs 47.9 (Table 5). Term-of-penalty MAE is 37.9 vs 20.1 months, and 35.4 on the repeat run (Table 6).
  - **One ablation effect is missing.** Removing Semantic Match causes no drop (ours 38.9 vs full 38.95; paper −1.8). The community-expansion and charge-anchored ablations do drop, as claimed (−1.1 and −2.9; paper −2.4 and −1.6).
- **Not testable:** the "beats baselines / SOTA" claims (Table 2 other rows, Tables 4–6 baselines), because no baseline code is released. These are `NOT_COMPARABLE`.
  - Our CAIL Public Safety and CMDL Public Safety per-category numbers would fall below several baseline numbers *as the paper reports them*.
  - Our 49.0 average would still beat every baseline average in Table 2 (best 43.1).
  - Table 4 needs GPT-4o-mini / DeepSeek-V3.1 APIs and was not run.

## What I ran
Environment:
- conda env `./env` with python 3.11, torch 2.6.0+cu124 and transformers 4.51.3 (the README minimums), plus `requirements.txt`, sentence-transformers, fastapi and uvicorn.
- Models: `Qwen/Qwen3-8B` and `BAAI/bge-m3` from the shared HF cache.
- One H200 GPU.

Steps (cwd = `codebase/`, `PYTHONPATH=.`):
1. **Data check.** `sha256sum -c datas/main_experiment/SHA256SUMS` passed for every file.
2. **Embedding service.** Ollama is not installed, so `tools/embed_server.py` serves an Ollama-compatible `POST /api/embed` on `localhost:11434` with BGE-m3 (fp16, normalised dense vectors). The config's `embedding_api_url` and `embedding_model` are unchanged.
3. **Graph construction** (equivalent to `run.py --force-rebuild`): `python ../tools/run_resumable.py --build --build_only --devices cuda:0` with `configs/main.env`.
   - Result: 14,047 case nodes (2 corpus cases have no `criminal_acts` and are skipped by the code), 487 law nodes (after deleting articles ≤101), 601 crime nodes and 60 Louvain communities.
   - Community summaries were written by Qwen3-8B. The build took 2,001 s (paper Table 7: 3,687 s).
4. **Main runs** (`tools/run_main.sh`):
   - Command: `python ../tools/run_resumable.py --datasets {CAIL,CMDL} --devices cuda:0 ×7` with the unmodified `configs/main.env` (top_k = 5 for both retrieval operators, all three operators on, zh prompts).
   - 7 Qwen3-8B worker processes share the GPU.
   - Wall time: CAIL 7,116 s and CMDL 9,300 s, with 0 per-case errors.
5. **Evaluation:** `python evaluation/evaluate_results.py --results outputs/main_experiment/{CAIL,CMDL}/qwen3_results_combined.json`. This is the README's Table 2 protocol: the `overall` row and the per-category rows in `_metrics.csv`.
6. **Ablations** (`tools/run_ablations.sh`), each on CAIL with one config flag turned off:
   - `--direct_retrieve False` gives w/o Semantic Match.
   - `--top_retrieve False` gives w/o Community Expansion.
   - `--augment_retrieve False` gives w/o Charge-Anchored.
   - The w/o HierarGraph, w/o Researcher and w/o Auditor ablations are not exposed by the code and were not run.
7. **Repeat of the full CAIL run** (`tools/run_repeat.sh`) to measure run-to-run variance. Qwen3 samples at T=0.6 (see discrepancies).
8. **Check of the released entry point.** The unmodified `run.py --no-build-graph` was run on 4 CAIL cases with 2 workers. It works and writes the same output schema.

`tools/run_resumable.py` is a thin driver that calls the same `LegalGraphRAG.build_graph` / `analyze_case` as `run.py`. It differs in three ways, none of which change per-case computation:
- It writes one JSON line per case, so a crash or kill keeps finished cases.
- It records a per-case exception instead of crashing. This never triggered.
- It load-balances cases across workers by number of defendants. `run.py` assigns case `i` to worker `i % n`.

`tools/summarize.py` and `tools/write_status.py` build the comparison table below.

### Settings that differ from the paper
- **Embeddings:** BGE-m3 via sentence-transformers fp16 instead of Ollama's bge-m3 GGUF. Same model; small numerical differences are possible.
- **Graph-construction LLM:** Qwen3-8B. The paper says GPT-4o-mini, but the code always uses the backbone; see discrepancies.
- **Decoding:** Qwen3's default sampling, exactly as the released code does it. Two CAIL runs give 38.9 and 39.0 ACC.
- **Workers:** 7 processes on one GPU instead of the README's 2 GPUs. This does not affect results.

## Discrepancies
Code vs. paper:
1. **Charge-Anchored Retrieval (major).**
   - Paper (Eq. 11): retrieves the neighbouring *cases* of each predicted charge in the Fact Graph.
   - Code (`util.retrieve_law` → `feature_graph.query_similar_laws`): the LLM-predicted charges are matched to the top-1 Crime node, and the *law articles* linked to it are returned. No cases are retrieved by this operator.
2. **Community detection (major).**
   - Paper (Sec. 4.2): Leiden algorithm.
   - Code: networkx `louvain_communities(seed=42)` over the whole graph (cases, laws and crimes).
3. **No judicial interpretations in the main-experiment Rule Graph (major).**
   - Paper (Sec. 4.2, Table 10): links 452 articles to 656 judicial interpretations, which the Auditor uses.
   - Code: `configs/main.env` points to `datas/main_experiment/criminal_law_processed.json`, whose `related_laws` is non-empty for only 54 of 590 items, and those entries are cross-referenced articles, not interpretations.
   - `raw_data/judicial_explanations.json` (657 entries) is merged only into the small demo file `datas/law_to_crime.json`.
4. **Graph-construction LLM (minor).**
   - Paper: GPT-4o-mini.
   - Code: community summaries come from the backbone model (Qwen3-8B here). Case features ship pre-extracted, and `env.example` defaults the feature-extraction script to deepseek-chat.
5. **Extra LLM reranking (minor).**
   - Paper (Eqs. 9–10): plain top-k similarity.
   - Code: takes the top-5 communities, LLM-reranks them, expands the top 2 (k=5 cases each), and also LLM-reranks / filters both candidate case lists.
6. **Decoding settings (minor).**
   - `configs/main.env` sets `temperature=0.1`, but it is never passed to `generate()`. Qwen3's own generation config applies (`do_sample=True`, T=0.6, top_p=0.95, top_k=20), so runs are non-deterministic.
   - The paper does not state decoding settings.

Paper-internal:
1. Obs.1 says LegalGraphRAG improves "6.3% to 19.1%" over baselines, but Table 2's Δ column ranges from 6.3 to 28.2.
2. Table 2's "Average All" for LegalGraphRAG is 49.5, which is not the mean of its eight per-category ACCs (51.3). It is consistent with the mean of the overall CAIL ACC (40.9) and an overall CMDL ACC (~58), and Table 2 never reports the latter.
