## What the paper claims / what I targeted

Table 1: ACC/ARI/NMI of TLSA on BANKING, CLINC, HWU (bert-base-uncased) and THUCNews (bert-base-chinese) at known-class
ratios ρ ∈ {0.25, 0.5, 0.75}, 10 % labeled known-class data, averaged over 3 seeds, with locally deployed DeepSeek-V3 as the LLM.
Ablations (Table 2), Top-k / sampling analyses and the prompt/LLM studies (Table S1 etc.) were **not** run.

## Setup actually used

- Env: conda env at `./env` (Python 3.11, torch 2.13+cu130, transformers 5.18, vLLM 0.30, langchain-openai), 1× H200.
- **LLM substitution.** The paper uses locally deployed **DeepSeek-V3** (671B). It cannot be hosted on one GPU and no API key
  was available, so I served **google/gemma-3-27b-it** (bf16) with vLLM (`--max-model-len 131072`, prefix caching,
  temperature 0 as in the code). The paper itself evaluates Gemma-3-27B as an alternative backend (Table S1, BANKING ρ=0.25:
  74.02 ACC vs 74.97 with DeepSeek-V3), so this is a documented, small-gap substitute. It is still a different LLM, and this
  is the most likely cause of the systematic shortfall. THUCNews prompts contain up to 60 full news articles (30–60k tokens),
  so a long context window is required.
- Hyper-parameters: exactly those in the released `scripts/run_*_0.5.sh` (100 warm-up epochs with patience 20, 40 phase-2
  epochs, batch 48 (THUCNews 24), lr 1e-4/1e-3, τ=0.07, α=0.5, top-k=5, r_h 0.15→0.40, r_l=0.25, k_h/k_m/k_l = 8/12/16,
  label refinement from epoch 5, MLP heads). The released scripts only cover ρ=0.5 and seed 2. I used the same
  settings for ρ=0.25/0.75 via the CLI (`--known_cls_ratio`) and seeds {0,1,2}; the paper does not state its seeds.
- Launcher: `run_one.sh <dataset> <ratio> <seed>` (mirrors the released scripts, sets `LLM_MODEL/LLM_BASE_URL/LLM_API_KEY`
  to the local vLLM server); queues: `xargs -P 12` over `jobs_en.txt`, then `xargs -P 3` over `jobs_th.txt`.
  Outputs: `runs/<dataset>_<ratio>_<seed>/{stdout.log,training_summary.json}`. Aggregation: `aggregate.py` → `results_summary.json`;
  `make_status.py` → `comparisons.json`.
- vLLM: `VLLM_USE_FLASHINFER_SAMPLER=0` (flashinfer's sampler JIT needs nvcc, which is absent). The server was restarted
  3 times during the experiment (context length, max-num-seqs, memory headroom). The released client retries forever, so runs
  just waited. All 36 reported runs started after the final 128k-context configuration except that the memory fraction was
  lowered once, at 18:50, while the seed-1 English runs and THUCNews seed 2 were in progress (same model and settings).

## Codebase completeness: MINOR_FIXES

The release contains the full method (dual encoder, symmetric hard-negative contrastive loss, Hungarian novel-cluster detection,
LLM label induction, graph-based forced renaming, confidence-bucketed LLM verification, linear r_h schedule) and the
datasets with fixed splits and known-class lists for all three ratios. Missing or needed pieces:
- An LLM endpoint must be supplied (`LLM_MODEL/LLM_BASE_URL/LLM_API_KEY`, empty in the scripts). The paper's
  DeepSeek-V3 was not available, so I used Gemma-3-27B through vLLM.
- Scripts only for ρ=0.5 and a single seed (2). The other ratios and seeds need CLI changes only.
- BERT checkpoints must be placed in `pretrained_models/` (I symlinked the HF-cache copies of bert-base-uncased / bert-base-chinese).

Code changes I made in `./codebase` (uncommitted; `git -C codebase diff`). All are performance-only, needed to fit
36 runs (each about 40 × (KMeans + 100–300 LLM calls)) into 48 h on one GPU and 7 CPU cores:
1. `trainer.py::_generate_labels_for_novel_clusters` and `_create_phase2_dataloader`: the per-cluster LLM calls (label
   generation, sample verification) are dispatched concurrently through a thread pool (`LLM_PARALLEL_CALLS`, 16, or 4 for
   THUCNews). All random sampling still happens sequentially in the original order (identical RNG stream), and results are
   consumed in the original order, so the pseudo-label set is constructed exactly as before.
2. `trainer.py::_extract_unlabeled_features_and_texts` / `_extract_labeled_features_and_texts`: batched (256) forward passes
   instead of one sample at a time. Eval mode with fixed-length padding gives the same features up to float noise.
3. `clustering.py` + one call in `trainer.py::_discover_novel_clusters_hungarian`: the **per-epoch** pseudo-labelling KMeans
   uses a torch/GPU port of sklearn's KMeans (greedy k-means++ init, Lloyd iterations, n_init=10, tol=1e-4·mean-var,
   empty-cluster relocation, best inertia). The per-epoch silhouette, which is only logged, is computed exactly on the GPU.
   The **final test-set evaluation still uses sklearn KMeans** (unchanged metric protocol). This is the only change
   that can alter results, through different random restarts of the same algorithm. On synthetic data its inertia was within
   0.3 % of sklearn's.

Scripts I wrote outside the codebase: `run_one.sh`, `run_one_orig.sh`, `progress.sh`, `w.sh`, `w2.sh`, `aggregate.py`,
`make_status.py`, `make_report.py`.

## Discrepancies

- None found between the released code and the paper's method description (loss Eq. 3–6, confidence Eq. 7/9, Hungarian
  matching, θ_sim graph refinement, bucket sampling Eq. 10, r_h schedule Eq. 12, k_h/k_m/k_l, α, top-k all match).
  Several values are not given in the paper but fixed in code (margin m=0.4, θ_sim=0.96, r_l=0.25, lr, epochs, early stopping
  on dev known-class accuracy, refinement start epoch 5). These are unspecified rather than contradictory.
- No internal paper inconsistencies found. The relative-improvement numbers in §5.2 (3.56 % / 4.20 % / 1.55 % at ρ=0.25)
  recompute correctly from Table 1, and Table S1's DeepSeek-V3 row equals Table 1.

## Why it is not fully reproduced

1. **Different LLM** (Gemma-3-27B vs DeepSeek-V3; external, no access to the paper's backend). The LLM produces the novel-class
   names, the forced renaming and the per-sample pseudo-label verification, so it directly affects the training signal.
2. Seed variance (THUCNews ρ=0.25 std ≈ 4 ACC) and unknown paper seeds.
3. GPU KMeans for the per-epoch pseudo-labels (same algorithm, different random restarts).
4. Baselines are not released, so the "beats SOTA" claim can only be checked against the paper's own baseline numbers,
   which were themselves computed with DeepSeek-V3.
