## Discrepancies

**Code vs paper.** All of these were verified in the code; many are also listed in the authors' own `CAP_TTA_provenance_and_data_audit_EN.md`.

1. **(major) Online preconditioned steps.** The paper (§4.5, App. A) says CAP-TTA uses "ten preconditioned steps". In `tta_lora_update_precond` the docstring says "One preconditioned update step", and `run_main_experiments` calls it once per routed type. `precond_steps=10` only sets the number of offline gradient-collection steps in `estimate_preconditioner_diag`. The latency comparison against 10-step SGD/AdamW is therefore not like-for-like: per step, precond is slower than SGD in our measurement.
2. **(major) Trigger committee decoding.** `ToxicityModel.p_toxic` applies softmax over all labels. `unitary/toxic-bert` and `unitary/unbiased-toxic-roberta` are `multi_label_classification` models and need a sigmoid. This changes every trigger score, trigger decision, routed type and update. Example: toxic-bert gives 0.53 on "Black holes are fascinating objects in astrophysics."
3. **(major) TTA loss.** The paper's objective is −log p(safe | history). The code computes LM loss with `labels=input_ids` on `history + "\n\n" + safe_text`, which trains on the history tokens too, does not mask padding, and truncates to 256 tokens from the left context.
4. **(major) LoRA target modules.** The paper lists q, k, v, o, gate, up and down projections. The code (`attach_lora`) targets only `q_proj`, `k_proj`, `v_proj`, `o_proj`.
5. **(minor) Hyperparameters.**
   - Precond learning rate: paper 1e-3, code 3e-4.
   - max_delta_norm: paper 0.25, code 0.5.
   - CAP-TTA update max length: paper 384, code 256.
   - Fisher damping: paper λ = 1e-4, code `lambda_reg` = 1e-3.
   - SGD/AdamW batch size: paper 4, code safe_k = 2.
   - Trig-2 ε: paper 0.22, code 0.18. With the paper's 0.22 we match the trigger rate but not the bias; the paper's row cannot be tied to one config.
   - Trig-2 "precond_steps=4": in the code this is the number of preconditioner-estimation steps, not online steps.
   - RTP scanning: the paper says it scans up to 50k prompts; the code takes the first 9,000 prompts with toxicity ≥ 0.4.
6. **(minor) Reporting unit.** Table 3/4 ± values are standard deviations over segment rows (1,200 rows), not over prompts. The released generator has no `groupby(prompt_id)`.
7. **(minor) Output post-processing.** TTA generation strips `<think>…</think>`; the static baseline generation does not. This is a small protocol difference between the TTA rows and the baseline rows.
