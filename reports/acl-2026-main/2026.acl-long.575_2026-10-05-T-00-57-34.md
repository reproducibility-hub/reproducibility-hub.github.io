## 1. What the paper claims and what I targeted

The paper fits regularized linear regressions (statsmodels OLS / Lasso / Ridge, with hyperparameters tuned on a held-out split, then 10-fold CV) that predict word-level eye-tracking measures (first fixation FFD, gaze duration GD, total reading time TRT). It reports ΔMSE against a baseline of length/frequency features (+ previous word) on Provo (English) and MECO (English, Greek, Hebrew, Russian, Turkish). The predictors are mGPT-derived: surprisal, layer-wise representations h (2048-d), information value v, and logit-lens surprisal s_LL, plus the combinations repr+s, repr+v, repr+s_LL.
Headline claims, all from **Table 1 / Table 2 (Figures 2/3 plot the same runs)**:
- C1: early-layer representations beat surprisal on early-pass measures (FFD, GD) in English.
- C2: for TRT, scalar surprisal is usually better than representations, despite being far more compressed.
- C3: repr+s improves over representations alone, and usually over surprisal too.
- C4: the best predictor varies strongly across languages and measures. Information value is best at early/intermediate layers, and logit-lens surprisal at late layers.

## 3. Results — Tables 1 and 2 (mGPT), paper vs. ours

ΔMSE = MSE(target) − MSE(baseline), mean over the 10 CV folds, with the std across folds in parentheses and the best layer in brackets (negative = better than baseline). The code and the notebook compute target − baseline, even though the captions say "baseline − target"; see Discrepancies. Match rule: NUMBERS_MATCH if |ours − paper| ≤ the paper's reported fold std, or ≤ 5 % relative, or ≤ 1 ms.

Summary: **125/126 cells NUMBERS_MATCH; 1 TREND_MATCH** (Hebrew TRT best v: −86.5 vs −53.6, same layer 24). By stricter criteria, 96/126 cells are within 5 % of the paper's value (111/126 within 10 %), and the best layer is identical in 88/108 layer-indexed cells. The least exact cells are information value, because it is a Monte-Carlo estimate (k=50 sampled continuations), and the Turkish cells, which needed data repairs.

## 5. Significance of combined models over scalars (Table 2 caption, §6.1, App. B)

The paper states: "None of the models in the combined settings were significant over their respective scalars, e.g. repr+s over surprisal". §6.1 adds that the gains "tend to be significant over representations but not over scalars". In the released `significance.py`, `mix_vs_scalar()` first loads the scalar's squared errors and then overwrites them with the combined model's own errors:

`base_sq_error = pd.read_csv(mpath / featureset / "predictions.csv")[sq_err_col]`

So it tests every combined model against itself, and p = 1.0 always (I reproduced this: 0/54 significant). With the scalar's errors actually used, **12 of the 54 best-layer combined cells are significant over their scalar at p < 0.001**: Provo FFD repr+s and repr+s_LL; MECO-English GD and TRT for all three combinations; Greek TRT repr+v; Hebrew TRT for all three (`results_significance.csv`). This paper statement is therefore an artifact of a code bug. It does not change any ΔMSE value.

## 6. Extra check: representation definition (Eq. 15) vs. code

Eq. 15 defines the unit representation as the mean of the hidden states **at the unit's own tokens**. `score_embed.py` stores `hstates[l][0][:-1]` paired with `input_ids[1:]`, so each token gets the hidden state of the **preceding** position. That is the state that predicts the token, before the model has read it. I verified the one-token shift numerically: the released vectors equal the Eq. 15 vectors shifted by one position. I re-extracted the Provo representations following Eq. 15 (`extra/score_embed_eq15.py`, a one-line change) and re-ran the embedding and repr+s CV with the same released hyperparameters (`extra/eq15_results.txt`):

| Provo | released (shifted) best ΔMSE [layer] | Eq. 15 best ΔMSE [layer] | surprisal |
|---|---|---|---|
| h, FFD | −17.06 [2] | −25.79 [6] | −2.31 |
| repr+s, FFD | −20.29 [2] | −29.97 [6] | −2.31 |
| h, GD | −55.39 [5] | −117.07 [3] | −40.47 |
| repr+s, GD | −94.17 [6] | −143.75 [3] | −40.47 |
| h, TRT | −196.41 [2] | −245.91 [8] | −293.98 |
| repr+s, TRT | −398.05 [2] | −413.35 [13] | −293.98 |

The paper's numbers come from the shifted variant. The Eq. 15 variant is much stronger: GD gains roughly double, and the best layers move deeper (3–8 instead of 2–5). The qualitative conclusions on Provo still hold: h beats surprisal on FFD and GD, and surprisal still beats h on TRT. These runs reuse hyperparameters tuned on the shifted features (not re-tuned).

## 7. Codebase completeness: MAJOR_FIXES

All method code and the pipeline scripts are released, and Provo runs end-to-end without edits. Making all of MECO run required fixes to data alignment, which is pipeline logic. Without them, Table 1's v column and Table 2's repr+v column for MECO, and the whole MECO-Turkish block, cannot be produced. Changes, from least to most invasive:

1. **Environment** (minor): installed only the needed subset of the bloated `requirements.txt`, at the pinned versions.
2. **Hyperparameter file names** (config): the released MECO tuning files for `mix_logitlens` and `mix_infoval` (English/Greek/Hebrew/Russian) are named `*_layer_XX.csv`, but `meco_crossval.py` reads `*_XX.csv`, so every MECO repr+s_LL / repr+v run crashed with FileNotFoundError. Fix: copies under the expected names (no code change).
3. **`codebase/tok2w_meco.py`** (code edit, uncommitted; added an opt-in `--iv_dir` flag, default behaviour unchanged): the released script attaches information value with a row-wise `new_df.join(iv)`. The infovalue file has one row per whitespace word of the polybox plaintext, minus punctuation-only words that `score_infovalue.py` skips (e.g. "–"). That plaintext merges hyphenated MECO interest areas ("performance-" + "enhancing" → "performance-enhancing"), so the rows do not line up with the eye-tracking IAs. For example, English has 2081 infovalue rows for 2095 IA rows. The values shift relative to their words and the tail becomes NaN, and `meco_crossval.py` then crashes for every MECO infoval/repr+v run (`MissingDataError: exog contains inf or nans`). Fix:
   - recompute infovalue on one-word-per-IA texts made with the repo's own `meco_csv_to_text.py`;
   - merge on (document, word position) instead of row order;
   - set the 0–3 punctuation-only IAs per language to 0.
4. **MECO-Turkish data** (data repair; the released `tok2w_meco.py` crashes with "All arrays must be of the same length"): in `merged_data_no_zero/tr.csv`, doc 3 lacks an IA for the word "ilaçların" that the plaintext contains, and doc 8 has a spurious empty IA (ianum 29, all measures NA). Doc 9 "de" also has NA for all three measures, i.e. no reader fixated it. Fix:
   - drop the empty IA;
   - set the NA reading times of doc 9 "de" to 0, following the codebase's own Provo convention (mean = 0 when no valid fixation);
   - score Turkish (surprisal, embeddings, logit lens, infovalue) on the one-word-per-IA text built from the cleaned CSV.
5. No changes to the regression, tuning, CV or significance code. The `mix_vs_scalar` bug (section 5) was left in place, and I computed the corrected comparison separately.

Scripts I wrote are listed in section 2. All of them only orchestrate or aggregate the released scripts. The exceptions are `extra/score_embed_eq15.py` (the Eq. 15 check, not used for the main tables) and the corrected scalar test in `extra/significance_mgpt.py`.

As released (no source edits, only data downloads and config-level file renames): Provo Tables 1/2 completely, and MECO English/Greek/Hebrew/Russian for surprisal, h, s_LL, repr+s and repr+s_LL. ## 9. Wall-clock time
