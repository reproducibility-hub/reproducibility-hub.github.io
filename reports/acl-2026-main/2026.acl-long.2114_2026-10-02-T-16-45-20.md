- **Result match:** `NUMBERS_MATCH` (as released, no source edits: `NUMBERS_MATCH`).

**Summary.**
- **Benchmark numbers reproduce.** I ran the released SkMTEB code (the `slovak-nlp/mteb` fork, `MTEB(slk, v1)`) with the released `slovak-nlp/e5-sk-small` / `e5-sk-large` checkpoints and 8 baselines.
  - Every comparable Table 1 number matches: the 4 complete type averages per model, plus a 27-task average. All Table 9 classification numbers match too. Most numbers are within 0.1 points; the largest gaps are 0.4 points on the clustering average, except mE5-large-instruct retrieval (below).
  - The paper's comparative claims about these checkpoints hold on the 27 tasks:
    - e5-sk-small ≥ mE5-small (68.29 vs 68.03);
    - e5-sk-large ≥ mE5-large (72.39 vs 71.91);
    - mE5-large-instruct is the strongest open model (74.81);
    - the Slovak-specific slovakbert-* models trail the multilingual ones (60.92 / 65.31 vs 68.03).
- **Why only a subset.** 4 of the 31 datasets are manually gated on HF and couldn't be evaluated. API models weren't run.
- **The training claims can't be checked from the release.** Only the final weights are released, not the code that made them. My re-implementation from the paper's own recipe (Sec. 4, Table 8) reproduces the parameter counts exactly, but not the released models' behaviour.
  - The released fine-tune barely moves the model away from mE5 (skLEP STS-validation Spearman 0.7808 vs 0.7795 for the base).
  - The Table 8 recipe moves it a lot (0.83): STS and classification go up, retrieval and clustering go down.
  - For e5-large it ends *below* the mE5-large baseline (70.96 vs 71.91 on 27 tasks). The variant without SK-QuAD, which matches the released training-set size, does worse (70.31).
  - So the +0.2–0.5 gains in Table 2 can't be verified from released code, and those rows are labelled NOT_COMPARABLE.

## What the paper claims (targets)
- **Table 1** (main result): SkMTEB (31 datasets, 7 task types) scores for 31 embedding models. The proposed models are **e5-sk-small** (45M, All = 70.56) and **e5-sk-large** (365M, All = 74.70). They are compared with multilingual-e5-small (70.32) / -large (74.25), and the text says they are "on par" with text-embedding-3-small/large (70.48 / 75.07). Other claims: multilingual-e5-large-instruct is the best model overall (77.49), and Slovak-specific NLU models (slovakbert-*) underperform.
- **Table 2**: ablation of vocabulary trimming (VT), fine-tuning (FT) and prompts. Small: 70.32 → VT 70.45 → FT 70.58 → VT+FT 70.56 → +prompt 71.07. Large: 74.25 → 74.56 → 74.46 → 74.70 → 74.72.
- **Table 3**: bitext F1 for original vs. trimmed mE5. **Table 9**: per-dataset classification accuracy.
- Model sizes: VT to 60K tokens gives 45M / 365M parameters.

## What I ran (all inside `env/`, 1×H200)
Environment: Python 3.11, torch 2.6.0+cu124, `pip install -e codebase/mteb_fork` (mteb 2.3.0, which pulled in transformers 5.18 and sentence-transformers 6.1), plus pillow, accelerate, and gritlm (`--no-deps`, needed for the e5-instruct loader).

1. **SkMTEB evaluation of released models** with the README's documented path (`mteb.get_model(<id>)` + `mteb.get_benchmark("MTEB(slk, v1)")` + `mteb.evaluate`). This goes through my thin wrapper `run_eval.py <hf_id> results/<name>` (default batch size 64). Models: e5-sk-small, e5-sk-large, multilingual-e5-small/base/large, multilingual-e5-large-instruct, bge-m3, paraphrase-multilingual-MiniLM-L12-v2, slovakbert-sts-stsb, slovakbert-skquad-mnlr. Queues: `run_queue.sh`, `run_queue_base.sh`, `run_queue_tf4.sh`. Logs are in `logs/` and result JSONs in `results/`.
   - e5-sk-small/large were also run with their built-in `query:`/`passage:` prompts stripped (`--no-prompts`, folders `*_noprompt`). Result: the paper's Table 1 numbers come from evaluating *with* the prompts (the README default). Without them, retrieval drops by about 0.6 points.
2. **Diagnostic runs** in `results_aux/`:
   - mE5-large-instruct on a git worktree of the fork with PR #24's task instructions removed (`mteb_noprompts_worktree/`). Details under Discrepancies.
   - mE5-small without prompts on 4 tasks.
3. **Re-implementation of the unreleased training pipeline** (in `recon/`, written by me from Sec. 4 and App. F of the paper, so this is a reconstruction, not the authors' code):
   - `recon/count_tokens.py` + `recon/vt.py`: pre-FT vocabulary trimming. I counted mE5 token frequencies on **11 of the 204 FineWeb2-Slovak train shards** (1.43M documents, 1.2B tokens; scaled down from the full 26M-document corpus to save download and time), then kept the special tokens plus the most frequent tokens, 60,002 in total (the released vocab size). The resulting models have **exactly the released parameter counts** (44,680,320 and 365,330,432), and 87% of my small vocabulary overlaps with the released one. Trimming is lossless on Slovak text (cosine 1.0 to the original model's embeddings).
   - `recon/ft.py`: multi-task sentence-transformers training with the Table 8 hyperparameters: SK-QuAD (question, context), NLI (premise, entailment, contradiction), RTE entailment pairs (all with MNRL), STS with CosineSimilarityLoss; batch size 32, lr 2e-5, linear schedule with 10% warmup, 3 epochs, weight decay 0.01, seed 42, fp32, max_seq_len 256, no prefixes during training. Evaluation used E5 prefixes, like the released models.
   - Variants: VT+FT (small, large), VT+FT without SK-QuAD (small, large; this matches the training-set size in the released model cards, see Discrepancies), FT without VT (small), and VT only (small, large).
4. `make_tables.py` produces `tables.md` and `comparisons.json`.

### Settings that differ from the paper
- **4 of 31 datasets are manually gated on HF** and the account in this environment has no access: SlovakSumSTS (`slovak-nlp/slovak-sts-synthetic`), SlovakNLI (`natalia-nk/NLI-SK-annotated`), SlovakPharmacyDrMaxReranking and SlovakPharmacyMojaLekarenReranking. I did not request access, because that is an outward-facing action and approval is manual. As a result, the 31-task "All"/"Type" averages and the PrClf/Rrnk/STS type averages can't be computed. I compare: (a) the 4 complete type averages (Btxt, Clf, Clust, Rtrvl) from Table 1 directly; (b) a **27-task average**, where the paper-side value is computed from the authors' released per-task JSONs (which reproduce Table 1 exactly); (c) Table 3 and Table 9 per-dataset numbers.
- Library versions: mteb 2.3.0 (the fork's HEAD) instead of the 1.39.7 used for the paper's numbers.
- transformers 5.18 breaks the tokenizer of paraphrase-multilingual-MiniLM-L12-v2: Slovak text is lowercased, accents are stripped, and many words become `<unk>`, which gave garbage scores (Rtrvl 2.9). That model was rerun with transformers 4.57.3 + sentence-transformers 5.2.0 (the versions in the e5-sk model cards), installed into `env/extra_tf4` and used via PYTHONPATH. The broken run is kept in `results_broken_paraphrase-MiniLM_tf5/` for reference.
- Not run: the 5 API models (closed-source, no keys; the paper doesn't depend on them for its own method), and the other 18 open baselines, to save time. The sturovec-base model is not public.
- My training runs shared the GPU with evaluation runs, so wall-clock training time isn't comparable to App. F.2.

## Discrepancies
1. **code_vs_paper (major, affects results): SK-QuAD apparently not used to train the released e5-sk models.**
   - Paper (Sec. 4) and model-card prose: trained on SK-QuAD 72K + NLI + STS + RTE.
   - The released models' auto-generated sentence-transformers metadata says `dataset_size:137745`. That equals NLI-entailment (130,899) + STS (5,604) + RTE-entailment (1,249). My no-SK-QuAD data build has 137,749 rows.
   - This is inferred from metadata; the training code isn't released.
2. **code_vs_paper (major, affects results for instruction-tuned models): task instructions added after the paper's numbers were produced.**
   - The fork's HEAD includes PR #24 ("hladek/prompts"), which adds task instructions to 9 SkMTEB tasks. The paper's numbers (mteb 1.39.7) were computed without them.
   - With the released code, mE5-large-instruct gets SKQuadRetrieval 62.76 (paper per-task 69.13), SkQuadReranking 64.17 (71.00), MultiEupParty 40.79 (46.51), Rtrvl average 84.31 (86.08).
   - Removing just those prompt lines (worktree `mteb_noprompts_worktree/`) restores 69.07 / 70.92 / 46.51.
   - e5-sk and mE5 aren't affected, because they don't use task instructions.
3. **code_vs_paper (minor): the authors' VT-only checkpoints aren't a pure trim.**
   - A pure vocabulary trim, like mine, leaves symmetric-task scores (classification, pair classification) unchanged.
   - The authors' VT-only evaluations shift them by up to 4 points (e.g. SlovakRTE 40.44 → 44.64). Their trimming code and checkpoints are private, so the cause can't be checked.
   - My VT gives −0.23 / −0.19 instead of +0.13 / +0.31.
4. **paper_internal: when the prefixes are applied.**
   - Sec. 4.1 says the e5-sk models prepend `query:`/`passage:` "during both training and inference".
   - But Table 2 lists "+ VT + FT + prompt" (71.07 / 74.72) as a separate variant from the reported e5-sk models (70.56 / 74.70).
   - The released results show the Table 1 models were trained *without* prefixes and evaluated with them. The README default gives exactly the paper numbers; stripping the prefixes at inference lowers retrieval by about 0.6 points.

Other observations, not counted as discrepancies:
- The paper says all datasets are released openly, yet 4 datasets are manually gated.
- The authors' +FT checkpoint folder names (`...-contradiction-neg`) suggest NLI contradictions were used as hard negatives, which the paper doesn't mention. My re-implementation uses them.
- The authors' released JSONs differ from Table 1 in 2 cells: gemini-embedding-001 Rrnk 88.22 vs 88.27, and Qwen3-Embedding-4B Rrnk 86.40 vs 86.29 / Type 74.98 vs 74.96. These are API rows I didn't run.

## Codebase completeness: MISSING_CORE

- **What's missing.** All code for the paper's second contribution: vocabulary trimming, fine-tuning, and the intermediate/ablation checkpoints. Only the final weights are released, so the training-based claims (Sec. 4, Table 2) can't be re-run from the release.
