## What the paper claims / what was reproduced
The paper evaluates three human-in-the-loop theme-discovery systems: a Topic Model (Fang et al. 2023, `fang`), a Relational system (Pacheco et al. 2023, `pacheco`) and an LLM-based system (Chew et al. 2023 with Llama-3.2-3B, `laca`). Each is used under synchronous (2 groups) and asynchronous (3 individual coders) collaboration on COVID tweets (85,799) and Climate ads (5,471). The main results are:
- **Table 1**: consistency between code-books in the same setting. It reports the average best-match Jaccard, centroid cosine and group-average cosine similarity.
- **Table 2**: intra- and inter-theme group-average similarity, computed over all documents and over the top 25 % closest to each theme.
- **Figure 4**: correctness, i.e. the F1 of the system's assignments judged by human annotators, accumulated over relatedness quartiles.
- **Krippendorff's α** of the correctness annotations: 0.632 (COVID) and 0.696 (Climate).

The paper's conclusions are:
- On COVID, synchronous coding gives more consistent and cohesive themes, most clearly for the Relational system.
- On Climate, consistency is comparable across settings, and synchronous coding gives more cohesive themes.
- The LLM system is largely insensitive to the collaboration setting.
- Correctness depends on the dataset (Relational is best on COVID; synchronous Topic Model is best on Climate).

All of these mean-level patterns reproduce.

## Bugs found in the release (and the fixes applied in `./codebase`, left uncommitted)
1. **Group Avg. consistency is computed in one direction only, and that direction depends on filesystem order (affects Table 1).** The cell loops over `itertools.combinations_with_replacement(annotators, 2)`, so only one of (A,B) and (B,A) is computed. The order of `annotators` is the order returned by `glob.glob`, which the filesystem determines. As a result:
   - "max over the other coder's themes" is averaged only over the themes of whichever coder happens to come first;
   - the number of averaged themes differs from the Jaccard and centroid columns (e.g. 16 vs 31);
   - the result changes from machine to machine.

   On our filesystem, the unmodified code gives Climate Topic Model Sync 0.50 (paper 0.43), COVID Relational Async 0.42 (paper 0.44), and COVID LLM 0.43/0.43 (paper 0.44/0.45). With the authors' file order we get exactly the paper's values. **Fix:** use `itertools.product(annotators, repeat=2)` so both directions are computed, as the paper describes and as the Jaccard and centroid cells already do.
2. **The top-25 % cohesion dictionary is keyed by theme name only (affects Table 2 top-25 % rows, by ≤ 0.01).** Themes with identical names in different coders' code-books overwrite each other, and which one survives depends on order. Examples: Climate Topic Model `AntiGunBan`, `TPUSAAd`, `AntiPropertyTax`; Climate Relational/LLM `ClimateChangeDonations`, `RestoreVirginia`; COVID Relational `VaxLessensSymptoms`. **Fix:** key the dictionary by `(annotator, theme)`.
3. **The file list is non-deterministic and Climate topic-model files collide.** In `climate_ads/fang_evaluation_notebook.ipynb`, `glob('*.json')` also matches `async_1_selected.json`, and the `'async_1' in path` mapping keeps whichever file comes last. It works only by luck of order. **Fix:** use an explicit sorted list of the five code-book files.
4. **The KMeans/Unknown exclusion is case-sensitive.** `str.contains('Kmeans')` does not exclude the `KMeans_*` "unassigned" clusters as candidate best matches. **Fix:** `case=False`. This had no numerical effect here.

Environment-level fixes (not code):

- install `nltk`, which is missing from requirements.txt.
