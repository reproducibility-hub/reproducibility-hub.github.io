In short:
1. **The paper's own data is not released.** The README says "Coming soon — Dataset release". The data loaders point to the authors' local paths (`/u/y/u/yuwang/.../data/*.jsonl`). This covers the controlled outlier dataset with ground-truth masks (Tables 1/2, Figs. 3–6), the enlarged TrueMICL Outlier/Clock/Operator sets (50 support / 290 test, Table 3) and the text-only variants (Table 1). The authors generated all of these themselves.
2. **The released code cannot run as-is.**
   * `util/mllm_inference.py` and `util/load_mllm_model_and_data.py` are shipped only as CPython-3.11 bytecode in `util/__pycache__/`, so `from util import load_mllm_model_and_data, mllm_inference` fails.
   * `StaICC/__init__.py` imports a missing `StaICC/normal.py`, so `import StaICC` fails.
   * `vqa_eval/evaluate.py`, which `run_eval.sh` uses for OK-VQA, is absent. So is `Experiments/vis_attention_analysis.py` (README, Fig. 4).
   * `IMP_mllm_ours_v1.py` does `os.chdir("xxxx")`.
3. **The MGI implementation differs from the paper in several logic-level ways.** The most important: the per-query entropy "peak grounding layer" ℓ* (Eq. 1–2) is computed but never used, because `wire_intervention(mode='already')` is a no-op. Details are under Discrepancies.
4. **What we could test.** We reconstructed the missing helpers from the bytecode and ran the *released* intervention code (`Experiments/copy_atten.py`, `copy_atten_gemma.py`, unmodified) on all 4 models.
   * **OK-VQA** (public, the paper's Table 3 setting, our own re-implementation of the missing evaluation pipeline): the vanilla numbers are close to the paper's: 7B and 12B fall within the paper's std; 27B and 32B are 1.2 and 2.4 points higher. MGI gives **no gain** on any model (Δ = +0.00 / −0.27 / −0.01 / −0.24 for Qwen-7B / Qwen-32B / Gemma-12B / Gemma-27B). The paper reports +0.04 / +0.46 / +1.12 / +0.92.
   * **Public TrueMICL** (substitute for the unreleased data; not comparable): MGI−vanilla is between −1.33 and +1.33 points. It is positive in only 4 of 12 model×task cells. The paper reports MGI ≥ vanilla in all 12.
   * Fixing the ℓ* bug does not change this picture.
   * Run-to-run GPU nondeterminism alone changes about 2.5% of OK-VQA answers (0.1–0.3 points), which is the size of most of the paper's claimed gains.

## What the paper claims (targets)
- Table 1: text-only vs multimodal ICL (zero-shot / 4-shot) on the authors' controlled outlier dataset. **Not runnable**: data and the text-only experiment script (`mllm_exp3_all_cross_diff_model_text_only.py`, referenced in `run.sh`) are not released.
- Table 2: Uniform Attention Suppression (UAS) causal study. **Not runnable**: data not released. Also, as released, the UAS intervention is never wired in (see discrepancies).
- Figs. 5/6: attention-ratio analyses. These need the authors' masks, which are not released.
- **Table 3 (main method result)**: MGI vs vanilla 4-shot multimodal ICL, on TrueMICL Outlier/Clock/Operator (the authors' enlarged regeneration) and OK-VQA, for Qwen2.5-VL-7B/32B and Gemma-3-12B/27B. **This is what we targeted.**

Environment: `conda create -p ./env python=3.11`. Packages: torch 2.6.0+cu124, transformers 4.57.1 (the version in `environment.yml`), accelerate 1.11.0, datasets 3.2.0, numpy 1.24.4. Hardware: 1× H200. Models in bf16 with eager attention.

## Why it is not reproduced
* **Missing data (main reason).** The paper's datasets (controlled outlier set + masks; enlarged TrueMICL Outlier/Clock/Operator; text-only versions) are not released ("Coming soon"). Tables 1 and 2, Figs. 3–6 and three of the four Table 3 columns cannot be run on the paper's data.
* **Missing code.** These modules are not in the release: the inference/model-loading helpers (only `.pyc`), `StaICC/normal.py`, the OK-VQA/VQA evaluation pipeline (`vqa_eval/`), the text-only experiment script, and the Fig. 4 visualization script. We reconstructed or wrote them, so even our OK-VQA numbers come from our own pipeline.
* **On what we could run, the method's claimed gain does not appear.**
  * OK-VQA: the vanilla numbers match the paper, but MGI ≈ vanilla or slightly below it (−0.27…+0.00). The paper reports +0.04…+1.12.
  * Public TrueMICL: there is no consistent improvement.

## Codebase completeness: MISSING_DATA
The paper's own datasets are absent; that is the worst level that applies. Other issues, each of which would on its own make the release MISSING_SCRIPTS or MAJOR_FIXES:
* `util/mllm_inference.py` and `util/load_mllm_model_and_data.py` are shipped only as `util/__pycache__/*.cpython-311.pyc`. Python cannot import them (sourceless imports from `__pycache__` are not supported). We reconstructed the four needed functions from the bytecode (`repro_scripts/mllm_inference_reconstructed.py`).
* `StaICC/normal.py` is missing, so `import StaICC` raises `ModuleNotFoundError`. Our driver does not import StaICC; it builds prompts in the identical format.
* `vqa_eval/evaluate.py` (OK-VQA with RICES, called by `run_eval.sh`) is missing. We wrote `run_mgi_okvqa.py` and `vqa_metric.py`.
* `Experiments/vis_attention_analysis.py` (README Fig. 4) and `Experiments/mllm_exp3_all_cross_diff_model_text_only.py` (Table 1 text-only, referenced in `run.sh`) are missing.
* `IMP_mllm_ours_v1.py` has `os.chdir("xxxx")`, hard-coded `CUDA_VISIBLE_DEVICES='1'`, and a model list with missing commas (`"google/gemma-3-27b-it" "Qwen/..." "Qwen/..."` concatenates into one invalid name). Its defaults (k_list=[1,2,3], start layer 17 for every model, `dataset_index_list=[0]` = shape_ood only) differ from the paper's 4-shot / per-model L_start.
* Bug (crash): the released loop leaves the interceptors enabled with the *previous* sample's label/span indices during the next sample's attention-extraction pass. This raised a CUDA index-out-of-bounds assert once prompt length shrank (Qwen, switching from clock to operator_induction). Our driver disables the intervention before the extraction pass. ℓ* is unaffected, because the interceptor only rewrites the last-token row.
* Bug (silent): `wire_intervention(..., mode='already')` in `copy_atten.py` / `copy_atten_gemma.py` never updates the interceptors.
  * In the Qwen version, `discover_attn_sites` finds the *inner* attention module via the wrapper's `.attn` attribute and sets `mid_layer` on it.
  * In the Gemma version, the type check `== "Gemma3Attention"` excludes the wrappers.
  * As a result, ℓ* (Eq. 1) is never used, and the task mapping is always read at L_start (`check_already_mode.py` demonstrates this). We ran both the released behaviour and a fixed variant (`--fix_peak_layer`).
* Bug (silent, Table 2): `control_att_exp.py` calls `wire_intervention` with the default `mode='flatten'`, but the function checks `mode=='fallten'`. So the UAS intervention is never installed, and the "after UAS" accuracy would equal the original.
* We made **no edits** to files in `codebase/`. Running the code recompiled `util/__pycache__/utils.cpython-311.pyc`; we restored it with `git checkout` and removed the generated `Experiments/__pycache__/`.

## Discrepancies

### code vs paper
1. **[major, affects results]** `Experiments/copy_atten*.py::wire_intervention(mode='already')`. Paper (Sec. 5.1, Eq. 1–2): the task mapping is taken at the per-query entropy-argmin layer ℓ*. Code: ℓ* is computed (`get_optimal_layer_idx`) but the 'already' branch never reaches the interceptors, so the mapping is read at L_start for every query.
2. **[major, affects results]** `AttnInterceptorV2.forward`. Paper (Eq. 3/5): amplify query→evidence attention by λ for every head, leave all other tokens unchanged, renormalize. Code:
   * only the **top-2 heads** (ranked by query→evidence attention) are amplified;
   * non-evidence image tokens (≤ `low_ratio`·mean) are **multiplied by β** (0.1 TrueMICL / 0.01 VQA);
   * attention to each demo **label token** is boosted ×1.2 in its top-2 heads;
   * the evidence set S comes from **head-averaged** label→image attention, not per head (ℓ*,h).
3. **[major, affects Table 2]** `control_att_exp.py` / `wire_intervention`. Paper: UAS replaces label-token attention *over image tokens* with a uniform distribution. Code: the 'flatten' vs 'fallten' typo means UAS is never applied. The UAS interceptor itself would replace the label-token rows over *all* tokens (with 20% noise), not just image tokens.
4. **[minor]** `IMP_mllm_ours_v1.py` defaults: k_list=[1,2,3] (paper: 4-shot), a single start layer of 17 for all models (paper: 16/40/17/37), and only `shape_ood` evaluated (`dataset_index_list=[0]`).
5. **[minor]** `run_eval.sh` (VQA): `top_ratio` 1.7 / `low_ratio` 0.8 vs the paper's k=1.5; Gemma-27B uses `my_alpha` 2 vs the paper's λ=6 for VQA. The active block evaluates VQAv2, not OK-VQA.
6. **[minor]** Outlier correctness is the substring test `prediction in label` on a single argmax token (e.g. the token "s" would count as correct for "Answer: square"). The paper says keyword matching. It made no difference in our runs.
7. **[minor]** Data split, `StaICC/util/configs.py`: 50 calibration + 50 demonstration + 580 test drawn from one `train.jsonl` per dataset. Paper: Outlier = 500 queries per category from 2000; TrueMICL = 50 support / 290 test.

### paper-internal
1. Table 1 multimodal 4-shot accuracy vs Table 2 "Original (4-shot)" / Table 3 "Vanilla" Outlier: Qwen-7B 63.60 vs 69.09; Qwen-32B 76.13 vs 78.45; Gemma-27B 78.80 vs 78.62. Gemma-12B matches (72.93).
2. App. C.3, Tables 4/5 (Qwen-7B, Outlier): every MGI value in the λ and L_start sweeps is ≤ 68.97, which is below Table 3's *vanilla* 69.09, while Table 3 reports MGI 70.17. C.3 also names L_start=14 as optimal but then uses 16 for the 7B model.
3. App. C.3 says λ=6 is used "for the two VQA datasets", but only one VQA dataset (OK-VQA) is reported. The released `run_eval.sh` also contains VQAv2.
