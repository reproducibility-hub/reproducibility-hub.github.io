# Reproduction report: AgentGL (ACL 2026, 2026.acl-long.1161)

**Verdict: FAILED.** Result match: **NO_MATCH** (as released: **NO_MATCH**; Arxiv-23 NC gives 0.0 as released). Coverage: **SUBSET**. Codebase completeness: **MAJOR_FIXES**.

The released training pipeline runs on our hardware with small, hardware-only adaptations. We ran the two-stage GRPO training with Qwen2.5-3B-Instruct, the hyperparameters and data sizes in the release scripts, for both node classification (NC) and link prediction (LP), and evaluated on all 7 datasets with the released evaluation code. AgentGL-GRPO-3B comes out far below Table 1 on every dataset: −12 to −27 points on NC and −8 to −28 points on LP. Its accuracy is also essentially the same as the *untrained* Qwen2.5-3B-Instruct under the same agentic evaluation, which contradicts the paper's central claim. Under the released config the RL barely moves the policy:

- KL to the reference model stays at ~0.001–0.005.
- Tool use stays flat during training instead of rising toward full tool coverage as in Fig. 2a: ~0.5 searches/rollout for NC, ~1.1 for LP.

## 1. What was attempted

- **Paper target:** Table 1, rows *AgentGL-GRPO* with *Qwen2.5-3B-Instruct*, both tasks (NC and LP), 2 in-domain datasets (OGB-Arxiv, OGB-Products) and 5 zero-shot transfer datasets (PubMed, Amazon-Photo, Amazon-Computers, Arxiv-2023, Reddit). Metric: accuracy (%).
- **Code:** https://github.com/sunyuanfu/AgentGL (commit `c05f9fa`), cloned to `./codebase`. It contains a bundled OpenRLHF fork, reward servers, 8 training scripts, data builders and an evaluation script.
- **Data:** the authors' Google Drive (`node_data.tar.gz`, `edge_indices.tar.gz`), as linked in the README. NC/LP train and eval JSONL files were generated with the README's commands (seed 42, since the README says "choose your own seed").
- **Models:** `Qwen/Qwen2.5-3B-Instruct`; encoder `sentence-transformers/all-roberta-large-v1`.

### Commands (all logs in `./logs`, scripts in `./repro_scripts`)

1. Data:
   - `generate_datasets_from_splits.py` in eval mode (1000/test split) and in stage1/stage2 modes (README sizes);
   - `build_lp_datasets.py` (1500+/1500− train, 500+/500− test);
   - `build_lp_stage_datasets.py`.
   All use exactly the README arguments.
2. Services: `train/embedding_server.py` plus the reward servers in `train/`. Started by `repro_scripts/start_services.sh` / `start_reward.sh`, with a private Ray head.
3. Training, in this order:
   - `repro_scripts/train_nc_grpo_stage1_1gpu.sh` → `train_nc_grpo_stage2_1gpu.sh`
   - `train_lp_grpo_stage1_1gpu.sh` → `train_lp_grpo_stage2_1gpu.sh`

   Each is a `sed` copy of the release script `scripts/train_*.sh`. Only the GPU layout changed: actor/ref/vLLM on 1 GPU instead of 4+4 GPUs + TP-2 vLLM, no `--colocate_actor_ref`, and `--vllm_sync_backend gloo`, because NCCL cannot broadcast between two processes on the same GPU. Every hyperparameter is the release default:
   - 16 rollouts/prompt, train batch 128, rollout batch 32, lr 2e-6, KL 0;
   - temperature 1.0, generate_max_len 1600 (NC) / 2000 (LP);
   - curriculum easy→hard, max_samples as in the scripts.

   Steps: NC stage1 124 steps (7.6 h), NC stage2 62 steps (3.8 h), LP stage1 124 steps (6.7 h), LP stage2 124 steps (6.8 h).
4. Evaluation:
   - NC: `repro_scripts/eval_nc.sh`, which wraps `evaluation/run_eval_suite.py` with the README arguments (`--head 1000`, temperature 1.0, max 5 searches, TP=1).
   - LP: `repro_scripts/eval_lp.sh`, which wraps `evaluation/eval_gs.py --graph-task link`, as in the README, plus `--graph-topk-similar 3 --graph-topk-pagerank 2` to match the paper and the LP training scripts.
   - Accuracy is computed with `evaluation/metric_acc.py` exact match (`repro_scripts/acc_summary.py`).

## 3. Why it did not reproduce (our best understanding)

- **The training ran end to end, but the policy barely changed.**
  - Logged KL stayed ~1e-3. Of the saved weight tensors, 179/434 differ from the base model at all, with a max relative change of 1.5%.
  - Mean reward stayed flat:
    - NC stage1: ~0.9→1.1
    - LP stage1: ~1.7→1.9
  - Tool usage stayed flat:
    - NC: ~0.5 searches/rollout, ~19% of rollouts use any tag
    - LP: ~1.1 searches/rollout
  - The paper's Fig. 2a/b (7B) shows tool use rising to ~4 valid calls within 80 steps under rCOV.
- With the released configuration (lr 2e-6, 1 episode, 4 optimizer steps per rollout batch, ~124 steps), the 3B model never learns the tagged tool-call format for NC. Its evaluation accuracy is the untrained model's.
- We found no bug in the training loop that would explain this. We checked:
  - token masking of retrieved documents (start/end token ids match Qwen tokenisation);
  - GRPO grouping (rollouts sorted by node id, groups of 16 are contiguous);
  - reward plumbing (reward log shows the expected values).
- Possible remaining causes we could not test within budget:
  - undocumented differences in the authors' actual runs (more epochs/steps, a different base checkpoint or 7B);
  - the 4-GPU vs. 1-GPU difference in data-parallel sampling order (it should not change the expected update);
  - run-to-run variance. The paper's Table 6 reports variance ≤1.1, far smaller than the gaps we see.
- The Arxiv-2023 NC score of 0.0 as released is a genuine evaluation bug (see §4). Fixing it does not change the conclusion.

## 5. Discrepancies

Code vs. paper:

1. **Stage-1 reward** (`train/reward_server_qwen_zero.py`). Paper: R = r_FMT + r_ACC + r_COV. Code additionally adds a "think-length" reward (+0.5 if every reasoning segment ≥30 words, else −0.2/segment, capped at −0.6) and a −0.5 length penalty (>2200 words). **major**
2. **Stage-2 cognitive-density reward** (`train/reward_server_qwen_stage2.py`). Paper: threshold 100 tokens, penalty −0.2 per short segment (unbounded), +0.5 bonus. Code: threshold 80 whitespace words, penalty capped at −0.6, plus a length penalty above 2000 words. **minor**
3. **Search budget.** Paper: B = 4 (Table 2). Scripts/eval: `--graph_max_searches 5`; the rollout loop (`experience_maker._generate_vllm_with_retrieve`) allows up to 6 search rounds and does not enforce `graph_max_searches` during training. **minor**
4. **GCCL quotas** (README/`generate_datasets_from_splits.py`). Paper: Stage 1 800 easy/500/500, Stage 2 200 easy/500/500. Code: Stage 1 1000/500/500, Stage 2 0 easy/500/500. **minor**
5. **GCCL NC difficulty score** (`compute_difficulty_labels`). Paper: η·log(1+d). Code: η·log(1+d)/log(1+d_max), with tertile split. **minor**
6. **REINFORCE++ NC scripts** (`scripts/train_nc_reinforcepp_stage1.sh`). These omit `--curriculum_easy_to_hard`, so the prompt order is hard→medium→easy; the paper says both stages use easy→hard GCCL. **minor** (not run by us)
7. **Arxiv-2023 NC evaluation.** Gold labels are full category names, the prompt asks for `cs.XX`, and the metric is exact match, so accuracy as released is always ≈0. Paper reports 60.2/66.9 (3B) and 67.6/67.4 (7B). **major**, affects results.
8. **Retrieval tool definitions.** Paper Def. 4.1 says 1-hop/2-hop are ranked by cos(h_n, λ_r h_Q + (1−λ_r) h_x) with the common-neighbour quota for pairs. Code: NC 1-hop/2-hop follow this with λ = 0.5. The "pagerank" tool returns the same global top-K PageRank nodes regardless of the query. Consistent with Def. 4.3; noted for clarity, no severity assigned.

Paper-internal: none clearly identified. Obs. 4 and Table 1 are consistent as far as we checked.
