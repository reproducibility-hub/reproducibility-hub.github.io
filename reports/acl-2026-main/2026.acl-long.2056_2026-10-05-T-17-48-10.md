## Summary

- **Code.** The release (https://github.com/Sakonii/SafeConstellations) is a set of Colab notebooks with no README or requirements file. The notebooks are complete enough to run the main pipeline, and I executed their code cells verbatim. My wrapper only skips Colab/`!pip` lines and points the data loaders at public data.
- **Judge (blocker).** Every over-refusal number in the paper comes from a **GPT-4o judge**. That includes Table 2's OR rate and Reduction, Table 4, and Figure 3. The judge labels are also an **input** to the method: they define the target and over-refusal centroids. No OpenAI key is configured.
  - The notebooks contain hard-coded OpenAI keys. I did **not** use them: they are leaked third-party credentials, not authorized for this run.
  - So all judge-based numbers are `NOT_COMPARABLE`.
  - To still run the method end to end I used two label sources: (a) a transparent keyword refusal detector, and (b) **the authors' own GPT-4o over-refusal labels recovered from the released notebook logs**. The logs print every prompt the authors steered.
  - Outcomes are re-scored with the keyword detector. Those are indicative only.
- **Judge-free results that reproduce:**
  - Llama-3.1-8B MMLU (Table 2): 45.09 vs 46.57 (−1.5 pt, 3.2% rel). Re-scoring the authors' logged responses with the released metric gives exactly 46.57.
  - Steering is never triggered on MMLU for Llama (0/101), as in the authors' logs.
  - Gating and layer selection match the authors' logs: steering applied to 41/48 (85.4%; paper 85.4%) with 48/48 per-sample gating decisions identical. Qwen: 21/22, identical.
  - Selected layers match Appendix A.3 exactly for translate [-1,20,14,15,18]; sentiment and Qwen cryptanalysis select the same layer sets.
  - Qwen MMLU with SafeConstellations: 27.17 vs 28.42.
  - But unsteered Qwen1.5-7B scores **44.0** (greedy) or **33.0** (sampled, no steering) on the same 101 questions, not 28.42. So for Qwen the method *does* cost utility, about 6 points even against the decoding-matched control. The paper's "no degradation" claim does not hold for Qwen.
- **Indicative only (keyword stand-in judge).** The main over-refusal claim looks directionally right. With the authors' over-refusal set, Llama OR goes 17.78% → 4.44 / 5.56 / 4.81% (3 seeds; paper 4.81%), a 75.0 / 68.8 / 72.9% reduction (paper 72.92%). The released no-steering resampling control only reaches 14.6%.
- **What does not hold:**
  1. **Three of the five Table 2 ablation rows are not different computations.** "Late Layers", "Final Layer Only" and "Less Trajectory Steering" only change config flags (`decision_layers`, `monitor_all_layers`, `USE_TRAJECTORY_COORDINATION`) that the executed steering function never reads. With the same seed they produce **byte-identical outputs** to the full method (47/47). The paper's differences between these rows (4.81 vs 6.29 / 5.92 / 6.64) and the claims built on them ("Trajectory reduces OR by 2.08%", "dynamic selection beats late/final-layer steering") are sampling and judge noise.
  2. **Fixed-layer utility drop.** The claimed MMLU drop for Fixed Layers [15,20,25,30] (39.20) doesn't reproduce: we get 44.55 / 49.50. The intense variant's drop is label-dependent (45.60 with keyword labels, 40.75 with the authors' labels; paper 43.66).

  4. **Code differs from the paper's method.** The executed method differs substantially from the paper's equations (see Discrepancies). The task embeddings are built on the **same 270 test samples** that are then steered and evaluated, not on the 75% training split.

## Why it is not fully reproduced
1. **Closed judge.** GPT-4o produces all OR / Reduction numbers and also the labels that build the method's centroids. With no key, these are `NOT_COMPARABLE`. The keyword stand-in agrees well on Llama's baseline (17.41% vs 17.77%) but cannot see Qwen's "non-answer" refusals at all.
2. **Ablations are inert in code.** Three Table 2 rows are the same computation as the full method, so the component-contribution claims are not supported by the released code.
3. **Fixed-layer baselines.** The fixed-[15,20,25,30] baseline shows no MMLU degradation (44.55 / 49.50 vs 39.20). The intense variant's drop depends on the labels.
4. **Qwen gating.** The Qwen task gate (mean cosine to the target centroid > 0.85) accepts almost every prompt, MMLU included. Unsteered Qwen MMLU (44.0 / 33.0) is far above the paper's base value (28.42), which our *steered* run matches (27.17).

## Discrepancies
Code vs paper:
1. **Train/test leakage (major).** The memory bank (centroids, layer selection) is built from the 270-sample `with_harmful_response` split, which is the test split, and the same over-refusal test samples are then steered and evaluated. Paper §3.2/Table 1: built from D_train (75% split, 777 samples).
2. **Inert ablations (major).** The "Late Layers", "Final Layer Only" and "Less Trajectory Steering" notebooks differ only in `decision_layers`, `monitor_all_layers` and `USE_TRAJECTORY_COORDINATION`. None of these is read by `extract_embeddings_with_configurable_steering_FIXED`. Outputs are byte-identical to the full method with the same seed.
3. **Steering rule (major).** Code: `h += (c_tar − h_prompt_last)·I`, with I = 0.5 / 1.0 / 1.5 for layers ≤10 / 11–20 / >20. It is added at **every token position** (prompt and generated) of the selected layers' `input_layernorm` output. Paper Eq. 6: `h + λ·v/‖v‖`, with `v = c_tar − c_ref` and `λ = λ0(1−L_Align)·conf·κ`, λ0 = 0.3, κ = 0.8 / 1.0 / 1.2.
4. **Task identification (major).** Code: mean cosine(h, c_tar) over all 32 layers, threshold 0.85, restricted to `STEERING_TASKS`. Paper Alg. 1: mean over L_t of [cos(h,c_tar) − cos(h,c_ref)].
5. **Layer selection (major).** No per-sample dynamic selection (Eq. 4, Pot(ℓ), K'=4) in the executed path. The static per-task top-5 layers by effectiveness score are used, with the final norm (-1) filtered out, leaving 4 transformer layers. `select_best_layers_for_sample` exists but is only called from an unused function.
6. **Effectiveness score (major).** Code: `0.3·sep_ratio + 0.2·‖Δc‖ + 0.2·separability + 0.3·‖Δc‖`. Paper Eq. 3: `‖v‖/(σ_tar+σ_ref+ε)`; Appendix A.3.1 gives yet another formula.
7. **Decoding protocol (major).** Baseline responses use the model's default `generate()` (Llama: sampled T=0.6/top-p 0.9; Qwen: greedy). Steered responses use T=0.8, top-p 0.95, repetition penalty 1.1. The paper doesn't mention this. Re-sampling alone removes 12.8–14.6% of over-refusals in our control.
8. **Qwen model (major).** Code uses `Qwen/Qwen1.5-7B` (base); Appendix A.3 says Qwen1.5-7B-Chat.
9. **MMLU metric (minor).** The first capital A–D anywhere in the response counts as the answer (e.g. "A polynomial…" → A), accuracy is over parseable responses, and the reported value is `round(acc,2)·n_valid/101`. The paper just says "MMLU accuracy on a subset".

Paper internal:
1. **Table 4 vs Table 2 (Llama).** Table 4 gives translate 8.9% of 60 (not an integer count) and sentiment 18.2% of 55 = 10 remaining, about 15 in total. Table 2's 4.81% means 13/270 remaining.
2. **Table 4 Qwen cryptanalysis.** OR is given as 63.33%, but the released log / Appendix A.3 counts give 19/60 = 31.7%. The 29.41% reduction is consistent neither with 63.33 → 43.33 (31.6%) nor with Table 2's 63.64%.
3. **§5 "73.2% successful".** §5 says "85.4% steered, of which 73.2% successful". The full-method notebook log shows 34/41 = 82.9%; 73.2% (30/41) is the output of the "Late Layers" ablation notebook.
4. **Qwen model name.** "Qwen1.5-7B" (Table 2/text) vs "Qwen1.5-7B-Chat" (Appendix A.3).
