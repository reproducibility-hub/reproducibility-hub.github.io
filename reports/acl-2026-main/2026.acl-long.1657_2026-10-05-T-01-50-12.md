## Data: gated HF dataset, rebuilt with the released script
- `lecslab/polygloss-corpus` is gated on HF ("auto" approval). This account had no access, and I did not accept terms or request access on the user's behalf.
- Instead I rebuilt the corpus with the repo's own `create_dataset.py`, from public sources:
  - the in-repo raw ODIN, SIGMORPHON-2023 and Guarani data;
  - the CLDF git submodules (apics, imtvault, uratyp) at their pinned commits, cloned via https;
  - `wav2gloss/fieldwork` from HF;
  - Glottolog v5.2, which `data/process.py` needs at `../glottolog`.
- **Result of the rebuild:** 373,382 raw → 353,266 unique rows, train/dev/test = 340,251 / 6,148 / 6,867, and the per-language splits for all 9 languages equal **Table 1 and Table 2 exactly**.
- This needed one non-obvious step. `create_dataset.py` de-duplicates with `drop_duplicates(keep="first")`, so the split a duplicated SIGMORPHON example ends up in depends on `Path.iterdir()` order, which depends on the filesystem.
  - With the Lustre order here, arp, lez and nyb dev/test counts differed from Table 2 (totals were identical).
  - I tried all 6 train/dev/test file orders. For every language some order reproduces Table 2 exactly, so the final build uses those per-folder orders (in my wrapper `scripts/rebuild_dataset.py`; the repo code is not modified).
- **Sanity check:** GlossLM evaluated on this rebuilt test set gives MER identical to Table 3 (avg 0.639 vs 0.639, ≤0.001 per language).
- **Remaining difference:** the *row order* of train/dev cannot be recovered. It only matters for the iid 90/10 pretraining dev split (`train_test_split(seed=0)`), and so for perplexities computed with the released checkpoint (see Figure 2 below).

## What I ran (exact commands)
All runs were from `codebase/` with `WANDB_MODE=offline` and `dataset_key=<attempt>/data_final`. Configs were copied to `runs/<name>/` so the repo's own `metrics.json` files are not overwritten.
1. **Data:** `PYTHONPATH=. SORTED_ITERDIR='{"Arapaho":"dev,train,test","Tsez":"train,dev,test","Uspanteko":"test,train,dev","Lezgi":"train,test,dev","Natugu":"dev,train,test","Nyangbo":"test,dev,train","Gitksan":"dev,test,train"}' python ../scripts/rebuild_dataset.py ../data_final`

   - Uses the repo's `experiments/{byt5_g+s_interleaved,byt5_g+s_multitask,byt5_g+s_concatenated,glosslm_v1}/eval.cfg`.

4. **Monolingual joint baselines** (Table 7–9 "Finetuned ByT5 (joint)", Figure 4): `python run.py runs/mono_joint/train_baseline.cfg -o glottocode=<g> ...`

5. **Table 10 and Figure 2:**
   - `scripts/long_only.py` re-evaluates saved predictions on inputs at or above the per-language 75th length percentile. Its logic is equivalent to the `eval_length_percentile` option on the repo's `camera-ready` branch, which is not on `main`.

## Codebase completeness: MINOR_FIXES
Changes to the released code (left uncommitted in `./codebase`):
1. **`run.py`:** wrapped `HfApi().dataset_info(config.dataset_key).sha` in try/except. That call only logs a dataset SHA to W&B and crashes when `dataset_key` is a local path, which I needed because the HF dataset is gated. No effect on results.
2. **`src/train.py` (gradient accumulation bug):** with `gradient_accumulation_steps > 1` the original loop never updates the weights.
   - Cause: it checks `(step + 1) % gas == 0` but only increments `step` inside that branch, and it calls `zero_grad()` every micro-batch.
   - Fix: test on the micro-batch index and zero the grads only after an optimizer step.
   - No effect when gas = 1, which is what the paper's 4-GPU configs use. It was needed to reproduce the paper's effective batch of 4×64 on one GPU.
