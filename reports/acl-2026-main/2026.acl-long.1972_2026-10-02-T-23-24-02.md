### Summary

I ran the released SecureGate pipeline end to end, at the paper's scale, for the paper's main setting: Table 1, the SecureGate column (identical to the r=16 column of Table 8). That setting is ECHR, Llama-3.2-1B, 10 clients, LoRA r=16, α=64, 20 federated rounds, perplexity-based PII inference attack with c=50 candidates. I also computed Table 9 (perplexity per client).

- **The qualitative claim reproduces.** With the correct key the gate always routes to the revealing adapter, and with a wrong key it always routes to the secure adapter: routing was 100% correct for all clients. Inference-attack accuracy is high with the correct key and low with the wrong key.
  - Ours: 38.46% vs 5.64%, a 6.8× reduction.
  - Paper: reported average 25.20% vs 4.20%. The mean of the paper's own per-client column is 29.09%, which gives a 6.9× reduction.
- **The absolute leakage with the correct key is higher than reported.** Our mean is 9–13 points above the paper's.
- **The Table 9 perplexities match closely.**

Data:
- **Training data:** the released `datasets/echer.zip` (`echer_{masked,undefended}_{train,eval}.jsonl`), first 10,000 samples. Each client gets a contiguous shard of 1,000.
- **Evaluation data:** the ECHR builder in the submodule, which runs Flair NER over HF `ecthr_cases`. Its `train[:10000]` is identical, row for row, to the training jsonl, so client k is attacked on its own training shard.

### Settings that differ from the paper or the release

- **Base model.** `meta-llama/Llama-3.2-1B` is gated for our HF token. I used `NousResearch/Llama-3.2-1B`, an ungated mirror with the same Meta weights. It is symlinked locally under the name `meta-llama/Llama-3.2-1B` because the code dispatches on that string.
- **Fusion speed-ups.**
  - TF32 matmuls via `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1`. In a check, fusion losses were identical to 4 decimals with and without it.
  - The reporting-only FLOP count was skipped (`SG_SKIP_FLOPS=1`).
  - One process per client, selected only through command-line arguments (`--fuse_model_number k --num_clients k+1 --dataset_sample 1000(k+1)`), so client k still uses rows [1000k, 1000k+1000).
  - Without these changes fusion would have taken more than 40 h.
- **Secure-adapter fusion target.** I fused the secure adapter (`SG_FUSE_ADAPTER=masked`) exactly as the code does in `--load_the_saved_model True` mode. That reads the Stage-A local secure adapter (see the Discrepancies section).
- **Unauthorized condition.** Only the "wrong key" case is used, as in the released `evaluate.py`.
- **Table 9 evaluation text.** The paper does not say which text Table 9 is computed on. I used the first 200 raw training samples of each client. I also computed perplexity on the ECHR test split: about 98 for the revealing adapter and 48 for the secure adapter, so Table 9 was evidently not computed on held-out text.
- **Other settings.** Every other hyperparameter is the release default: the paper values from Appendix A.1 and Section 5.1 are hard-coded in the optimize stage.

## 4. Codebase completeness: MISSING_SCRIPTS

The method itself (dual adapters, federated learning, fusion, gating, two-pass inference, the attack evaluation) is implemented and does produce Table 1. However, I had to fill in missing pieces and fix bugs; every change is listed below.

### Missing pieces I added

1. `records.py`. It is imported by `main_sft*.py` but not released. It is only used by a helper function that is never called, so I stubbed it with empty lists.
2. `gating_module/parse.py`. It is imported by `train_gating_module_combined.py` but not released. I wrote an argument parser matching the arguments in `train_gating_module.sh`.
3. `ppl_eval.py`, for Table 9. No released script computes gated per-client perplexity; `evaluate_perplixty.py` is a stub with an invalid dataset path.

### Edits to `main_sft.py` (uncommitted; see `git diff`)

- **Dataset selection.** Hard-coded Yelp paths are replaced by the `SG_DATA` environment variable.
- **Fusion target.** The target is controlled by `SG_FUSE_ADAPTER`, which sets the selected adapter, whether fusion data is masked or raw, and the output name. The released code has these as hand-toggled lines (alternatives left as comments).
- **FLOP counting.** Optional `SG_SKIP_FLOPS`. It only affects the printed report, not the fused weights.

### Other fixes and workarounds

- `strip_embeddings.py`, my own script: removes the untrained `embed_tokens`/`lm_head` copies that peft auto-saves into the adapter files. Without this, the gated loader crashes. It leaves the original file in place as `adapter_model.full.safetensors`.
- **Stage A crash.** Stage A crashes at the very end while building the training-statistics DataFrame (lists of unequal length). All adapters were already saved, so I continued from them.
- **Evaluation configs.** The released configs `inference-gated-fl-1b/pii-inference6-10.yml` point to Yelp (left over from the non-IID experiment). I copied all ten into `inference-gated-fl-1b-echr-iid/` with the ECHR dataset path; only config values changed.
- **Data download.** `ecthr_cases` downloads from archive.org timed out under fsspec. `prep_echr.py` serves the identical zip, fetched with curl, to build the dataset cache.
- **Launcher scripts:** `stage*.sh`, `fuse_one.sh`, `fuse_gated.sh`, `eval_one.sh`, `after_fusion.sh`.

## 5. Discrepancies

1. **Paper internal: Table 1 average.** The SecureGate average with the correct key is reported as 25.20%, also quoted in the abstract, introduction and Sec. 5.2. The ten per-client values in the same column (identical to Table 8, r=16) average **29.09%**, which Appendix B.2 also reports. The other columns' averages are consistent (FedAvgM 20.12; SecureGate wrong key 4.20).
2. **Code vs paper (major): federated aggregation** (`train_optimizer`).
   - Paper: every organization starts each round from the global adapter, and the server applies a |D|-weighted average with Nesterov momentum.
   - Code:
     - Clients are trained one after another on the same model, without resetting to the global adapter in between, so each client's "delta" contains all previous clients' updates.
     - The deltas are averaged without weights.
     - The update is w ← w + m·v + η·Δ̄, with v ← m·v + η·Δ̄.
3. **Code vs paper (major): which secure adapter gets fused.**
   - Paper: Eq. 6 fuses the global adapter with the organization's secure adapter after T rounds.
   - Code: fusion can only run after the optimize stage in `--load_the_saved_model True` mode. In that mode it reads the Stage-A local adapters (`client_k_sft_personalized_adapter_name/`), so the client adapters produced by the 20 federated rounds are never used.
   - Consequence: the learned weights are about 1.05 for the local adapter and −0.035 for the global one (about 1.025 / −0.013 for the revealing adapter). The federated global adapter therefore contributes almost nothing to the final adapters.
4. **Code vs paper (minor): Stage-A training hyperparameters.**
   - Paper: 3 epochs, lr 1e-4.
   - Code: Stage A, which trains the revealing adapter, uses 10 epochs, lr 5e-5, batch 2×4 with gradient accumulation, and a linear schedule. Only the optimize stage uses 3 epochs and lr 1e-4.
   - This plausibly drives memorization, and hence the authorized leakage level.
5. **Code vs paper (minor): fusion objective.**
   - Paper: a small query set Q.
   - Code:
     - The loss is computed over the client's full 1,000 samples.
     - The auto-saved embedding and output-head tensors are fused too, so they are rescaled by w1+w2 during the search.
6. **Code vs paper (minor): "Wrong/No token".** The evaluation uses only one wrong key; the empty-key and no-key cases are commented out.
7. **Code vs paper (minor): gated vs standalone perplexity.** With correct routing, the gated adapter pass is exactly the standalone adapter's forward pass on the key-stripped text, so the two perplexities must be identical. Ours are (6.51 / 6.51 and 15.79 / 15.79). Table 9 instead reports small differences (6.32 vs 6.46).
