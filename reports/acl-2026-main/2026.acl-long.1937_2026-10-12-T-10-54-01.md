### Summary
1. **The released artifacts are internally faithful.** The authors' raw LLM outputs (the 1.2 GB Google-Drive `release-artifacts.zip` linked from the README) were passed through the repo's own stats pipeline (`python -m src.analyze --dataset all --analysis stats`). This reproduces **every one of the 72 cells of Tables 1–2** (deltas and significance stars), **all Section 4.1 in-text numbers** (e.g. Qwen2.5-14B 35.67/28.15/27.61 and 30.12/29.12/27.66; Ministral 29.71/18.67/21.54) and **Table 14**, all exactly.
2. **Our fresh inference rerun on MuSiQue reproduces the paper.** This used the released runners, vLLM 0.11.0 on an H200, and 5 models.
   * 27 of 30 Matched−NA cells (Tables 1–2) are within tolerance (≤1 pp or ≤5% relative). The other 3 are TREND_MATCH (≤1.4 pp off).
   * All 30 are significant at p<0.01, as in the paper (30/30).
   * The mean absolute deviation from the paper's deltas is 0.56 pp.
   * The in-text No-MFAI numbers for Qwen2.5-14B are within 0.72 pp. For Ministral they are 1.6–2.3 pp lower in absolute terms, with the same ordering.
   * Absolute position governs accuracy (Beginning ≫ Middle ≈ Tail for every model).
   * Weakest Link: Cross NA is below the average of its two constituent Spread buckets in 14/15 bucket pairs. The exception, Qwen2.5-7B M+T, is also an exception in the authors' released outputs. On NeoQA the same holds in 14/15 pairs (exception: Ministral M+T; the released outputs give 15/15).
3. **NeoQA reproduces only at the trend level.** The NeoQA effects are small (Matched−NA of 0–6 pp on 50–70% baselines). Re-running inference changes 10–23% of individual NeoQA predictions relative to the released outputs, which moves cell deltas by up to ±2.6 pp (mean |diff| 1.23 pp).

## What the paper claims (reproduction targets)
* **Main results.**
  * Figures 2–4 and 6 give Spread/Cross accuracy for No-MFAI / Matched / Unmatched on MuSiQue (EM, 1,246 questions) and NeoQA (accuracy, 402 questions), with 18 documents in 3 buckets.
  * Tables 1–2 give McNemar Matched−NA deltas for 5 models plus Qwen3-8B-Think.
  * Section 4.1 gives in-text numbers.
* **Central claims:**
  * (RQ1) A step function in absolute bucket position, and the "Weakest Link" effect: Cross accuracy collapses toward the weaker bucket.
  * (RQ2) Matched MFAI rescues low-visibility buckets: +4.83 to +11.49 pp in Tail on MuSiQue, all significant. Gains on NeoQA are smaller.
  * (RQ3) Unmatched MFAI hurts MuSiQue but not NeoQA.
  * The thinking model is robust.

## What we did
1. **Code.** Cloned the official repo into `./codebase`.
2. **Data.** The GitHub release v1.0.0 that the README points to has **no assets**: the `processed_dataset.tar.gz` URL returns 404, and the API lists no releases. The README's second link (Google Drive, `release-artifacts.zip`, 1.2 GB) contains `processed_dataset.tar.gz` (the preprocessed 18-doc banks; 1,246 MuSiQue / 402 NeoQA entries, as in the paper) and `results.tar.gz` (the authors' raw LLM responses, about 10 GB unpacked). Both are in `./data_dl/release-artifacts/`. The banks were copied to `codebase/dataset/`.
3. **Environment.** `./env` (conda, Python 3.10). We installed `vllm==0.11.0` and then `requirements.txt` (torch 2.8.0). `transformers` was pinned to 4.57.1 and `datasets` to 4.4.2, because the unpinned requirements pulled transformers 5.x and datasets 5.x. The paper used vLLM 0.8.5.post1.
4. **Server.** `runs/start_server.sh` mirrors `scripts/infer/start_vllm_server.sh`: bf16, `--max-model-len 32768`, `--max-num-seqs 256`, `--max-num-batched-tokens 32768`, seed 42. It differs in the Python path and in dropping `--enforce-eager`, which only affects speed.
5. **Inference.** Ran the released unified runners unmodified (`runs/run_model.sh`; the sequential variant is `runs/run_model_seq.sh`):
   ```
   python -m src.infer.entity.run_inference --experiment {spread|cross} --bank-file dataset/processed_musique_bank/musique_bank_18docs.jsonl \
       --model M --api-url http://localhost:8000/v1 [--groups beginning,midsection,tail --distances 1,3,5 | --local-indices 0,3,5] \
       --max-tokens 3000 --temperature 0.0 --prompt-id 0 --seed 42 --modes MODES --results-dir results/musique/2hop/{spread|cross} --timeout 900 --num-threads 128/256
   python -m src.infer.event.run_inference --experiment {spread|cross} --bank-file dataset/processed_neoqa_bank/neoqa_bank_18docs.jsonl \
       --model M --api-url http://localhost:8000/v1 [same grid] --modes MODES --max-tokens 3000 --temperature 0.0 --seed 42 --num-threads 128/256 \
       --results-dir results/neoqa/same_timeline/{spread|cross}
   ```
   * Models and modes:
     * Qwen2.5-7B-Instruct: `na,matched,unmatched`.
     * Llama-3.1-8B-Instruct, Ministral-8B-Instruct-2410, Qwen3-8B (non-thinking) and Qwen2.5-14B-Instruct: `na,matched`.
     * Llama-3.1-8B-Instruct: `unmatched` added at the end with leftover time. Only MuSiQue Spread completed (18 configs). The partially finished MuSiQue Cross Unmatched files were moved to `partial_llama_cross_unmatched/` and are not used.
   * Each NeoQA model automatically uses the prompt of Table 17 (`src/utils/neoqa_prompting.py`).
6. **Evaluation.** Used the repo's own pipeline, `python -m src.analyze --dataset {musique|neoqa} --analysis stats`: repo EM metric, 10k-bootstrap CIs, McNemar with continuity correction. Its outputs are in `final_stats_na_matched/`. The same pipeline was run on the released outputs: full grid in `analysis_released/`, and restricted to our sparse grid in `analysis_released_subgrid/`, which gives an apples-to-apples comparison.
7. **Our helper scripts** (none modify the repo):
   * `tools/paper_numbers.py`: paper numbers transcribed from the PDF.
   * `tools/compare.py` and `tools/build_comparisons.py`: paper vs ours tables and `comparisons.json`.
   * `tools/summary.py`: per-bucket accuracies and the Weakest Link check.
   * `tools/agree.py`: per-item agreement of our rerun with the released outputs.
   * `tools/figure_values.py`: Figure 2/3 bar values, written to `figure_values.csv`.
   * `runs/*.sh`: server, runner and queue scripts.

### Settings that differ from the paper
| Setting | Paper | Ours | Why |

## Why it is not fully reproduced
* **Scale.** Coverage is SCALED_DOWN: a 1/3 sparse grid, no Qwen3-8B-Think, and Unmatched for only 1–2 models. The 15.8 h single-GPU budget could not fit the paper's 150 configs × 6 model configurations × 2 datasets.
* **Inference nondeterminism / version drift.** Prompts are identical to the released runs: we checked options order, gold index, attention targets and the prompt template. Even so, 10–31% of predictions change relative to the authors' released outputs. MuSiQue absolute EM is lower for every model (by 0.3–2.6 pp; Ministral differs most), while the deltas are unaffected. On NeoQA the per-cell Matched−NA deltas move by up to ±2.6 pp. This is enough to flip significance in 6 of 30 NeoQA cells, because the NeoQA effects themselves are only 0–6 pp. The paper (A.1) acknowledges drift "by a fraction of a percentage point". We observe somewhat more than that: vLLM 0.11.0 on an H200 vs 0.8.5.post1 on A6000/3090/A100, plus a smaller n from the sparse grid.
* **No code bug** was found that would explain the differences.

## Codebase completeness: MINOR_FIXES
No file under `./codebase` was edited (`git status` is clean; `dataset/` and `results/` are gitignored). The released Python pipeline (`src/infer/entity`, `src/infer/event`, `src/analyze`) ran unmodified. The issues are in the documented launch path and the data release:
1. **`scripts/infer/run_qwen3_neoqa.sh` crashes.** `SPREAD_SCRIPT`/`CROSS_SCRIPT` are bash arrays but are expanded as `"$SPREAD_SCRIPT"`, giving `python "-m" --bank-file ...`. We bypassed the script and called the module directly.
2. **`scripts/infer/run_qwen3_musique.sh` defaults differ from the paper.**
   * `PROMPT_ID=22` selects a CoT "NeoQA-style reasoning" template, not the paper's A.10.1 prompt (template 0, which the released outputs record). A quick test with prompt 22 on Qwen2.5-7B gave a different output format and EM (17.98 vs 17.26 on one cell).
   * `MODES="na,matched"` omits Unmatched.
   * We used `--prompt-id 0` and set the modes explicitly.
3. **All shell launchers hard-code `PYTHON="$HOME/miniconda3/envs/event/bin/python"`.** We used `./env/bin/python`.
4. **`requirements.txt` has no upper pins.** It pulled transformers 5.x and datasets 5.x, which we pinned back (transformers 4.57.1, datasets 4.4.2).
5. **Data.** The README's GitHub release asset is missing; the data and raw outputs are only on Google Drive (same README). They are public and complete, so this is not missing data.
6. **Scripts we wrote outside the repo** (runner loops, comparison and aggregation):
   * `runs/start_server.sh`, `runs/run_model.sh` / `run_model_seq.sh` / `run_model_par*.sh`, `runs/queue.sh`, `runs/extra_llama_unmatched.sh`.
   * `tools/*.py`.
