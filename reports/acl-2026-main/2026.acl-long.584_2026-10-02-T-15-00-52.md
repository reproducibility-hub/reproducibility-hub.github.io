## Summary
CostBench is a benchmark. The paper's claims are the scores of 10 LLMs (Tables 3/4) and trends under task length and dynamic blocking (Figs 2, 5, 6).
I re-ran every **open-weight** model the paper evaluates that fits on 1×H200 (Qwen3-8B/14B/32B, Llama-3.1-8B-Instruct), using the released `env/run.py`
on all 381 test queries, with seed 42, costs 15–25, noise σ=0.1, 20 max steps, temperature 0, and the longest tool banned (Table 6 settings and the authors' scripts).
- **Greedy baseline** (computed by the released simulator) matches Table 3 and Table 4 **exactly** (EMR 10.76 / 3.41, ANED 74.74 / 84.82, AED 2.202 / 3.194, cost gap 0.269 / 0.524). This confirms the environment, tool costs and ground truth are the same as the authors'.
- **Table 3 (task seq 5):** Qwen3-32B matches on nearly all metrics (EMR 33.86 vs 33.60, ANED 51.3 vs 52.5, TCR 90.0 vs 90.55). Qwen3-8B is within the paper's 95% CI on EMR/ANED. Qwen3-14B EMR is 29.1 vs 33.45 (TREND). Llama path metrics are within tolerance, but ITUR is 4.1% vs 32.5%.
- **Table 4 (task seq 8):** Qwen3-8B and Qwen3-32B match well. The **Qwen3-14B row does not reproduce**: EMR 7.35 vs 1.57, ANED 76.6 vs 81.3, cost gap ~2× the paper's. In our runs 14B beats greedy and 32B rather than sitting at greedy level.
- **Trend claims hold:** performance declines with task length (Fig 2); 8B→14B gives a clear gain and 14B→32B a marginal one at length 5. For Qwen3-14B, dynamic blocking lowers EMR under cost change (29.1→18.5), ban tool (→8.1) and preference change (→25.2), while remove-tools has no consistent effect (34.0), as in Fig 5. Repeated cost changes drive Qwen3-14B EMR to ~0 after 2 blocks and exactly 0 after 3, as in Fig 6 and the text.
- **Not run:** GPT-5, Gemini-2.5-Pro, Claude-Sonnet-4, GPT-4o, DeepSeek-V3.1 (API keys needed, none configured), GLM-4.5 (355B, also run via API in the config). The paper's headline numbers (e.g. GPT-5 <75% EMR at length 8) are therefore untested. Also not run: Fig 3 (noise sweep, includes Gemini), Fig 4 (coverage needs GPT-4o-mini as extractor), dynamic results for the closed models, and the Figure 9 seed robustness.

## What I ran
- Env: conda Python 3.12, `pip install -e codebase`, vLLM 0.30.0 (torch 2.13). Models are served with `vllm serve <model> --max-model-len 40960 --enable-auto-tool-choice --tool-call-parser hermes` (Llama: `llama3_json`), with prefix caching and `VLLM_USE_FLASHINFER_SAMPLER=0` (no nvcc on node for the FlashInfer JIT). Qwen3 runs in default thinking mode with no reasoning parser, as `eval.py` expects (it strips `<think>` itself).
- Search DB: `python env/domains/travel/generate_search_space.py --generate_test --test_config_path env/domains/travel/travel_config.yaml --num-times 5000 --num-time-combinations 5000 --seed 42`. I verified that every TimeInfo/groundtruth ID in `queries.json` exists in it.
- Eval command (`run_eval.sh`): `python env/run.py --tool_creation_seed 42 --refinement_level R --max_tool_steps 20 --tool_mode memory --min_atomic_cost 15 --max_atomic_cost 25 --noise_std 0.1 --ban_longest_tool --query_path env/data/runtime/queries/queries.json --model_name M --temperature 0.0 --max_tokens T --start_index 0 --end_index -1 --num_threads 24-128 --use_stimulation --stimulation_num 1 --greedy --provide_atomic_tool_sequence --use_example [--use_blocker --block_mode X --block_num N]`. Task sequence = R+3.
- `max_tokens` T: 16384 (paper) for length 5. For lengths 6–8 I used 8192 (released scripts); see Discrepancies. Results for length 8 at 16384 are kept in `outputs/main_r16k/`: Qwen3-8B TCR 75.9 / EMR 4.78, Qwen3-14B TCR 70.5 / EMR 3.95, AED 4.20. The lower TCR there comes from silently failed HTTP-400 requests.
- Metric mapping (`summarize.py`): Cost Gap = avg_agent_cost − avg_gt_cost, i.e. `avg_delta_atomic`×20 (the paper's eq. 14; confirmed by the exact greedy match). AED/ANED/EMR = `tool_path_metrics`. TCR = `final_answer_accuracy`. ITUR = 1 − `valid_search_ratio`. Greedy = `stimulation_metrics`. The parenthesised "excluding redundant/extra calls" cost gap is **not in the released code**, so I re-implemented it from App. B.3.1/D.2 (exclude queries with a repeated valid tool or a valid call after the goal type was returned). Treat those values as approximate.
- Differences from the paper: max_tokens 8192 for lengths 6–8; client concurrency 24–128 (batching may perturb greedy decoding slightly); single seed (42), as in the paper's main tables.

## Why not fully reproduced
1. Closed-source models need API keys (none configured), and GLM-4.5 is too large for 1 GPU. Most headline claims (GPT-5, Gemini, Claude) are untested → coverage SUBSET.
2. Table 4 Qwen3-14B: our run is much better than reported (EMR 7.35 vs 1.57). I found no code/config difference that explains it; with the paper's 16384 max_tokens we get EMR 3.95 / ANED 82.9 / AED 4.20, closer to the paper but with TCR collapsing to 70.5. The authors may have hit the context overflow or used different serving settings, which are unspecified.
3. Llama-3.1-8B ITUR 4.1% vs 32.5%: the paper doesn't specify the tool-call parser or chat template. We used vLLM's `llama3_json`.

## Discrepancies
- (code_vs_paper, minor, affects results) The paper says max tokens 16,384, but the released scripts use 8192. With 16384 and Qwen3's 40,960 context, long task-seq-8 prompts return HTTP 400. `run.py` swallows the error and the query ends as a failure (82/381 for Qwen3-14B).
- (code_vs_paper, minor) The code's headline cost-gap metric is gap/20 (`avg_delta_atomic`), while the paper reports the raw gap. The "excl. redundant calls" variant is not implemented.
- (code_vs_paper, minor) The README setup command references a non-existent config, and the output path doesn't match the runtime path.
- (code_vs_paper, minor) The README calls the refinement_level=2 command "Table 4" (arXiv numbering). In the ACL version that is Table 3.
- (paper_internal) Sec 5.1 says Qwen3-8B/14B "collapse entirely (EMR = 0)" at length 8, but Table 4 gives 5.25 and 1.57. Also, Table 4's Qwen3-14B TCR (88.71) is identical to its Table 3 value, which may be a copy error (not counted as a discrepancy).
