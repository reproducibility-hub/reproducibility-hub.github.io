## What the paper claims

The paper trains a single GPT or nGPT (hyperspherical) Transformer block head on top of 6 backbones (mE5-large, mxbai-embed-large, Qwen3-Embedding-4B, llama-embed-nemotron-8b, Llama-3.2-3B, OLMo-3-7B). It uses three contrastive losses: SINCERE, SoftCSE with circumplex-angle weights, and the proposed CircularCSE. Evaluation uses V-Measure of spherical k-means and CD-r, the Pearson correlation with the "Circumplex Distance", on 4 datasets (Table 1 averages, Table 4 per dataset). The headline finding is a trade-off. CircularCSE gives the best psychological alignment (CD-r ≈ 0.9) and is robust to PCA down to 2-D (Fig. 5a). But it has lower V-Measure than SINCERE/SoftCSE, especially with high-dimensional backbones. The nGPT head lowers V-Measure for decoder-only LLMs.

## What I ran

* **Environment.** conda env `env/` with Python 3.12, `torch==2.7.0`, `transformers==4.57.3`, `accelerate==1.12.0`, `datasets==4.4.1`, `numpy==2.3.5`, `pandas==2.3.3` (the versions in `uv.lock`), the `flash-attn==2.8.3` prebuilt wheel, scikit-learn and scipy.
* **Training.** I used the released `codebase/utils/train_emolit.sh`, unmodified, driven by `run_grid.sh`, which only sets the script's environment variables. Variables:
  * `TRAIN_FILE=emolit_12labels_train.csv`, `VALID_FILE`/`TEST_FILE=emolit_12labels_test.csv`. The script's defaults `emolit12_labels_*.csv` do not exist.
  * `MODEL_NAME`, `MODEL_ID`, `POOLER_TYPE` (cls / last / avg), `INPUT_DIM` (1024 / 1024 / 2560 / 4096 / 3072 / 4096), `FREEZE_ENCODER` (false for the BERT-like models, true for the LLMs), `LOSS_FUNCTION`, `CLASSIFIER_TYPE`, `EXPERIMENT_NAME`, `SEED`.
  * All other hyperparameters are the script defaults, which equal Table 3: 15 epochs, lr 5e-5 constant, batch 128, bf16, τ = 0.05, margin 0, seed 42.
  * 36 trainings per seed. Seeds 42 (the paper's seed), 43 and 44 on Emolit: 108 trainings in total.
* **Evaluation.** I wrote `eval_ecm.py` myself, because none is released. It loads the trained model with the released `BiEncoderForClassification.from_pretrained` and forward pass, and embeds the Emolit test set (1200 texts) with batch 128. It then computes:
  * V-Measure of spherical k-means (k = #labels, k-means++ seeding on cosine distance, 10 inits, keep minimum inertia, seed 42);
  * CD-r = Pearson(CD(y_i, y_j), 1 − AvgCosSim(y_i, y_j)) over the 66 label pairs i < j. CD = polarity distance (Pos–Neg 4, Neutral–Pos/Neg 2, same 0) + number of 30° steps on the ECM. Polarity is read off Fig. 3: Positive = love, joy, excitement, relief, trust; Negative = anger, fear, disgust, sadness, boredom; Neutral = surprise, calmness.
  * "Pretrained": the backbone's last hidden state with the backbone's pooling (cls / last non-pad token / mean), L2-normalised.
* **Substitute datasets.** `prep_extra_data.py` rebuilds approximate ED (8 labels, 500/100 per label, speaker's first utterance, faithful→trust) and SuperEmotion (9 labels from the GoEmotions + CrowdFlower subsets, 450/100 per label) splits following App. C. The authors' exact subsets are not released, so these are NOT_COMPARABLE.
* **PCA analysis.** `pca_robustness.py`: PCA of the mE5 head embeddings to d ∈ {2, …, 1024}, then spherical k-means V-Measure, as in Fig. 5(a), but on Emolit only.
* `aggregate.py` and `make_tables.py` produce the tables below. Logs are in `logs/` and `codebase/outputs/*/*/*/train.log`; per-run JSON and fp16 test embeddings are in `results/<TAG>/`. I deleted the trained weight files afterwards to free shared disk space (~100 GB).

### Settings that differ from the paper

* **Llama-3.2-3B.** `meta-llama/Llama-3.2-3B` is licence-gated and the HF token here has no access (HTTP 403). I used the ungated re-upload `unsloth/Llama-3.2-3B` (same weights). Its tokenizer config had been changed (left padding, a pad token), so I restored the original Meta tokenizer config in `models/Llama-3.2-3B`: right padding and no pad token, so the code falls back to EOS. Pretrained Llama numbers match the paper to 3 decimals (0.101/0.063 vs 0.100/0.064).
* **Local backbone paths.** From seed 43 on, the backbones were passed as local paths to the HF-cache snapshots (`models/*` symlinks), because of HF Hub rate limits (see below). The weights are the same as the hub ids used for seed 42.
* **Seeds.** I report the mean (± sd) over 3 seeds. The paper reports a single run with seed 42; the seed-42 column is shown too. Training is not bit-deterministic, so even seed 42 varies slightly between reruns: mE5 CircularCSE-nGPT gave 0.811/0.897 in a smoke run and 0.806/0.882 in the grid.
* **Unknown evaluation details.** The paper does not specify the k-means initialisation, whether CD-r includes the diagonal pairs, or whether mE5 used a "query: " prefix. I used k-means++ init, pairs i < j only, and no prefix. Spherical k-means V-Measure varies by about ±0.02 across clustering seeds for weakly clustered embeddings (e.g. pretrained mE5: 0.375–0.421).

## Not reproduced and why

* **PersonaGen column of Table 4, and therefore the Table 1 averages and Fig. 5(a) as published.** The synthetic dataset was generated with 7 LLMs, including the closed-source gpt-5-nano, and is not released anywhere (repo, HF Hub search). Rebuilding it would need the persona generator plus the closed API and could not reproduce the same texts.
* **ED/SuperEmotion exact subsets.** Their preprocessing and sampling are not released (substitutes above).
* **Fig. 5(b) (number of labels), Fig. 7 (39-label Emolit).** These need the full 38/39-label Emolit and the label configurations of Fig. 10. Only the 12-label preprocessed subset is released.
* **Table 5 (Fr/It/Nl Emolit), Table 6 (Qwen3-14B).** Not released / out of scope; not attempted.

## Codebase completeness: MISSING_DATA

Issues, from worst to least:
1. **Missing data.** Only the 12-label Emolit train/test CSVs are released. The paper's own synthetic PersonaGen dataset and the exact Empathetic-Dialogue / SuperEmotion subsets used for Tables 1/4 are absent.
2. **Missing scripts.** There is no evaluation code at all: no embedding extraction, spherical k-means, V-Measure, CD-r, PCA or MDS. I wrote `eval_ecm.py` and `pca_robustness.py` from Sec. 4.2. There is no data-preparation code for the other datasets (I wrote `prep_extra_data.py`), and no driver for the model × loss × head grid (I wrote `run_grid.sh`, which only sets env vars of the released script).
3. **Minor config/loading issues** (no source edits were needed):
   * `train_emolit.sh` defaults to the non-existent files `emolit12_labels_{train,test}.csv`; the files are `emolit_12labels_*.csv`. I set them via env vars.
   * `BiEncoderForClassification.from_pretrained` calls `AutoConfig.from_pretrained(path)` without `trust_remote_code`, so loading a trained llama-embed-nemotron model fails. My eval script works around this by forcing `trust_remote_code=True` (eval-side monkey-patch, no codebase edit).
   * The SoftCSE config always loads an unused frozen `intfloat/multilingual-e5-large` "similarity_calculator" (`use_angle_map=true`). This only wastes memory and time.
   * `nGPT_model.py` imports `flash_attn`, which is never used. The environment needs flash-attn installed; a prebuilt wheel worked.
   * The head's `last` pooler takes index `attention_mask.sum()-1`, which is only correct with right padding. All original tokenizers used are right-padded, so this does not matter here, but it would silently break with left-padded tokenizers such as the unsloth Llama mirror's.

**No file under `codebase/` was modified.** `git status` shows only the 4 substitute ED/SuperEmotion CSVs I added under `codebase/dataset/` as untracked files. The training outputs in `codebase/outputs/` are git-ignored.

## Discrepancies

* **code_vs_paper (major: different attention mask in the head), App. B, Eq. 15–16 vs `nGPT_model.Block.forward`.** The paper says that for unidirectional (decoder-only) backbones the head's attention attends to tokens 1..t (causal). The code always uses `F.scaled_dot_product_attention(..., is_causal=False)` with only a padding mask, i.e. bidirectional head attention for every backbone. This affects the decoder-only (Llama-3.2-3B, OLMo-3-7B) results. The released bidirectional version reproduces the paper's numbers (Llama rows within ~0.01), so the paper's results were most likely produced with bidirectional heads and the text is inaccurate.
* **code_vs_paper (minor), `train_emolit.sh` default file names.** They do not match the released dataset files (see above).
* **code_vs_paper (minor), heads (`modeling_classifier.py`).** The heads apply dropout 0.1 to the backbone hidden states and use sinusoidal RoPE inside the head block (`nGPT_model.Block`). Neither is mentioned in the paper (Table 3 / App. B).
* **paper_internal: none found.** Table 1 values equal the Table 4 averages for the rows checked (e.g. mE5 0.760/0.317, Llama 0.725/0.358).
