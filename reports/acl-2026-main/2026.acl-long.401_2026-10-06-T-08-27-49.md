## Discrepancies
**Code vs. paper**
1. *(minor, affects results)* Temperature: the paper says T=0.0 and top-p 0.95 for all experiments. `run_guard.sh` uses T=0.6 / top-p 0.95 (the code script uses 0.0).
2. *(major, affects results)* Undocumented "boxed answer" early termination in the math pipeline, implemented with a token-id set that contains generic tokens (`\`, `{`, `ed`, `Box`, `BOX`). It truncates trajectories and branches.
3. *(major, affects results)* Branch selection: the paper (Eq. 5) picks the branch with minimal mean entropy. The code adds a +10 bonus to branches that triggered the early stop and then ends the sample.
4. *(minor)* Branch sampling: the inhibitory branch prefix is "Wait" (no comma) at T=0.6; the counterfactual branch runs at T=1.5. The paper doesn't specify these.
5. *(minor)* Late-stage control: the paper (Eqs. 6–7) replaces the predicted token "Wait" with `</think>` when ρ_t ≤ 0.2. The code instead:
   - stops continuing after a branch when ≤2000 tokens remain;
   - then runs a regenerate loop with "Wait" as a stop string, string-replacing "Wait" with `</think>`;
   - applies that loop to every unfinished trajectory regardless of position, including ones that ended by EOS.
6. *(minor)* Trigger quantile (Eq. 3): computed over previous delimiter-position entropies only, with ≥5 such entries and >200 remaining tokens required.
7. *(minor)* LiveCodeBench models are loaded with fp8 quantization, which the paper doesn't mention.

**Paper-internal**
1. Table 1's Entro-duction rows for 7B and QwQ-32B are (nearly) identical to the 1.5B row, which looks like a copy-paste.
2. Sec. 5.1 says greedy decoding (T=0.0), yet BASE cells report std over 3 runs (e.g. 57±2.6, 78.9±1.3).

## Notes on the compute setup
- vLLM 0.5.1, required by the repo, is CPU-bound on this node (~250 tok/s single-sequence for 1.5B, ~2k tok/s batched). Running several processes on one GPU was slower (GPU time-slicing), which is why the per-sample loop was batched.
- No processes outside this session were touched.
