1. Read the paper and cloned the repo into `./codebase`, which has no source edits (`git status` is clean).
2. Created the environment `./env`: python 3.10, torch 2.4.1+cu121, numpy 1.26.4, networkx 2.8.4, scipy, tqdm. The repo's `spec-file.txt` pins torch 2.0.0+cu117, which does not support the H200, so I used a newer CUDA build.
3. Generated the data with the released script, using the paper's settings (App. C: ER n=100, p=0.04; USG n=100, ρ=0.3; seed 42 is fixed in the script):
   - 90/10 split, for Tables 1–3: `python generate_dataset.py --type er --nodes 100 --edge_p 0.04 --train_ratio 0.9` (and `--type usg --edge_p 0.3`).
   - 50/50 split, for Appendix E Tables 5–7: the same commands with `--train_ratio 0.5`. The paper says it used *new* graphs for Appendix E; the script's fixed seed gives the same graph, so we only re-split the pairs.
4. Trained with `python train.py --dataset {er,usg} --method {standard,lse} --n_tokens K --lambda_l L --lambda_s S`, using the defaults otherwise: 6 layers, 6 heads, 120-dim, 20k iterations, batch 1024, lr 5e-4, cosine schedule to 5e-5, 1000 warmup steps, bf16, grad-clip 1.0 — all matching App. C.4.
   - 90/10 split: NTP plus MTP and LSE(0.1,0.1) for K=2,3,4 on both graphs = 14 models, × 3 seeds. The extra seeds use `scripts/train_seed.py`, which runs the unchanged `train.py` with its hard-coded seed 1337 shifted by 1 and 2.
   - 50/50 split: the same 14 models, plus LSE at (0.3,0.3), (0.5,0.5) and (0.3,0) for K=2,3,4 on both graphs = 32 models.
   - Total: 74 models, about 30 min each, run 10 at a time on one H200.
5. Evaluated every model with the released scripts, run with `PYTHONPATH=<repo root>`:
   - `test_accuracy.py`: temperature 0.8, the default.
   - `evaluation/eval_representation_alignment.py --k {2,3,4} --max_samples 4000`, following the paper's "4,000". The script samples from `val_incremental.txt`, so it used all 990 (90/10) or 4950 (50/50) validation paths.

   - `evaluation/eval_structural_hallucinations.py --max_samples 10000`, the paper's 10,000. 6. Parsed the logs with `scripts/aggregate.py` (writes `results.json`) and built the tables with `scripts/make_tables.py` (writes `tables.md`, `comparisons.json`).

### Settings that differ from the paper
- Graph instances: we use the graphs that the released generator produces with seed 42, not the authors' exact instances. Appendix E uses the same graphs as the main experiments rather than new ones.
- The 90/10 runs use 3 training seeds; the paper reports one run.
- PyTorch is 2.4.1 instead of 2.0.0, for H200 support.
- Accuracy decoding is stochastic: temperature 0.8 with no fixed seed.

### Matching rule
A row is NUMBERS_MATCH if the relative difference is ≤5%. For [0,1] similarities and probabilities, an absolute difference ≤0.01 also counts; for success rates on the 0–100 scale, an absolute difference ≤1 point counts. Otherwise a row is TREND_MATCH if its difference from the reference model (MTP for LSE rows, NTP for MTP rows) has the same sign as in the paper, and NO_MATCH if the sign flips.

Caveat on Table 5: many LSE rows are labelled NUMBERS_MATCH (within 5% relative) even though LSE < MTP, which contradicts the paper's claim. The claim-level table above is what drives the overall label.

## Why it is not fully reproduced
1. **Missing code.** The Manhattan Taxi experiment (Table 4), one of the two settings named in the abstract, cannot be run from the release.
2. **Method claims only partly hold.** These results come from the released code run without edits:
   - LSE-MTP's belief-compression gain over MTP reverses on ER.
   - Its navigation-accuracy gain (Appendix E) does not appear.
   - The λs=0 collapse is much weaker than reported.
3. **ISP is lower than reported.** Absolute ISP values are 1.5–4× below the paper's, but the ordering is preserved. This may come from the graph instances or the candidate mining; the paper's description of ISP candidates ("action-token pairs sharing a future token f") is looser than the code's.

## Codebase completeness: MISSING_SCRIPTS
- **No source edits** to the released code.
- **Environment fixes:**
  - torch 2.4.1+cu121 instead of the spec-file's 2.0.0+cu117, for H200 support.
  - The `evaluation/*.py` scripts need `PYTHONPATH=<repo root>` because they import `model` from the parent directory. This is undocumented.
- **Output paths:** `train.py` writes to `data/` and `out/` relative to the working directory, and the folder names don't encode train_ratio or λ. I ran each configuration in its own directory under `runs/`, using symlinks to the unchanged code.
- **Missing from the release:**
  - The whole Manhattan Taxi pipeline (Table 4).
  - The linear toy model for Figure 3 (not targeted here).
- **Scripts I wrote** (all in `scripts/`, none of them method code):
  - `train_job.sh`, `eval_job.sh`, `isp_one.sh`: job runners.
  - `train_seed.py`: seed-offset wrapper for the extra seeds.
  - `isp_precise.py`: full-precision printout of the released ISP functions.
  - `aggregate.py`, `make_tables.py`, `paper_numbers.py`, `write_status.py`: log parsing and tables.
