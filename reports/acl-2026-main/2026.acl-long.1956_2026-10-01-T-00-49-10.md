## Summary

* The paper's central quantitative result on its own model of record — **Qwen3-30B-A3B-Instruct-2507, OAKS-B, Base setting (full 1,224 questions × 62–66 intervals = 78,994 queries)** — reproduces closely: All 36.1 vs 35.8, Sparse 39.0 vs 38.5, Moderate 37.7 vs 37.3, Frequent 29.2 vs 29.4 (Table 2); question types and AL/DS/PM (Tables 3 and 6) also match within ~1 point (tracking 25.0 vs 27.1 is the only row outside tolerance).
* **Thinking helps (Sec. 5.2, Tables 3/6)**: Qwen3-30B-A3B-Thinking-2507 on 1224/1224 questions gives All 43.3 vs 36.1 for the Instruct model on the same questions (paper 43.6 vs 35.8), with the largest gains on tracking/bridge and a large drop of the phase-miss rate PM, as in the paper.
* **RAG (top-30, Qwen3-Embedding-0.6B)** on one OAKS-B document (111 questions): 36.3 vs 33.1 Base on the same document (paper, full set: 37.8 vs 35.8) — same direction.
* **Model size**: on documents 0–3 (413 questions) Qwen3-4B 23.5 < Qwen3-30B 33.7 (paper 26.4 < 35.8). Qwen2.5-7B scores 26.2 there, i.e. slightly *above* Qwen3-4B, whereas the paper has 24.7 < 26.4 (small ranking flip between the two weakest baselines; subset only).
* **OAKS-N**: only the public half of the dataset is released (19 books / 435 q vs 39 / 870). With the released prompt and the released answer extractor Qwen3-30B gets 47.9 (paper 62.8) because ~14% of answers are not in the `answer:` format the extractor expects; the paper says a stricter `## Answer: [CHAR]` instruction was used, which the released prompt lacks. With a lenient letter extractor (sensitivity analysis, our script) we get 61.8 / 72.0 / 63.2 / 57.0 vs the paper's 62.8 / 71.2 / 63.7 / 57.1.
* The release does **not run as-is** (crash on a README argument; context truncation/rolling window not implemented; evaluation script tied to unreleased internal files), hence `DOES_NOT_RUN` as released and `MAJOR_FIXES`.

### Settings that differ from the paper

* **Scale**: RAG only on document OAKSB00 (111/1224 questions); Qwen3-4B and Qwen2.5-7B only on documents OAKSB00–03 (413/1224 questions); Qwen3-30B Base and Thinking on the full OAKS-B (1224/1224). Reason: one GPU and a 48 h limit; every query re-reads up to 128k tokens of context (the paper reports ~125 A100-hours for one Qwen3-30B baseline run). Models not run: Qwen3-8B, Qwen3-Next-80B, Qwen3-235B, GPT-OSS-20B/120B (time), Gemma-3-4B/27B (gated on HF, 403), Gemini 2.5/3 (closed, no API key), HippoRAG2/MemAgent/A-Mem (no code released).
* **OAKS-N data**: released public subset only (19/39 books, 435/870 questions).
* **max_tokens 2048 instead of 4096** for the Qwen3-4B (after the first 12.5k queries), Qwen2.5-7B, OAKS-N and the last ~3.6k RAG queries. Justification (measured on the full Qwen3-30B OAKS-B run with 4096): 3.7% of outputs are degenerate repetitions that hit the 4096 limit (0 of them correct); only 11 of 78,994 outputs that were correct were longer than 2048 tokens (≤0.014 points). Thinking runs keep 4096.
* **Cascade attention**: the released code hard-codes `disable_cascade_attn=True` for Qwen3-30B-A3B. To fit the time budget we enabled it (env `ALLOW_CASCADE=1`) for the remaining ~53k Qwen3-30B OAKS-B queries and all later Qwen3-30B runs, after verifying on document OAKSB00 (6,696 shared queries) that it gives the same accuracy (33.6 vs 33.5) and degenerate-output rate (1.0% vs 1.2%).
* **Scheduling**: a streaming generation loop replaces the synchronous `--batch-size` loop (same prompts and sampling parameters; only affects speed). Because jobs were restarted several times (resume by `doc_id`), some queries were generated in later restarts; this does not change the protocol.
* Sampling is stochastic (T=0.7, no seed in the release); the paper reports single runs too.

## Claims

1. *OAKS is hard; accuracy drops for frequently changing facts* — reproduced (Qwen3-30B: Sparse 39.0 > Moderate 37.7 > Frequent 29.2; OAKS-N lenient 72.0 > 63.2 > 57.0).
2. *Larger/better models do better* — reproduced for Qwen3-4B < Qwen3-30B (subset); Qwen2.5-7B vs Qwen3-4B ordering flips on our subset (26.2 vs 23.5; paper 24.7 vs 26.4).
3. *Thinking improves accuracy, mostly by reducing phase misses (PM) while DS rises* — reproduced in direction (see table above).
4. *Naive RAG gives limited/modest changes* — on one document RAG is +3.2 points over Base (paper +2.0 overall), direction consistent; not comparable in size.
5. Agentic memory systems (Table 4) and closed models (Gemini) — not run (no code / no key).
