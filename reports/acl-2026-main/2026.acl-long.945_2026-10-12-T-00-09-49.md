# Reproduction report: AHD — Anchor-based History-stable Decoding (2026.acl-long.945)

## Verdict
* **Verdict: PARTIALLY_REPRODUCED**
* **Result match: MIXED** (as released: MIXED, because no source edits were made)
* **Coverage: SCALED_DOWN**. Fixed first-N subsets of six benchmarks; HumanEval is the full set. Only the LLaDA tables (Tables 1–2) were run, without MMaDA (Table 3) or DIFFA (Table 4).
* **Codebase completeness: RUNS_AS_IS**

**Summary.** The released code ran Table 1 (LLaDA-8B-Instruct) and Table 2 (LLaDA-1.5) with no edits, comparing the Semi-AR baseline (256 steps, block 32) against AHD.
* **Step reduction reproduces.** AHD's reduction in decoding steps reproduces closely in every setting. For example, BBH: 52.7 vs 51.48 steps; HumanEval: 77.6 vs 77.24; MBPP: 65.8 vs 66.03; MMLU-Pro: 139.6 vs 133.06.
* **Accuracy gains reproduce only partly.**
  * The headline result, LLaDA-8B BBH, reproduces: +2.78 over 756 items vs +3.67 in the paper.
  * Also reproduced: LLaDA-8B HumanEval (+2.44 vs +2.44, exact), MBPP on both models, TruthfulQA on both (bleu_acc), ASDiv on both, and LLaDA-1.5 MMLU-Pro.
  * Not reproduced: LLaDA-8B MMLU-Pro (−1.07 vs +1.85), MATH on both models (−0.57 and −1.71 vs +0.12 and +0.02), and LLaDA-1.5 HumanEval (−0.61 vs +1.22). LLaDA-1.5 BBH shows no gain: 0.00 with the script's ε=0.05 and −1.06 with the paper's ε=0.01, vs +1.55 in the paper.
  * Net: the gain appears in 9 of 14 model×benchmark settings. That doesn't support the paper's claim of "consistent performance improvements across all seven benchmarks".
  * Caveat: our subsets have a standard error of about 2–3 points, so a single ±1–2 point difference is weak evidence either way.

## What was run
* **Environment.** Python 3.12 conda env at `./env`, built from `codebase/llada/requirements.txt` (torch 2.8.0, transformers 4.57.0, lm_eval 0.4.9). The env was installed cleanly and later removed.
* **Models.** `GSAI-ML/LLaDA-8B-Instruct` and `GSAI-ML/LLaDA-1.5` from the HF Hub (bf16).
* **Hardware.** 1× H200. The paper used 8× H20.
* **Command.** Each run is the README / `eval_*.sh` command (see `scripts/run_one.sh`):
  ```
  cd codebase/<llada|llada1.5>
  python eval_llada.py --tasks <task> --num_fewshot <k> --batch_size 1 --limit <N> --confirm_run_unsafe_code --model llada_dist \
    --model_args model_path=<hf snapshot>,gen_length=256,steps=256,block_length=32,show_speed=True,decoding_strategy=<baseline|AHD>,save_dir=...[,threshold_AHD=0.9,kl_threshold_AHD=<eps>,history_length_AHD=<H-1>,decay_lambda_AHD=0.5] \
    --output_path ... --log_samples
  ```
* **Tasks and settings.** Taken from the released scripts and Appendix Table 10:
  * BBH: `bbh` (CoT, 3-shot)
  * MMLU-Pro: `mmlu_pro` (0-shot)
  * HumanEval: `humaneval` (0-shot)
  * MBPP: `mbpp` (3-shot)
  * TruthfulQA: `truthfulqa_gen` (0-shot)
  * MATH: `minerva_math` (3-shot)
  * ASDiv: `asdiv_cot_llama` (0-shot)
* **AHD hyper-parameters.** Taken from the released scripts:
  * LLaDA-8B: ε=0.02 for HumanEval, ε=0.05 for BBH, ε=0.01 for everything else; H=6 throughout.
  * LLaDA-1.5: as LLaDA-8B, except HumanEval ε=0.01, MBPP H=4, MATH ε=0.001 with H=7, and BBH ε=0.05 (the paper's Table 11 says 0.01; that value was also run as an extra).
* **Scoring.**
  * HumanEval is scored with the released `postprocess_code.py`, as the README says.
  * The paper doesn't say which TruthfulQA metric it reports. We use `bleu_acc` (the first metric lm-eval prints) as primary and list the ROUGE metrics below. With `rougeL_acc`, the TruthfulQA gain turns negative on both models (−1.6).
  * MATH uses lm-eval's `math_verify` as primary. `exact_match` is shown below.

How the match labels were assigned:
* Absolute scores are NUMBERS_MATCH within 1 point or 5% relative.
* Gain rows are NO_MATCH when the sign of the gain flips or the gain disappears.
* MATH baselines are about 4–6 points lower than the paper's on our 175-item subset. MBPP baselines are lower by 2.5–4 points on 150 items.
* Baselines that land above the paper's number weaken the reported gain. The clearest case is LLaDA-8B MMLU-Pro: 38.57 vs 35.57. The difference is about one standard error on 280 items, so we did not add the BASELINE_STRONGER_THAN_REPORTED flag.

## Why it is not fully reproduced
1. **Time budget.** Only subsets could be run, because the 256-step baseline costs 5–15 s per sample. Coverage is therefore SCALED_DOWN, and the per-benchmark standard error is about 2–3 points, which is the same size as most of the claimed gains.
2. **Inconsistent gains.** Even on these subsets, the accuracy gain is not consistent. AHD is worse than or equal to the baseline in 5 of 14 settings (both MATH runs, LLaDA-8B MMLU-Pro, LLaDA-1.5 HumanEval and BBH). That contradicts the claim that AHD improves performance on all seven benchmarks.
3. **What does hold.** The efficiency claim, a 50–80% reduction in decoding steps with almost identical step counts to the paper, holds across the board.

## Codebase completeness: RUNS_AS_IS
* **No source edits.** `git diff` is empty; only `__pycache__` directories were added.
* **What was set from outside the code:**
  * The eval scripts' placeholder paths (`path/to/...`) and the `HF_ENDPOINT` mirror were replaced by command-line values.
  * `accelerate launch` on 8 GPUs was replaced by plain `python` on 1 GPU.
  * `--limit` or `--samples` was added for subsets.
* **Scripts we wrote outside the codebase.** All are wrappers or parsers only:
  * `scripts/run_one.sh`, `scripts/queue_main.sh`, `scripts/queue_extra.sh`: job runners. A time-budget subset override lives in `logs/limit_override.txt`.
  * `scripts/aggregate.py`: collects lm-eval results and calls the released `postprocess_code.py`.
  * `scripts/build_table.py`, `scripts/make_status.py`: build the tables.
  * `scripts/speedtest.py`: timing.
* **Notes on the release:**
  * The AHD path supports batch size 1 only. The authors' `eval.md` notes that bs>1 is buggy.
  * Speed metrics are lost when a run is resumed.
  * The MMaDA and DIFFA code exists but was not exercised.

## Discrepancies
1. *code_vs_paper (minor, affects results).* `llada1.5/eval_bbh.sh` uses ε=0.05, but Appendix Table 11 lists ε=0.01 for LLaDA-1.5 BBH. We ran both: 49.21 with ε=0.05 and 48.15 with ε=0.01, against a 49.21 baseline. Neither gives the reported gain.
2. *code_vs_paper (minor).* Two constants the paper never states:
   * AHD's cross-block set also requires top-1 confidence ≥ 0.9, while Eq. 7 uses only D_acs < ε.
   * The in-block "confidence-aware parallel decoding" threshold (0.9) and the decay λ=0.5 are not given in the paper either.
3. *code_vs_paper (minor).* In `TemporalWeightedKL`, the weights are normalised over the full H−1 even while the buffer is still filling, so D_acs is a partial sum in the early steps. `history_length_AHD` equals H−1 (5 ↔ H=6), which is consistent with the paper once that indexing is accounted for.
4. *Unspecified rather than contradictory.* The paper does not say which TruthfulQA metric (BLEU or ROUGE acc) or which MATH metric it reports.
