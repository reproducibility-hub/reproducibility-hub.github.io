# Reproduction report — LGSA: Label Geometry Structuring and Aligning for Hierarchical Text Classification (ACL 2026, 2026.acl-long.1322)

## Verdict

**PARTIALLY_REPRODUCED.** Result match: **NUMBERS_MATCH**, and the same as released. Coverage: **SUBSET** (only WOS). Codebase completeness: **MINOR_FIXES**.

- I could only run **WOS (Web-of-Science)**, which is one of the three datasets in Table 3. The NYT data (LDC2008T19) and RCV1-V2 data (NIST/Reuters) are licence-gated third-party corpora. Their raw text is not available here. The repo ships only NYT document-ID lists and taxonomies.
- On WOS, the **released checkpoint** gives test Micro-F1 87.78 / Macro-F1 82.48. The paper reports 87.79 / 82.47.
- **Retraining from scratch with the released code** (Table 2 WOS hyper-parameters, 2 seeds) gives 87.57 / 82.11 (mean over seeds, best-macro checkpoint). That is within 0.4 points of the paper on both metrics.
- I also ran a fixed version where the label prototypes are learnable, as the paper describes; the released code freezes them. It gives 87.72 / 82.16, which is about the same.
- The comparative claims ("LGSA beats SIHTC/COPHTC on WOS by 0.14 / 0.38") cannot be checked. Those baselines are not in the release, and the margins are smaller than the seed-to-seed spread we observed (up to about 0.6 Macro-F1).

## What the paper claims / what was targeted

- **Main result:** Table 3, LGSA row: WOS 87.79 / 82.47, RCV1-V2 87.90 / 71.35, NYT 81.19 / 71.35 (Micro-F1 / Macro-F1).
- The paper also has ablations (Tables 4–6, RCV1-V2 and NYT only), low-resource results (Table 8) and hierarchical consistency (Table 9, RCV1/NYT only).
- **Released material:** code (https://github.com/LGSA666/LGSA), and checkpoints on Google Drive for **WOS and NYT** (no RCV1).

## What I did (exact commands)

1. **Environment:** `conda create -p ./env python=3.10`; torch 2.1.2+cu121, torch-geometric 2.6.1, transformers 4.36.2, datasets 2.16.1, swanlab (imported by train.py), wandb (imported by HPT). The README asks for "torch==2.12", which is not a real version; I used 2.1.2. The backbone is bert-base-uncased from the HF cache.
2. **WOS data:**
   - Downloaded `WebOfScience.zip` from Mendeley (dataset 9rw3vkcfy4, the official HDLTex/HPT source).
   - Converted `Meta-data/Data.xlsx` to the tab-separated `Data.txt`, as the HPT README instructs ("save Data.xlsx as Data.txt"). Script: `xlsx_to_txt.py`.
   - Ran `python preprocess_wos.py; python data_wos.py` in `codebase/data/WebOfScience`. The split is 30070 / 7518 / 9397, identical to Table 1, with 141 labels.
3. **Released checkpoint evaluation:**
   - Downloaded with `gdown` from the README's Drive folder.
   - Converted parameter names with `convert_ckpt.py`; no values change. The checkpoint was saved with torch-geometric 1.7.x GATConv names (`att_l/att_r/lin_l/lin_r`, where `lin_l == lin_r`) plus the old transformers `position_ids` buffer, while the README says to use PyG 2.6.1.
   - Then: `python test.py --name WebOfScience-released --data WebOfScience --arch <bert> --batch 64 --extra _macro|_micro`.
4. **Retraining LGSA on WOS** with Table 2 settings (λ=0.01, θt=20°, γ=0.90, batch 16, lr 1e-4, 30 epochs, the code's default):
   `python train.py --name <run> --batch 16 --data WebOfScience --arch <bert> --seed {42,3} --epoch 30 --lr 1e-4 --gof_loss_weight 0.01 --gof_angle 20 --gof_decay 0.9`
   - `released_s42`, `released_s3`: released behaviour, i.e. frozen label prototypes (`LGSA_FREEZE_PROTOTYPES=1`).
   - `fixed_s42`, `fixed_s3`: learnable label prototypes, as the paper describes.
   - `fixed_noHGA_s42`: same as fixed, but with `--gof_loss_weight 0`. This is the "−r.m. HGA" variant, which the paper only reports for RCV1/NYT.
   - train.py tests both the best-macro and best-micro dev checkpoints.
5. **HPT baseline** (the base model of LGSA, run with its official repo https://github.com/wzh9969/HPT and its defaults: lr 3e-5, batch 16, early stop 6, seed 3):
   `python train.py --name hpt_s3 --batch 16 --data WebOfScience --lr 3e-5`, then `test.py --extra _macro/_micro`.
6. **Seeds:** the paper does not say how many runs it averages or which seed it uses. The released checkpoint's args show seed 42; the code's default is seed 3. I ran both.

Observations:
- **LGSA vs HPT (both run here):** LGSA is ahead by about 0.9–1.0 Micro-F1 and 0.7 Macro-F1. Two caveats:
  - The two use different training recipes. LGSA's code uses 30 epochs with warmup plus exponential LR decay at 1e-4; HPT uses early stopping at a constant 3e-5.
  - Our HPT run is about 0.5 below the HPT number the paper cites.
- **No visible HGA effect on WOS:** the −HGA run (same pipeline, λ=0) scores the same as full LGSA (87.60 / 82.26 vs 87.73 / 82.26). The paper's HGA ablation is reported only on RCV1/NYT, so this is not a contradiction. Within our pipeline, though, the WOS gain over HPT comes mostly from the training recipe and the HGS initialization, not from the geometric loss.
- **Reruns slightly below the released checkpoint:** our retrains score 0.05–0.5 below the released checkpoint. That is within run-to-run noise, and the paper's numbers are still within tolerance. Separately, the evidence below suggests the checkpoint was produced by a different code version.

## Codebase completeness: MINOR_FIXES

The as-released code, run with the paper's Table 2 settings, reproduces the WOS numbers. The fixes it needed are path, file-name and environment level.

Changes to `./codebase` (uncommitted, see `git diff`):
1. **`test.py`:** replaced the hard-coded placeholder path `'/Your file path/checkpoints'` with `'checkpoints'`.
2. **`data/WebOfScience/wos.taxonomy`:** added a copy of `wos.taxnomy`. `preprocess_wos.py` writes the misspelled name, but `models/prompt.py` opens `wos.taxonomy` and crashes without it.
3. **`train.py` (2 places), `test.py`, `models/prompt.py:generate`:** the gold/prediction bookkeeping loops over GPU tensors element by element (one GPU sync per element). I changed this to `.tolist()` / one `(scores > 0).tolist()`.
   - The results are identical: the released checkpoint gives the same numbers before and after.
   - Without this, dev evaluation took 1.5–6 h per epoch on a shared GPU, which made 30-epoch training infeasible.
   - `train.py` has CRLF line endings, which first defeated this patch.
4. **`models/prompt.py` `GraphEmbedding`:** `nn.Embedding.from_pretrained(new_embedding, True, 0)` freezes the label prototypes. The paper says the prototypes are learnable ("Frozen" is a worse ablation variant in Table 5).
   - I made freezing switchable: `LGSA_FREEZE_PROTOTYPES=1` gives the released (frozen) behaviour, and the default is learnable.
   - Both variants were run; on WOS they give the same numbers within noise.
   - This is a method-level change, but not one the reproduction needed.
5. The same `.tolist()` bookkeeping change was applied to the reference HPT repo (`hpt_ref/`), which I used for the baseline.

Scripts I wrote outside the codebase:
- `xlsx_to_txt.py`: Data.xlsx → Data.txt, as the README instructs.
- `convert_ckpt.py`: renames released-checkpoint keys from PyG 1.7 to PyG 2.6; values unchanged.
- `check_frozen.py`, `check_toggle.py`: prototype analysis.
- `collect.py` → `results.json`.
- `queue.sh` and `poll*.sh` for scheduling and monitoring.

## Discrepancies

1. **code_vs_paper (major, did not change WOS results):** `models/prompt.py` `GraphEmbedding.__init__` freezes the label prototypes (`from_pretrained(..., freeze=True)`). The paper says they are fine-tuned during training: Sec. 4.4, "the learnable HGS outperforms the frozen variant". So the released code trains the paper's "Frozen" ablation variant. On WOS, frozen and learnable gave statistically indistinguishable results (82.11 vs 82.16 Macro-F1). The paper claims a gap on RCV1/NYT, which could not be tested.
2. **code_vs_paper (major, evidence-based):** the released WOS checkpoint was not produced by the released code.
   - Its label prototypes (`new_embedding`) differ from the HGS initialization the code computes (mean row difference 0.31; head labels no longer orthogonal), so they were trained, unlike in the released code.
   - Its `ideal_label_embeddings` parameter also changed, even though the released code never uses that parameter in any loss.
   - Its saved args include `align_w=0.05`, which belongs to a prototype-alignment loss that is commented out in the released `train.py` and not in the paper's objective (Eq. 14: L = Lcls + Lmlm + λLgeo).
   - So the checkpoint behind the reported WOS number most likely used learnable prototypes plus an extra alignment loss. Our retrains with the released code (and with the paper's description) still match within tolerance.
3. **code_vs_paper (minor):** the paper only says "Adam, lr 1e-4". The code adds a schedule: linear warmup for one epoch, then exponential decay toward 1e-7 (one decay step per epoch, gamma set for 49 epochs), with a fixed 30 epochs and no early stopping. The epoch count is not given in the paper.
4. **code_vs_paper (minor):**
   - The `train.py` defaults are batch 24, λ=1.0, θt=10 (the RCV1 settings).
   - The paper's WOS settings (batch 16, λ=0.01, θt=20, γ=0.9, Table 2) must be passed on the command line.
   - `grid_search.py` uses seed 42, and the default seed is 3. The paper does not state seeds or the number of runs.
5. **code_vs_paper (minor):** the README requirements are inconsistent with the release.
   - It lists "torch==2.12", which does not exist.
   - It lists torch-geometric 2.6.1, but the checkpoints were saved with PyG 1.x parameter names and need key renaming to load.

I found no paper-internal inconsistencies. All the gains quoted in the text (0.14/0.38, 0.64/1.82, 0.57, 0.22/0.36, and the ablation deltas) match Tables 3–5.

## Why this is not a full reproduction

- **RCV1-V2 and NYT need licence-gated raw corpora.** NYT is LDC2008T19; RCV1 requires a signed NIST/Reuters agreement. Neither is available in this environment, and the repo ships no text for them. These are external third-party datasets, not a gap in the release (the paper's own data-prep scripts are provided).
- As a result, Table 3 (RCV1/NYT columns) and every ablation (Tables 4–6, 9), which are reported only on RCV1/NYT, were not run.
- The baselines other than HPT are not in the release, so the "beats SIHTC/COPHTC/NERHTC" claims are NOT_COMPARABLE.
