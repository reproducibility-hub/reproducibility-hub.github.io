## 1. What the paper claims and what was targeted

TOHA scores a (prompt, response) pair by MTop-Div_G(R,P). That is the length of the minimum spanning forest that attaches the response tokens to the prompt tokens in the attention graph (distance = 1 − attention, prompt–prompt distances set to 0), divided by the response length. The score is averaged over ≤ N_max = 10 "hallucination-aware" heads, chosen on a 100-sample labelled probe set by the mean-difference ranking Δ_ij plus a greedy choice of N_opt (Algorithm 1). The main results are **Table 1** (ROC AUC, mean ± std over 5 random splits, 25 % test, probe set of 100) on five datasets × three LLMs.

**Reproducible part of Table 1:** the two RAGTruth benchmarks are public with human span labels and the models' own responses: *MS MARCO* (RAGTruth QA) and *CNN/DM + Recent News* (RAGTruth Summary). I ran both for all three models: Mistral-7B-Instruct-v0.1, LLaMA-2-7B-chat and LLaMA-2-13B-chat. That is 6 of the 15 TOHA cells in Table 1.

**Not reproducible here:** CoQA, SQuAD and XSum (the other 9 TOHA cells). The authors generated their own responses and labelled them with **GPT-4o** (App. D.1, Tables 17 and 20). Neither the labelled generations nor an OpenAI key is available. The README says to "prepare your raw data files in .csv format", and `config/preprocess/coqa.yaml` expects `data/raw/CoQA/coqa_<model>.csv`, which is not in the repo. Rebuilding these datasets would mean substituting the closed GPT-4o annotator, so they were not run. This is why coverage is **SUBSET**. HotpotQA (Table 3), the transfer experiments (Fig. 3c), LLaMA-3.1/Qwen-2.5 (Tables 6–7) and the ablations were not run either.

**Baselines:** the release includes baseline code. I ran the two cheap single-generation baselines, **Max entropy** and **Perplexity**, through the released `run_unsupervised.py` on RAGTruth QA as a sanity check of the setup. They finished for Mistral-7B and LLaMA-2-13B; the LLaMA-2-7B runs were OOM-killed (§4). Not run: the consistency-based baselines (SelfCheckGPT, semantic entropy, EigenScore), which need 5–20 sampled generations per item, and HaloScope, LLM-Check and ReDeEP (time budget). Claims about those baselines are not verified.

## 2. What I ran

**Environment:** `conda create -p ./env python=3.11`, then pip-installed torch 2.4.0 (cu121), transformers 4.43.2, tokenizers 0.19.1, huggingface_hub 0.25.0, hydra-core 1.3.2, omegaconf 2.3.0, ripser 0.6.12, scikit-learn 1.5.1, scipy 1.14.0, pandas 2.2.2, joblib 1.4.2, numpy<2, comet_ml, plus the packages imported by `src/methods/__init__.py` (easydict, selfcheckgpt 0.1.7, nltk 3.8.1, evaluate, datasets, num2words, einops, optuna). Versions follow `container_setups/environment.yml` where pinned. The Docker image was not used.

**Data:** `response.jsonl` and `source_info.jsonl` from the official RAGTruth repo (github.com/ParticleMedia/RAGTruth, `dataset/`), placed in `codebase/data/raw/RAGTruth/`. The released `PreprocessRAGTruth` keeps quality == "good", labels is_hal = (any annotated span), uses both RAGTruth splits, and for LLaMA-2-13B summaries keeps prompt+response ≤ 1450 words. Resulting sizes (n / #hallucinated): Mistral QA 939/378, Summ 940/615; LLaMA-2-7B QA 971/497, Summ 943/434; LLaMA-2-13B QA 984/396, Summ 899/276.

**Main command** (from `codebase/`, once per model × task):
```
COMET_AUTO_LOG_DISABLE=1 python run_mtopdiv.py preprocess=ragtruth_{qa|summ} model_name=<model> 'transfer_names=[]' \
    method.device=cuda:0 method.n_jobs=14 method.n_max=10 hydra.job.chdir=False \
```

The job queues are `run_queue*.sh` and the logs are in `logs/` (`<model>_<task>_n10*.log`). The evaluation is the released `src/evaluation/evaluation.py::evaluate` with `config/evaluation/default.yaml`: k = 5 splits (seeds 42–46), test_size 0.25, probe/val size 100. Heads are selected on the probe split by the released `MTopDiv.fit_hyperparameters` (unsupervised mode = Algorithm 1), and the test score is the mean MTop-Div over the selected heads. The reported number is mean ± std of test ROC AUC over the 5 splits.

**Shipped-default variant (N_max = 6):** the shipped `config/method/mtopdiv.yaml` has `n_max: 6`, while the paper uses N_max = 10 "in all experiments". The main result uses the paper value. For the extra N_max = 6 column I re-ran the released `evaluate()` with `n_max=6` on the cached MTop-Div features (`eval_from_cache.py`, no LLM forward passes). The N_max = 6 head set is always a prefix of the N_max = 10 greedy ranking on the same probe set, so its full-dataset features are columns of the cached N_max = 10 features. As a check, `eval_from_cache.py <task> <model> 10` reproduces every `run_mtopdiv.py` number exactly (`logs/n10_*.json`).

**Settings that differ from the paper:**

## 4. Problems encountered

1. **GPT-4o-annotated datasets (CoQA, SQuAD, XSum) are not released**, and rebuilding them needs the closed GPT-4o annotator. Those Table 1 cells were not run (coverage SUBSET).
2. **Comet logger requires an API key.** `run_mtopdiv.py` always builds `comet_ml.Experiment(api_key=os.getenv("COMET_API_KEY"))`, which raises without a key. I worked around it with the env var `COMET_AUTO_LOG_DISABLE=1` (the experiment object becomes a disabled no-op); no code change.
3. **HF login.** `LLMBase.get_model_id` calls `huggingface_hub.login(os.getenv("HUGGING_FACE_API_KEY"))`, so the key must be in `codebase/.env`. I created it and deleted it at the end.
4. **Config defaults that must be overridden.** `config/method/mtopdiv.yaml` sets `device: cuda:3` (overridden to `cuda:0`) and `n_max: 6` (paper: 10). It also hard-codes `n_layers: 32, n_heads: 32`; for LLaMA-2-13B (40 × 40 heads) these have to be overridden, otherwise only 32 × 32 heads are searched. `hydra.job.chdir=False` is needed because the relative data/cache paths otherwise break. `transfer_names=[]` is needed because the transfer branch of `run_mtopdiv.py` reads `cfg['method']['zero_out']`, which is not in any config, and would crash with a KeyError after the main results print. Transfer is not part of Table 1.
5. **Runtime.** The released feature extractor runs `ripser` for every head (1024, or 1600 for 13B) on each of the 100 probe samples in every split, through joblib worker processes. With 14 cores this took ~12–15 s/sample on QA and ~35–90 s/sample on summarization: 2–3 h per QA cell and 7–14 h per summarization cell. The paper's efficiency figures refer only to inference with the ≤ 10 selected heads.
6. **Crash in the LLaMA-2-7B summarization run.** In split 3, joblib raised `BrokenProcessPool` / `FileNotFoundError` on a memmap file in `/dev/shm` that disappeared mid-run. I re-ran with `JOBLIB_TEMP_FOLDER` pointing to the job-private `$TMPDIR` (env var only, plus automatic retry). The run resumed from the per-split caches written by the released `cache_result` decorator, so the result is the same as an uninterrupted run.
7. **Baseline memory.** The released max-entropy and perplexity baselines keep full-vocabulary logits for every sample in RAM and on disk (16–72 GB of cache for one QA dataset). The LLaMA-2-7B QA baseline runs died silently (most likely OOM-killed under the 111 GB job limit). I did not start the summarization baselines, so as not to risk OOM-killing the main TOHA runs. I deleted these caches afterwards.

## 6. Discrepancies

- **code_vs_paper (minor):** `config/method/mtopdiv.yaml` sets `n_max: 6`, but the paper (§3.5, Algorithm 1, Fig. 4) uses N_max = 10 "in all experiments". Effect on our cells: ≤ 0.007 AUC on 5 of them; on LLaMA-2-7B summarization 0.537 → 0.531.
- **code_vs_paper (minor):** `config/method/mtopdiv.yaml` hard-codes `n_layers: 32, n_heads: 32`. LLaMA-2-13B has 40 × 40 heads, so the shipped config would search only 64 % of the heads for 13B. The paper ranks all heads.
- **code_vs_paper (minor):** the `run_mtopdiv.py` transfer branch reads `cfg['method']['zero_out']`, which no config defines, so the default `transfer_names: ["ragtruth_qa"]` crashes after the main results. This does not affect Table 1.
- **code_vs_paper (major, baseline only):** `src/methods/perplexity/perplexity.py` scores each answer token with the logits from the same position (off by one), which is not the standard perplexity the paper attributes to Ren et al. (2023). Our perplexity AUROCs (0.638 / 0.647) differ greatly from the paper's (0.45 / 0.54), so the paper's perplexity numbers were probably produced by different code.
- **paper_internal:** in Table 4 (MTop-Div column), Mistral-7B MS MARCO = 0.65 ± 0.02 and LLaMA-2-7B MS MARCO = 0.76 ± 0.04 (CoQA 0.90 / 0.89). Table 1 gives Mistral-7B = 0.76 ± 0.04 and LLaMA-2-7B = 0.65 ± 0.02 (CoQA 0.89 / 0.90). The model labels in Table 4 appear to be swapped.
