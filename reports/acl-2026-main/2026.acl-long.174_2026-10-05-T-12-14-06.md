**One-paragraph summary.** The repo implements SAGE (MI pseudo-feature table, Feature Selector = `sample`, Logit
Correction = `sample_logits`) but ships an evaluation pipeline only for Iris. Run **as released**, the
constrained decoding destroys numeric features with GPT-2 (the default model of the run scripts). Only single-character
tokens may be generated for numbers, commas are forbidden at every step, and since the 2026-04 commit the separator
is masked out of the training labels, so a value can never terminate. Housing gives MAPE 0.86/0.70 (FS) and
0.80/0.68 (LC) with a 53 % California-boundary violation rate (paper: 0.34/0.25, 0.64/0.40, 4.73 %/2.65 %). Adult
education-consistency violations are 36 %, and the repo's own Iris script gives 60–83 % accuracy (paper 96.55/100). With
three small fixes (allow multi-digit number tokens, block the comma only as the *leading* token, keep the separator
as a training target as in the pre-2026-04 code, plus robust number parsing), results get much closer. Housing
(3 seeds): FS RF MAPE matches (0.257 vs 0.25), FS DT is slightly outside tolerance (0.367±0.027 vs 0.34); LC is *better* than reported
(0.332/0.240 vs 0.64/0.40); FS violation matches (5.7 % vs 4.73 %). Adult (2 seeds): macro-F1 matches in all four FS/LC×DT/RF cells
(0.677/0.765/0.716/0.786 vs 0.68/0.75/0.72/0.76), and the FS education violation matches (1.28 % vs 1.32 %); LC DT accuracy matches
(78.8 vs 82.58 is within 5 %), RF accuracies are higher than reported, FS DT accuracy is lower (75.8 vs 80.66). HELOC (3 seeds): RF
matches (70.9/71.9 vs 70.89/70.58). Diabetes (1 seed): RF accuracy, LC DT accuracy, LC RF F1 and the FS discriminator match. But several numbers do not:
DT accuracies on HELOC (≈10 points lower; our real-data DT is also 6.7 points lower than the paper's "Original" row),
Iris (≈75–87 % vs 96.55/100 with GPT-2, ≈86–92 % with Qwen3-0.6B), the Housing LC violation (5.1 % vs 2.65 %) and several
Table-2 discriminator values. Some FS-vs-LC comparisons the paper makes are reversed in our runs (we get lower MAPE
with LC, not FS; lower Adult violation with LC, not FS); the claim "LC lowest Housing violation" holds (LC < FS in
all 3 seeds). The paper's central comparative claims (beats GReaT/TabSyn/…, +10 % F1 vs GReaT, −1 point violation vs
GReaT) could not be checked, because no baseline code or configs are released: **NOT_COMPARABLE**. Taken against the
paper's own reported GReaT numbers, our Adult F1s (0.677–0.786) are above GReaT's reported 0.60/0.69.

## What was attempted

**Target.** Table 1 (downstream utility: DT/RF trained on synthetic data, tested on the real 20 % test split — accuracy + F1 for
classification, MAPE for Housing), Figure 4 / Table 3 (constraint violation rates: California boundary for Housing,
education↔education-num consistency for Adult), and, as secondary checks, Table 2 (SVM real-vs-synthetic discriminator,
5-fold CV) and Figure 7 (per-LLM results for GPT-2 / Qwen-3 on Adult and Housing). Datasets: Adult Income, HELOC, Iris,
CDC Diabetes (3-class), California Housing. **MIC was not run** (target column not specified in the paper/repo; 111 features
exceed GPT-2's 1024-token context when serialised).

**Code.** `https://github.com/ShuoYangtum/SAGE` @ `3e9e129` (HEAD, 2026-04-07). The repo contains the SAGE library
(`sage.py`: `fit`, `sample` = Feature Selector (FS), `sample_logits` = Logit Correction (LC)), an Iris-only evaluation
script (`run_iris_formal_eval.py`) and an imputation CLI (`run_sage.py`, not described in the paper). There is no
script that generates synthetic data and evaluates it for the other datasets, and no script for the violation /
discriminator metrics; these were written by me (`scripts/`), calling the released library unchanged except for the fixes
listed below.

**Environment.** conda env (python 3.11) with the pins of `setup_and_run.sh` / `environment.yml`
(torch 2.4.1+cu121, transformers 4.53.2, peft 0.11.1, pandas 2.2.2, numpy 1.26.4, scikit-learn 1.4.2,
python-Levenshtein 0.27.1, accelerate 1.8.1) + shapely/kagglehub/ucimlrepo for data & metrics. 1× H200.

**Data.** Kaggle datasets linked in the README (adult.csv, heloc_dataset_v1.csv, housing.csv, diabetes_012_health_indicators_BRFSS2015.csv
— the 3-class version, matching the paper's "3 classes"; the README's UCI link is the binary version), Iris from
scikit-learn exactly as in `run_iris_formal_eval.py`. 80/20 split, `random_state=42`, stratified for classification.

**Settings used (paper → ours).**
- Base LLM: not stated for Table 1. Main runs use **GPT-2** (default of `run_sage.py` / `run_iris_formal_eval.py`; Figure 7 also
  reports GPT-2 numbers). Sensitivity runs with **Qwen/Qwen3-0.6B-Base** (named in a code comment and in Figure 7). README's
  Llama-3.2-1B is gated (HTTP 403) → not run.
- Full fine-tuning (as in the run scripts; `use_lora=False`), AdamW, lr 1e-4, **batch size 8** (paper §4.3), up to 30 epochs with the
  repo's early stopping (patience 5 on the repo's validation loss; val split = min(10 %, 300 rows)). Adult stopped at 12 epochs,
  Housing 9, HELOC 16. **Diabetes: stopped manually after 2 epochs** (val loss rose after epoch 1; best = epoch 1 checkpoint) for
  compute reasons. Qwen-Adult likewise stopped after 3 epochs (best = epoch 1).
- Bins / MI threshold τ (FS) / λ (LC): Table 6 values (Adult 5/0.0004/1.0, HELOC 10/0.0142/1.0, Iris 5/0.119/1.2,
  Diabetes 20/0.0063/0.8, Housing 10/0.004/1.0), equal-width bins (Eq. 4). The released default would be FD bins and τ = median MI.
- Sampling: `temperature=1.0`, `p=0.7` (README/iris script; in the code this is the fraction of features copied from a random real row
  as the prefix), hard-coded `top_p=0.95` and `top_k=30/50`; LC clip [0.5,1.5] (code default). `copy_factor=1`.
- Number of synthetic rows = size of the training split (paper: "same sample size as the original datasets").
  Exceptions: as-released Adult (10 000 rows/mode) and as-released Diabetes (20 000 rows/mode) because the released decoding is ~10× slower;
  as-released Qwen Housing (5 000 rows/mode); Qwen Adult (10 000 rows/mode).
- Downstream models: `DecisionTree(random_state=42)`, `RandomForest(n_estimators=300, random_state=42)` (as in `run_iris_formal_eval.py`),
  categorical features ordinal-encoded. F1 = macro-F1 (the Adult "Original" row of the paper, 0.73/0.78, is consistent with macro-F1;
  we report weighted F1 in results_summary.json too).
- Violation (Housing): fraction of synthetic (longitude, latitude) outside the 2010 Census 500k California polygon (the real
  training data itself gives 1.14 % with this polygon). Violation (Adult): fraction of rows whose `educational-num` differs from the
  canonical value of `education` in the real data. Discriminator: RBF-SVM on standardised features, 2 000 real + 2 000 synthetic
  rows, 5-fold CV (the paper does not give the subsample size).
- Seeds (generator training + sampling): Iris 5 (42–46); Housing and HELOC 3 (42–44); Adult 2 (42–43); Diabetes 1 (42). As-released and Qwen runs: 1 seed (Iris: 5). The paper does not
  state its number of runs.

## Why it is not fully reproduced
1. **Released code bug (decoding)**. As released, numeric/categorical values cannot terminate during constrained decoding,
   and (for BPE tokenizers such as GPT-2's) numbers can only be spelled with single-character tokens. Generated numbers are mostly
   unparsable and replaced by the column minimum; integers get extra digits and are clipped to the column max. This
   affects every dataset with numeric features (results above, "as released" columns).
2. **Missing pipeline**. Only Iris has an evaluation script; generation + DT/RF evaluation for the other datasets, the violation
   metrics and the discriminator were written by me from the paper's description. Choices the paper leaves open (F1 averaging,
   categorical encoding, DT/RF hyper-parameters, discriminator subsample, California polygon) may explain part of the gaps.
3. **Unspecified settings**. The paper does not say which LLM produced Table 1 (README: Llama-3.2-1B with LoRA, gated → not
   accessible; run scripts: GPT-2; Figure 7: GPT-2/Qwen-3/Llama-3), how many runs the significance tests used, or which MIC
   label is predicted. Table 6 thresholds disagree with the "median MI" rule stated in the text.
4. **Compute**. Diabetes generator trained for 2 epochs (best = epoch 1) instead of early stopping with patience 5; most datasets
   1–3 seeds (Iris 5, Housing/HELOC 3, Adult 2, Diabetes 1). MIC was not run.
5. **Baselines** (TVAE, CTGAN, TabSyn, GReaT, GRADE, SPADA) have no released code/configs → every "SAGE beats X" claim is
   NOT_COMPARABLE.

## Codebase completeness: MISSING_SCRIPTS
Changes made to the released code (left uncommitted in `./codebase`, `git diff` shows them):
1. `generation.py::NoLeadingCommaLogitsProcessor.__call__`: forbid "," only as the first generated token (it was forbidden at every
   step, so a value could never end). *Result-changing bug fix.*
2. `sage.py::fit` (numeric features): allowed-token set for numbers extended to every vocabulary token consisting only of
   `0-9 . -` (new helper `_numeric_token_ids`); previously only single-character tokens, incompatible with GPT-2/Llama BPE
   number tokens. *Result-changing bug fix.*
3. `sage.py::fit` (categorical features): "," added to the allowed-token set so a categorical value can terminate.
4. `sage.py::apply_constraints`: parse the leading well-formed number (`-?\d+(\.\d+)?`) instead of `float()` on the whole
   generated string (which fails and falls back to the column minimum).
5. `motf_datasets.py::FeatureTextDataset`: the ", " separator is kept as a training target (as in the repo before commit 3e9e129) so the
   model learns where a value ends. *Training change; requires retraining.*
6. (Supplementary variant only, separate copy `codebase_promptfix/`): sampling prompt `"<feat> is "` (trailing space, as used in
   training and in the repo's own validation loss) instead of `"<feat> is"` in `sample`/`sample_attn`/`sample_logits`.
   Not used for the main numbers.
