### Settings that differ from the paper
- **Bootstrap.** Paper/Table 8: 100 random labeled splits, seed 0. Same here; extra seeds 1–5 were used only for robustness.
- **ATP re-simulation**:
  - GPT-4o-mini was not re-run (no OpenAI key; it is not needed for the open-model claims).
  - The MC-response parser is my re-implementation, because the released one is missing.
  - Attention is `sdpa` instead of `flash_attention_2`.
- **NHANES Domain-FT**:
  - Trained with my HF-Trainer script instead of axolotl 0.12.2, mirroring every value in the axolotl config. One difference: axolotl's exact chat-template masking may differ slightly. For Mistral-v0.3 the full-conversation template is used, and the loss covers tokens after the last `[/INST]`.
  - kcal mapping uses a substitute ϕ: a nearest-neighbour energy density over the authors' released grounded food lines, via all-MiniLM-L6-v2 embeddings. The authors' ϕ is FNDDS retrieval plus a GPT-4o-mini grounder, which is not released.
  - Validation (leave-one-file-out on released outputs): ϕ_sub vs the authors' energies give per-person corr 0.99. Bias% stays within ±0.15 points for the Qwen/Llama/Mistral FT files. ϕ_sub is weaker on free-form prompting outputs (corr 0.4–0.96).
- **Not re-run**:
  - SubPOP-FT: external llama-cookbook training; no checkpoints exist for the paper's 3 models, and no SubPOP inference config is released.
  - ATP Domain-FT: training data not released.
  - NHANES prompting methods other than the Qwen Demo-only check.
  - Table 3 (subgroups) and Fig. 2 (FT/PPI allocation): no code or split data released.

## Why it is not fully reproduced
- **Paper Table 2 vs. code.** Table 2's rectified rows cannot be regenerated from the release (they disagree with the paper's own Table 8, which the release reproduces exactly). One specific claim, that Domain-FT|Rec_λopt is clearly best with <3% average bias, is not supported by the released artifacts: methods tie at about 4.2%. All other headline claims hold, hence TREND_MATCH.
- **Coverage.** Only part of the synthesis could be re-run:
  - GPT-4o-mini: no API key.
  - SubPOP-FT: external pipeline, no checkpoints.
  - ATP Domain-FT: training data not released.
  - NHANES ϕ pipeline: code, FNDDS data and the HF dataset are missing, and it needs the closed GPT-4o-mini grounder.

## Discrepancies
1. **paper_internal: Table 2 vs. Table 8.**
   - Table 2's method averages do not equal the averages of Table 8's per-model cells. Baseline: 7.61/2.30/62.41 vs 7.49/2.11/59.00. Domain-FT|Rec_opt: 3.33/1.73/3.40 vs 3.73/4.69/3.96. Demo-only|Rec_λ=1 ATP Q1: 16.94 vs 5.73.
   - The release reproduces Table 8. The README mentions regenerated simulations after a storage loss, which may explain it.
2. **code_vs_paper (major): ATP response coding.**
   - Paper (Table 1, §4): Q1 on a 1–6 scale (mean 3.16, 691 cases); Q2 with (1) Excellent … (4) Poor (mean 3.57, 643 cases).
   - Code: Q1 A–E→4..0 with "Not sure" dropped (θ*=2.00, 630 humans); Q2 Excellent=4 … Poor=1 with Not sure/Refused dropped (θ*=1.58, 576 humans).
   - ATP relative-bias percentages depend on this. The README acknowledges it, and the paper's tables were computed with the code's coding.
3. **code_vs_paper (minor): sampling.**
   - Paper: "τ=0.7 for all models".
   - Code: `simulate_hf` passes only `temperature`, so Mistral-v0.3 (no `do_sample` in its generation_config) decodes greedily. Qwen and Llama also inherit default top_p/top_k (and repetition_penalty 1.05 for Qwen).
4. **code_vs_paper (minor): NHANES fine-tune data path.** The NHANES `finetune_*.yaml` train on `splits_ft_vs_ppi/ft_train_800/...` (the Fig. 2 split, not released), not on the released `human_train.chat.jsonl` that the paper's Table 2 Domain-FT uses.
