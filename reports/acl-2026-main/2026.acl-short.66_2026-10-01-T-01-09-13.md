# Reproduction report: 2026.acl-short.66, "A Shared Geometry of Difficulty in Multilingual Language Models"

**Verdict: PARTIALLY_REPRODUCED.** Result match is `TREND_MATCH` (the same after our fixes and as released), coverage is `FULL`, and codebase completeness is `MINOR_FIXES`.

The main experiment is Table 1. We ran it for all 4 models on the full dataset: 21 languages × 3968 problems, with a 70/15/15 split (seed 42). Two things limit how literally this reproduces the paper:

- **Translations.** The paper's GPT-5.1 translations aren't released, and no OpenAI key was available. We regenerated them with **Qwen3-32B**, using the repo's own vLLM script. Qwen3-32B is the alternative translator the paper evaluates in Appendix B, Table 2.
- **Results.** The headline Spearman numbers match within the paper's std for every model. However, the depth-separation statistics turn out to depend on a token-position bug in the released code (see the sensitivity run below).

Code: https://github.com/Stefano-Civelli/multilingual-difficulty-interpretability (linked in the paper). It is cloned into `./codebase`, and our edits are left as uncommitted changes.

## What was run
1. `conda create -p ./env python=3.11`, then the README's pip install list.
2. Translation: `VLLM_USE_FLASHINFER_SAMPLER=0 python -m src.scripts.2_vllm_translate_amc`, with `MODEL_NAME="Qwen/Qwen3-32B"` and `max_num_seqs=256`.
   - Greedy decoding, the prompt from Appendix A, and `enable_thinking=False`.
   - Time: about 1 h on the H200.
   - The script's 900-token prompt filter drops 7 of the 3975 problems, leaving 3968.
   - Output is in `codebase/data/translation/amc_translations_Qwen_Qwen3-32B.csv`, with a copy in `translations_backup_qwen3-32b.csv`.
3. Probing: swapped in transformer-lens 2.17.0 and transformers 4.57.6. Then, for each model, `cd codebase; python ../run_paper_results.py released <model>` (driven by `run_all.sh`). That command:
   - adds the English column;
   - points `paper_results.py`'s constants at our files;
   - calls the repo's `paper_results.main()` unchanged, which covers TransformerLens fp16 `resid_post` extraction with the chat template, Ridge probes with alpha ∈ {10, 100, 1000} chosen on dev, test-set evaluation, the figures, and the Table 1 statistics.
   - Logs are in `logs/released_*.log`, figures in `results_released/<model>/`, and the parsed numbers in `summary_released.json`.
4. Appendix E: `python -m src.scripts.4_correlation_analysis --dataset data/translation/amc_translations_qwen3-32b_21lang.csv` (log in `logs/correlation_analysis.log`).
5. Sensitivity check: `run_paper_results.py lasttokfix <llama model> --fix-last-token`, which reads the true final prompt token. Results are in `summary_lasttokfix.json` and `results_lasttokfix/`.

### Settings that differ from the paper
- **Translator:** Qwen3-32B instead of GPT-5.1. This affects the 20 non-English languages; English is the original text.
- **Llama-3.2-1B/3B weights:** loaded from the `unsloth/` re-uploads, because our HF token is not authorised for the gated meta-llama repos. The tokenizer pad token is reset so it behaves like Meta's.
- **Package versions:** transformer-lens 2.17.0, transformers 4.57.6, torch 2.13. The paper doesn't state its versions.
- **Batch size:** the default of 2 was kept. The Llama 3.x chat template inserts the current date ("Today Date: 01 Oct 2026"), so that system-prompt text differs slightly from the authors' runs.

### Assessment
- **As released:** 16 of the 24 Table 1 numbers are within tolerance. That includes all 8 Spearman means and every optimal-layer mean except Llama-3.2-1B. The rest (mostly the transfer/in-lang drops) are 5–25% off, but in the same direction.
- **Claims that hold:**
  - Same-lang beats cross-lang Spearman, significantly.
  - The same-lang optimal layer is deeper than the cross-lang one.
  - Transfer drop is much larger than in-lang drop, for every model.
- **Overall:** `TREND_MATCH`. With a different translator, numbers this close are a strong confirmation of the reported pipeline.
- **Caveat from the sensitivity run:** with the token the paper describes (the true final prompt token), the Llama results change.
  - Spearman goes *up* (8B cross-lang 0.797 vs 0.778).
  - The depth separation shrinks a lot. For Llama-3.1-8B, the same-lang optimal layer is 21.9 instead of 30.1, the transfer drop 0.073 instead of 0.190, and the in-lang drop 0.007 instead of 0.020. For Llama-3.2-3B, the layers are 18.3 / 11.9 and the transfer drop 0.065 instead of 0.226.
  - The qualitative ordering still holds: diag layer > off-diag layer, transfer drop > in-lang drop, and diag ρ > off-diag ρ with p < 1e-5.
  - So the size of the "two-stage" effect reported for the Llama models depends partly on reading the `assistant` token rather than the final prompt token.
  - This is a code-vs-paper discrepancy. It is not a reproduction failure: the released code does reproduce the paper's numbers.

## Codebase completeness: MINOR_FIXES

- **Gated models:** the meta-llama 3.2 repos are gated for us, so our driver redirects loading to the unsloth mirrors.
- **No logic edits.** The only diff in `./codebase` is the 2 config lines in `src/scripts/2_vllm_translate_amc.py`.
- **Scripts we wrote:** `run_paper_results.py`, `run_all.sh`, `run_fixed.sh`, `summarize.py`, `make_status.py`.

## Discrepancies
1. **code_vs_paper, major (affects the Llama results):** in `src/model.py` `get_residual_activations`, the last token is found with `(tokens != pad_token_id).sum() - 1`.
   - For Llama, pad = eos = `<|eot_id|>`, which appears twice in the chat-templated prompt, so the code reads the `assistant` token, 2 positions before the end. We verified this by decoding the selected token.
   - The paper says the final prompt token is used.
   - Qwen3 is unaffected.
   - Effect: see the sensitivity column above.
2. **code_vs_paper, minor:** `1_gpt_translate_amc.py` defaults to `NUM_SAMPLES=1000` with an unseeded `random.sample`. The paper says all 3,975 problems were translated.
3. **code_vs_paper, minor:** `2_vllm_translate_amc.py` drops problems whose prompts exceed 900 tokens, leaving 3968 rather than 3,975. Our English Table 3 row matches the paper exactly, which suggests the paper also used 3968.
4. **code_vs_paper, minor:** `4_correlation_analysis.py` computes a LaTeX *character density*, whereas the paper's Table 3 says "LaTeX token count".
