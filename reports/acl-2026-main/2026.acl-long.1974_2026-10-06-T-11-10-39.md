# Reproduction report — AdaFuse: Adaptive Ensemble Decoding for Large Language Models (ACL 2026, 2026.acl-long.1974)

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): MIXED.** AdaFuse's own numbers reproduce on 5 of 6 Table 1 benchmarks (NQ, SQuAD, TriviaQA, GSM8K, Flores En→De), and the 6-task average matches (62.48 vs 63.23). The Top-2 GSM8K row also matches (87.34 vs 90.25, within 5% relative). Flores De→En misses (41.15 vs 45.25). The large gains the paper attributes to AdaFuse over the base models do not hold. Running the base model through the *released* pipeline with ensembling switched off (Llama-3.1-8B paired with itself) gives much higher base scores than Table 1 reports: NQ 42.63 vs 34.24, SQuAD 91.83 vs 80.13. With that baseline, AdaFuse's gain on NQ shrinks from +8.61 to +0.25 pts, and on SQuAD it turns into −0.20. The comparison against the ensemble baselines (LLM-Blender, DeePEn, SweetSpan, UniTE), which carries the headline "6.88% average relative improvement", is NOT_COMPARABLE: the release contains no code or configs for them.
- **Result match as released: DOES_NOT_RUN.** `AdaFuse_two_models.py` crashes on import (`from utils.ans_process import *`; the `utils/` package is not in the repo). Four of the five evaluators also crash, on missing imports (`w2n`, `sacrebleu`).
- **Coverage: SUBSET.** The full "AdaFuse (Fixed Base)" row of Table 1 was run at full scale (all 6 benchmarks, full test files). For the "Top-2 Base" row only GSM8K was run (Qwen3-8B + Llama-3.1-8B), and the GSM8K row is the only place where it differs from Fixed Base apart from a 0.23-pt SQuAD difference. ## What the paper claims (Table 1)

Table 1 covers 6 benchmarks: NQ (5-shot EM), SQuAD (5-shot EM), TriviaQA (5-shot EM), GSM8K (4-shot CoT accuracy), Flores-101 En→De and De→En (0-shot spBLEU). Settings: AdaFuse with a fixed Llama-3.1-8B-Instruct + Mistral-7B-Instruct-v0.3 pair, τΔ = 0.7, M = 3 words per round, and diversity-aware scaling (Sec 3.3) disabled (i.e., B = 1). Paper average 63.23, which it reports as +6.88% over the best ensemble baseline (SweetSpan, 59.16).

## What I ran

- Code: https://github.com/CCM0111/AdaFuse (commit c7ecc71), cloned to `./codebase`. All data ship inside the repo (`local_datasets/`). Prompts and test files are the authors' own: NQ `test/natural-questions.jsonl` (3610), SQuAD `squad_2500.jsonl` (2500), TriviaQA `wikipedia-test-6000.jsonl` (6000), GSM8K `test.cleand.jsonl` (1319), Flores devtest (1012 each direction). Sizes match paper Appendix C.
- Environment: conda env, Python 3.10, torch 2.4.1+cu121, transformers 4.51.3, tokenizers 0.21.0, accelerate 1.6.0, datasets 3.0.2 (the versions in paper App. D.4), plus sacrebleu 2.6.0, word2number, sentencepiece. Hardware: 1× H200; models in fp16, as in the code.
- Command, per shard (each dataset split into shards and run by 2–3 concurrent workers on the one GPU; `scripts/worker.sh`):
  ```
  python AdaFuse_two_models.py --test_set <shard>.jsonl --prompts <task prompt> \
     --model_path1 meta-llama/Llama-3.1-8B-Instruct --model_path2 mistralai/Mistral-7B-Instruct-v0.3 \
     --output_file out.jsonl --theta_delta 0.7 --max_words 3 --max_total_tokens 512 \
     --span_length 1 --max_span_rounds {5 for NQ/SQuAD/TriviaQA, 1000 for GSM8K/Flores}
  ```
  Shard outputs were then concatenated and scored with the repo's `evaluation/eval_{nq,squad,trivia,gsm,spbleu}.py` (`scripts/evaluate_all.sh`).
- Settings chosen by me (none of them is documented in the repo):
  - `--span_length 1` instead of the code default of 4. See Discrepancies. With the default, the first "word" of a round is up to 4 words cut from a 7-token window. That often truncates a word mid-way ("ger aniums", "pet unias") and gives rounds of up to 6 words, which contradicts the paper's M = 3. The paper's word-per-round statistics (rounds of 1/2/3 words only) and Example 1 can only come from span_length = 1. On the first 33 GSM8K items: span_length=4 gives 18/33 and span_length=1 gives 22/33. A first full run with the default was aborted after 132 GSM8K items (59.1%); its logs are in `runs/main_spanlen4_aborted/`.
  - `--max_span_rounds`: the default of 5 rounds cannot finish a GSM8K chain of thought or a Flores sentence, so I used 1000 for those tasks, with generation bounded by `--max_total_tokens 512` (see code change 2). The QA tasks keep the default of 5. QA answers finish well within 5 rounds (max prediction length 40 tokens).
- Extra runs (sanity checks on the base-model rows, not part of the release):
  1. **Released pipeline with ensembling switched off**: the same `AdaFuse_two_models.py`, with `--model_path1 = --model_path2 = Llama-3.1-8B-Instruct`. Both "models" produce identical candidates, so this is greedy word-level decoding of Llama through the authors' code. Run on NQ, SQuAD and TriviaQA (`runs/selfens_llama/`).
  2. **My own single-model greedy script** (`scripts/single_model_baseline.py`): same prompt construction, same answer cleanup (`clean_text_before_question` / `extract_boxed_answer`) and same evaluators. HF batched greedy decoding. Run for Llama and Mistral on all 6 benchmarks (`runs/single/`). On NQ, SQuAD and TriviaQA it agrees with run 1 to within 0.2 pts.
  3. **AdaFuse (Top-2 Base) on GSM8K**: Llama-3.1-8B-Instruct + Qwen3-8B, the two best GSM8K models in Table 1. Same settings (`runs/top2_gsm/`).

## Why it is not fully reproduced

1. As released, the main script does not run: the `utils/` package it imports is missing, and the evaluators lack imports.
2. Undocumented CLI settings had to be chosen: `span_length` (the code default contradicts the paper's M = 3) and `max_span_rounds` (the default of 5 truncates GSM8K and translation).
3. Flores De→En is 4.1 BLEU below the paper.
4. No code exists for the four ensemble baselines or the base-model rows, so the headline relative improvement can't be checked. The base models evaluated through the released pipeline come out much stronger than reported.
5. The Top-2 configuration was run only for GSM8K (87.34 vs 90.25), and there it is below Qwen3-8B alone (91.51 with my greedy script, vs 89.99 in the paper). For SQuAD the top-2 pair would be Mistral + InternLM3, and I didn't run InternLM3, for time.

## Discrepancies

1. **code_vs_paper (minor, affects results)** — `AdaFuse_two_models.py::generate_candidate_spans` / `--span_length` (default 4). Paper (Sec 3.1–3.2, Alg. 1, Sec 4.3 statistics, Example 1): each round commits at most M = 3 *words*, starting from one complete word. Code: the "first word" is `" ".join(valid_words[:span_length])` from a 7-token greedy continuation, i.e. up to 4 words, often cut mid-word, and then up to 2 more words, so up to 6 words per round. The `--max_words` argument (README: `--max_words 3`) is never used. I matched the paper with `--span_length 1`; on GSM8K the default is clearly worse (18/33 vs 22/33 on the same items).
2. **code_vs_paper (minor, affects results)** — `--max_total_tokens` / `--max_span_rounds`. Paper: generation bounded by a task-dependent limit of up to 512 tokens. Code: `--max_total_tokens` is unused, and length is governed only by `--max_span_rounds` (default 5 rounds), which truncates GSM8K CoT and Flores translations when run with the README command.
3. **code_vs_paper (minor, affects results slightly)** — word construction in `generate_candidate_spans`. The paper describes extending tokens until a whitespace boundary. The code splits decoded text on whitespace, drops punctuation-only "words" from the first segment, and re-joins with single spaces. Newlines are lost, and stray fragments appear in GSM8K outputs (e.g. "$80,000 $130"). It doesn't change the method's logic but alters generated text.
4. **paper_internal** — Sec 4.2 text says AdaFuse improves "+10.25 pts on SQuAD" over Llama (80.13), but Table 1's Fixed-Base SQuAD is 90.15 (+10.02). +10.25 corresponds to the Top-2 row (90.38).
5. **paper_internal (minor)** — the PDF title is "AdaFuse: Adaptive Ensemble Decoding with Test-Time Scaling for LLMs"; the anthology/catalog title is "AdaFuse: Adaptive Ensemble Decoding for Large Language Models".
