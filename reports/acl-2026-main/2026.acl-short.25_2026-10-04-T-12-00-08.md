# Reproduction report — *Prefix Parsing is Just Parsing* (ACL 2026, 2026.acl-short.25)

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): TREND_MATCH.** As released: **TREND_MATCH**. I made no edits to the source, so the two are the same.
- **Coverage: FULL.** I ran every experiment the paper reports (Fig. 1, Tables 1–2, Fig. 2 left and right) at the paper's scale. The only thing not run is the WSJ 5000 CKY row, which the paper also leaves out.
- **Codebase completeness: MINOR_FIXES.** No source edits were needed. The fixes were to the environment and command line only: no LaTeX on the node, `--n-workers` has to be given explicitly, and the README's sparse command needs an extra EarleyX flag.

Most numbers match within tolerance:
- All fitted runtime exponents (Fig. 1, Fig. 2).
- The prefix-vs-parse slowdown (~3.0× vs. the paper's ≈2.9×).
- Every Social Discourse grammar size, the WSJ 500 Table 2 row (exact), and the WSJ 5000 Table 2 row (within 1.4%).

A few numbers fall just outside the 5% tolerance, but the conclusions still hold:
- Next-token/prefix coefficient ratio: 1.32 vs. the paper's "≈1.2".
- Table 1 WSJ 500 prefix-grammar size: 220,367 vs. 235,459 (−6.4%), so the ratio is 3.01× vs. 3.22×.
- EarleyX exponent in Fig. 2 left: 2.10 vs. 1.99.

Absolute runtime coefficients (`a`) depend on the hardware and can't be compared directly. Because of these out-of-tolerance entries, I graded the overall match as TREND_MATCH rather than NUMBERS_MATCH.

## What was run

- **Paper:** https://aclanthology.org/2026.acl-short.25.pdf
- **Code:** https://github.com/genlm/prefix-acl-26 (linked from the paper), cloned with its `earleyx` submodule (fork commit `1171b93`) into `./codebase`.
- **Environment:** conda env at `./env` with Python 3.11 and, from conda-forge, rust 1.98, openjdk 11 and ant.
  - `pip install ".[bench,test]"` (built the PyO3 Rust extension).

- **Hardware:** 14 CPU cores (Slurm allocation; the GPU was not used — the paper's experiments are CPU-only), about 111 GB RAM.

### Commands (run from `codebase/`)

`run_wrapped.py` (in the attempt dir) is a thin wrapper that does two things:
- turns off `text.usetex`, because no TeX is installed;
- pickles the raw timings the scripts already compute.

It does not change any logic.

1. **Fig. 1:**
   ```
   python ../run_wrapped.py benchmarks/benchmark.py ../results/fig1_raw.pkl \
     --grammar grammars/grammar_5000.txt --sentences grammars/sentences_500.txt \
     --backend rust-rescaled --n-workers 12
   ```
   This runs 435 sentences, i.e. those with at least 10 tokens (the script's default filter). Power laws are fit on positions 10–50 with the script's own WLS fit.
2. **Tables 1–2:** `python benchmarks/benchmark_grammar_size.py --grammar <G> --start <S>`, for:
   - `earleyx/grammars/wsj500unk.grammar` (this is the paper's "WSJ 500"; `--timeout 14400`, so CKY unary removal finishes);
   - `earleyx/grammars/socialDiscourse.grammar` (`--start Discourse`);
   - `grammars/grammar_5000.txt`, Earley pipelines only (`--only "Earley(G)" "Earley(PG(G))"`; the paper omits WSJ 5000 CKY too).
3. **Fig. 2 left:**
   ```
   python ../run_wrapped.py benchmarks/benchmark_earleyx.py ../results/fig2left_raw.pkl \
     --grammar grammars/grammar_5000.txt --sentences grammars/sentences_500.txt --n-workers 12
   ```
   EarleyX took about 6.5 h on 12 JVMs.
4. **Fig. 2 right:**
   ```
   python ../run_wrapped.py benchmarks/benchmark_sparse.py ... \
     --grammar earleyx/grammars/socialDiscourse.grammar \
     --sentence earleyx/data/socialall.ortho.yld.concat --start Discourse \
     --max-position 2000 --earleyx-extra "-io em -maxiteration 1"
   ```
   - The README command, which has no `--earleyx-extra`, crashes inside EarleyX with an NPE at `EarleyParser.java:1019`. The script's own docstring predicts this.
   - `-decode marginal` (the other flag the docstring suggests) parses all words but then NPEs in `MarginalDecoder`, so the script aborts.
   - The reported numbers come from a rerun on an otherwise nearly idle node. The first run, made while the EarleyX WSJ job loaded 12 cores, gave distorted exponents: ours 1.15, EarleyX 0.89.
5. **Sanity checks:**
   - `pytest tests/test_earleyx_comparison.py tests/test_prefix.py`: 16/16 pass. Prefix weights match EarleyX exactly on proper (normalized) PCFGs.
   - `analyze_fig1.py` refits Fig. 1 from the raw timings.

### Settings that differ from the paper

- **Hardware and worker count.** I used 12 parallel workers on 14 cores. The paper doesn't give its machine or worker count. Absolute runtimes and coefficients `a` are therefore not comparable; ratios and exponents are.
- **Worker count must be set.** The script default `n_workers = multiprocessing.cpu_count()` returns 224 on this node, which would start 224 grammar-loading processes of about 2 GB each and run out of memory. I set `--n-workers 12`.
- **EarleyX flag for the sparse run.** The paper doesn't say which flag it used.

**Claims checked:**
- **Prefix parsing keeps the N-dependence of parsing.** Confirmed: exponents agree within about 0.02.
- **The overhead is about the grammar-size factor.** Confirmed: 3.0× slowdown against a 2.86× size increase.
- **Next-token weights cost only a small constant factor more.** Confirmed: 1.32× in the coefficient, below the 4× bound.
- **The blowup from the prefix transformation is small in practice.** Confirmed by Tables 1–2.
- **Faster than EarleyX by a constant factor.** Confirmed: about 22× on WSJ 5000.

**Correctness check.** On WSJ 5000, EarleyX's prefix probabilities differ from ours by up to about 3× relative. This is expected and not a bug:
- `grammar_5000.txt` is not a proper PCFG. Per-LHS rule sums range from 0.82 to 1.47, and its treesum is about 0.004.
- Stolcke's algorithm assumes a proper PCFG; the repo's test docstring says so.
- On normalized grammars, the repo's tests show exact agreement, and they passed.
- In the Fig. 2 comparison, EarleyX therefore computes different values on the unnormalized WSJ 5000 grammar. Since that figure compares runtime, not values, this doesn't affect its conclusion.

**Other observations:**
- The Fig. 1 run reports 415 "UNDERFLOW" warnings. These are exact zeros:
  - complete-string weights of prefixes that aren't complete sentences (414);
  - one prefix weight of 0 (sentence 320, position 27). This is probably a real zero, given UNK replacement.
- The README's `grammars/grammar_500.txt` is **not** the paper's "WSJ 500" grammar: it has |G|=18,912 and 70 nonterminals. The paper's WSJ 500 is `earleyx/grammars/wsj500unk.grammar`, which matches Tables 1 and 2 exactly.

## Discrepancies

1. **Paper internal (Fig. 1 caption).** The caption says "Prefix parsing is roughly 2.9× slower than parsing (fitted coefficient a = 30.9 vs 12.1)", but 30.9/12.1 = 2.55. Our measured coefficient ratio is 3.02.
2. **Code vs. paper, minor (Table 1, WSJ 500 |G2|).** The released `benchmark_grammar_size.py` (binarize → prefix_grammar → CKY chain) gives 220,367 instead of 235,459, so the ratio is 3.01× instead of 3.22×. |G1|, |N1| and |N2| match exactly.
3. **Code vs. paper, minor (Table 2, WSJ 5000 |G2|).** 500,772 instead of 494,017; |N2| is 85,386 instead of 84,566.
4. **Code vs. paper, minor (Fig. 1 caption, "≈2.86× size increase (binarize, then prefix)").**
   - The code's 2.86× comes from `prefix_grammar` applied to the *unbinarized* grammar: 333,349/116,663, which matches the README's "333.7k".
   - Binarizing first and then prefixing gives about 418k (3.58×).
   - The input-grammar stats (35,014 rules, 447 nonterminals, size 116,663) differ by a handful from the caption (35,016, 448, 116,667).
5. **Code vs. paper, minor (README, Fig. 2 right command).** The command as given crashes in EarleyX (NPE). It needs `--earleyx-extra "-io em -maxiteration 1"`. The paper doesn't say which EarleyX mode it used.

## Codebase completeness: MINOR_FIXES

No source files in `./codebase` were modified (`git status` is clean apart from build artefacts). Fixes and additions:
- **No TeX on the node.** The three benchmark scripts hard-code `text.usetex=True`. I ran them through `run_wrapped.py`, which turns that off and also pickles the raw timings.
- **`--n-workers` must be passed.** The default `cpu_count()` (224 here) would run out of memory.
- **The README's sparse benchmark command crashes in EarleyX.** It needs the `--earleyx-extra "-io em -maxiteration 1"` CLI flag, which the script's docstring mentions.
- **The WSJ 500 grammar in the tables is a different file from the one in `grammars/`.** It is `earleyx/grammars/wsj500unk.grammar`, which is what the script docstring uses.
- **CKY unary removal on WSJ 500 prefix grammar needs a longer timeout.** It exceeded the default 1800 s per-stage timeout, so I used `--timeout 14400`.
- **Scripts I wrote (analysis only):**
  - `analyze_fig1.py`: refits Fig. 1 using the repo's own fit functions and computes ratios.
  - `crosscheck.py`: compares prefix weights with EarleyX.
  - `run_sizes.sh`: driver for the grammar-size runs.
