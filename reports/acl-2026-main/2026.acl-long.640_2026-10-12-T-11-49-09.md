## Discrepancies

1. **code_vs_paper (minor, does not affect EZ numbers)** — Appendix B: "Our implementations [of LOSS, Zlib, Min-K%++] are included in the repository" and "The [SPV-MIA] code is included in our repository". The repository contains only the EZ-MIA package `mia/`.
2. **code_vs_paper (minor, affects only over-fit checkpoints)** — `mia/ez_score.py::error_zone_pos_neg_sum_ratio`: the paper defines EZ = P/N; the code returns 0.0 (the lowest possible score) if N = 0 or if there are fewer than 2 error tokens, so the most strongly memorised sequences are ranked as least likely members. ≤0.04% of samples in the paper's settings; 26% of members on GPT-2-XL/XSum epoch 3.
3. **code_vs_paper (minor, no effect when using configs)** — CLI defaults in `mia/config.py` (train_total 8000, eval_total 2000, batch 8, lr 5e-5, LoRA r 8/α 16) differ from the paper's protocol (10k/10k, batch 16, lr 1e-4, r 16/α 32); the YAML configs have the paper's values.

No paper-internal inconsistencies found (we checked the averages/multipliers in §5.1–5.3 and the abstract against Tables 1, 2, 6). The code selects the best-validation-loss checkpoint, as the paper describes; this matches, but the selection is fragile (see AG News/Llama-2).
