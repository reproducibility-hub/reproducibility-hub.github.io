## 1. What the paper claims (target)
Table 3 is the main result. CoPoLLM, built on Llama3.1-8B, Qwen3-8B or Qwen2.5-7B and fine-tuned with DSCO on CogBiasESC-PRO, beats 15 baselines on:
- Cognitive Distortion Diagnosis (CDD): macro P/R/F1. Best F1 is 0.641 (Qwen3).
- HRMDR (high-risk missed detection rate). Best is 0.203 (Llama).
- Six intervention-quality Likert metrics, rated by GPT-4o and by human experts.

The reproducible, non-judge part is CDD P/R/F1 and HRMDR. The GPT-4o-judge columns need a closed judge and the human columns need experts, so neither was run (`CLOSED_JUDGE_UNAVAILABLE`). The ablations in Table 4 need CPRL plus GPT-4o data generation and were not run.

## 2. What was released
- GitHub repo: `data/train.json` (1,346 dialogues), `data/test.json` (324 dialogues), task1 (LLM annotation and DQN pool), task2 (CPRL DQN), task3 (SFT-data generation with a teacher LLM), task4 (DSCO SFT scripts).
- HF: `Chips95/Lora_Adapter_for_ACL2026_CoPoLLM`, LoRA adapters for all three backbones.
- **Not released:**
  - CogBiasESC-PRO, the CPRL-policy-guided, GPT-4o-generated SFT data actually used for DSCO.
  - The D4-derived part of train and test (withheld under the D4 DUA). The paper uses 2,094/405 dialogues; the release has 1,346/324.
  - The DQN training pool `Total_S_train_pool.jsonl`.
  - Any inference or evaluation code.
- Size check: the released adapters' `trainer_state.json` shows 2,145 steps/epoch × 32 samples ≈ 68.6k training samples/epoch. `train.json` yields only about 22.7k samples (17,060 generation + 5,686 resampled classification).

## 3. What I ran
Environment: conda env at `./env` with Python 3.11, vllm 0.10.1.1, torch 2.7.1, transformers 4.55.4, trl 0.19.1, peft 0.17.1 and bitsandbytes. Base models are the HF-cached `Qwen/Qwen3-8B`, `Qwen/Qwen2.5-7B-Instruct` and `meta-llama/Llama-3.1-8B-Instruct`.

1. **Evaluation script (written by me, none released): `scripts/eval_cdd.py`.**
   - Covers every annotated seeker utterance in `test.json`: 1,022 utterances, 42 of them gold high-risk.
   - Prompts are built exactly in the training format of `task4/sft_unified.py`: `[TASK_TYPE:CLASSIFY]\n[CLS_TASK-分析任务]\n<SYS_PROMPT_CLASSIFY>\n历史对话：\n<history>患者：<utt>\n\n### Response:\n`.
   - Decoding uses vLLM with LoRA at T=0, top_p=0.9, top_k=5 and max_tokens=128 (App. B.1).
   - The output parser reads the `认知偏差标签/安全风险/偏差强度` lines.
   - CDD metric: the gold label is single-label, so the first predicted tag is the prediction. P and R are macro over the 8 distortion types. F1 = 2PR/(P+R), which matches how Table 3's F1 relates to its P and R (e.g. .647/.636 → .641).
   - HRMDR = fraction of gold 高危 utterances whose predicted risk is not 高危 (App. B.2).
   - `scripts/rescore.py` adds a lenient variant (a hit if the gold tag is anywhere in the predicted set). `scripts/summarize.py` adds 95% bootstrap CIs over dialogues.
2. **Released adapters:** `eval_cdd.py --base <HF base> --lora adapters/lora_adapter_for_<m>`.
3. **Retraining with the released DSCO script** (`codebase/task4/sft_unified.py`, after the masking fix in §5), run once per backbone:
   `python sft_unified.py --model_name_or_path <base> --dataset_path ../data/train.json --resample_ratio 3.0 --max_length 2048 --per_device_train_batch_size 4 --gradient_accumulation_steps 1 --learning_rate 2e-4 --num_train_epochs 3 --max_steps -1 --disable_unsloth`
   - This is QLoRA 4-bit, r=16, α=32, dropout 0.05, cosine schedule, warmup 0.03, grad-clip 0.3, which are the paper's App. B.1 values.
   - Each run is about 17k steps and 2.5–3 h on the H200.
   - Then evaluate with `eval_cdd.py`. Chain script: `scripts/chain.sh`.
4. **As-released retraining:**
   - The unmodified script gives loss exactly 0 at every step. I verified this in a real run, logged in `dual_task_loss_log.csv` before the fix.
   - With zero loss the LoRA B matrices stay at 0, so the "as-released" adapter equals the base model.
   - I evaluated each base model with the training-format prompt and no adapter (`results/asreleased_*`).
5. **Open-model baselines (sanity check only):**
   - Each base model with chat template + `SYS_PROMPT_CLASSIFY` (Qwen3 with thinking off).
   - The paper's baseline prompt is not released, so these are `NOT_COMPARABLE`.

Settings that differ from the paper:
- Training data is the released `train.json` subset with the original counselor responses, not CogBiasESC-PRO.
- The test set is the released 324-dialogue non-D4 subset, not 405 dialogues.
- `max_length` is 2048 (the paper does not state it).
- Training is a single seed.
- CPRL (task2) was not run. It needs a non-released DQN pool and local Qwen3-30B-A3B + embedding servers, and its only downstream use is guiding the closed GPT-4o teacher.

**Interpretation:**
- On the released data, DSCO fine-tuning clearly improves distortion-type diagnosis over the untuned backbone (F1 +0.25 to +0.32 over our base-model runs). CDD F1 rankings among the CoPoLLM backbones match the paper: Qwen3 > Qwen2.5 > Llama.
- Absolute F1 is 0.08–0.15 below Table 3.
- The safety claim does not reproduce: the lowest HRMDR, 0.203 for Llama, is not reached. Our best is 0.548, and the models rarely predict 高危.
- The authors' own released adapters score even lower (F1 0.26–0.40) on the released test subset. That is a hyper-parameter mismatch (lr 1e-5, 2 epochs), not a data artifact of our runs.
- Because the training data actually used (CogBiasESC-PRO plus the D4 portion) and 81 test dialogues are unavailable, none of this can be settled. Per the protocol, MISSING_DATA makes the verdict FAILED.

## 5. Codebase completeness: MISSING_DATA
Changes and additions:
1. **`codebase/task4/sft_unified.py` (MAJOR fix, affects results):**
   - The `DataCollatorForCompletionOnlyLM(response_template="\n\n### Response:\n")` template never occurs in tokenized text. Both Qwen and Llama BPE merge the leading `\n\n` with the preceding `。`/`？`, so 0 of 1,000 sampled training texts matched.
   - Every label becomes −100, and the custom `DualTaskTrainer.compute_loss` divides by `mask.sum()+1e-9`, giving loss **exactly 0**. The trainer suppresses `UserWarning`, so this fails silently.
   - Fix: pass the token ids of `"### Response:\n"` (`tokenizer.encode(...)[1:]`). Match rate becomes 100% (Qwen) and 98.8% (Llama, rest truncated).
   - This is a 4-line diff, left uncommitted.
2. **Written by me (MISSING_SCRIPTS):** `scripts/eval_cdd.py`, `scripts/rescore.py`, `scripts/summarize.py`, `scripts/chain.sh`, `scripts/run_released_and_base.sh`.
3. **Config:** script defaults `max_steps=120`, bs 2 × ga 4 were overridden to the paper's values via CLI.
4. **Env:** pinned transformers 4.55.4, huggingface_hub<1.0 and datasets<4.1. trl must be ≤0.19 because the script needs `DataCollatorForCompletionOnlyLM`. Unsloth (optional) was not installed.
5. **Missing data:** CogBiasESC-PRO, the D4 portions, and the DQN pool. Hard-coded author paths are in task2/task3. Third-party API keys are hard-coded in `task1/get_bias_label.py`. The task3 teacher model name is empty.

- `logs/` holds all training and eval logs.
- `train_runs/*/` holds the final retrained LoRA adapters and per-task loss logs (intermediate checkpoints deleted).
- `adapters/` holds the authors' adapters.
- The conda env was removed at the end.
