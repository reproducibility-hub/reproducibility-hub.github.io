## What the paper claims and what we ran

The paper proposes ASA (Activation Steering Attack), which adds a random Gaussian perturbation to the hidden state at one layer. The perturbation is renormalized to the mean and standard deviation of that layer's activations. Each of the first 100 AdvBench prompts is attacked at every layer, and QwQ-32B judges the steered responses. Metrics:

- **MASR:** fraction of prompts broken at ≥1 layer.
- **PASR:** the best layer's attack success rate.
- **INIT:** attack success rate of the unsteered response.

ASA_grad uses the sign of the gradient of the harmful-target ("Sure, here is …") loss instead of random noise. Central results: Fig. 1 (8 models) and Table 1 (ASA_random vs ASA_grad on 4 models). Supporting results: Table 3 (seeds 42/45/48), Table 4 (GCG + ASA) and Fig. 8 (4 reasoning models).

### Pipeline (all scripts are in `codebase/runs/`)

1. **Generation.** `run_one.sh MODEL METHOD SEED [DATASET] [MAXTOK]` is a thin wrapper around the released CLI: `python -m exp.effectiveness --model_name_or_path M --seed S --jailbreak {random|gasa} --dataset {advbench|gcg} --max_new_tokens {50|20} --num_samples 100`. It runs from `codebase/runs/` so that the code's relative `../data/...` paths resolve. `scheduler.sh` / `queue.txt` run up to 3 jobs concurrently on the single GPU.
2. **Judge.** `start_vllm.sh` serves `Qwen/QwQ-32B` with vLLM 0.8.5 on `127.0.0.1:10046` under the model name `qwq`, which is exactly the endpoint hard-coded in `exp/annotate.py`. `judge_files.sh` calls the released `python -m exp.annotate --target steered_response` (the paper's Fig. 7 prompt, 'parallel' mode). It calls it again with `--target original_response` to get INIT, which the annotator de-duplicates per prompt.
3. **Metrics.** `summarize.py` calls the released `exp.aggregate.Parser.random_attack` for MASR/PASR. It adds INIT (from the original-response annotations) and the peak-layer index. Output: `codebase/runs/results_summary.csv`, copied to `./results_summary.csv`.
4. **Report tables.** `make_status.py` builds the paper-vs-ours table below.

Runs completed (77,600 attacked (prompt, layer) generations in total, all judged by QwQ-32B):

- ASA_random, seed 42, AdvBench, 50 tokens: Llama-3.2-3B (+Instruct), Qwen2.5-7B (+Instruct), Llama-3.1-8B (+Instruct), Llama-2-13B-chat, and 4 DeepSeek-R1-Distill models (Qwen-1.5B/7B/14B, Llama-8B).
- ASA_grad, seed 42: Qwen2.5-7B (+Instruct) and Llama-3.1-8B (+Instruct).
- ASA_random, seeds 45 and 48: Llama-3.1-8B (+Instruct).
- GCG + ASA_random with the released GCG suffixes (`data/gcg/*.csv`), 20 tokens: the 6 models of Table 4.

### Settings that differ from, or are unspecified in, the paper

- **Model checkpoints.** Llama-3.2-3B(-Instruct) weights come from the `unsloth/` mirror; these are byte-identical re-uploads of the Meta weights. Llama-2-13B-chat comes from the `NousResearch/Llama-2-13b-chat-hf` mirror. All other models are the official HF repos.
- **Precision and prompting.** The released code runs in **fp32** with **raw prompts and no chat template**, including for Instruct models. The paper does not state either; we kept the code's behaviour.
- **Judge sampling.** The annotator sends no sampling parameters, so vLLM uses QwQ's `generation_config` (T=0.6, top-p 0.95). The judge is therefore stochastic. As a measure of noise, INIT for the same original responses differs by up to 0.02 between files (e.g. Llama-3.1-8B: 0.62 vs 0.60). We set `--max-model-len 16384`.
- **Failed judge requests.** A handful of requests (≤ 8 of 2800–4800 per file) failed. The released annotator drops these (returns `None`), so they are excluded from the metrics.
- **Not run:**
  - Llama-3.3-70B-Instruct (Fig. 1): about 280 GB in fp32, which does not fit on 1 GPU.
  - Table 2 (refusal-suffix ASA_grad): the code hard-codes `target + '!'` and the paper does not give the refusal suffixes.
  - Table 5 (no-normalization PPL ablation), Table 9 / Figs. 11–12 (LAPT training and ASABench), Table 10 (AgentHarm/XSafety/Flames), Figs. 2–4 and 13–14 (NLL landscape, NLL curves, length scaling, KL), and Table 8 (judge accuracy vs human labels).

## Codebase completeness: MINOR_FIXES

The release contains the method (`sv/intervent.py`: ASA_random / ASA_grad / trojan), the experiment driver (`exp/effectiveness.py`), the LLM-judge annotator (`exp/annotate.py`), the MASR/PASR aggregator (`exp/aggregate.py`), the GCG suffixes and AdvBench data. As released, it cannot run. All fixes were small crash or plumbing fixes, and none of them touch the attack or metric logic.

### Changes to the released code

These are left uncommitted in `./codebase`; see `git diff`.

1. **`sv/intervent.py`, `generate_w_steer`.** `torch.load('steer_layer.pt')` and the `SteerLayer` construction ran unconditionally, but no checkpoint is released. This crashed every mode (random/gasa/trojan). We moved it inside `if mode == 'mlp':`.
2. **`sv/intervent.py`, gasa branch.** It called the non-existent `self.fgsm_attack(...)`. We renamed the call to the existing `self.gasa_attack(...)`.
3. **`sv/intervent.py`, speed only.** We cache the unsteered greedy generation per prompt, because the code regenerated it identically for every layer. We restarted the first three runs with the cache and verified the outputs are byte-identical to the uncached code on 367 overlapping records. This gave about a 2× speed-up.
4. **`exp/effectiveness.py`.** The output path was missing its `f` prefix, so every run wrote to the literal file `{args.seed}_..._{args.num_samples}.json` and runs overwrote each other. We added the f-string.
5. **`exp/annotate.py`.** It imported the unreleased package `llm_safecheck` (`vLLM` class), which is used only by the unused 'dynamic' mode. We removed the import and set `self.judger = None`. The released `__main__` uses 'parallel' mode, which calls the OpenAI-compatible endpoint directly.

### Environment fixes

- `requirements.txt` pins `numpy==2.3.0` with `pandas==1.5.3`, which are binary-incompatible (import crash). We pinned `numpy==1.26.4`.
- We added `scikit-learn` (imported by `sv/pca.py` and not listed), `aiohttp` (used by the annotator) and `vllm==0.8.5` (to serve the QwQ judge, as the README implies).

### Scripts we wrote

These are thin wrappers, all in `codebase/runs/`:

- `run_one.sh`, `scheduler.sh` and `queue.txt` drive the released CLI.
- `start_vllm.sh` and `judge_files.sh` serve the judge and call the released annotator.
- `summarize.py` calls the released aggregator and adds INIT and the peak layer.
- `kw_proxy.py` is a keyword sanity check only; it is not used for any reported number.
- `../../make_status.py` builds the tables.
- Symlinks named after the short model names are needed because `--dataset gcg` looks up `path_to_name[args.model_name_or_path]` using the raw argument.

The README's `python -m exp.aggregate` reads a hard-coded directory (`steer_results_seed42_annotated`), so we called `Parser.random_attack` on our own directory instead.

## Discrepancies

### Code vs paper

1. **Normalization statistics are off by one layer** (`sv/intervent.py`, `generate_w_steer`). Minor; affects results.
   - Paper, Eq. 1: δ′ is normalized to μ/σ of h^(l), the activation at the injected layer.
   - Code: μ/σ come from `hidden_states[layer_idx]`, which is the input to decoder layer `layer_idx` (index 0 is the embeddings), while the hook adds δ′ to that layer's output.
2. **ASA_grad gradient position and target** (`sv/intervent.py`, `gasa_attack`; `exp/effectiveness.py`). Minor; affects results.
   - Paper, Alg. 1: take ∇ at the activation of the final prompt token.
   - Code: takes the gradient at position −2 of the concatenated prompt+suffix sequence (the last target token before the appended '!'), and uses suffix = AdvBench `target + '!'`. The model is put in `train()` mode for this step.
3. **No chat template** (`sv/intervent.py`). Minor; unspecified in the paper, may affect results. Prompts, including for Instruct and reasoning models, are tokenized raw without a chat template, and the models run in fp32.

### Paper-internal

1. **Single-step vs every-step injection.**
   - §3.1 describes ASA as a single injection at one generation step t ("h′_t ← h_t + δ′").
   - §4 and App. G describe injecting "at each generation step". The code does the latter: the hook's `applied` flag is never set, so δ′ is added to the last position on every forward pass during generation.
2. **Fig. 1 vs Table 1 (same setting, seed 42).** Fig. 1 MASR/PASR: Qwen-7B 0.85/0.63, Qwen-7B-Instruct 0.80/0.43, Llama-8B 0.98/0.66, Llama-8B-Instruct 0.92/0.42. Table 1 ASA_random: 0.96/0.55, 0.89/0.45, 0.99/0.69, 0.96/0.41. Table 3's seed-42 column matches Fig. 1, not Table 1.
3. **Fig. 5 PASR labels.** Fig. 5 labels PASR as 0.6 / 0.36 / 0.55 / 0.48 for the same four models, which matches neither Fig. 1 nor Table 1.
4. **Qwen2.5-7B-Instruct peak layer.** §4 says the instruct peak is at L19, while Table 9 / the LAPT discussion says it shifts from L14 to L19 after LAPT, i.e. L14 before training.
