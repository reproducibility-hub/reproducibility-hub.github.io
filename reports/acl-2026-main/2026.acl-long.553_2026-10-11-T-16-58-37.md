## What the paper claims (the targets)
- **Table 1.** On COCO Caption and GranDf, Diffusion-CAM (LaViDa backbone, hook at layer 10) beats LLaVA-CAM, Grad-CAM and TAM on all four metrics:
  - COCO: Obj-IoU 30.10, Contrast 2.58x, Concentration 51.41, F3 23.04

## What I ran
- **Model:** `jacklishufan/lavida-llada-v1.0-instruct` with vision tower `google/siglip-so400m-patch14-384`. Both are the defaults in `predict.load_model_only`, which hooks transformer block 10.
- **Data:** the README does not say where to get data. `method/diffusion_cam/dataset_prep.py` is adapted from TAM, so I used TAM's formatted data (`huggingface.co/datasets/yili7eli/TAM`, `data.tar`):
  - COCO2014: 5,000 images, of which 4,952 have `seg_label` masks.
  - GranDf: 1,000 images with `anno.json`.
  - The code expects `annotations/instances_val2014.json`, but TAM ships `instances_minival2014.json`, so I added a symlink.
- **Environment:** Python 3.10, torch 2.7.1+cu118, transformers 4.52.1, and the rest of `requirements.txt`, on one H200.
  - DeepSpeed refused to import without `CUDA_HOME`, so I installed `cuda-nvcc` 11.8 into the env and set `CUDA_HOME` (see `envvars.sh`).
- **As-released smoke test:** `python codebase/predict.py --selected_images ids.txt --ablation_mode all_methods` (`runs/smoke_asreleased`). It runs unmodified and writes per-image summary files. It never computes dataset-level numbers, and no image-id list is released.
- **Main driver:** `scripts/run_eval.py` (logs in `runs/coco`, `runs/grandf`). For each image it:
  - calls the released `predict.process_single_image(..., ablation_mode="all_methods")`;
  - re-applies the released `apply_cam_postprocess` for each `--ablation_mode` (`gaussian_only`, `confidence_only`, `background_only`) to the same raw CAM, using the `heatmap_raw` / `_postprocess_args` that the function returns for exactly this purpose;
  - rebuilds the `baseline` mode exactly as in `process_single_image` (threshold 0.4, then resize);
  - scores everything with the released `compute_obj_func_iou` (Otsu, max IoU over classes) and `compute_comprehensive_score`.
  - It also adds a supplementary "SICD-only" variant by calling the released `apply_single_image_eci`.
  - Prompts:
    - COCO uses `"Describe this image in one sentence."`, the fixed prompt in `test_selected_images` and the appendix.
    - GranDf uses `"Describe what you see in this image. Focus on <first object>."`, the prompt from the GranDf branch of `predict.main()`.
- **Grad-CAM baseline:** `scripts/run_gradcam.py`, which calls the released `baselines/gradcam.py::process_single_image_gradcam` (layer 10). Its Obj-IoU is used as is; contrast, concentration and F3 are added with the released `compute_comprehensive_score`. Runs: GranDf, all 1,000 images; COCO, every 5th image (991).
- **Fixed runs:** the same drivers with `PREDICT_MODULE=predict_fixslice GRADCAM_MODULE=gradcam_fixslice` (`runs/fixslice`), over full COCO, full GranDf, and Grad-CAM on GranDf plus the COCO 1/5 subset.
- **Aggregation:** `scripts/aggregate.py` writes `runs/*/aggregate_*.json`.
  - Metrics are averaged over images.
  - Per-image contrast is clipped at 20, the point where F3 saturates. Unclipped, mean contrast explodes to about 4e4x because of maps with zero background activation. Medians are also logged.
  - F3 is the harmonic mean of the averaged Obj-IoU, min(Contrast/20, 1) and Concentration. This is the arithmetic the paper's own F3 values follow: 3/(1/0.301 + 20/2.58 + 1/0.5141) = 23.04. The mean of per-image F3 is also logged.
- 4,932 of 4,952 COCO images (4,934 after the fix) and 1,000 of 1,000 GranDf images produced a CAM. The remaining roughly 20 return `None` inside the released code.

### The bug (why the as-released numbers are about half)
- With LaViDa's config (`image_aspect_ratio=anyres`, `mm_patch_merge_type=spatial_unpad`), the hi-res image block is laid out in `vendor/llava/model/llava_arch.py` as **h rows of (w+1) tokens**: each row ends with an `image_newline` token.
- `predict.py` (and `baselines/gradcam.py`) instead slices **h·w** consecutive tokens after the base features and reshapes them to (h, w). Row *i* therefore comes out shifted by *i* tokens: the map is sheared, includes newline-token features, and loses the bottom rows.
- My fix takes h·(w+1) tokens and drops the newline column. Nothing else changes.
- Effect on COCO, Diffusion-CAM full:

  | | Obj-IoU | Contrast | Concentration | F3 |
  |---|---|---|---|---|
  | As released | 11.86 | 1.29x | 32.82 | 11.09 |
  | Fixed | 21.95 | 2.60x | 41.56 | 20.46 |

## Why it is not fully reproduced
1. **Code bug (newline tokens in the image span).** It halves every metric. With it fixed, COCO comes close to the paper; GranDf does not.
2. **Data and protocol unspecified or missing:**
   - No data link, no COCO id list, and no script to build segmentation labels for the 40,504 images the paper states.
   - No GranDf entry point for the 1,000-image set.
   - No aggregation code, so how dataset-level contrast is computed is unknown (it is unbounded per image).
   - "Average of multiple experiments" is not specified.
   - Some of the remaining gap on COCO and GranDf may come from a different subset, prompt (GranDf), or aggregation.
3. **Module implementations differ from the paper** (see Discrepancies): the AKD kernel is effectively fixed at 3, DACG blurs a flattened 1-D list, and the SICD gate is disabled.
4. **LLaVA-CAM and TAM baselines are not released**, so they were not run.

## Discrepancies
**code_vs_paper (major):**
1. **Image-span slicing ignores `image_newline` tokens** (`predict.py`, `baselines/gradcam.py`). This shears the feature map. It affects results (F3 11.09 → 20.46).
2. **The target score differs from Eq. 2.**
   - The code takes the sum over the whole vocabulary of the logits at the position of the 2nd generated token, minus the same sum at a "distractor" token position.
   - It clamps gradients to ≥ 0 before pooling (Eq. 4 has no clamp).
3. **AKD's dynamic kernel collapses to a constant.** `step_ratio` is hard-coded to 0.5 and the size factor is computed from the CAM grid height, so the kernel is always 3.
4. **DACG blurs the wrong thing.** The "Gaussian denoising" is a `cv2.GaussianBlur((3,1))` over the flattened 1-D list of low-confidence values, not a spatial neighbourhood. In our runs it has almost no effect.
5. **SICD does not match its description.**
   - The conditional gate is disabled (`should_apply_eci = True`).
   - M_rep is a spatially constant map.
   - λ is not constrained to [0, λmax] (only capped at 0.5).
   - SICD is applied in every ablation mode, so Table 2's single-module rows cannot be isolated, and there is no SICD-only mode.
6. **COCO data:** the paper says 40,504 val images with masks. The code needs a TAM-format folder and ships no data or label-building script. The only available formatted data has 4,952 images. `main()` hard-codes 42 images (`[478:520]`).
7. **GranDf:** the paper uses 1,000 images. `main()` reads the GranDf **train** RLE json and evaluates only 10 images.

**code_vs_paper (minor):**
- **CBA:** S4 is 0.05·max instead of max, and the weights are not given in the paper.
- **`baseline` mode** applies LLaVA-CAM's 0.4 threshold, while the paper says its approach omits it and the other modes start from the raw map.
- **Contrast** is unbounded per image (eps = 1e-8), and there is no aggregation code.

**paper_internal:**
- Concentration 51.41 (Table 1) vs 51.44 (Table 2).
- LLaVA-CAM layer-10 F3 18.07 (Table 3) vs 18.08 (Table 1).
- On 200 images, Table 11 has base F3 0.188, +DACG 0.187 and full 0.225, while Table 2 has baseline 18.16 and +Gating 18.88. Table 11 shows DACG lowering F3; Table 2 shows it raising F3.
