## What the paper claims (main result: Table 1)
CRISP finds SAE features that are salient on the target corpus and suppresses them with LoRA fine-tuning. On WMDP-Bio and WMDP-Cyber, with Llama-3.1-8B and Gemma-2-2B, the paper reports that CRISP:
- lowers Unlearn accuracy (on WMDP MCQs);
- keeps Retain accuracy (in-domain MMLU subsets) and full-MMLU accuracy close to the original model;
- keeps generations fluent;
- gets the best Overall score, a harmonic mean that includes LLM-judged Fluency and Concept scores, beating RMU and ELM.

## What I did
1. **Environment.** Created a conda env (python 3.11) and ran `pip install -r requirements.txt` with the pinned versions (torch 2.9.1, transformers 4.57.1, peft 0.18.0). It installed without problems.
2. **Data** (`scripts/prepare_data.py`, my own script). The release does not ship the WMDP files that `data.py`/`eval.py` read. I rebuilt them from public sources:
   - **Corpora:** the cyber forget/retain and bio-retain corpora from `cais/wmdp-corpora`. Cleaning follows Sec 4.1: strip markdown headers, links, images, citations, link refs and non-ASCII characters; drop documents shorter than 200 characters; right-truncate to 1000 characters.
   - Result: 989 cyber-forget docs (the paper says 986) and 4128 cyber-retain docs.
   - **MCQs:** from `cais/wmdp` (bio 1273 questions, cyber 1987) and the MMLU test splits: high_school_biology 310, college_biology 144, high_school_computer_science 100, college_computer_science 100.
   - The repo's released `mmlu.json` (14042 questions) was used as-is.
3. **Experiment driver** (`scripts/run_crisp.py`, my own script). It follows the released demo notebook's workflow: `CRISP(CRISPConfig)` → `unlearn_lora` (feature selection plus LoRA training) → `get_mcq_accuracy`.
   - The edited model is evaluated first, then the original model with the adapter disabled.
   - MCQ val/test is a 50/50 split, which `eval.py` does itself with seed 0.
   - It also writes greedy 50-token generations for the 100 released fluency/concept prefixes per domain; these are not judged.
4. **Hyper-parameters (paper Appendix F):**
   - Gemma-2-2B Cyber: SAE layers [4,6,…,14], k=50, λ(alpha)=20, LoRA rank 4, lr 4e-5.
   - Llama-3.1-8B Cyber: SAE layers [4,6,…,18], k=50, λ=30, rank 4, lr 4e-5.
   - Fixed for both: β=0.99, γ=0.01, τ=3 (hard-coded in the code), 1 epoch, LoRA on layers 3–9, seed 0.
   - Batch size is not given in the paper, so I used 4, as in the demo notebook.
   - Commands:
     ```
     python scripts/run_crisp.py --model gemma --domain cyber --layers 4,6,8,10,12,14 --k 50 --alpha 20 --rank 4 --lr 4e-5 --out results/gemma_cyber.json
     python scripts/run_crisp.py --model llama --domain cyber --layers 4,6,8,10,12,14,16,18 --k 50 --alpha 30 --rank 4 --lr 4e-5 --out results/llama_cyber.json
     python scripts/eval_original_bio.py google/gemma-2-2b results/gemma_bio_original.json
     python scripts/eval_original_bio.py meta-llama/Llama-3.1-8B results/llama_bio_original.json
     # supplementary (Table 3, Harry Potter; hyper-parameters from the demo notebook since the paper gives none):
     python scripts/run_crisp.py --model gemma --domain hp --layers 4,6,8,10,12,14 --k 10 --alpha 5 --rank 4 --lr 1e-5 --n_examples 2500 --out results/gemma_hp.json
     python scripts/run_crisp.py --model llama --domain hp --layers 4,6,...,28 --k 10 --alpha 30 --rank 4 --lr 2e-5 --n_examples 2500 --out results/llama_hp.json
     ```
5. **How Retain accuracy is aggregated.** The paper doesn't say. Taking the mean of the two subjects' test accuracies reproduces Llama Bio-original 76.81 almost exactly (ours: 76.85). For Cyber, the pooled and mean values are identical.

## Why it is not fully reproduced
1. **WMDP-Bio forget corpus is gated.** `cais/wmdp-bio-forget-corpus` returns 403 for our token. Requesting access means submitting an access form on the user's behalf, which I did not do in this unattended session. So CRISP could not be trained for Bio. Original-model Bio numbers were computed and they match.
2. **Closed-source judge.** The Fluency and Concept scores, and therefore the Overall score, need Claude Sonnet 4 as an LLM judge. No API key is configured, so the flag CLOSED_JUDGE_UNAVAILABLE is set. The generations themselves were produced and saved.
3. **No baseline code.** The release contains no RMU or ELM implementation.

## Codebase completeness: MISSING_SCRIPTS
The method itself is fully implemented: feature statistics, salient-feature selection, LoRA suppression training, MCQ evaluation and SAE loaders. The pipeline for the paper's main WMDP experiment is missing:
- **No experiment script.** There is no script or config for the WMDP runs; the only runnable entry point is a Harry-Potter demo notebook. I wrote `scripts/run_crisp.py` (driver) and `scripts/eval_original_bio.py` (original-model Bio evaluation).
- **No WMDP data files or preprocessing.** The code reads `data/wmdp/{bio,cyber}/*_cleaned.jsonl` and `*_mcq.json`, but neither the files nor the cleaning code are shipped. I wrote `scripts/prepare_data.py` from the description in paper Sec 4.1. It gives 989 cleaned cyber-forget docs against the paper's 986, so the exact cleaning differs slightly.
- **One source change** (`codebase/crisp/data.py`): defined `DATA_PATH = os.path.join(PROJECT_PATH, "crisp", "data")`. It is referenced in `load_wmdp_data` but never defined, so the release crashes with a `NameError`. The diff is saved in `codebase_changes.diff` and left uncommitted.

- **Hyper-parameters had to be passed manually.** The defaults in `UnlearnConfig` (lr 1e-5, k 10, alpha 5, rank 4) are not the paper's WMDP settings, so the Appendix F values were passed on the command line. Batch size (4) and the WMDP `n_examples` are not specified in the paper.

## Discrepancies
1. **code_vs_paper, minor — coherence-loss weight** (`unlearn.py:381`). The paper's total loss is α·L_unlearn + β·L_retain + γ·L_coherence with γ=0.01. The code uses `config.beta * config.gamma` (= 0.0099) as the weight.
2. **code_vs_paper, minor — unlearning loss form** (`unlearn.py:get_features_acts`/`loss_features_acts`).
   - Paper Eq. 9: minimize E[a_i + λ·c_t] over all target tokens.
   - Code: adds |λ·mean(pre-activations)| to the salient features' *pre-activations* before the JumpReLU/TopK nonlinearity, and only at positions where the frozen model activates the feature. It then averages only the non-zero activations.
   - It is the same idea, implemented differently.
3. **code_vs_paper, minor — SAE layer site** (`crisp.py`/`unlearn.py`). SAEs for "layer L" are applied to `outputs.hidden_states[L]`, which in HF is the residual stream *before* block L (the output of block L-1). GemmaScope `layer_L` and LlamaScope `L{L}R` SAEs are trained on the residual stream *after* block L, so the code is off by one layer. The paper's numbers were presumably produced with this same code; the effect on results is unknown.
4. **paper_internal — original-model MMLU, Table 1 vs Table 3.**
   - Table 1: Llama-3.1-8B 61.15, Gemma-2-2B 46.30.
   - Table 3 (HP): the same un-edited models score 65.96 and 48.94.
   - Our full-MMLU evaluation gives 61.49 and 46.38, consistent with Table 1.
5. **paper-description gap — Cyber data count and Retain aggregation.** The paper says it uses "all 986 entries" of WMDP-Cyber, but the corpus has 1000 rows and the cleaning code is not released. How Retain accuracy is aggregated over the two MMLU subjects is not stated; the per-subject mean reproduces the paper.
