## What the paper claims / what we targeted
SCS is a training-free steering method. At one layer ℓ it computes a second attention output for the last token, with the condition tokens masked and positions shifted. It then subtracts that output (DE) or projects it out (PE), scales by α, and continues the forward pass. The main claim is that this improves PonTE conditional embeddings on clustering (V-measure), STS (Spearman/Pearson) and triplet alignment (accuracy), across LLMs.
- **Table 1** (main result, LLaMA3-8B-Inst): we ran PonTE, PonTE+Echo, PonTE+SCS-DE and PonTE+SCS-PE on TweetEmo, Amazon-R, Amazon-C, I.STSB, Toxic and AGNews.
- **Table 4** (generalization across 6 backbones): we ran PonTE and PonTE+SCS-DE on I.STSB, TweetEmo and Amazon-R for LLaMA3-8B, LLaMA3.1-8B(-Inst) and Qwen2.5-7B(-Inst); the LLaMA3-8B-Inst rows are shared with Table 1.

## What we ran
- **Environment:** conda env at `./env`, Python 3.9, torch 2.1.0+cu118, transformers 4.51.3, and the authors' pip freeze (`now.txt`). Hardware: 1× H200.
- **Data:** HF `BrandonZYW/InstructSTSB` (pinned revision), `cardiffnlp/tweet_eval` emotion test, `mteb/toxic_conversations_50k` test, Kaggle `mexwell/amazon-reviews-multi` (en test, 5,000 reviews) and Kaggle `amananandrai/ag-news-classification-dataset` (test, Description field). These are the sources `download_data.sh` names.
- **Models:** HF Meta-Llama-3-8B(-Instruct), Llama-3.1-8B(-Instruct), Qwen2.5-7B(-Instruct). dtype float32 as in the configs, with the authors' batch sizes from `scripts/evaluation.sh`.
- **Command (via `run.sh`):** `cd codebase; SCS_MODE={de|pe} python evaluation.py --dataset <DS> --batch_size <BS> --config_file <generated config> --overwrite_results True --output_layer -1 --seed=0`.
  - The generated config is the authors' config with `model_path` set to the HF id, `inject_layer_indexes`/`alphas` set to the grid, and `model_id` renamed.
  - PonTE = `inject_layer_indexes=[99]`, so no layer is intervened.
  - PonTE+Echo = config key `pattern_echo`.
- **Hyperparameter search (paper Sec 5.1):** grid over the intervention layer and α ∈ {5, 10, 15}, selected on the test set as the paper does (no dev split is mentioned).
  - We used code layer indices 1–20, i.e. paper layers 2–21 (see the layer-indexing discrepancy below), and picked the best main score (Spearman for STS).
  - To fit the budget, the grid ran with **TF32 matmuls** (`eval_tf32.py`, about 4–5× faster). We checked agreement: TweetEmo 44.873 vs 44.871, I.STSB 39.61/37.44 vs 39.61/37.44.
  - The selected configuration was then **re-run in exact fp32** with the released code. That fp32 number is the "Ours" value below; the TF32 grid value is shown alongside.
- **Wall-clock:** about 22 h, including about 20.5 h of GPU time. Most of it went to the full grids on the 30,000-sentence triplet datasets (Toxic about 194 s per configuration with TF32, 16 min with fp32).
- **Settings that differ from the paper:**
  - TF32 was used only for the grid search; final numbers are fp32.
  - Hardware is an H200, not the V100 used in the paper's timing section.
  - We grid-searched code index 20 (paper layer 21) in addition to the paper's [2, 20], because the authors' own configs and released result use index 20.
  - Otherwise nothing was reduced.
