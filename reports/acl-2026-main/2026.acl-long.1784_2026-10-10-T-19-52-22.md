# Reproduction report: Vision-Language Introspection (VLI), ACL 2026 (2026.acl-long.1784)

## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): TREND_MATCH**. **As released: TREND_MATCH.** We made no edits to the source code, so the two are the same.
- **Coverage: SUBSET.** We ran the full LLaVA-1.5-7B POPE part of Table 1: 3 datasets × 3 splits × 3000 questions, at the paper's scale. The parts below were not run or could not be scored:
  - **MMHal-Bench (LLaVA):** we generated all 96 answers, but scoring needs a GPT-4 judge and there is no API key here. Flag: `CLOSED_JUDGE_UNAVAILABLE`.
  - **Qwen3-VL rows:** the release contains no Qwen3-VL implementation.
  - **Baselines:** no baseline code is released.
- **Codebase completeness: MINOR_FIXES.** We changed the environment only; the source code is untouched. See the notes below for the pieces missing from the release.

**Bottom line.** The released code runs end to end. On POPE, the baseline (greedy LLaVA-1.5-7B) matches the paper's "Origin" row within tolerance. VLI does improve accuracy on all three POPE datasets, and the gain is statistically significant, but it is only **+0.66 / +0.82 / +0.80** accuracy points. The paper reports **+5.79 / +6.33 / +6.23**. So the direction holds, but about 87% of the claimed gain does not appear. The headline claim ("improving accuracy by 5.8% on POPE") is **not** reproduced in size.

## What was run
Environment: a conda env at `./env` with Python 3.10, torch 2.1.2+cu121, transformers 4.37.2, LLaVA v1.2.2.post1 (cloned to `./llava_src`) and datasets 2.14.6. GPU: 1× H200.

- **Model:** `liuhaotian/llava-v1.5-7b` (LLaVA-1.5-7B, fp16), as in the paper.
- **POPE data:** the standard 27,000 questions from the VCD repo, `experiments/data/POPE/{coco,aokvqa,gqa}/*_pope_{random,popular,adversarial}.json`.
  - COCO and A-OKVQA images: downloaded individually from COCO val2014.
  - GQA images: downloaded from Visual Genome.
- **POPE command** (sharded into 1500-question chunks over 4 parallel processes on one GPU by `pope_worker.sh`):
  ```
  python codebase/scripts/run_vli_pope.py --model-path liuhaotian/llava-v1.5-7b \
     --pope-file data/vcd_repo/experiments/data/POPE/<ds>/<ds>_pope_<split>.json \
     --image-folder data/images --output-file results/pope/<ds>_<split>_<start>.jsonl --start-idx S --end-idx E
  ```
  - Hyperparameters were the release defaults, which match the paper: θ=0.1, ρ=0.4, α=0.5, greedy decoding, calibration λ=1.0.
  - Other defaults: max_new_tokens=30, top-3 risky tokens, mask inpainting, and the shipped expert heads.
- **Metrics:** `aggregate_pope.py` calls the release's own `scripts/eval_pope.compute_metrics`.
  - For **VLI** it scores `corrected_answer`.
  - For **Origin** it scores `original_answer`, the plain greedy LLaVA answer that the release's runner writes into the same row. The baseline therefore comes from the same pipeline and the same questions.
- **Significance:** `significance.py` runs an exact McNemar test of VLI vs. Origin.
- **MMHal command:**
  ```
  python codebase/scripts/run_vli_mmhal.py --model-path liuhaotian/llava-v1.5-7b \
     --mmhal-file data/mmhal/mmhal_local.jsonl --image-folder data/mmhal/images --output-file results/mmhal/mmhal_vli.jsonl
  ```
  - This uses the README's "Option B" (local records), built from the HF repo's `response_template.json` and `images/`.
  - We did not run `eval_mmhal.py`: it needs an OpenAI key.

### Settings that differ from the paper
- The release does what the code does, not exactly what the paper describes (see Discrepancies):
  - expert heads: 24 instead of 64
  - simple mask/blur counterfactual images instead of a pretrained inpainting model
  - a VTI-style steering hook
  - sink masking always on
- MMHal answers are capped at the release default of 30 new tokens; 17/96 answers end mid-sentence. The paper does not give a limit.
- POPE prompt: the raw question, with no "answer in one word" suffix. This is the release's own behaviour.

## Codebase completeness: MINOR_FIXES
We made no changes to the released source (`git status` in `./codebase` is clean). These were the environment and data issues:
- **Version pins don't fit the code.** `requirements.txt` pins torch 2.0.1 and transformers 4.31 (the LLaVA v1.1.x stack). The code needs the LLaVA ≥ v1.2 API: it calls `generate(inputs=..., images=...)` and expects generate to return only new tokens. We installed LLaVA v1.2.2.post1 instead (torch 2.1.2, transformers 4.37.2).
- **bitsandbytes breaks the import.** bitsandbytes 0.41.0 (pulled in by LLaVA) cannot load its CUDA library, which makes `import llava.model` fail. We uninstalled it. We also pinned pyarrow<15 for datasets 2.14.6.
- **README model path doesn't load.** The README's example `llava-hf/llava-1.5-7b-hf` does not work with the llava loader the code uses; we used `liuhaotian/llava-v1.5-7b`.
- **MMHal loading fails in three ways:**
  - The default HF loading in `run_vli_mmhal.py` passes `trust_remote_code`, which datasets 2.14.6 rejects.
  - With URL records, `--image-folder` is ignored.
  - One Flickr URL now returns HTTP 410.

  We used the README's documented local-records option instead.
- **POPE data** comes from the public VCD repo, plus public COCO and Visual Genome images.
- **Missing from the release:**
  - the Qwen3-VL implementation (half of Table 1)
  - all baseline implementations
  - the offline MC-Bench expert-head calibration code (only a precomputed 24-head JSON is shipped)
  - configurations for the ablations in Tables 2 and 3
- **One unit test is broken:** `tests/test_runner_contract.py` fails with a NameError (missing `import torch`); 24/25 tests pass.
- **Scripts we wrote:** `pope_worker.sh` (shard runner), `aggregate_pope.py` (metrics via the release's evaluator), `significance.py`, `dl_images.sh`, `wait_pope.sh` / `wait_tail.sh` (polling).

## Discrepancies
1. **code_vs_paper, major — steering** (`vli/steering.py`, `vti_utils/llm_layers.py`).
   - **Paper:** h_d = h_g + α(h_a − h_c) at the conflict step t.
   - **Code:**
     - It builds d = h_g + α(h_a − h_c) from the *last token of the full grounded answer*.
     - It adds this after every MLP layer, at all positions, through a whole re-generation, VTI-style: x ← normalize(normalize(x) + 0.1·α·normalize(d))·‖x‖.
     - The injected direction is therefore dominated by h_g, and its strength is fixed at 0.1·α.
2. **code_vs_paper, major — counterfactual images** (`vli/counterfactual_backends.py`).
   - **Paper:** the images come from a pretrained inpainting model.
   - **Code:** by default it zeroes the anchor patches and blurs everything else. The diffusers option needs a model that is never named.
3. **code_vs_paper, minor — expert heads.** The shipped list has 24 heads; Appendix C says M=64.
4. **code_vs_paper, minor — sink masking.** The code always applies explicit attention-sink masking. The paper treats sink masking as a separate variant ("VLI + Explicit Sink Masking", Table 3), not part of standard VLI.
5. **code_vs_paper, minor — suspicious token.** Eq. 5 (argmax over the vocabulary of log Pg − log Pu) is not implemented. The code instead averages attention over up to 3 high-JS generated tokens.
6. **code_vs_paper, minor — ungrounded path.** It uses an all-zero image (576 visual tokens) rather than the paper's "null tokens".
7. **code_vs_paper, minor — MMHal judge.** The judge defaults to `gpt-4o-mini`; the paper says GPT-4.
8. **paper_internal — calibration under greedy decoding.**
   - The paper says it uses greedy decoding (Sec 4.1), and Adaptive Confidence Calibration only divides the logits by Tc (Eq. 14).
   - Dividing logits by a positive number cannot change the greedy argmax, so calibration cannot change any output.
   - Yet Table 2 reports that removing calibration changes the results (47.10 vs 45.63 hallucination rate).
   - In the released code it is likewise a no-op on outputs.
9. **paper_internal — Table 1 vs Table 3.** Several POPE rows have Acc and F1 swapped between the two tables. For example, LLaVA VLI on MSCOCO is 89.61/89.27 in Table 1 but 89.27/89.61 in Table 3.
10. **paper_internal — Sec 4.5 vs Table 1.** Sec 4.5 says α=0.5 gives an MMHal Score of 3.12 for LLaVA, while Table 1 reports 3.11 at the same default.
