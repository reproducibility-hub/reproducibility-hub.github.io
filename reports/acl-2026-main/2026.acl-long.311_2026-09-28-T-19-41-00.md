## What was run
- **Models:** `GSAI-ML/LLaDA-8B-Instruct` and `GSAI-ML/LLaDA-1.5`, bf16. Temperature 0 (greedy), steps equal to generation length.
- **Generation lengths:** 256 for HumanEval, GSM8K and GPQA; 128 for MBPP, Countdown and Sudoku; 1024 for MATH500 (paper App. A.6).
- **UNCODE settings:** `--mode pc_sampler --alpha 10`. λ = 0.25 for everything except Countdown (λ = 0.5) and Sudoku (λ = 0), matching the paper. Reference corpus: `data/baseline/reference_corpus.json`, which is identical to `reference_corpus_llada.json`.
- **Harnesses:**
  - HumanEval, MBPP, MATH500, Countdown and Sudoku: the released `scripts/eval.py` on the released data files. Code tasks are scored with the released `utils/judge_python_code.py`.
  - GSM8K (4-shot, lm_eval `gsm8k`) and GPQA (5-shot, lm_eval `gpqa_main_generative_n_shot`, 448 questions): the released `scripts/eval_llada.py` with lm_eval 0.4.8. Reported with the `flexible-extract` filter.
- **Baselines:**
  - Semi-AR: `mode=original`, `block_length = gen_length/8`. This matches the release's `eval_semi_ar.sh` and the paper's "8 blocks".
  - Margin: `mode=margin`, a single block, as in `eval_margin.sh`.
  - Confidence: `mode=original` with `block_length = gen_length`. The release has no Confidence script, so this configuration is my guess.
- **Parallelism:** to fit the time budget, the data files were split into shards (`work/make_shards.py`). The released `eval.py` / `eval_llada.py` were run on each shard by a 4-GPU job queue (`work/runner.py`), and the shard results were recombined (`work/aggregate.py`). The generation loop is per-example with batch size 1, so sharding does not change any output.
- **Example command:** from `codebase/scripts`,
  `python eval.py --task math500 --model_name GSAI-ML/LLaDA-8B-Instruct --device cuda:0 --gen_length 1024 --steps 1024 --block_length 1024 --mode pc_sampler --lambd 0.25 --alpha 10 --baseline_name <abs>/data/baseline/reference_corpus.json --data_path work/shards/math500_0.jsonl --result_path work/out/llada_uncode_math500_0.txt`
  and
  `python eval_llada.py --tasks gsm8k --num_fewshot 4 --model llada_dist --confirm_run_unsafe_code --output_path ... --log_samples --model_args model_path=GSAI-ML/LLaDA-8B-Instruct,gen_length=256,steps=256,block_length=256,lambd=0.25,alpha=10,mode=pc_sampler,baseline_name=<abs>,device=cuda:0`
  Full per-job commands are on the first line of each `work/logs/*.log`.

### Settings that differ from, or are unspecified in, the paper
- **GPQA task:** the release scripts pass `--tasks gpqa`, an lm_eval tag that runs all 12 GPQA variants. I used `gpqa_main_generative_n_shot` because it matches the paper's 448 questions, 5-shot, and generation-based scoring.
- **GSM8K/GPQA metric:** the paper doesn't say which filter it used. `flexible-extract` reproduces the paper's numbers; `strict-match` gives, for example, 53.6 on GSM8K for UNCODE/LLaDA and 0 on GPQA.
- **Countdown λ:** the release's `eval_pc_sampler.sh` uses λ = 1; I used the paper's λ = 0.5.
- **Sudoku size:** the data file has 500 puzzles, not the 501 listed in the paper's Table 4.
- **Hardware:** H200 instead of A100, and torch 2.14 (the requirements file leaves torch unpinned). Small bf16 numeric differences are expected.

### Paper claims
1. **UNCODE's own scores (the main claim):** reproduced within tolerance on HumanEval, MBPP, GSM8K, MATH500, GPQA and Countdown for both backbones. The averages are 42.2 vs 42.7 (LLaDA-8B) and 43.2 vs 44.7 (LLaDA-1.5). Sudoku is lower than reported: 25.6 vs 29.8 and 29.0 vs 33.4.
2. **UNCODE beats existing decoders by more than 7%.** The strongest baseline in Table 1 is Semi-AR, and it reproduces well (averages 36.4 vs 35.7 and 37.9 vs 37.1).
   - UNCODE beats Semi-AR by +5.8 (LLaDA-8B) and +5.3 (LLaDA-1.5) average points; the paper reports +7.0 and +7.6.
   - UNCODE wins 13 of the 14 per-task comparisons. The exception is GPQA on LLaDA-1.5, where our Semi-AR scores 30.8 (paper: 26.1) against UNCODE's 27.9.
   - The direction and ranking of the claim hold; the size of the gain is somewhat smaller. Hence TREND_MATCH.
3. **The uncertainty-based baselines (Confidence, Margin) can't be reproduced from the release.**
   - With a single full-length block (the release's Margin script, and my guess for Confidence), LLaDA-8B-Instruct mostly emits EOS early on the long-generation tasks. For example, about 90% of Confidence's GSM8K responses are empty. Result: GSM8K 5.8 / 11.1 vs the paper's 59.1 / 58.3, and MATH500 3.0 / 1.6 vs 20.8 / 19.8.
   - On the short-generation tasks (GPQA, Countdown, Sudoku) these baselines do match the paper.
   - The paper must have used some configuration for these baselines that isn't in the release, so these rows are NOT_COMPARABLE. Our numbers for them are much *lower* than the paper's, so they don't weaken the claim that UNCODE is better.
4. **Not tested:** the AR model rows, Uniform, Entropy, EB-Sampler and Fast-dLLM, Dream-7B (Table 10), the ablations (Fig. 4), and Tables 2 and 5–9.
