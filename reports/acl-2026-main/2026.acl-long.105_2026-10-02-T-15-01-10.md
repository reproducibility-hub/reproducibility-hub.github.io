## What the paper claims (target)
The main result is Table 2: GIoU, ΔSGA and CGA for 15 LLMs on French, Arabic and Hindi, with full breakdowns in Tables 10–12. The text draws these claims from it:
1. Larger models outperform smaller ones (§5.1).
2. Arabic is the hardest language and Hindi the easiest (§5.6, §5.7).
3. There is masculine bias (ΔSGA>0) in French and Arabic, e.g. Llama-3.3-70B French ΔSGA = 15.15 and Qwen3-32B Arabic ΔSGA = 11.94. Hindi has low or feminine-skewed bias, e.g. Gemma-3-4B Hindi ΔSGA = -14.32 (§5.2).
4. Some specific numbers: Gemma-3-27B Arabic CGA 74.74 vs Gemma-2-2B 14.10; Phi-4 French CGA 87.70 vs Gemma-2-2B 37.54; Llama-3.1-8B Hindi CGA 89.21 vs Llama-3.3-70B 91.40.

## What I did
1. Cloned https://github.com/arnav10goel/Morphogen into `./codebase`. I made **no edits** to any file in it.
2. Downloaded the dataset from https://huggingface.co/datasets/ag2003/morphogen (`dataset-{fr,ar,hi}.tsv`) into `codebase/dataset/`.
3. Generated `instruction_set-{lang}.tsv` with the repo's `src/dataset_preparation/preprocessing.py`. This file is the input to `model_vllm.py` but is not shipped. It gives 2 rows per pair (MF and FM): fr 19,998, ar 5,438, hi 15,220.
4. Set up the env: conda env with Python 3.11, vllm 0.10.2, torch 2.8, transformers 4.56.2 and pandas 2.3. `requirement.txt` is unpinned.
5. Ran inference with `scripts/run_vllm_batched.py`, a batched copy of `src/inference/model_vllm.py`. It keeps the same `inference.json` prompts, the same `config.yaml` sampling (temperature 0.1, top_p 0.95, max_tokens 100, stop tokens), the same `max_model_len=512` and the same Gender→instruction mapping. Prompts longer than 512 tokens get the same `ERROR: ...` output as the released per-row try/except; the authors' released Qwen3-4B Hindi outputs contain the same ERROR rows. Each model was run with two prompt formats:
   - **raw** — the released hard-coded `<|system|>\n…\n<|user|>\n…\n<|assistant|>` string. This is the as-released behaviour.
   - **chat** — the model's own chat template, which is what paper App. C says was used. Qwen3 runs with `enable_thinking=False`; for Gemma-2, which has no system role, the system prompt is merged into the user turn.
   Command: `scripts/run_all.sh`, which calls `python scripts/run_vllm_batched.py --model <hf id> --file_name <name>` for every model.
6. Evaluated with `scripts/eval_all.py {chat,raw,released}`. It uses `scripts/eval_runner.py`, which executes the metric functions from `src/eval.ipynb` unchanged and only swaps in an equivalent cached `get_label`. I also scored a variant that counts length-mismatched outputs as 0 (see Discrepancies).
7. Downloaded the authors' released model outputs (the Google Drive link in the README) into `released_outputs/` and re-scored them with the same evaluator.
8. Compared everything with `scripts/compare.py`. Outputs are `results/comparison_table.md`, `results/trend_summary.txt`, `results/metrics_*.json` and per-rule result TSVs in `results/<kind>/`.

### Why some numbers are off
The deviations are concentrated in small models, which are very sensitive to prompt format and sampling. Examples:
- Gemma-2-2B and Gemma-2-9B French: we get 53.7 and 76.0 GIoU vs 39.7 and 60.5.
- Gemma-3-4B Hindi: 50.0 vs 67.5.
- Qwen3-4B Hindi: 74.3 vs 62.8.

Two sources of drift are likely:
- The exact prompt and template the authors used is unknown, because the released script is not what produced their outputs.
- Some of the authors' runs used a different version of the inputs (see Discrepancies). For example, Llama-3.2-3B Hindi: paper 48.54 vs our 69.48. Only 62% of that run's inputs match the released dataset.

The ΔSGA gaps are small differences between two noisy accuracies, so they vary the most.

## Discrepancies
1. **code_vs_paper, major: the evaluator silently drops length-mismatched outputs.** In `src/eval.ipynb` `evaluate_gender_metrics`, when the generated token count ≠ the reference token count, the code sets `iou_score = acc_score = 0` but never appends the sample. Such samples are excluded from SGA, GIoU and CGA, and CGA becomes 1.0 if every output mismatches. Sec 4.2 defines all three metrics over all N sentences. Counting these samples as 0 changes the numbers a lot:
   - Authors' Llama-3.1-8B French GIoU/CGA: 67.89/81.61 → 38.14/45.63.
   - Authors' Gemma-3-27B Hindi: 77.98/82.56 → 63.83/65.54.
   - Authors' Llama-3.2-3B Hindi: 48.54 → 28.58.
   This reshuffles the ranking. Our comparison table uses the released behaviour, since that is what produced the paper's numbers; the zero-counting variant is in `results/metrics_*.json` under `mismatch_as_zero`.
2. **code_vs_paper, major: the inference prompt is not the chat template.** `model_vllm.py` uses a hard-coded generic `<|system|>/<|user|>/<|assistant|>` string, but App. C says the model-specific chat template was used. As released, Qwen3 models emit reasoning text and score 0. The authors' released outputs are clean, so they were not produced by this script as released.
3. **code_vs_paper, major (data): released outputs don't match the released dataset for several runs.** Share of inputs that match the released dataset:
   - Llama-3.2-3B Hindi: 61.9%.
   - Nine Arabic runs (Gemma-2-2B/9B, Gemma-3-4B/12B/27B, Llama-3.1-8B, Phi-4, Qwen2.5-0.5B): 91.1%.
   - Several French runs: 99.3–99.8%.
   Llama-3.3-70B Arabic and Llama-3.2-3B fr/ar are incomplete. So some paper numbers were scored against mismatched references.
4. **code_vs_paper, minor: generation settings.** The paper says max new tokens 256 and deterministic decoding (do_sample False). The config uses max_tokens 100, temperature 0.1 / top-p 0.95 sampling and max_model_len 512, which turns long Hindi prompts into ERROR outputs.
5. **code_vs_paper, minor: system prompts.** The French system prompt in `inference.json` differs from App. D.2. The Hindi and Arabic prompts name the language.
6. **code_vs_paper, minor: dtype.** `config.yaml` sets dtype float16, which vLLM rejects for Gemma-2/3.
7. **code_vs_paper, minor: SGA_M/SGA_F labels.** The paper defines SGA_M as masculine→feminine, but the code's `Acc_M` is computed on rows with target gender male (feminine→masculine). §5.2's reading of positive ΔSGA as masculine bias matches the code, not the definition.
8. **paper_internal: model list.** §4.1 lists "Qwen3-27B" and 13 models, and the abstract says 15 models "2B–70B". Table 2 has Qwen3-32B and also includes Qwen2.5-0.5B and the closed GPT-4o-mini.
9. **paper_internal: dataset statistics.** Table 1 gives unique sentences ar 2,719 / hi 7,610. Table 9 gives Arabic "unique 7610" (from 5,413 generated) and Hindi "unique 10248" with 2,694 discarded of 10,248, which is inconsistent.
10. **paper_internal: decoding.** App. C says "Deterministic (no sampling), do_sample False" and also lists temperature 0.1 and top-p 0.95.

## Flags
None of RERUN_WEAKER_THAN_RELEASED or BASELINE_STRONGER_THAN_REPORTED apply. Our chat-template rerun is on average equal to or slightly higher than the paper, and there is no method-vs-baseline structure. GPT-4o-mini is an evaluated model, not a judge, so it is simply not covered.
