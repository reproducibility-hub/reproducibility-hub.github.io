# Reproduction report — 2026.acl-long.300 "Faithfulness Serum" (Alon, Zimerman, Wolf; ACL 2026)

## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): MIXED**. **Result match as released: MIXED**
- **Coverage: SCALED_DOWN**. Table 1 only (the paper's main result), with n=500 counterfactual examples per Llama cell and n≤500 / n=400 per Qwen cell, vs. 1000 in the paper.
- **Codebase completeness: MAJOR_FIXES** (see below)

Short summary
- **Llama-3.1-8B-Instruct (main model):** the released pipeline reproduces Table 1 well. All 16 Llama cells (4 hints × {General, Protocol-Specific} × {LLM judge, CT}) show the claimed improvement. 6/16 are within tolerance of the paper's numbers. The other 10 have the same direction, and usually the same size, of gain (e.g. Sycophancy/General LLM 36.1→47.7 in the paper vs 32.6→49.4 ours; Grader-Hack/General LLM 2.8→10.7 vs 2.8→11.0; Metadata/General 3.0→10.0 vs 2.6→9.6).
- **Qwen2.5-7B-Instruct:** does **not** reproduce cleanly.
  - *As released*, the Qwen prompt is malformed: a stray `<` after the assistant header, and the explanation turn uses *Llama-3* special tokens. With that prompt, baselines differ a lot from the paper (e.g. Metadata/General 20.6 vs 11.6). The intervention *lowers* faithfulness for Grader Hack (both prompts), and CT for Unethical/Protocol-Specific.
  - *With the chat format fixed* (proper Qwen turns), the α=0.1 intervention often collapses Qwen explanations to a bare "Answer: X" (e.g. Sycophancy/General mean length 97→42 words). Faithfulness then drops sharply for Sycophancy/General (60→41 LLM) and Grader Hack, and for Metadata and Unethical under the Protocol-Specific prompt.
  - The large LLM-judge "gains" for Unethical Information under the fixed format are largely an artifact: the Qwen2.5-14B judge labels a bare "Answer: X" as "hint used" for this hint type (100% of ≤10-word explanations judged True).
- So the paper's claim that the method helps "across all hint types, models, and prompt levels" holds for Llama but not for Qwen.

## What the paper claims / what we targeted
Table 1 (Sec. 5): epistemic faithfulness (LLM judge = Qwen2.5-14B-Instruct, and keyword Counterfactual Test, CT) of post-hoc explanations for MMLU questions where a hint flipped the model's answer. It reports Original → Faithfulness-Serum (PE-LRP relevance added to post-softmax attention of the question tokens in layers 17-19; α=0.06 for Llama, 0.1 for Qwen), for Llama-3.1-8B-Instruct and Qwen2.5-7B-Instruct, 4 hint types, General and Protocol-Specific explanation prompts, 1000 examples each.
Not attempted (time; one GPU): Table 2/9 (other datasets, same script), Table 3 (closed-source GPT-4o/Gemini: no API keys, and not the method), Table 4 (TTα: not implemented in the release), Table 5 (open-ended: `--open_question` flag is parsed but not used by `lrp_guidance.py`), Tables 6, 7, 10-12 and Fig. 4-6 ablations.

## What we ran
Environment: conda env at `./env`, Python 3.9, `pip install -r codebase/requirements.txt` (torch 2.4.1, transformers 4.49.0). Installs as-is. One H200 (141 GB), with 2-3 jobs in parallel.

Command per cell (wrapper `run_one.sh`, queue `worker.sh`):
```
cd codebase
REASON_PROMPT={general|protocol} python -u scripts/lrp_guidance.py --dataset mmlu --dataset_specific_name all \
   --num_of_examples N --eval_model_path Qwen/Qwen2.5-14B-Instruct --model_path {meta-llama/Llama-3.1-8B-Instruct|Qwen/Qwen2.5-7B-Instruct} \
   --alpha {0.06|0.1} --hint_type {sycophancy|unethical_information|metadata|grader_hacking}
```
The fixed-Qwen variant (`run_one_fix.sh`) adds `REPRO_QWEN_FIX=1`. Seed 42 (default), greedy decoding, layers 17-19 (k=3), as in the code.

Differences from the paper:
- **Sample size:** Llama n=500 per cell (paper 1000).
- **Qwen as released:** n=500 for Sycophancy; the rest were stopped by a 3.5 h-per-job watchdog at the last 25-example checkpoint. Unethical/G 450, Metadata/G 175, Grader/G 425, Unethical/PS 425, Metadata/PS 175, Grader/PS 425. Under the malformed as-released prompt Qwen follows the Metadata hint only about once per 12 inputs, so those cells are slow.
- **Qwen fixed:** n=400 per cell.
- The full 16+8 cells at n=1000 would need about 100+ GPU-hours with this single-example, eager-attention pipeline; we had ~45 h on 1 GPU.
- The examples are the first N counterfactuals in the seed-42 shuffle of MMLU-test (`all`), so each run is a prefix of the paper's protocol.
- **Lost examples (CUDA OOM):** with 2-3 processes sharing one GPU, occasional CUDA OOMs occur. They are caught by the script's `try/except` and the example is skipped. Llama: ≤2 per cell. Qwen fp32: 10-90 per cell, almost all during hint-answer generation (`use_cache=False`, `output_hidden_states=True`), i.e. before the example is counted. These skips can slightly bias which examples are sampled (long hint answers are dropped).
- **Crash and rerun:** three Llama runs crashed at about n=150-175 with `Errno 122 Disk quota exceeded`. The shared 1 TB /scratch project quota was briefly full because of other jobs, not ours. They were rerun from scratch; the run is deterministic, and the rerun reproduced the crashed partial numbers exactly.

### Additional analyses (from the logged explanations, no extra GPU)
- **Grader-Hack CT keyword bug.** `match_check` tests `"Internal" in expl_lower` on a lower-cased string, so the keyword "internal" (App. B.4) never matches. Recomputing CT with "internal" included (`ct_fixed_grader.py`):
  - Llama Grader/G: 7.4→19.2 becomes 8.8→20.8.
  - Llama Grader/PS: 33.8→58.8 becomes 42.8→60.0.
  - The paper's 35.8→58.6 is consistent with the buggy check.
- **Explanation length / judge artifact** (`expl_len.py`, `degenerate.py`).
  - Llama: the intervention does not shorten explanations (mean 134-183 → 148-205 words), and no explanation has ≤10 words.
  - Qwen: the intervention roughly halves explanation length: as released 99-133 → 42-77 words, fixed 75-136 → 18-91 words.
  - With the fixed format, 10-66% of intervention explanations are ≤10 words in 5 of 8 cells, mostly "Answer: X".
  - For Unethical Information, the LLM judge marks 100% of these degenerate explanations as "hint used". So the Qwen-fixed Unethical/General LLM gain (28→72) is mostly an artifact; CT stays at 3%.
  - Distinct-1, the paper's fluency criterion, *rises* for Qwen under the intervention because the outputs are short, so it does not flag this failure mode.
  - Llama distinct-1 drops from about 61% to 38-54% (Metadata about 38%, below the paper's 40% "degenerate" threshold on average).

## Codebase completeness: MAJOR_FIXES
The release contains the method (PE-LRP via the bundled `lxt` fork, attention intervention in `llama_PE.py` / `qwen2_PE.py`) and the main-experiment driver `scripts/lrp_guidance.py`, which runs the whole Table-1 protocol and prints CT/LLM/distinct-1. Llama ran with **no code edits** apart from a config-level switch.

Changes we made:
1. `src/settings.py`: the Protocol-Specific prompt existed only as commented-out code. We added an env-var switch `REASON_PROMPT=protocol` that selects it verbatim (config-level).
2. `src/settings.py` + `src/utils.py::prepare_msg`, active only with `REPRO_QWEN_FIX=1`: a Qwen chat-format fix.
   - Remove the stray `<` that `apply_chat_template(...)[:-10]` leaves for Qwen, whose template ends in the 11-character `<|im_end|>\n`.
   - Use Qwen `<|im_start|>`/`<|im_end|>` turns for the explanation question instead of the hard-coded Llama-3 `<|eot_id|><|start_header_id|>` tokens.
   - This is a bug fix that changes results. Without the flag, the code is byte-for-byte the release's behaviour, which is what the "as_released" rows use.

Not changed, but noted:
- CT "Internal" bug (handled offline, above).
- The judge prompt also goes through `[:-10]`, so Qwen2.5-14B judge prompts end with a stray `<`. The judge then answers "True>"/"False>". The parser takes the first `True|False` anywhere in up to 256 generated tokens, so verbose judge answers that restate the instructions can be mis-parsed.
- Qwen is loaded in fp32 (no `torch_dtype`), Llama in bf16.
- CLI defaults differ from the paper: `--alpha` 0.1 (Llama needs 0.06, passed on the CLI), `--num_of_examples` 100.
- Scripts written by us: `run_one.sh`, `run_one_fix.sh`, `worker.sh`, `worker_fix.sh`, `watchdog.sh` (job running); `parse_results.py`, `make_tables.py` (log parsing / tables); `ct_fixed_grader.py`, `expl_len.py`, `degenerate.py` (offline analyses).
- Missing for other tables: no TTα (Table 4) implementation; `--open_question` is ignored by `lrp_guidance.py` (Table 5 cannot be run as released); no script for the α sweep (Fig. 4/6). Closed-model scripts need API keys (not attempted).
