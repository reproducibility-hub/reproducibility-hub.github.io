## Discrepancies

**Code vs paper** (all minor):
1. **Adjacency weights** (`compute_text_adjacency_matrix` in `modex/main.py` and `modex-lite/model/ma_decoder.py`). The paper's Eq. (1) sums the unigram, bigram and trigram Jaccard scores equally (s1+s2+s3). The code computes (s1 + (s2+s3)/2)/2, i.e. weights 0.5 / 0.25 / 0.25.
2. **Evaluation subset** (`data/cnn_daily.py`, `data/math500.py`). The paper says "first 300 samples of the test split". The code shuffles the split with `random_state=0` and takes 300. Our numbers match the paper, so the paper's numbers were probably produced with the code's selection.
3. **Code-generation prompt** (`evaluator.get_instruction_suffix`). The code omits the paper's "First, briefly state your step-by-step reasoning" instruction (Appendix B.1) and asks only for code after "# Code #".
4. **ModeX-Lite pruning interval.** The paper uses T = 100. The README quick-start and `scripts/run_modex_lite.sh` use `--prune_frequency 300`; the argparse default is 100, which is what I used.

**Paper internal:**
1. Section 4.2 credits "ModeX with N=16" with 69.89 → 78.66 on HumanEval Pass@1. In Table 1, 78.66 is ModeX-Lite (N=16); ModeX (N=16) is 75.61.
2. Section 4.2 says ModeX-Lite gains +7.33 points on Llama MATH from N=4 to N=16. Table 1 gives 39.00 → 45.33 = +6.33.
3. Table 1, Qwen: the Perplexity BoN (N=16) row is identical to ModeX (N=16) on all summarization numbers and on math (34.28 / 11.24 / 21.06 / 3.92; 78.00), but differs on code. This is likely a copy error.
4. Section 5.2 attributes the 9.1 s latency to "ModeX (N=16)". Table 2 lists it for ModeX-Lite (N=16).
5. Section 4.1 says "four baselines" and then lists six.

## Why not fully reproduced

All of the proposed method's results reproduce. The verdict is PARTIALLY_REPRODUCED only because coverage is SUBSET: the baseline rows of Table 1 can't be run, since the release has no code for them, and the claims of beating those baselines therefore can't be checked. A few individual cells (8/98) fall outside the numeric tolerance. This is consistent with single-seed sampling noise: one HumanEval problem is 0.61 points and one MATH problem is 0.33 points.
