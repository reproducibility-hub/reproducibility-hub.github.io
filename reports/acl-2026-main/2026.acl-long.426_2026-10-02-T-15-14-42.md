## What I did
Environment: `conda create -p ./env python=3.11` plus `pip install vllm pandas scikit-learn pypinyin pinyin-to-ipa jiwer scipy statsmodels`. vLLM 0.30.0 needed `VLLM_USE_FLASHINFER_SAMPLER=0` because the FlashInfer JIT could not find nvcc.

Scripts I wrote (in `./scripts`, outputs in `./outputs`):
1. **`run_llm.py <hf_model> <tag> [sample]`** runs the inference.
   - Prompts are parsed verbatim from `Prompts.txt`.
   - The detection prompt runs on all 7,744 `original_review`s. The same output gives the detection label and the multi-label classes, as the paper's prompt does.
   - Rating prompts:
     - `original_review` for all 7,744 reviews (6,844 non-coded and 900 coded);
     - `char_mask_review`, `span_mask_review` and `decode_review` for the 900 coded reviews.
   - The decoded-review prompt is not in `Prompts.txt`, so I copied it from the paper's Appendix A.4.2.
   - Decoding: vLLM chat template, greedy (temperature 0), max 512 tokens.
   - The `sample` option uses each model's HF generation-config sampling as a sensitivity check. It changes almost nothing; see `outputs/*_sample_metrics.json`.
   - Commands: `VLLM_USE_FLASHINFER_SAMPLER=0 env/bin/python scripts/run_llm.py Qwen/Qwen2.5-7B-Instruct qwen` and the same with `meta-llama/Llama-3.1-8B-Instruct llama`. Each takes about 2 minutes on the H200.
2. **`evaluate.py <tag>`** computes the metrics.
   - JSON parsing with a regex fallback. Llama gave 190/7,744 malformed detection JSONs (mostly unescaped quotes or runaway evidence lists); the label/classes were recovered by regex. Qwen gave 6.
   - Detection: binary P/R/F1.
   - Classification: per-class multi-label P/R/F1 with sklearn. A class only counts as predicted when label = 1.
   - Rating: MSE.
   - The classification scoring protocol is not stated in the paper. Scoring over **all 7,744 reviews** reproduces Table 7. I also report coded-only scores in `*_metrics.json`.
3. **`phonetic.py`** computes the Table 5 CER and the Figure 4/7 S/D/I proportions.
   - Character-level CER (jiwer) on the dictionary's `code_*` (hypothesis) vs `decode_*` (reference) pinyin/IPA strings. Cipher and Orthographic are excluded, and the dictionary's `cross-lingual` label is merged into `transliteration`.
   - The paper's numbers come out only when each dictionary entry's CER is **weighted by how many times that span occurs** in the annotated `code_span` column of CodedLang.csv. Unweighted per-entry means are lower (e.g. AH 0.33/0.43 vs 0.49/0.57).
4. **`stats_a1.py`** runs the Appendix A.1 statistics; this is a secondary check.
5. **`compare.py`** builds the paper-vs-ours table (`outputs/comparisons.md`, `outputs/comparisons.json`).

Settings that differ from or are unknown in the paper:
- Decoding parameters, the inference framework (the paper does not say vLLM or HF) and the JSON-parse fallback policy are unspecified.
- The CER averaging (occurrence-weighted) and the classification scoring set (all reviews) were inferred from which choice reproduces the numbers.
