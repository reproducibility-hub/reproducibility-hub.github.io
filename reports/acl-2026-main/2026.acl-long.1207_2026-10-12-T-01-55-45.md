## 1. What the paper claims and what I targeted
The paper proposes two training-free ensemble attacks that suppress backdoor fingerprints (IF, C&H/"Hash", ImF) in a 3-model LLM ensemble:
- **TFA**: token-level top-K intersection/union filter.
- **SVA**: sentence-level perplexity cross-verification plus voting.

Main claims:
* **Table 2.** ASR on 6 primary models (LLaMA2-7B, LLaMA3.1-8B-It, Qwen2.5-7B, Qwen2.5-7B-It, Mistral-7B-v0.1, Amber-7B) × 3 fingerprint methods, with the auxiliary models fingerprinted LLaMA3.1-8B-It and Qwen2.5-7B-It.
  - TFA: 100% everywhere.
  - SVA: ≈100% on IF and C&H, but weaker on ImF (78% average).
* **Figure 5 (harmlessness).** TFA keeps or exceeds the accuracy of the best individual model; SVA improves on the primary model.
* **Table 3.** Comparison against baselines. GRI removes only IF fingerprints.
* **Tables 5 and 6 (scenario b).** The auxiliary models' fingerprints are suppressed too.

## 2. What I ran (exact pipeline)
All scripts I wrote are in `scripts/`. All released scripts were run **unmodified** (`git status` in `codebase/` shows no changes).

1. **Fingerprinted models: 18 in total** (6 bases × IF/Hash/ImF). Each was full-parameter SFT with the released `Fingerprint_dataset/train_fingerprint.py` on the released `train_IF_60.json`, `train_chain_hash60.json` and `train_stego60.json` (`scripts/train_one.sh`, `scripts/train_queue.sh`).
   - Hyperparameters from `Fingerprint_dataset/run.sh`: 20 epochs, lr 2e-5, cosine schedule, warmup 0.03, weight decay 0, fp32, gradient checkpointing, max length 512.
   - **Deviation:** the release uses 4 GPUs × batch 15 with DeepSpeed ZeRO-3 CPU offload. I used 1 GPU, batch 15 × gradient-accumulation 4, which gives the same global batch of 60 and the same 20 optimizer steps.
   - **Deviation:** I used `--optim adamw_torch_fused`. It is the same AdamW, but the default foreach implementation runs out of memory for 8B models in fp32 on a 141 GB GPU.
   - Trained weights were stored as fp16, which is the dtype every evaluation script loads.
   - Every model reached training loss ≈1e-4 and memorized its fingerprint. Single-model fingerprint success was 100% for IF and C&H; for ImF it was 90–100% with substring match and 100% with fuzzy match.
2. **Base models:**
   - `NousResearch/Llama-2-7b-hf`, a weight-identical mirror of the gated `meta-llama/Llama-2-7b-hf`.
   - `meta-llama/Llama-3.1-8B-Instruct`, `Qwen/Qwen2.5-7B`, `Qwen/Qwen2.5-7B-Instruct`, `mistralai/Mistral-7B-v0.1`, `LLM360/Amber`.
3. **Ensembles.** The auxiliary models follow Appendix C:
   - IF primary → C&H-LLaMA3.1-8B-It + ImF-Qwen2.5-7B-It
   - C&H primary → IF-LLaMA3.1-8B-It + ImF-Qwen2.5-7B-It
   - ImF primary → IF-LLaMA3.1-8B-It + C&H-Qwen2.5-7B-It
4. **Commands** (`scripts/eval_one.sh`), with `--max_new_tokens 50` as in the paper's Table 1:
   - `python single_model_test.py --test_set data/fingerprint_test/main3.jsonl --model_path1 models/<P> ...`
   - `python SVA.py --test_set ... --model_path1 models/<P> --model_path2 models/<aux1> --model_path3 models/<aux2> ...`
   - `python TFA.py` with the same arguments as SVA.
   - `main3.jsonl` concatenates the three released test sets (`IF/test_IF_10.json`, `Hash/test_chain_hash10.json`, `ImF/test_stego10.jsonl`; n = 10 each, matching the paper's n = 10). One run therefore gives scenario a (the primary's fingerprint) and scenario b (the auxiliary models' fingerprints).
   - SVA samples (temperature 0.7, top-p 0.85, top-k 50, no seed), so I ran it 3 times.
5. **ASR scoring.** The release has no scorer, so I wrote `scripts/score_asr.py` and `scripts/aggregate.py`. ASR = 1 − (fraction of queries whose output contains the normalized fingerprint target y), following Eq. 2.
   - Two sensitivity variants: fuzzy (first sentence ≥ 0.9 similar to y) and literal equality.
6. **GRI baseline (Table 3)** with the released `GRI_attack.py`, on Mistral-7B and Qwen2.5-7B.
7. **Figure 5 (harmlessness), scaled down.**
   - The paper's downstream evaluation files are not released and their size is not stated. I built 200-sample random subsets of six benchmarks in the field format of the released collate functions (`scripts/build_downstream.py`): PIQA (validation), ARC-C (test), TriviaQA (rc.nocontext, validation), MMLU (test), BoolQ (validation), ANLI (R1 test).
   - These were run through the released `single_model_test.py`, `SVA.py` and `TFA.py` with their built-in accuracy parsers, using `--max_new_tokens 16` (to fit the budget; TFA has no KV cache).
   - Covered: the 4 primaries shown in Figure 5 × 3 methods, plus the 4 auxiliary models individually.

## 4. Why this is PARTIALLY_REPRODUCED rather than REPRODUCED

## 5. Codebase completeness: MINOR_FIXES
No source file was edited. Everything ran through the released scripts with CLI arguments, plus runner, scoring and data-building scripts I wrote. Issues found:
- `run.sh` calls non-existent `SVA_3.py` / `TFA_3.py` and has a quoting bug (`--test_set''`). I used the README's direct commands instead.
- No ASR scorer is released (the scripts only dump predictions). I wrote `scripts/score_asr.py` and `scripts/aggregate.py`.
- The training launcher assumes 4 GPUs and DeepSpeed, which is not in `requirements.txt`. I ran plain Python on 1 GPU with gradient accumulation 4 and fused AdamW.
- `train_fingerprint.py` sets eos/bos/unk to `</s>` whenever the lowercase string "llama" appears in the model path. That would break LLaMA-3, because the token doesn't exist and its id goes out of range. I avoided it through directory naming.

- The fingerprint loaders trigger only if the test-set path contains "fingerprint".
- Default `max_new_tokens` values differ from the paper (256 / 16 / 20 vs 50); I set 50 via the CLI.
- The downstream evaluation files are not released; I rebuilt them.
- The UniTE, F-T, MEraser and Merge baselines are absent.
- The gated Llama-2 checkpoint was replaced by the ungated NousResearch mirror (an access-only change).

## 6. Discrepancies
**Code vs. paper:**
1. **Major. TFA probability aggregation** (`TFA.py: update_vocab1`, `vocab_softmax`).
   - Paper (Eq. 1): tokens in V_U but outside model j's top-K get probability 0.
   - Code: it looks up model j's real logit for those tokens (or uses logit 0 if the id is a duplicate) and takes a softmax over V_U. Such tokens therefore get non-zero, renormalized probability.
2. **Major. TFA token filter** (`get_intersection_vocab` / `ensemble_decoding`).
   - Paper (Algorithm 2): if a pair's intersection is empty, that pair contributes its union.
   - Code: V_U is the union of the pairwise intersections, and falls back to the union of all three top-K sets only if every intersection is empty.
3. **Minor. SVA perplexity** is computed on prompt + only the *first sentence* of each candidate, not on the full answer as in Algorithm 1.
4. **Minor. Inconsistent prompts.**
   - TFA and the single-model test prepend the "###instruction: A chat between a curious user…" system text.
   - SVA feeds the raw query.
   - This contradicts the paper's "consistent settings".
5. **Minor. Default max_new_tokens** are 256 (SVA), 16 (TFA) and 20 (single) vs 50 in Table 1.
6. **Minor, no effect on results. TFA tie-break.**
   - Paper: ties go to the primary model's highest probability P′.
   - Code: ties are broken by dict insertion order (the primary's top-K first).

**Paper-internal:**
7. Table 9's "SVA" column (Qwen2.5-7B ImF 1.0, Mistral IF 1.0, Mistral Hash 0.8) disagrees with the same settings in Tables 2, 3 and 8 (0.9, 0.9 and 1.0 respectively).
