# Reproduction report — BEFT: Bias-Efficient Fine-Tuning of Language Models in Low-Data Regimes (ACL 2026, 2026.acl-long.1799)

## Verdict
- **Verdict: PARTIALLY_REPRODUCED.** The numbers match the paper closely across almost every table. The central claim also holds almost everywhere: in low-data regimes, fine-tuning b_v beats b_q, and b_q beats b_k. There are a few real exceptions, listed below.
- **Result match (after fixes): TREND_MATCH.** Of 335 compared numbers, 291 are within tolerance, 37 are outside tolerance but keep the same ordering, 6 contradict the paper, and 1 is not comparable.
- **Result match (as released): TREND_MATCH.** The main tables (1, 2, 3 SST-2/RTE, 5, 10, 11) run with the released code unchanged. The bias-free-LLM experiments (Table 6, appendix Table 16), the CB/WiC rows of Table 3/12, and the VeRA/DoRA columns of Table 4 do not run without source edits (45 rows are DOES_NOT_RUN).
- **Coverage: FULL.** I ran every main-paper table at the paper's scale (same models, data sizes, hyper-parameters and seeds), plus appendix Tables 10, 11, 12 and 16 and the low-data rankings for Fig. 2/4/10. Not run: the Table 6 LoRA baseline (not implemented for LLaMA in the release). Runtimes in Table 2 were not compared (different hardware and a shared GPU).
- **Codebase completeness: MAJOR_FIXES.** The Table 6 (bias-free LLM) code path is broken as released: it always adds the bias to the value projection and then freezes it, so 0 parameters train and every run crashes. Fixing that required a logic change. All other fixes are minor.
- **Flags:** BASELINE_STRONGER_THAN_REPORTED. The LoRA baseline on WiC scores 69.3 (OPT-1.3B) and 66.5 (OPT-6.7B), against the paper's 50.0 and 50.4, so on WiC LoRA beats b_v, where the paper had b_v ahead.

## What was run
Code: https://github.com/whubaichuan/BEFT, cloned into `./codebase`. My edits are left uncommitted; the diff is saved in `codebase_changes.diff`.

Environment: one conda env `./env` (Python 3.10, torch 2.1.0+cu121, transformers 4.41.2, datasets 3.6.0, per `requirements.txt`). - Tolerance is ≤1 point absolute or ≤5% relative, or within the paper's reported std when it gives one (Tables 2, 6, 10, 11, 12).
- TREND_MATCH means the value is outside tolerance but the comparison that matters keeps its sign: b_v vs b_q for b_v rows, and b_v vs that row for the other rows.
- Table 1 cells are single runs at seed 0, as in the paper.

## Why it is not "REPRODUCED"
The coverage is full and most numbers are within tolerance, but the overall match is TREND_MATCH rather than NUMBERS_MATCH:
- 37 numbers are outside tolerance, and 6 contradict the paper. The contradictions are OPT-1.3B CB b_v (single run and the 3-seed mean), OPT-6.7B WSC b_q vs b_v, and the WiC LoRA and OPT-6.7B WSC LoRA baselines.
- BEFT+VeRA does not reproduce b_v > b_q.
- The bias-free-LLM experiments needed a logic fix before they would run at all.

I found no code bug or configuration difference that explains the OPT-1.3B CB collapse. The released script runs CB at lr 1e-2 with fp16, batch 1 and 8 gradient-accumulation steps, and b_v does not learn on any seed. The other tasks and models are unaffected.

## Codebase completeness: MAJOR_FIXES
Changes to the released code (left uncommitted; see `codebase_changes.diff`):
1. `run_BEFT.py`: added `'cb':[250], 'wic':[1000]` to `low_data_lib`. Without these entries the README's Table 3 command silently does nothing for CB/WiC. Minor.
2. `autoregressive_llm/additive_bias.py` and `run.py`: `Addbias` hard-coded `change_bias='value'`, and `run.py` then froze every parameter not matching `<x>_proj.bias`. That freezes the added `add_bias` too, leaving 0 trainable parameters and crashing with "element 0 of tensors does not require grad". I verified this crash on the unmodified code (`logs/llama_asreleased_test.log`). Fix: pass the selected bias term into `Addbias` and match `.add_bias`. Major: program logic, and it gates all of Table 6/16.
3. `autoregressive_llm/run.py`: set the pad token to eos when the tokenizer has none (GPT-J, Table 16 only; added after all other LLM runs had finished).
4. `autoregressive_llm/utils.py`: `getattr` fallback for `tokenizer.add_bos_token` (DeepSeek-Coder under transformers 4.28; Table 16 only).
5. `others/BEFT_LoRA_evaluator.py`: added a `BEFT_PEFT` environment variable to choose LoRA, VeRA or DoRA. The release does this by (un)commenting code, and `DoraLinear`'s extra argument is never passed. The default (`lora`) keeps the released behaviour.
