**Summary.**
- **What reproduces.** The released A²-Judger implementation, run with the paper's settings (Qwen2.5-VL-7B judging agent, k=5 candidates, 5% budget, 5 runs), reproduces the paper's Table 1 ranking accuracy on **AI2D (93.5 vs 95.1), MMMU (87.1 vs 87.5) and MMT (90.7 vs 91.2)**. It also reproduces **ranking stability on all four benchmarks** (97.9/97.2/96.0/97.5 vs 98.8/96.0/96.9/97.1) and the Table 4 diversity distances.
- **What does not reproduce.** **SEEDBench ranking accuracy (87.5 vs 92.4)** is clearly lower. This holds in all 5 runs, at every budget from 1% to 5%, and for the 3B agent too.
- **The released default.** It uses 10 retrieval candidates rather than the paper's k=5. With it, our numbers match the paper's own 10-candidate ablation (Table 13) within 1 point on all four benchmarks.
- **An embedding-order bug may explain the gaps.** The released CLIP-feature script writes embeddings in a row order that differs from the order main.py uses to look them up; the two orders differ only for AI2D and SEED. With that misaligned, as-released ordering, AI2D/SEED rise to **95.0 / 90.3**. That is closer to the paper's 95.1 / 92.4, which suggests the paper's AI2D/SEED numbers may come from this misalignment.
- **The "beats all baselines" claim.** The baselines are not released, so I can't check this claim directly. A simple Random baseline that I re-implemented is as good as or better than A²-Judger on AI2D and SEED ranking accuracy. A²-Judger is far more *stable* than Random on every benchmark.

## What the paper claims and what I targeted

- **Main claim (Abstract, Sec. 3.2, Table 1).** Under a 5% data budget, A²-Judger gives the most reliable (ranking accuracy ρ) and most stable (pairwise ρ across K=5 runs) evaluation on AI2D, MMMU, MMT-Bench and SEEDBench. It reports average 91.5 / 97.2 and beats all baselines (best baseline average 90.1 / 90.6).
- **Other results checked.**
  - Table 5: the Qwen2.5-VL-3B agent reaches an average of 91.1.
  - Table 4: average CLIP distance among the selected questions.
  - Tables 13/15–17: the 1–5% budget curves.
- **How the evaluation works.** The release uses pre-collected 0/1 response matrices of the 17 test models (`model_performance/*.csv`), so "querying" an evaluated model is a table lookup. Only the judging agent (Qwen2.5-VL-7B/3B-Instruct, open weights) has to run, and no closed API is needed.

## What I ran

1. **Data.**
   - Downloaded the four VLMEvalKit TSVs from the URLs in the README. The opencompass host has an expired TLS certificate, so I used `curl -k`. MD5s match VLMEvalKit's `DATASET_MD5`.
   - Unzipped `data/question_diff.zip`, which contains the released IRT difficulties.
2. **CLIP text embeddings (ViT-B/32).** These are not released and have to be generated:
   ```
   python -P clip_features/clip.py --benchmark <B> --mode text --data_dir LMUData --download_root clip_features/clip_models \
       --align_to data/<B>/train/train_prob_df.json --out_path clip_features/<B>/text_embeddings
   ```
   - `text` matches main.py's default `--feature text` and the init file name `clip_text_init10.json`.
   - My sanity check on the feature type: the expected random-subset distance with these features matches the paper's Table 4 Random row (0.740/0.817/0.754/0.755 vs 0.741/0.806/0.756/0.757).
3. **Judging agent.**
   - Qwen2.5-VL-7B-Instruct and -3B-Instruct, served with vLLM 0.8.5.post1 (bf16).
   - Decoding: greedy with repetition_penalty 1.05. This equals the model's generation_config (temperature 1e-6), as in the paper's App. B.2.4.
4. **Main command**, run once per (benchmark, test model, run). `scripts/driver.py` runs these in parallel, about 40 at a time against one vLLM server:
   ```
   python main.py --agent_model Qwen2.5-VL-7B-Instruct --test_model <M> --benchmark <B> --include_text --include_image \
       --save_dir ../runs/<run>/... --max_iter <0.05N-9> --vllm_url http://127.0.0.1:18765 [--top_n 5]
   ```
5. **Configurations run.** Each covers 4 benchmarks × 17 models × 5 runs:
   - **(a) 7B, k=5:** the paper's main setting.
   - **(b) 7B, top_n=10:** the released default.
   - **(c) 3B, k=5:** the Table 5 setting.
   - **(d) diagnostic, 7B, k=5, AI2D+SEED only:** uses embeddings in raw TSV order (unaligned). This is what the released clip.py produces if its output is simply renamed to the file main.py loads.
6. **Metrics** (`scripts/evaluate.py`).
   - Ranking accuracy ρ = 1 − 2·#inversions/(n(n−1)), using the same formula as main.py. It compares the 17 models' IRT ability after B = ⌊0.05·N⌋ questions (10 initial + adaptive; `ability_list[B-10]`) to the full-benchmark accuracy ranking.
   - Budgets B: AI2D 154, MMMU 52, MMT 156, SEED 711.
   - Ranking stability: mean pairwise ρ over the 5 runs.
   - Table 4 distance: mean pairwise Euclidean distance between the B selected questions' text-CLIP embeddings, averaged over models and runs.
7. **Random baseline** (`scripts/random_baseline.py`). This is my own implementation of App. B.2.1: a uniform 5% subset, ranked by accuracy. Random is the only baseline simple enough to rebuild from the paper's description. Values are expectations over 200 × 5 trials.

**Settings that differ from the paper:**
- **Agent engine.** I served the agent with vLLM instead of HF `generate`, purely for throughput: 8 HF processes on one GPU ran at about 14 s/step. A 30-step spot check gave equivalent selections, and HF itself is not deterministic run-to-run.
- **Stopping point.** Each run stops at the 5% budget instead of running max(200, N/20) steps. Trajectories are sequential, so the prefix up to the budget is unchanged.
- **Multi-image MMMU questions.** For the 47 MMMU questions with more than one image, only the first image is shown to the agent. The TSV stores a list of images, which the released code cannot handle.

## Why it is not fully reproduced

1. **SEED gap.** SEEDBench ranking accuracy is about 5 points below the paper in every run, both agents, and every budget. I found no config difference that explains it, apart from the embedding-order issue (which closes about 60% of the gap).
2. **Missing code.** Baselines, A²-Judger_H and the ablations are not released, so the "beats all baselines" claim can't be checked directly. A re-implemented Random baseline is as good or better on AI2D/SEED in ranking accuracy.
3. **Released code needs fixes.** The release does not run unmodified, and its default (10 candidates) is not the paper's main setting.

## Codebase completeness: MAJOR_FIXES

Changes to the released code. These are uncommitted in `./codebase`; see `git diff`.
- **`main.py`**:
  - The model-info path pointed to `data/model_information_new.csv`, which has English column names. `utils/util.get_model_param` selects Chinese column names, so it crashed with a KeyError.   - **MMMU images.** `MMMU_DEV_VAL.tsv` stores images as a stringified list. main.py builds an undecodable data-URI from it, so loading crashes. I parse the list and use the first image.

  - Added `--top_n` (the released code hard-codes 10; the paper uses k=5) and `--max_iter` (stop at the budget).

- **`clip_features/clip.py`**:
  - Fixed the undefined `ni(...)` (should be `clip.load`).
  - Read the TSV with `sep='\t'`.
  - The script's name shadows the `clip` package, so it must be run with `python -P`; the README's `cd clip_features; python clip.py` fails.

  - **Result-affecting:** added `--align_to` to reorder embeddings to the `train_prob_df.json` order that main.py indexes by. Without it, AI2D/SEED retrieval uses other questions' embeddings.
