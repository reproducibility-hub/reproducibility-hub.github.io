# Reproduction report — Dynamic Infilling Anchors (DIA), ACL 2026 (2026.acl-long.1205)

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): MIXED**. **As released: MIXED**. No source edits were made for the main runs, so both labels are the same.
- **Coverage: SCALED_DOWN.**
  - DIA GSM8K (1319) and DIA MATH-500 (500) ran at full scale.
  - DIA Wikibio JSON ran on the first 3000 of 10000 samples.
  - Base/Instruct baselines ran on subsets.
  - The Infilling baseline and the JSON baselines were not run because no code was released for them.
- **Codebase completeness: MINOR_FIXES.**
  - The method and its pipelines ran unmodified.
  - The README/run script defaults differ from the paper (8-shot, 4 diffusion steps, `--limit 5`).
  - The MATH task config is missing.
  - The baselines are not released.
  - The released Stage-1 code has a truncation bug. It was left in place for the main runs and run patched only as a diagnostic.

**Summary.**

What reproduces:
- GSM8K accuracy: 47.92 vs 46.78.
- MATH-500 accuracy is close: 23.60 vs 20.08.
- Wikibio JSON valid-format rate: 79.83 vs 79.84.
- With the released strict regex, Dream-Base/Instruct prompt-only baselines score 0.00 format, as the paper reports. DIA's format compliance is far above that.

What does not reproduce:
- DIA's own format scores on the reasoning benchmarks: GSM8K 49.20 vs 72.63, MATH-500 63.00 vs 76.82.
- The Wikibio hallucination rate: 7.97% vs 0.15%. That is worse than the paper's Instruct baseline (5.10), so the "lowest S_Hal" claim fails.

Notes on the gaps:
- The paper itself reports different GSM8K format numbers for the same configuration in its appendix: 58.91–59.67 in Tables 6/7.
- The released code never truncates the `<think>` block in Stage 1, contrary to Algorithm 1.
- Patching that bug raises format compliance (GSM8K 52→85.5, MATH 62→75 on matched subsets) but lowers accuracy (48.5→40.0, 22→16). Neither variant reproduces the paper's combination of numbers.

## What was run

Model: `Dream-org/Dream-v0-Base-7B` (bf16). The released `dia/modeling_dream.py` and `dia/generation_utils_dia.py` were injected into `codebase/resource/dream_dia`, as the README instructs. Hardware: 1× H200.

Environment:
- conda env at `./env` with Python 3.10, torch 2.5.1+cu124, `transformers==4.46.2` (README pin) and accelerate 1.15.
- lm-evaluation-harness from git main (0.4.14.dev0), plus math-verify.

### Reasoning (Table 1)

Each chunk ran the unmodified `codebase/reasoning/eval_dia.py` through `runs/chunk.sh`, driven by a job queue (`runs/worker.sh`, 3 concurrent workers on one GPU):

```
python eval_dia.py --model dream \
  --model_args pretrained=<model_dir>,max_new_tokens=<256|512>,diffusion_steps=512,add_bos_token=true,temperature=0,top_p=0.95 \
  --tasks <gsm8k_cot|minerva_math500> --num_fewshot 0 --batch_size 1 --log_samples --samples '{"task": [chunk doc ids]}'
```

Settings:
- **GSM8K:** lm-eval `gsm8k_cot` (the task in `run_dia.sh`) forced to 0-shot, max_new_tokens 256, all 1319 test docs.
- **MATH-500:** lm-eval `minerva_math500` (HuggingFaceH4/MATH-500), 0-shot, max_new_tokens 512, all 500 docs.
- DIA hyperparameters are the code's built-ins: Δ=4, c=0.05, M=512. 512 diffusion steps are split evenly over the 2 blocks.
- Paper settings that differ: Table 4 gives c=0.065 for GSM8K, but the code hard-codes 0.05. Table 4 gives batch size 3 for MATH, but the code supports only 1.

Metrics:
- **S_format:** the released `reasoning/format_eval.py::format_reward`, i.e. the strict regex `^<think>.*?</think><answer>.*?</answer>$`, applied to the lm-eval response after its `until` cut.
- **Accuracy:** lm-eval `exact_match` with `flexible-extract` for GSM8K and `math_verify` for MATH-500. The paper does not name its accuracy extractor.
- Aggregation across chunks: `scripts/aggregate.py`.

Baselines:
- Dream-Base and Dream-Instruct prompt-only baselines (not released) were run with the same `eval_dia.py` and the same format prompt. The model dir pointed at the stock Dream code (`resource/dream_base_stock`, `resource/dream_instruct`), which uses Dream's standard `diffusion_generate`. Steps = 512; no chat template.
- They ran on prefixes of the test sets because of the time budget: Base GSM8K/MATH and Instruct GSM8K/MATH subsets, sizes in the table below.

### JSON generation (Table 2)

1. Wikibio (DavidGrangier/wikipedia-biography-dataset) test split → `json/process_biography_dataset.py --max-samples 10000`.
2. `json/build_separator_tokens.py`.
3. `bash json/run_json_eval.sh` with the release defaults: initial 6,6,6; max 32,32,32; 16 steps per block; temperature 0.7; top-p 0.95; top-k 50; Δ=4; threshold 0.05.
4. Samples 0–999 in one run, then samples 1000–2999 in a second run that was stopped at 2000 samples to save GPU time.
5. Scored with the released `json/json_eval.py` (regex and prefix-removal extraction) on the merged 3000 samples.

The paper does not state the JSON generation hyperparameters, so the release defaults were used.

## Why it is not fully reproduced

1. **Format scores (reasoning) are lower than reported.**
   - The released Stage-1 code (`_block_sample`) clamps the detected end position of every non-final block to the block end, so the `<think>` block is never truncated.
   - The surplus masked space is then filled by the model with its own `…think><answer>X</answer>` followed by a hallucinated `Q: …` continuation.
   - lm-eval's `until=["Q:"]` cuts the response there, which removes DIA's real end anchors, and the strict format regex fails.
   - Patching this one comparison (`<` → `>`) raises S_format a lot but lowers accuracy (see diagnostics).
   - The paper is also internally inconsistent here: Table 1 says 72.63 for GSM8K format, while Tables 6/7 give 58.91–59.67 for the same configuration.
2. **The Wikibio hallucination rate is ~8%, not 0.15%.**
   - Under the released sampling settings (temperature 0.7), the model often closes the last field early and adds extra keys inside the masked span (`"profession": "footballer", "club":"}"`). `json_eval.py` counts these as hallucinated fields.
   - The S_format of 79.83% matches the paper almost exactly, so the pipeline and data are the same. The gap is in S_Hal only.
3. **Baselines are not released.**
   - The Fixed-position Infilling baseline (anchor positions unspecified) and all JSON baselines could not be run.
   - The Base/Instruct baselines needed guesses (no chat template; stock Dream sampler with 512 steps).
   - Dream-Base's GSM8K accuracy matches the paper (68.5 on 600 docs vs 68.99).
   - Dream-Base on MATH-500 is clearly stronger than reported: 39.0 on the first 200 docs vs 25.14. On the same 200 docs DIA scores 26.0, so the Base-minus-DIA accuracy gap is about 13 points, vs about 5 in the paper. Flag `BASELINE_STRONGER_THAN_REPORTED`; caveat: the Base sampler config is our guess.
   - Instruct does not match: higher on GSM8K, and empty outputs on MATH because it emits EOS immediately without a chat template. These rows are NOT_COMPARABLE.
4. **Compute/time.**
   - At 512 diffusion steps, DIA costs about 17 s (GSM8K) and about 26 s (MATH) of H200 time per sample.
   - With a 20 h limit, the JSON evaluation was cut to 3000/10000 samples and the baselines to subsets.
