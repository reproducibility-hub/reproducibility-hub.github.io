### Observations
- **MCD:** reproduces the ranking on every model. AUROC 94.6–97.0 vs paper 95.0–98.6. On InternVL, AUROC/AUPRC match the paper almost exactly (96.2/96.0 at L21). Accuracy and F1 come out ~2–4 points below the paper on LLaVA and InternVL, and FPR is higher (22–28 vs 15–20).
- **KCD:** the separability metrics are systematically and substantially lower than reported. AUROC is 88–91, so 5–8 points below the paper, well outside its std. Seed variance is large (AUROC std 3–7, AUPRC std up to 10). KCD scores saturate at ±2 (unit-sphere k-NN distance difference), because the learned projection collapses each class almost to a point. Many test samples therefore tie, and AUROC becomes noisy. Within a single seed, per-layer AUROC jumps between 0.80 and 0.98.
- **Qwen KCD/MCD:** the operating point differs from the paper. Ours has much lower TPR (71–90 vs 95–98) and lower FPR (5–19 vs 18–25), i.e. the calibrated threshold is more conservative.
- **Paper's KCD-vs-MCD claim** ("KCD achieves significantly lower FPR and superior F1"): partly holds. KCD's FPR is lower than MCD's on all three models. But its F1 is not superior: LLaVA 88.1 vs 88.3, Qwen 80–85 vs 85–87.
- **Baselines:** the released HiddenDetect replication matches the paper on Qwen to within 2.2 points on every metric. On LLaVA and InternVL it comes out weaker than reported, which only widens the methods' margin.
- **Determinism:** the same seed does not give the same result across processes (seed-42 LLaVA KCD L16: AUROC 0.964 in a fresh run, 0.961 in a cached rerun, 0.897 inside the runner). The scripts set `os.environ["PYTHONHASHSEED"]` inside `main()`, which has no effect on the running interpreter. Iteration over the Python `set` of training dataset names, which fixes dataset IDs and concatenation order for projection training, therefore varies per process. Combined with the saturating KCD scores, this makes single runs noisy. The 20-seed means are the meaningful comparison.

## Why it is not fully reproduced
No missing data, models or compute blocked the run; the full Table 3/5 protocol ran. The gap is in the numbers themselves:
1. KCD's AUROC/AUPRC come out ~5–9 points below the paper on all three models, and Qwen's TPR/F1 are lower. Checks run: k=40 vs 50 (no effect), fresh vs cached features (no systematic effect). A cause in the released code was not identified. The KCD AUROC is very unstable across seeds and processes; the paper's tighter std (e.g. ±0.9 at LLaVA L16) is not reproduced (ours ±4.0).
2. MCD comes out ~1.5–3.5 AUROC points lower on LLaVA/Qwen. That is outside the paper's very small reported std (±0.1–0.3), but the ranking is unchanged.
3. Missing baseline code (GradSafe, JailGuard, JailDAM, JailDAM-RCS) prevents re-checking those comparisons.

## Codebase completeness: MINOR_FIXES
The method, the data pipeline, the evaluation and the multi-seed driver are all released. Edits to the released code (left uncommitted in `./codebase`; `git diff` shows them):
1. `code/run_multiple_experiments.py`: the script paths pointed to non-existent `code/balanced_ood_kcd.py` / `balanced_ood_mcd.py`, so the README's multi-seed command fails. Changed them to `kcd.py` / `mcd.py`. File-name fix only.
2. `code/kcd.py`, `code/mcd.py`: the "baseline model forward pass" latency benchmark (only for Table 4 profiling) calls the LLaVA-only `extractor._construct_conv_prompt` and `tokenizer_image_token`. It crashed with AttributeError for `--model qwen` and `--model internvl` before any detection ran. Changed `if baseline_sample:` to `if baseline_sample and model_type == "llava":`. The benchmark is skipped for non-LLaVA models; detection logic is untouched; LLaVA behaviour is unchanged.

Environment/data-level issues (no source edits):
- Per-model transformers versions are installed in side directories inside the single env (see above).
- `hidden_detect_*.py` need numpy>=2 (`np.trapezoid`), which conflicts with the README's LLaVA env (scikit-learn 1.2.2 / numpy 1.26). Solved with the side directory. Under numpy 1.26, every sample silently errors ("Error processing sample: module 'numpy' has no attribute 'trapezoid'").
- InternVL's remote code needs `timm.layers` (timm ≥0.9), but LLaVA pins timm 0.6.13.
- `download_datasets.py` creates an empty `data/JailBreakV-28K` directory that shadows the real `data/JailBreakV-28k` in the loader.
- The gated `walledai/AdvBench` and `walledai/XSTest` were replaced by the identical original public CSVs (access-only change).
- `feature_extractor_internvl.py` runs InternVL3-8B (a bf16 model) in fp16. The final layer (28) overflows to NaN for 2,223 samples, which crashes MCD when all layers are processed. Worked around with the runner's own `--layers 20,21,22`. Layers 20–22 contain no non-finite values.
- The committed `mcd.py` has `MAIN_SEED = 45` while `kcd.py` has 42. This is irrelevant for multi-seed runs, where the runner sets seeds 42..61.

Scripts I wrote (outside the codebase, in `scripts/`): `prepare_gated_substitutes.py` (AdvBench/XSTest from public CSVs), `aggregate.py` (mean±std/max over the seed CSVs), `paper_values.py`, `compare.py` and `build_outputs.py` (tables), and `run_kcd_k50.sh` (k=50 diagnostic, on scratch copies only).
