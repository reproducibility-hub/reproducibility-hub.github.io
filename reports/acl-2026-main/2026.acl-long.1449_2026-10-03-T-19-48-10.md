Code: https://github.com/kg4sci/CITE-NEW (linked in the paper), cloned to `./codebase`. Data: https://huggingface.co/datasets/kg4sci/CITE (public; downloaded to `./data`).

**Summary.** The benchmark's main table (Table 2, node classification on CITE) largely reproduces:
- **TAPE**, the best model in the paper: we get **0.9936 / 0.5609** Micro/Macro-F1 vs 0.9936 / 0.5655 in the paper.
- **Heterogeneous GNNs** (5 seeds): SimpleHGN, HGT, HPN, NARS and RGCN are within tolerance, except SimpleHGN Macro-F1, which is 3.4 points high.
- **GCN, Llama-2 and Vicuna** match. Vicuna matches exactly.

All of the paper's qualitative findings hold:
- heterogeneous models beat homogeneous ones by a wide margin;
- SimpleHGN and HGT are the strongest heterogeneous models;
- TAPE is the best model overall;
- LLM-only models score near zero.

Deviations:
- **GAT and GraphSAGE** on the full homogenised graph come out much higher than reported (0.635 / 0.675 Micro-F1 vs 0.51). On the paper-only graph used by the released `run.sh`, Micro-F1 matches but Macro-F1 is lower.
- **CompGCN** comes out much higher (0.949 / 0.443 vs 0.817 / 0.218).

Not run:
- GraphGPT and LLaGA;
- HAN and MAGNN;
- all link-prediction AUC-ROC numbers.

Three results from the released pipeline weaken parts of the paper's interpretation:
1. **The Vicuna score is a parsing artifact.** The released LLM scorer maps every unparsable answer to class 1. Vicuna's reported 0.0077 / 0.0002 is exactly the frequency of class 1: 127,664 of 127,690 Vicuna predictions are this fallback, as are 103K of Llama-2's.
2. **Graph propagation isn't what drives TAPE.** Replacing SAGE with the released MLP on the same TAPE features (no graph propagation) gives **0.9955 / 0.7349**, higher than TAPE itself. The fine-tuned LM alone gets 0.9959 / 0.7930 because the node text contains the journal name. This contradicts the paper's Table 3 claim that TAPE's advantage "mainly arises from explicit structural propagation". The paper's own w/o-propagation variant isn't released, so this comparison is NOT_COMPARABLE, but the released pipeline doesn't support the claim.
3. **The released Qwen script uses a different model.** It calls an API model, `qwen2.5-72b-instruct`, while the paper reports Qwen2.5-7B.

## What I ran

Environment: one conda env (`./env`, Python 3.10) with:
- torch 2.1.2+cu121, torch_geometric 2.6.0 (+ pt21 wheels), dgl 2.1.0+cu121;
- transformers 4.44.2 and accelerate 0.33;
- vLLM 0.3.3 (used only to speed up LLM inference).

Hardware: 1×H200.

### 1. Homogeneous GNNs (`codebase/models/gnn/gnn.py`, unmodified)

Command: `python gnn.py --dataname {my_graph_data|chemistry} --model {GCN|GAT|SAGE} --hidden_channels 16 --num_layers 2 --dropout 0.3 --lr 0.01` (via `run_gnn.sh`). This uses the hyperparameters from App. E.1 and 200 epochs.

Two graphs were run:
- **`my_graph_data.pt`**: the full 438,304-node graph with all node types merged into one. This matches the paper's text ("treat all heterogeneous nodes as a single type"), and `gnn.py`'s label padding is written for it.
- **`chemistry.pt`**: the 127,690-paper citation graph that the released `run.sh` uses.

The seed is hard-coded to 42 in `gnn.py`, so each setting is a single run. Micro-F1 is test accuracy at the best validation accuracy; Macro-F1 is test Macro-F1 at the best validation Macro-F1 (the script's own reporting).

### 2. Heterogeneous GNNs (`codebase/models/HGN`)

The released `hgn` package is a pruned, renamed copy of OpenHGNN and doesn't import as shipped (e.g. `hgn.models.NEW_model` and `trainerflow.link_prediction` are missing). The README says to `pip install openhgnn`. To run it:
- I overlaid the whole released `hgn` tree onto OpenHGNN commit `2df2f64` (Nov 2024) as package `openhgnn`, in `./hgn_work`.
- Command: `python main.py -m {RGCN,CompGCN,SimpleHGN,HGT,NARS,HPN} -t node_classification -d my_custom_node_classification -g 0 --use_best_config [--seed s]`, for seeds 0–4 (`run_hgn.sh`, `run_hgn2.sh`).
- Hyperparameters come from the released `config.ini` and equal those in App. E.1.

The data loader (`your_dataset.py`) expects CSVs that aren't released in that form. The released CSVs are a 50K-paper subset with inconsistent ID ranges. I therefore rebuilt the same heterograph (same relations pa/ap, pk/kp, pj/jp, pp) from the released `my_graph_data.pt`, whose size matches Table 1 (438,304 nodes, 1,220,374 edges, 84 classes):
- Node-type index ranges were inferred from the node texts and edge structure: paper 0–127,689, author 127,690–348,786, keyword 348,787–435,750, journal 435,751–438,303.
- Split: 60/20/20 random split from the loader (`np.random.permutation`, seeded by the config seed).

### 3. LLM-centric models

The "Original" free-form prompt behind Table 2 is the "LLMs&TAPE prompt" in App. C.1. It exists only in `TAPE/chat.py`: the raw node text (title, journal, authors, keywords, abstract) followed by "Question: Which of the following categories does this paper belong to: …107 names…".

The released `LLMs/*/chat.py` scripts don't implement it:
- they use the Forced-choice toolkit prompt;
- `Llama2/chat.py` has a placeholder arXiv label set;
- the Llama-3.1 and Qwen scripts have empty paths;
- the Qwen script calls an API 72B model.

So for each of the four models I ran the `TAPE/chat.py` prompt:
- Inference: greedy decoding, 64 new tokens, the full prompt+generation stored as in `chat.py`, all 127,690 papers. I used vLLM (`scripts/llm_infer_vllm.py`), because HF generate would have taken 10–19 h per model.
- Scoring: the released parser and metric, `TAPE/llama_preds.py` (`scripts/llm_eval.sh`). It computes F1 over **all nodes**, as the release does.
- Models: Llama-2-7b-chat (NousResearch mirror), vicuna-7b-v1.5-16k, Qwen2.5-7B-Instruct, Llama-3.1-8B-Instruct. Llama-3.1 was run with `rope_scaling` removed, because vLLM 0.3.3 lacks the llama3 rope type.

### 4. TAPE (`codebase/models/TAPE`, steps as in `run.sh`)

1. Llama-2 responses (step 3).
2. `llama_preds.py` → `chemistry.csv` with the top-k predictions.
3. `python -m core.trainLM dataset chemistry seed 0`: fine-tunes the TA LM, multi-qa-distilbert-cos-v1, 10 epochs.
4. `python -m core.trainLM dataset chemistry seed 0 lm.train.use_gpt True`: fine-tunes the E LM on the Llama-2 responses.
5. `python -m core.trainEnsemble dataset chemistry gnn.model.name SAGE`: config defaults are layers 4, hidden 128, dropout 0, and the TA_P_E ensemble.

I also ran `gnn.model.name MLP` with the same features, as a "without graph propagation" check. This uses the released 80/10/10 split; the paper says 60/20/20.

## Why not fully reproduced

- **GraphGPT and LLaGA**: not run. GraphGPT needs two-stage instruction tuning of a 7B model on ~1.7 GB of instruction data, followed by generation. The LLaGA training code reads `dataset/cite/CITE.pt` with `label_texts`, which isn't released (only `chemistry.pt` with `label_name`), and it pins transformers 4.31 / deepspeed 0.11, which conflicts with the single shared env. This is a compute/time and environment limit, plus missing data.
- **HAN and MAGNN**: they aren't in the README's run list, and the CITE dataset defines no metapaths.
- **Link prediction (AUC-ROC column of Table 2, Tables 5 and 7)**: the release has no CITE link-prediction dataset or pipeline. `my_custom_node_classification` is node classification only.
- **Seeds**: single seed for the homogeneous GNNs (seed hard-coded in `gnn.py`) and for TAPE. The paper uses 5 runs.
- **Qwen 2.5 / Llama 3.1**: the scripts for the Original protocol aren't released, so my runs are reconstructions and marked NOT_COMPARABLE.
- **CompGCN, GAT/SAGE (full graph)**: they come out clearly higher than reported. I found no code difference that explains it.

## Codebase completeness: MISSING_SCRIPTS

Missing pieces and every change I made:
- **`models/HGN/hgn`**:

## Discrepancies

1. **TAPE split (code vs paper, minor).** `load_chemistry.py` uses an 80/10/10 split; the paper says all experiments use 60/20/20.
2. **Qwen model (code vs paper, major).** `LLMs/Qwen2.5/chat.py` calls the DashScope API model `qwen2.5-72b-instruct`; the paper reports Qwen2.5-7B.
3. **LLM prompt protocol (code vs paper, major).** The released `LLMs/*/chat.py` scripts use the Forced-choice prompt, but Table 2 is the "Original" protocol. `Llama2/chat.py` passes a placeholder arXiv label set.
4. **LLM scoring (code vs paper, major).** `llama_preds.py` scores all 127,690 nodes, not a test split, and maps unparsable answers to class 1:
   - Vicuna's reported 0.0077 / 0.0002 is exactly the class-1 frequency (127,664 fallback predictions);
   - 103K of Llama-2's 127,690 predictions are the fallback;
   - Qwen gives sensible free-text answers, but the parser only looks after the word "Answer", which this prompt never produces, so 121,912 of its predictions are the fallback.
5. **Homogeneous-GNN graph and grid (code vs paper, major).** `gnn/run.sh` uses `chemistry` (paper-only graph) and a hyperparameter grid. The paper says all node types are merged into one, with hidden=16. On the merged graph GAT and SAGE are much stronger.
6. **HGN loader (code vs paper, minor).** It hard-codes 106 classes and needs unreleased CSVs (the paper uses 84 classes). The released CSVs are a 50K-paper / 63-label subset.
7. **HGN mini-batching (code vs paper, minor).** `HGN/main.py` always passes `mini_batch_flag=False`, overriding the mini-batch settings and batch sizes in `config.ini` / App. E.1. All HGN models train full-batch.
8. **TAPE GNN defaults (code vs paper, minor).** layers 4, hidden 128, dropout 0.0; dropout 0.0 is outside the paper's stated grid.
9. **Label names (code vs paper, minor).** `chemistry.pt` (107 names) and `my_graph_data.pt` (84 names) list different class names for the same `y` from index 10 on. The LLM prompt and parser use the 107-name list, which includes MATHEMATICS twice and NOTHING.
10. **TAPE w/o graph propagation (code vs paper, major).** The Table 3 variant isn't released. The released pipeline shows TAPE's performance doesn't depend on graph propagation (MLP 0.9955 / 0.7349 > SAGE 0.9936 / 0.5609). This contradicts the paper's interpretation in Sec. 3.1.2.
11. **Graph used by LLM+Graph models (code vs paper, minor).** They run on `chemistry.pt` (127,690 papers, citation edges only), not the 438K-node heterogeneous graph of Table 1. The heterogeneous information enters only as text.
