**Main findings**

- **SFT-Vanilla and SFT w/ correct traces reproduce Table 2 numerically** for both small models. Accuracy, F1, P, R, classification-step accuracy, IR-step accuracy and trace length are all within about 1 point or 5% relative (mean of 3 seeds).
- **Table 4 (Llama-3.1-8B) reproduces numerically.** The one exception is incorrect-trace classification accuracy (26.5 vs 21.6).
- **SFT w/ incorrect traces does not reproduce.**
  - Qwen3-1.7B: 56.7 vs 63.9 accuracy. Incorrect still beats correct (51.7), but no longer beats Vanilla (59.1).
  - Llama-3.2-1B: 37.2 vs 45.6, which is *below* both correct-trace (39.3) and Vanilla (43.7). The paper's ranking flips.
  - So "SFT with incorrect traces yields the highest final-solution scores for both models" (§5.1) does not hold: Vanilla is best for both models.
  - The weaker claim, that incorrect traces "don't necessarily degrade accuracy", holds only for Qwen.
  - The seed-42 runs (what the released scripts actually do) show the same pattern.
- **Trace-correctness claims reproduce.** Correct-trace models get much higher classification-step accuracy than incorrect-trace models (Qwen 46.0 vs 20.0; Llama 39.8 vs 20.7; paper 47.1/20.4 and 39.1/18.8). There are many "correct answer, wrong trace" cases.
- **The released IR-step metric has a bug.** It counts *any* context fact as a gold fact, so the incorrect-trace IR accuracy is inflated: 64–75% as released vs 12–14% with the evident intent. The paper's numbers (56.9 / 73.6) match the buggy metric.
- **Fig. 3 (own pipeline, seed 42):**
  - SFT w/ R1 traces gives the highest accuracy for both small models (Llama 62.8, Qwen 70.5; paper ≈69 / ≈71), so the main claim holds.
  - Summary and explanation runs score below the paper's values. Llama: summaries 45.1 (≈51.5), explanations 48.8 (≈53). Qwen: summaries 56.9 (≈68.5), explanations 63.4 (≈67).
  - The released "correct traces on the R1 subset" dataset is corrupted (messages misaligned with questions, heavy duplication), so that bar can't be compared.
- **Table 3 (own inference/eval code):**
  - Llama-1B on MARCO matches well: vanilla 30.4 vs 33.4, correct 32.6 vs 33.7, incorrect 28.3 vs 28.9. Correct traces lead, as in the paper.
  - Llama-1B on bAbI: vanilla matches (97.1 vs 96.5) and is best, as in the paper. Correct and incorrect differ: 84.3 vs 94.4 and 92.6 vs 86.2.
  - Qwen does not match. MARCO vanilla gives 28.1 vs the paper's 3.4, and Qwen's per-dataset rankings differ from the paper's.
  - The trace metrics use definitions I had to choose and differ a lot from the paper's.

## Discrepancies

1. **code_vs_paper (major, affects results). `cotempqa_trace_eval.get_gold_facts` and the copy in `cotempqa_confusion_matrix.py`.**
   - The function literal-evals the `facts` column twice: `answers = ast.literal_eval(gold_facts_text)`. The `answer` column is never used, so *every context fact* counts as a gold fact.
   - "IR step accuracy" therefore measures "the trace quotes any fact from the context", not "the trace retrieves the relevant fact" (§3.1, §4.2).
   - The paper's Table 2 IR numbers match this buggy metric. For example, Llama incorrect-trace: paper 73.6, released metric 74.9, corrected 14.2.
   - So the reported IR accuracy of incorrect-trace models (56.9 / 73.6) is an artifact; with the intended metric it is about 12–14%. The qualitative claim (correct > incorrect) is unaffected, and in fact stronger.
2. **code_vs_paper (minor). `scripts/bash_scripts/cotempqa_sft_{vanilla,reasoning_facts,reasoning_facts_perturbed}.sh`.** The line `--wandb_token $wandb_token` has no trailing `\`, so `--seed "$SEED"` runs as a separate (failing) command and every run trains with the default seed 42. The trace-eval script names adapters `-121/-122/-123`, implying three seeds, but the released scripts would produce three identical-seed runs.
3. **code_vs_paper (minor). `cotempqa_sft_vanilla.py`.** `warmup_ratio=0.03`, while §4.4 says 0.1 warm-up (the trace scripts use 0.1).
4. **paper_internal. §4.2 vs Table 2 header.** §4.2 defines average trace length as "# of words in the intermediate trace", while the Table 2/3 headers say "# tokens". The code counts whitespace words.

Data/release issues (no effect on our Table 2/4 numbers):
- `data/cotempqa/sft_dataset_reasoning_facts_perturbed_chat_template/*.csv` and `README.md` are committed with unresolved git merge-conflict markers. The training scripts load the HF copies, which equal the HEAD side of the conflict.
- HF `sbhambr1/cotempqa_for_sft_r1_set_custom_traces` (Fig. 3, "correct traces" on the R1 subset) is misaligned and duplicated:
  - Its `messages` agree with its `question` column for only 25% (test) / 27% (train) of rows.
  - Only 420 of 742 test conversations and 995 of 2968 train conversations are unique.
- The README refers to non-existent `inference.py` / `create_sft_dataset.py`.

## Why not fully reproduced

- **Incorrect-trace SFT is weaker than reported** for the small models: Qwen −7 points, Llama-1B −8 points. Changing the seed doesn't close the gap (3 seeds plus seed 42, std < 1). I found no code or config difference that explains it; the HF perturbed data equals the repo data.
  - With the released code, the paper's headline ordering (incorrect traces ≥ correct traces and Vanilla) holds only partially: incorrect > correct for Qwen, but not for Llama-1B.
  - Llama-3.1-8B matches the paper, and there the paper itself reports incorrect < correct.
- **Missing pipelines.** Table 3 and Fig. 3 have data on HF but no inference or evaluation code. Our numbers come from pipelines I wrote, and for Table 3 from metrics I had to guess.
- **Human-subject study** (Table 5, abstract's 3.39 / 4.59 ratings): not reproducible computationally.
- **Not run:** Fig. 3 for Qwen3-8B / Llama-3.1-8B (time budget).
