# Reproduction report: Self-SoftCoT (ACL 2026, 2026.acl-long.1496)

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes / as released): MIXED / MIXED.** No released source file was edited, so the two are the same.
- **Coverage: SUBSET.** Config B on both backbones, all 5 datasets, 5 eval seeds. Config A was not run; the cited baselines were not re-run.
- **Codebase completeness: MINOR_FIXES.** Only environment, data-unzip and path fixes were needed. To fit the compute budget I wrote faster vLLM-based re-implementations of the train and eval loops; they reuse the released functions.
- Code: https://github.com/haha34342/Self-SoftCoT-Code (linked from the paper), cloned to `./codebase`.

## Summary

- **Qwen2.5-7B-Instruct (Table 1).** Config B reproduces on all 5 datasets, each within about 2 points. The average is **77.56 vs 78.42** in the paper, so the method beats the cited SoftCoT average (75.06) and the N=0 baseline (72.06).
- **LLaMA-3.1-8B-Instruct (Table 2), default training seed 42.**
  - GSM8K (82.62 vs 82.91) and AQuA (62.05 vs 63.31) reproduce.
  - **StrategyQA collapses:** 36.0 vs 69.3. With the released training script, unmodified, outputs degenerate into repeated role headers and very long text.
  - ASDiv-Aug shows no gain over N=0: 86.9 vs 92.35.
  - The **GSM8K→DU transfer fails:** 40.3 vs 64.9.
  - Average: 61.6 vs 74.55.
- **LLaMA with training seed 43** (my vLLM driver, otherwise identical recipe): StrategyQA **69.1** and ASDiv-Aug **93.5** match the paper, GSM8K gives 82.4, and DU transfer is still only 54.0.
- **Conclusion.** The recipe can hit the paper's numbers, but on LLaMA it is very sensitive to the training seed. The paper reports only eval-seed std from a single training run. The DU result for LLaMA could not be reproduced with either seed.
- **A real bug in the released training reward for StrategyQA:** substring matching treats "no" inside "not"/"know" as answering "No". It speeds up the LLaMA degeneration: the step-10 checkpoint scores 35.2 with the released reward vs 65.7 with a word-boundary reward.

## What I ran

### Environment
- One conda env at `./env`: Python 3.11, torch 2.7.0, transformers 4.51.3, fastNLP 0.7.0, vLLM 0.9.2, accelerate 1.6.0, setuptools<70.
- The paper pins transformers 4.51.0; 4.51.3 was needed for the vLLM 0.9.2 install.

### Models and data
- Models: `Qwen/Qwen2.5-7B-Instruct` and `meta-llama/Meta-Llama-3.1-8B-Instruct`, from the shared HF cache.
- Data: the repo's `buffer/data.zip`, unzipped. Split sizes match Table 6 exactly: GSM8K 7000/150/1319, ASDiv-Aug 4000/150/1038, AQuA 97467/254/254, StrategyQA 1603/229/458, DU 250.

### Training (Config B, paper App. D.3.2 / README commands)
Settings: `--num_thought_tokens 2 --group_size 5 --episodes_per_round 16 --update_epochs 3 --train_steps 150 --save_every 10 --beta_kl 0.01`, with:
- lr 1e-5 for Qwen, 5e-6 for LLaMA;
- `--max_data_epochs 1` for GSM8K and ASDiv-Aug, 0 for AQuA and StrategyQA;
- seed 42 (the default).

Two implementations were used:
- **Released script, unmodified:** `codebase/buffer/train_gspo_buffer_multitask.py` for StrategyQA on both backbones (wrapper: `repro_scripts/hf_train.sh`).
- **`repro_scripts/train_vllm.py`** for GSM8K, ASDiv-Aug and AQuA. It has the same algorithm and imports the released functions (`build_prompt_embeddings_indep`, `get_logprobs`, `extract_answer`, `compute_reward`). Rollouts from π_old are sampled with vLLM from the same HF-computed prompt embeddings; the backbone is frozen, so this is the same policy. Old log-probs are still recomputed with the HF model exactly as in the release.
  - Why: the released loop does one HF `generate` per question, which costs 1–10 min per step.
  - Check: sampling statistics match HF `generate` on the same prompts (reward 0.50 vs 0.53, similar length and log-prob/token).
  - Check: for Qwen StrategyQA, the released script gives 66.20 and this driver with seed 43 gives 67.51.

Training details:
- GSM8K and ASDiv-Aug stop early on the 1-epoch data budget, as the released code does. Qwen stopped at 80 and 35 steps, LLaMA at 117 and 46.
- DU has no training split. Config B DU uses the GSM8K-trained projection: zero-shot transfer, as stated in the Table 9 caption.

### Evaluation
- Harness: `repro_scripts/vllm_eval.py` with seeds 41–45 on the test splits. It is a re-implementation of `evaluate_unified.py` that keeps the same:
  - prompts, soft-thought projection and GT parsing;
  - extraction functions (imported from the release);
  - sampling settings: temperature 1.0, top_p 1.0, and the model generation_config's top_k / repetition_penalty, as the released eval inherits them; 1024 new tokens; eos = tokenizer eos.

### Not reproduced / not comparable

  - holds for Qwen (77.56 > 75.06);
  - fails for LLaMA seed 42 (61.59 < 70.52).
- **Tables 9–12** (MATH-500/Gaokao transfer, latency, Qwen3, DPO/KTO/GRPO ablations) were not attempted.

## Why it is not fully reproduced
1. **LLaMA training instability.** With the released default seed, LLaMA StrategyQA degenerates and ASDiv-Aug shows no gain. A second training seed matches the paper. The paper gives no training-seed variance.
2. **StrategyQA reward bug.** The released training reward bug accelerates the LLaMA StrategyQA degeneration.
3. **LLaMA DU.** The GSM8K→DU transfer gives 40.3 (seed 42) and 54.0 (seed 43) vs 64.88, below the N=0 baseline. The paper does not say how the LLaMA DU number was obtained. The code's DU "train" split is the test file.
4. **Scope.** Config A and the cited baselines were not run (compute / not released).

## Discrepancies
1. **code_vs_paper (major)** — `train_gspo_buffer_multitask.py::extract_answer_boolean`.
   - Paper: binary reward = final-answer correctness.
   - Code: compares `rfind('yes')` with `rfind('no')` without word boundaries, so "Yes, but I do not know." is scored as "No".
   - Impact: affects LLaMA StrategyQA training (step-10 accuracy 35.2 with the released reward vs 65.7 with a word-boundary reward).
2. **code_vs_paper (minor)** — gradient clipping.
   - Paper: Table 8 lists gradient clipping 1.0.
   - Code: applies no clipping (the README says the main results don't use it).
3. **code_vs_paper (minor)** — DU prompt.
   - Paper: "six options".
   - Code: "five options: A, B, C, D, E, and F".
4. **code_vs_paper (minor)** — chat template.
   - Prompts use the chat template without `add_generation_prompt`, so the model generates its own role header. The paper doesn't mention this, and it shows up in the degenerate LLaMA outputs.
5. **code_vs_paper (minor)** — DU splits.
   - `DULoader` uses the DU test file as its train and dev splits too. The paper says DU has no train split and, for Qwen, uses GSM8K transfer.
   - How the LLaMA DU number in Table 2 was produced is unspecified.
6. **code_vs_paper (minor)** — math answer extraction.
   - Training takes the `\boxed{}` content first; evaluation takes the last number in the text.
