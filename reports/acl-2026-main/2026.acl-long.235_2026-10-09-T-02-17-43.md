## What the paper claims (target)
RACE builds an RST logic graph over EDU-level RoBERTa features and runs a 2-layer RGCN with basis decomposition, root pooling and a joint SupCon+CE loss. It is evaluated on a 4-class re-split of HART (11,200 / 1,600 / 3,200). Table 2 reports RACE at **AUROC 97.99±0.13** and **average TPR@1%FPR 83.06±0.57** (3 seeds), above the best baseline CoCo (79.70). Table 3 gives ablations.

## What I did
1. Cloned https://github.com/ICTMCG/RACE into `./codebase` and read the paper (`paper/paper.txt`).
2. Downloaded the authors' Google Drive folder linked in the README (`gdrive/RACE_data-and-model`). It contains:
   - the exact train/val/test split used in the paper, with pre-parsed IsaNLP RST trees (11,200 / 1,600 / 3,200; it matches Table 7);
   - one checkpoint (seed 3407) with its test predictions and metrics.

   I symlinked it as `codebase/data/hart_split`.
3. Environment: conda env at `./env` with Python 3.11, torch 2.5.1+cu124, torch_geometric 2.8.0, transformers 4.46.3, and scikit-learn and the other packages from requirements.txt.
   - `isanlp_rst` was not installed. The RST parsing and HART preprocessing steps (`prepare_data.sh`) were not re-run, because the authors' pre-parsed split was used.
4. Config `scripts/RACE_hf.json` is `codebase/configs/RACE.json` with one change: `backbone_model_path` is set to `FacebookAI/roberta-base`. The repo's value, `Facebook-AI/roberta-base`, is not a valid HF id. All hyperparameters match the paper: 20 epochs, batch size 16, lr 2.9e-5, linear warmup 0.1, last layer unfrozen, feat 128, hidden 512, L=2, 10 bases, τ=0.07, model selection on best val macro-F1.
5. Released checkpoint evaluation:
   `cd codebase; python test.py --config ../scripts/RACE_hf.json --checkpoint_path ../runs/released_ckpt_eval/best_model.pth`
6. Training. Each seed was run as its own process, three in parallel on one H200:
   `cd codebase; env -u SLURM_PROCID bash scripts/run_multiple_seeds.sh ../scripts/RACE_hf.json "<seed>," 0`
   - Seeds: 3407, 42 and 2025. 3407 is the seed of the released checkpoint; 42 and 2025 come from the README's example list. Seeds 0 and 1 were added as extras.
   - Ablations used the same command with `scripts/RACE_woCL.json` (`loss.use_supcon=false`), `scripts/RACE_woRelation.json` (`graph.gnn_layer_type=GCN`) and `scripts/RACE_woBasis.json` (`graph.rgcn_num_bases=null`), with seeds 3407, 42 and 2025.
7. Aggregation:
   - `scripts/aggregate.py` reads every run's `test_metrics.json`, which `train.py` writes itself (the "as released" numbers).
   - It also recomputes the metrics from the saved logits with a single softmax, the way `test.py` does (see the discrepancy below).
   - Output is in `runs/aggregate.txt` and `runs/all_results.json`. Logs are in `runs/logs/`. Per-run outputs and checkpoints are in `codebase/results/multi_seed_runs/`.

Settings that differ from the paper:
- Hardware: an H200 shared with other jobs, instead of an RTX 4090.
- Seeds: the paper's other two seeds are not stated, so I used 3407/42/2025.
- Nothing else differs.

## Codebase completeness: MINOR_FIXES
I made no changes to the source code. `git status` in `./codebase` shows only untracked items: the data symlink, `results/` and `__pycache__`. The workarounds were:
1. **`configs/RACE.json`:** `backbone_model_path` "Facebook-AI/roberta-base" is not a valid HF repo id. I set it to "FacebookAI/roberta-base" in my copy of the config.
   - `test.py` takes the backbone path from the checkpoint (`/data/liyang/MODELS/roberta-base`). That is overridden by the `graph.backbone_model_path` key in the test config, so this is also a config-only fix.
2. **`utils/misc.py: init_distributed_mode`:** if `SLURM_PROCID` is set, it assumes srun-distributed mode and crashes with `KeyError: SLURM_NPROCS` inside a plain Slurm allocation. I worked around it by launching with `env -u SLURM_PROCID`.
3. **`scripts/run_multiple_seeds.sh`:**
   - Its usage text says the GPU id is optional, but the script requires exactly 3 arguments.
   - A single seed argument (e.g. `3407`) is interpreted as "run 3407 random seeds". I passed `"3407,"` instead. My first launch started that runaway loop, and I killed only my own process group.
4. **Data:** I downloaded the authors' processed split and checkpoint from the Google Drive folder linked in the README. `isanlp_rst` was not needed.
5. **Missing from the release:**
   - code for all 12 baselines;
   - switches for the w/o RGCN and w/o Bottleneck ablations;
   - the DMRST variant, and the OOD and group-aware split experiments.

   Scripts I wrote outside the codebase, all in `scripts/`: `metrics_from_preds.py` and `aggregate.py` (metric aggregation and recomputation), `progress.sh` and `queue_ablation.sh` (job runners), and the 4 config JSONs.

## Discrepancies
1. **code_vs_paper (metric computation; affects reported AUROC):**
   - In `train.py: evaluate()`, `compute_classification_metrics` is passed `softmax(logits)`, but that function applies softmax again. So AUROC and TPR are computed on softmax(softmax(logits)), not on the predicted probabilities defined in Appendix A.2.
   - `test.py` passes logits, so it applies softmax once.
   - Effect: AUROC drops by about 1 point (ours 97.56 vs 98.60; released checkpoint 98.03 vs 98.79). TPR@1%FPR moves by less than 0.5.
   - The paper's AUROC of 97.99 is consistent with the double-softmax path. Its ablation AUROCs are therefore also likely computed this way.
2. **paper_internal:**
   - Section 4.1 says train/val/test is split "at the 70:20:10 ratio".
   - Table 7 (and the released split) is 11,200 / 1,600 / 3,200, i.e. 70:10:20.
3. **code_vs_paper (minor):** the shipped config's backbone id "Facebook-AI/roberta-base" differs from the paper's FacebookAI/roberta-base. The model is the same; only the HF id is wrong.
