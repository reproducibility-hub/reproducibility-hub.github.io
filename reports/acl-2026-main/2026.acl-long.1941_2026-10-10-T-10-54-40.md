## 1. What the paper claims and what we targeted

Main claims: (i) VLMs copy an overstated count from a "Describe the N+k [objects]" prompt (PIH), especially for N ≥ 5 (Fig. 2); (ii) mean-ablating a small, model-specific set of attention heads ("PIH heads": 3 for Qwen2-VL-7B, 10 for LLaVA-OneVision-7B and Janus-Pro-7B) cuts prompt copying to <11% and raises true-count answers to 70–78% without hurting baseline counting (Table 1); random heads from the same layers do not (Table 1); (iii) the same heads cut colour-prompt PIH by 40–95% (Table 4); (iv) PIH heads sit in early layers and overlap between Qwen-VL and LLaVA-OV (Tables 3/9); (v) ablation changes answer format (Table 6).

We ran: Table 1 (all rows, all 3 models), Table 4 (PIH / no-PIH totals; the fine-grained split only as a reconstruction), Table 6, Table 8 / Figure 2 (baseline curves), and the single-head sweep behind Tables 3/9 for all 3 models. Not run: Table 2 (CalTech101 / MM-Vet / POPE — no code in the release, MM-Vet needs a GPT-4 judge) and Figures 3–5, 7–10 (attention-mass / attention-map / probability scripts are incompatible with the released utilities, see §5).

All commands run from `./codebase` with `../env/bin/python`.

   `python ../scripts/build_counting_dataset.py` → `counting_with_prompts.csv`, `countbench_images/` (491 images, same filtering as the notebook; object names from Qwen2-VL-7B-Instruct with the *identical* GPT-4o instruction + caption).
2. Baselines (released script): `python 2_evaluate_vlms.py --model_version {qwen,llava-one,janus} --dataset_size full --task {count,color}`.

### Settings that differ from the paper
- **Object names in all counting prompts** come from Qwen2-VL-7B instead of GPT-4o (dataset not released). Several names are singular or wrong ("dining table", "nest", "suit", "cpu"), which lowers baseline exact match (e.g. "There is one CPU in the image").
- Prompts / generation exactly as in the released code (which itself differs slightly from the paper text: "in this image", 50 new tokens, LLaVA-OV in 4-bit NF4, colour task restricted to 160 images; see Discrepancies).
- Random-head control: not released; we draw one other head from the same layer for every PIH head (seed 0 for all models; seeds 1, 2 additionally for Qwen).
- Sweep sample set: not specified/released; we use one PIH case per base-correct image (smallest k∈1..5 whose answer equals N+k): 251 (Qwen), 304 (Janus), 251 (LLaVA-OV) samples vs. ~383/372/298 implied by the paper's Table 9 percentages.
- Sweep implementation: batched (one ablated head per batch element) with per-row early stopping after the first number; verified identical to the released per-head loop (identical texts for 4 heads; identical extracted numbers on 2,352 rows).

## 4. Why not fully reproduced
1. **Data:** the counting prompts depend on GPT-4o object names that are not released; we had to substitute an open annotator (no OpenAI key). This plausibly explains the 5–9 point lower baseline exact match and the higher true-count rates.
2. **Missing code:** the random-head control, the baseline-prompt ablation, the Table 1/4/6 aggregation and the Table 4 copy taxonomy are not in the release; our versions follow the paper's descriptions but are not guaranteed to be the authors'.
3. **Sweep protocol unspecified:** Table 9's sample set is not described precisely; ours is a reconstruction, so success percentages are not directly comparable.
4. **Not run:** Table 2 (no code; MM-Vet needs a closed GPT-4 judge) and Figures 3–5, 7–10 (scripts incompatible with the released utilities).
