**Summary.**
- **The authors' checkpoint reproduces Table 1 (Qwen3-4B).** The GitHub repo has no data, no checkpoints and no data-processing scripts. On the first author's Hugging Face account (not linked from the paper or repo) I found the processed test sets (`Twwilght/{NQ,MQA,HQA,NEWS}`, whose sizes match App. E) and a checkpoint, `Twwilght/GMSA-Qwen3-4B`.
  - The checkpoint does **not** load into the released code: different module names, 16 vs 8 encoder layers, LoRA on q/v vs all-linear, a different vocab size, and the loader uses `strict=False`. I converted it.
  - The converted checkpoint reproduces the Qwen3-4B GMSA rows of Table 1 closely on NQ, 2WikiMQA and HotpotQA, and on the AVG columns (EM-avg 47.42 vs 45.35, F1-avg 51.35 vs 49.89 at 4x; 38.07 vs 38.62 and 44.48 vs 44.77 at 8x).
  - MultiNews comes out ~9 F1 lower (27.4 vs 36.3) because the code hard-codes `max_new_tokens=100`. With 300 new tokens (diagnostic, 300 samples) it gives 35.3 / 33.1 vs the paper's 36.26 / 33.94.
- **Retraining is weaker.** I retrained GMSA end to end with the released training code at the paper's hyperparameters: PwC autoencoding for one full epoch, then fine-tuning for one epoch on a mixture I rebuilt from public data (the paper's training mixture is not released).
  - On 2WikiMQA and HotpotQA, whose training data matches the test format, the retrained model is 1–5 points below the paper.
  - On NaturalQuestions it is ~27–33 points below (containment-acc 33.6 vs 60.38 at 4x). The authors' 20-document NQ training set (75,322 samples) is not released and I had to substitute a BM25-negatives version.
  - Retraining the autoencoder alone (public PwC) gives strong reconstruction at 4x: ROUGE-L 0.98 and BERTScore 0.99 at L=512.
- **Baseline claims not checked.** The release has no code for any baseline, so claims of the form "GMSA beats X" could not be checked (`NOT_COMPARABLE`).

## What I did

1. Read the paper. The main claim is Table 1: GMSA beats hard and soft compression baselines on NQ, 2WikiMQA, HotpotQA, NarrativeQA and MultiNews at 4x and 8x, for LLaMA-3.2-3B and Qwen3-4B. Fig. 3 / Table 5 cover PwC reconstruction, and Table 3 the ablations.
2. Cloned https://github.com/Twilightaaa/GMSA into `./codebase`. It contains the model (`modeling_gmsa.py`), AE training (`autoencoding.py`), fine-tuning (`instruction_finetune.py`), QA inference with EM/F1 (`ft_inference.py`, `eval_utils.py`) and launchers (`gmsa_all.sh`, `test.sh`).
3. Created the env `./env` (python 3.10, torch 2.4.0+cu121, transformers 5.1.0, datasets 4.3.0, peft 0.13.0, deepspeed 0.18.7, accelerate 1.13.0, following the README), plus `cuda-toolkit 12.1` (needed for DeepSpeed), `rouge-score`, `nltk` and `bert-score`.
4. **Data.**
   - Downloaded the authors' test sets from HF `Twwilght/{NQ,MQA,HQA,NEWS}` (2,655 / 12,576 / 7,345 / 5,615 rows). These match the counts in App. E; MultiNews has 5,615 rows vs 5,622 in the paper.
   - They are in `{question, ctxs, answers}` format, not the code's `{input, prompt, answer}`. I converted them with `scripts/convert_ctxs.py`, using the context assembly and prompt template from the authors' sibling repo RAM (`data_utils.prepare_nq_example`): `"\n".join(f"{title} {text}")` and `"Question:{q}\nAnswer:"`. A raw-question prompt gives ~0 EM, which confirms the template.
   - NarrativeQA test is not released. I rebuilt it with `scripts/build_narrativeqa.py` from `deepmind/narrativeqa`, keeping stories ≤32K Qwen3 tokens as App. E describes: 1,093 questions over 37 stories.
5. **Released checkpoint (`Twwilght/GMSA-Qwen3-4B`).**
   - Converted it with `scripts/convert_released_ckpt.py`: renamed `llm_encoder.` to `encoder.` and `llm.` to `decoder.`, and padded the vocab rows 151,670 → 151,936 from the base model. The extra rows are never produced by the tokenizer; the extra row 151,669 is identical to the base model in the encoder.
   - Verified an exact key match with `scripts/check_keys.py`, for encoder_layers=16 and LoRA r=128 on `q_proj,v_proj`.
   - LoRA alpha is not stored in the checkpoint. A 100-sample NQ probe (4x) gave EM 16 / 22 / 44 / 52 / 51 for alpha 16 / 32 / 64 / 128 / 256, so I used alpha = 128 (= r, scale 1).
   - Then ran the unmodified `ft_inference.py` on all test sets at merge sizes 4 and 8, batch 1, `model_max_length` 28000 as in `test.sh`, via `scripts/eval_stream.sh`.
6. **Retraining with the released code**, using the launcher's options with the paper's §5.1 hyperparameters (`scripts/train_stage.sh`). The code defaults are kept: encoder_layers 8, LoRA all-linear r128/α32, a 1-layer LSA.
   - AE: PwC train (241,564 rows), merge sizes {4,8} sampled per batch, lr 1e-4, batch 32 (8×GA4), 1 epoch = 7,549 steps, DeepSpeed ZeRO-2 + CPU offload (`ds_config.json`). Took 5.9 h on 1×H200; final loss 0.07.
   - FT: rebuilt mixture of 83,574 samples (`scripts/build_train_mix.py`): 20k each from HotpotQA-distractor train, 2WikiMQA train, MultiNews train and NQ (Tevatron/wikipedia-nq: 1 positive + 19 BM25 negatives), plus all 3,574 NarrativeQA train questions with stories ≤32K. lr 1e-5, batch 32 (1×GA32), 1 epoch = 2,611 steps. ZeRO-2 without optimizer offload, with `torch_adam` (see the codebase notes). Took 10.2 h; final loss 0.84.
   - Evaluated the result with the same `ft_inference.py` pipeline (`results/retrained/`).
7. **Reconstruction (Fig. 3 / Table 5 metrics).** The evaluation script is missing from the release, so I wrote `scripts/recon_eval.py`. For each of 100 unique PwC test contexts per length, it truncates to L ∈ {128, 256, 512} tokens, compresses, prompts with "Restate the aforementioned Text." (the AE instruction), and decodes greedily. It scores BLEU, PrefixEM (longest correct token prefix / L), ROUGE-1/2/L and BERTScore-F1. I ran it on the retrained AE.
8. **MultiNews generation-length diagnostic.** `scripts/ft_inference_maxnew.py` runs the unchanged `ft_inference.py` but overrides the hard-coded `max_new_tokens=100` with 300, on the first 300 MultiNews test samples.

Settings that differ from the paper:
- Only the Qwen3-4B-Instruct-2507 backbone. No LLaMA checkpoint was released, and there was no time to retrain a second backbone.
- The retraining used the released code's architecture defaults (8-layer encoder, LoRA all-linear α32). The released checkpoint was evidently trained with a 16-layer encoder and LoRA on q/v (α≈128). The paper implies the full LLM as encoder.
- 1×H200 instead of 8×H20 / 64×H100. Global batch 32 was preserved, but via different micro-batch and gradient-accumulation settings.
- Reconstruction is evaluated on 100 contexts per length, not the full PwC test set.

## Why it is not fully reproduced
- **Missing data.** The paper's training data is not released:
  - The 20-document NQ training set (75,322 samples) is not publicly available in that form. I substituted Tevatron NQ with BM25 negatives.
  - The 20k-per-dataset fine-tuning mixture is not released.
  - The NarrativeQA test set is not released.
  - No data-processing scripts or prompt templates are included.
- **Unlinked checkpoint, incompatible with the code.** The checkpoint that reproduces the numbers is not linked from the repo or paper. It does not match the released code (different architecture defaults and LoRA layout), and its LoRA α had to be inferred.
- **Retraining is weaker.** Retraining with the released code and rebuilt data comes out weaker, dramatically so on NQ (−27 points), and averages ~6 points below the paper.
- **MultiNews.** The code's fixed 100-token generation cannot reproduce the paper's MultiNews F1.
- **Compute.** With 48 h on 1 GPU I could cover only one backbone. Baselines, ablations and latency have no released code.

## Codebase completeness: MISSING_DATA (PARTIAL_DATA)

Changes to released code (left uncommitted in `./codebase`):
- `modeling_gmsa.py`, `autoencoding.py`, `instruction_finetune.py`, `ft_inference.py`: added a `--lora_target_modules` argument. Its default, `all-linear`, keeps the original behaviour; I added it so the released checkpoint's q/v LoRA layout could be built. The retraining used the default.

Scripts written outside the codebase (`./scripts`):
- `convert_ctxs.py`: authors' HF test format → code JSONL format, using the RAM prompt template.
- `build_narrativeqa.py`: NarrativeQA test and train sets, filtered to ≤32K tokens.
- `build_train_mix.py`: the fine-tuning mixture.
- `convert_released_ckpt.py` (plus a vocab-padding step) and `check_keys.py`: converting and checking the released checkpoint.
- `eval_stream.sh`, `probe.sh`: runners for `ft_inference.py`.
- `train_stage.sh`: per-stage version of `gmsa_all.sh`. The released launcher feeds the same `TRAIN_FILE` to both stages, and its defaults (merge 16/32, not random, 5k/10k steps, batch 2) differ from the paper.
- `recon_eval.py`, `recon_run.sh`: reconstruction metrics, which are missing from the release.
- `ft_inference_maxnew.py`, `news_diag*.sh`: MultiNews generation-length diagnostic.
- `rescore.py`, `aggregate.py`, `make_status.py`: scoring and aggregation.

Environment and config adjustments:
- Installed `cuda-toolkit 12.1` into the env so DeepSpeed can import (`CUDA_HOME`).
- FT used `scripts/ds_config_nooffload.json`: the released `ds_config.json` without CPU optimizer offload, plus `torch_adam: true`. With offload, the job hit the 113 GB host-RAM limit (SIGKILL). Without offload, DeepSpeed's `fused_adam` JIT-compile fails because the system gcc is newer than 12.
- `WANDB_MODE=offline`: the scripts call `wandb.init` unconditionally.

Other issues found:
- `GMSA._load_checkpoint` uses `load_state_dict(strict=False)`. Loading the released HF checkpoint therefore silently ignores all encoder and decoder weights (the key names differ). After renaming, it fails on the vocab-size mismatch.
- The checkpoint's LoRA α is not recoverable. The code default α=32 gives about half the accuracy of α=128.
- Batched inference (`eval_batch_size` > 1) would leave padding between the memory tokens and the prompt without adjusting position ids. I used batch 1, the `test.sh` default.
- Missing from the release:
  - baselines;
  - the ICAE-AE reconstruction baseline;
  - the "w/o Group Merging" (appended learnable tokens) and "Rand. init. LSA" ablations;
  - latency scripts;
  - the reconstruction evaluation.
