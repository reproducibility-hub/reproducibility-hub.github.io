- Checkpoints: HF `iLearn-Lab/ACL26-TEMA` (`TEMA_mfashioniq.pt`, `TEMA_mcirr.pt`).
- **Not released:** the Parsing-Assistant (PA) summaries and the code that generates them (the LLM summarizer and the Consistency Detector, which use gpt-3.5-turbo). Training needs them.

### A. Released checkpoints (main result)
`eval_tema.py` (my script) loads BlipCir-base, loads the checkpoint (strict: no missing or unexpected keys), and calls the repo's own `test.test` and `test.test_mcirr_valset`:
```
env/bin/python eval_tema.py --dataset mfashioniq --ckpt ckpt/TEMA_mfashioniq.pt --q 1 --out results/mfiq_q1.json
env/bin/python eval_tema.py --dataset mcirr      --ckpt ckpt/TEMA_mcirr.pt      --q 1 --out results/mcirr_q1.json
```
Things to know about this evaluation:
- **Evaluation protocol:** it is the repo's own. For M-FashionIQ the gallery is the set of images that appear in the val queries, the reference image is excluded, and there is one MMT per triplet. For M-CIRR it is the full val gallery plus the subset metrics.
- **q (number of learnable queries):** the paper says N=3, but the code's default is q=1 and the checkpoints don't store q. Evaluating with q=3 collapses the results (M-FashionIQ Avg R@10 36.6, M-CIRR Avg 64.6; see `results/*_q3.json`). So the released checkpoints were trained with **q=1**.
- **The "learnable queries" are never learned.** `nn.Parameter(torch.zeros(...)).cuda()` makes them plain zero tensors, so they are not registered, not optimized and not saved. With q=1 the orthogonal-regularization loss is identically 0.

### B. Retraining (supplementary)
1. `gen_summaries.py` produces the PA summaries. It uses the paper's summarizer prompt and the Consistency-Detector prompt from Fig. 3, with up to 3 refinement rounds. **Qwen2.5-7B-Instruct replaces gpt-3.5-turbo** because no OpenAI key is available; the paper's Table 6 shows the choice of LLM changes results by only about ±1–2 points. Summaries that still failed the detector after the last round (kept their final attempt): 56, 65 and 67 of about 6k per FashionIQ category, and 1,273 of 28,225 for CIRR.
2. The training commands, with the paper's hyper-parameters (lr 2e-5, batch 64, κ=0.6, μ=0.2 as in Eqn 8, 10 epochs, q=1 as in the released ckpts):
```
cd codebase
../env/bin/python train.py --dataset mfashioniq --mfashioniq_path ../data/M-FashionIQ-train/ --lr 2e-5 --batch_size 64 --num_epochs 10 --model_dir ../experiments/mfiq_retrain
../env/bin/python train.py --dataset mcirr --mcirr_path ../data/M-CIRR-train/ --lr 2e-5 --batch_size 64 --num_epochs 10 --model_dir ../experiments/mcirr_retrain
```
3. The best epoch is picked on val, which is what `train.py` does and what the paper implies, since it reports val results and has no separate test labels. M-FashionIQ best epoch: 6 of 10. M-CIRR best epoch: 9 of 10. Last-epoch numbers are within about 0.6 points of the best (see logs).

## Codebase completeness: MISSING_SCRIPTS
The model code and training loop exist, and evaluating the checkpoints needs only minor fixes. But the PA summarization pipeline (the LLM summarizer and Consistency Detector) and its outputs are missing, so training crashes as released. There is also no evaluation or inference entry point. The released model code also differs from the paper:
- The summary is not fed to the textual entity-mapping transformer (the Eq. 3 line is commented out).
- The learnable queries are not learnable (zero tensors).
- q defaults to 1, while the paper says N=3.
- Losses are summed without the κ/μ weights.
- The reference-image branch sees an extra global token during training but not at inference.

Changes to the released code (left uncommitted in `codebase/`; see `git diff`):
1. `lavis/models/__init__.py`: commented out the import of `lavis.models.blip2_models.blip2_cir`, a module that is not in the release (import error).
2. `lavis/models/blip_models/blip.py` and `lavis/models/blip2_models/blip2.py`: replaced the hard-coded `/root/bert-base-uncased` with `bert-base-uncased` from the HF hub.
3. `lavis/models/blip_models/blip_cir.py`: uncommented `summ = samples["summ"]`. Without it, `forward` hits a NameError because `summ` is used but never defined. Needed for training only.
4. `datasets.py`: `M_FashionIQ` and `M_CIRR` now read the optional `*.mmt.summ.json` and return `out['summ']`. Needed for training only.
5. `train.py`:
   - passes `summ` to the model;
   - weights the losses as in Eqn 8, using new args `--kappa` (0.6) and `--mu` (0.2); the original summed them without weights;
   - removes `os.environ["CUDA_VISIBLE_DEVICES"]='1'`, which would override Slurm's GPU assignment.
