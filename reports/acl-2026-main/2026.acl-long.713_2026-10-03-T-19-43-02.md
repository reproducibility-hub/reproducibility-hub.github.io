## Summary
- The released code (https://github.com/cvzh/BiMind) implements BiMind-LLaMA: a frozen Llama-2-7B, a POS adapter, kNN/FiLM knowledge injection, a dual head, gate/agree-head/logit-avg/PoE fusion, and a sym-KL regulariser. `main.py` runs end-to-end on ReCOVery with no source edits. The only change was a config value: `LLM_NAME` now points to the ungated `NousResearch/Llama-2-7b-hf` mirror, because our access request for meta-llama is still pending. Seed 0 gives fused Acc **95.07%**.
- **Table 1 (main result), BiMind:**
  - ReCOVery, 10 seeds: we get **95.3 ± 1.6 Acc / 95.3 F1**; the paper reports 91.8 ± 1.3 / 91.9.
  - LIAR, 10 seeds: we get **65.2 ± 2.6** with the split re-drawn for each seed, or **61.9 ± 1.4** with a fixed split; the paper reports 63.3 ± 0.1.
  - Both datasets are outside the paper's std but within about 4% relative. Our numbers are well above every baseline the paper reports (best: HeteroSGT 72.7 / 58.1). The baselines themselves are not released, so "beats baselines" is NOT_COMPARABLE as a reproduced claim.
- **Table 3 ablations (ReCOVery):** the full model is best on average against every ablation, so the direction matches. But the gaps are only 0.3–0.9 points, against the paper's 2.5–5 points. Only removing AGA is significant (paired p = 0.035). The content-only Head0 "baseline" scores 94.9 against the paper's 85.2, so the reported knowledge gain mostly disappears (BASELINE_STRONGER_THAN_REPORTED).
- **Table 2 VoX/gate diagnostics** depend on the seed:
  - Seed 0 (the `main.py` default) matches the paper's ReCOVery story almost exactly: VoX +0.466 with 92% positive, gate mean 0.014 with 100% below 0.3, HeadE better than Head0 and Fused equal to HeadE.
  - Across 10 seeds, the gate collapses to about 0 (trusts HeadE) in 5 seeds and to about 1 (trusts Head0) in the other 5. Mean VoX is −0.54.
  - On LIAR, the claimed collapse of HeadE F1 (58.8 → 47.3) never happens.
- MM COVID and MC Fake could not be run (data not obtainable; see below).

## What was run
Environment: conda env at `env/` with Python 3.10, torch 2.4.1+cu121, transformers 4.44.2, sentence-transformers 3.1.1, spaCy 3.7.6 + en_core_web_md, and scikit-learn. One H200 GPU.

1. As released: `cd codebase && python main.py` (log: `logs/main_as_released_seed0.log`).
2. `run_bimind.py` is my wrapper. It does the same thing as `main.py`: same split code, `prepare_llm_features`, `L3BTwoBrainLLM`, `train_llm_model`, AdamW at lr 2e-4, 20 epochs, patience 5, batch 16, knowledge dropout 0.3, λ_agree 0.05, gate fusion, and the same seed semantics. It adds a seed/dataset argument, ablation switches, and evaluation of macro and weighted P/R/F1, VoX and gate statistics. All method code is imported unchanged from `codebase/`. With seed 0 it reproduces `main.py` exactly (95.07).
3. Runs, each over seeds 0–9 (90 runs; per-run JSON in `results/`, logs in `logs/runs/`):
   - `rec_full`: ReCOVery, full model. The split is re-drawn per seed, as `main.py` does with `random_state=seed`.
   - `recfix_full`: ReCOVery with the split fixed (random_state = 0) and only the initialisation seed varying.
   - `liar_full` and `liarfix_full`: the same two protocols on LIAR.
   - ReCOVery ablations: `rec_noAGA` (`use_adapter=False`), `rec_noKnow` (kNN knowledge vectors zeroed), `rec_logitavg`, `rec_agreehead`, `rec_noKL` (λ_agree = 0).
   - Aggregates are in `results_summary.txt/json`; paired ablation tests are in `ablation_paired.txt`.

### Settings that differ from or are unspecified in the paper
- **Backbone:** Llama-2-7b-hf, as in the code. The paper says "LLaMA-7B".
- **Split:** the code splits 81/9/10; the paper says 80/10/10.
- **Seeds:** the paper does not say whether its 10 runs re-draw the split, so both protocols are reported. The paper's LIAR std of ±0.001 suggests the split was fixed.
- **Metrics:** the paper says "macro" P/R/F1, but its reported recall always equals accuracy, which only happens with weighted recall. Table rows therefore use weighted P/R/F1. Macro values are in `results_summary.txt`; they are about 0.5–1 point lower on ReCOVery.
- **ReCOVery text field:** we used `body_text`. The paper's Table 5 gives an average length of 500 words, which is consistent with article bodies. The model truncates to 256 tokens.
- **LIAR:** we kept only statements labelled true/false, from all official splits (4,560 items). This reproduces the Table 5 counts exactly.
- **Ablation definitions** are my mapping onto the code's switches; the release has no ablation scripts.

## Why the reproduction is only partial
- **Data:**
  - MM COVID: the MM-COVID repository (github.com/bigheiniu/X-COVID) contains only crawler code.
  - MC Fake: the NaCTeM `MC_Fake_dataset.csv.gz` link returns 404, and there is no Wayback copy.
  - The paper's filtered subsets (3,048 and 15,292 items) are not defined, and the abstract's promised link to "the tested datasets" is empty.
  - So only ReCOVery and LIAR were run.
- **Missing baselines:** the five baseline models are not released.
- **Mixed results:** absolute BiMind numbers come out *higher* than the paper's, but the components' contributions (ablation gaps, knowledge gain over Head0) are much smaller. The Table 2 interpretations (where the gate routes, VoX sign, LIAR knowledge collapse) do not hold across seeds.

## Discrepancies
**Code vs paper:**
1. **Major — the AGA in the LLM variant doesn't touch attention.** The paper says AGA adds POS-conditioned query/key offsets to pre-softmax attention logits (Eq. 6–7). In the code, Llama runs unmodified, and gated POS vectors (q_bias + k_bias) are added to the **final hidden states** before pooling. No attention logits are reshaped.
2. **Major — pooling.** The paper uses max-pooling (Eq. 9); the code uses masked mean-pooling.
3. **Major — the repo's own config doc disagrees with the code.** `LLM_HYPERPARAMETERS.md` describes query-only injection, a 0.3 gate floor, and extra losses λ_kb_sens = 0.1 and λ_gate_reg = 0.05. The code has q+k injection, no gate floor, and neither loss.
4. **Minor — head and FiLM architecture.**
   - Heads: the paper describes linear heads; the code uses 2-layer MLP heads.
   - FiLM input: the code builds the knowledge vector as [mean top-3 embedding, max sim, mean sim] and passes it through an extra `know_proj` layer before FiLM.
5. **Minor — split:** 81/9/10 in the code vs 80/10/10 in the paper.
6. **Minor — backbone:** Llama-2-7B in the code vs "LLaMA-7B" in the paper.
7. **Minor — reported metric:** `main.py` prints weighted F1, while the paper says macro.

**Paper-internal:**
1. The same model and dataset get different headline numbers in different tables:
   - ReCOVery: 0.918 (Table 1), 91.82 (Table 9), 87.19 (Table 2), 0.897 (Table 3), 0.879 (Table 10).
   - LIAR: 0.633 (Table 1), 62.93 (Table 9), 58.29 (Table 2), 0.605 (Table 10).
2. The paper claims macro metrics, but Rec = Acc in Tables 1–3, which implies weighted recall.
3. Table 5 gives ReCOVery 1,899 items, but Appendix D's 1,643 training samples imply 2,029 in total, which matches the README and the public data.
4. LIAR std is ±0.1 in Table 1 but ±4.1 in Table 10 for the same model.
