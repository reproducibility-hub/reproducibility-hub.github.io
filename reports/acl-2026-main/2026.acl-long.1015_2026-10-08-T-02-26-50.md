**Template-assisted Contrastive Learning of Task-oriented Dialogue Sentence Embeddings (TaDSE)**

## Verdict
- **Verdict: REPRODUCED**
- **Result match (after fixes): NUMBERS_MATCH.** All 105 paper numbers I re-ran are within tolerance: ≤1 pt absolute or ≤5 % relative. That covers Table 2 (all 9 models × 5 datasets), Table 3, Table 4 and Table 5. The largest absolute gap is 3.1 pts (SimCSE (ours), ATIS: 86.56 vs 83.43), the median 0.3 pts.
- **Result match as released: DOES_NOT_RUN.** Two things block the release as shipped. The augmentation script for SNIPS/ATIS/MASSIVE/HWU64 (`data/massive/augment_data.py`, named in the README) is not in the repo, and neither is the augmented data. The released trainer also crashes at the end of the first epoch. The off-the-shelf baseline evaluation (BERT/SimCSE/TOD-BERT/DSE rows of Table 2) runs unmodified and reproduces the paper exactly.
- **Coverage: FULL** for the main experiments (Tables 2, 3, 4, 5). Not run:
  - Table 6: OpenAI and Gemini embedding APIs are closed, and the released evaluator has no Qwen3-Embedding path.
  - Figures 5–11 (t-SNE, uniformity/alignment plots, k-NN curve, training curve): qualitative, no numbers in the text.
- **Codebase completeness: MISSING_SCRIPTS.** The method, trainer and evaluator are released. Missing: the augmentation script for 4 of 5 datasets, `requirements.txt`, and any launch scripts or hyper-parameter configs.
- **Flag: BASELINE_STRONGER_THAN_REPORTED.** The paper evaluates DSE and TOD-BERT through the SimCSE tool with `pooler=cls`, i.e. BERT's NSP pooler output. With the released evaluator's `--pooler cls_before_pooler` option, or with DSE's official mean pooling, DSE averages 86.0 / 86.5. That beats TaDSE (82.85 ours; 83.64 paper) on **every** dataset. Semantic compression (Table 5), λ ∈ {0.1, 0.2, 0.5}, two template sources:

## Codebase completeness: MISSING_SCRIPTS
Changes to the released code (left uncommitted in `./codebase`):
1. `model/tadse/trainers.py` l.649: the end-of-epoch `_maybe_log_save_evaluate(tr_loss, model, trial, epoch)` call has the wrong signature for the transformers version the rest of the code requires (Qwen3, `num_items_in_batch`). It crashes after epoch 1. I replaced it with the same call used per step. This does not affect training.

Workarounds without code edits:
- `--save_safetensors False`: saving fails on the tied lm_head weights.
- `GOOGLE_API_KEY=dummy`: `accuracy_infer.py` builds a Gemini client at import time.
- `PYTHONUTF8=1` for `extract_ptn_clinc.py`. The script also crashes after writing its output, at `ptnUnique[0:5]` (slicing a set); this is harmless.
- `--use-pair-for-target` for gold-template compression, which otherwise crashes.

Scripts I wrote (outside `./codebase`):
- `scripts/augment_data.py`: replaces the missing augmentation for SNIPS/ATIS/MASSIVE/HWU64. It includes `--cap` for SNIPS.
- `train_eval.sh`, `run_eval.sh`, `comp_eval.sh`, `rcomp_eval.sh`, `queue*.sh`, `comp_batch*.sh`, `eval_clsbp.sh`: launchers.
- `scripts/accuracy_infer_fixed.py`: a copy of the evaluator with the template-bank overwrite fixed (`res_vecs, _ = _infer(...)`). Used only for the retrieved-template compression numbers.
- `scripts/eval_dse_mean.py`: patches the evaluator's buggy DSE mean pooling. Used only for the extra DSE analysis.
- `scripts/collect.py`, `scripts/compare.py`: result tables.

Missing from the release:

## Discrepancies
Code vs. paper:
- **minor** — `pairwise_neg_type` defaults to 'pattern' (template negatives). The paper's Eq. 3 draws negatives from utterances; I set 'utterance'.
- **minor** — `pairwise_loss_ratio` defaults to 0.01; the paper uses λ_pair=0.5.
- **minor** — `-t snips` uses the 2,100-utterance SNIPS train subset as k-NN references. The paper says the full training set; Table 1 lists 13.1K. The paper's numbers match the subset exactly (SimCSE 91.71; full set 92.00).
- **major (HWU64 column only)** — the HWU64 test set is built by exact string matching and yields 830 utterances, not the 1,076 in Table 12. The paper's numbers reproduce exactly with 830.
- **major (Table 5)** — in `accuracy_infer.py` the template bank is overwritten after the first test batch. Retrieved-template compression therefore uses wrong templates (MASSIVE λ=0.5 drops to 23.9 %), and gold-template mode crashes without `--use-pair-for-target`.
- **minor** — the README-listed `augment_data.py` and `requirements.txt` are absent.

Paper-internal:
- Table 2 DSE MASSIVE (76.77) equals SimCSE MASSIVE. The evaluator gives 75.29 for DSE, while all other baseline cells match exactly.
- Table 4 CLINC "aug" 70.98 is Table 3's top-3 value, while its "+Lt,Lpair" 72.98 is the top-5 value; Table 3's top-5 Lu is 69.62.
- Table 4 ATIS +Lt,Lpair = 89.59, but Table 5 lists 89.57 for the same model.
- Table 1 SNIPS: 163K utterances from 13.1K is inconsistent with the Sec 3.1 procedure. Applied to the SNIPS data (whose slot/value/template counts do match Table 1), it gives 4.66M. ATIS has 4,978 training utterances in the file versus 4.5K in Table 1.
