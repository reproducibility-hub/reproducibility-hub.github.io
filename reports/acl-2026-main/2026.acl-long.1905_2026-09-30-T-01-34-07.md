### Settings that differ from the paper
- **Gemma-2 weights**: `google/gemma-2-9b(-it)` is gated for the available HF account (403). I loaded the identical public bf16 copies `unsloth/gemma-2-9b(-it)` and handed them to TransformerLens under the official model names. Same architecture and config; I assume the weights are the same.
- **Accuracy CV**: the paper says 5-fold (80/20). The released code uses `StratifiedKFold(n_splits=3)`. I kept the released code.
- **Seeds**: uniformity was run with 10 seeds (666, 42, 100, 500, 999, 1–5) for both residual and heads, matching the paper; logic coherence with 5 seeds (666, 42, 100, 500, 999). The shipped result files contain 1 seed. Note that `stratify()` hard-codes `seed=42`, so the train/test split is identical across "seeds"; only the internal 80/20 probe split changes.
- **Coherence (probabilistic)**: the logistic-regression probe was run with 5 seeds for all models and both sites; all four estimators with 5 seeds on Llama residual (Fig. 7); MMP/logits/self-report with seed 666 for the other models. The paper's appendix figures are single-run.
- **Use control hyperparameters**: the random-direction control's K/α are not given in the paper. I used the overrides hard-coded in `scores.ipynb` where present (Llama residual, Llama-it residual, Llama-it heads), and otherwise the clean K/α. The paper says it keeps the clean hyperparameters when the control shows no effect.
- **Use effect clipping**: the paper clips E and E_rand at 0.05; `scores.ipynb` does not. I apply the clip, as the paper describes.
- **Not reproduced**: Table 1 (probe accuracy on PCA projections) and Fig. 4 (no released script computes Table 1's accuracies; `--exp visualizations` only dumps projections). The Use grid-search figures and the control-probe (shuffled-label) curves were also not re-run.

## Why it is not a full numeric reproduction

The remaining deviations are listed below. None is caused by missing data or compute.

- **Use control (random-direction) hyperparameters are not reported.** E_dir depends on them. With the `scores.ipynb` overrides, Llama residual E_dir differs from Table 2 (F→T 8.5 vs 3.02; T→F 0.58 vs 1.00).
- **Run-to-run variance.** The released code fixes the seeds, but data-split order, sklearn and GPU numerics still differ. Uniformity, logic and probabilistic scores are on average 0.01–0.03 below the paper (largest gaps: Gemma/Gemma-it logic residual, Gemma uniformity residual).
- **Ambiguous small-model numbers.** The Yi/Pythia figures in Sec. 5.1 do not say which variant (base or deduped / chat) they refer to.
- **GPT-J readout bug** (see Discrepancies). Fixing it changes GPT-J's Table 2 numbers; the unmodified code reproduces them.
- **Gemma weights from a mirror.** google/gemma-2 is gated for us, so I used the unsloth mirror; I assume the weights are identical.

## Codebase completeness: MAJOR_FIXES

The released repo implements all four experiments, with interactive prompts. It ships the data, the fold-averaged probe directions used by the downstream experiments, the pre-computed results, and a scoring notebook.

Reproducing the paper needed only config/environment-level changes. One result-affecting bug was fixed (GPT-J last-token position); the paper's own numbers were produced without that fix. Per the rubric, fixing a bug that changes numbers counts as MAJOR_FIXES.

Changes to `./codebase` (left uncommitted; see `git -C codebase diff`):

1. `utils/get_model.py`
   - Gemma-2 is loaded from the public mirror `unsloth/gemma-2-9b(-it)` and passed to `HookedTransformer.from_pretrained(<official name>, hf_model=..., tokenizer=...)`, because google/* is gated for our account.
   - An optional `fcntl` lock around model loading (env `BELIEFS_LOAD_LOCK`) serialises the host-RAM-heavy loads (Gemma peaks at ~83 GB RSS). It has no effect on results.
2. `src/cfg.py`: the config path can be overridden via env `BELIEFS_CFG`, so per-seed configs can run concurrently. The release's `--config` and `--set` flags are parsed but ignored.
3. `configs/default.yaml`: `probe.control: True → False`. With the default, every "accuracy" probe is trained on shuffled labels.
4. `utils/intervention.py`, `utils/probe.py`: the authors' manual toggle ("Change to - 0 for GPT-style models") is exposed as env `BELIEFS_GPT_POS_FIX` (default = released behaviour). It was used only for the GPT-J runs in `runs/use_posfix/` and `runs/coherence_posfix/`.
5. During the runs, the shipped `codebase/full_results` was moved aside, because new outputs collide with it (`save_results` then silently writes timestamped files to the results root). Afterwards my outputs were moved to `runs/accuracy_full_results/` (Accuracy) and `runs/<exp>/...`, and the shipped `full_results` was restored unchanged (`git checkout`).

Scripts I wrote outside the release:
- `run_accuracy_queue*.sh`, `run_use.sh`, `run_exp.sh`, `queue_*.sh`, `rerun_failed.sh`: pipe the interactive answers into `src/main.py` and file the outputs per model/setting/seed.
- `download.py`: model prefetch.
- `analysis/*.py`: recompute the paper's metrics from the saved outputs.
  - Accuracy: top-k over fold-averaged accuracies.
  - Table 2: E, E_dir, S, clipping.
  - A.2.2 scores.
  - Uniformity/logic: avg/worst and mean−std.
  - Probabilistic coherence: baseline-corrected average.

`scores.ipynb` cannot be used on fresh outputs: it expects fold-averaged arrays and sigmoid-squashed Use logs.

Other issues found (not fixed):
- `run_accuracy` crashes at the very end in `get_top_entries`, because the heads array is 3-D (per fold). This happens after all results are saved.
- Nothing converts `run_accuracy`'s per-fold outputs into the fold-averaged `data/directions` format that the downstream experiments need; I used the shipped `data/directions` instead.
- No script computes Table 1.
- Concurrent runs occasionally fail inside `huggingface_hub.login()` because `main.py` logs in on every run and rewrites the shared `~/.config/stored_tokens`. Six transient failures (2 of them HF login, 4 CUDA OOM from my own concurrent jobs) and two CUDA-OOM failures in Use were re-run. The failed logs are kept in `runs/failed/`.

## Discrepancies

Code vs paper:
- **[major] GPT-J readout position** (`utils/intervention.py`, `utils/probe.py`).
  - What happens: `last_positions = (tokens != pad).sum() - 1` is off by one when pad == BOS (GPT-J). Steering and P(True)/P(False) are taken at the token before the last ('Answer' instead of 'Answer:'); the top token is ':' rather than ' True'.
  - Effect: the paper's GPT-J Use numbers (and the GPT-J logits baseline in Coherence) carry this artefact.
- **[minor] Accuracy cross-validation** (`utils/probe.py` `probe_sweep`): the paper says 5-fold / 80-20; the code uses `StratifiedKFold(n_splits=3)`.
- **[minor] Control-probe default** (`configs/default.yaml`): `probe.control: True` makes `--exp accuracy` train shuffled-label control probes by default.
- **[minor] Uniformity/logic split seed** (`utils/processing.py` `stratify()`): the paper describes 10 (uniformity) / 5 (logic) random seeds for the split. The code hard-codes `seed=42`, so the test split is identical across seeds, and the shipped results contain one seed.
- **[minor] Use metric** (`scores.ipynb` vs released code):
  - `recover_pd` inverts a sigmoid(5x) squashing that the released code does not apply, so the logging code that produced the paper differs from the release.
  - The 0.05 clipping described in the paper is not implemented anywhere.
  - The notebook's control K/α overrides give Llama residual T→F E_dir = 0.58, not Table 2's 1.00.
- **[minor] Accuracy → downstream format**: `run_accuracy`'s per-fold outputs cannot be consumed directly by the downstream experiments, and no conversion script is provided.
- **[minor] Table 1**: no released code computes the PCA-projection probe accuracies. The README also calls the experiment `visualization`, but the code key is `visualizations`.

Paper-internal:
- **Eq. (4) vs Table 2:** Eq. (4) says S = |α|·sqrt(K·D_act/D_model), but Table 2 lists S = sqrt(|α|·K·D_act/D_model). E.g. α=9, K=1 gives S = 3.00, and Gemma T→F (α=33, K=22) gives 26.94.
- **Llama accuracy:** Sec. 5.1 gives Llama top-3 residual accuracy 0.889, below the top-5 value 0.895 in App. A.2.2. A top-3 mean cannot be lower than a top-5 mean.
- **Uniformity seeds:** the paper says 10 seeds (App. A.3.2, Fig. 8). The shipped uniformity results, which reproduce the A.2.2 scores exactly, are single runs.

Also noted: the shipped `full_results` logic files (`uniformity_uniformitylogic*`) do **not** reproduce the paper's Coherence (Logic) scores or the negated-CC numbers. For example, Gemma-it's negated-CC accuracy is 0.26 in the shipped file vs 0.67 in the paper. Fresh runs with the released code do reproduce them (0.66).
