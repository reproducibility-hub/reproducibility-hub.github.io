## What was run

All runs use the released `sabpe` package unmodified (`sabpe.train_and_save`, vocab 32,768, special tokens `<|endoftext|>`, `<|unused_token_{1,2,3}|>`, ByteLevel pre-tokenizer as in the README), in a fresh conda env (Python 3.11, transformers 5.19, tokenizers 0.23, torch 2.14).

1. **Data (rebuilt).**
   * `scripts/build_train.py`: 36,052 random files from the 18 languages of Table 7, taken from 6 Common Corpus shards (`PleIAs/common_corpus`, collection "Github Open Source"). Repo = `owner/name` from the GitHub URL. 150 MB of text (paper: 0.25% of 56.22 GB ≈ 140 MB). 34,583 distinct repos.
   * `scripts/build_eval.py`: GitHub search with created 2025-03-01..2025-12-31 (the paper gives no collection date; we capped at the end of 2025), ≥10 stars, ≥15 commits (checked with a tree-less clone), top-200 by stars per language, and ≤20 random files per repo with the Table 8 extensions. Result: 55,228 files from 3,158 repos. Haskell, Julia, Scala and OCaml have fewer than 200 qualifying repos, so all were kept, as in the paper.
   * `scripts/build_train_mono.py`: 36,052-file Java and 36,052-file Python samples for Table 2. The paper doesn't give their size. The Java/Python slices of the 36k multilingual sample (7,000 and 4,319 files) ran out of merges for R-thresholds ≥5–10, whereas the paper's runs complete, so the paper must have used more data.
   * `scripts/build_lm_data.py`: LM pre-training text from 1,190 further Common Corpus shards (18 languages, about 63 GB of text). It is disjoint from the tokenizer-sample shards.
2. **Tokenizers** (`scripts/train_tok.py`, one process per configuration). We trained the 10 multilingual configurations of Table 3 and 2×7 monolingual configurations of Table 2. The F·log(R+1) variants and the skip predicates were passed as `score_fn`/`skip_fn` (not shipped in `sabpe.scoring`). Training takes ~17–20 min per multilingual tokenizer.
3. **Intrinsic evaluation** (`scripts/eval_tok.py`, `scripts/vocab_diff.py`). Metrics:
   * CR = UTF-8 bytes / tokens over the eval set.
   * Coverage = number of distinct token ids used.
   * MTL = mean string length over the vocabulary, as in the notebook.
   * 3-digit = distinct 3-digit strings in the vocab (with or without a leading `Ġ`).
   * Per-language CR and coverage.
   * Table 14 = symmetric vocabulary difference.
4. **LMs** (`scripts/train_lm.py`). Llama with Table 5's config (hidden 768, 12 layers, 12 heads / 4 KV heads, FFN 2048, tied embeddings, RoPE 10k): 100.7M parameters. Table 6 optimizer: AdamW (0.9, 0.95), wd 0.01, clip 1.0, peak LR 3e-4, linear warmup, linear decay to 3e-6. Batch 128×2048 = 262,144 tokens per step, on 1 H200 in bf16. The paper used 2 A100s with 16×2×4 accumulation, which gives the same effective batch.
   * **s8000** (all 10 Table-3 tokenizers): 8,000 steps (2.1B tokens), warmup scaled to 667 steps.
   * **s60000** (BPE and F·log R·L only): the paper's 60,000 steps (15.7B tokens), warmup 5,000.
   * Scaling reason: one 60k-step model takes ~9.5 h on the whole GPU (~0.53 s/step), so 10 models (~95 GPU-h) would not fit in the 48 h budget.
5. **Under-trained tokens.** We ran `magikarp/fishing.py` (cohere-ai/magikarp, unmodified) with `--known_unused_tokens [1,2,3]` (the reserved tokens never seen in training), the default 2% threshold, the cosine indicator, and the default 3 verification prompts. A token counts as verified under-trained if the max next-token probability of the token itself is < 1% (paper Sec. 4.3). Magikarp tests 645 tokens for every model (paper: 646).
   * Sanity check (`scripts/sanity_magikarp.py`): for 100 random non-candidate tokens of the 8k-step BPE model, only 3% are "verified", and 0/50 from the top quartile of the indicator. So the verification prompts work for these small models.

* The tokenizer training sample, the eval set and the monolingual samples were all rebuilt (different random files and repos; the eval set is a different GitHub snapshot).
* LM training: 8k instead of 60k steps for 8 of the 10 models; 1 GPU instead of 2, with the same effective batch.

## Practical notes
* The released trainer is pure Python (heapdict). On 36k files (150 MB) it takes ~17–20 min and ~7 GB RAM per tokenizer; 10–14 configurations ran in parallel.
* An eval-script version that kept all `Encoding` objects used 55 GB of RAM and came close to the job's 121 GB limit. We killed it (our own process) and rewrote it to stream.
* Rebuilding the eval set used the unauthenticated GitHub search API (10 req/min) plus git clones. The paper's exact snapshot can't be recovered.
