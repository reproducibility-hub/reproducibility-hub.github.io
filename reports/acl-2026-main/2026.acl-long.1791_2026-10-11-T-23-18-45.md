## Verdict
- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): NUMBERS_MATCH**: 34 of 36 QuDAR-simple/QuDAR-confidence numbers in Tables 1–2 fall within tolerance on all 4 datasets. Overall, 122 of 156 compared numbers are within tolerance, 33 match the trend, and 1 does not match.
- **Result match as released: TREND_MATCH**: with the released BM25, QuDAR still beats every individual retriever and the static hybrids, so the claimed ordering holds. But the released BM25 is far weaker than the paper's, so FiQA/HotpotQA absolute numbers are 5–13 % low and the gains over the best individual retriever are inflated (FiQA +38 % vs. +7–10 % in the paper).
- **Coverage: SUBSET**: we ran all four datasets at full scale (all test queries, full corpora) for the individual retrievers, the single-perspective static hybrids, QuDAR-simple (RRF/Equal) and QuDAR-confidence. Not run:
  - QuDAR-llm, Table 4 and the Table-3 RAG evaluation: closed API (gpt-4o-mini), not run per the user's instructions.
  - DAT: needs an LLM, and no code is released.
  - Dual-perspective "Static Avg / Static UB" rows: not implemented in the release.

## What the paper claims (target)
Tables 1 and 2 report retrieval results on four BEIR test sets (FiQA, SciDocs, Climate-FEVER, HotpotQA):
- Settings: BM25 as the sparse retriever, Contriever as the dense retriever, and HyDE-style query expansion generated by LLaMA-3.1-8B.
- Metrics: R@10, nDCG@10, P@1.
- Claims: QuDAR outperforms the individual retrievers (avg. 12–16 % gains over the best one) and static single-perspective hybrids (up to ~30 % over static averaging), and is close to grid-searched upper bounds.

## What we did
Code: https://github.com/kaist-dmlab/QuDAR (commit 0702721), in `./codebase` with no source edits (`git status` is clean apart from the egg-info). Env: conda Python 3.11, `pip install vllm` + `pip install -e codebase` (+ `bm25s` for the fix). Torch 2.13, transformers 5.17, faiss-cpu 1.15, beir 2.2. 1×H200.

1. **Data**: BEIR fiqa / scidocs / climate-fever / hotpotqa from the official BEIR URL that `scripts/download_beir.sh` points to, test split. Query counts: 648 / 1000 / 1535 / 7405. Corpora: 57.6K / 25.7K / 5.42M / 5.23M docs.
2. **Query expansion (missing from release; written by us)**: `scripts/expand_queries.py`, using vLLM with `meta-llama/Llama-3.1-8B-Instruct` and the exact paper Prompt 2 (App. G) as a single user chat turn.
   - Decoding: greedy (T=0), max 256 new tokens. The paper does not give decoding settings.
   - Output: average length ~130–150 words. Files are in `expanded/`.
3. **Dense indexes**: the repo's own command, `python -m qudar.build_index --model-name facebook/contriever --dim 768 --batch-size 256`, for every dataset (fp32; ~3.8 h + 2 h for the two 5M-doc corpora).
4. **Pipeline**: the repo's `qudar.cli` with `--full --disable-llm`, via `scripts/run_qudar.py`, a thin wrapper that can swap the sparse retriever. Configs are in `configs/*.yaml`; they follow `configs/fiqa_example.yaml` with paths filled in: top_k=1000, eval@10, confidence_tau=2.0, confidence_topk=10, rrf_k=60.
   - **As released** (`outputs/`):
     - FiQA, SciDocs: `python -m qudar.cli --config configs/{fiqa,scidocs}.yaml --full --disable-llm`, completely unmodified (rank_bm25).
     - Climate-FEVER, HotpotQA: the released rank_bm25 retriever is infeasible on 5M docs (one Python dict lookup per document per query token, i.e. hours per query). We substituted `scripts/fast_bm25.py`, an exact sparse-matrix re-implementation of rank_bm25 `BM25Okapi` with the same tokenisation. It was verified identical on FiQA (max |score diff| 2e-10; identical top-100 lists on 41/41 test queries). This is a speed-only change.
   - **After fix** (`outputs_fixed/`): `scripts/run_qudar.py --bm25-impl bm25s ...`. BM25 = `bm25s` (Lucene BM25, k1=1.5, b=0.75, English stopwords, PyStemmer English). This BM25 reproduces the paper's Original-Sparse numbers almost exactly (FiQA 0.3178/0.2514/0.2299 vs. paper 0.3135/0.2500/0.2299; SciDocs 0.1653/0.1578/0.1830 vs. 0.1655/0.1578/0.1810), so it is evidently what the paper used.
   - **Diagnostic** (`outputs_fix_expq/`, not used for the verdict): bm25s plus expanded queries encoded with the query path ("query: " prefix) instead of the released `encode_passages` ("passage: " prefix). See Discrepancies.
5. Comparison tables were built with `scripts/make_comparisons.py` (→ `comparisons.json/md`, `claims.md`).

- BM25 implementation, but only in the as-released runs.
- QuDAR-llm, DAT and the dual static rows were not run.

The paper's individual **Expanded-Dense** row matches the "query: " encoding on Climate-FEVER, FiQA and SciDocs. Its **fusion rows** (UB(D), QuDAR) match the released "passage: " encoding: with "query: ", Climate-FEVER QuDAR rises to 0.279 R@10, well above the paper's 0.247. On HotpotQA both encodings match the paper within tolerance.

Also: Contriever is run with E5-style "query:/passage:" prefixes and L2-normalised mean pooling (`qudar/retrievers.py`). Original-Dense comes out 7–25 % below the paper on all datasets (e.g. FiQA nDCG 0.1188 vs. 0.1299). Dropping the query prefix gives FiQA OD 0.1612/0.1333/0.1265, so the paper's exact dense setup cannot be pinned down. These dense baselines are therefore labelled TREND_MATCH.

QuDAR-confidence weights are nearly uniform (FiQA per-query weights range 0.21–0.33, because softmax(τ=2) is applied to margins in [0,1]). That is why QuDAR-confidence ≈ QuDAR-simple(Equal) in both the paper and our runs.

## Discrepancies
1. **code_vs_paper (major, affects results)**: `qudar/retrievers.py::BM25SparseRetriever`. The paper's BM25 numbers match bm25s (Lucene BM25 with English stopword removal and regex tokenisation) to within 0.004. The released code uses rank_bm25 BM25Okapi with `text.lower().split()` tokens (punctuation kept, no stopwords). Effect on FiQA Original-Sparse nDCG@10: 0.168 vs. 0.250. This weaker BM25 lowers every hybrid and QuDAR number.
2. **code_vs_paper (minor)**: `qudar/retrievers.py::DenseEncoder`. Contriever is run with E5-style "query: "/"passage: " prefixes and L2-normalised embeddings. The paper just says "Contriever", whose standard usage has no prefixes and uses dot product. The pipeline also encodes the expanded query with `encode_passages` ("passage: " prefix). This affects the absolute dense numbers.
3. **paper_internal**: Tables 1–2, query-format "Static UB(D)" vs. "Expanded-Dense". UB(D) is the best fixed α ∈ {0,…,1} over OD/ED, and α=1 is ED alone, so UB(D) ≥ ED must hold for every metric. Yet the paper reports:
   - Climate-FEVER UB(D) 0.1527/0.1195/0.1075 < ED 0.1960/0.1624/0.1564.
   - FiQA R@10: UB(D) 0.1810 < ED 0.1835.
   - SciDocs R@10: UB(D) 0.1479 < ED 0.1487.

   The individual ED row and the fusion rows therefore come from different ED runs. Our diagnostic suggests the ED row used "query:"-prefixed and the fusion rows "passage:"-prefixed expanded queries.
4. **paper_internal**: §5.2.1 says "QuDAR outperforms all individual retrievers across datasets". Table 2 Climate-FEVER has Expanded-Sparse 0.2598 R@10 / 0.2053 nDCG@10 > QuDAR-confidence 0.2473/0.2050, and > QuDAR-llm 0.2583 R@10.
