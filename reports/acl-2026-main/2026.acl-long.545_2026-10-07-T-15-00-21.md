# Reproduction report — DecoCal: Decoding with Calibration in Diffusion LLMs (ACL 2026, 2026.acl-long.545)

## Verdict

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after my additions): MIXED.** On **LLaDA-1.5**, DecoCal's gains over vanilla decoding come out about as the paper reports. The gain is close in size on TriviaQA, GSM8K, MATH and MBPP. On HumanEval DecoCal ties vanilla, where the paper reports +1.2. DecoCal also uses fewer steps than the 256-step baseline. On **Dream-v0-Instruct-7B**, my DecoCal numbers match the paper's DecoCal numbers closely (TriviaQA/GSM8K/MATH/HumanEval are within 1.2 pts). But the **vanilla Dream baseline** (entropy decoding + the paper's EOS penalty, same pipeline) is far stronger than the paper reports, for example GSM8K 61.3 vs 36.0. It matches or slightly beats DecoCal on all five benchmarks, so the paper's headline Dream claim ("new records across all five benchmarks", "double-digit improvements") does **not** reproduce.
- **Result match as released: DOES_NOT_RUN.** The release has only the decoding functions. It has no evaluation pipeline, prompts, data loading, scoring, or run scripts for any table, so the unmodified release cannot produce the main results.
- **Coverage: SUBSET.** I ran Table 1 (DecoCal and Vanilla, both models, all 5 benchmarks, full paper scale) and Table 2 (LLaDA ablations), each at the paper's sample counts. I did not run the ReMDM/RCR/Tolerator baselines, which are not in the release. I also did not run Tables 3, 4, 8–12 or the figures.
- **Flags:** `BASELINE_STRONGER_THAN_REPORTED` (Dream vanilla).
- **Codebase completeness: MISSING_SCRIPTS.**

## What the paper claims (target)

Table 1: accuracy and average decoding steps of DecoCal vs. Vanilla, ReMDM, RCR and Tolerator on LLaDA-1.5 and Dream-v0-Instruct-7B. The benchmarks are TriviaQA (1000 random wikipedia-dev questions, L=64), GSM8K (1319), MATH (700 = 100 random per subject), HumanEval (164) and MBPP (500), with L=256 for all but TriviaQA. Settings: A=0.9, γ=2, K=1, C=8 (C=2 for TriviaQA), temperature 0, zero-shot, block length = L. Table 2 gives ablations on LLaDA-1.5 (GSM8K, HumanEval).

## What I did

1. Cloned https://github.com/pku0xff/DecoCal (commit 327a730) into `./codebase`. It contains `calibrate_core.py`, `llada_DecoCal.py` and `dream_DecoCal.py`, which hold the method's `generate_DecoCal` functions and nothing else (no README, no requirements, no eval scripts).
2. Environment: `conda create -p ./env python=3.10`, then `pip install torch==2.5.1 transformers==4.46.2 accelerate datasets numpy==1.26.4 math-verify sympy`. I used the transformers version that Dream's remote code requires.
3. Models: `GSAI-ML/LLaDA-1.5` and `Dream-org/Dream-v0-Instruct-7B` (bf16), on one H200.
4. Wrote the missing pipeline myself (`scripts/`):
   - `run_eval.py`: loads data, builds zero-shot chat-template prompts, and calls the **unmodified** released `generate_DecoCal` (imported as a package) with the paper's hyper-parameters. It counts diffusion steps with a forward pre-hook on the model, writes resumable JSONL, and runs vanilla baselines.
     - LLaDA vanilla: the official LLaDA `generate.py` (`scripts/llada_generate_official.py`, downloaded from ML-GSAI/LLaDA), `low_confidence` (= maskgit-style) remasking, steps = gen length = block length.
     - Dream vanilla: Dream's own `diffusion_generate(alg="entropy", steps=L, temperature=0)` plus the paper's EOS penalty (App. B.2, logits[EOS] /= 1 + #EOS/L), implemented as a logits hook in exactly the way the released `dream_DecoCal.py` applies it.
   - `score.py`: scores each benchmark.
     - GSM8K: `\boxed{}` > `####` > "answer is" > last number (lm-eval flexible-extract fallback).
     - MATH: last `\boxed{}` vs. gold boxed answer, checked with `math_verify` plus a string-normalisation fallback.
     - TriviaQA: a normalised answer alias (any of the official aliases) appears in the output.
     - HumanEval/MBPP: pass@1 by executing the official tests (10 s timeout). Code is cut at the closing ```` ``` ```` and at the first top-level model-written test/print/`__main__` line. This sanitisation is applied identically to every method.
   - `worker.sh`/`worker2.sh` run a job queue; `aggregate.py` and `make_comparisons.py` merge the shards and build the tables.
5. Prompts (the paper says only "zero-shot"; I adopted the lm-eval templates used by Tolerator, which the paper follows for the EOS penalty):
   - GSM8K / TriviaQA: `Question: {q}\nAnswer:`
   - MATH: `{problem}\nPlease reason step by step, and put your final answer within \boxed{}.`
   - HumanEval / MBPP: the lm-eval `*_instruct` prompts with the assistant prefix `Here is the completed function:\n```python\n...`.
   - All prompts are wrapped in each model's chat template.
6. DecoCal call settings:
   - `calib_mode="ig"` (KL-adaptive w, Eq. 2), `ig_gamma=2.0`.
   - `error=0.1`: the released `EarlyDecider` tests odds(q) > (1-e)/e, i.e. q > 0.9 = A.
   - `remask_steps=1` (K) and `cool_down=8`/`2`.
   - Step budget `steps = L·(K+1)` (512, or 128 for TriviaQA). This matches the paper's "steps bounded by T·(K+1)" and its Dream step counts above 256. The released code auto-sets K = steps // L − 1, which is consistent with this.
   - LLaDA: `block_length=L`, temperature 0. Dream: `mask_token_id`/`eos_token_id` passed explicitly from the model config.
7. Ablations (Table 2), all via arguments of the released function:
   - fixed w: `calib_mode="fix", alpha_fixed=0.5`
   - w/o cool-down: `cool_down=0`
   - w/o remask: `remask_steps=0`
   - w/o calibration: `use_calib=False`. This leaves only threshold unmasking on p, and remasking is automatically disabled because q is None.
8. Data subsets: TriviaQA = 1000 questions from `mandarjoshi/trivia_qa` `rc.wikipedia.nocontext` validation, drawn with `random.Random(0)`. MATH = 100 per subject from `EleutherAI/hendrycks_math` test, also with seed 0. The authors' exact random subsets are not released, so these are re-drawn subsets of the same size and source.
9. Extra diagnostics (not in the paper's tables), to understand the Dream baseline gap:
   - Dream on GSM8K **without the chat template** (raw prompt), vanilla and DecoCal.
   - Dream vanilla **without the EOS penalty** on GSM8K (cf. Table 7).

Commands (each job; four or more ran concurrently on one GPU from `results/jobs*.txt`):
```
env/bin/python scripts/run_eval.py --model {llada,dream} --method {decocal,vanilla,fixed_w,no_cooldown,no_remask,no_calib,vanilla_noeos} \
    --task {triviaqa,gsm8k,math,humaneval,mbpp} --shard i/n [--no_chat] --out results/main/<model>_<method>_<task>.s<i>o<n>.jsonl
env/bin/python scripts/aggregate.py && env/bin/python scripts/make_comparisons.py
```

Without the EOS penalty my vanilla Dream score (29.72) is close to the paper's Table 7 no-penalty number (30.63). With the penalty, implemented exactly as in the released `dream_DecoCal.py` (logits[EOS] /= 1 + #EOS/L), vanilla jumps to 61.33, whereas the paper reports only 36.01. So the paper's penalised vanilla baseline appears to be much weaker than what the described penalty actually produces. Dropping the chat template lowers vanilla (46.0) more than DecoCal (53.4), but neither variant recovers the paper's 24-point gap.

### Interpretation

- **LLaDA-1.5:** The paper's claims hold in direction and roughly in size. DecoCal ≥ vanilla on all 5 tasks, the gains are close to the paper's (GSM8K +4.5 vs +4.0, MATH +1.0 vs +0.7, TriviaQA +0.7 vs +0.9, MBPP +0.6 vs +0.8), HumanEval is a tie (paper +1.2), and DecoCal uses fewer steps on TriviaQA, GSM8K, MATH and MBPP, with step counts close to the paper's. Absolute accuracies differ by several points on GSM8K (−5.6), MATH (+4.3) and MBPP (+8.8). This is expected, since the prompts, answer extraction and code sanitisation are not released and had to be chosen by me. The same shift appears for both methods.
- **Dream-v0-Instruct-7B:** DecoCal's own accuracies reproduce well. But the vanilla entropy baseline with the EOS penalty is 8–28 points higher than reported and slightly above DecoCal on every benchmark. My vanilla numbers are plausible for this instruct model: Dream's own report gives instruct-model scores well above the paper's vanilla numbers, though I did not re-check its exact settings. The paper's Dream vanilla numbers (e.g. GSM8K 36.0, MATH 14.7) look like a degraded baseline. The diagnostics point the same way. Vanilla Dream *without* the EOS penalty scores 29.7 on GSM8K, close to the paper's Table 7 'wo penalty' 30.6. So my setup reproduces the paper's unpenalised baseline, but the penalised baseline (the one actually used in Table 1) comes out at 61.3 instead of 36.0. The paper's vanilla+penalty run therefore probably did not apply the penalty as described, or applied it differently; the vanilla code is not released, so I cannot check. DecoCal is robust to the EOS-collapse failure: its own step-wise thresholding plus the penalty gets 60.6, roughly what vanilla gets once the penalty works. With a raw prompt (no chat template), vanilla drops to 46.0 and DecoCal to 53.4. DecoCal helps there (+7.4), but this is still far from the paper's +24. Under the standard chat-template setup, the claim "DecoCal sets new records across all five benchmarks" on Dream (+6 to +24 points) does not reproduce: the gains are −0.6 to −1.2 points.
- **Ablations (Table 2, LLaDA):** On GSM8K, removing remasking or calibration costs about 5 points, as in the paper, and removing cool-down costs a bit over 1 point. Fixed w=0.5 is essentially identical to the KL-adaptive w on GSM8K (57.32 vs 57.39; paper −1.21) and lower on HumanEval (40.85 vs 43.90; paper −0.61), so 'adaptive weighting contributes consistently' is only partly supported. On HumanEval, the ablations barely move the score (DecoCal, w/o remask and w/o cool-down are all 43.90), so the paper's HumanEval ablation drops (−2.4 to −3.1) do not reproduce.

## Why not fully reproduced

1. The release has no evaluation pipeline, prompts or scoring, so absolute numbers depend on my reconstruction. Prompt and extraction choices move accuracies by several points.
2. The Dream vanilla baseline, run with the paper's described settings (entropy, L steps, temperature 0, EOS penalty), is much stronger than reported, which removes DecoCal's claimed gain on Dream.
3. The ReMDM, RCR and Tolerator baselines are not in the release. They are not reconstructed and are counted as NOT_COMPARABLE (not run).
4. The TriviaQA/MATH random subsets are not released, so I re-drew subsets of the same size.

## Codebase completeness: MISSING_SCRIPTS

The method is fully implemented: calibration, KL-adaptive weight, threshold+consistency unmasking, p<q remasking with budget K and cool-down C, and fallback, for both models. I made **no edits** to the released code; everything ran through function arguments. What is missing and what I wrote:

- No evaluation pipeline at all: data loading/subsampling, prompts, chat formatting, generation loop over datasets, answer extraction, code execution, metric aggregation, step counting for Dream (the Dream function does not return a step count, so I count model forwards with a hook). I wrote this as `scripts/run_eval.py`, `scripts/score.py`, `scripts/aggregate.py`, `scripts/make_comparisons.py` and `scripts/worker*.sh`.
- No vanilla baseline code. I used the official LLaDA `generate.py` and Dream's built-in `diffusion_generate`, plus the EOS-penalty hook from the paper and the released code.
- No README, requirements, or hyper-parameter config. The function defaults differ from the paper (`calib_mode="fix"`; Dream `cool_down=0`; LLaDA `cool_down=2`) and must be set explicitly.
- Dream's `generation_config.json` has `mask_token_id: null`, and the released Dream function reads `model.generation_config.mask_token_id` by default, so I passed `mask_token_id` (151666, from `config.json`) explicitly. This is an argument, not a code edit.
- The TriviaQA/MATH subsets are not released (re-drawn with seed 0).
- The ReMDM/RCR/Tolerator baselines are not included.

## Discrepancies

- **[code_vs_paper] codebase/llada_DecoCal.py, generate_DecoCal, fallback step (4)** — severity **minor**; affects results: True.
  - Paper: Sec. 3.5 / Alg. 1 line 28: fallback unmasks the masked position with the highest *instantaneous* confidence c_t = p_t(v_t).
  - Code / other part: After calibration the variable p is overwritten with q, and the fallback ranks positions by x0_p = q(argmax logits), i.e. by the calibrated distribution (token still from instantaneous argmax).
- **[code_vs_paper] codebase/dream_DecoCal.py, generate_DecoCal, order of steps 2/3** — severity **minor**; affects results: True.
  - Paper: Sec. 3.4 / Alg. 1: remasking is applied before unmasking at each step.
  - Code / other part: Dream version unmasks (early lock) first and then remasks, excluding the positions locked in this step (LLaDA version follows the paper's order).
- **[code_vs_paper] codebase/dream_DecoCal.py, fallback step (4)** — severity **minor**; affects results: True.
  - Paper: Sec. 3.5: fallback commits exactly one token (the most confident masked position).
  - Code / other part: Dream fallback commits max(1, int(n_mask*(1-s/t))) tokens following Dream's linear time schedule over the 2L-step budget, and all remaining masks at the last step.
- **[code_vs_paper] codebase/calibrate_core.py, should_skip_remask (used by both models)** — severity **minor**; affects results: True.
  - Paper: Remasking is limited only by the per-position budget K and the cool-down C.
  - Code / other part: Remasking is additionally disabled entirely during the last C steps of the step budget (remaining_steps < cool_down). Not mentioned in the paper.
- **[code_vs_paper] codebase/*_DecoCal.py, generate_DecoCal default arguments** — severity **minor**; affects results: False.
  - Paper: Sec. 4.1: KL-adaptive weight (gamma=2), A=0.9, K=1, C=8 (C=2 TriviaQA).
  - Code / other part: Defaults are calib_mode='fix' (w=0.5, i.e. the 'fixed w' ablation), cool_down=2 (LLaDA) / 0 (Dream), A expressed as error=0.1 via an odds test q/(1-q) > 9 (strict >, paper uses >=); K defaults to steps//gen_length-1. Paper settings must be passed explicitly (no config/script provided).
- **[paper_internal] Table 3 (ECE)**; affects results: False.
  - Paper: Columns are described as min / mean / max ECE over tokens in a sequence.
  - Code / other part: Reported values are not ordered: Vanilla mean 0.5480 > max 0.3400; DecoCal mean 0.3283 > max 0.3050 — impossible for min/mean/max of the same quantity.
- **[paper_internal] Table 1 vs Table 8 (LLaDA-1.5, GSM8K, default DecoCal)**; affects results: False.
  - Paper: Table 1: 63.00 accuracy with 174.01 average steps.
  - Code / other part: Table 8 'Default': 63.00 accuracy with 170.66 average steps for the same setting.
- **[paper_internal] Appendix C.2**; affects results: False.
  - Paper: 'Table 8 presents the detailed statistics of Figure 3'.
  - Code / other part: Figure 3 is the unmask/remask heatmap; the trade-off plot that Table 8 details is Figure 2.

  - Code / other part: Table 1 lists 256 steps for Tolerator on Dream TriviaQA, inconsistent with L=64 single-pass decoding.
