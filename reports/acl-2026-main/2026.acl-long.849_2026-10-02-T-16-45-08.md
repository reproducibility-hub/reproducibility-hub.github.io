### Settings that differ from / are unspecified in the paper
- **Embedding inputs for LLM2Vec.** These embeddings are not unit-norm (norms 120–270). The README just says "save the encodings", so the primary results use the raw saved embeddings (`data/embeddings_raw`); the code normalizes internally only for labels and eval. With pre-normalized LLM2Vec embeddings, which is what the paper text implies, L2V-LLaMA SciFact drops to 0.792 peak (paper 0.884) and L2V-Mistral NFCorpus to 0.439. So the shipped hyperparameters evidently assume raw embeddings. Qwen and GritLM outputs are already unit-norm, so the question doesn't arise there.
- **Released defaults vs Table 9.** The released defaults (batch 32, wd 1e-4, no dropout) were used, not Table 9 (batch 256, wd 0.01, dropout 0.1). The Table-9 variant is consistently worse, e.g. Qwen-0.6B SciFact 0.807, GritLM SciFact 0.877.

## Why not fully reproduced
- **MS MARCO block.** "msmarco_subset_50k" is not released. Its baselines (Qwen-0.6B 0.562 NDCG@10) imply a much smaller test corpus than BEIR's 8.8M passages, and the paper doesn't describe how it was built. Reconstructing it would be guesswork, so it was not run.
- **OpenAI text-embedding-3-large.** Closed API, no key configured.
- **Adapter and Eclipse-PRF baselines.** "Our implementation"/"our reproduction" in the paper, but no code was released. Claims of beating them are NOT_COMPARABLE.

## Discrepancies
1. **code_vs_paper (minor):** the eval grid is hard-coded to 10% steps; the paper uses 2% steps.
2. **code_vs_paper (minor):** Table 9 says batch 256, weight decay 0.01, dropout 0.1. The code uses batch 32, wd 1e-4 and has no dropout. The code's settings are the ones that reproduce the paper; Table 9 settings are about 1–2 points worse.
3. **code_vs_paper (major, evaluation metric):** `ndcg_at_k` uses exponential gain 2^rel−1 and computes the ideal DCG only from the retrieved top-1000 list.
   - On binary SciFact this is identical to pytrec_eval.
   - On graded NFCorpus it inflates all numbers by about 0.015–0.02 (e.g. Qwen-8B full 0.433 vs 0.414 standard BEIR NDCG@10).
   - The paper's NFCorpus numbers match the code's variant, not standard BEIR. It affects every method about equally, so relative claims are unaffected.
4. **code_vs_paper (major, preprocessing):** the paper says embeddings are L2-normalized once. The code trains the predictor on raw saved query embeddings but feeds normalized ones at test time. For non-unit-norm encoders (LLM2Vec), the results depend heavily on whether the user pre-normalizes: L2V-LLaMA SciFact 0.882 raw vs 0.792 normalized.
5. **code_vs_paper (minor):** some shipped hyperparameters lie outside Table 9's search space (e.g. qwen-4b msmarco epoch 10, sgpt nfcorpus τ=0.5). These are not in the settings I ran.
6. **paper_internal:** Table 1 and Table 5 disagree for the same settings: Qwen-8B SciFact Ours 0.883 vs 0.899; GritLM NFCorpus Full 0.429 vs 0.439; GritLM MS MARCO Ours 0.632 vs 0.626.
