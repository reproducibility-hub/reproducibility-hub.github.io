# Reproduction report — 2026.acl-long.310
**Don't Click That: Teaching Web Agents to Resist Deceptive Interfaces (DUDE / RUC)**
Code: https://github.com/Ink0722/DUDE (linked from the paper). Data: HF `Ink0722/Real-UI-Clickboxes`.

## Verdict
- **Verdict: FAILED**
- **Result match (after fixes): NO_MATCH.** The vanilla baselines reproduce (sanity check). The one testable method claim, Table 4 "Stage-1 only" (SR 6.5 → 28.0), does not hold under the paper's own SR definition (a click inside the correct box): ground-truth SR is 3.5 (accepted click) or 7.0 (last click) vs 7.0 for vanilla. The paper's number is matched only by the release's metric (SR 30.5 vs 28.0). That metric counts the evaluator's own judgment of the click, not task success. The untrained base evaluator scores 44.5 on it.
- **Result match as released: DOES_NOT_RUN.** `src/config.py` raises `TypeError` at import, and even after that is fixed, the evaluator class has no `call_model`, so every judgment is silently `None`.
- **Coverage: SUBSET.** Table 4 Vanilla and Stage-1-only rows, plus the vanilla rows of Table 2 for all three agents, at full scale (200 tasks). The full DUDE (Stage-1 + Stage-2) rows of Tables 2/4/6/8 could not be run: Stage-2's experience summariser is GLM-4.6V via the ZhipuAI remote API, and no `ZHIPUAI_API_KEY` is available.
- **Codebase completeness: MISSING_SCRIPTS.** Details below.

## What the paper claims / what I targeted
- Table 2 / abstract: DUDE (Stage-1 GRPO-trained evaluator + Stage-2 experience) raises SR and cuts DFR on a 200-task RUC test suite (50 per domain).
  - This needs Stage 2, which calls the ZhipuAI API → **not runnable here**.
- Table 4 (Qwen3-VL-4B-Instruct agent, Qwen3-VL-2B evaluator): Vanilla 6.50 / 2.00 / 25.23 and Stage-1 only 28.00 / 5.50 / 5.80 (SR / DFR / Steps).
  - **Main reproducible target.**
- Table 2 vanilla rows for Qwen3-VL-4B, UI-TARS-1.5-7B and GLM-4.6V-Flash: baseline sanity check.
- Table 5 (full reward: eval pass 55.9%, fatal error 9.75%): evaluator-level check. Note that the paper doesn't say which set these were measured on.

## What I ran
Env: conda python 3.11, `pip install -r requirements.txt` (torch 2.8.0, transformers 5.0.0rc1, trl 0.26.2, peft 0.18.0). I also installed `zai-sdk`, because the pinned `zai==0.0.2` is an unrelated package without `ZhipuAiClient`. Hardware: 1×H200.

Data: `python data/download.py`.
- `train.json` has 250 samples (249 deceptive + 1 normal without a box). This gives 796 training / 200 held-out clicks.
- `eval.json` has 200 deceptive tasks, 50 per domain, matching the paper's test-suite description.

`.env`: `DEFAULT_AGENT_MODEL=Qwen/Qwen3-VL-4B-Instruct`, `DEFAULT_EVAL_MODEL=Qwen/Qwen3-VL-2B-Instruct`. The paper says 2B-Instruct; the README `.env` example says 2B-Thinking.

1. **Stage-1, released config** (`train/stage1.py` `main()`): 1 epoch, LR 1e-5, per-device batch 2, 2 generations, LoRA r=8 on q/v, TRL defaults otherwise (β=0, no grad-accum, sampling temperature 1.0). 796 steps, ~20 min.
   - Launched as `python -c "import src; from train.stage1 import main; main()"`. The README's `python train/stage1.py` shadows HF `datasets` with `train/datasets.py`, and `python -m train.stage1` hits a circular import.
   - Training reward rose from ≈ −25 to ≈ −1.5, like the paper's Fig. 4.
2. **Stage-1, paper config** (`scripts/stage1_paper_cfg.py`, Appendix B.3 / Table 15): 3 epochs, grad-accum 8 (effective 16), KL β=0.05, max-grad-norm 0.2, wd 0.01, cosine, warmup 0.1, temp 0.7, top-p 0.8, seed 42.
   - 300 optimizer steps, ~1h40.
   - I set `steps_per_generation=1` so each reward call sees one prompt. The reward function reads boxes and click only from sample `[0]` of the batch.
3. **Agent inference** with `scripts/run_inference.py`, a thin driver around `agent_runner/run_agent_with_evaluator.py` on all 200 tasks of `eval.json` with Tmax=3.
   - Greedy decoding (`do_sample=False`), as the paper says (temperature 0). The released code samples with the model's default temp 0.7 / top-p 0.8; I also ran that ("sample").
   - The driver caches the agent model instead of reloading it for every sample.
   - Vanilla mode (no evaluator; my reconstruction, since the release has no vanilla runner): the click tool just reports "executed" and the episode ends.
4. **Scoring**: `scripts/score.py` computes three kinds of metric.
   - The release's metric:
     - `rel_SR` = evaluator's last judgment is 1.
     - `rel_DFR` = evaluator's last judgment is −1.
   - The paper's definition (App. F.1), checked against the ground-truth boxes:
     - `gt_exec`: the first click the evaluator accepted (= the click that is executed under DUDE gating; for vanilla, the click).
     - `gt_last`: the last proposed click.
   - SR means the click is inside the correct box; DFR means it is inside the dark (deceptive) box.
5. **Evaluator classification** (`scripts/eval_evaluator.py`, greedy).
   - Pass rate (judge == label) and fatal C4 rate (deceptive click judged 1).
   - Run on the held-out 20% Stage-1 split and on clicks generated from `eval.json`.
   - Done for the base, released-config and paper-config evaluators.

### Interpretation
- With ground-truth scoring, the vanilla baselines match the paper closely for all three agents. So the RUC eval set, the agent scaffold and the paper's GT metric are consistent for vanilla.
- With the same scoring, the Stage-1 evaluator **does not** raise task success; it lowers it, because correct clicks get rejected.
  - Qwen-4B: 7.0 → 3.5.
  - UI-TARS: 42.5 → 19.0, while DFR falls only 23 → 17.
- The paper's Stage-1 SR (28.0) is reproduced only by the code's metric, `in_correct_eval = (last_judge == 1)`. That metric is the evaluator's own approval of the click, not ground-truth success.
  - The untrained evaluator scores even higher on it (44.5).
  - DFR under that metric is 0 by construction, since a −1 judgment means the click was blocked.
- The likely explanation is that the DUDE rows in the paper were computed with this self-judged metric and the vanilla rows with ground truth. I cannot prove this; it is an inference from the numbers.
- Steps in the paper (25.23, 5.80, …) exceed Tmax=3 and cannot come from the released loop.
- About half the Qwen-4B episodes (51%) never call `click`: the agent emits `<final_answer>` directly. This is the released ReAct loop's behaviour, and it holds identically for vanilla, whose numbers match the paper.

## Why not fully reproduced
1. **External blocker:** Stage 2 (experience summarisation, part of every "w/ DUDE" number in Table 2, Table 4 "+Stage-2" rows, Tables 6 and 8) calls `glm-4.6v` through the ZhipuAI remote API, and no `ZHIPUAI_API_KEY` is configured.
2. **Release gaps:** even with a key, the Stage-2 experience is never fed into inference.
   - `agent_runner` sets `experience="To be update"`, and the evaluator's `system_prompt` has the experience block commented out.
   - `stage2.py` crashes on import (`from src.template import static_template`).
3. **Stage-1 claim not reproduced** under the paper's GT metric (see above). Under the code's metric it "matches", but that metric is not task success.

## Discrepancies
- **code_vs_paper, major — metric** (`agent_runner/run_agent_with_evaluator.py: run_one_sample/finalize_metrics`).
  - Paper App. F.1: SR = executed click inside the correct box Bc; DFR = click inside the dark box Bd.
  - Code: SR = `last_judge == 1`, DFR = `last_judge == -1`, i.e. the evaluator's own judgment, with no ground-truth check (`ClickEnv.inside_box` is unused).
  - Affects results: yes.
- **code_vs_paper, major — Stage-2 not used at inference.** The paper injects the learned experience into the evaluator prompt; the code never loads `exp.txt` (placeholder `"To be update"`, block commented out in `src/template.py`).
- **code_vs_paper, minor — Stage-1 hyperparameters.**
  - Paper: 3 epochs, grad-accum 8, KL 0.05, clip 0.2, wd 0.01, cosine, warmup 0.1, temp 0.7, top-p 0.8.
  - `stage1.py main()`: 1 epoch, no grad-accum, TRL defaults (β=0, temp 1.0, linear schedule).
  - This changes the evaluator substantially: one collapses to always-0, the other is near-random.
- **code_vs_paper, minor — decoding.** Paper: temperature 0 / greedy at eval. Code: model default sampling (temp 0.7, top-p 0.8).
- **code_vs_paper, minor — evaluator model.** Paper: Qwen3-VL-2B-Instruct. Code default and README `.env`: Qwen3-VL-2B-Thinking.
- **code_vs_paper, minor — Stage-2 settings.** Code: `BATCH_COUNT=25, K=17, MAX_ITERATIONS=5`. Paper App. H: |Bf|=15, |Bs|=5, ~50–60 iterations.
- **code_vs_paper, major — training data / split.** Paper Table 13: train 985 (637 normal + 348 deceptive) / valid 212 / test 210, stratified. Released `train.json`: 250 deceptive-only samples, randomly split 80/20 inside `stage1.py`.
- **paper_internal — Steps.** Sec. 5.1 / App. F.3 bound Steps by Tmax=3, yet Tables 2, 4 and 7 report 25.23, 28.67, 5.80, 6.49 and similar. The deceptive-click penalty of 10 cannot explain 25+, nor 5.86 with DFR=0.
- **paper_internal — test suite.** Sec. 5.1 says the test suite is 200 tasks (50 per domain); Table 13 lists a 210-sample test split with normal samples.
- **paper_internal — software stack.** App. B.2 lists transformers 4.40 / trl 0.8.6 / PyTorch 2.1, which cannot load Qwen3-VL. The release pins transformers 5.0.0rc1 / trl 0.26.2.
- **paper_internal — GLM-4.6V-Flash.** Called "closed-source / accessed via remote API" (Sec. 5.1, B.1), but it is an open-weights model, and the code runs it locally (`GLMFlashBackend`).
