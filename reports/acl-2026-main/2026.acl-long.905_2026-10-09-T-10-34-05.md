# STK-Adapter (ACL 2026, 2026.acl-long.905) — reproduction report

- **Verdict: PARTIALLY_REPRODUCED**
- **Result match (after fixes): TREND_MATCH.** Hit@1 and Hit@3 are within tolerance. Hit@10 is 4.4 points below the paper. STK-Adapter still clearly beats the RE-GCN encoder it builds on.
- **Result match as released: DOES_NOT_RUN.** The released code cannot train or evaluate unmodified (details below).
- **Coverage: SUBSET.** Only ICE14 with the REGCN encoder was run, with one training run instead of the paper's mean of 5. That is the only dataset/encoder combination for which the release ships data and an encoder checkpoint.
- **Codebase completeness: MISSING_SCRIPTS.** Training data was partially released, and the deleted TLR pipeline had to be recovered from git history. The RE-GCN top-k prediction step for hybrid scoring is missing. The inference glue is missing. Generation crashes.

## 1. What the paper claims and what was targeted
STK-Adapter places three MoE adapter modules into every layer of a frozen Llama3-8B:
- ST-MoE over TKG embeddings from a frozen evolving-graph encoder;
- EA-MoE over the event-chain text;
- CMA-MoE, cross-attention from text to the TKG embedding.

The model is trained for 2 epochs on TLR-retrieved event chains. Inference uses beam search (B=20) plus a hybrid LLM/TKG score (λ=0.1).

**Main claim (Table 1):** STK-Adapter beats embedding-based, LLM-based and hybrid baselines on ICE14, ICE18, ICE15 and WIKI with 4 different encoders.

**What the release contains:**
- ICE14 only: quadruples, the full test event chains, and **269 of 82,114 training event chains**;
- one encoder checkpoint, REGCN for ICE14.

**Target:** Table 1, row "STK-Adapter (REGCN)", ICE14 — Hit@1/3/10 = **37.26 / 52.86 / 67.57**.

**Also compared:**
- Table 1 REGCN (as a sanity check of the shipped encoder);
- Table 2 "-w/o Hybrid Score", computed offline from the same predictions with λ=0.

**Not run:**
- ICE18, ICE15 and WIKI: no event chains or encoder checkpoints are released.
- The TiRGN, CognTKE and LogCL encoders: no code or checkpoints.
- Every baseline except REGCN: no code. Comparisons against them are `NOT_COMPARABLE`.
- Ablations that need retraining (Table 2 rows other than w/o Hybrid Score), Tables 3–5 and 7, Figures 3–5 and 7: not enough time, since one training run takes about 23.5 h.

## 2. What was done (commands)
The environment is conda `env/` with Python 3.9:
- torch 2.3.0+cu121, transformers 4.46.2, peft 0.13.2, accelerate 1.1.1;
- torch_geometric 2.6.1 with torch_scatter / torch_sparse / torch_cluster (pt23cu121), dgl 0.6.1;
- versions follow the requirements.txt that was deleted from the repo HEAD but is still in git history (saved as `orig_requirements.txt`).

The LLM is `meta-llama/Meta-Llama-3-8B` from the HF cache. Steps:

1. **Recover the data pipeline.** The authors' `data_process/` (TLogic rule learning + TLR retrieval + JSON builder) was deleted from HEAD in commit 878c736. I restored it from git history into `recovered/`, with a working copy in `rebuild/scripts/`.
   - Rules: `python learn.py -d ICEWS14 -l 1 2 3 -n 200 -p 8 -s 12` on the released `train.txt`.
   - Chains: `rebuild/build_chains.py --split train|test` wraps the authors' `Retriever` class and reproduces steps 3 and 4 in memory. Its only change is a numeric instead of lexicographic time comparison.
   - **Validation against the released files:**
     - 7,986 of 8,616 test prompts (92.7%) are identical to the released `test_text_history_new.json`, with 98.1% history-line overlap;
     - 247 of the 269 released training rows are identical.
   - Final training file: the rebuilt chains for rows 0..81,844, plus the authors' released 269 rows for the tail.
   - Evaluation uses the **released** test chains.
2. **Train** (`runs/main/cmd.txt`, 23.5 h on one H200):
   ```
   python codebase/train.py --base_model <Meta-Llama-3-8B> --dataset ICEWS14 --peft_path codebase/base_tkg_encoder/ICEWS14 \
     --hidden_size 4096 --graph_hidden_size 400 --topk 1 --kg_adapter_hidden_size 8 --use_load_balancing_loss \
     --max_grad_norm 1.0 --num_epochs 2 --lr 2e-5 --weight_decay 0.01 --warmup_steps 1642
   ```
   - The CLI values set the paper's hyper-parameters; the code defaults differ (see Discrepancies).
   - Trainable parameters are 15,276,448 and the total is 8,045,537,696, exactly Table 3's 15.27M / 8,045.53M.
   - Mean training loss: epoch 1 = 2.02, epoch 2 = 1.78.
3. **RE-GCN top-k predictions for hybrid scoring.**
   - `Predicton_2_DDP.py` needs `top100_predictions.json`. It is not released, and no released script produces it.
   - I wrote `scripts/regcn_topk.py`: the released checkpoint and RecurrentRGCN code on the full snapshot graph, ground-truth history of 3 (the checkpoint was trained with `his3`), softmax probabilities. Output: `runs/regcn_top100_his3.json`.
4. **Evaluate** (`runs/eval_ep2a`, `runs/eval_ep2b`: two halves of the test set in parallel; `runs/eval_ep1` for the epoch-1 checkpoint):
   ```
   python codebase/Predicton_2_DDP.py --base_model <Llama-3-8B> --peft_model runs/main/ckpt/llama/ --dataset ICEWS14 \
     --peft_path codebase/base_tkg_encoder/ICEWS14 --alpha 0.9 --graph_scores_file runs/regcn_top100_his3.json \
     --eval_start 0|4308 --num_eval 4309|8617 --pred_log pred.jsonl
   ```
   - `--alpha` is the LLM weight, so λ = 1 − alpha = 0.1 as in the paper; the code default is 0.7.
   - Generation uses the released settings: 20 beams, 10 returned sequences, 5 new tokens.
   - `scripts/score.py` re-implements the released hybrid scoring in torch. It reproduces the logged ranking for 100% of epoch-1 queries and 4,308/4,308 first-half epoch-2 queries.
   - **Bug in my own helper option, corrected offline:** in the epoch-2 run, my newly added `--eval_start` option did not offset the RE-GCN score list. The second half was therefore hybrid-scored with RE-GCN scores of the wrong queries; its LLM outputs are unaffected. The reported epoch-2 numbers re-apply the identical hybrid formula offline, with correctly aligned RE-GCN scores, to the logged LLM candidates (`runs/eval_ep2/pred_ep2_full_realigned.jsonl`). The uncorrected value, 36.59 / 50.34 / 61.61, is kept in `runs/eval_ep2/scores_full.txt`. The option is now fixed in the code.

## 4. Why the release does not run as released (`result_match_as_released` = DOES_NOT_RUN)
- **Training data:** only 269 of 82,114 training event chains are shipped ("only a portion is shown here"). `TKGAdapterDataset` pairs `train.txt[i]` with `train_text[i]`, so as released it would train on misaligned or partial data. The TLR scripts that generate the chains were deleted from HEAD.
- **Inference:** `Predicton_2_DDP.py` cannot run unmodified:
  - the dataset class only serves the training split and returns 2-tuples, while `collate_fn_test` needs `(quad, text, graph_scores, graph_emb)`;
  - `top100_predictions.json` is required but neither shipped nor produced by any script;
  - checkpoint shard names are hard-coded for a 3-shard model, so an 8B checkpoint (4 shards) would be silently **not loaded** (`strict=False`);
  - `generate()` with the default `use_cache=True` crashes (`KeyError: 'sa_key_value'`) because the custom decoder layers never return their KV cache.
- **Training script:**
  - `train.py` calls `model.module...`, which crashes without DDP, e.g. on 1 GPU;
  - `save_pretrained` crashes because `config.device` is a `torch.device` and is not JSON-serializable.

## 5. Codebase completeness: MISSING_SCRIPTS
Edits to `codebase/` are left uncommitted; the full diff is in `codebase_changes.diff`.
- `train.py`:
  - use `model.module` only if the model is DDP-wrapped (single-GPU crash);
  - save a checkpoint after each epoch (added, so a partial run could be evaluated).
- `utils/model.py`: `model_config.device = str(args.device)` (JSON-serialization crash at save).
- `lora/model.py` — implemented KV caching for generation. It shares one transformers `DynamicCache` across the HF self-attention modules and returns it from every layer. This is the only logic change; it is numerically equivalent: 29/30 test queries give identical candidates with and without the cache, and the remaining one differs by fp noise. Without it, generation needs `use_cache=False`, which runs at about 19 s/query and is infeasible.
- `Predicton_2_DDP.py`:
  - point the dataset to the test split and RE-GCN scores (new `--graph_scores_file`);
  - load safetensors shards by glob;
  - `--num_eval` / `--eval_start` options;
  - per-query JSONL log;
  - `use_cache=True` (after the fix above).

**Scripts written or recovered outside the codebase:**
- `recovered/data_process/` and `rebuild/scripts/`: the authors' TLR pipeline from git history, with paths adapted;
- `rebuild/build_chains.py`: retrieval wrapper;
- `scripts/regcn_topk.py`: missing RE-GCN top-k prediction file;

## 6. Discrepancies (code vs. paper, and within the paper)
Also listed in `status.json`.
1. **Major — EA-MoE routing.** The paper (Eq. 5) has an event-aware router that shares one routing signal across the tokens of an event, computed from that event's time-token hidden state. The code routes every token independently (`TokenRouter` on each token's hidden state); there is no event or time-token logic.
2. **Major — CMA-MoE routing.** The paper routes from the TKG representation H_g. The code's `router_cross` routes on the down-projected *text* hidden states.
3. **Major — Adaptive fusion.** The paper (Eq. 8–9) uses a dynamic gating network and an additive residual (Ĥ_text + H_enh + H_FFN). The code uses one learned scalar sigmoid gate g, with the same module used twice:
   - `text = g·EA + (1−g)·CMA`;
   - `out = residual + g·FFN + (1−g)·text`.

   So the frozen FFN output is also scaled by g (0.5 at init), and the gate does not depend on the input.
4. **Major — Evolving-graph encoder path** (`rgcn/utils.build_sub_graph`, `rrgcn.forward`, PyG `UnionRGCNLayer`) that produces the TKG embedding fed to the LLM:
   - The subgraph is rooted on the subject **and the ground-truth object** of the query, including at test time.
   - The subgraph keeps local node order, but its embeddings are mixed with globally indexed embeddings and the subject row is read by global id. The "subject embedding" is therefore generally another node's state. Verified: for test query 0 (subject 17), row 17 is global node 14.
   - Message passing is a plain sum of neighbour states, without the relation embeddings or `weight_neighbor` that RE-GCN uses.

   We ran this code as released.
5. **Minor — `args.py` defaults differ from the paper** (all set to the paper's values via CLI in our run):

   | setting | code default | paper |
   |---|---|---|
   | `topk` | 4 (dense) | 1 |
   | `kg_adapter_hidden_size` | 128 | 8 |
   | `hidden_size` | 3072, with a `Meta-Llama-3-3B` default path | 4096 (Llama3-8B) |
   | `num_epochs` | 1 | 2 |
   | gradient clipping | none | 1.0 |
   | warmup | constant, 20 steps | linear warmup, ratio 0.01 |
6. **Minor — Auxiliary loss.** The default is the HMoRA divergence loss; the paper's load-balancing loss (Eq. 11) is only used with `--use_load_balancing_loss`, which we set.
7. **Minor — Precision.** The code uses fp16 mixed precision (training weights bf16, inference fp16); the paper says BF16.
8. **Minor — Hybrid weight.** The default alpha is 0.7 (λ=0.3); the paper uses λ=0.1.
9. **Minor — Evaluation range.** The released eval script only scores the first 7,999 of 8,616 test queries (`select(range(8000))` with an off-by-one).
10. **Minor — Data split.** The paper (Table 6, Sec. 5.1.1) describes an 8:1:1 split with 74,845 / 8,514 / 7,371 queries. The release has 82,114 training queries (timestamps 0–328, i.e. train + valid merged) and 8,616 test queries (329–364), with no validation set. Table 1's REGCN numbers are reproduced on the released split, so the experiments evidently used it.
11. **Minor — Encoder history length.** The encoder checkpoint was trained with history length 3 (`his3`), but STK-Adapter feeds it 2 snapshots (`train-history-len=2`).
12. **Paper-internal.** In Eq. 11, α is the load-balancing coefficient. Appendix F.1 says both "the auxiliary load-balancing loss weight is set to 0.01" and "α is set to 0.1".
