**Why not REPRODUCED:**
1. **Table 3 (HR-Benchmark) could not be scored.** Its judges are closed APIs (DeepSeek-Chat / Qwen-Plus) and no key is configured. I generated the AALawyer outputs for all 200 cases with the released pipeline, but couldn't score them.
2. **The training stage (IPT + SFT) could not be re-run.** The training corpora are referenced only by the authors' local paths and are not released. All evaluation used the released merged checkpoint.
3. **The BGE-v1.5 baseline in Table 2 does not reproduce.** Re-running the released script gives a much *stronger* baseline (F1 48.4 vs 24.26). It is still far below SCR, so the ranking is unchanged.

## What I ran

Environment: conda env at `./env`, Python 3.9.21, torch 2.6.0+cu124 (as `env.yml`), plus vLLM 0.8.5 for fast generation, which pulled in transformers 4.57.6. The paper's transformers 4.45.2 was installed into `env/pylib_t445` and put on `PYTHONPATH` for the authors' HF scripts. GPU: 1× H200.

1. **Re-scored the released predictions** (`codebase/ckpt/predictions/zero_shot/output_results_*`, `codebase/c/baseline_predictions*`) with the released LawBench evaluator (`LawBench/evaluation/main.py`) and the released Table 2 metric. These reproduce the paper's numbers exactly:
   - Table 1 rows for DeepSeek-7B, Qwen3-8B and InternLM3-8B.
   - The AA-LeLLM single-run values used in Tables 13/14: FAP 88.94, CP 57.05, DFI 20.20, MDI 46.24, ITI 40.20, ED 81.31.
   - Every Table 2 baseline row.
   - The Table 4 csvs and Table 6.
2. **LawBench, Table 1 + Table 14 (main experiment)**, all 11 tasks used by the paper (`3-1,3-3,3-8,3-7,2-5,2-6,2-7,2-2,2-3,2-4,2-9`, 500 samples each, zero-shot):
   - (a) `scripts/gen_lawbench.py` is a vLLM re-implementation of `LLaMA-Factory/a/evab.py`. It keeps the identical prompt, the "You are Qwen…" system prompt, the chat template, the identical token ids (including the double BOS that `evab.py` produces), and the HF default sampling from `generation_config.json` (do_sample, T=0.6, top_p=0.95, 2048 new tokens).
     - Released AA-LeLLM: seeds 0/1/2.
     - Base DeepSeek-R1-Distill-Qwen-7B: seeds 0/1/2. The current HF chat template appends `<think>\n`; I removed it to match the authors' outputs, which were made with the older template. I then applied the authors' `clean.py` regex that removes the `<think>` block.
   - (b) **As released:** the authors' HF script, run once. Command: `PYTHONPATH=env/pylib_t445 WANDB_MODE=disabled MODEL_PATH=models/LeLLM_m20 LAWBENCH_DATA=… PRED_ROOT=runs/asreleased python LLaMA-Factory/a/evab.py --experiment_id m20 --device 0 --mode zero_shot --max_new_tokens 2048`.
   - Scoring: `python LawBench/evaluation/main.py -i <dir> -o results.csv` (`scripts/score_runs.sh`).
3. **Table 2 (FAP retrieval):**
   - SCR row: computed from the 3-1 predictions above with the same parsing as LawBench (`scripts/scr_retrieval_metrics.py`). Precision/recall are micro-averaged and F1 is averaged per sample, as in `c/analyze_final_results2.py`.
   - Baselines: re-run with the released `c/test_baselines_law.py` (BM25 k=1..3; BGE-m3 k=1..3 and τ 0.40–0.80 within top-5; SAILER k=1..3 and τ 0.40–0.90 within top-10) and `c/test_baselines_v15.py` (BGE-v1.5 k=1..3 and τ 0.80–0.99). Driver: `scripts/run_retrieval.sh`.
   - The law corpus `RAGDatabase1_v2.json` is not released, so I used the released `aiEval/HRBench/data/RAGDatabase_v2023_v3.json` (452 articles, covering every article ID the released baselines predicted).
4. **Table 4 (hallucination risk, 150 cases, no judge):**
   - Vanilla 4-1/4-2 generations: `gen_lawbench.py --tasks 4-1,4-2`.
   - SCR step: `scripts/gen_scr_articles.py`, a vLLM port of `LLaMA-Factory/a/generate_auth.py` (greedy, 512 tokens, RAGDatabase_v2023_v3).
   - Scoring: `scripts/score_table4.py`, which uses the same functions as `LawBench/evaluation/mainv4.py` (`acc.compute_ljp_article`, `authen_simple.*`), with the reference DB set to v2023_v3.
5. **Table 6 (long tail):** `scripts/longtail_eval.py` on the released 26-item subset `aiEval/HRBench/data/longtail_fromtrain_dataset.json`.
6. **Table 3 pipeline, without the judge:**
   - Built the APR FAISS index over the released 172,455-case database with `b/rag2_builtfaiss.py` (bge-large-zh, IndexFlatL2).
   - Ran `aiEval/generate_response_json_m20.py` (HF greedy, transformers 4.45.2) on the 200 HR-Benchmark cases. Output: `runs/hrbench/generated_200_m20.json`, with all 4 variants: no-RAG, SCR, SCR+APR and APR-only.
   - Not scored: `aiEval/HRBench/eval_dp_200_final.py` needs a DeepSeek API key. As a judge-free sanity check, the SCR article F1 on those 200 cases is 0.740.

### Settings that differ from the paper
- **No training:** I used the released checkpoint. The paper trained on 4×RTX 4090.
- **Generation backend:** for the 3-seed runs I used vLLM, not HF `generate`, with the same sampling parameters. The authors' HF script was run once as well, and its numbers agree.
- **Law corpus:** `RAGDatabase_v2023_v3.json` replaces the unreleased `RAGDatabase1_v2.json`, both for the retrieval baselines and as the Table 4 Auth reference.
- **Base-model chat template:** I removed the trailing `<think>\n` that today's DeepSeek-R1-Distill template appends, to match the authors' outputs.
- **Baselines not re-run:** the other Table 1 baselines (LawGPT, LexiLaw, HanFei, Wisdom-Interrogatory, Fuzi-Mingcha, Qwen3-8B, InternLM3-8B). Their released predictions re-score exactly to the paper.

## Codebase completeness: MINOR_FIXES

The method (SCR = the fine-tuned model's article-number generation followed by a database lookup; APR = bge + FAISS case retrieval), the evaluation scripts and the checkpoint are all released. The main evaluation ran after path-only edits. All edits are left uncommitted in `./codebase`; the full diff is in `codebase_changes.diff`.

Changes to released code (no logic changes):
- `LLaMA-Factory/a/evab.py`: hard-coded model, data and output paths replaced by env-var overrides (defaults kept). The script imports `wandb`; I installed it and ran with `WANDB_MODE=disabled`.
- `c/test_baselines_law.py`, `c/test_baselines_v15.py`: hard-coded test file, corpus file, output dir and BGE-v1.5 model path replaced by env-var overrides.
- `b/rag2_builtfaiss.py`, `aiEval/generate_response_json_m20.py`: hard-coded paths replaced by env-var overrides. I commented out `os.environ["CUDA_VISIBLE_DEVICES"]="0"` (Slurm already sets it).

Environment fixes:
- vLLM needs a newer transformers, but FlagEmbedding 1.3.4 fails with transformers 4.57 (`GEMMA2_START_DOCSTRING` import error). So the paper's transformers 4.45.2 sits in a side directory (`env/pylib_t445`) for the HF/FlagEmbedding scripts.
- LawBench's `main.py` calls `python3` through a subprocess (task 2-1, not used here), so `env/bin` must be on `PATH`.

Scripts I wrote (in `./scripts`):
- `gen_lawbench.py`: vLLM port of `evab.py`, for speed.
- `gen_scr_articles.py`: vLLM port of `generate_auth.py`.
- `score_table4.py`: same computation as `mainv4.py`, but with the reference DB and SCR file as arguments.
- `score_retrieval.py` and `scr_retrieval_metrics.py`: the `analyze_final_results2.py` metric, plus LawBench parsing for the SCR row.
- `longtail_eval.py`, `score_runs.sh`, `run_retrieval.sh`, `run_hrbench_gen.sh`, `run_evab_asreleased.sh`, `chain*.sh`: drivers.
- `score_table.py`: table formatting.

Missing pieces (noted, but they don't block the main evaluation):
- **IPT/SFT training data.** The entries `articles-all`, `legal-instrument-all`, `articles-only-penal`, `accusations` and `nine_sft_tasks` in `LLaMA-Factory/data/dataset_info.json` point to `/mnt/ssd_2/...` and are not released, so the training stage can't be reproduced. The merged checkpoint is released on HF.
- **`RAGDatabase1_v2.json`** (law corpus for the Table 2 baselines and the Table 4 Auth reference) is not released. Released v2023 variants were used instead.
- **HR-Benchmark judge.** The judge script has a placeholder API key; it needs DeepSeek / Qwen API access.
