Code: https://github.com/pengqian-lu/TPA, the repo linked in the paper (commit `f433e63`). It contains:

## TL;DR

1. **RAGTruth, LLaMA family (Table 1 top).** Running `3_detect_ragtruth.py` unchanged on the shipped features reproduces every TPA number **exactly** (mean and std over 5 seeds) for Llama2-7B, Llama2-13B and Llama3-8B.
2. **Re-running the method from scratch** (step 1 with the patched fork, then step 2) produces features that match the shipped ones (per-token corr ≥ 0.998) for every model:
   - Dolly: all 3 models, all samples;
   - RAGTruth: Llama3-8B, all samples; Llama2-7B, all 2,965 samples;
   - subsets of 29–30 samples each for Llama2-13B, Mistral-7B and Qwen3-8B.

   Step 2 reproduces the shipped POS tags 100%. Detection on our own from-scratch features:
   - Llama2-7B: F1 0.7264 / AUC 0.7905 / Recall 0.8399 vs paper 0.7238 / 0.7873 / 0.8328.
   - Llama3-8B: F1 0.7799 / AUC 0.8153 / Recall 0.7835 vs paper 0.7843 / 0.8211 / 0.7860.

   So the full method reproduces end to end from raw data.
3. **Mistral-7B (Table 2).**
   - The released pipeline reproduces the paper exactly (F1 0.8702 / AUC 0.9096 / Recall 0.9200), but only because of a data bug. The shipped `attribution_feature_mistral-7B-instruct_proc_0.csv` has **no header row**, so `pd.read_csv` eats its first row as the header and all 741 samples in that shard (614 train, 127 test) silently drop out.
   - The paper's Table 2 TPA numbers are therefore computed on **323 of the 450** RAGTruth-Mistral test responses, with ~76% of the training data.
   - After adding the missing header (and re-running the released step 2 to POS-tag the recovered samples), the released detection on the full data gives **F1 0.8090 / AUC 0.8553 / Recall 0.8980**.
   - TPA still edges out the paper's Novo numbers (0.8000 / 0.8419 / 0.8765), but the claimed "~7% F1 gain over Novo" shrinks to ~1 point.
4. **Qwen3-8B (Table 3).** Using the shipped responses, Opus labels and features: `qwen3_6_detect_tpa.py` with the paper's 50 Optuna trials gives F1 0.5991 / AUC 0.8243 / Recall 0.7111. With the README's 100 trials it gives 0.6021 / 0.8244 / 0.7130. Paper: 0.6006 / 0.8236 / 0.7130.
5. **Dolly (AC) (Table 1 bottom).**
   - The main `3_detect_dolly.py` **does not run as released**. It needs 99 per-fold Optuna studies in `results/new_dolly_*_ultimate_nested_optimization_trials.db`. The DBs are git-ignored and not shipped, and the script that creates them is absent.
   - We wrote the missing nested search from the paper's Protocol III description and then ran the unmodified `3_detect_dolly.py`. TPA comes out far below the paper on Llama2-13B (F1 0.686 vs 0.8075, AUC 0.707 vs 0.8159) and Llama3-8B (F1 0.522 vs 0.7529, AUC 0.673 vs 0.7608).
   - The released alternative path (`3_detect_dolly-nopostag.py --feature_mode pos`) gives similar numbers.
   - The paper's Rank-1 Dolly claims for 13B and 8B do not reproduce.
6. **Table 5 (aggregation ablation).** The released `*-nopostag.py` scripts reproduce every TPA-Mean / TPA-Stat number **exactly** (RAGTruth ×4, Dolly ×3). However, the claim "TPA-POS wins in all seven settings" fails when POS is evaluated the same way:
   - With the uniform Dolly protocol, POS loses to Mean/Stat on Dolly-7B and Dolly-8B.
   - On full-data Mistral, POS 0.8090 < Mean 0.8093 < Stat 0.8102.

## Why it is not fully reproduced

1. **Mistral (Table 2, Table 5).** A shipped feature file is missing its CSV header, so the released pipeline silently evaluates on 323/450 test samples and ~76% of the training set. The paper's numbers equal this buggy evaluation. With the full split, TPA drops by ~6 F1 / ~5.4 AUC points.
2. **Dolly (Table 1 bottom).**
   - The main script depends on per-fold Optuna studies that are not released, and the nested search script is not in the repo.
   - Our reconstruction follows the paper's description (50 TPE trials per LOO fold, 5-fold stratified-CV F1, Table 4 search space). Neither it nor the released global-search variant comes close to the paper's 13B/8B numbers.
   - These results depend on how the missing search was done, so we cannot tell whether the paper's Dolly numbers come from a different (unreleased) objective or protocol.
3. The **Figure 4 component-exclusion ablation** has no code in the release and was not run.

## Discrepancies

1. **code_vs_paper, major, affects results.**
   - Where: Table 2 / Table 5 Mistral vs shipped `attribution_feature_mistral-7B-instruct_proc_0.csv`.
   - Paper: evaluation on the RAGTruth Mistral train/test split (450 test responses).
   - Release: the headerless shard makes the released pipeline use 2,224/2,965 samples (323 test). The reported numbers match this reduced evaluation. On full data: F1 0.8090 vs 0.8702, AUC 0.8553 vs 0.9096.
2. **code_vs_paper, major, affects results.**
   - Where: Table 5 Dolly.
   - Paper: TPA-POS vs TPA-Mean/Stat presented as an ablation of the aggregation step only.
   - Release: POS numbers come from `3_detect_dolly.py`, i.e. per-fold nested Optuna DBs, 45% eval split, no early stopping, seeds 6–10. Mean/Stat numbers come from `3_detect_dolly-nopostag.py`: one global Optuna search, 20% split with early stopping, seeds 1–5.
   - Under the same released protocol, POS gives 0.690 / 0.660 / 0.536, losing to Stat/Mean on 7B and 8B.
3. **code_vs_paper, minor, affects results.**
   - Where: `3_detect_dolly.py` ensemble training.
   - Paper (App. C): each member is trained on an 85%/15% split with early stopping (patience 50) and n_estimators = 1000.
   - Code: `test_size=0.45` eval split, no early stopping, and n_estimators left at the XGBoost default unless it is in the Optuna params.
4. **code_vs_paper, minor, affects results.**
   - Where: `LlamaDecoderLayer.forward` (and the Mistral/Qwen3 equivalents) in the fork.
   - Paper: Eq. 13 sums raw attention weights over exhaustive index sets I_Qry = [1, Tq], I_RAG, I_Past, I_Self.
   - Code: query/RAG indices cover only the query and RAG text spans. Chat-template and BOS positions (attention sinks) belong to no source, and the four source weights are renormalised to sum to 1 per head (`total_weights`).
5. **paper_internal, affects results.** Eq. 13 (unnormalised attention sums) vs Appendix E (∆P_S = Σ_h ∆P_h · w_{h,S} / Σ_all sources w_{h,·}).
6. **paper_internal.** App. C Protocol III says Dolly has N = 100 with 99 training samples per LOO fold. The Dolly (AC) release has 99 responses per model (98 per fold).
7. **code_vs_paper, minor, affects results.**
   - Where: Qwen3 detection.
   - Paper: 50 Optuna trials.
   - README: `--n_optuna 100` for the headline numbers. 50 trials gives F1 0.5991, 100 trials gives 0.6021.
8. **code_vs_paper, minor.** App. C says Qwen3 attribution used a fork of Transformers 4.55.0. The release uses the same `transformers-4.56.1` directory (actually 4.57.0.dev0) for all models.
9. **code_vs_paper, minor, affects results.**
   - Where: step-1 precision.
   - Paper: unspecified (only "fp32" for Qwen3 generation).
   - `1_get_attritbution_ragtruth_llama2.py` uses fp32, yet the shipped RAGTruth Llama-2/Mistral features are fp16-quantized.
   - `1_get_attritbution_dolly_llama2.py` uses fp16, which overflows for Llama2-7B: 595 of 8,898 Dolly tokens are NaN and are silently skipped in the per-POS means. The Llama-3 scripts use bf16.
   - The differences are small (corr ≥ 0.999).
10. **code_vs_paper, minor.** The first response token y1 is never attributed: the loop starts by predicting response token 2. The paper's Algorithm 1 covers t = 1..T.

11. **code_vs_paper (README), minor, no effect on results.** The README's `python 3_detect_ragtruth.py --model_name llama-2-7b-chat` is rejected by argparse. The script accepts `7b/8b/13b/mistral-7B-instruct`.

## Notes

- The step-1 scripts write through a file handle whose buffer is sized by the filesystem block size (4 MB here), so CSV output lags ~150 samples behind progress until the process exits. This only matters for interrupted runs. For shard 3 of RAGTruth Llama2-7B we stopped the process right after a buffer flush and dropped its last (possibly partial) sample, which a helper process covers.

- Protocol II (Llama3-8B RAGTruth) tunes hyper-parameters once on all 447 samples before the 20-fold CV, so the test folds are seen during tuning. The paper says so explicitly ("prior to the cross-validation loop"), so it is not listed as a discrepancy.
- 447 of the 450 Llama3 test responses are present, both in the shipped features and in our re-extraction.
- We tried CUDA MPS to speed up the multi-process extraction, but the control daemon cannot create its socket on the scratch filesystem. We did not move it to /tmp, to stay inside the attempt directory.
