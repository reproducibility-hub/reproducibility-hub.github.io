## What the paper claims and what was runnable
- **Table 2 (main result).** VISTA accuracy is compared with FActScore and LLM-as-Judge on AIS (500 turns), BEGIN (500), FaithDial (2,229) and FADE (639), across 8 LLMs. This could not be run:
  - The release contains none of the benchmark samples and no preprocessing code. The paper doesn't say how the samples were drawn.
  - It contains no FActScore or LLM-as-Judge code.
  - GPT-5, GPT-4o and DeepSeek need API keys, and none are configured. DeepSeek-V3 (671B) is too large to host on one GPU.
  - Claims of the form "VISTA beats FActScore / LLM-as-Judge" are therefore **NOT_COMPARABLE** / not tested.
- **Table 3 / Figure 2 / App. F (human-evaluation subset).** The released `data/reannotated_data/human_eval_VISTA_input.json` holds 140 conversations, 227 scored turns and 888 consensus claims. I reproduced this for Llama-3.1-70B, Llama-3.1-8B, Qwen3-32B, Qwen3-8B and Mistral-7B-v0.3. Settings follow the paper (App. B): HF transformers, 4-bit bitsandbytes, greedy decoding, few-shot, no dialogue context in Stages 2/3.

## What I ran
Environment: conda env at `./env`, Python 3.10, with the unpinned `requirements.txt` installed as-is (torch 2.14.1+cu130, transformers 5.18.0, bitsandbytes 0.50.2). No compatibility fixes were needed. Hardware: one H200, with all 10 runs sharing it.

1. **Full released pipeline**, unmodified except the config values:
   `cd codebase/code_base; VISTA_MODEL=<m> VISTA_INPUT=../data/reannotated_data/human_eval_VISTA_input.json VISTA_OUTPUT=../../runs/out/released_<m>.json python run_metric.py`
   (driven by `runs/run_one.sh <m> released`). The outputs give VISTA's own claim decomposition and categories, used for Figure 2.
2. **Consensus claims through Stage 2/3**: `runs/run_human_claims.py` (`runs/run_one.sh <m> human`). This is the same loop as `run_metric.py`, except that annotated turns use the 888 human claims instead of Stage 1. Table 3 and App. F need this: one prediction per consensus claim.
3. **Evaluation**: `runs/evaluate.py` → `runs/results.json` and `runs/eval_final.txt`. It uses the release's `normalize.clean_category` to parse categories. For comparison I also ran the release's `normalize.py` + `metrics.py` on the step-1 outputs (`runs/released_metrics_py.txt`).
   - **Turn label (paper, Sec 6.1/6.2):** a turn is verifiable only if every claim is VERIFIED.
   - **Claim accuracy:** 5-class accuracy over the 888 claims.
   - **Macro-F1:** sklearn macro-F1 over the 5 classes.

How the paper's metric definitions were inferred:
- The Table 3 majority baseline turn accuracy is 83.26 = 189/227, which is exactly the share of turns with at least one non-verifiable human claim. So Turn Acc uses the strict label.
- GPT-5's App. F confusion matrix gives 724/888 = 81.53, matching its Table 3 Claim Acc.
- The Figure 2 bars match "strict prediction vs. original dataset label" and "strict prediction vs. strict consensus label" (see the table below).

## Discrepancies
1. **code_vs_paper, major** — `evaluation/metrics.py::predict_label`. The paper treats any non-VERIFIED claim as making the turn unverifiable (OUT-OF-SCOPE and ABSTENTION are merged into UNVERIFIABLE). The code counts OUT-OF-SCOPE and ABSTENTION as faithful. This changes reported turn accuracy by roughly 5–36 points.
2. **code_vs_paper, major** — the released `gold_label` field. It is "faithful" iff no claim is lacking-evidence or contradicted (all 227 turns follow this rule). The paper's Table 3 Turn Acc and Figure 2 "new" bars use the strict all-verifiable consensus label instead.
3. **code_vs_paper, minor** — Sec 3 says the Stage 3 prompt has n=9 few-shot examples. Both the code and App. A.1.3 have 8.
4. **code_vs_paper, minor** — the Stage-1 few-shot wording differs slightly from App. A.1.1 ("Dr. Ilsa" vs "Dr. Ilse", "Ohio State University" vs "OSU").
5. **paper_internal** — the Table 3 caption says the majority baseline predicts VERIFIED. But its Turn Acc of 83.26 corresponds to predicting every turn unverifiable; all-VERIFIED would score 16.74. Its macro-F1 also computes to 12.80, not 13.00.
6. **paper_internal** — Stage 3 has "n=9" examples in Sec 3 but 8 in App. A.1.3.
