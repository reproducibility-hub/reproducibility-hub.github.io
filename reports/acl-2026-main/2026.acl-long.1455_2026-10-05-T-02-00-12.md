## What was run

Everything ran in the conda env `env/` (Python 3.11.13; packages pinned from `requirements.txt` / `environment.yml`, with faiss-gpu 1.8.0 from conda) on 1×H200 with ~111 GB host RAM.

### 1. Main experiment: BGE-M3, full mMARCO (Sec. 4; Fig. 5–10; Tables 1–3, 11, 12)

- **Data.** Queries: `codebase/query_embedding_mix/download_mmarco_queries.py --split dev` (6,980 queries × 14 languages), evaluated on the released 1,484-qid list `configs/qid_lists/qids-common.tsv`. Collections: the 14 `*_collection.tsv` files (8,841,823 passages each) downloaded from `unicamp-dl/mmarco`, the same files the HF loader script uses. Qrels: `BeIR/msmarco-qrels` validation, the same as the scripts.
- **Why a driver was needed.** The released full-scale pipeline (`scripts/run_encode_index_groups.sh` + `scripts/run_all_vector_pairs.sh`) does not fit this machine:
  - it stores one fp32 `IndexFlatIP` per language (≈36 GB × 14 ≈ 500 GB), but only ≈350–430 GB of shared scratch was free;
  - the bilingual script rebuilds a combined CPU index from two cached indexes, needing over 100 GB of host RAM;
  - the run script searches all 6,980 queries on CPU FAISS (no `--gpu_faiss`).
- **The driver** (`repro/`) reproduces the same computation:
  - `repro/encode_queries.py`: BGE-M3 query encoding with the run script's settings (fp16, unnormalised encode, then torch L2 normalisation).
  - `repro/encode_search.py`: encodes each full collection exactly as `encode_multilingual_corpus.py` does (`dtype=auto` → bf16, `normalize_embeddings=True`, empty passages skipped). It stores vectors as fp16 and runs exact top-100 inner-product search on GPU in fp32 with TF32 off, equivalent to `IndexFlatIP` (checked identical to brute force). Mixed query vectors are built with the released `safe_mix()`, λ ∈ {0, .1, .3, .5, .7, .9, 1}. Embeddings are deleted after each language's search.
  - `repro/make_runs.py`: writes TREC runs in the released formats.
    - Mono: `\t`-separated, scores `.4f`, top-100.
    - Bilingual: top-100 over the L1∪L2 union with `base#lang` ids, scores `.6f`, then the released `collapse_run_max()`.
    - It then calls the released `evaluate.py` with the same CLI as `run_all_vector_pairs.sh`.
  - The job list (35 bilingual pairs, 70 mono jobs) is parsed directly from `run_all_vector_pairs.sh`.
- **Tables.** Built with the released `collect_results.py` and a copy of `calculate_paper_values.py` that differs only in reading `TABLES_DIR` from an env var (`repro/calculate_paper_values_ours.py`). ## Discrepancies

1. **code_vs_paper (minor, affects reported numbers): the released result tables don't match the paper's numbers.**
   - Where: `artifacts/tables/full_mmarco_*_results.csv` and `paper_values.txt`.

2. **code_vs_paper (minor): the 100k subset is not the one App. B describes.**
   - App. B: "exactly 100,000 documents in total… keep every encountered non-relevant document (no sampling)".
   - Ablation scripts (`--subset_neg_cap 100000 --neg_prob 1.0`): all 7,433 relevant + 100,000 non-relevant = 107,433 passages.
   - `reproduce_word_mix.sh`: uses `NEG_PROB=0.02`, i.e. randomly *sampled* negatives, so Fig. 3 and Table 4 use two different "100k" subsets.
3. **paper_internal: Qwen3-8B partner ranking (Sec. 5 "Scale" text vs. Table 4).**

4. **paper_internal (minor): Fig. 3a vs the released artifacts.** Fig. 3a labels the EN-docs embed peak "85.3409 @ 10%". The released `artifacts/examples/repro_en_zh_example` bundle peaks at 0% (85.32 vs 85.11 at 10%), as do our runs.
