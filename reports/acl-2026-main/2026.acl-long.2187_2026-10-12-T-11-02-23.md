# Reproduction report — Awakening Dormant Experts: Counterfactual Routing to Mitigate MoE Hallucinations (2026.acl-long.2187)

**Verdict: FAILED** · result match (after our fixes / re-implementation): **NO_MATCH** · as released: **DOES_NOT_RUN** · coverage: **SCALED_DOWN** (Qwen-3-30B-A3B only, half the paper's calibration tokens) · codebase completeness: **MISSING_CORE**

## TL;DR
* The repo (https://github.com/ZhaiYanbo/CoR) releases only the **offline** analysis: token stratification, layer sensitivity R_l + per-expert CEI, and the layer-budget allocation. The **online CoR router** is missing. Every inference script calls lm-eval backends `custom_our` / `custom_moe` that are not in the repo, and the FACTOR task configs are missing too. As released, the main experiment cannot run.
* We ran the released offline pipeline on Qwen3-30B-A3B (C4 validation calibration, δ=0.1, 10%/10% hard/easy split), re-implemented the CoR router exactly as Sec. 3.3 / Eq. 8-9 / App. A.3 describe (λ=0.1, layer-wise min-max CEI, constant total budget 384 = 48×8), and evaluated it on the paper's full benchmarks with lm-eval 0.4.9.
* **The Standard Top-8 baseline reproduces Table 1 closely** (all six columns within ≤1.1 points; average 48.62 vs 48.01).
* **CoR does not reproduce.** Our CoR averages **47.43 vs Standard 48.62** (paper: 49.95 vs 48.01). It is worse than Standard on 5/6 metrics; only TruthfulQA-Gen improves. The ablations show where the drop comes from. Layer-wise reallocation alone is roughly neutral (avg 48.42). The CEI fusion (Expert-wise only, avg 48.02) lowers FACTOR, MC2 and TriviaQA.
* Caveat: the authors' unreleased backend is invoked with `extra_mass=0.1, cei_temp=5.0`. `cei_temp` does not appear in the paper, so their fusion probably differs from Eq. 9 as written. Our negative result is for the method **as the paper describes it**.

## What was run (all on 1× H200, inside ./env)
1. **Token stratification** (released `token_stratification/getHardTokens_new.py` via `scripts/stratify_hard_easy.py`): Qwen/Qwen3-30B-A3B (bf16) on the first 3,000 docs of C4 `en/c4-validation.00000-of-00008` (max_length 512): 831,119 tokens. Hard = top 10% NLL (≥ 90th pct), easy = bottom 10% (≤ 0.0055).
2. **Layer sensitivity + CEI** (released `layer_analysis/run_layer_sensitivity_sampled.py --comprehensive --perturbation_scale 0.1 --generate_topk`, perf-patched, `scripts/offline.sh`): calibration = 20 randomly sampled documents (the release's own `sample_tokens`), i.e. **510 hard tokens** + 1,039 easy tokens (paper: "1,000 tokens"). Output: `offline/sensitivity_results/` (R_l for 48 layers; CEI for 5,038 of 6,144 (layer, expert) pairs, since experts that never received a hard token get no score). Took ~1h50m.
3. **Layer budget**: released `get_layer_k_total.calculate_expert_allocation_budget` (robust, avg 8, k_min 6, k_max 10) → `configs/layer_k_budget_8_6_10.json` (sum 384). Per-layer k: [6, 7, 7, 6, 7, 6, 7, 9, 7, 9, 8, 7, 7, 8, 8, 8, 9, 9, 9, 9, 10, 9, 8, 8, 7, 8, 9, 8, 8, 7, 7, 6, 7, 6, 7, 7, 7, 7, 8, 7, 10, 10, 10, 10, 10, 10, 10, 10]. Eq. 8 gives an almost identical allocation (`configs/layer_k_budget_8_6_10_eq8.json`).
4. **Evaluation** (`scripts/eval_config.sh <name> <backend> <args>`; lm-eval 0.4.9, zero-shot, no chat template, bf16):
   * loglikelihood: `truthfulqa_mc1, truthfulqa_mc2, factor_news, factor_wiki` (batch 16)
   * `truthfulqa_gen` (built-in, BLEURT disabled; we report **bleu_acc** as "Gen". It matches the paper's Standard value best; rouge1/L acc are also logged)
   * `triviaqa_g32` = built-in `triviaqa` (rc.nocontext validation, 17,944 q, EM) with max_gen_toks 32 instead of 256. EM is computed on the text before the first `\n`/`.`/`,`, so the cap cannot turn a correct answer into a wrong one. It was needed because batches never stopped early and the full set took >6h per config.
   * Configs: `standard` = custom_moe, k=8 everywhere (bit-identical to HF Qwen3MoE, verified); `cor` = custom_our, layer_k + CEI fusion λ=0.1; `layer_only` = custom_moe with layer_k; `expert_only` = custom_our, k=8 + CEI fusion; `random` = k=8 experts drawn uniformly at random per token, router weights renormalised. This is our guess, since the paper only says 'activates random experts within the budget'. It collapses the model to chance level (~24% on 4-way FACTOR), far below the paper's Random row, so the paper must have used a milder scheme. Its generation tasks were skipped to save time, and the row is NOT_COMPARABLE.

### Our CoR implementation (scripts/cor_lm.py)
For every MoE layer l: p = softmax(router_logits); score = p + λ·MinMax_l(CEI_l) (missing CEI → raw 0, i.e. neutral, before min-max); select top-k_l experts by score; combine their outputs with p of the selected experts, renormalised (Qwen3 `norm_topk_prob`). The paper doesn't say which weights to use after fusion or how to treat experts without CEI, so both are our choices.

## Judgement
* About the per-row labels: they apply the tolerance rule mechanically (≤1 point absolute or ≤5% relative). Several Expert-wise-only rows (and CoR TQA-Gen) count as NUMBERS_MATCH by that rule, even though for most of them our effect vs. Standard has the opposite sign from the paper's (see the Δ rows). The overall judgement is based on the claimed effects.
* Standard baseline: NUMBERS_MATCH on all 6 metrics, which confirms the evaluation setup (prompting, FACTOR formatting, metrics) is the same as the authors'.
* CoR (the method's main claim, +1.9 avg on Qwen): **NO_MATCH**. With the method implemented as described, CoR is below Standard on average and on 5/6 metrics. The claimed improvement does not appear, and the ranking flips on MC1, MC2, FACTOR News/Wiki and TriviaQA.
* The release cannot produce any CoR number on its own (`result_match_as_released = DOES_NOT_RUN`): the core online routing code is missing (**MISSING_CORE**). Our negative result may come from implementation details only the authors' unreleased backend has (the `cei_temp` fusion, which weights to use after fusion, CEI computed on a larger calibration set). That cannot be checked without their code.
* Coverage SCALED_DOWN: only the Qwen-3-30B-A3B block of Table 1, and calibration of 510 hard tokens instead of ~1,000. DoLa/ITI not run.

## Discrepancies
* **[code_vs_paper, major]** `layer_analysis/layer_sensitivity_analyzer_fast.py: compute_expert_cei_scores_batch_fixed / ablation_hook` — paper: Eq. 5: virtual ablation removes expert e and redistributes its gating mass proportionally over the remaining (k-1) selected experts. — code: Sets the router logit of e to -1e4 before Qwen3's softmax/top-k, so e is replaced by the next-ranked (9th) expert and k stays 8; the counterfactual is 'swap e for the runner-up', not 'drop e'. (affects results: True)
* **[code_vs_paper, minor]** `expert_analysis/get_layer_k_total.py (calculate_expert_allocation_budget)` — paper: Eq. 8: k_l = Round(K_total * R_l / sum_j R_j). — code: Robust (5th-95th percentile clipped) min-max normalisation of R_l, a k_min floor, proportional allocation of the remaining budget, a k_max cap and greedy rounding. Our ratios gave nearly the same allocation either way (Eq. 8: range 6-14; code with avg 8, k_min 6, k_max 10: range 6-10). (affects results: True)
* **[code_vs_paper, minor]** `layer_analysis/run_layer_sensitivity_sampled.py --perturbation_scale default; single.sh` — paper: App. A.3: perturbation magnitude δ = 0.1. — code: Default perturbation_scale = 0.01, and single.sh does not override it (we passed 0.1). (affects results: True)
* **[code_vs_paper, minor]** `layer_sensitivity_analyzer_fast.py: _analyze_layer_sensitivity_for_tokens` — paper: Eq. 3: S_l(D) = mean over tokens of (perturbed loss - original loss), signed. — code: sensitivity_score = mean |Δloss| (absolute value). (affects results: True)
* **[code_vs_paper, minor]** `single.sh / getHardTokens_new.py defaults; README` — paper: App. A.3: 1,000 tokens sampled from the C4 validation set. — code: Defaults point to c4-train.00000-of-01024 and single.sh uses --max_samples 1000 documents (tens of thousands of hard tokens, not ~1,000 tokens). (affects results: True)
* **[code_vs_paper, major]** `inference/test_our.sh (custom_our model_args)` — paper: Eq. 9 + App. A.3: Score = G_l(x) + λ·MinMax(CEI_l), λ = 0.1; no other fusion hyperparameter. — code: The (unreleased) backend is called with extra_mass=0.1 and cei_temp=5.0. cei_temp has no counterpart in the paper, which suggests the authors' fusion differs from Eq. 9 (e.g. a temperature-softmax over CEI). Cannot be checked because the backend is not released. (affects results: True)
