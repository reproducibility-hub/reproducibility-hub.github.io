# Reproduction report: *Detoxification for LLM: From Dataset Itself* (ACL 2026, 2026.acl-long.1079)

**Verdict: PARTIALLY_REPRODUCED.** Result match (after fixes): **MIXED**. Result match as released: **TREND_MATCH**. Coverage: **SUBSET**. Codebase completeness: **MINOR_FIXES**.

Short version:
- The released pipeline runs end to end: DGHS prep → toxic model → SoCD detox → fusion ranking → fine-tune → ToxiGen/MMLU eval.
- Base-model sanity numbers match the paper closely.
- Fine-tuning on HSPD-detoxified DGHS does reduce downstream toxicity on all four models, and MMLU is preserved. But the size of the effect is much smaller than the paper reports. On GPT2-XL, TP-ID is 0.32 using the authors' released corpus (0.38 using our own re-run of the corpus), against the paper's 0.18.
- The ablation claim that SoCD is what drives the improvement (Table 2: TP-ID 0.48 → 0.26) does **not** reproduce. With the released SoCD code, the result is the same as prompting only (0.415 vs 0.414).
- An internal probe shows why: as coded, SoCD essentially never changes the decoded token.

## 1. Paper claims targeted
- **Table 1 (main):** HSPD rows for GPT2-XL, LLaMA2-7B, OPT-6.7B and Falcon-7B. Each model is fine-tuned on the HSPD-detoxified DGHS corpus and evaluated on ToxiGen: TP/EMT for ID (gender, race, religion) and OOD (disability), 25 samples × 20 tokens, top-p 0.9, 5 runs. Reference metrics: PPL (LLaMA2-7B), Dist-1/2/3, MMLU 1-shot. The un-finetuned base-model rows serve as sanity checks.
- **Abstract:** "On GPT2-XL, HSPD … reducing TP … to 0.18 and EMT … to 0.20".
- **Table 2 (ablation, GPT2-XL, T=0.7):** prompt-only s=1, prompt+FR s=3, SoCD s=1, SoCD+FR s=3, plus Sim.
- **Table 3:** detoxified-corpus diversity and length (checked qualitatively).
- **Not run:**
  - Baselines LM-Steer, DExperts and UniDetox: no code or configs in the release.
  - Table 5 / Fig. 2 / Fig. 3 divergence sweeps: FKL/RKL/JS/TVD/vanilla CD × 3 base sizes. Each full-corpus detox takes ~6 h of GPU here, so the sweep doesn't fit the budget.

Data used by the eval:
- **"Released corpus"** = the authors' LFS file `data/step3/swift_dghs_ranked_…jsonl`, which the README says gives the Table 1 GPT2-XL result. sha256 matches the LFS pointer.
- **"Our corpus"** = our full re-run of steps 1–3.

Settings that differ from the paper:
- **LLaMA-2-7B weights:** `meta-llama/Llama-2-7b-hf` is gated (access pending), so `unsloth/llama-2-7b` (an ungated mirror of the same weights) was used. This applies both to the PPL scorer and to the LLaMA2-7B row.
- **Eval generation batch size:** 16 for 7B and ablation evals, 8 for OPT/Falcon, versus 64 in the config. This was needed because of GPU sharing; it only changes the RNG stream.
- **Downstream fine-tuning:** follows the released script, not paper A.3. A.3 describes 640 random texts ≤256 tokens, total batch 16, lr 3e-5, with no epoch/step count given.
- **Checkpoint choice:** the paper doesn't say which checkpoint is reported. I report checkpoint-2000 (the final one). Toxicity for checkpoints 400–2000 is in `logs/results_table.txt`, and it plateaus after ~1200 steps. A 3000-step run (the eval config's default range ends at 3000) gives TP-ID 0.31 / 0.314 at checkpoints 2500 / 3000.

The paper's central ablation finding is "SoCD leads to a substantial reduction in toxicity scores". In our runs, SoCD changes neither the corpus toxicity (Detoxify mean 0.157 prompt-only vs 0.158 SoCD at s=1) nor the downstream model (TP-ID 0.415 vs 0.414).

**Diagnosis** (`runscripts/probe_socd.py`, 8 DGHS texts, ~480 decode steps):
- With the released SoCD code, α ≈ 0.28 and k ≈ 42k tokens.
- **52% of the "suppressed" tokens have negative toxic logits**, so the code (which subtracts `alpha*toxic_logit` without the paper's `abs`) *raises* them.
- The argmax token is never changed (0/480), and the mean KL shift is 1e-4.
- So the coded SoCD is effectively a no-op on the decoding trajectory.
- The gain of the full HSPD corpus over T=0.7 prompting (0.381 vs ~0.41) comes from multi-temperature sampling + fusion ranking, not from SoCD.

## 4. Why the numbers are not fully reproduced
1. **Fine-tuning protocol:** paper A.3 (640 texts, batch 16, lr 3e-5, unknown epochs/checkpoint) differs from the released script (all 12,575 texts, batch 2, lr 2e-5, 2000 steps). The reported checkpoint is unspecified. The eval config's checkpoint range (500–3000) doesn't match what the training script saves (200–2000). We followed the released code. Longer training (3000 steps) does not close the gap (0.31).
2. **Released corpus vs Table 1:** even the authors' own released corpus gives 0.32, not 0.18. Its Sim (0.8685) equals the Table 2 "s=3" row exactly (TP 0.28/0.30), which suggests the released file corresponds to that setting rather than the Table 1 one.
3. **SoCD implementation:** it deviates from the paper (no `abs`, toxic model run without an attention mask over 512-token left padding, "EMD" that is really an L2 distance), and in practice it has almost no effect (see the probe). So the SoCD-specific claims cannot be reproduced with this code.
4. **Baselines and divergence sweeps not run** (no code / compute budget).

## 6. Discrepancies
**Code vs paper**
1. *(major)* `step2_text_detox.py` SoCD update: `scores - alpha * toxic_logits`. Paper Eq. 11 is `s_base − α·m⊙abs(s_toxic)`. Without `abs`, tokens with negative toxic logits (~52% of selected ones) are boosted, not suppressed.
2. *(major)* `modules/diffs_funcs.py::wsd_diffs_fn` ("EMD"): `geomloss.SamplesLoss` applied to `(1,V)` tensors treats each distribution as **one point in R^V**. The result ≈ ‖p−q‖₂ (verified numerically), not the earth mover's distance over the vocabulary that the paper defines.
3. *(major)* `DetoxifyTokenProcessor.__call__`: the toxic model's first forward gets the 512-token left-padded prompt **without an attention mask**, so it conditions on hundreds of pad tokens. The paper describes p_toxic(x<t).
4. *(minor)* k: code `floor(αV)` clipped to [10, V]; paper `ceil(αV)` clipped to [10, V/2].
5. *(minor)* `configs/step2_text_detox.yaml`: temperatures [0.6, 0.8, 1.0, 1.2, 1.5] × 2 samples. Paper A.2 (and the released step2 file): {0.6, 0.8, 1.0, 1.2, 1.3, 1.5} × 3.
6. *(minor)* `scripts/step1_finetune_toxic.sh`: 1000 steps (~1.3 epochs), selection by loss. Paper: 3 epochs, best token accuracy.
7. *(minor)* `scripts/step4-1_toxic_eval_sft.sh`: all 12,575 texts, batch 2 (no accumulation), lr 2e-5, 2000 steps, max_len 1024. Paper A.3: 640 random texts ≤256 tokens, total batch 16, lr 3e-5.
8. *(minor)* `configs/step4_toxic_eval.yaml`: evaluates checkpoints 500–3000, while training saves 200–2000; checkpoint selection unspecified. ToxiGen eval uses a random 66.7% of the annotated test split; the paper says "every ToxiGen example".
9. *(minor)* README/scripts use Qwen2.5-*-Instruct models; the paper says Qwen2.5-0.5B/3B.

**Paper internal**
1. Abstract: "reducing TP from 0.42 to 0.18 and EMT from 0.43 to 0.20" on GPT2-XL. Table 1 gives GPT2-XL TP-ID 0.54 and EMT 0.54; 0.42/0.43 are the LM-Steer/UniDetox rows.
2. §5.5 says the ablation "reuse[s] the HSPD method presented in table 1", but Table 2's full-HSPD row (s=3) is TP .28/.30, EMT .29/.30, versus Table 1's .18/.19/.20/.22. The released "Table 1" corpus has Sim .8685, identical to Table 2's s=3 row.
3. Table 1 claims EMD was used, but its LLaMA2-7B HSPD row (.16/.18/.21/.22, PPL 18.42, 38.60) equals the **JS** row of Table 5, not the EMD row (.18/.22/.23/.25, 19.23, 39.12). The OPT and Falcon rows do match EMD.
4. Table 4 defines "JS" as ½(KL(P‖Q)+KL(Q‖P)), which is the symmetric KL, not the Jensen–Shannon divergence. The code implements the paper's formula.
